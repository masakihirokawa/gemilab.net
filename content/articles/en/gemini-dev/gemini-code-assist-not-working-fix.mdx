You've installed Gemini Code Assist, but the suggestions aren't showing up. Or maybe the extension is installed but sign-in keeps failing. Or the Outline feature just isn't appearing. Whatever the symptom, this guide walks through the most common Gemini Code Assist issues and exactly how to fix them.

## Start Here: Basic Checklist

Before diving into specific symptoms, run through these basics.

**1. Check authentication status**

Click the Gemini icon in the VS Code sidebar. If you see a prompt to sign in, that's your first stop. Sign in with a Google account that has access to Gemini Code Assist.

**2. Verify the extension version**

Open the Extensions tab in VS Code, search for "Gemini Code Assist," and make sure you're on the latest version. Older versions may lack features or contain bugs that have since been fixed.

**3. Check your network connection**

Gemini Code Assist is a cloud service and requires a stable internet connection. Corporate proxy and VPN environments often need extra configuration — covered below.

## Symptom-by-Symptom Fixes

### Symptom 1: No Inline Suggestions at All

**Check the setting state first**

Open the Command Palette (`Cmd+Shift+P` on Mac, `Ctrl+Shift+P` on Windows/Linux), type "Gemini: Enable/Disable Suggestions," and confirm whether suggestions are currently enabled.

**Verify your settings.json**

Make sure these entries are present and set to `true`:

```json
{
  "editor.inlineSuggest.enabled": true,
  "geminiCode.enableInlineSuggestions": true
}
```

Restart VS Code after any settings change.

**Check Tab completion settings**

If `editor.tabCompletion` is set to `"off"`, you may see suggestions appear but not be able to accept them with Tab. Set it to `"on"` or `"onlySnippets"`.

**Still not working?** Uninstall the extension, restart VS Code, then reinstall it fresh. Sometimes cached state from a previous install causes persistent issues.

### Symptom 2: Can't Sign In to the Extension

**Reset the authentication state**

1. Run "Gemini Code Assist: Sign Out" from the Command Palette.
2. Clear any cached Google credentials from your OS keychain (Keychain Access on macOS, Credential Manager on Windows).
3. Run "Gemini Code Assist: Sign In" again.

**Browser-related sign-in failures**

VS Code opens an external browser to complete OAuth authentication. If your default browser blocks popups or has security extensions interfering, try temporarily disabling them.

**Google Workspace (enterprise) accounts**

If you're using a company Google account, your administrator may not have enabled Gemini Code Assist for your organization. Check with your admin to confirm it's enabled in the Google Workspace Admin Console under "Apps → Additional Google Services → Gemini for Google Cloud."

### Symptom 3: Outline Feature Not Showing

The Outline feature in Gemini Code Assist generates a structural overview of your code to help with navigation. Here's what to check when it's missing.

**Language support**

Outline is currently supported for select languages including Python, JavaScript, TypeScript, Java, and Go. Check the official documentation to confirm support for your language.

**Enable the setting explicitly**

```json
{
  "geminiCode.enableOutline": true
}
```

Add this to your `settings.json` if it's not already there.

**Large file processing time**

Very large files (several thousand lines) can take time to process. Watch for a spinner in the status bar while Gemini is working. If it eventually appears, the file size is likely the cause of the delay rather than a configuration issue.

### Symptom 4: Suggestions Are Off-Topic or Low Quality

Code completion quality depends heavily on the context surrounding your cursor. A few techniques reliably improve it.

**Add descriptive comments above your cursor:**

```python
# Email address validation function
# Checks format compliance with RFC 5322
def validate_email(email: str) -> bool:
    # ← Gemini will produce much more accurate suggestions here
```

**Declare your stack at the top of the file:**

```typescript
// Framework: Next.js 15 App Router
// State: Zustand
// Styling: Tailwind CSS
```

This context significantly improves suggestion relevance, especially in files that might otherwise look ambiguous.

### Symptom 5: Not Connecting in a Proxy or VPN Environment

Corporate networks often require explicit proxy configuration for VS Code to reach cloud services.

**VS Code proxy settings:**

```json
{
  "http.proxy": "http://your-proxy-server:port",
  "http.proxyStrictSSL": false,
  "http.proxyAuthorization": null
}
```

**If the VS Code setting isn't enough**, try launching VS Code with the environment variable set:

```bash
# macOS / Linux
export HTTPS_PROXY=http://your-proxy-server:port
code .

# Windows (PowerShell)
$env:HTTPS_PROXY="http://your-proxy-server:port"
code .
```

If you're on a corporate network with SSL inspection, you may also need to add your company's root CA certificate to VS Code's trusted certificates.

### Symptom 6: JetBrains IDE Issues (IntelliJ, PyCharm, etc.)

Gemini Code Assist also supports JetBrains IDEs through the Google Cloud Code plugin.

**Verify the plugin is installed and up to date** in the JetBrains Marketplace. After installation, a full IDE restart is required.

**Find the settings in a different location** than VS Code: navigate to "Settings → Tools → Google Cloud Code" to configure Gemini Code Assist for JetBrains.

**Authentication in JetBrains** works through the same Google account flow, but uses JetBrains' own browser integration. If the browser doesn't open automatically, look for a link in the notification area at the bottom of the IDE.

## Finding Root Cause in the Logs

When symptoms don't match the above patterns, the logs usually tell you what's wrong.

**VS Code logs:**

1. Open "Help → Toggle Developer Tools"
2. In the Console tab, search for "gemini" or "google"

Or use the Output panel (`Ctrl+Shift+U`) and select "Gemini Code Assist" from the dropdown.

## Common Error Messages Decoded

"Authentication failed" means your sign-in state is stale — sign out and sign back in. "Quota exceeded" means you've hit your usage limit for the period; wait a few hours or consider upgrading your plan. "Network error" points to connectivity or proxy issues. "Extension host terminated unexpectedly" is a VS Code crash — fully quit and restart the application.

## Wrapping Up

Most Gemini Code Assist problems fall into one of three buckets: authentication issues, configuration settings, or network environment. Working through this guide's checklist in order should resolve the majority of cases. If you're still stuck, the official [Gemini Code Assist documentation](https://cloud.google.com/gemini/docs/codeassist/overview) is worth a visit. We hope this helps you get back to coding quickly.


## What Agent Mode Actually Does (and What It Doesn't)

Before diving into troubleshooting, it's worth clarifying what agent mode is. Unlike inline code completion or simple chat responses, agent mode can plan and execute multi-step tasks — modifying multiple files, suggesting shell commands, generating tests, and iterating based on feedback.

It became generally available for Enterprise and Individual Pro plans in late 2025. If you're on the Free tier, agent mode is not available.

The most common misunderstanding: **agent mode requires explicit activation**, not just installing the extension. If you don't see an "Agent" toggle in the chat input area, you haven't enabled it yet — or your setup doesn't meet the requirements.

## Step 1: Check Your Extension Version

Agent mode was introduced in version `2.x` of the VS Code extension. If you're running an older version, the feature simply won't appear.

How to verify:

```bash
# Check installed extension versions via CLI
code --list-extensions --show-versions | grep -i gemini
# Expected output: GoogleCloudTools.cloudcode@2.3.1 (or newer)
```

In the VS Code Extensions view (`Ctrl+Shift+X` / `Cmd+Shift+X`), search for "Gemini Code Assist" and confirm the version number. If an update is available, install it and reload the window.

For **JetBrains IDEs** (IntelliJ IDEA, PyCharm, etc.), go to `Preferences > Plugins > Installed`, find "Gemini Code Assist", and verify you're on plugin version `1.8` or later.

## Step 2: Verify Authentication and License

Agent mode requires an active authenticated session with an eligible plan. Here's a quick checklist:

```
✅ Gemini icon visible in VS Code status bar (bottom-left)
✅ Clicking the icon shows your signed-in Google account
✅ License shows "Pro" or "Enterprise" — not "Free"
❌ "Free" license → agent mode is unavailable; upgrade required
```

If you're not signed in, open the Command Palette (`Ctrl+Shift+P` / `Cmd+Shift+P`) and run **Gemini Code Assist: Sign In**. This opens a browser window for Google account authentication.

For **Enterprise environments**, your organization's admin must explicitly enable agent mode in the Google Cloud admin console. If you're unsure whether it's enabled for your account, check with your IT admin — this is often the culprit in corporate setups.

## Step 3: When the Agent Stalls Mid-Task

Authentication is fine, but the agent starts a task and freezes? A few patterns to check:

### Context overload

Agent mode can reference your entire repository, but there's a limit to how much it can process in a single request. Broad instructions on large codebases tend to hit this ceiling.

```
# Too broad — often causes stalling or timeout
"Find and fix all the bugs in this project"

# Scoped — works reliably
"Look at src/api/auth.ts and check whether the JWT validation logic handles token expiry correctly"
```

Keep requests focused on specific files or modules. If you need broader analysis, break it into multiple focused sessions.

### Proxy and network timeouts

In corporate environments with proxies or VPNs, agent mode's persistent connections can be interrupted. Make sure your proxy is correctly configured in VS Code settings:

```json
// .vscode/settings.json or global settings.json
{
  "http.proxy": "http://your-proxy.example.com:8080",
  "http.proxyAuthorization": null,
  "http.proxyStrictSSL": false
}
```

### `@workspace` and `@file` references not resolving

These workspace references depend on an index that VS Code builds in the background. If the index is incomplete or stale, file references will silently fail.

**Quick fix**: Reload the window (`Ctrl+Shift+P` → "Developer: Reload Window"). This triggers a fresh index build.

Also worth checking: files listed in `.gitignore` are excluded from the workspace index. If the agent can't see an important file, verify it's not accidentally ignored.

## Error Messages and What They Mean

Here are the most common error messages you'll encounter in agent mode, and what each one tells you:

**`Failed to complete task: context limit exceeded`**
→ The scope of your request is too large. Narrow it to a specific file or function.

**`Agent mode is not available for your plan`**
→ Your current license doesn't include agent mode. A plan upgrade is required.

**`Unable to index workspace`**
→ The workspace is either too large or there's a permission issue. Check the Output panel for more detail.

**`Connection to Gemini service failed`**
→ Network issue or service outage. Check the [Google Cloud Status page](https://status.cloud.google.com/) to rule out an outage.

## Reading the Logs

When error messages aren't enough, the Output panel is your best diagnostic tool.

```
// How to access logs
1. Open View > Output
2. Select "Gemini Code Assist" or "Gemini Code Assist - Agent" from the dropdown
3. Look for log entries around the time the issue occurred
```

A few patterns worth knowing:

```
[ERROR] Agent: Task execution failed after 3 retries
→ Repeated API failures — likely an auth or network issue

[WARN] Workspace indexing incomplete: 2847 files skipped
→ Large repo with partial indexing — review .gitignore

[INFO] Agent mode: Using gemini-2.5-pro-latest
→ Model is connected and responding (if you see this, the connection is healthy)
```

The `[INFO]` line with the model name is particularly useful — if it appears, the extension is communicating with Gemini successfully, and the issue is likely in the request scope rather than the connection.
