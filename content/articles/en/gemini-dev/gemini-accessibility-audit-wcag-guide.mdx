## Why Automate Accessibility Audits with Gemini API

Web accessibility is no longer optional. With the European Accessibility Act (EAA) taking full effect in 2025, ADA enforcement expanding in the United States, and similar regulations rolling out worldwide, WCAG 2.2 compliance has become the de facto international standard for web development.

The challenge is scale. WCAG 2.2 contains 78 success criteria, and manually auditing every page of a website is prohibitively time-consuming. This is where Gemini API's multimodal capabilities shine. By combining HTML code analysis with screenshot-based visual recognition, you can detect accessibility issues that traditional rule-based tools like axe and Lighthouse simply miss — things like poor visual contrast in complex layouts, inadequate touch targets on mobile, and content that relies solely on color to convey meaning.

In this guide, we'll build an automated accessibility audit system using Gemini API and Python, complete with working code examples.

## Understanding WCAG 2.2 and What Can Be Automated

WCAG 2.2 success criteria are organized around four core principles.

- **Perceivable**: Text alternatives, captions, color contrast ratios
- **Operable**: Keyboard access, sufficient time, seizure prevention, navigation
- **Understandable**: Readability, predictability, input assistance
- **Robust**: HTML conformance, assistive technology compatibility

Industry estimates suggest that automated tools can catch roughly 30–40% of all WCAG violations. The rest requires human judgment. However, Gemini API's multimodal analysis can extend automated coverage significantly by handling **visual review** tasks that were previously manual-only — pushing that coverage well beyond what traditional linting tools achieve.

## Detecting WCAG Violations Through HTML Analysis

The first approach sends raw HTML to the Gemini API for structural accessibility analysis.

```python
def audit_html_accessibility(url: str) -> dict:
    """Fetch a URL's HTML and run a Gemini-powered accessibility audit."""
    
    # Fetch the page with Playwright
    with sync_playwright() as p:
        browser = p.chromium.launch()
        page = browser.new_page()
        page.goto(url, wait_until="networkidle")
        html_content = page.content()
        browser.close()
    
    # Strip scripts and styles to reduce token usage
    soup = BeautifulSoup(html_content, "html.parser")
    for tag in soup(["script", "style", "noscript"]):
        tag.decompose()
    
    clean_html = str(soup)[:30000]  # Respect token limits
    
    prompt = f"""You are a WCAG 2.2 expert. Audit the following HTML
for accessibility issues and generate a JSON report.

Check for:
1. Missing or inadequate alt attributes on img elements
2. Form elements without associated labels
3. Heading hierarchy violations (h1 → h2 → h3 order)
4. Proper use of landmark roles (nav, main, footer, etc.)
5. Correct ARIA attribute usage
6. Ambiguous link text ("click here", "read more")
7. Missing lang attribute
8. Improper tabindex usage

Output format:
{{
  "url": "target URL",
  "violations": [
    {{
      "criterion": "WCAG criterion number (e.g., 1.1.1)",
      "severity": "critical / major / minor",
      "element": "problematic HTML element",
      "description": "description of the issue",
      "recommendation": "how to fix it"
    }}
  ],
  "passed": ["list of passed checks"],
  "score": "0-100 score"
}}

HTML:
{clean_html}"""
    
    response = client.models.generate_content(
        model="gemini-2.5-flash",
        contents=prompt,
        config=types.GenerateContentConfig(
            temperature=0.1,  # Low temperature for consistent output
            response_mime_type="application/json",
        ),
    )
    
    return json.loads(response.text)

# Usage

# print(json.dumps(result, indent=2))
```

## Visual Audit with Screenshots

This is where Gemini API truly differentiates itself. By analyzing actual screenshots, it can catch contrast ratio issues, focus indicator visibility, and responsive design problems that no amount of HTML parsing would reveal.

```python
def visual_accessibility_audit(url: str) -> dict:
    """Run a visual accessibility audit using page screenshots."""
    
    with sync_playwright() as p:
        browser = p.chromium.launch()
        page = browser.new_page(viewport={"width": 1280, "height": 720})
        page.goto(url, wait_until="networkidle")
        
        # Full-page desktop screenshot
        screenshot_bytes = page.screenshot(full_page=True)
        
        # Mobile viewport screenshot
        page.set_viewport_size({"width": 375, "height": 812})
        mobile_screenshot = page.screenshot(full_page=True)
        
        browser.close()
    
    response = client.models.generate_content(
        model="gemini-2.5-pro",  # Pro model recommended for visual analysis
        contents=[
            types.Part.from_bytes(
                data=screenshot_bytes,
                mime_type="image/png",
            ),
            types.Part.from_bytes(
                data=mobile_screenshot,
                mime_type="image/png",
            ),
            """Audit these pages for WCAG 2.2 visual accessibility.

Focus on:
1. **Color contrast** (WCAG 1.4.3): Text-to-background contrast ratio
   must be ≥4.5:1 (normal text) / ≥3:1 (large text)
2. **Text size** (WCAG 1.4.4): Is text large enough to be readable?
3. **Touch targets** (WCAG 2.5.8): Are buttons and links at least
   24×24px on mobile?
4. **Color-only information** (WCAG 1.4.1): Is information conveyed
   through color alone without additional cues?
5. **Visual heading hierarchy**: Do heading sizes/weights reflect
   a logical structure?
6. **Responsive design**: Does content overflow or overlap on mobile?

Image 1 is desktop view, Image 2 is mobile view.
Return results as JSON.""",
        ],
        config=types.GenerateContentConfig(
            temperature=0.1,
            response_mime_type="application/json",
        ),
    )
    
    return json.loads(response.text)
```

The real power here is catching issues that require "seeing" the page — decorative fonts with poor legibility, hover effects that don't provide enough visual contrast, or buttons that look tappable on desktop but are impossibly small on mobile.

## Combining Lighthouse with Gemini API for Better Results

Rather than relying on AI alone, combine Lighthouse's deterministic checks with Gemini API's contextual analysis for the most thorough audit possible.

```python
import subprocess

def combined_audit(url: str) -> dict:
    """Run an integrated Lighthouse + Gemini API audit."""
    
    # Run Lighthouse (requires Node.js)
    result = subprocess.run(
        ["npx", "lighthouse", url,
         "--output=json",
         "--only-categories=accessibility",
         "--chrome-flags=--headless --no-sandbox"],
        capture_output=True, text=True, timeout=60
    )
    
    lighthouse_data = json.loads(result.stdout)
    
    # Extract failed accessibility audits
    a11y_audits = lighthouse_data.get("audits", {})
    failed_audits = {
        k: v for k, v in a11y_audits.items()
        if v.get("score") is not None and v["score"] < 1
    }
    
    # Ask Gemini API to create a prioritized improvement plan
    prompt = f"""Below are the Lighthouse accessibility audit results.
Create a prioritized improvement plan for each failed item.

For each item, include:
- Impact level (critical / major / minor)
- Estimated fix time (in hours)
- Specific code fix example
- Expected score improvement after the fix

Failed audits:
{json.dumps(failed_audits, indent=2)[:10000]}

Current accessibility score: {lighthouse_data.get('categories', {}).get('accessibility', {}).get('score', 0) * 100}
"""
    
    response = client.models.generate_content(
        model="gemini-2.5-flash",
        contents=prompt,
        config=types.GenerateContentConfig(temperature=0.2),
    )
    
    return {
        "lighthouse_score": lighthouse_data.get("categories", {}).get("accessibility", {}).get("score", 0) * 100,
        "failed_count": len(failed_audits),
        "improvement_plan": response.text,
    }
```

Lighthouse provides the hard numbers, while Gemini API transforms those results into actionable, developer-friendly recommendations. It's a best-of-both-worlds approach.

## Frequently Asked Questions

### Can Gemini API replace axe or Lighthouse for accessibility testing?

Not entirely. axe and Lighthouse perform precise DOM-level analysis based on strict HTML specification rules — they're excellent at catching structural violations deterministically. Gemini API's strength lies in detecting visual issues that code analysis alone can't catch (like poor contrast in complex gradients or undersized touch targets) and in translating raw audit data into clear, actionable improvement plans. The most effective approach combines both: use axe or Lighthouse for rule-based checks, then layer Gemini API on top for visual analysis and human-readable reporting.

### Which Gemini model should I use?

For HTML code analysis, `gemini-2.5-flash` delivers strong accuracy with fast response times, making it ideal for CI/CD integration. For screenshot-based visual analysis, `gemini-2.5-pro` is the better choice — its superior image understanding catches subtle contrast and layout issues that Flash may miss. Use Flash for speed-sensitive pipelines and Pro for thorough visual audits.

### Does this scale to large sites with hundreds of pages?

Yes, with some planning. For large sites, the most efficient strategy is to identify your distinct page templates (homepage, listing page, detail page, form page, etc.) and audit one representative page per template. Fixing issues at the template level propagates improvements across all pages using that template. This keeps API costs manageable while maximizing coverage.

### Can I integrate this into my CI/CD pipeline?

Absolutely. You can add the audit script to GitHub Actions, GitLab CI, or Cloudflare Pages build hooks to run automated checks before every deployment. Set up the pipeline to fail the build if any critical violations are detected — this acts as an accessibility regression gate that prevents new issues from reaching production.
