## Introduction — Why Vector Search in Firestore?

When building RAG (Retrieval-Augmented Generation) systems, most developers consider dedicated vector databases like Pinecone, Qdrant, or pgvector. However, for projects already using Firebase and Firestore as their backend (check out our [Gemini × Firebase Integration Guide](/en/articles/gemini-dev/gemini-firebase-integration-guide) for the basics), the added infrastructure complexity and cost can be a significant barrier.

This changed dramatically when Firestore released native vector search capabilities in late 2024. You can now store vector fields directly in Firestore documents and execute KNN (K-Nearest Neighbors) queries for semantic search — no external vector database required.

In this guide, we'll walk through building a production-grade serverless RAG system that combines Gemini's Embedding models (`text-embedding-004` / `embedding-001` — see our [Gemini Embeddings API Guide](/en/articles/gemini-api/embeddings-api-guide) for details) with Firestore Vector Search. We'll cover everything from architectural design to cost optimization, with complete working code at every step.

**Who this guide is for:**

- Developers already using Firebase/Firestore who want to add RAG capabilities
- Teams looking to reduce infrastructure overhead by eliminating separate vector DB management
- Engineers who want to leverage Gemini Embeddings in production applications

**Prerequisites:**

- Familiarity with Firebase/Firestore basics (document CRUD operations)
- Node.js/TypeScript fundamentals
- Basic knowledge of the Gemini API (API key obtained)

## Firestore Vector Search Architecture

### How Vector Search Works

Firestore's vector search stores vector data in documents using `FieldValue.vector()` and queries them using the `findNearest()` method. Under the hood, Google's infrastructure runs ANN (Approximate Nearest Neighbors) algorithms for efficient similarity matching.

**Supported distance metrics:**

- `COSINE` — Cosine similarity (ideal for text search with normalized vectors)
- `EUCLIDEAN` — Euclidean distance (when spatial proximity matters)
- `DOT_PRODUCT` — Dot product (fast computation for high-dimensional vectors)

Since Gemini Embeddings return normalized vectors, **we recommend `COSINE`** for most use cases.

### System Architecture Overview

The production RAG system consists of two main pipelines.

**Embedding generation pipeline:**
Document added → Cloud Functions Trigger → Gemini Embeddings API → Firestore vector field updated

**Search and generation pipeline:**
User query → Gemini Embeddings (vectorize query) → Firestore findNearest() → Retrieve relevant documents → Gemini Pro generates answer

The key advantage of this architecture is that **everything stays within the Firebase ecosystem**. Authentication (Firebase Auth), storage (Cloud Storage), compute (Cloud Functions), and database (Firestore) are all integrated, dramatically reducing IAM and network configuration complexity.

## Choosing the Right Gemini Embedding Model

### Model Comparison

Several embedding models are available through Gemini.

**text-embedding-004 (recommended):**
- Dimensions: 768 (default), reducible to 256/512
- Max input tokens: 2,048
- Use cases: text search, classification, clustering
- Cost: generous free tier, $0.00001/1,000 characters beyond

**embedding-001:**
- Dimensions: 768 (fixed)
- Max input tokens: 2,048
- Use cases: general purpose (legacy model)
- Note: Use text-embedding-004 for new projects

**Dimension selection guidelines:**
Firestore vector fields support up to 2,048 dimensions, but higher dimensions increase storage costs and query latency. For production environments, consider these guidelines:

- **768 dimensions**: Accuracy-focused (datasets under 100K documents)
- **512 dimensions**: Balanced approach (100K–1M documents)
- **256 dimensions**: Cost-focused (1M+ documents or strict latency requirements)

### Implementing Embedding Generation

```typescript
// lib/embeddings.ts
import { GoogleGenerativeAI } from "@google/generative-ai";

const genAI = new GoogleGenerativeAI(process.env.GEMINI_API_KEY\!);

// Use the text-embedding-004 model
const embeddingModel = genAI.getGenerativeModel({
  model: "text-embedding-004",
});

/**
 * Generate an embedding vector from text
 * @param text - Input text (max 2,048 tokens)
 * @param taskType - Task type (affects search accuracy)
 * @returns Array of 768 floating-point values
 */
export async function generateEmbedding(
  text: string,
  taskType: "RETRIEVAL_DOCUMENT" | "RETRIEVAL_QUERY" = "RETRIEVAL_DOCUMENT"
): Promise<number[]> {
  const result = await embeddingModel.embedContent({
    content: { parts: [{ text }], role: "user" },
    taskType,
  });

  return result.embedding.values;
}

/**
 * Batch embedding generation (up to 100 texts per request)
 * Rate limit: 1,500 RPM for text-embedding-004
 */
export async function generateEmbeddingsBatch(
  texts: string[],
  taskType: "RETRIEVAL_DOCUMENT" | "RETRIEVAL_QUERY" = "RETRIEVAL_DOCUMENT"
): Promise<number[][]> {
  const result = await embeddingModel.batchEmbedContents({
    requests: texts.map((text) => ({
      content: { parts: [{ text }], role: "user" },
      taskType,
    })),
  });

  return result.embeddings.map((e) => e.values);
}
```

**Key point:** The `taskType` parameter directly impacts search accuracy. Use `RETRIEVAL_DOCUMENT` when storing documents and `RETRIEVAL_QUERY` when processing search queries. This tells the Gemini Embedding model to optimize vectors for each specific use case.

## Creating and Managing Vector Indexes

### Storing Vector Fields

When storing vector data in Firestore, use `FieldValue.vector()`.

```typescript
// lib/firestore-vector.ts
import {
  getFirestore,
  FieldValue,
} from "firebase-admin/firestore";
import { generateEmbedding } from "./embeddings";

const db = getFirestore();

/**
 * Store a document with its embedding in Firestore
 */
export async function addDocumentWithEmbedding(
  collectionName: string,
  data: { title: string; content: string; category: string }
): Promise<string> {
  // Combine title and content for embedding
  const textForEmbedding = `${data.title}\n\n${data.content}`;

  // Truncate for the 2,048 token limit
  const truncated = truncateToTokenLimit(textForEmbedding, 2000);
  const vector = await generateEmbedding(truncated, "RETRIEVAL_DOCUMENT");

  const docRef = await db.collection(collectionName).add({
    title: data.title,
    content: data.content,
    category: data.category,
    createdAt: FieldValue.serverTimestamp(),
    // Store as a vector field
    embedding: FieldValue.vector(vector),
  });

  return docRef.id;
}

/**
 * Truncate text based on estimated token count
 */
function truncateToTokenLimit(text: string, maxTokens: number): string {
  // English: ~1.3 tokens per word; Japanese: ~1.5 tokens per character
  const estimatedCharsLimit = Math.floor(maxTokens * 4);
  if (text.length <= estimatedCharsLimit) return text;
  return text.slice(0, estimatedCharsLimit) + "...";
}
```

### Creating Vector Indexes

You need to create a vector index before running vector searches. This is done via the Firebase CLI or Google Cloud Console.

```bash
# Create a vector index using gcloud CLI
gcloud firestore indexes composite create \
  --collection-group=documents \
  --query-scope=COLLECTION \
  --field-config=vector-config='{"dimension":"768","flat":{}}',field-path=embedding

# Check index status
gcloud firestore indexes composite list --format="table(name,state)"
```

**Important notes:**

- Index creation can take several minutes to complete
- The `dimension` must match your embedding model's output dimensions
- The `flat` configuration works well for small to medium datasets. For datasets exceeding 1M documents, consult Google's documentation
- Composite indexes (vector + metadata filters) are also supported

### Using Composite Indexes

In production, you'll frequently combine vector search with metadata filtering.

```bash
# Composite index: category filter + vector search
gcloud firestore indexes composite create \
  --collection-group=documents \
  --query-scope=COLLECTION \
  --field-config=field-path=category,order=ASCENDING \
  --field-config=vector-config='{"dimension":"768","flat":{}}',field-path=embedding
```

## Implementing Semantic Search

### Basic Similarity Search

```typescript
// lib/search.ts
import { getFirestore, VectorQuery } from "firebase-admin/firestore";
import { generateEmbedding } from "./embeddings";

const db = getFirestore();

interface SearchResult {
  id: string;
  title: string;
  content: string;
  category: string;
  score: number;
}

/**
 * Execute semantic search
 * @param query - User's search query
 * @param collectionName - Target collection
 * @param limit - Number of results (default: 5)
 * @param category - Optional category filter
 */
export async function semanticSearch(
  query: string,
  collectionName: string,
  limit: number = 5,
  category?: string
): Promise<SearchResult[]> {
  // Convert query text to embedding (using RETRIEVAL_QUERY type)
  const queryVector = await generateEmbedding(query, "RETRIEVAL_QUERY");

  let collectionRef = db.collection(collectionName);

  // Apply category filter if specified
  let baseQuery: FirebaseFirestore.Query = collectionRef;
  if (category) {
    baseQuery = collectionRef.where("category", "==", category);
  }

  // Execute vector search with findNearest()
  const vectorQuery: VectorQuery = baseQuery.findNearest({
    vectorField: "embedding",
    queryVector,
    limit,
    distanceMeasure: "COSINE",
    // Get distance scores in results
    distanceResultField: "vector_distance",
  });

  const snapshot = await vectorQuery.get();

  return snapshot.docs.map((doc) => {
    const data = doc.data();
    return {
      id: doc.id,
      title: data.title,
      content: data.content,
      category: data.category,
      // Convert cosine distance to similarity score (0–1, 1 = most similar)
      score: 1 - (data.vector_distance || 0),
    };
  });
}
```

### Score Threshold Filtering

Vector search results can include low-relevance documents. In production, apply a score threshold to ensure quality.

```typescript
/**
 * Semantic search with score threshold filtering
 * Filters out results below the threshold for high-quality output
 */
export async function semanticSearchWithThreshold(
  query: string,
  collectionName: string,
  options: {
    limit?: number;
    category?: string;
    minScore?: number; // 0.0–1.0 (default: 0.7)
  } = {}
): Promise<SearchResult[]> {
  const { limit = 10, category, minScore = 0.7 } = options;

  // Fetch extra results for post-filtering
  const results = await semanticSearch(
    query,
    collectionName,
    limit * 2,
    category
  );

  // Apply score threshold
  const filtered = results.filter((r) => r.score >= minScore);

  // Trim to requested count
  return filtered.slice(0, limit);
}
```

## Automated Embedding Pipeline with Cloud Functions

### Auto-Generate Embeddings on Document Creation

The most critical piece for production is automatically generating embeddings whenever documents are added or updated. Cloud Functions' Firestore Triggers make this completely hands-off.

```typescript
// functions/src/embedding-pipeline.ts
import { onDocumentCreated, onDocumentUpdated } from "firebase-functions/v2/firestore";
import { getFirestore, FieldValue } from "firebase-admin/firestore";
import { GoogleGenerativeAI } from "@google/generative-ai";
import { defineSecret } from "firebase-functions/params";

const geminiApiKey = defineSecret("GEMINI_API_KEY");
const db = getFirestore();

/**
 * Auto-generate embedding when a new document is created
 */
export const onDocumentCreate = onDocumentCreated(
  {
    document: "documents/{docId}",
    secrets: [geminiApiKey],
    // Enable retry for transient Embedding API errors
    retry: true,
    memory: "512MiB",
    timeoutSeconds: 120,
  },
  async (event) => {
    const data = event.data?.data();
    if (\!data || data.embedding) return; // Skip if embedding already exists

    const genAI = new GoogleGenerativeAI(geminiApiKey.value());
    const model = genAI.getGenerativeModel({ model: "text-embedding-004" });

    const textForEmbedding = `${data.title}\n\n${data.content}`;
    const truncated = textForEmbedding.slice(0, 1300); // Safety margin

    try {
      const result = await model.embedContent({
        content: { parts: [{ text: truncated }], role: "user" },
        taskType: "RETRIEVAL_DOCUMENT",
      });

      // Write the embedding back to the document
      await event.data?.ref.update({
        embedding: FieldValue.vector(result.embedding.values),
        embeddingModel: "text-embedding-004",
        embeddingGeneratedAt: FieldValue.serverTimestamp(),
      });

      console.log(`Embedding generated for document: ${event.params.docId}`);
    } catch (error) {
      console.error(`Embedding generation failed: ${error}`);
      if (isRetryableError(error)) {
        throw error; // Cloud Functions will auto-retry
      }
      // Set error flag for non-retryable errors
      await event.data?.ref.update({
        embeddingError: String(error),
        embeddingErrorAt: FieldValue.serverTimestamp(),
      });
    }
  }
);

/**
 * Re-generate embedding when a document is updated
 * (only if title or content changed)
 */
export const onDocumentUpdate = onDocumentUpdated(
  {
    document: "documents/{docId}",
    secrets: [geminiApiKey],
    retry: true,
    memory: "512MiB",
    timeoutSeconds: 120,
  },
  async (event) => {
    const before = event.data?.before.data();
    const after = event.data?.after.data();
    if (\!before || \!after) return;

    // Skip if title and content haven't changed
    if (before.title === after.title && before.content === after.content) {
      return;
    }

    const genAI = new GoogleGenerativeAI(geminiApiKey.value());
    const model = genAI.getGenerativeModel({ model: "text-embedding-004" });

    const textForEmbedding = `${after.title}\n\n${after.content}`;
    const truncated = textForEmbedding.slice(0, 1300);

    const result = await model.embedContent({
      content: { parts: [{ text: truncated }], role: "user" },
      taskType: "RETRIEVAL_DOCUMENT",
    });

    await event.data?.after.ref.update({
      embedding: FieldValue.vector(result.embedding.values),
      embeddingModel: "text-embedding-004",
      embeddingGeneratedAt: FieldValue.serverTimestamp(),
      embeddingError: FieldValue.delete(), // Clear error flag
    });
  }
);

function isRetryableError(error: unknown): boolean {
  const message = String(error);
  return (
    message.includes("429") || // Rate limit
    message.includes("503") || // Service unavailable
    message.includes("ECONNRESET") ||
    message.includes("ETIMEDOUT")
  );
}
```

### Batch Embedding Script

For existing documents, you'll need a batch process to add embeddings in bulk.

```typescript
// scripts/batch-embed.ts
import { initializeApp, cert } from "firebase-admin/app";
import { getFirestore, FieldValue } from "firebase-admin/firestore";
import { GoogleGenerativeAI } from "@google/generative-ai";

// Initialize Firebase Admin
initializeApp({ credential: cert("./service-account.json") });
const db = getFirestore();

const genAI = new GoogleGenerativeAI(process.env.GEMINI_API_KEY\!);
const model = genAI.getGenerativeModel({ model: "text-embedding-004" });

async function batchEmbedDocuments(
  collectionName: string,
  batchSize: number = 20,
  delayMs: number = 1000 // Rate limit protection
) {
  // Get documents missing embeddings
  const snapshot = await db
    .collection(collectionName)
    .where("embedding", "==", null)
    .limit(batchSize)
    .get();

  if (snapshot.empty) {
    console.log("All documents have embeddings");
    return;
  }

  console.log(`Processing ${snapshot.size} documents...`);

  const texts = snapshot.docs.map((doc) => {
    const data = doc.data();
    return `${data.title}\n\n${data.content}`.slice(0, 1300);
  });

  // Use Gemini's batch embedding API
  const batchResult = await model.batchEmbedContents({
    requests: texts.map((text) => ({
      content: { parts: [{ text }], role: "user" },
      taskType: "RETRIEVAL_DOCUMENT" as const,
    })),
  });

  // Firestore batch write
  const writeBatch = db.batch();
  snapshot.docs.forEach((doc, index) => {
    writeBatch.update(doc.ref, {
      embedding: FieldValue.vector(batchResult.embeddings[index].values),
      embeddingModel: "text-embedding-004",
      embeddingGeneratedAt: FieldValue.serverTimestamp(),
    });
  });

  await writeBatch.commit();
  console.log(`Processed ${snapshot.size} documents`);

  // Wait to respect rate limits
  await new Promise((resolve) => setTimeout(resolve, delayMs));

  // Recursively process next batch
  await batchEmbedDocuments(collectionName, batchSize, delayMs);
}

// Run
batchEmbedDocuments("documents")
  .then(() => console.log("Batch embedding complete"))
  .catch(console.error);
```

## Building the RAG Pipeline

### Context-Aware Answer Generation

Here's the production pipeline that passes search results to Gemini Pro for context-grounded answer generation.

```typescript
// lib/rag-pipeline.ts
import { GoogleGenerativeAI } from "@google/generative-ai";
import { semanticSearchWithThreshold, SearchResult } from "./search";

const genAI = new GoogleGenerativeAI(process.env.GEMINI_API_KEY\!);

interface RAGResponse {
  answer: string;
  sources: Array<{ id: string; title: string; score: number }>;
  tokensUsed: number;
}

/**
 * RAG pipeline: search → build context → generate answer
 */
export async function ragQuery(
  userQuery: string,
  collectionName: string,
  options: {
    maxContextDocs?: number;
    maxContextTokens?: number;
    category?: string;
    systemPrompt?: string;
  } = {}
): Promise<RAGResponse> {
  const {
    maxContextDocs = 5,
    maxContextTokens = 8000,
    category,
    systemPrompt = "You are an accurate and helpful assistant. Answer based only on the provided context. If the information isn't in the context, honestly say you couldn't find it.",
  } = options;

  // Step 1: Semantic search for relevant documents
  const searchResults = await semanticSearchWithThreshold(
    userQuery,
    collectionName,
    { limit: maxContextDocs, category, minScore: 0.65 }
  );

  if (searchResults.length === 0) {
    return {
      answer: "I couldn't find any relevant information for your question.",
      sources: [],
      tokensUsed: 0,
    };
  }

  // Step 2: Build context (respecting token limits)
  const context = buildContext(searchResults, maxContextTokens);

  // Step 3: Generate answer with Gemini Pro
  const model = genAI.getGenerativeModel({
    model: "gemini-2.5-pro-preview-05-06",
    systemInstruction: systemPrompt,
  });

  const prompt = `## Context

${context}

## User Question

${userQuery}

Based on the context above, provide an accurate answer to the user's question. Cite the document titles that support your answer.`;

  const result = await model.generateContent(prompt);
  const response = result.response;

  return {
    answer: response.text(),
    sources: searchResults.map((r) => ({
      id: r.id,
      title: r.title,
      score: r.score,
    })),
    tokensUsed: response.usageMetadata?.totalTokenCount || 0,
  };
}

/**
 * Build context string from search results
 * Truncates to stay within token budget
 */
function buildContext(results: SearchResult[], maxTokens: number): string {
  let context = "";
  let estimatedTokens = 0;

  for (const result of results) {
    const docText = `### ${result.title}\n${result.content}\n\n`;
    const docTokens = Math.ceil(docText.length * 0.4); // English ~0.4 tokens per char

    if (estimatedTokens + docTokens > maxTokens) {
      const remainingChars = Math.floor((maxTokens - estimatedTokens) / 0.4);
      if (remainingChars > 100) {
        context += `### ${result.title}\n${result.content.slice(0, remainingChars)}...\n\n`;
      }
      break;
    }

    context += docText;
    estimatedTokens += docTokens;
  }

  return context;
}
```

### API Endpoint Implementation

Expose the RAG pipeline as a Cloud Functions HTTP endpoint.

```typescript
// functions/src/rag-api.ts
import { onRequest } from "firebase-functions/v2/https";
import { defineSecret } from "firebase-functions/params";
import { ragQuery } from "../../lib/rag-pipeline";

const geminiApiKey = defineSecret("GEMINI_API_KEY");

    timeoutSeconds: 60,
    cors: true,
    maxInstances: 10,
  },
  async (req, res) => {
    if (req.method \!== "POST") {
      res.status(405).json({ error: "Method not allowed" });

    if (\!query || typeof query \!== "string") {

        sources: result.sources,
        metadata: {
          tokensUsed: result.tokensUsed,
          sourcesCount: result.sources.length,
        },
      });
    } catch (error) {
      console.error("RAG query failed:", error);
      res.status(500).json({ error: "Internal server error" });
    }
  }
```

## Cost Optimization and Performance Tuning

### Understanding the Cost Structure

This system has three main cost components.

**Firestore storage costs:**
768-dimension vector = 768 × 4 bytes (float32) = 3,072 bytes per document. For 100K documents, that's roughly 292MB of vector data. At Firestore's storage rate of $0.18/GB/month, the vector portion alone costs about $0.05/month.

**Gemini Embeddings API costs:**
text-embedding-004 has a generous free tier (1,500 RPM with daily limits), so medium-sized applications can often operate entirely within the free tier. Beyond that, pricing is just $0.00001 per 1,000 characters.

**Gemini Pro generation costs:**
Each RAG query incurs charges for input tokens (context + query) and output tokens. With Gemini 2.5 Pro, that's $1.25/million input tokens and $10/million output tokens.

### Cost Reduction Techniques

```typescript
// lib/cost-optimization.ts
import { createHash } from "crypto";

/**
 * Embedding cache (prevents regenerating identical texts)
 * Stores cache in a Firestore subcollection
 */
export async function getOrCreateEmbedding(
  text: string,
  taskType: "RETRIEVAL_DOCUMENT" | "RETRIEVAL_QUERY"
): Promise<number[]> {
  const cacheKey = createHash("sha256")
    .update(`${taskType}:${text}`)
    .digest("hex");

  // Check cache
  const cacheRef = db.collection("embedding_cache").doc(cacheKey);
  const cached = await cacheRef.get();

  if (cached.exists) {
    return cached.data()\!.vector;
  }

  // Cache miss: generate new embedding
  const vector = await generateEmbedding(text, taskType);

  // Save to cache (TTL: 30 days)
  await cacheRef.set({
    vector,
    text: text.slice(0, 100), // First 100 chars for debugging
    taskType,
    createdAt: FieldValue.serverTimestamp(),
    expiresAt: new Date(Date.now() + 30 * 24 * 60 * 60 * 1000),
  });

  return vector;
}

/**
 * Dimension reduction for cost optimization
 * 768 dimensions → 256 dimensions
 * Reduces storage costs by ~66%
 */
export function reduceDimensions(
  vector: number[],
  targetDim: number = 256
): number[] {
  // text-embedding-004 supports the outputDimensionality parameter
  // for server-side dimension reduction (recommended)
  // Client-side truncation uses the first N dimensions
  // (effective for Matryoshka Representation Learning compatible models)
  return vector.slice(0, targetDim);
}
```

## Production Best Practices

### Security

Use Firestore Security Rules to restrict direct access to vector fields. Embeddings are for internal processing and should not be exposed to clients.

```javascript
// firestore.rules
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /documents/{docId} {
      // Read: authenticated users only
      allow read: if request.auth \!= null;
      // Write: clients cannot write embedding fields
      allow create: if request.auth \!= null
        && \!("embedding" in request.resource.data);
      allow update: if request.auth \!= null
        && \!("embedding" in request.resource.data);
    }
    // Embedding cache is server-only
    match /embedding_cache/{cacheId} {
      allow read, write: if false;
    }
  }
}
```

### Error Handling and Fallback

```typescript
/**
 * RAG query with fallback
 * Falls back to text search if vector search fails
 */
export async function ragQueryWithFallback(
  query: string,
  collectionName: string
): Promise<RAGResponse> {
  try {
    // 1. Try vector search
    return await ragQuery(query, collectionName);
  } catch (vectorError) {
    console.warn("Vector search failed, falling back to text search:", vectorError);

    try {
      // 2. Text-based fallback search
      const snapshot = await db
        .collection(collectionName)
        .orderBy("createdAt", "desc")
        .limit(5)
        .get();

      // Simple keyword matching filter
      const keywords = query.toLowerCase().split(/\s+/);
      const matched = snapshot.docs.filter((doc) => {
        const data = doc.data();
        const text = `${data.title} ${data.content}`.toLowerCase();
        return keywords.some((kw) => text.includes(kw));
      });

      if (matched.length === 0) {
        return {
          answer: "The search service is currently experiencing issues. Please try again shortly.",
          sources: [],
          tokensUsed: 0,
        };
      }

      // Generate answer from fallback results
      const context = matched
        .map((doc) => `### ${doc.data().title}\n${doc.data().content}`)
        .join("\n\n");

      const model = genAI.getGenerativeModel({
        model: "gemini-2.5-flash-preview-04-17",
      });
      const result = await model.generateContent(
        `Based on the following information, answer the question.\n\n${context}\n\nQuestion: ${query}`
      );

      return {
        answer: result.response.text(),
        sources: matched.map((doc) => ({
          id: doc.id,
          title: doc.data().title,
          score: 0,
        })),
        tokensUsed: result.response.usageMetadata?.totalTokenCount || 0,
      };
    } catch (fallbackError) {
      console.error("Fallback search also failed:", fallbackError);
      throw fallbackError;
    }
  }
}
```

### Scaling Guidelines

Here are guidelines for scaling your system in production.

**Under 10K documents:** Firestore's flat index is sufficient. Expect 50–100ms latency.

**10K–1M documents:** Consider composite index optimization, dimension reduction (768→256), and embedding caching. Target latency: under 200ms.

**Over 1M documents:** Firestore alone may become a bottleneck at this scale. Consider migrating to Vertex AI Vector Search or a hybrid architecture (Firestore metadata + dedicated vector DB).
