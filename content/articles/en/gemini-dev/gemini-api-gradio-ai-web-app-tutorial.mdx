## Why Gradio Is the Fastest Way to Ship AI Apps

No matter how powerful an AI model is, it delivers no value without a UI that users can interact with. When you want to quickly turn your Gemini API features into a shareable web app, **Gradio** — a Python UI framework — is one of the best options available.

With Gradio, you can build functional AI web apps in just a few dozen lines of Python — no frontend experience required. Here's what you can create:

- Text generation and summarization apps
- Image upload and AI analysis tools
- Real-time chatbots with conversation history
- Document upload and parsing interfaces

In this tutorial, we'll build **three practical apps** step by step using Gemini API and Gradio, then deploy them to Hugging Face Spaces. If you're new to the Gemini API, check out our [Gemini API Quickstart Guide](/en/articles/gemini-api/gemini-api-quickstart) first.

## App 1 — Text Summarization Tool

Let's start with a simple app that uses Gemini to summarize user-provided text.

```python
import os
import gradio as gr
from google import genai

# Initialize the Gemini client
client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])

def summarize_text(text: str, style: str) -> str:
    """Summarize text in the specified style"""
    prompt = f"""Summarize the following text in a {style} tone.
List 3-5 key points as bullet items, then provide a one-sentence conclusion.

Text:
{text}
"""
    response = client.models.generate_content(
        model="gemini-2.5-flash",
        contents=prompt,
    )
    return response.text

# Define the Gradio UI
demo = gr.Interface(
    fn=summarize_text,
    inputs=[
        gr.Textbox(
            label="Text to Summarize",
            placeholder="Paste your text here...",
            lines=10,
        ),
        gr.Radio(
            choices=["Business", "Casual", "Technical"],
            label="Summary Style",
            value="Business",
        ),
    ],
    outputs=gr.Markdown(label="Summary"),
    title="Gemini Text Summarizer",
    description="Quickly summarize any text using Gemini API.",
)

# Expected output:
# A web UI opens in the browser with a text input area
# and style selector. Gemini generates summaries instantly.

demo.launch()
```

Save this as `app_summary.py` and run `python app_summary.py`. A summarization app will appear in your browser. You can customize the input fields and output format simply by changing the `gr.Interface` arguments.

## App 2 — Image Analysis Chat

Next, let's leverage Gemini's multimodal capabilities to build an app that analyzes uploaded images and answers questions about them.

```python
import os
import gradio as gr
from google import genai
from PIL import Image

client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])

def analyze_image(image: Image.Image, question: str) -> str:
    """Analyze an uploaded image and answer questions about it"""
    if image is None:
        return "Please upload an image first."

    prompt = question if question else "Describe this image in detail."

    response = client.models.generate_content(
        model="gemini-2.5-flash",
        contents=[prompt, image],
    )
    return response.text

demo = gr.Interface(
    fn=analyze_image,
    inputs=[
        gr.Image(type="pil", label="Image to Analyze"),
        gr.Textbox(
            label="Question (optional)",
            placeholder="e.g., What food is shown and what's its approximate calorie count?",
        ),
    ],
    outputs=gr.Markdown(label="Analysis"),
    title="Gemini Image Analyzer",
    description="Upload an image and let Gemini analyze its contents.",
    examples=[
        ["https://upload.wikimedia.org/wikipedia/commons/thumb/a/a7/Camponotus_flavomarginatus_ant.jpg/320px-Camponotus_flavomarginatus_ant.jpg", "What creature is shown in this image?"],
    ],
)

# Expected output:
# An image upload area and text input field appear.
# Uploading an image triggers Gemini's multimodal analysis.

demo.launch()
```

Gemini 2.5 Flash handles images and text simultaneously — just pass them as a list to `contents` and multimodal inference kicks in automatically. For more advanced multimodal techniques, check out [Gemini API Multimodal Techniques Collection](/en/articles/gemini-api/gemini-api-multimodal-techniques).

## App 3 — Real-Time Chatbot

Gradio's `gr.ChatInterface` makes it incredibly easy to build chatbot UIs. Let's create one with conversation history support.

```python
import os
import gradio as gr
from google import genai

client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])

def chat_with_gemini(message: str, history: list) -> str:
    """Chat with Gemini (with conversation history)"""
    # Convert chat history to Gemini API format
    contents = []
    for user_msg, bot_msg in history:
        contents.append({"role": "user", "parts": [{"text": user_msg}]})
        contents.append({"role": "model", "parts": [{"text": bot_msg}]})
    contents.append({"role": "user", "parts": [{"text": message}]})

    response = client.models.generate_content(
        model="gemini-2.5-flash",
        contents=contents,
        config={
            "system_instruction": "You are a helpful and knowledgeable AI assistant. Respond clearly and concisely.",
        },
    )
    return response.text

demo = gr.ChatInterface(
    fn=chat_with_gemini,
    title="Gemini Chatbot",
    description="A real-time chatbot powered by Gemini API.",
    examples=["What's the most efficient way to learn Python?", "Suggest 3 recipes based on today's weather"],
    theme="soft",
)

# Expected output:
# A chat UI appears. Each message you send receives
# a context-aware response from Gemini.

demo.launch()
```

`gr.ChatInterface` automatically manages conversation history, passing previous exchanges to your function via the `history` parameter as a list of tuples. Converting this to Gemini API's `contents` format is all it takes to enable multi-turn conversations.

## Customizing UI with Gradio Blocks

When you need more layout flexibility, use `gr.Blocks` to build custom interfaces. Here's a **tabbed app** that combines text summarization and image analysis:

```python
import os
import gradio as gr
from google import genai
from PIL import Image

client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])

def summarize(text: str) -> str:
    response = client.models.generate_content(
        model="gemini-2.5-flash",
        contents=f"Summarize the following text:\n{text}",
    )
    return response.text

def analyze(image: Image.Image) -> str:
    if image is None:
        return "Please select an image."
    response = client.models.generate_content(
        model="gemini-2.5-flash",
        contents=["Analyze this image in detail.", image],
    )
    return response.text

with gr.Blocks(title="Gemini AI Toolkit", theme=gr.themes.Soft()) as demo:
    gr.Markdown("# Gemini AI Toolkit")
    gr.Markdown("A collection of AI tools powered by Gemini API.")

    with gr.Tabs():
        with gr.TabItem("Text Summarization"):
            text_input = gr.Textbox(label="Text", lines=8)
            text_btn = gr.Button("Summarize", variant="primary")
            text_output = gr.Markdown(label="Result")
            text_btn.click(fn=summarize, inputs=text_input, outputs=text_output)

        with gr.TabItem("Image Analysis"):
            img_input = gr.Image(type="pil", label="Image")
            img_btn = gr.Button("Analyze", variant="primary")
            img_output = gr.Markdown(label="Result")
            img_btn.click(fn=analyze, inputs=img_input, outputs=img_output)

# Expected output:
# A tabbed UI with "Text Summarization" and "Image Analysis"
# tabs, each with their own input/output areas.

demo.launch()
```

With `gr.Blocks`, you can combine row/column layouts (`gr.Row`, `gr.Column`), accordions (`gr.Accordion`), and more to build complex interfaces entirely in Python.

## Gradio vs. Streamlit — Which Should You Choose?

Gradio and **Streamlit** are the two most popular Python UI frameworks for AI apps. Here's how they compare:

- **Gradio**: Purpose-built for ML demos. Define inputs and outputs with `gr.Interface` and you're done. Tight integration with Hugging Face makes it ideal for model showcases.
- **Streamlit**: Designed for general-purpose data apps. Stronger for dashboards and data visualization. Has its own deployment platform (Streamlit Cloud).

As a rule of thumb, **choose Gradio for AI model demos and prototypes**, and **Streamlit for data dashboards and complex business apps**. To learn about building AI apps with Streamlit, see [Rapid AI Web App Prototyping with Gemini API and Streamlit](/en/articles/gemini-dev/gemini-api-streamlit-ai-web-app-rapid-prototyping).

## Basic Implementation — Calling Gemini API from Django Views

A clean architecture separates the AI logic into a service layer, keeping your views simple and testable.

```python
# ai_chat/services.py
from google import genai
from django.conf import settings

# Initialize client at module level to avoid re-creation per request
client = genai.Client(api_key=settings.GEMINI_API_KEY)

def generate_response(prompt: str, model: str = "gemini-2.5-flash") -> str:
    """Send a prompt to Gemini API and return the text response."""
    response = client.models.generate_content(
        model=model,
        contents=prompt,
    )
    return response.text
```

Now create a view that uses this service:

```python
# ai_chat/views.py
import json
from django.http import JsonResponse
from django.views.decorators.csrf import csrf_exempt
from django.views.decorators.http import require_http_methods
from .services import generate_response

@csrf_exempt
@require_http_methods(["POST"])
def chat_api(request):
    """AI chat API endpoint."""
    try:
        body = json.loads(request.body)
        user_message = body.get("message", "")

        if not user_message:
            return JsonResponse({"error": "Message is required"}, status=400)

        # Call Gemini API
        ai_response = generate_response(user_message)

        return JsonResponse({
            "response": ai_response,
            "model": "gemini-2.5-flash",
        })

    except Exception as e:
        return JsonResponse({"error": str(e)}, status=500)
```

Wire up the URL configuration:

```python
# ai_chat/urls.py
from django.urls import path
from . import views

urlpatterns = [
    path('api/chat/', views.chat_api, name='chat_api'),
]

# mysite/urls.py
from django.urls import path, include

urlpatterns = [
    path('', include('ai_chat.urls')),
]
```

You now have a working endpoint at `POST /api/chat/` that accepts a message and returns a Gemini API response.

## Multi-Turn Conversations — Managing Chat History with Sessions

A useful chat application needs to maintain conversation context. Django's built-in session framework makes this straightforward.

```python
# ai_chat/services.py (extended)
from google import genai
from google.genai import types
from django.conf import settings

client = genai.Client(api_key=settings.GEMINI_API_KEY)

def generate_chat_response(
    message: str,
    history: list[dict],
    model: str = "gemini-2.5-flash"
) -> str:
    """Call Gemini API with conversation history for context."""
    # Convert history to Gemini API format
    contents = []
    for entry in history:
        contents.append(
            types.Content(
                role=entry["role"],
                parts=[types.Part(text=entry["text"])]
            )
        )
    # Add the current user message
    contents.append(
        types.Content(
            role="user",
            parts=[types.Part(text=message)]
        )
    )

    response = client.models.generate_content(
        model=model,
        contents=contents,
    )
    return response.text
```

Update the view to persist conversation history in the session:

```python
# ai_chat/views.py (extended)
import json
from django.http import JsonResponse
from django.views.decorators.csrf import csrf_exempt
from django.views.decorators.http import require_http_methods
from .services import generate_chat_response

@csrf_exempt
@require_http_methods(["POST"])
def chat_api(request):
    """Multi-turn chat API endpoint with session-based history."""
    try:
        body = json.loads(request.body)
        user_message = body.get("message", "")

        if not user_message:
            return JsonResponse({"error": "Message is required"}, status=400)

        # Retrieve conversation history from session
        history = request.session.get("chat_history", [])

        # Call Gemini API with context
        ai_response = generate_chat_response(user_message, history)

        # Update history
        history.append({"role": "user", "text": user_message})
        history.append({"role": "model", "text": ai_response})

        # Keep only the last 20 entries to prevent session bloat
        if len(history) > 20:
            history = history[-20:]

        request.session["chat_history"] = history

        return JsonResponse({
            "response": ai_response,
            "history_length": len(history),
        })

    except Exception as e:
        return JsonResponse({"error": str(e)}, status=500)

@csrf_exempt
@require_http_methods(["POST"])
def reset_chat(request):
    """Clear conversation history."""
    request.session["chat_history"] = []
    return JsonResponse({"status": "reset"})
```

Django's session middleware automatically handles per-user session management via cookies, so each user maintains their own independent conversation history. For production deployments, consider using Redis or a database-backed session engine for better scalability.

For more advanced patterns like long-term memory and large-scale chatbot architecture, check out [Long-Term Memory and Session Persistence for Gemini API](/en/articles/gemini-advanced/gemini-api-long-memory-session-persistence-chatbot-architecture) for a deeper dive.

## Streaming Responses — Delivering Real-Time AI Output to the Browser

To create a ChatGPT-like experience where tokens appear progressively, you need streaming. Django's `StreamingHttpResponse` handles this well.

```python
# ai_chat/services.py (streaming support)
def generate_stream_response(
    message: str,
    history: list[dict],
    model: str = "gemini-2.5-flash"
):
    """Stream Gemini API response as a generator."""
    contents = []
    for entry in history:
        contents.append(
            types.Content(
                role=entry["role"],
                parts=[types.Part(text=entry["text"])]
            )
        )
    contents.append(
        types.Content(
            role="user",
            parts=[types.Part(text=message)]
        )
    )

    response = client.models.generate_content_stream(
        model=model,
        contents=contents,
    )

    for chunk in response:
        if chunk.text:
            yield chunk.text
```

Deliver the stream as Server-Sent Events (SSE):

```python
# ai_chat/views.py (streaming endpoint)
import json
from django.http import StreamingHttpResponse
from .services import generate_stream_response

@csrf_exempt
@require_http_methods(["POST"])
def chat_stream_api(request):
    """SSE streaming endpoint for real-time AI responses."""
    body = json.loads(request.body)
    user_message = body.get("message", "")
    history = request.session.get("chat_history", [])

    def event_stream():
        full_response = ""
        for chunk_text in generate_stream_response(user_message, history):
            full_response += chunk_text
            # Send each chunk in SSE format
            yield f"data: {json.dumps({'text': chunk_text})}\n\n"

        # Signal stream completion
        yield f"data: {json.dumps({'done': True})}\n\n"

    response = StreamingHttpResponse(
        event_stream(),
        content_type='text/event-stream'
    )
    response['Cache-Control'] = 'no-cache'
    response['X-Accel-Buffering'] = 'no'
    return response
```

On the frontend, consume the stream with the Fetch API:

```javascript
// Frontend streaming example
async function sendMessage(message) {
  const response = await fetch('/api/chat/stream/', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ message }),
  });

  const reader = response.body.getReader();
  const decoder = new TextDecoder();

  while (true) {
    const { done, value } = await reader.read();
    if (done) break;

    const text = decoder.decode(value);
    const lines = text.split('\n');

    for (const line of lines) {
      if (line.startsWith('data: ')) {
        const data = JSON.parse(line.slice(6));
        if (data.done) break;
        // Append text to chat UI
        appendToChat(data.text);
      }
    }
  }
}
```

## Production Readiness — Security and Performance Considerations

Before deploying your Django + Gemini API application to production, there are several important considerations to address.

**API Key Protection**: Beyond environment variables, implement rate-limiting middleware to prevent abuse. Django REST Framework's throttling classes make it easy to set per-IP or per-user request limits.

**Async Views for Better Throughput**: Since Django 4.1, async views are fully supported. Gemini API calls are I/O-bound operations, making them ideal candidates for async execution:

```python
# Async view example
import json
from django.http import JsonResponse
from asgiref.sync import sync_to_async

async def async_chat_api(request):
    """Async chat API endpoint for improved throughput."""
    body = json.loads(request.body)
    user_message = body.get("message", "")

    # Run sync function asynchronously
    ai_response = await sync_to_async(generate_response)(user_message)

    return JsonResponse({"response": ai_response})
```

**Celery for Background Tasks**: For long-running AI operations like batch document analysis or large-scale content generation, offload work to a Celery task queue. This keeps your web server responsive while heavy AI processing happens in the background.

**Robust Error Handling**: Implement retry logic with exponential backoff and graceful degradation for API failures. For a comprehensive guide to production error handling patterns, see [Gemini API Error Handling and Rate Limiting Deep Dive](/en/articles/gemini-dev/gemini-api-error-handling-rate-limit-production-patterns).
