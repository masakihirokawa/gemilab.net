## Introduction: Why SvelteKit and Gemini API Work So Well Together

When building an AI chat application, your choice of framework has a big impact on both the developer experience and the final product quality. **SvelteKit** has been gaining serious traction as a full-stack framework, thanks to its minimal footprint, fast server-side rendering, and elegantly simple reactivity system. Pair that with **Gemini API's** streaming responses, and you have a remarkably efficient foundation for building real-time AI chat experiences.

In this guide, you'll learn how to:

- Integrate the Gemini API into a SvelteKit project
- Safely manage your API key on the server side
- Implement streaming responses and reflect them in real time via Svelte state
- Handle multi-turn conversations with chat history
- Deploy to Vercel or Cloudflare Pages

**Who this is for**: Developers who are comfortable with TypeScript and have a basic understanding of SvelteKit's project structure. No prior Gemini API experience required.

---

## Why SvelteKit Is a Great Choice for AI Chat Apps

Compared to Next.js or Nuxt.js, SvelteKit offers some distinct advantages for this use case.

**Smaller bundle size**: Svelte compiles your components to plain JavaScript at build time, with no virtual DOM runtime overhead. This means the JS shipped to the browser is significantly smaller, translating to faster initial load times.

**Clean server/client separation**: SvelteKit's `+server.ts` files let you keep your API key safely on the server while making it seamless to stream data to the frontend — exactly what you need for a chat interface.

**Minimal reactivity boilerplate**: With Svelte 5's `$state` rune, updating the UI as streaming tokens arrive requires almost no extra code.

These characteristics make SvelteKit an excellent match for **Gemini API's streaming architecture**.

Visit [Google AI Studio](https://aistudio.google.com/) and click "Get API key" to generate your key. Keep it somewhere safe.

### Creating a SvelteKit Project

```bash
# Create a new SvelteKit project (TypeScript + ESLint)
npm create svelte@latest my-gemini-chat
cd my-gemini-chat
npm install

# Install the Google Generative AI SDK
npm install @google/generative-ai
```

When prompted during project setup, choose "Skeleton project" (not the demo app) and enable TypeScript.

### Setting Up Environment Variables

Create a `.env` file in your project root:

```bash
# .env — never commit this to Git
GEMINI_API_KEY=YOUR_GEMINI_API_KEY
```

> ⚠️ In SvelteKit, environment variables without the `VITE_` prefix are accessible **only on the server**. By keeping `GEMINI_API_KEY` without a prefix, you ensure it never leaks to the client bundle.

## Implementing the Server-Side API Endpoint

Create `src/routes/api/chat/+server.ts` to handle communication with Gemini:

```typescript
// src/routes/api/chat/+server.ts
import { GoogleGenerativeAI } from '@google/generative-ai';
import { GEMINI_API_KEY } from '$env/static/private';
import type { RequestHandler } from './$types';

const genAI = new GoogleGenerativeAI(GEMINI_API_KEY);

export const POST: RequestHandler = async ({ request }) => {
  const { messages } = await request.json();

  // Gemini 2.5 Flash — fast responses and cost-efficient
  const model = genAI.getGenerativeModel({ model: 'gemini-2.5-flash' });

  // Convert chat history to Gemini's expected format
  const history = messages.slice(0, -1).map((msg: { role: string; content: string }) => ({
    role: msg.role === 'user' ? 'user' : 'model',
    parts: [{ text: msg.content }],
  }));

  const chat = model.startChat({ history });
  const lastMessage = messages[messages.length - 1].content;

  // Generate a streaming response
  const result = await chat.sendMessageStream(lastMessage);

  // Deliver chunks to the client via a ReadableStream
  const stream = new ReadableStream({
    async start(controller) {
      const encoder = new TextEncoder();
      for await (const chunk of result.stream) {
        const text = chunk.text();
        if (text) {
          controller.enqueue(encoder.encode(`data: ${JSON.stringify({ text })}\n\n`));
        }
      }
      controller.enqueue(encoder.encode('data: [DONE]\n\n'));
      controller.close();
    },
  });

  return new Response(stream, {
    headers: {
      'Content-Type': 'text/event-stream',
      'Cache-Control': 'no-cache',
      Connection: 'keep-alive',
    },
  });
};
```

The key here is using `sendMessageStream()` to enable streaming, then delivering each token chunk in **Server-Sent Events (SSE)** format. This lets the browser receive and display text as it's generated, rather than waiting for the full response.

## Building the Chat UI in Svelte

Now create the front-end chat interface in `src/routes/+page.svelte`:

```svelte
<!-- src/routes/+page.svelte -->
<script lang="ts">
  let messages = $state<{ role: 'user' | 'assistant'; content: string }[]>([]);
  let input = $state('');
  let isStreaming = $state(false);

  async function sendMessage() {
    if (!input.trim() || isStreaming) return;

    const userMessage = input.trim();
    input = '';
    messages.push({ role: 'user', content: userMessage });
    messages.push({ role: 'assistant', content: '' });
    isStreaming = true;

    const assistantIndex = messages.length - 1;

    try {
      const response = await fetch('/api/chat', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ messages: messages.slice(0, -1) }),
      });

      // Read the SSE stream
      const reader = response.body!.getReader();
      const decoder = new TextDecoder();

      while (true) {
        const { done, value } = await reader.read();
        if (done) break;

        const text = decoder.decode(value);
        const lines = text.split('\n').filter(l => l.startsWith('data: '));

        for (const line of lines) {
          const data = line.replace('data: ', '');
          if (data === '[DONE]') break;
          const parsed = JSON.parse(data);
          messages[assistantIndex].content += parsed.text;
        }
        // Trigger Svelte reactivity
        messages = [...messages];
      }
    } catch (error) {
      console.error('Chat error:', error);
      messages[assistantIndex].content = 'Something went wrong. Please try again.';
    } finally {
      isStreaming = false;
    }
  }
</script>

<main class="chat-container">
  <div class="messages">
    {#each messages as msg}
      <div class="message {msg.role}">
        <p>{msg.content}</p>
      </div>
    {/each}
    {#if isStreaming}
      <div class="typing-indicator">Gemini is typing...</div>
    {/if}
  </div>

  <form on:submit|preventDefault={sendMessage} class="input-area">
    <input
      type="text"
      bind:value={input}
      placeholder="Type a message..."
      disabled={isStreaming}
    />
    <button type="submit" disabled={isStreaming || !input.trim()}>
      Send
    </button>
  </form>
</main>
```

This implementation uses Svelte 5's `$state` runes for reactive state management. The `messages = [...messages]` spread ensures Svelte detects the array mutation and re-renders the component. This pattern is clean and avoids the more verbose store-based approaches used in earlier Svelte versions.

## Deploying to Vercel or Cloudflare Pages

### Deploying to Vercel

```bash
npm install -D @sveltejs/adapter-vercel
```

Update `svelte.config.js`:

```javascript
// svelte.config.js
import adapter from '@sveltejs/adapter-vercel';
import { vitePreprocess } from '@sveltejs/vite-plugin-svelte';

export default {
  preprocess: vitePreprocess(),
  kit: {
    adapter: adapter()
  }
};
```

Add `GEMINI_API_KEY` to your Vercel project's "Environment Variables" settings, then run `vercel deploy`.

### Deploying to Cloudflare Pages

```bash
npm install -D @sveltejs/adapter-cloudflare
```

Switch the adapter in `svelte.config.js` to `@sveltejs/adapter-cloudflare`, then add your key in the Cloudflare Dashboard under Pages → Settings → Environment variables.

> 💡 Keep an eye on Gemini API **rate limits** in production. Depending on your plan, you may hit request-per-minute caps during traffic spikes. For more advanced production patterns — including caching, retry logic, and API key rotation — see [Gemini API × Next.js 15 App Router Full-Stack Production Guide](/articles/gemini-dev/gemini-api-nextjs15-app-router-fullstack-production).

## Error Handling and Rate Limit Management

Production AI apps need robust error handling. Here's a practical pattern to handle the most common failure modes:

```typescript
// Enhanced server-side error handling
export const POST: RequestHandler = async ({ request }) => {
  try {
    const { messages } = await request.json();
    if (!messages?.length) {
      return new Response(JSON.stringify({ error: 'No messages provided' }), { status: 400 });
    }

    const model = genAI.getGenerativeModel({
      model: 'gemini-2.5-flash',
      generationConfig: { maxOutputTokens: 2048, temperature: 0.7 },
    });

    const history = messages.slice(0, -1).map((msg: { role: string; content: string }) => ({
      role: msg.role === 'user' ? 'user' : 'model',
      parts: [{ text: msg.content }],
    }));

    const chat = model.startChat({ history });
    const result = await chat.sendMessageStream(messages.at(-1).content);

    const stream = new ReadableStream({
      async start(controller) {
        const encoder = new TextEncoder();
        try {
          for await (const chunk of result.stream) {
            const text = chunk.text();
            if (text) controller.enqueue(encoder.encode(`data: ${JSON.stringify({ text })}\n\n`));
          }
          controller.enqueue(encoder.encode('data: [DONE]\n\n'));
        } catch {
          controller.enqueue(encoder.encode(`data: ${JSON.stringify({ error: 'Stream error' })}\n\n`));
        } finally {
          controller.close();
        }
      },
    });

    return new Response(stream, {
      headers: { 'Content-Type': 'text/event-stream', 'Cache-Control': 'no-cache' },
    });
  } catch (error: unknown) {
    const msg = error instanceof Error ? error.message : 'Internal server error';
    const status = msg.includes('429') ? 429 : 500;
    return new Response(JSON.stringify({ error: msg }), { status });
  }
};
```

On the client side, always check `response.ok` before reading the stream — and surface rate-limit errors (HTTP 429) with a user-friendly message rather than a generic failure notice.

## Frequently Asked Questions

**Q1. How does SvelteKit compare to Next.js or Nuxt.js for this use case?**

SvelteKit produces the smallest client-side bundles of the three, since Svelte compiles away its reactivity system at build time. For a chat interface with frequent real-time DOM updates, this lightweight footprint translates to a noticeably snappier experience. That said, Next.js has a larger ecosystem and is more familiar to most teams. Choose based on your team's existing expertise and project requirements.

**Q2. Which Gemini model should I use for a chat app?**

**Gemini 2.5 Flash** is the best starting point — it's fast, cost-efficient, and handles conversational tasks extremely well. If your app needs complex reasoning or longer context windows, consider upgrading to **Gemini 2.5 Pro** or **Gemini 3 Pro**. For a detailed breakdown of model trade-offs, see the [Gemini Model Selection Guide](/articles/gemini-basics/gemini-model-selection-guide).

**Q3. How do I persist chat history across sessions?**

For basic persistence, `localStorage` works fine for single-user scenarios. For multi-device sync or multi-user apps, connect to **Supabase** or **Firebase** and serialize the `messages` array to your database. On page load, fetch the stored history and pass it directly to `startChat({ history })` to restore the conversation context seamlessly.
