When I got my Gemini API key for the first time, I stared at the docs for way too long. The documentation is thorough, but there's no clear map of what to try first. It took me a few days of scattered experimentation before I understood the basic shape of how the API works.

These 4 code examples are what I wish I'd run in sequence from the start. Text generation, streaming, image analysis, and structured output — each one teaches you something different about how Gemini thinks about input and output.

---

## Setup: Install the Package and Configure Your API Key

Start with the `google-genai` package.

```bash
pip install google-genai
```

Get your API key from [Google AI Studio](https://aistudio.google.com/app/apikey). Store it as an environment variable — never hardcode it in your scripts.

```bash
export GEMINI_API_KEY="YOUR_GEMINI_API_KEY"
```

Initialize the client once at the top of your script or application:

```python
import os
from google import genai

client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])
```

Reuse this `client` object throughout your code. Re-initializing it on every request wastes resources and can cause unexpected behavior in async contexts.

## 1. Text Generation: Just Get It Running

The simplest pattern. Pass a prompt, get a response.

```python
import os
from google import genai

client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])

# Basic text generation
response = client.models.generate_content(
    model="gemini-2.0-flash",
    contents="What's the most common way to read a file in Python?"
)

print(response.text)
# Example output:
# The most common way to read a file in Python is using the `with open()` syntax...
```

`gemini-2.0-flash` is a good starting point. It's fast, generous in the free tier, and precise enough for most tasks. When you need higher reasoning quality, switching to `gemini-2.5-pro` is literally a one-line change.

### What this teaches you

- The minimum viable call to `generate_content()`
- How to extract text from the response object with `response.text`
- How model names are specified

If something goes wrong, replace `print(response.text)` with `print(response)` to inspect the full response object. Safety filter blocks and auth errors surface there.

## 2. Streaming: Get Responses as They're Generated

Instead of waiting for the full response, streaming lets you process chunks as they arrive. This matters a lot for chat apps, CLI tools, and anything where perceived latency is important.

```python
import os
from google import genai

client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])

# Stream the response in real time
for chunk in client.models.generate_content_stream(
    model="gemini-2.0-flash",
    contents="Explain Python's asyncio module in about 200 words."
):
    # Guard against None — the final chunk or safety info chunks can be None
    if chunk.text:
        print(chunk.text, end="", flush=True)

print()  # Add newline at the end
# Output appears incrementally as the model generates it
```

The most common streaming mistake is not guarding against `chunk.text` being `None`. The last chunk and any safety-related chunks return `None`, and forgetting this guard causes an `AttributeError` or `TypeError` at the end of otherwise-working code.

### When to use streaming vs. regular generation

Use streaming when:
- You're building a user-facing interface where wait time is noticeable
- Responses are long (500+ words)
- You're sending output over WebSocket or SSE

Stick with regular `generate_content()` when you need the full text before doing anything with it — writing to a file, parsing JSON, or chaining requests.

## 3. Image Analysis: Your First Multimodal Call

Gemini's multimodal capabilities are one of its biggest differentiators. The entry point is simpler than you might expect — just pass image bytes alongside your text prompt.

```python
import os
from pathlib import Path
from google import genai
from google.genai import types

client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])

# Load a local image (PNG, JPEG, WebP, HEIC are all supported)
image_path = Path("sample.jpg")  # Replace with your image path
image_data = image_path.read_bytes()

response = client.models.generate_content(
    model="gemini-2.0-flash",
    contents=[
        types.Part.from_bytes(data=image_data, mime_type="image/jpeg"),
        "Describe what's in this image in detail."
    ]
)

print(response.text)
# Example output (depends on your image):
# The image shows a coffee mug on a wooden desk. The mug is white...
```

The key pattern here is making `contents` a list, mixing image parts and text parts. The `mime_type` argument tells Gemini how to interpret the bytes.

### Ideas worth trying immediately

- Drop in a screenshot of a UI and ask "What accessibility issues do you see?"
- Use a photo of handwritten notes and ask for a clean transcription
- Pass a product photo and ask for a marketing description

When I first tried this with an app screenshot, asking for specific accessibility feedback, the response was detailed enough that I actually used some of it in a real code review. That's when I started taking the multimodal feature seriously.

## 4. Structured Output: Reliable JSON Without the Cleanup

If you've ever asked a language model to "respond in JSON format" and then spent 20 minutes writing regex to strip Markdown code fences — this one is for you.

Gemini's structured output feature enforces a JSON schema on the response, so you get parseable JSON directly.

```python
import os
from google import genai
from google.genai import types
import json

client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])

# Define a schema and request structured output
response = client.models.generate_content(
    model="gemini-2.0-flash",
    contents="List 3 Python data types with their names and a brief description.",
    config=types.GenerateContentConfig(
        response_mime_type="application/json",
        response_schema={
            "type": "array",
            "items": {
                "type": "object",
                "properties": {
                    "name": {"type": "string"},
                    "description": {"type": "string"}
                },
                "required": ["name", "description"]
            }
        }
    )
)

# response.text is already valid JSON — no stripping needed
data = json.loads(response.text)
for item in data:
    print(f"{item['name']}: {item['description']}")

# Example output:
# int: Represents whole numbers without decimal points
# str: Represents sequences of characters (text)
# list: An ordered, mutable collection of items
```

Setting `response_mime_type="application/json"` combined with `response_schema` guarantees schema-compliant JSON in `response.text`. No `strip()` calls, no regex, no hoping the model followed your instructions.

### Where structured output makes the biggest difference

- Saving API responses directly to a database
- Feeding model output into downstream code that expects typed data
- Building pipelines where a human won't be reviewing every response

In my experience, structured output is the single biggest quality-of-life improvement once you move from experimenting to actually shipping something. The saved time from not debugging malformed JSON adds up quickly.

## What These 4 Examples Actually Show You

Running them in order gives you a practical map of Gemini's core capabilities:

**Streaming is easier than it looks.** The method name changes, but the mental model stays the same. Once you've written it once, it becomes automatic.

**Multimodal has almost no friction.** There's no special preprocessing pipeline — you pass bytes with a mime type and ask your question. The hard part is figuring out *what to ask*, not how to ask it.

**Structured output is table stakes for production.** Relying on prompt instructions for JSON is too fragile at scale. If you're building anything that processes model output programmatically, use this from day one.

**Switching models is one line.** This makes it easy to calibrate your intuition for cost vs. quality. Try the same prompt on Flash and Pro and see if you can tell the difference for your specific use case.
