The Gemini API is mature, but the moment you push it at near-production scale, error handling becomes the job. Two different root causes hide behind the same 404; a 429 from Free-tier RPM looks identical to a 429 from a project-level quota; a 403 could be a deprecated preview model or a billing flag. Surface-level status codes don't carry enough signal. This handbook is the one I wish I had when I was first running Gemini in production: a symptom-indexed field guide, organized by HTTP status, pointing at the root cause and the specific recovery for each error I've actually hit.

## How to read this handbook

Chapters are HTTP status first. When an error lands, jump to the chapter matching the response status. Each entry is four parts: symptom, where it's happening, how to inspect, how to recover. A final chapter covers retry strategy and observability.

## 1. 401 Unauthorized and 403 Forbidden

### `401 API key not valid` on every call

Either the key is typoed, expired, revoked, or no longer bound to a quota project.

First, verify the key is actually reaching the server. `generativelanguage.googleapis.com` accepts both the `?key=` query parameter and the `x-goog-api-key` header. Some SDKs only send one form — if you're setting the other, the server never sees a key.

If the key string is intact, open AI Studio's API key manager and confirm the key is active and bound to an existing project. Keys whose parent project was deleted are auto-invalidated. Reissue a new one.

### `403 Permission denied` on specific models

Some models gate by region, account tier, or preview status. Preview models (identifiers containing `-preview`) typically require explicit early-access enrollment.

In AI Studio, check the model's "availability" state. If it requires early access, apply — on Vertex AI, enable via Model Access Management.

### `403 Billing not enabled`

You've crossed a Free-tier limit, or you're calling a billable model without a billing account attached. Enable billing on the Google Cloud project and retry.

## 2. 404 Not Found

### `models/gemini-2.5-pro-latest is not found`

Covered in depth in the free companion article: the `-latest` alias is inconsistent in the 2.5 generation. Switch to the base name (`gemini-2.5-pro`) or fully versioned ID (`gemini-2.5-pro-001`). Use `ListModels` to confirm what your key actually resolves.

### Tuned model 404s

Tuned model IDs require a `tunedModels/` prefix (e.g. `tunedModels/my-model-abc123`). Also: tuned models are scoped to the project where they were created. A key from another project cannot see them.

### Uploaded file 404 via the File API

Files uploaded via `files.upload` have a TTL — 2 days at time of writing — after which they're garbage-collected. Referring to an older file returns 404, and that's the correct behavior. For long-lived files, store them yourself (GCS, etc.) and pass `inline_data` instead.

## 3. 429 Resource Exhausted / Quota Exceeded

Gemini quotas are layered: per model, per project, per time window. The first triage step is identifying which layer.

### 429 after a burst of requests

That's the RPM (requests per minute) ceiling. Free-tier `gemini-2.5-flash` is ~15 RPM; `gemini-2.5-pro` is ~2 RPM. Either upgrade the plan or space requests at least four seconds apart.

### 429 later in the day

RPD (requests per day). Free-tier `gemini-2.5-flash` is around 1500/day — obviously insufficient for heavy experimentation. Paid tiers effectively remove the daily cap.

### 429 on large prompts

TPM (tokens per minute). RPM can be fine while token budget blows out on a few long-context calls. Split prompts, or compact conversation history before sending.

### "Quota exceeded for quota metric ... per project"

A project-level quota. Request an increase via Google Cloud Console → IAM & Admin → Quotas. Approval takes hours to days.

## 4. 500 Internal / 503 Service Unavailable

### Intermittent 500s

If only a small fraction of calls fail, treat it as transient model-side noise. But if the same input deterministically returns 500, your prompt is tripping an internal guard (extreme length, unusual tokens, abnormal format). Shorten input and lower `generationConfig.temperature` to bisect.

### Widespread simultaneous 503s

Check Google Cloud Status Dashboard for the region. For region-wide incidents, having a fallback endpoint configured (e.g. a different Vertex regional endpoint) keeps user-facing downtime near zero.

### 504 Gateway Timeout on long calls

Very large contexts (hundreds of thousands of tokens) can exceed the gateway's sync-call window. Switch to `streamGenerateContent`. Streaming improves both perceived latency and the error rate.

## 5. Special 4xx

### `400 Invalid argument: contents`

Format mismatch. The most common case: sending a multi-turn history with `role: "assistant"` or `role: "system"` — other providers' naming. Gemini only accepts `user` / `model` as roles, and system prompts go into the separate `systemInstruction` field.

### `400 Invalid image format`

Either an unsupported format or `mimeType` that doesn't match the actual bytes. Extension spoofing (`.png` named, `.heic` inside) fails validation.

### `413 Request payload too large`

Single-request body caps are in the tens of MB. Inline-embedded images and videos blow past that quickly. Pre-upload via `files.upload` and reference by file ID in the request.

## 6. Not an error, but still broken

### Empty `candidates` array

200 OK, but `candidates` is empty and `promptFeedback.blockReason` says `SAFETY`. The safety filter blocked the response. Tuning `safetySettings` per category (`HARM_CATEGORY_HARASSMENT`, etc.) can unblock legitimate use, but don't globally relax every category — the defaults exist for reasons.

### Streaming cuts midway

SSE connections get killed by middleboxes with aggressive idle timeouts, especially on corporate proxies. Ask infra to extend keep-alive windows, and add a client-side retry-on-disconnect loop so users don't see it.

### Garbled Japanese in responses

Content-Type mismatch with the client's decoder. Explicitly read `response.text()` as UTF-8, or inspect `content-type` on JSON parse.

### CORS errors from the browser

Calling `generativelanguage.googleapis.com` directly from a browser fails CORS — and anyway, shipping the API key in client code is a security antipattern. Proxy through a backend (Cloudflare Workers, Next.js API routes).

## 7. Retry strategy and observability

Given the above, here's the retry policy I use for production.

**Retry**: 429 (quota), 500 (transient), 503 (availability dip), 504 (gateway timeout), streaming disconnects. These recover naturally.

**Do not retry**: 400 (bad input), 401 (auth), 403 (permission), 404 (missing model/resource), 413 (payload too big). Retrying without fixing the root cause just burns quota.

**Backoff**: Exponential with jitter — initial 1s, factor 2, max 30s, ±20% jitter. For 429s, prefer the `Retry-After` header when present.

**Observability**: Track error rate, status-code counters, and latency per model. On my sites I aggregate Gemini responses at the Cloudflare Workers edge and push custom events to Google Analytics — cheap to implement, makes regressions visible within minutes.

## Treat errors as configuration mismatch

The deeper pattern is that most Gemini API errors aren't "the code is wrong." They're "the combination of model, project, network, and quota doesn't match what the code assumes." So the highest-leverage habit isn't memorizing status codes — it's having a lightweight system for seeing what your environment actually looks like.

Call `ListModels` periodically and log the list. Review `gcloud quota list` weekly. Always log `error.details[]` — it carries the structured reason even when the top-level message is generic. With those habits in place, many of the entries in this handbook stop being surprises and start being caught pre-production.

Next time you get a Gemini API error, jump to the chapter that matches the status code, walk the four-step check, and you'll be at root cause in minutes.
