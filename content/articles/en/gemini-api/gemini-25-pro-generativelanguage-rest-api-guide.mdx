## Introduction: Why Use the REST API Directly?

While the Python and JavaScript SDKs are popular ways to access the Gemini API, calling the **REST API directly** is often the better choice in these situations:

- You're working in a language without official SDK support (Go, Rust, PHP, Ruby, Swift, etc.)
- You want to minimize dependencies in your backend service
- You need to quickly test requests with Postman or cURL
- You're building microservices that need lightweight HTTP calls only
- You need low-level control for production infrastructure

## Understanding the Endpoint Structure

The base endpoint for `generativelanguage.googleapis.com` follows this pattern:

```
https://generativelanguage.googleapis.com/v1beta/models/{MODEL_ID}:{METHOD}?key={API_KEY}
```

- **MODEL_ID**: The model name (e.g., `gemini-2.5-pro-latest`)
- **METHOD**: The action to perform (`generateContent`, `streamGenerateContent`, `countTokens`, etc.)

### Gemini 2.5 Pro Endpoint Examples

```
# Non-streaming text generation
POST https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-pro-latest:generateContent?key=YOUR_API_KEY

# Streaming text generation
POST https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-pro-latest:streamGenerateContent?key=YOUR_API_KEY

# Token counting
POST https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-pro-latest:countTokens?key=YOUR_API_KEY
```

## JavaScript (fetch) Implementation

Here's a clean implementation using the native `fetch` API for Node.js or the browser:

```javascript
// gemini-rest-api.js
const API_KEY = process.env.GEMINI_API_KEY;
const MODEL = "gemini-2.5-pro-latest";
const BASE_URL = "https://generativelanguage.googleapis.com/v1beta/models";

/**
 * Generate text using the Gemini 2.5 Pro REST API
 * @param {string} prompt - The user prompt
 * @param {object} options - Generation configuration options
 * @returns {Promise<string>} - The generated text
 */
async function generateText(prompt, options = {}) {
  const url = `${BASE_URL}/${MODEL}:generateContent?key=${API_KEY}`;

  const requestBody = {
    contents: [
      {
        role: "user",
        parts: [{ text: prompt }],
      },
    ],
    generationConfig: {
      temperature: options.temperature ?? 1.0,       // Creativity level (0.0–2.0)
      maxOutputTokens: options.maxTokens ?? 8192,    // Max output tokens
      topP: options.topP ?? 0.95,                    // Sampling probability
    },
  };

  const response = await fetch(url, {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
    },
    body: JSON.stringify(requestBody),
  });

  if (!response.ok) {
    const error = await response.json();
    throw new Error(`Gemini API Error: ${error.error?.message ?? "Unknown error"}`);
  }

  const data = await response.json();
  return data.candidates?.[0]?.content?.parts?.[0]?.text ?? "";
}

// Example usage
(async () => {
  const result = await generateText(
    "Show me a minimal TypeScript REST API server example."
  );
  console.log(result);
})();
```

## Multi-Turn Conversations

With the REST API, you manage conversation history on the client side and send the full history with every request.

```javascript
// Multi-turn chat session
class GeminiChatSession {
  constructor(apiKey, model = "gemini-2.5-pro-latest") {
    this.apiKey = apiKey;
    this.model = model;
    this.history = []; // Conversation history
    this.baseUrl = "https://generativelanguage.googleapis.com/v1beta/models";
  }

  async sendMessage(userMessage) {
    // Add user message to history
    this.history.push({
      role: "user",
      parts: [{ text: userMessage }],
    });

    const url = `${this.baseUrl}/${this.model}:generateContent?key=${this.apiKey}`;

    const response = await fetch(url, {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({
        contents: this.history, // Send full history every time
      }),
    });

    const data = await response.json();
    const assistantMessage = data.candidates?.[0]?.content?.parts?.[0]?.text ?? "";

    // Add model response to history
    this.history.push({
      role: "model",
      parts: [{ text: assistantMessage }],
    });

    return assistantMessage;
  }

  clearHistory() {
    this.history = [];
  }
}

// Usage
const chat = new GeminiChatSession(process.env.GEMINI_API_KEY);

(async () => {
  const reply1 = await chat.sendMessage("What's the difference between JavaScript and TypeScript?");
  console.log("Model:", reply1);

  const reply2 = await chat.sendMessage("What's the trickiest part of migrating an existing project?");
  console.log("Model:", reply2); // The model responds with full conversation context
})();
```

> 💡 As conversation history grows, token usage increases. In production, implement a "window strategy" that trims old messages to stay within token limits. For more on session management patterns, see [Getting Started with the gemini-2.5-pro-latest API](/articles/gemini-api/gemini-25-pro-latest-api-quick-start).

## Streaming Responses

For long outputs, streaming with Server-Sent Events (SSE) provides a much better user experience than waiting for the full response.

```javascript
// Streaming response implementation
async function streamGenerateText(prompt) {
  const url = `${BASE_URL}/${MODEL}:streamGenerateContent?key=${API_KEY}&alt=sse`;

  const response = await fetch(url, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({
      contents: [{ role: "user", parts: [{ text: prompt }] }],
    }),
  });

  if (!response.ok) {
    throw new Error(`HTTP Error: ${response.status}`);
  }

  const reader = response.body.getReader();
  const decoder = new TextDecoder();
  let buffer = "";

  while (true) {
    const { done, value } = await reader.read();
    if (done) break;

    buffer += decoder.decode(value, { stream: true });
    const lines = buffer.split("\n");
    buffer = lines.pop() ?? ""; // Keep the last incomplete line in the buffer

    for (const line of lines) {
      if (line.startsWith("data: ")) {
        const jsonStr = line.slice(6).trim();
        if (jsonStr === "[DONE]") return; // Stream finished
        try {
          const chunk = JSON.parse(jsonStr);
          const text = chunk.candidates?.[0]?.content?.parts?.[0]?.text ?? "";
          if (text) process.stdout.write(text); // Output each chunk as it arrives
        } catch {
          // Ignore JSON parse errors for incomplete chunks
        }
      }
    }
  }
}

// Usage
(async () => {
  await streamGenerateText("Explain how quantum computers work in plain English.");
  console.log("\n--- Done ---");
})();
```

## Common Errors and How to Fix Them

### 400 Bad Request: Invalid Request Format

```json
{
  "error": {
    "code": 400,
    "message": "Request payload size exceeds the limit: 20971520 bytes.",
    "status": "INVALID_ARGUMENT"
  }
}
```

**Cause**: The request size exceeds the 20MB limit (e.g., when attaching large images or videos).

**Fix**:
- Pass images via Google Cloud Storage URLs instead of Base64-encoding them inline
- Split long prompts into smaller chunks

---

### 403 Forbidden: Invalid API Key

```json
{
  "error": {
    "code": 403,
    "message": "API key not valid. Please pass a valid API key.",
    "status": "PERMISSION_DENIED"
  }
}
```

**Fix**:
- Regenerate your API key in Google AI Studio
- Double-check that the `?key=` query parameter is correctly set
- Review any API key restrictions (e.g., IP address restrictions) in your Google Cloud Console

---

### 429 Too Many Requests: Rate Limit Exceeded

```json
{
  "error": {
    "code": 429,
    "message": "Resource has been exhausted (e.g. check quota).",
    "status": "RESOURCE_EXHAUSTED"
  }
}
```

**Fix**:
- Free tier limits apply (see FAQ for details)
- Implement Exponential Backoff for retries

```javascript
// Exponential Backoff retry implementation
async function fetchWithRetry(url, options, maxRetries = 3) {
  for (let attempt = 0; attempt < maxRetries; attempt++) {
    const response = await fetch(url, options);
    
    if (response.status === 429) {
      const waitMs = Math.pow(2, attempt) * 1000 + Math.random() * 500;
      console.log(`Rate limited. Retrying in ${waitMs}ms... (attempt ${attempt + 1})`);
      await new Promise(resolve => setTimeout(resolve, waitMs));
      continue;
    }
    
    return response;
  }
  throw new Error("Max retries exceeded");
}
```

## Controlling Output with generationConfig

The `generationConfig` field gives you precise control over the model's output:

```javascript
const requestBody = {
  contents: [/* ... */],
  generationConfig: {
    // Output diversity: 0.0 = deterministic, 2.0 = maximum creativity
    temperature: 0.7,

    // Consider only top P% of token probabilities (0.0–1.0)
    topP: 0.9,

    // Consider only the top K token candidates
    topK: 40,

    // Maximum number of tokens to generate
    maxOutputTokens: 4096,

    // Stop generation when these strings are encountered
    stopSequences: ["---END---"],

    // Force JSON output (structured output mode)
    responseMimeType: "application/json",
  },
};
```

### Structured JSON Output

Combining `responseMimeType: "application/json"` with `responseSchema` produces reliable, type-safe JSON output:


## Using the x-goog-api-key Header

Instead of passing your API key as a query parameter, you can use a request header:

```bash
curl -X POST \
  "https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-pro-latest:generateContent" \
  -H "Content-Type: application/json" \
  -H "x-goog-api-key: YOUR_API_KEY" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [{ "text": "Hello, Gemini!" }]
      }
    ]
  }'
```

> 💡 The header method prevents your API key from appearing in server access logs (which would log the full URL including query parameters). Use this approach in production environments.

## FAQ

**Q. What's the difference between using the SDK and calling the REST API directly?**

A. The SDK is essentially a wrapper around the same REST API endpoints. It handles session management, error retries, and type safety automatically. Direct REST API calls are better suited for languages without official SDKs, or when you need precise control over each request. Both approaches give you full access to Gemini 2.5 Pro's capabilities.

**Q. Is it safe to pass the API key as a query parameter?**

A. Over HTTPS, the connection is encrypted, so it's generally fine. However, the full URL (including the key) may appear in server access logs or debugging tools like Postman. For production systems, use the `x-goog-api-key` header and configure IP restrictions in Google Cloud Console.

**Q. What's the difference between `gemini-2.5-pro-latest` and `gemini-2.5-pro-001`?**

A. `gemini-2.5-pro-latest` is an alias that always points to the newest stable version of Gemini 2.5 Pro. `gemini-2.5-pro-001` pins you to a specific version. For development, `-latest` is convenient. For production, pin to a specific version to avoid unexpected behavior changes. You can confirm which version was used from the `modelVersion` field in the response.

**Q. What are the rate limits for the free tier?**

A. For Gemini 2.5 Pro on the free tier: **5 requests per minute (RPM) and 25 requests per day (RPD)**. This is sufficient for learning and prototyping. For production workloads, upgrade to the Pay-as-you-go plan. Always check the [official rate limits documentation](https://ai.google.dev/gemini-api/docs/rate-limits) for the latest figures.

**Q. How do I migrate from the Python SDK to direct REST API calls?**

A. The most important thing to handle manually is **error retries**—the SDK automatically retries on 429 and 500 errors, but with direct REST calls you need to implement this yourself (see the Exponential Backoff example above). You'll also need to manage conversation history manually. Use the `GeminiChatSession` class from this article as a starting point.
