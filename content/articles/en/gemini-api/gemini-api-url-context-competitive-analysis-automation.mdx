How much time do you spend manually checking competitor sites? Visiting three different pricing pages, copying numbers into a spreadsheet, noting feature changes — it adds up fast.

Gemini API's `url_context` tool lets you pass a URL and have the AI read and process that page's content directly. With it, you can automate tasks like "compare these five competitor pricing pages and summarize the differences" or "alert me when this product's price changes." No browser, no scraper setup, no manual copy-paste.

This guide walks through the URL Context tool from a basic call to a working competitive analysis and price monitoring system, with complete Python code for each step.

## How URL Context Works

[The basics of calling URL Context](/articles/gemini-api/gemini-url-context-guide) are covered in our intro guide. Here's a quick recap focused on what matters for automation:

```python
from google import genai
from google.genai.types import Tool, GenerateContentConfig

client = genai.Client(api_key="YOUR_GEMINI_API_KEY")

# Enable the url_context tool
url_tool = Tool(url_context={})

response = client.models.generate_content(
    model="gemini-2.5-pro-preview-05-06",
    contents="Summarize the pricing plans on this page: https://example.com/pricing",
    config=GenerateContentConfig(
        tools=[url_tool],
        temperature=0.2,
    ),
)

print(response.text)
```

One thing worth noting: set `temperature=0.2` (or lower) for fact-extraction tasks. Higher temperatures are fine for creative work, but when you need accurate prices and features, you want the model to stay close to what's actually on the page rather than filling in gaps.

## A Multi-Site Competitive Analysis System

Once you've confirmed the basics work, the next step is comparing multiple sites in a single request. The key is a specific comparison prompt combined with structured output — so you get clean JSON back instead of free-form text.

```python
import json
from google import genai
from google.genai.types import Tool, GenerateContentConfig, Schema, Type

client = genai.Client(api_key="YOUR_GEMINI_API_KEY")

def analyze_competitors(competitor_urls: list[str], product_category: str) -> dict:
    """
    Analyze multiple competitor sites and return a structured comparison report.
    Extracts pricing, features, target users, and differentiators.
    """
    url_tool = Tool(url_context={})

    # Define the response schema — this forces the output into a predictable structure
    competitor_schema = Schema(
        type=Type.OBJECT,
        properties={
            "site_name": Schema(type=Type.STRING),
            "main_price": Schema(
                type=Type.STRING,
                description="Price of the primary plan including currency. Use 'Contact for pricing' if not listed."
            ),
            "key_features": Schema(
                type=Type.ARRAY,
                items=Schema(type=Type.STRING),
                description="Up to 5 main features"
            ),
            "target_user": Schema(type=Type.STRING),
            "differentiator": Schema(
                type=Type.STRING,
                description="What sets this product apart from competitors"
            ),
        },
        required=["site_name", "main_price", "key_features", "target_user", "differentiator"],
    )
    report_schema = Schema(
        type=Type.OBJECT,
        properties={
            "product_category": Schema(type=Type.STRING),
            "competitors": Schema(type=Type.ARRAY, items=competitor_schema),
            "market_insights": Schema(
                type=Type.STRING,
                description="Overall market trends, common patterns, and notable differences"
            ),
        },
        required=["product_category", "competitors", "market_insights"],
    )

    urls_text = "\n".join(f"- {url}" for url in competitor_urls)
    prompt = f"""
Read each of the following {len(competitor_urls)} service pages and create a competitive analysis 
report for the {product_category} market.

URLs:
{urls_text}

For each service, extract: name, pricing, key features (up to 5), target users, and 
what differentiates it from the others. End with a summary of market-wide trends.
"""

    response = client.models.generate_content(
        model="gemini-2.5-pro-preview-05-06",
        contents=prompt,
        config=GenerateContentConfig(
            tools=[url_tool],
            response_mime_type="application/json",
            response_schema=report_schema,
            temperature=0.1,
        ),
    )

    return json.loads(response.text)


# Example usage
if __name__ == "__main__":
    urls = [
        "https://notion.so/pricing",
        "https://www.atlassian.com/software/confluence/pricing",
        "https://coda.io/pricing",
    ]

    report = analyze_competitors(urls, "knowledge management tools")
    print(json.dumps(report, indent=2))
```

Passing `response_schema` ensures the output is always valid JSON in the shape you expect. This pattern is covered in more depth in our [structured output web scraping guide](/articles/gemini-api/gemini-api-structured-output-web-scraping-automation), but it works especially well here because you're pulling comparable data from multiple sources and want to merge it into a single object.

The result is an array of competitor objects you can write directly to a spreadsheet, diff against previous results, or feed into a dashboard.

## A Price Change Monitoring System

Knowing when a competitor changes their pricing gives you a real edge. Here's a script designed for periodic execution — run it daily via cron or GitHub Actions and get a Slack alert whenever something changes.

```python
import json
import os
import hashlib
from datetime import datetime
from pathlib import Path
from google import genai
from google.genai.types import Tool, GenerateContentConfig, Schema, Type
import urllib.request

client = genai.Client(api_key="YOUR_GEMINI_API_KEY")
PRICE_CACHE_FILE = Path("price_cache.json")


def extract_pricing(url: str) -> dict:
    """Extract all pricing plans from a given URL."""
    url_tool = Tool(url_context={})

    price_schema = Schema(
        type=Type.OBJECT,
        properties={
            "plans": Schema(
                type=Type.ARRAY,
                items=Schema(
                    type=Type.OBJECT,
                    properties={
                        "plan_name": Schema(type=Type.STRING),
                        "price": Schema(type=Type.STRING),
                        "billing_cycle": Schema(
                            type=Type.STRING,
                            description="monthly, annual, one-time, etc."
                        ),
                    },
                    required=["plan_name", "price", "billing_cycle"],
                ),
            ),
            "currency": Schema(type=Type.STRING),
        },
        required=["plans", "currency"],
    )

    response = client.models.generate_content(
        model="gemini-2.5-flash-preview-04-17",  # Flash is fast and cheap for this task
        contents=f"Extract all pricing plans from this page: {url}",
        config=GenerateContentConfig(
            tools=[url_tool],
            response_mime_type="application/json",
            response_schema=price_schema,
            temperature=0.0,
        ),
    )
    return json.loads(response.text)


def check_price_change(url: str) -> tuple[bool, dict, dict | None]:
    """
    Detect price changes using hash comparison.
    Returns: (changed, current_data, previous_data)
    
    Hash comparison is reliable here — if any value changes in the JSON,
    the hash changes, and we get an alert.
    """
    current_pricing = extract_pricing(url)

    cache = {}
    if PRICE_CACHE_FILE.exists():
        with open(PRICE_CACHE_FILE) as f:
            cache = json.load(f)

    current_hash = hashlib.md5(
        json.dumps(current_pricing, sort_keys=True).encode()
    ).hexdigest()

    url_key = hashlib.md5(url.encode()).hexdigest()
    previous_entry = cache.get(url_key)
    changed = previous_entry is None or previous_entry.get("hash") \!= current_hash

    # Update the cache
    cache[url_key] = {
        "url": url,
        "hash": current_hash,
        "data": current_pricing,
        "checked_at": datetime.now().isoformat(),
    }
    with open(PRICE_CACHE_FILE, "w") as f:
        json.dump(cache, f, indent=2)

    previous_data = previous_entry.get("data") if previous_entry else None
    return changed, current_pricing, previous_data


def send_slack_notification(url: str, current: dict, previous: dict | None):
    """Send a Slack alert when a price change is detected."""
    webhook_url = os.environ["SLACK_WEBHOOK_URL"]
    label = "(first detection)" if previous is None else "Price change detected"
    message = {
        "text": (
            f"💰 *{label}*\n"
            f"URL: {url}\n"
            f"```{json.dumps(current, indent=2)}```"
        )
    }
    req = urllib.request.Request(
        webhook_url,
        data=json.dumps(message).encode(),
        headers={"Content-Type": "application/json"},
    )
    urllib.request.urlopen(req)


# URLs to monitor
MONITOR_URLS = [
    "https://openai.com/api/pricing",
    "https://www.anthropic.com/pricing",
]

for target_url in MONITOR_URLS:
    changed, current, previous = check_price_change(target_url)
    if changed:
        print(f"Change detected: {target_url}")
        send_slack_notification(target_url, current, previous)
    else:
        print(f"No change: {target_url}")
```

Notice that monitoring uses `gemini-2.5-flash` instead of Pro. Flash handles price extraction reliably and costs significantly less. For repetitive, scheduled tasks like this, [choosing the right model for the job](/articles/gemini-api/gemini-api-cost-optimization) makes a real difference at scale.

Running this once or twice a day with a cron job is all you need to catch pricing changes without any manual effort.

## Three Limitations You'll Hit in Production

Being upfront about where URL Context falls short will save you debugging time.

**Dynamically rendered pages often don't work**

If a site uses React or another SPA framework to render pricing client-side, URL Context may return nothing useful. The tool fetches the page's HTML as-is — it doesn't execute JavaScript. For these cases, try targeting a cached or static version of the page, or fall back to a different data source. You'll know this is the issue when the model returns "I couldn't find pricing information on this page."

**Keep request frequency reasonable**

For monitoring tasks, once or twice a day is plenty. More frequent requests increase the risk of being blocked by the target site, and they also drive up your Gemini API costs. If you have many URLs to monitor, add a `time.sleep(5)` between requests to stay within rate limits on both ends.

**Validate extracted values before using them**

Even with `response_schema` enforcing the output structure, individual values can occasionally be off. If you're writing prices to a database or triggering actions based on them, add a validation step — confirm the price field looks like a number, check that plan names are non-empty, and so on. A small assertion block before writing to your cache goes a long way toward catching edge cases before they cause problems downstream.
