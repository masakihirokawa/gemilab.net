App Store screenshots are among the highest-leverage elements of conversion rate optimization. Yet for indie developers, objectively evaluating screenshot quality is hard: no budget for a professional ASO consultant, A/B test data takes weeks to accumulate, and competitive analysis means staring at screenshots manually.

Gemini's Vision API changes this equation. It accepts images as direct input and can evaluate them from a marketing and UX perspective, automate competitive comparisons, and localize screenshot text — all in code.

This guide implements four working tools.

```python
import os
import json
import httpx
from pathlib import Path
from google import genai
from google.genai import types

client = genai.Client(api_key=os.environ["GOOGLE_API_KEY"])
VISION_MODEL = "gemini-2.5-pro-preview-05-06"
```

Image loading helper:

```python
def load_image_as_part(image_path: str) -> types.Part:
    """Load a local image file as a Gemini API Part object. Supports JPEG, PNG, WebP."""
    path = Path(image_path)
    mime_map = {".jpg": "image/jpeg", ".jpeg": "image/jpeg",
                ".png": "image/png", ".webp": "image/webp"}
    mime_type = mime_map.get(path.suffix.lower(), "image/jpeg")
    
    with open(path, "rb") as f:
        return types.Part.from_bytes(data=f.read(), mime_type=mime_type)
```

## Tool 1: Screenshot Quality Scoring

This tool evaluates a screenshot set from an ASO perspective and returns a structured score.

```python
def score_screenshots(
    screenshot_paths: list[str],
    app_name: str,
    app_category: str,
    target_market: str = "US",
) -> dict:
    """
    Evaluate a screenshot set from an ASO perspective.
    
    Score components (0-100 each):
    - visual_hierarchy: Are the most important elements most prominent?
    - message_clarity: Does screen 1 communicate the value proposition?
    - cta_presence: Is there action-oriented language?
    - consistency: Are design elements consistent across screens?
    - localization_fit: Cultural appropriateness for target market
    
    Returns a structured dict with scores, strengths, and prioritized improvements.
    """
    parts = [
        types.Part.from_text(
            f"""You are an App Store Optimization expert. Evaluate this screenshot set.

App: {app_name}
Category: {app_category}
Target market: {target_market}

Return ONLY valid JSON in this exact structure:
{{
  "overall_score": <integer 0-100>,
  "scores": {{
    "visual_hierarchy": <0-100>,
    "message_clarity": <0-100>,
    "cta_presence": <0-100>,
    "consistency": <0-100>,
    "localization_fit": <0-100>
  }},
  "strengths": ["strength1", "strength2", "strength3"],
  "improvements": [
    {{"issue": "description", "priority": "high|medium|low", "suggestion": "specific action"}}
  ],
  "first_impression": "One sentence describing what a user sees in the first second"
}}"""
        )
    ]
    
    for i, path in enumerate(screenshot_paths):
        parts.append(types.Part.from_text(f"Screenshot {i+1}:"))
        parts.append(load_image_as_part(path))
    
    response = client.models.generate_content(
        model=VISION_MODEL,
        contents=parts,
        config=types.GenerateContentConfig(
            response_mime_type="application/json",
            temperature=0.2,
        ),
    )
    
    try:
        return json.loads(response.text)
    except json.JSONDecodeError:
        return {"raw_response": response.text, "parse_error": True}
```

Usage:

```python
result = score_screenshots(
    screenshot_paths=["./screenshots/screen1.png", "./screenshots/screen2.png"],
    app_name="DailyWalls",
    app_category="Entertainment (Wallpapers)",
    target_market="US",
)

print(f"Overall score: {result['overall_score']}/100")
print(f"First impression: {result['first_impression']}")

for item in result['improvements']:
    if item['priority'] == 'high':
        print(f"\n❗ {item['issue']}")
        print(f"   Fix: {item['suggestion']}")
```

When I ran this on my own wallpaper app, the top finding was that screenshot one led with visual impact rather than explaining what the app does. That matched my user retention data — people installed and then churned because expectations didn't match reality.

## Tool 2: Competitor Comparison

Compare your screenshots against a competitor's using their App Store screenshot URLs.

```python
def get_competitor_screenshot_urls(app_id: str, country: str = "us") -> list[str]:
    """Fetch screenshot URLs from iTunes Search API using the App Store app ID."""
    url = f"https://itunes.apple.com/lookup?id={app_id}&country={country}"
    resp = httpx.get(url, timeout=15)
    data = resp.json()
    if data.get("resultCount", 0) == 0:
        return []
    return data["results"][0].get("screenshotUrls", [])

def compare_with_competitor(
    my_screenshots: list[str],
    competitor_name: str,
    competitor_screenshot_urls: list[str],
    focus_aspect: str = "overall comparison",
) -> dict:
    """
    Compare your screenshots against a competitor's.

    focus_aspect options: "value proposition", "design quality",
                          "text density", "overall comparison"
    """
    parts = [
        types.Part.from_text(
            f"""Compare these App Store screenshot sets.
Focus: {focus_aspect}

Return JSON in this structure:
{{
  "competitive_position": "ahead|parity|behind",
  "key_differences": [
    {{"aspect": "what", "my_app": "my status", "competitor": "{competitor_name} status",
      "advantage": "my|competitor|neutral"}}
  ],
  "ab_test_hypotheses": [
    {{"hypothesis": "what to test", "expected_lift": "estimated impact",
      "effort": "low|medium|high"}}
  ],
  "immediate_wins": ["quick wins requiring minimal effort"]
}}"""
        )
    ]
    
    parts.append(types.Part.from_text("=== MY APP SCREENSHOTS ==="))
    for i, path in enumerate(my_screenshots[:3]):
        parts.append(types.Part.from_text(f"Mine {i+1}:"))
        parts.append(load_image_as_part(path))
    
    parts.append(types.Part.from_text(f"=== {competitor_name.upper()} SCREENSHOTS ==="))
    for i, url in enumerate(competitor_screenshot_urls[:5]):
        try:
            img_bytes = httpx.get(url, timeout=30, follow_redirects=True).content
            parts.append(types.Part.from_text(f"{competitor_name} {i+1}:"))
            parts.append(types.Part.from_bytes(data=img_bytes, mime_type="image/jpeg"))
        except Exception as e:
            print(f"Warning: could not fetch {url}: {e}")
    
    response = client.models.generate_content(
        model=VISION_MODEL,
        contents=parts,
        config=types.GenerateContentConfig(
            response_mime_type="application/json",
            temperature=0.3,
        ),
    )
    
    return json.loads(response.text)
```

## Tool 3: Multi-Language Text Localization

Extract text from a screenshot and adapt it for multiple target markets — not just translation, but cultural adaptation.

```python
MARKET_PROFILES = {
    "us": "en-US — Simple, benefit-focused. Avoid superlatives. Show outcomes.",
    "jp": "ja-JP — Polite, trust-oriented. Quality and reliability resonate.",
    "de": "de-DE — Technical precision valued. Lead with features, not feelings.",
    "br": "pt-BR — Warm, social, emotional tone. Social proof is persuasive.",
    "kr": "ko-KR — Trendy, premium language. Exclusivity and trend-awareness matter.",
}

def localize_screenshot_text(
    screenshot_path: str,
    source_market: str = "us",
    target_markets: list[str] | None = None,
) -> dict:
    """
    Extract all visible text from a screenshot and produce market-adapted
    localizations for each target market.

    Returns extracted source texts and per-market adapted versions.
    """
    targets = target_markets or [k for k in MARKET_PROFILES if k \!= source_market]
    profiles_block = "\n".join(
        f"- {k}: {v}" for k, v in MARKET_PROFILES.items() if k in targets
    )
    
    prompt = f"""Extract all text elements visible in this screenshot.
Then produce culturally adapted (not just translated) versions for each market below.

Market profiles:
{profiles_block}

Return JSON:
{{
  "extracted_texts": ["original text 1", "original text 2", ...],
  "localizations": {{
    "<market_code>": {{
      "texts": ["adapted text 1", "adapted text 2", ...],
      "adaptation_notes": "Key cultural adaptations made (1-2 sentences)"
    }}
  }}
}}"""
    
    response = client.models.generate_content(
        model=VISION_MODEL,
        contents=[
            types.Part.from_text(prompt),
            load_image_as_part(screenshot_path),
        ],
        config=types.GenerateContentConfig(
            response_mime_type="application/json",
            temperature=0.4,
        ),
    )
    
    return json.loads(response.text)
```

## Tool 4: Full ASO Report

Combine all three tools into a single report generator.

```python
def generate_aso_report(
    app_name: str,
    app_category: str,
    screenshot_dir: str,
    competitor_name: str | None = None,
    competitor_app_id: str | None = None,
    target_markets: list[str] | None = None,
    output_path: str = "aso_report.json",
) -> dict:
    """
    Generate a complete ASO improvement report for a screenshot set.
    
    screenshot_dir: directory containing .png / .jpg / .webp screenshots
    competitor_app_id: App Store numeric ID (found in the app's store URL)
    """
    import datetime
    
    screenshots = sorted(
        str(p) for p in Path(screenshot_dir).glob("*")
        if p.suffix.lower() in {".png", ".jpg", ".jpeg", ".webp"}
    )
    if not screenshots:
        raise ValueError(f"No screenshots found in {screenshot_dir}")
    
    print(f"Processing {len(screenshots)} screenshots for {app_name}...")
    report = {
        "app_name": app_name,
        "category": app_category,
        "screenshot_count": len(screenshots),
        "generated_at": datetime.datetime.now().isoformat(),
    }
    
    print("Step 1/3: Quality scoring...")
    report["quality_score"] = score_screenshots(
        screenshot_paths=screenshots[:5],
        app_name=app_name,
        app_category=app_category,
    )
    
    if competitor_name and competitor_app_id:
        print(f"Step 2/3: Competitor comparison vs {competitor_name}...")
        urls = get_competitor_screenshot_urls(competitor_app_id)
        report["competitor_analysis"] = compare_with_competitor(
            my_screenshots=screenshots[:3],
            competitor_name=competitor_name,
            competitor_screenshot_urls=urls,
        ) if urls else {"error": "No competitor screenshots found"}
    else:
        print("Step 2/3: No competitor specified (skipping)")
        report["competitor_analysis"] = None
    
    print("Step 3/3: Localization analysis for primary screenshot...")
    report["localization"] = localize_screenshot_text(
        screenshot_path=screenshots[0],
        target_markets=target_markets or ["jp", "de", "br"],
    )
    
    with open(output_path, "w", encoding="utf-8") as f:
        json.dump(report, f, ensure_ascii=False, indent=2)
    
    overall = report["quality_score"].get("overall_score", "N/A")
    print(f"\n✅ Report saved to {output_path}")
    print(f"   Overall score: {overall}/100")
    return report

if __name__ == "__main__":
    report = generate_aso_report(
        app_name="DailyWalls",
        app_category="Entertainment (Wallpapers)",
        screenshot_dir="./screenshots/dailywalls/",
        competitor_name="Zedge",
        competitor_app_id="470786854",
        target_markets=["jp", "de", "kr"],
        output_path="./aso_report_dailywalls.json",
    )
```

## Cost Management

Each screenshot consumes several hundred to a few thousand input tokens. For high-volume usage:

- **Use lower resolution for scoring**: 1080px width is sufficient for quality evaluation
- **Use Gemini Flash for drafts**: `gemini-2.5-flash-preview-04-17` costs a fraction of Pro. Run Flash first, then Pro only for final review
- **Cache repeated images**: If you're running reports on the same screenshots repeatedly, implement a local cache keyed by image hash

```python
import hashlib

def image_hash(path: str) -> str:
    with open(path, "rb") as f:
        return hashlib.md5(f.read()).hexdigest()

# Cache results by hash
cache: dict[str, dict] = {}

def score_with_cache(screenshots: list[str], **kwargs) -> dict:
    key = "|".join(image_hash(p) for p in sorted(screenshots))
    if key not in cache:
        cache[key] = score_screenshots(screenshots, **kwargs)
    return cache[key]
```

## What This Changes in Practice

When I started running these reports on my own apps, the most valuable insight wasn't the high-priority findings — it was the consistent pattern across multiple apps and multiple runs. Certain issues kept appearing: the first screenshot not clearly communicating the app's purpose, text overlays that competed with the visual rather than reinforcing it, localizations that were grammatically correct but tonally off for the market.

These weren't things I was unaware of. They were things I knew needed attention but kept deferring because they felt subjective. Having a scored report makes them concrete and schedulable. "Screenshot score dropped below 70 → fix before next release" is a much cleaner decision rule than "I should probably improve these at some point."

The jump from good screenshots to great screenshots is small for most apps. Tooling that makes it a regular habit rather than a one-time project is where the real leverage is.
