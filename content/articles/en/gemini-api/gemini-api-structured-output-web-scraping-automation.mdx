Anyone who has maintained web scraping pipelines knows the frustration: you spend hours crafting XPath selectors and regex patterns, and the moment the target site updates its layout, everything breaks. You're back to square one.

Gemini API's **Structured Output** fundamentally changes this workflow. Instead of encoding site structure into fragile selectors, you describe what you want — "extract product name, price, and rating" — and Gemini handles the interpretation. The result is a JSON object that matches your schema exactly. This article walks you through building a production-ready data collection tool with this approach.

## What Makes Structured Output Different

Gemini's Structured Output enforces a strict JSON Schema on the model's response. By specifying `response_mime_type="application/json"` and providing a `response_schema`, you get type-safe data out of unstructured web content.

The key shift compared to traditional scraping:

- **Traditional approach**: Parse HTML → target elements with CSS/XPath → manually reshape data
- **Gemini + Structured Output**: Feed raw text to Gemini → extract by semantic meaning → get typed JSON back

When a site redesigns, the *meaning* of "product price" doesn't change — only the HTML structure does. Since Gemini understands meaning rather than structure, your extraction logic stays stable even as the underlying page evolves.

## Core Implementation: Extracting Product Data

Define your data model using Pydantic, then let Gemini populate it:

```python
import os
import requests
from bs4 import BeautifulSoup
from pydantic import BaseModel
from typing import Optional
import google.genai as genai
import google.genai.types as types
import json

# --- Data model ---
class ProductInfo(BaseModel):
    name: str
    price: Optional[str]         # Keep currency symbol as-is
    rating: Optional[float]      # 0.0 to 5.0
    review_count: Optional[int]
    availability: Optional[str]
    description: Optional[str]   # Max 100 chars

class ProductList(BaseModel):
    products: list[ProductInfo]
    total_found: int
    page_title: str

# --- Gemini client ---
client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])

def scrape_and_structure(url: str) -> ProductList:
    """Fetch a page, strip noise, and let Gemini structure the data."""

    # Step 1: Fetch HTML
    headers = {"User-Agent": "Mozilla/5.0 (compatible; DataBot/1.0)"}
    response = requests.get(url, headers=headers, timeout=15)
    response.raise_for_status()

    # Step 2: Extract text (remove script/style to save tokens)
    soup = BeautifulSoup(response.content, "html.parser")
    for tag in soup(["script", "style", "nav", "footer", "header"]):
        tag.decompose()
    # Prioritize main content area
    main = soup.find("main") or soup.find("article") or soup.find("body")
    clean_text = main.get_text(separator="\n", strip=True)[:8000] if main else ""

    # Step 3: Structured extraction
    prompt = f"""
Extract product information from the web page text below.
Preserve price with currency symbols. Convert rating to a numeric score.
Set missing fields to null.

Page text:
{clean_text}
"""

    gemini_response = client.models.generate_content(
        model="gemini-2.5-pro",
        contents=prompt,
        config=types.GenerateContentConfig(
            response_mime_type="application/json",
            response_schema=ProductList,
        ),
    )

    return ProductList.model_validate_json(gemini_response.text)

# Example usage
if __name__ == "__main__":
    result = scrape_and_structure("https://books.toscrape.com/")
    print(f"Page: {result.page_title}")
    print(f"Items found: {result.total_found}")
    for product in result.products[:3]:
        print(f"  - {product.name}: {product.price} (rating: {product.rating})")
```

Expected output:

```

Items found: 20
  - A Light in the Attic: £51.77 (rating: 3.0)
  - Tipping the Velvet: £53.74 (rating: 1.0)
  - Soumission: £50.10 (rating: 1.0)
```

## Building a Price Monitor for Competitor Tracking

One natural extension is continuous price monitoring across competitor URLs. The design principle here is to use **Flash for routine polling** and reserve Pro for pages that need deeper reasoning — roughly a 20x cost difference.

```python
import time
from datetime import datetime
from pathlib import Path

class PriceMonitor:
    """Poll multiple URLs and log price changes over time."""

    def __init__(self, urls: list[str], output_dir: str = "price_data"):
        self.urls = urls
        self.output_dir = Path(output_dir)
        self.output_dir.mkdir(exist_ok=True)
        self.client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])

    def fetch_prices(self, url: str) -> dict:
        """Fetch structured price data from a single URL."""
        class PricePoint(BaseModel):
            product_name: str
            current_price: Optional[str]
            original_price: Optional[str]  # Pre-sale price, if shown
            discount_rate: Optional[str]

        class PricePage(BaseModel):
            prices: list[PricePoint]
            timestamp: str

        headers = {"User-Agent": "Mozilla/5.0 (compatible; PriceBot/1.0)"}
        try:
            resp = requests.get(url, headers=headers, timeout=15)
            soup = BeautifulSoup(resp.content, "html.parser")
            for tag in soup(["script", "style", "nav"]):
                tag.decompose()
            text = soup.get_text(separator="\n", strip=True)[:6000]
        except Exception as e:
            return {"error": str(e), "url": url}

        prompt = f"""
Extract all product price information from the page below.
Include original prices and discount rates when available.
Set timestamp to: {datetime.now().isoformat()}

{text}
"""
        response = self.client.models.generate_content(
            model="gemini-2.5-flash",   # Flash for cost-effective monitoring
            contents=prompt,
            config=types.GenerateContentConfig(
                response_mime_type="application/json",
                response_schema=PricePage,
            ),
        )
        return json.loads(response.text)

    def run_monitoring(self, interval_minutes: int = 60):
        """Run a continuous monitoring loop."""
        while True:
            for url in self.urls:
                print(f"[{datetime.now().strftime('%H:%M')}] Checking: {url}")
                data = self.fetch_prices(url)

                filename = url.replace("https://", "").replace("/", "_")[:50]
                filepath = self.output_dir / f"{filename}_{datetime.now().strftime('%Y%m%d_%H%M')}.json"

                with open(filepath, "w", encoding="utf-8") as f:
                    json.dump(data, f, ensure_ascii=False, indent=2)

                time.sleep(2)  # Polite delay between requests

            print(f"Waiting {interval_minutes} minutes until next check...")
            time.sleep(interval_minutes * 60)
```

## News Aggregation with Sentiment Analysis

The same schema-driven approach works well for building a news monitoring system. Adding `sentiment` to the schema costs nothing extra in tokens but gives you immediate signal for filtering:

```python
class NewsArticle(BaseModel):
    title: str
    published_date: Optional[str]
    author: Optional[str]
    summary: str           # 3 sentences max
    keywords: list[str]    # Up to 5 key terms
    sentiment: str         # "positive", "neutral", or "negative"
    url: str

class NewsFeed(BaseModel):
    articles: list[NewsArticle]
    source_name: str

def collect_news(url: str) -> NewsFeed:
    """Extract and summarize articles from a news page."""

    headers = {"User-Agent": "Mozilla/5.0"}
    resp = requests.get(url, headers=headers, timeout=15)
    soup = BeautifulSoup(resp.content, "html.parser")

    for tag in soup(["script", "style", "nav", "footer", "aside"]):
        tag.decompose()

    text = soup.get_text(separator="\n", strip=True)[:10000]

    prompt = f"""
Extract article summaries from the news site text below.
Keep each summary to 3 sentences. Evaluate overall sentiment as
"positive", "neutral", or "negative". Source URL: {url}

{text}
"""

    client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])
    response = client.models.generate_content(
        model="gemini-2.5-pro",
        contents=prompt,
        config=types.GenerateContentConfig(
            response_mime_type="application/json",
            response_schema=NewsFeed,
        ),
    )

    return NewsFeed.model_validate_json(response.text)
```

## Common Errors and How to Fix Them

**Token limit exceeded for large pages**

While Gemini 2.5 Pro supports up to 2 million tokens, the cost-effective range is 8,000–15,000 characters of extracted text per call. Always prioritize the main content container:

```python
main = soup.find("main") or soup.find("article") or soup.find("body")
text = main.get_text(separator="\n", strip=True)[:8000] if main else ""
```

**Schema validation failures with empty strings**

Pydantic's `Optional[str]` accepts `None`, but Gemini sometimes returns empty strings instead. A simple validator normalizes this:

```python
from pydantic import model_validator

class ProductInfo(BaseModel):
    price: Optional[str] = None

    @model_validator(mode="after")
    def normalize_empty_strings(self):
        if self.price == "":
            self.price = None
        return self
```

**Respecting robots.txt and terms of service**

Before scraping any site, check its `robots.txt`. Pages marked `Disallow: /` may be off-limits regardless of technical feasibility. For commercial use, always check whether an official API exists first — it's more reliable, more stable, and keeps you on the right side of terms of service.

## Parallel Batch Processing for Scale

When you need to process dozens or hundreds of URLs at once, sequential requests become a bottleneck. Python's `asyncio` combined with the async Gemini client makes parallel batch processing straightforward:

```python
import asyncio
import aiohttp

async def scrape_batch(urls: list[str], max_concurrent: int = 5) -> list[dict]:
    """Process multiple URLs concurrently with a concurrency cap."""

    async_client = genai.AsyncClient(api_key=os.environ["GEMINI_API_KEY"])
    semaphore = asyncio.Semaphore(max_concurrent)

    async def process_one(session: aiohttp.ClientSession, url: str) -> dict:
        async with semaphore:
            try:
                async with session.get(url, timeout=aiohttp.ClientTimeout(total=15)) as resp:
                    html = await resp.text()

                soup = BeautifulSoup(html, "html.parser")
                for tag in soup(["script", "style", "nav"]):
                    tag.decompose()
                main = soup.find("main") or soup.find("body")
                text = main.get_text(separator="\n", strip=True)[:6000] if main else ""

                response = await async_client.aio.models.generate_content(
                    model="gemini-2.5-flash",
                    contents=f"Extract product data as JSON from:\n{text}",
                    config=types.GenerateContentConfig(
                        response_mime_type="application/json",
                        response_schema=ProductList,
                    ),
                )
                result = json.loads(response.text)
                result["source_url"] = url
                return result

            except Exception as e:
                return {"error": str(e), "source_url": url}

    async with aiohttp.ClientSession() as session:
        tasks = [process_one(session, url) for url in urls]
        return await asyncio.gather(*tasks)

# Run batch
if __name__ == "__main__":
    urls = [
        "https://books.toscrape.com/catalogue/page-1.html",
        "https://books.toscrape.com/catalogue/page-2.html",
        "https://books.toscrape.com/catalogue/page-3.html",
    ]
    results = asyncio.run(scrape_batch(urls, max_concurrent=3))
    for r in results:
        print(f"{r.get('source_url')}: {r.get('total_found', 'error')} items")
```

Setting `max_concurrent=5` provides a reasonable balance — aggressive enough to be fast, but considerate enough not to hammer any single server. Adjust based on your target sites' rate limits and your API quota.

## When Structured Output Outperforms Traditional Scraping (and When It Doesn't)

This combination isn't a universal replacement for CSS selectors. Here's a practical decision framework:

**Use Gemini Structured Output when:**
- The site structure changes frequently (news sites, e-commerce catalogs)
- You're scraping many different domains with varying layouts
- The data requires semantic interpretation (summarization, classification, sentiment)
- You're prototyping quickly and don't want to invest in XPath engineering

**Stick with traditional scraping when:**
- You're scraping a single, stable site you control or know well
- You need sub-millisecond extraction speed
- Cost is extremely sensitive and volume is very high (millions of pages/day)
- The data is purely structural with no ambiguity (fixed JSON APIs, XML feeds)

The real sweet spot is combining both: use BeautifulSoup to isolate the relevant section of the page cheaply, then hand that clean text to Gemini for semantic extraction. This keeps token counts low while maintaining flexibility.
