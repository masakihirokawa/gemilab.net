You've got your Gemini API key from Google AI Studio, opened a terminal, typed `pip install google-genai`, and then — error. Welcome to the club.

Almost everyone hits the same walls in the first few hours. I once spent an hour chasing an auth error that turned out to be a single extra space in my `.env` file. This guide is my attempt to save you that hour. I'll walk through the most common failure points in order — from installation through your first API call and into handling responses.

## SDK Installation: The Right Package Name

The single biggest source of confusion for beginners is that two different packages exist for Gemini in Python, and installing the wrong one causes cryptic errors later.

The **current** SDK is `google-genai`. The old SDK is `google-generativeai`, which is now deprecated and not compatible with the current API surface.

```bash
# ✅ Install the current SDK
pip install google-genai

# ❌ Old SDK — deprecated and incompatible with the new API
pip install google-generativeai
```

The import style is completely different between the two:

```python
# ✅ New SDK (google-genai)
from google import genai
from google.genai import types

client = genai.Client(api_key="YOUR_API_KEY")

# ❌ Old SDK import pattern — won't work with google-genai
import google.generativeai as genai  # This is the old approach
genai.configure(api_key="YOUR_API_KEY")
```

If you have both packages installed at the same time, things get confusing fast. Python may pick up one when you expect the other. Run `pip list | grep google` and make sure only `google-genai` appears. If `google-generativeai` is listed, uninstall it:

```bash
pip uninstall google-generativeai
```

For a deeper look at version conflicts and installation edge cases, the [Gemini SDK Version and Install Error Fix guide](/en/articles/gemini-api/gemini-sdk-version-install-error-fix) covers common scenarios including virtual environment issues and system Python conflicts.

## Environment Variable Mistakes That Cause Auth Errors

`PERMISSION_DENIED` or `API key not valid` errors almost always trace back to how the key is being loaded — not the key itself. The standard pattern for loading it from an environment variable is:

```python
import os
from google import genai

client = genai.Client(api_key=os.environ.get("GOOGLE_API_KEY"))
```

Three things to check when this doesn't work:

**① Your `.env` file isn't actually being loaded**

Writing `GOOGLE_API_KEY=AIzaSy...` in a `.env` file does nothing unless you explicitly load it with `python-dotenv`. A lot of beginners write the file and assume Python picks it up automatically.

```python
from dotenv import load_dotenv
import os

load_dotenv()  # Without this line, the .env file is completely ignored

api_key = os.environ.get("GOOGLE_API_KEY")
print(f"Key prefix: {api_key[:10] if api_key else 'None — key not loaded'}")
```

**② Stray whitespace in the key value**

If you typed `GOOGLE_API_KEY= AIzaSy...` with a space before the key, that space becomes part of the value — and the resulting string fails authentication. Either strip it in code (`api_key.strip()`) or open the file and remove the extra character.

**③ Using an AI Studio key with Vertex AI**

Keys from Google AI Studio work with the `google-genai` library but *not* with the `google-cloud-aiplatform` SDK (which requires service account authentication). If you're mixing up the two authentication systems, you'll get auth errors regardless of whether the key itself is valid. The [Gemini API Authentication Error Solutions guide](/en/articles/gemini-api/gemini-api-authentication-error-solutions) explains the distinction in detail.

## Errors on Your First API Call

Once setup is working, your first real API call might look like this:

```python
from google import genai

client = genai.Client(api_key="YOUR_GOOGLE_API_KEY")

response = client.models.generate_content(
    model="gemini-2.5-flash",
    contents="Hello\! Can you explain what you are?"
)
print(response.text)
```

Here are the errors that show up most often at this stage.

### `models/gemini-2.5-flash is not found`

This usually means either a typo in the model name, or the model isn't available in your region or account tier. To see exactly what models are accessible to you:

```python
for model in client.models.list():
    print(model.name)
```

Model names change more often than you'd expect. A model released as `gemini-2.5-flash-preview` might later become `gemini-2.5-flash`, or get a new date suffix. Always check the current names from the official documentation or from `client.models.list()` rather than copying from a tutorial written six months ago.

### `429 Resource Exhausted`

You've exceeded the free-tier rate limit. As of April 2026, the approximate limits on the free tier are:

- Gemini 2.5 Flash: 15 RPM (requests per minute)
- Gemini 2.5 Pro: 5 RPM

When you're iterating over a list of items and calling the API for each one, the simplest fix is adding a delay:

```python
import time

items = ["Text 1", "Text 2", "Text 3", "Text 4"]

for item in items:
    response = client.models.generate_content(
        model="gemini-2.5-flash",
        contents=item
    )
    print(response.text)
    time.sleep(4)  # 15 RPM ≈ one request every 4 seconds
```

If you're hitting limits consistently and need higher throughput, upgrading to a paid tier is the practical solution. The [Gemini API 429 Error and Quota Troubleshooting guide](/en/articles/gemini-api/gemini-api-quota-429-error-troubleshooting) covers exponential backoff and other production-grade strategies.

## Response Handling Problems

### `response.text` Returns `None`

When the safety filter blocks a response, `response.text` is set to `None`. Accessing it without a check raises an `AttributeError` that can be confusing because it implies something is wrong with the response object itself — but it's actually working as designed.

```python
response = client.models.generate_content(
    model="gemini-2.5-flash",
    contents="Your prompt here..."
)

# ❌ Will crash if the response was blocked
print(response.text.upper())

# ✅ Check before using
if response.text:
    print(response.text)
else:
    for candidate in response.candidates:
        print(f"finish_reason: {candidate.finish_reason}")
        # SAFETY = blocked by safety filter
        # MAX_TOKENS = hit the output token limit
        # STOP = normal completion
```

### JSON Wrapped in a Markdown Code Block

Without explicit formatting instructions, the model often returns JSON like this:

```
```json
{"city": "Tokyo", "population": 13960000}
```
```

That's valid Markdown but not valid JSON for `json.loads()`. The fix is to specify `response_mime_type`:

```python
import json
from google.genai import types

response = client.models.generate_content(
    model="gemini-2.5-flash",
    contents="Return the populations of Tokyo, Osaka, and Nagoya as JSON",
    config=types.GenerateContentConfig(
        response_mime_type="application/json"
    )
)

# Now response.text is clean JSON
data = json.loads(response.text)
print(data)
```

### Streaming Responses With Empty Chunks

When you use streaming, the final chunk is often empty. If you process every chunk without checking, you may get an `AttributeError` or unexpected blank lines in your output:

```python
for chunk in client.models.generate_content_stream(
    model="gemini-2.5-flash",
    contents="Tell me a long story"
):
    if chunk.text:  # Skip empty chunks
        print(chunk.text, end="", flush=True)
```

## When AI Studio Works But Your Code Doesn't

You tested a prompt in AI Studio's interface and got exactly what you wanted. Then you translated it to Python and got something completely different. This usually happens because the system instructions aren't being passed correctly.

In AI Studio, you write system instructions in the "System Prompt" field. In code, they go through `GenerateContentConfig`:

```python
from google.genai import types

response = client.models.generate_content(
    model="gemini-2.5-flash",
    contents="Write a product description for noise-cancelling headphones",
    config=types.GenerateContentConfig(
        system_instruction="You are a professional copywriter specializing in consumer electronics. Write concise, benefit-focused copy in under 100 words.",
        temperature=0.7,
        max_output_tokens=200,
    )
)
print(response.text)
```

The temperature slider in AI Studio maps directly to the `temperature` parameter here. If you don't set it explicitly in code, it defaults to the model's default value — which may differ from what you had in AI Studio.

## Multi-Turn Conversations: A Common Beginner Mistake

When building a chatbot or any conversation that spans multiple turns, a common mistake is to manually append messages to a list and pass the whole thing as `contents`. While this works, the cleaner approach is to use the chat interface:

```python
from google import genai

client = genai.Client(api_key="YOUR_GOOGLE_API_KEY")

chat = client.chats.create(model="gemini-2.5-flash")

# The chat object automatically maintains conversation history
response1 = chat.send_message("My name is Alex.")
print(response1.text)

response2 = chat.send_message("What's my name?")
print(response2.text)  # Should correctly say "Alex"
```

Manually managing the history list often leads to bugs where the model seems to "forget" earlier context — usually because the history was formatted incorrectly.

## Regenerating an Invalidated API Key

If an API call that worked yesterday now returns an auth error, your key may have been invalidated. This can happen if the key was accidentally committed to a public GitHub repository — Google's secret scanning will automatically revoke it. Visit [Google AI Studio](https://aistudio.google.com), check your key's status under "Get API key," and revoke and regenerate if anything looks off. It takes less than a minute.

## Building Toward More Interesting Things

These early errors are speed bumps, not roadblocks. Once you have a working loop — request goes in, response comes out, errors are handled gracefully — the interesting parts of the API become much more accessible. Structured output, function calling, multimodal inputs: all of it starts from this same foundation.

The natural next step after getting comfortable with `generate_content` is trying `generate_content_stream` for real-time text generation, and then `client.chats.create()` for multi-turn conversations. Both add only a few lines to what you already have.
