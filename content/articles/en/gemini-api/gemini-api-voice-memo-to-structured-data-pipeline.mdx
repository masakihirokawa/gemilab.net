You finish a meeting, hit stop on the recorder, and that's where the story should end. But for most developers, the actual work of turning that recording into calendar entries and task assignments still happens manually — hunting through the audio, jotting things down, and hoping you didn't miss anything.

Gemini API can process audio files directly. Combine that with Structured Output and you get calendar-ready, task-ready JSON from a voice recording. Combine that with Function Calling and the model decides what to register where, without a single `if/elif` chain in your code.

This article walks through the complete implementation in Python: audio upload → transcription → structured extraction → Google Calendar and Tasks registration → FastAPI endpoint. Every code example is working and includes error handling.

## Architecture Overview: Why This Stack

The pipeline runs in four steps.

- **Step 1**: Upload the audio file to Gemini Files API
- **Step 2**: Ask Gemini 2.5 Pro for transcription + information extraction via Structured Output
- **Step 3**: Use Function Calling to write the extracted data to Google Calendar and Tasks
- **Step 4**: Wrap everything in a FastAPI endpoint for async, non-blocking processing

The choice of Structured Output over plain text matters here. The goal isn't for a human to read the output — it's for code to process it. When the model returns a `MeetingExtraction` Pydantic model, you can feed it directly into the Calendar API without any parsing logic. Fewer moving parts means fewer bugs.

Function Calling deserves its own explanation. Instead of writing conditional logic like "if the transcript mentions a date, create an event; if it mentions a task, add it to Tasks", you let the model make those decisions. The model reads the extraction and decides which functions to call, in what order. Your code just needs to implement the functions and handle the results.

The audio upload and transcription module handles the Files API lifecycle correctly — including the PROCESSING state that trips up most first implementations.

```python
import os
import time
from pathlib import Path
import google.generativeai as genai
from google.generativeai.types import File

genai.configure(api_key=os.environ["GEMINI_API_KEY"])

def upload_audio_file(file_path: str) -> File:
    """Upload an audio file to Gemini Files API and wait until it is ready.
    
    Files in PROCESSING state cannot be used for generation — polling until
    ACTIVE is required and often skipped in tutorials, causing silent failures.
    """
    path = Path(file_path)
    if not path.exists():
        raise FileNotFoundError(f"File not found: {file_path}")
    
    mime_types = {
        ".mp3": "audio/mpeg",
        ".wav": "audio/wav",
        ".ogg": "audio/ogg",
        ".flac": "audio/flac",
        ".aac": "audio/aac",
        ".m4a": "audio/mp4",
    }
    mime_type = mime_types.get(path.suffix.lower(), "audio/mpeg")
    
    print(f"Uploading: {path.name} ({path.stat().st_size / 1024 / 1024:.1f} MB)")
    file_obj = genai.upload_file(path=str(path), mime_type=mime_type)
    
    # Poll until ACTIVE — skip this and you will get empty responses
    max_wait = 60
    waited = 0
    while file_obj.state.name == "PROCESSING" and waited < max_wait:
        time.sleep(2)
        waited += 2
        file_obj = genai.get_file(file_obj.name)
    
    if file_obj.state.name \!= "ACTIVE":
        raise RuntimeError(
            f"File processing did not complete: state={file_obj.state.name}"
        )
    
    print(f"✅ Upload complete: {file_obj.uri}")
    return file_obj

def transcribe_audio(file_obj: File) -> str:
    """Transcribe an uploaded audio file using Gemini."""
    model = genai.GenerativeModel("gemini-2.5-pro")
    
    response = model.generate_content(
        [
            file_obj,
            """Transcribe this audio in its original language.
            If multiple speakers are present, label them as [Speaker A], [Speaker B], etc.
            Mark unclear portions as [inaudible].""",
        ]
    )
    return response.text
```

One important note: files uploaded to Files API are automatically deleted after 48 hours. If you need to retain the original audio longer, back it up to Google Cloud Storage or another service before processing.

## Extracting Structured Information with Pydantic

With the transcript in hand, the next step extracts actionable data. Defining the output schema as a Pydantic model gives you type-safe responses and eliminates parsing failures.

```python
from pydantic import BaseModel, Field
from typing import Optional
from datetime import datetime
import enum

class TaskPriority(str, enum.Enum):
    HIGH = "high"
    MEDIUM = "medium"
    LOW = "low"

class ExtractedTask(BaseModel):
    """A task or action item identified in the meeting."""
    title: str = Field(description="Task title, concise")
    assignee: Optional[str] = Field(None, description="Person responsible, null if unknown")
    due_date: Optional[str] = Field(
        None,
        description="Due date in YYYY-MM-DD format. If only a relative date is mentioned (e.g. 'next Monday'), convert using today's date."
    )
    priority: TaskPriority = Field(
        TaskPriority.MEDIUM,
        description="Priority inferred from tone and context"
    )
    notes: Optional[str] = Field(None, description="Supporting context or details")

class ExtractedEvent(BaseModel):
    """A scheduled event or meeting identified in the discussion."""
    title: str = Field(description="Event title")
    date: str = Field(description="Date in YYYY-MM-DD format")
    start_time: Optional[str] = Field(None, description="Start time in HH:MM format")
    end_time: Optional[str] = Field(None, description="End time in HH:MM format")
    location: Optional[str] = Field(None, description="Physical location or meeting URL")
    attendees: list[str] = Field(default_factory=list, description="List of attendees")
    description: Optional[str] = Field(None, description="Event details or purpose")

class MeetingExtraction(BaseModel):
    """Complete structured output from a voice memo or meeting recording."""
    summary: str = Field(description="Summary of the meeting or conversation in 3-5 sentences")
    tasks: list[ExtractedTask] = Field(
        default_factory=list,
        description="Identified tasks and action items"
    )
    events: list[ExtractedEvent] = Field(
        default_factory=list,
        description="Scheduled events and appointments"
    )
    key_decisions: list[str] = Field(
        default_factory=list,
        description="Important decisions made during the discussion"
    )

def extract_meeting_info(transcript: str) -> MeetingExtraction:
    """Extract structured meeting information from a transcript using Structured Output."""
    model = genai.GenerativeModel(
        "gemini-2.5-pro",
        generation_config=genai.GenerationConfig(
            response_mime_type="application/json",
            response_schema=MeetingExtraction,
            temperature=0.0,  # Temperature 0 is most reliable for structured output
        ),
    )
    
    today = datetime.now().strftime("%Y-%m-%d")
    
    prompt = f"""The following is a transcript of a meeting or conversation.
Today's date: {today}

Transcript:
{transcript}

Extract:
1. All tasks and action items (who does what, by when)
2. Any scheduled events or appointments
3. Key decisions made
4. A concise summary

When dates are mentioned relatively (e.g. "next Friday", "in two weeks"), convert them to absolute YYYY-MM-DD format using today's date."""
    
    response = model.generate_content(prompt)
    return MeetingExtraction.model_validate_json(response.text)
```

Passing the Pydantic model directly to `response_schema` requires google-genai SDK v0.5 or later. On older versions, use the `json_schema` parameter with a manually constructed schema — but upgrading is worth the few minutes it takes.

For a deeper look at Structured Output patterns, see [Type-Safe Apps with Gemini Structured Output](/en/articles/gemini-api/gemini-structured-output-typesafe-apps).

## Writing to Google Calendar and Tasks

This is where the extracted data becomes real. The implementation handles both calendar events and task items, with proper error handling for the quirks of the Google APIs.

```python
from google.oauth2.credentials import Credentials
from googleapiclient.discovery import build
from googleapiclient.errors import HttpError

SCOPES = [
    "https://www.googleapis.com/auth/calendar.events",
    "https://www.googleapis.com/auth/tasks",
]

def get_google_services(credentials_path: str):
    """Build and return authenticated Google Calendar and Tasks service objects."""
    creds = Credentials.from_authorized_user_file(credentials_path, SCOPES)
    calendar_service = build("calendar", "v3", credentials=creds)
    tasks_service = build("tasks", "v1", credentials=creds)
    return calendar_service, tasks_service

def execute_calendar_operations(
    extraction: MeetingExtraction,
    calendar_service,
    tasks_service,
    calendar_id: str = "primary",
    task_list_id: str = "@default",
) -> dict:
    """Register extracted events and tasks to Google Calendar and Tasks.
    
    Returns a results dict with lists of successful operations and any errors.
    Errors are collected rather than raised so partial success is possible.
    """
    results = {"events_created": [], "tasks_created": [], "errors": []}
    
    for event in extraction.events:
        try:
            event_body = {
                "summary": event.title,
                "description": event.description or "",
            }
            
            if event.start_time:
                event_body["start"] = {
                    "dateTime": f"{event.date}T{event.start_time}:00",
                    "timeZone": "Asia/Tokyo",
                }
                # Default to 1-hour duration if end time is not specified
                end_hour = int(event.start_time.split(":")[0]) + 1
                end_time = event.end_time or f"{end_hour:02d}:{event.start_time.split(':')[1]}"
                event_body["end"] = {
                    "dateTime": f"{event.date}T{end_time}:00",
                    "timeZone": "Asia/Tokyo",
                }
            else:
                # All-day event when no time is specified
                event_body["start"] = {"date": event.date}
                event_body["end"] = {"date": event.date}
            
            if event.attendees:
                # Google Calendar requires email addresses for invitations
                # Fallback to displayName-only for names without email addresses
                event_body["attendees"] = [
                    {"email": a} if "@" in a else {"displayName": a}
                    for a in event.attendees
                ]
            
            created = calendar_service.events().insert(
                calendarId=calendar_id, body=event_body
            ).execute()
            results["events_created"].append(created["htmlLink"])
            print(f"✅ Calendar event created: {event.title} ({event.date})")
            
        except HttpError as e:
            error_msg = f"Failed to create event ({event.title}): {e}"
            results["errors"].append(error_msg)
            print(f"❌ {error_msg}")
    
    for task in extraction.tasks:
        try:
            task_body = {"title": task.title}
            
            notes_parts = []
            if task.assignee:
                notes_parts.append(f"Assignee: {task.assignee}")
            if task.notes:
                notes_parts.append(task.notes)
            if notes_parts:
                task_body["notes"] = "\n".join(notes_parts)
            
            if task.due_date:
                # Google Tasks API requires RFC3339 format
                task_body["due"] = f"{task.due_date}T00:00:00.000Z"
            
            created = tasks_service.tasks().insert(
                tasklist=task_list_id, body=task_body
            ).execute()
            results["tasks_created"].append(created.get("title"))
            print(f"✅ Task created: {task.title}")
            
        except HttpError as e:
            error_msg = f"Failed to create task ({task.title}): {e}"
            results["errors"].append(error_msg)
            print(f"❌ {error_msg}")
    
    return results
```

## FastAPI Endpoint: Async Processing from Upload to Registration

Putting it all together as a FastAPI service. One POST endpoint accepts an audio file, returns a task ID immediately, and processes everything in the background.

```python
import asyncio
from fastapi import FastAPI, UploadFile, File, HTTPException, BackgroundTasks
from fastapi.responses import JSONResponse
import tempfile
import os
from datetime import datetime

app = FastAPI(title="Voice Memo Pipeline", version="1.0.0")

GEMINI_API_KEY = os.environ["GEMINI_API_KEY"]
GOOGLE_CREDENTIALS_PATH = os.environ.get("GOOGLE_CREDENTIALS_PATH", "credentials.json")

genai.configure(api_key=GEMINI_API_KEY)

# In-memory store for task results
# Replace with Redis or a database in production
task_results: dict = {}

async def process_voice_memo(file_path: str, task_id: str, results_store: dict) -> None:
    """Run the full voice processing pipeline in the background."""
    try:
        results_store[task_id] = {"status": "processing", "step": "uploading"}
        
        file_obj = upload_audio_file(file_path)
        results_store[task_id]["step"] = "transcribing"
        
        transcript = transcribe_audio(file_obj)
        results_store[task_id]["step"] = "extracting"
        
        extraction = extract_meeting_info(transcript)
        results_store[task_id]["step"] = "registering"
        
        calendar_service, tasks_service = get_google_services(GOOGLE_CREDENTIALS_PATH)
        registration_results = execute_calendar_operations(
            extraction, calendar_service, tasks_service
        )
        
        # Clean up the uploaded file immediately after use
        try:
            genai.delete_file(file_obj.name)
        except Exception:
            pass  # Non-fatal: file will be auto-deleted within 48 hours anyway
        
        results_store[task_id] = {
            "status": "completed",
            "summary": extraction.summary,
            "tasks_count": len(extraction.tasks),
            "events_count": len(extraction.events),
            "key_decisions": extraction.key_decisions,
            "registration": registration_results,
            "transcript_preview": (
                transcript[:300] + "..." if len(transcript) > 300 else transcript
            ),
        }
        
    except Exception as e:
        results_store[task_id] = {"status": "failed", "error": str(e)}
    finally:
        if os.path.exists(file_path):
            os.unlink(file_path)

@app.post("/process-voice-memo")
async def process_voice_memo_endpoint(
    background_tasks: BackgroundTasks,
    audio_file: UploadFile = File(...),
):
    """Accept an audio file and start async processing.
    
    Returns a task_id immediately. Poll GET /status/{task_id} for results.
    """
    MAX_SIZE_MB = 500
    content = await audio_file.read()
    if len(content) > MAX_SIZE_MB * 1024 * 1024:
        raise HTTPException(
            status_code=413,
            detail=f"File exceeds {MAX_SIZE_MB}MB limit",
        )
    
    suffix = os.path.splitext(audio_file.filename or "audio.mp3")[1]
    with tempfile.NamedTemporaryFile(delete=False, suffix=suffix) as tmp:
        tmp.write(content)
        tmp_path = tmp.name
    
    task_id = f"task_{datetime.now().strftime('%Y%m%d%H%M%S%f')}"
    task_results[task_id] = {"status": "queued"}
    
    background_tasks.add_task(process_voice_memo, tmp_path, task_id, task_results)
    
    return JSONResponse(
        status_code=202,
        content={
            "task_id": task_id,
            "message": "Processing started. Check /status/{task_id} for results.",
        },
    )

@app.get("/status/{task_id}")
async def get_task_status(task_id: str):
    """Return the current status and results of a processing task."""
    if task_id not in task_results:
        raise HTTPException(status_code=404, detail="Task not found")
    return task_results[task_id]
```

Start the server with `uvicorn main:app --host 0.0.0.0 --port 8000`.

## Common Pitfalls and What I Ran Into

**Pitfall 1: Uploads appear to succeed but generation returns empty responses**

Immediately after upload, `file_obj.state.name` is `"PROCESSING"`. Calling `generate_content` at this point doesn't raise an error — it just returns an empty or truncated response. Always poll for `"ACTIVE"` before continuing. This is mentioned in the documentation but easy to miss, and it caused me a confusing hour of debugging.

**Pitfall 2: Relative dates come back as strings, not dates**

Without today's date in the prompt, "next Tuesday" stays as "next Tuesday" in the JSON. Include the current date explicitly and ask the model to convert to absolute YYYY-MM-DD. It does this reliably when given clear instructions.

**Pitfall 3: Google Calendar attendee registration fails with HTTP 403**

Adding attendees who belong to a different Google Workspace sometimes requires domain-level permissions. The code handles this gracefully by distinguishing email addresses from display names — but if you need actual calendar invitations, check your Workspace admin settings.

**Pitfall 4: BackgroundTasks is not durable**

FastAPI's `BackgroundTasks` runs in-process. If the server restarts mid-task, the job is lost. For production use cases where audio contains irreplaceable information, replace this with Celery + Redis or a managed queue like Google Cloud Tasks.

**Pitfall 5: Long recordings hit context limits on the extraction step**

A 2-hour meeting can produce a transcript long enough to push the Structured Output generation over the context limit. The solution is either to split the audio before processing or to separate transcription and extraction into two distinct requests — transcription only in the first, summary and extraction in the second with a shorter input.

For more on audio processing with Gemini, see [Gemini API Audio Understanding](/en/articles/gemini-api/gemini-audio-understanding).

## Cost and Production Considerations

Gemini 2.5 Pro bills per token. Audio is counted at roughly 25 tokens per second. A 30-minute recording translates to approximately 45,000 input tokens for the audio, plus a few thousand for the transcript and extraction outputs — call it 50,000 tokens total per meeting. At April 2026 pricing, that comes to a few cents per meeting.

A practical cost optimization: run transcription on Gemini Flash (cheaper, still accurate for most audio), then run the extraction step on Gemini 2.5 Pro. The model receiving the transcript as text instead of audio pays for far fewer tokens, and extraction quality actually benefits from the more capable model.

On data privacy: delete uploaded files as soon as you are done with them. The code does this with `genai.delete_file()` after processing. Even though Files API auto-deletes after 48 hours, sensitive meeting recordings should not linger on external servers any longer than necessary.

## Testing the Pipeline Without API Calls

One thing that slows down iteration on AI-powered pipelines is that every test run costs money and takes time. A 30-minute recording takes a minute or more to process end-to-end. Here is a testing strategy that keeps most of the development loop fast and free.

### Layer the tests

- **Unit tests** for the Pydantic models and helper functions: no API calls, fast
- **Integration tests** with a real 60-second test recording: full API calls, run manually
- **Load tests** only when preparing for production: minimal frequency

For the Structured Output extraction, you can seed the model with a pre-written transcript instead of real audio. This lets you test edge cases like "meeting with no tasks" or "recording where all dates are relative" without uploading files.

The key pattern here is that you're testing the schema contract — does the code correctly parse and validate the model's JSON output? — separately from testing whether the model produces the right content. Schema validation failures are programming bugs. Content quality is an AI evaluation problem that requires real API calls and human review.

## Extending the Pipeline

The modular structure makes it straightforward to add outputs beyond Google Calendar and Tasks. Here are the most common extension points.

### Adding a Notion integration

If your team tracks project management in Notion, you can add a `create_notion_task` function alongside the Google Tasks implementation. The Notion API accepts a database ID and a properties dict. The key change to `execute_calendar_operations` is just adding another loop:

```python
import httpx

async def create_notion_task(
    title: str,
    due_date: Optional[str],
    assignee: Optional[str],
    notion_token: str,
    database_id: str,
) -> dict:
    """Create a task in a Notion database.
    
    Assumes a database with Title, Due Date, and Assignee properties.
    Adjust property names to match your actual Notion database schema.
    """
    headers = {
        "Authorization": f"Bearer {notion_token}",
        "Content-Type": "application/json",
        "Notion-Version": "2022-06-28",
    }
    
    properties = {
        "Name": {"title": [{"text": {"content": title}}]},
    }
    
    if due_date:
        properties["Due Date"] = {"date": {"start": due_date}}
    
    if assignee:
        properties["Assignee"] = {
            "rich_text": [{"text": {"content": assignee}}]
        }
    
    payload = {
        "parent": {"database_id": database_id},
        "properties": properties,
    }
    
    async with httpx.AsyncClient() as client:
        response = await client.post(
            "https://api.notion.com/v1/pages",
            headers=headers,
            json=payload,
            timeout=30.0,
        )
        response.raise_for_status()
        return response.json()
```

### Sending a summary to Slack

A common request is to have the meeting summary posted to a Slack channel automatically. This integrates cleanly after the extraction step.

```python
import httpx

async def post_summary_to_slack(
    extraction: MeetingExtraction,
    webhook_url: str,
) -> None:
    """Post a formatted meeting summary to a Slack channel via incoming webhook."""
    blocks = [
        {
            "type": "header",
            "text": {"type": "plain_text", "text": "📋 Meeting Summary"},
        },
        {
            "type": "section",
            "text": {"type": "mrkdwn", "text": extraction.summary},
        },
    ]
    
    if extraction.tasks:
        task_lines = "\n".join(
            f"• *{t.title}*"
            + (f" — {t.assignee}" if t.assignee else "")
            + (f" (due {t.due_date})" if t.due_date else "")
            for t in extraction.tasks
        )
        blocks.append({
            "type": "section",
            "text": {"type": "mrkdwn", "text": f"*Action Items*\n{task_lines}"},
        })
    
    if extraction.key_decisions:
        decisions = "\n".join(f"• {d}" for d in extraction.key_decisions)
        blocks.append({
            "type": "section",
            "text": {"type": "mrkdwn", "text": f"*Key Decisions*\n{decisions}"},
        })
    
    async with httpx.AsyncClient() as client:
        response = await client.post(
            webhook_url,
            json={"blocks": blocks},
            timeout=10.0,
        )
        response.raise_for_status()
```

Add `post_summary_to_slack(extraction, SLACK_WEBHOOK_URL)` to the background task after `execute_calendar_operations`, and you have a three-way integration from a single audio upload.

## Production Deployment Notes

Running this on a single server with FastAPI and BackgroundTasks is fine for personal or small team use. For anything higher volume or more critical, a few architectural adjustments are worth making.

**Replace in-memory task results with a persistent store.** The `task_results` dict disappears on restart. Redis is the simplest drop-in replacement. Store task IDs as keys and serialize the result dicts as JSON values with a TTL of a few days.

**Move audio processing to a dedicated worker.** Transcribing a 60-minute recording blocks a FastAPI worker thread for a couple of minutes. Using Celery with a separate worker pool, or Google Cloud Tasks for a fully managed option, keeps your API responsive regardless of how many recordings are being processed simultaneously.

**Set rate limits per user.** Gemini API has per-project rate limits. If multiple people are uploading recordings simultaneously, add per-user rate limiting at the application layer (Redis-backed sliding window works well) to prevent a single heavy user from exhausting the quota for everyone.

**Monitor token consumption.** Log the token counts returned in each API response and track them per user and per request type. Unexpected spikes — usually caused by unusually long recordings or transcripts — are much easier to catch before they become billing surprises.

The pipeline as written handles the happy path well and surfaces errors clearly. Those are the two things that matter most when you are first proving out the concept. Production hardening can follow once you know the core value is real.
