Hitting unexpected errors while building with the Gemini API can be frustrating, especially when the error message isn't entirely clear. This guide breaks down the most common Gemini API error codes, explains what's actually causing them, and walks through practical fixes.

## Understanding HTTP Error Codes

Before getting into specifics, a quick orientation:

- **4xx errors** mean the problem is on your side — something about the request is wrong
- **5xx errors** mean something went wrong on Google's servers — usually temporary

This distinction is useful because 4xx errors require you to change something in your code or configuration, while 5xx errors often resolve on their own with a retry.

## 400 Bad Request — Invalid Request Format

**Common causes**:
- Malformed JSON in the request body
- Missing required parameters
- Incorrect or outdated model name
- Input exceeding the context window limit

**Example error messages**:
```
400 INVALID_ARGUMENT: Request contains an invalid argument
400 Bad Request: Model not found
```

**How to fix it**:

Check your model name first — it's one of the most common culprits:

```python
import google.generativeai as genai

genai.configure(api_key="YOUR_GEMINI_API_KEY")

# ❌ Outdated model name
model = genai.GenerativeModel('gemini-pro')

# ✅ Current model name (as of 2026)
model = genai.GenerativeModel('gemini-2.5-pro')
```

To see all currently available models:

```python
for m in genai.list_models():
    print(m.name)
```

If your input is very long, consider splitting it into smaller chunks or switching to a model with a larger context window (Gemini 2.5 Pro supports up to 1 million tokens).

## 401 Unauthorized / 403 Forbidden — Authentication Errors

**Common causes**:
- API key is incorrect (typo, incomplete copy)
- API key has been revoked or expired
- The API hasn't been enabled in your Google Cloud project
- Trying to access a resource outside your key's permissions

**Example error messages**:
```
401 API_KEY_INVALID: API key not valid
403 PERMISSION_DENIED: Caller does not have permission
```

**How to fix it**:

1. **Re-verify your API key** at [Google AI Studio](https://aistudio.google.com) and copy it again carefully.

```python
import os

# Always load from environment variables — never hardcode keys
api_key = os.environ.get("GEMINI_API_KEY")
if not api_key:
    raise ValueError("GEMINI_API_KEY environment variable not set")

genai.configure(api_key=api_key)
```

2. **Enable the API**: In Google Cloud Console, confirm that the "Generative Language API" is enabled for your project.

3. **Rotate the key**: If you suspect the key was exposed or compromised, revoke it and generate a new one.

## 429 Too Many Requests — Rate Limit Exceeded

This is the most frequently encountered error when building seriously with Gemini API.

**Common causes**:
- Sending too many requests per minute (RPM limit)
- Exceeding daily request limits (especially on the free tier)
- Sending too many tokens per minute (TPM limit)

**Example error message**:
```
429 RESOURCE_EXHAUSTED: Resource has been exhausted (e.g. check quota usage)
```

**How to fix it**:

Implement **exponential backoff** — the standard approach to handling rate limits gracefully:

```python
import time
import google.generativeai as genai
from google.api_core.exceptions import ResourceExhausted

def generate_with_retry(model, prompt, max_retries=5):
    for attempt in range(max_retries):
        try:
            response = model.generate_content(prompt)
            return response
        except ResourceExhausted:
            if attempt == max_retries - 1:
                raise
            wait_time = (2 ** attempt) + 1  # 2, 3, 5, 9, 17 seconds
            print(f"Rate limited. Retrying in {wait_time} seconds...")
            time.sleep(wait_time)
```

**If you've hit the free tier daily limit**:
- Check your usage at [Google AI Studio](https://aistudio.google.com) under API usage
- Enabling billing in Google Cloud Console significantly raises your limits
- Even on the free tier, staying within RPM limits prevents most 429 errors

## 500 Internal Server Error / 503 Service Unavailable

**Cause**: Something went wrong on Google's side.

**How to fix it**:
- **Wait and retry**: Most 5xx errors resolve within a few minutes
- **Check Google's status page**: [status.cloud.google.com](https://status.cloud.google.com) shows active incidents
- **Build in automatic retries**: Use the `google-api-core` retry utilities for production code

```python
from google.api_core import retry

@retry.Retry(predicate=retry.if_exception_type(Exception))
def stable_generate(model, prompt):
    return model.generate_content(prompt)
```

## Content Filtering Errors

**Symptoms**: Request goes through but returns an empty response, or you see a message indicating the response was blocked by safety filters.

**Cause**: The input or intended output triggered Google's safety systems.

**How to diagnose**:

```python
response = model.generate_content(prompt)

# Inspect the safety evaluation
print(response.prompt_feedback)
for candidate in response.candidates:
    print(candidate.finish_reason)   # SAFETY means it was filtered
    print(candidate.safety_ratings)
```

**How to fix it**:
- Review your prompt for language that might be misinterpreted as harmful
- For medical, legal, or other sensitive topics, consider adding context about legitimate use
- Safety settings thresholds can be adjusted, but always review Google's usage policies before doing so in production

## Quick Reference Table

| Error Code | Common Cause | First Step |
|---|---|---|
| 400 | Invalid format, wrong model name | Check request JSON and model name |
| 401/403 | Bad API key, missing permissions | Re-verify key, enable API |
| 429 | Rate limit hit | Add exponential backoff |
| 500/503 | Google server issue | Wait and retry |

Errors are a normal part of working with any API. Understanding what each code means — and having retry logic built into your code — goes a long way toward making your Gemini-powered application reliable. I hope this guide makes your debugging sessions a little less frustrating.
