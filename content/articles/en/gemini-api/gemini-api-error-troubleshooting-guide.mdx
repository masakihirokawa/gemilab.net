Error messages can be frustrating when you're just getting started with the Gemini API. This guide walks you through the most common errors you'll encounter, explains what causes them, and shows you exactly how to fix them.

## Common Gemini API Errors

When working with the Gemini API, you'll likely run into one of these error codes:

- 400 Bad Request — Your request is malformed or missing required fields
- 401/403 Unauthorized/Forbidden — Authentication failed or credentials are invalid
- 429 Too Many Requests — You've hit the rate limit
- 500/503 Internal Server Error — Google's servers are experiencing issues

The good news is that once you understand what each error means, most of them are easy to fix.

## 400 Bad Request — Invalid Requests and Wrong Model Names

A 400 error means the API can't understand your request. The three most common causes are model name mistakes, malformed JSON, and input that's too long.

### 1. Using the wrong model name

Typos or outdated model names are the number-one cause of 400 errors. The Gemini API only accepts specific model names.

```python
import google.generativeai as genai

genai.configure(api_key="YOUR_GEMINI_API_KEY")

# ❌ Wrong: Model doesn't exist
model = genai.GenerativeModel("gemini-invalid-model")

# ✅ Correct: Use a real model name
model = genai.GenerativeModel("gemini-2.0-flash")
response = model.generate_content("Hello, world!")
print(response.text)
```

You can find the latest available models on the [Google AI Studio model selection page](https://aistudio.google.com/). Here are the most commonly used ones:

- `gemini-2.0-flash` — Fast and efficient
- `gemini-2.0-pro` — Higher quality responses
- `gemini-2.0-flash-thinking-exp-01-21` — Extended thinking capabilities

### 2. Malformed JSON in your request

When using TypeScript or JavaScript, if your request body's JSON structure isn't correct, you'll get a 400 error. Make sure all required fields are present.

```typescript
import { GoogleGenerativeAI } from "@google/generative-ai";

const genAI = new GoogleGenerativeAI("YOUR_GEMINI_API_KEY");
const model = genAI.getGenerativeModel({ model: "gemini-2.0-flash" });

// ✅ Correct request structure
const response = await model.generateContent({
  contents: [
    {
      role: "user",
      parts: [{ text: "Hello, world!" }],
    },
  ],
});
```

Pay special attention to required fields like `contents`, `parts`, and `role`. Missing any of these will cause a 400 error.

### 3. Input text exceeds maximum length

Very long text inputs can trigger a 400 error. Each Gemini model has a context window limit (the maximum amount of text you can send):

- `gemini-2.0-flash` — Up to 1 million tokens

If you need to process large amounts of text, split it into smaller chunks and make multiple requests.

## 429 Too Many Requests — Rate Limiting

You'll get a 429 error if you send too many requests in a short time. The Gemini API has different rate limits depending on whether you're using the free tier or a paid plan.

### Free tier rate limits

When using Google AI Studio for free:

- Maximum 60 requests per minute
- Daily request limits vary

### Paid tier rate limits

With a Google Cloud paid plan:

- Maximum 360 requests per minute (standard)
- Varies by plan and model

### Exponential backoff strategy

When you hit a 429 error, don't immediately retry. Instead, use exponential backoff — gradually increasing wait times between retries.

```python
import time
import google.generativeai as genai

genai.configure(api_key="YOUR_GEMINI_API_KEY")
model = genai.GenerativeModel("gemini-2.0-flash")

def generate_with_retry(prompt, max_retries=5):
    """Retry logic with exponential backoff"""
    for attempt in range(max_retries):
        try:
            response = model.generate_content(prompt)
            return response.text
        except Exception as e:
            if "429" in str(e):
                # Wait: 1s, 2s, 4s, 8s, 16s...
                wait_time = 2 ** attempt
                print(f"Rate limited. Waiting {wait_time} seconds...")
                time.sleep(wait_time)
            else:
                raise

# Usage
result = generate_with_retry("What is the capital of France?")
print(result)
```

Here's the TypeScript equivalent:

```typescript
import { GoogleGenerativeAI } from "@google/generative-ai";

const genAI = new GoogleGenerativeAI("YOUR_GEMINI_API_KEY");
const model = genAI.getGenerativeModel({ model: "gemini-2.0-flash" });

async function generateWithRetry(prompt: string, maxRetries = 5): Promise<string> {
  for (let attempt = 0; attempt < maxRetries; attempt++) {
    try {
      const response = await model.generateContent(prompt);
      return response.response.text();
    } catch (error) {
      if (error instanceof Error && error.message.includes("429")) {
        const waitTime = Math.pow(2, attempt) * 1000; // Convert to milliseconds
        console.log(`Rate limited. Waiting ${waitTime / 1000} seconds...`);
        await new Promise((resolve) => setTimeout(resolve, waitTime));
      } else {
        throw error;
      }
    }
  }
  throw new Error("Max retries exceeded");
}

// Usage
const result = await generateWithRetry("What is the capital of France?");
console.log(result);
```

## 500/503 Server Errors — Google's Infrastructure Issues

When you get a 500 (Internal Server Error) or 503 (Service Unavailable) error, Google's servers are experiencing temporary issues. This isn't a problem with your code or credentials.

### What to do

1. Wait a moment and retry (use exponential backoff)
2. Check the [Google Cloud Status Dashboard](https://status.cloud.google.com/) to see if there are any known issues
3. If the problem persists, contact Google Cloud Support

```python
import time

def generate_with_500_retry(prompt, max_retries=3):
    """Retry logic for server errors"""
    for attempt in range(max_retries):
        try:
            response = model.generate_content(prompt)
            return response.text
        except Exception as e:
            error_code = str(e)
            if "500" in error_code or "503" in error_code:
                wait_time = 5 * (attempt + 1)  # 5s, 10s, 15s
                print(f"Server error. Retrying in {wait_time} seconds...")
                time.sleep(wait_time)
            else:
                raise
```

## Setup and context

You're building a solid application with Gemini API, and suddenly it crashes with a `429 Too Many Requests` error. Service down, users frustrated, and you're not sure why.

This error signals that you've hit the API's quota limit, but that simple explanation masks several deeper causes. Maybe you've outgrown the free tier. Perhaps your retry logic isn't right. Or your quota settings in Google Cloud Console need adjustment. Without understanding the root cause, you'll keep bumping into the same wall.

## What 429 Really Means — And Why RESOURCE_EXHAUSTED Appears

### When You'll See a 429 Error

Three main scenarios trigger 429 errors in Gemini API:

- **RPM (Requests Per Minute) limit**: You've exceeded the number of requests allowed in a single minute
- **RPD (Requests Per Day) limit**: You've exceeded the daily request count
- **TPM (Tokens Per Minute) limit**: You've processed too many tokens in 60 seconds

The free tier has strict thresholds for all three. During development, you might never hit them, but when your app scales, 429 errors appear without warning.

### RESOURCE_EXHAUSTED: The Underlying Status

```json
// What a 429 response looks like
{
  "error": {
    "code": 429,
    "message": "Resource has been exhausted (e.g. check quota).",
    "status": "RESOURCE_EXHAUSTED"
  }
}
```

Inside Google's API infrastructure, `RESOURCE_EXHAUSTED` is the detailed status code, and HTTP 429 is the higher-level representation. When you see "Resource has been exhausted," you've hit a quota limit.

This differs from `INVALID_ARGUMENT` or `PERMISSION_DENIED`, which signal malformed requests or auth issues—not quota problems.

## Free Tier vs. Paid Plan: A Side-by-Side Comparison

### Free Tier Quotas

The free tier is designed for development and testing, not production workloads.

| Quota | Limit | Unit |
| --- | --- | --- |
| Requests Per Minute (RPM) | 60 | requests/minute |
| Requests Per Day (RPD) | 1,500 | requests/day |
| Tokens Per Minute (TPM) | 10,000 | tokens/minute |
| Concurrent Connections | 2 | sessions |

These limits apply to your **entire project**, not per user or app. If you're running multiple applications or scripts under the same project, they share the same quota pool, causing limits to be reached faster.

### Paid Tier (Pay-as-you-go) Quotas

Upgrading to a paid plan dramatically increases these limits:

| Quota | Limit | Unit |
| --- | --- | --- |
| RPM | 1,000–10,000 | requests/minute (varies by model/region) |
| RPD | Unlimited | — |
| TPM | 100,000–1,000,000 | tokens/minute (scales with purchase) |
| Concurrent Connections | 100 | sessions |

Additionally, you can set a **Spend Limit** in Google Cloud Console to prevent surprise bills.

## Emergency Fixes for Active 429 Errors

### Three Techniques You Can Implement Immediately

**1. Exponential Backoff Retry Strategy**

```python
import time
import anthropic

def call_gemini_with_backoff(prompt, max_retries=5):
    client = anthropic.Anthropic(api_key="YOUR_GEMINI_API_KEY")

    for attempt in range(max_retries):
        try:
            response = client.messages.create(
                model="gemini-2.0-flash",
                max_tokens=1024,
                messages=[
                    {"role": "user", "content": prompt}
                ]
            )
            return response.content[0].text
        except Exception as e:
            if "429" in str(e) or "RESOURCE_EXHAUSTED" in str(e):
                # Exponential backoff: wait 2^attempt seconds
                wait_time = 2 ** attempt
                print(f"Rate limited. Waiting {wait_time} seconds...")
                time.sleep(wait_time)
            else:
                raise

    raise Exception("Max retries exceeded")

# Usage example
result = call_gemini_with_backoff("Explain quantum entanglement")
print(result)
```

**2. Request Queuing**

When requests spike unpredictably, queuing ensures even distribution:

```python
import queue
import threading
import time

class GeminiQueue:
    def __init__(self, max_rpm=60):
        self.queue = queue.Queue()
        self.max_rpm = max_rpm
        self.request_times = []
        self.lock = threading.Lock()

    def add_request(self, prompt):
        self.queue.put(prompt)

    def process_requests(self):
        while True:
            prompt = self.queue.get()
            self._rate_limit_check()
            # Actual API call here
            self.queue.task_done()

    def _rate_limit_check(self):
        with self.lock:
            now = time.time()
            # Keep only requests from the last 60 seconds
            self.request_times = [t for t in self.request_times if now - t < 60]

            if len(self.request_times) >= self.max_rpm:
                # Wait until the oldest request is outside the 60-second window
                wait_time = 60 - (now - self.request_times[0])
                time.sleep(wait_time)

            self.request_times.append(now)

# Usage example
gq = GeminiQueue(max_rpm=50)
for i in range(100):
    gq.add_request(f"Question {i}")
```

**3. Enforce Serial Processing on Free Tier**

Free tier limits concurrent connections to 2. Force sequential processing:

```python
import asyncio

async def process_sequentially(prompts):
    """Limit concurrent connections to 1 to avoid free tier limits"""
    semaphore = asyncio.Semaphore(1)

    async def fetch_with_semaphore(prompt):
        async with semaphore:
            # API call
            await asyncio.sleep(1)  # Delay to respect rate limits
            return f"Response to: {prompt}"

    tasks = [fetch_with_semaphore(p) for p in prompts]
    return await asyncio.gather(*tasks)

# Usage example
prompts = ["What is AI?", "How does machine learning work?"]
results = asyncio.run(process_sequentially(prompts))
```

## Error 2: RESOURCE_EXHAUSTED — Rate Limit Hit

```
google.api_core.exceptions.ResourceExhausted: 429 Resource has been exhausted
(e.g. check quota usage or reduce request rate).
```

Free-tier usage of Gemini 2.0 Flash is capped at 15 requests per minute (RPM). Running a tight loop will hit this immediately. Exponential backoff is the right fix:

```python
import google.generativeai as genai
import time
import os
from google.api_core import exceptions

genai.configure(api_key=os.environ["GOOGLE_API_KEY"])
model = genai.GenerativeModel("gemini-2.0-flash")

def call_gemini_with_retry(prompt: str, max_retries: int = 5) -> str:
    """
    Wraps a Gemini API call with exponential backoff retry on rate limits.
    Backoff schedule: 1s → 2s → 4s → 8s → 16s
    """
    for attempt in range(max_retries):
        try:
            response = model.generate_content(prompt)
            return response.text
        
        except exceptions.ResourceExhausted:
            if attempt == max_retries - 1:
                raise
            wait = 2 ** attempt
            print(f"Rate limited. Waiting {wait}s... (attempt {attempt + 1}/{max_retries})")
            time.sleep(wait)
        
        except exceptions.GoogleAPICallError as e:
            print(f"API error: {e}")
            raise

# Process a list of items with a small delay between each
items = ["topic 1", "topic 2", "topic 3"]
for i, item in enumerate(items):
    result = call_gemini_with_retry(f"Explain {item} briefly.")
    print(result[:100])
    if i < len(items) - 1:
        time.sleep(1)  # Minimum 1-second gap between requests
```

For production workloads, consider upgrading to a paid tier to get significantly higher rate limits.

## Error 4: Context Window Overflow

```
google.api_core.exceptions.InvalidArgument: 400 Request payload size exceeds the limit
```

Or on token count:
```
Invalid request: the total input token count exceeds the model's limit
```

You've exceeded the model's context window. Before sending a long request, check the token count:

```python
import google.generativeai as genai
import os

genai.configure(api_key=os.environ["GOOGLE_API_KEY"])
model = genai.GenerativeModel("gemini-2.0-flash")

def count_tokens(text: str) -> int:
    """Count tokens before sending to avoid overflow errors."""
    response = model.count_tokens(text)
    return response.total_tokens

def safe_generate(prompt: str, max_tokens: int = 500_000) -> str | None:
    """
    Check token count before sending.
    Truncates intelligently if over the limit.
    """
    token_count = count_tokens(prompt)
    
    if token_count > max_tokens:
        print(f"Prompt too long: {token_count} tokens (limit: {max_tokens})")
        # Keep the first and last quarters for context
        quarter = len(prompt) // 4
        prompt = prompt[:quarter] + "\n...[content omitted]...\n" + prompt[-quarter:]
        print(f"Truncated to ~{count_tokens(prompt)} tokens")
    
    try:
        response = model.generate_content(prompt)
        return safe_get_text(response)
    except Exception as e:
        print(f"Error: {e}")
        return None

# Example: check token count before a large request
long_text = "..." * 1000  # Very long text
print(f"Token count: {count_tokens(long_text)}")
```

Gemini 2.5 Pro and Flash support up to 1 million tokens of context — if you're processing large documents, upgrading to one of those models is often simpler than implementing chunking.

## Error 5: Empty Response or Blocked by Safety Filters

```
AttributeError: 'NoneType' object has no attribute 'text'
```

Or:
```
finish_reason: SAFETY
safety_ratings { ... probability: HIGH }
```

Gemini's safety filters may block responses for certain content types. The response object comes back, but `response.text` raises an error. Always check the response before accessing `.text`:

```python
def safe_get_text(response) -> str | None:
    """
    Safely extract text from a Gemini response.
    Handles safety blocks, recitation blocks, and token limits.
    """
    if not response.candidates:
        # Completely blocked — check prompt_feedback for details
        print(f"Response blocked: {response.prompt_feedback}")
        return None
    
    candidate = response.candidates[0]
    finish_reason = candidate.finish_reason.name  # "STOP", "MAX_TOKENS", "SAFETY", etc.
    
    if finish_reason == "SAFETY":
        ratings = {r.category.name: r.probability.name 
                   for r in candidate.safety_ratings}
        print(f"Safety block. Ratings: {ratings}")
        return None
    
    if finish_reason == "RECITATION":
        print("Blocked: possible copyright content detected.")
        return None
    
    if finish_reason == "MAX_TOKENS":
        print("Warning: response truncated at max_output_tokens. Consider increasing it.")
        # Can still return partial text
    
    try:
        return candidate.content.parts[0].text
    except (IndexError, AttributeError):
        return None

# Always use this wrapper instead of response.text directly
response = model.generate_content("Your prompt here")
text = safe_get_text(response)

if text:
    print(text)
else:
    print("Couldn't get a response. Try rephrasing the prompt.")
```

If you're seeing frequent safety blocks on legitimate content, try rephrasing the prompt in more neutral language. You can also adjust `safety_settings` in `GenerationConfig`, though default settings are appropriate for most use cases.

## Quick Diagnostic Checklist

When you hit an API error, check these in order:

1. `echo $GOOGLE_API_KEY` — is the variable set and does the value look right?
2. Model name — does it exactly match the [official list](https://ai.google.dev/gemini-api/docs/models/gemini)?
3. Token count — use `model.count_tokens()` before sending large requests
4. Response structure — check `response.candidates` before accessing `.text`
5. Rate limits — add `time.sleep(1)` between requests in loops, add retry logic

These five checks resolve the vast majority of Gemini API issues that come up during development.
