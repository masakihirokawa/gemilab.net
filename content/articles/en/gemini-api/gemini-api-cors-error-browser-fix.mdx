If you've ever tried calling the Gemini API directly from a React component or the browser console, you've probably seen this error plastered across your DevTools:

```
Access to fetch at 'https://generativelanguage.googleapis.com/...' 
from origin 'http://localhost:3000' has been blocked by CORS policy: 
No 'Access-Control-Allow-Origin' header is present on the requested resource.
```

This is one of the most common roadblocks developers hit when getting started with the Gemini API — and the fix is simpler than it looks.

## Why Does the Gemini API Trigger CORS Errors?

CORS (Cross-Origin Resource Sharing) is a browser security mechanism that blocks HTTP requests made to a different origin (domain, port, or protocol) unless the server explicitly says it's okay.

When your app at `http://localhost:3000` tries to fetch from `generativelanguage.googleapis.com`, the browser performs a CORS check. If the server doesn't respond with an `Access-Control-Allow-Origin` header that permits your origin, the browser blocks the response.

The Gemini API is designed to be called from **server-side code** — backends, cloud functions, CLI tools. It doesn't include the CORS headers that browsers require for client-side requests, which is why calling it directly from your frontend always fails.

### The Code That Breaks in the Browser

```javascript
// ❌ This will throw a CORS error in the browser
const response = await fetch(
  'https://generativelanguage.googleapis.com/v1beta/models/gemini-2.0-flash:generateContent?key=YOUR_API_KEY',
  {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      contents: [{ parts: [{ text: 'Hello!' }] }]
    })
  }
);
```

No matter what HTTP client you use (fetch, axios, ky — it doesn't matter), the browser will block this.

## Three Root Causes to Check

**Pattern 1: You're calling the API from client-side code**

The most common cause. Any `fetch()` or `axios.get()` call inside a React component, a `useEffect`, or an `onClick` handler runs in the browser and will trigger CORS errors.

**Pattern 2: Your API key is exposed in the frontend**

Even if you find a workaround for CORS, embedding your API key in client-side JavaScript is a serious security risk. Anyone can open DevTools and steal it.

**Pattern 3: Your proxy works locally but fails in production**

A Vite dev server proxy can mask the issue in development. When you deploy, the proxy is gone — and CORS errors come back in production.

## The Fix: Route All API Calls Through Your Server

The solution is straightforward: **never call the Gemini API from the browser**. Instead, call your own server, which then calls Gemini on your behalf. Since your frontend and your server share the same origin (or you control the CORS headers), the browser has no objection.

### Fix 1: Next.js Route Handlers (Recommended)

If you're using Next.js, this is by far the cleanest approach.

```typescript
// app/api/gemini/route.ts
import { NextRequest, NextResponse } from 'next/server';

export async function POST(request: NextRequest) {
  const { prompt } = await request.json();

  // API key lives in a server-side env variable — never exposed to the browser
  const apiKey = process.env.GEMINI_API_KEY;
  if (!apiKey) {
    return NextResponse.json({ error: 'API key not configured' }, { status: 500 });
  }

  const response = await fetch(
    `https://generativelanguage.googleapis.com/v1beta/models/gemini-2.0-flash:generateContent?key=${apiKey}`,
    {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        contents: [{ parts: [{ text: prompt }] }]
      })
    }
  );

  const data = await response.json();
  // Expected response: { candidates: [{ content: { parts: [{ text: '...' }] } }] }
  return NextResponse.json(data);
}
```

Now your React components call your own API endpoint instead:

```typescript
// components/GeminiChat.tsx
async function sendMessage(prompt: string) {
  // ✅ Same origin — no CORS issue
  const response = await fetch('/api/gemini', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ prompt })
  });
  const data = await response.json();
  return data.candidates?.[0]?.content?.parts?.[0]?.text ?? '';
}
```

Don't forget your environment variable:

```bash
# .env.local — do NOT commit this to Git
GEMINI_API_KEY=YOUR_GEMINI_API_KEY
```

### Fix 2: Express.js Proxy (Node.js Backend)

For setups where your React app (Vite or CRA) and backend are separate:

```javascript
// server.js
const express = require('express');
const cors = require('cors');

const app = express();
app.use(express.json());

// Only allow requests from your frontend — avoid using '*' in production
app.use(cors({ origin: process.env.FRONTEND_URL || 'http://localhost:5173' }));

app.post('/api/gemini', async (req, res) => {
  const { prompt } = req.body;

  try {
    const response = await fetch(
      `https://generativelanguage.googleapis.com/v1beta/models/gemini-2.0-flash:generateContent?key=${process.env.GEMINI_API_KEY}`,
      {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({
          contents: [{ parts: [{ text: prompt }] }]
        })
      }
    );
    const data = await response.json();
    res.json(data);
  } catch (err) {
    res.status(500).json({ error: 'Failed to call Gemini API' });
  }
});

app.listen(3001, () => console.log('Proxy server running on port 3001'));
```

### Fix 3: Use the Official SDK on the Server Side

The `@google/generative-ai` package is built for Node.js environments. Use it inside server-side code only — never in browser-side modules.

```typescript
// app/api/gemini/route.ts
import { GoogleGenerativeAI } from '@google/generative-ai';
import { NextRequest, NextResponse } from 'next/server';

const genAI = new GoogleGenerativeAI(process.env.GEMINI_API_KEY!);

export async function POST(request: NextRequest) {
  const { prompt } = await request.json();

  const model = genAI.getGenerativeModel({ model: 'gemini-2.0-flash' });
  const result = await model.generateContent(prompt);
  const text = result.response.text();
  // Expected response: { text: "Response from Gemini" }

  return NextResponse.json({ text });
}
```

## How to Verify the Fix

After implementing the proxy, confirm the error is gone:

**Step 1:** Open DevTools (F12 or Cmd+Option+I) and go to the **Network** tab.

**Step 2:** Trigger a Gemini API call in your app.

**Step 3:** Look at the request. You should now see a request to `/api/gemini` (your own server) returning `200 OK` — not a failed request to `generativelanguage.googleapis.com`.

**Step 4:** Check the **Console** tab. If the phrase "CORS policy" no longer appears, you're done.

## Prevention: Best Practices to Avoid CORS Issues Long-Term

**Never prefix your API key with `NEXT_PUBLIC_`**

Any variable prefixed with `NEXT_PUBLIC_` is bundled into your client-side JavaScript and visible to anyone using DevTools.

```bash
# ✅ Server-side only (safe)
GEMINI_API_KEY=YOUR_GEMINI_API_KEY

# ❌ Exposed to the browser (dangerous)
NEXT_PUBLIC_GEMINI_API_KEY=YOUR_GEMINI_API_KEY
```

**Add `.env.local` to `.gitignore`**

```
.env.local
.env*.local
```

**Set environment variables on your deployment platform**

Vercel, Cloudflare Pages, and similar platforms have dashboards for setting environment variables. Your `.env.local` file is never deployed — you need to configure the values there explicitly.

## Summary

A Gemini API CORS error isn't a bug — it's the browser doing its job. The API simply isn't designed for direct browser access. The fix is to route all API calls through your own server, keeping your API key off the client and letting the browser communicate with an endpoint it trusts.

With Next.js Route Handlers or an Express proxy, you can resolve this in under 30 lines of code. Build this pattern from day one, and you'll never need to fight CORS again.
