There's a counterintuitive line in the Gemma 4 release notes: the smallest models — E2B and E4B — support audio input and OCR, while the larger 26B and 31B variants do not. That seems backwards until you think about where E2B and E4B are meant to run: on smartphones and edge devices, where network dependency is a liability, not a feature.

The design intent is an offline-first multimodal AI that handles voice, text, and images without a single API call. Here's how to put those capabilities to work.

## Why the Smaller Models Have More Modalities

The four Gemma 4 models divide cleanly by deployment target. E2B and E4B are built for smartphones, IoT devices, and edge hardware — environments where low latency and offline operation matter more than raw capacity. Audio input, OCR, and multilingual handwriting recognition are included precisely because those use cases arise in edge deployments.

The 26B MoE and 31B Dense models target consumer GPUs and cloud environments, where dedicated audio transcription services (like Google Cloud Speech-to-Text) are typically available and the workload justifies specialized tooling.

What makes this less counterintuitive than it first appears: the Per-Layer Embeddings (PLE) technology in E2B and E4B significantly reduces actual compute cost relative to the raw parameter count. Running multimodal inference — audio plus image plus text simultaneously — stays within the power and memory budgets of mobile hardware.

## Implementing Audio Input

With Ollama running E2B or E4B locally, audio files (wav, mp3) are passed as Base64-encoded content in the same field used for images:

```python
import requests
import base64

def transcribe_audio_gemma4(audio_file_path: str) -> str:
    with open(audio_file_path, "rb") as f:
        audio_b64 = base64.b64encode(f.read()).decode("utf-8")

    response = requests.post(
        "http://localhost:11434/api/generate",
        json={
            "model": "gemma4:4b",
            "prompt": "Transcribe this audio. If multiple speakers are present, distinguish between them.",
            "images": [audio_b64],
            "stream": False
        }
    )
    return response.json()["response"]

transcript = transcribe_audio_gemma4("meeting_recording.wav")
print(transcript)
```

For real-time microphone input, PyAudio handles the stream capture and feeds chunks to the model:

```python
import pyaudio
import wave
import tempfile
import requests
import base64

def real_time_transcription(duration_seconds: int = 5) -> str:
    p = pyaudio.PyAudio()
    stream = p.open(
        format=pyaudio.paInt16,
        channels=1,
        rate=16000,
        input=True,
        frames_per_buffer=1024
    )

    print(f"Recording for {duration_seconds} seconds...")
    frames = [stream.read(1024) for _ in range(int(16000 / 1024 * duration_seconds))]
    stream.stop_stream()
    stream.close()
    p.terminate()

    with tempfile.NamedTemporaryFile(suffix=".wav", delete=False) as tmp:
        with wave.open(tmp.name, "wb") as wf:
            wf.setnchannels(1)
            wf.setsampwidth(p.get_sample_size(pyaudio.paInt16))
            wf.setframerate(16000)
            wf.writeframes(b"".join(frames))
        return transcribe_audio_gemma4(tmp.name)

result = real_time_transcription(10)
print("Transcript:", result)
```

## OCR and Multilingual Handwriting Recognition

E2B and E4B support OCR across 140+ languages, including handwritten text. Japanese handwriting, Arabic invoices, mixed-language documents — a single model handles them all without language-specific preprocessing.

```python
import requests
import base64

def ocr_with_gemma4(image_path: str, language_hint: str = "Japanese") -> str:
    with open(image_path, "rb") as f:
        image_b64 = base64.b64encode(f.read()).decode("utf-8")

    response = requests.post(
        "http://localhost:11434/api/generate",
        json={
            "model": "gemma4:2b",
            "prompt": f"Extract all text from this image. Language: {language_hint}. Preserve layout structure (paragraphs, tables, lists).",
            "images": [image_b64],
            "stream": False
        }
    )
    return response.json()["response"]

extracted = ocr_with_gemma4("handwritten_notes.jpg", "Japanese")
print(extracted)
```

For multi-page PDFs, convert each page to an image first:

```python
import io
from pdf2image import convert_from_path
from PIL import Image

def ocr_pdf(pdf_path: str) -> list:
    pages = convert_from_path(pdf_path)
    results = []
    for i, page in enumerate(pages):
        buf = io.BytesIO()
        page.save(buf, format="JPEG")
        img_b64 = base64.b64encode(buf.getvalue()).decode("utf-8")

        resp = requests.post(
            "http://localhost:11434/api/generate",
            json={
                "model": "gemma4:2b",
                "prompt": f"Extract all text from page {i + 1}.",
                "images": [img_b64],
                "stream": False
            }
        )
        results.append(resp.json()["response"])
    return results
```

## Variable Resolution: What It Means for Mobile Developers

Gemma 4 processes images at variable aspect ratios and resolutions — no preprocessing required to resize portrait phone shots, landscape screenshots, or square social media images before sending them to the model.

One constraint to know: each image is capped at 1,120 tokens. High-resolution images are automatically downscaled, which can reduce accuracy for small-print OCR. For dense printed text, crop the region of interest before sending rather than passing the full image:

```python
from PIL import Image
import io

def crop_and_ocr(image_path: str, region: tuple) -> str:
    # region: (left, top, right, bottom) in pixel coordinates
    img = Image.open(image_path).crop(region)
    img.thumbnail((1024, 1024), Image.LANCZOS)

    buf = io.BytesIO()
    img.save(buf, format="JPEG", quality=90)
    img_b64 = base64.b64encode(buf.getvalue()).decode("utf-8")

    resp = requests.post(
        "http://localhost:11434/api/generate",
        json={
            "model": "gemma4:4b",
            "prompt": "Extract all text from this image accurately.",
            "images": [img_b64],
            "stream": False
        }
    )
    return resp.json()["response"]
```

## Where E2B/E4B Shine Over the Larger Models

The use cases where the smaller multimodal Gemma 4 models outperform their larger siblings (which lack audio/OCR):

**Offline-first note-taking apps**: Voice memos transcribed without any network request, handwritten scan import handled by the same model. Zero external API dependency.

**Field operations tooling**: Construction site inspection reports dictated by voice, floor plan OCR — same model, same local inference, same privacy guarantee.

**Multilingual document processing**: Hospitality, trade, logistics — industries handling documents in varied languages benefit from a single on-device model that reads across writing systems without a language-detection preprocessing step.

Apache 2.0 licensing removes any commercial deployment friction. Start with Ollama for rapid prototyping, then evaluate Raspberry Pi 5 or Qualcomm Dragonwing for production edge deployment.
