## Bringing Gemini's Vision to Your Automation Workflows

One of Gemini's most powerful capabilities is its ability to process not just text but images, video, and audio in a single request. When you pair this multimodal understanding with n8n's visual automation engine, you can automate tasks that previously required human eyes.

Here's what becomes possible:

- Auto-tag product images on an e-commerce platform with categories, colors, and features
- Monitor uploaded images for potential brand guideline violations
- Read receipts or invoices from photos and extract line items, totals, and dates
- Detect changes in a surveillance feed and trigger alerts automatically

In this guide, we'll build a practical workflow: **images dropped into a Google Drive folder get analyzed by Gemini and logged to a Google Sheet** — a pattern you can adapt to many real-world use cases.

---

## What You'll Need

- An n8n account (the free n8n.cloud tier works fine)
- A Gemini API key from Google AI Studio
- A Google account (for Drive and Sheets integration)

---

## Getting Your Gemini API Key from Google AI Studio

Google AI Studio ([aistudio.google.com](https://aistudio.google.com/)) is Google's developer interface for experimenting with and deploying Gemini models.

1. Go to Google AI Studio and sign in with your Google account
2. In the left sidebar, click **Get API key**
3. Click **Create API key** and select a project
4. Copy your key immediately and store it securely — treat it like a password

> **Security note:** Store your API key in n8n's Credentials manager, not in plain text in your workflow. Never expose it in logs or commit it to version control.

---

## Adding the Gemini API Credential to n8n

1. In n8n, go to **Credentials → Add Credential → Header Auth**
2. Fill in:
   - **Name**: `Gemini API`
   - **Header Name**: `x-goog-api-key`
   - **Header Value**: your API key
3. Click **Save**

## Workflow Architecture

```
Google Drive Trigger (new file)
  ↓
HTTP Request (download image binary)
  ↓
Set Node (prepare Base64 and MIME type)
  ↓
HTTP Request (Gemini API multimodal request)
  ↓
Set Node (parse response)
  ↓
Google Sheets (log results)
```

---

## Step 1: Google Drive Trigger

Add a **Google Drive Trigger** node:
- **Event**: `File Created`
- **Drive**: your Google Drive
- **Folder**: the folder you'll drop images into

Create a dedicated Google Drive folder for this workflow and drop a test image (JPEG or PNG) into it to trigger a test run.

---

## Step 2: Download the Image Binary

The Drive Trigger gives you the file ID, not the actual image data. Add an **HTTP Request** node to fetch the binary:

```
Method: GET
URL: https://www.googleapis.com/drive/v3/files/{{ $json.id }}?alt=media
Authentication: OAuth2 (your Google Drive credential)
Response Format: File
```

---

## Step 3: Prepare the Base64 Payload

Gemini's multimodal API expects images as Base64-encoded `inline_data`. Add a **Set** node:

```json
{
  "imageBase64": "{{ $binary.data.data }}",
  "mimeType": "{{ $binary.data.mimeType }}"
}
```

n8n's `$binary.data.data` already contains the Base64-encoded content, so you can pass it directly.

---

## Step 4: Send the Multimodal Request to Gemini

This is the core step. Add an **HTTP Request** node:

```
Method: POST
URL: https://generativelanguage.googleapis.com/v1beta/models/gemini-2.0-flash:generateContent
Authentication: Header Auth → Gemini API
Content-Type: application/json
```

**Request Body:**

```json
{
  "contents": [
    {
      "parts": [
        {
          "text": "Analyze this image and return a JSON object with the following fields:\n1. category (e.g., Food, Electronics, Clothing)\n2. colors (up to 3 main colors)\n3. keywords (up to 5 descriptive keywords)\n4. quality_score (1–10)\n5. description (one sentence, max 100 characters)"
        },
        {
          "inline_data": {
            "mime_type": "{{ $json.mimeType }}",
            "data": "{{ $json.imageBase64 }}"
          }
        }
      ]
    }
  ],
  "generationConfig": {
    "temperature": 0.2,
    "responseMimeType": "application/json"
  }
}
```

Setting `temperature: 0.2` improves consistency for structured outputs. The `responseMimeType: "application/json"` instructs Gemini to respond with valid JSON directly.

**Sample Response:**

```json
{
  "candidates": [
    {
      "content": {
        "parts": [
          {
            "text": "{\"category\":\"Food\",\"colors\":[\"red\",\"green\",\"white\"],\"keywords\":[\"fresh\",\"salad\",\"vegetables\",\"healthy\",\"colorful\"],\"quality_score\":8,\"description\":\"A colorful salad with fresh vegetables, neatly arranged on a white plate.\"}"
          }
        ]
      }
    }
  ]
}
```

---

## Step 5: Log Results to Google Sheets

Extract the parsed values and write them to a spreadsheet:

```
{{ JSON.parse($json.candidates[0].content.parts[0].text).category }}
{{ JSON.parse($json.candidates[0].content.parts[0].text).quality_score }}
```

Add a **Google Sheets** node, select your spreadsheet and sheet, then map each field to the appropriate column.

## Troubleshooting Common Issues

### Issue 1: Invalid MIME Type

**Symptom:** `Invalid mime type` error from the API.

**Fix:**
- Gemini supports `image/jpeg`, `image/png`, `image/gif`, and `image/webp`
- BMP and TIFF formats are not supported inline. Check the `mimeType` returned by Google Drive and convert if needed

### Issue 2: Request Too Large / Timeout

**Symptom:** `Request entity too large` or the HTTP request times out.

**Fix:**
- Images larger than ~10MB can exceed request limits when Base64-encoded
- Compress images before uploading, or switch to Gemini's [File API](https://ai.google.dev/) for large files (the File API supports up to 2GB per file)

### Issue 3: JSON Parsing Fails

**Symptom:** `SyntaxError` when trying to parse Gemini's response.

**Fix:**
- Confirm that `responseMimeType: "application/json"` is set in `generationConfig`
- Add explicit instructions in the prompt: "Return only valid JSON with no additional text"
- Lower the `temperature` to 0.1 for more deterministic output

### Issue 4: Image Not Recognized

**Symptom:** Gemini returns "I cannot analyze this image" or an empty response.

**Fix:**
- The image may be too small (minimum ~32×32px), too dark, or corrupted
- Verify that the binary data is being correctly passed — check that the n8n node outputs a binary `data` field before encoding
- Try with a clean, well-lit JPEG as a baseline test

### Issue 5: Google Drive Permission Error

**Symptom:** `403 Forbidden` or `Insufficient permissions`.

**Fix:**
- Your Google OAuth credential needs the `drive.readonly` scope at minimum
- In n8n.cloud, try disconnecting and reconnecting the Google credential to refresh the OAuth token
- Make sure the folder you're watching is accessible with the authenticated account

## Advanced Pattern: Route Images by Quality Score

You can extend this workflow to automatically handle low-quality images:

```
Gemini Response
  ↓
IF Node: quality_score < 5
  ↓ YES                       ↓ NO
Slack Alert (needs review)   Log to Sheets (approved)
```

This lets Gemini's judgment drive automated decision-making — going beyond simple data extraction into intelligent routing.

## FAQ

### Q1. Can I use Gemini 2.5 Pro instead of 2.0 Flash?

**A:** Yes. Replace `gemini-2.0-flash` in the URL with `gemini-2.5-pro`. Pro models offer better reasoning for complex images, but Flash is faster and more cost-effective for high-volume workflows.

### Q2. How many images can I process per day on the free tier?

**A:** The free tier has per-minute request limits (RPM). For batch processing, add a **Wait** node between requests to stay within limits, or upgrade to a paid plan for higher throughput.

### Q3. Can this work with video files too?

**A:** Yes, Gemini supports video. However, video files need to be uploaded via the File API first (rather than sent inline as Base64). The File API supports up to 2GB per file and returns a URI you include in your request. We'll cover this in a dedicated video analysis guide.
