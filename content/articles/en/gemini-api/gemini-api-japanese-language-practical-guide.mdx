One of the first surprises when using the Gemini API for Japanese-language applications is how inconsistent the output can be. The same model that produces clean, polished English might suddenly mix formal and casual Japanese registers, produce unexpected katakana variations, or generate awkward honorifics — all within a single response.

This isn't a bug. It reflects how Japanese works: a single meaning can be expressed in multiple grammatical registers, and without explicit instructions, the model picks whatever feels statistically "natural" from its training data. The good news is that this is highly controllable once you understand the levers available.

Here are the techniques I've found most effective through building Japanese-language apps with the Gemini API.

## Why Japanese Output Varies

Japanese has a richer register system than most Western languages. The question "Where are you going?" maps to at least three distinct Japanese forms — casual, polite, and honorific — with different vocabulary, verb conjugations, and sentence-ending particles. Without guidance, the API defaults to a mix it learned from diverse Japanese text sources.

A second factor is **hallucination behavior in Japanese**. Proper nouns (people, companies, product names) are more prone to errors in Japanese, and katakana loanwords often have multiple accepted spellings that can vary within a single response.

Both issues are addressable with the right prompting strategy.

## Technique 1: Lock the Writing Style with System Instructions

The most reliable solution is specifying your target writing style in the system instruction. This persists across the entire conversation.

```python
import google.generativeai as genai

genai.configure(api_key="YOUR_GEMINI_API_KEY")

model = genai.GenerativeModel(
    model_name="gemini-2.5-pro",
    system_instruction="""
You are a Japanese technical writer. Always follow these rules:

[Writing Style]
- Use polite Japanese (desu/masu form) consistently
- Never use casual Japanese (da/de aru form)
- Address readers as "読者の方" not "あなた"

[Terminology]
- Use "アプリ" (not "アプリケーション") consistently
- Keep technical terms in English (API, SDK, JSON, etc.)
- Always use long vowel marks in katakana (e.g., "プログラマー" not "プログラマ")

[Prohibited patterns]
- Do not end sentences with "〜となります" — use "〜です" instead
- Do not use "させていただきます"
- Do not repeat the same sentence ending more than twice in a row
"""
)

response = model.generate_content(
    "Gemini API の主な特徴を3つ教えてください。"
)
print(response.text)
# Expected output (in consistent polite Japanese):
# Gemini API の主な特徴は以下の3つです。
# 1. マルチモーダル対応: テキスト・画像・音声・動画を...
```

For chat applications, setting this once at initialization ensures every turn follows the same style. See also the [Gemini API System Instructions Complete Guide](/en/articles/gemini-api/system-instructions-guide) for more advanced configurations.

## Technique 2: Be Specific About Which Japanese

"Please respond in Japanese" is a start, but specifying *which kind of Japanese* dramatically improves consistency.

```python
# Vague instruction — prone to style drift
prompt_vague = "マーケティング戦略を教えてください。"

# Specific instruction — produces stable, readable output
prompt_specific = """
Please respond according to these specifications:
- Language: Standard Japanese (標準語)
- Register: Polite (です・ます調)
- Target reader: SMB business owner with minimal IT background
- Length: 300–400 characters
- If using English or katakana terms, always include a Japanese explanation in parentheses

Question: マーケティング戦略を教えてください。
"""
```

In practice, the vague prompt frequently produces output like "マーケティングには、ターゲティング（targeting）を意識することが..." — mixing Japanese with English loanwords spelled out phonetically. The specific prompt yields something like "マーケティング戦略を立てる際は、まず顧客層（どんな人に売るか）を絞り込むことが重要です" — far more readable for non-technical Japanese users.

## Technique 3: Preprocess Japanese Input for Better Accuracy

When processing Japanese text as input (review analysis, summarization, classification), preprocessing significantly affects output quality.

```python
import google.generativeai as genai
import re
import json

genai.configure(api_key="YOUR_GEMINI_API_KEY")

def preprocess_japanese_text(text: str) -> str:
    """Normalize Japanese text before sending to the API."""
    # Convert full-width spaces to half-width
    text = text.replace('\u3000', ' ')
    # Compress runs of 3+ newlines to double newline
    text = re.sub(r'\n{3,}', '\n\n', text)
    # Normalize full-width ASCII to half-width for consistency
    text = text.translate(str.maketrans(
        '０１２３４５６７８９ＡＢＣＤＥＦＧＨＩＪＫＬＭＮＯＰＱＲＳＴＵＶＷＸＹＺａｂｃｄｅｆｇｈｉｊｋｌｍｎｏｐｑｒｓｔｕｖｗｘｙｚ',
        '0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz'
    ))
    return text.strip()

def analyze_japanese_review(review_text: str) -> dict:
    """Sentiment analysis for Japanese reviews, returning structured data."""
    model = genai.GenerativeModel(
        model_name="gemini-2.5-flash",
        system_instruction="You are a Japanese text sentiment analysis expert."
    )

    clean_text = preprocess_japanese_text(review_text)

    prompt = f"""
Analyze the following Japanese review.
Respond only with valid JSON — no other text.

Review:
{clean_text}

Output format:
{{
  "sentiment": "positive or negative or neutral",
  "score": integer from 1 to 5,
  "key_points": ["point1", "point2"],
  "summary_ja": "summary in Japanese, 20 characters or less"
}}
"""

    response = model.generate_content(prompt)

    # Strip markdown code fences if present
    text = response.text.strip()
    if text.startswith('```'):
        text = re.sub(r'^```(?:json)?\n?', '', text)
        text = re.sub(r'\n?```$', '', text)

    return json.loads(text)

# Example usage
review = "このアプリ、最初は使い方が難しかったですが、慣れると便利です！　ただ、動作が重いのが気になります…"
result = analyze_japanese_review(review)
print(result)
# Expected output:
# {
#   "sentiment": "neutral",
#   "score": 3,
#   "key_points": ["慣れると便利", "動作が重い"],
#   "summary_ja": "便利だが動作が重い"
# }
```

Full-width ASCII normalization is the preprocessing step that catches the most people off guard. Japanese users routinely type "API" in full-width characters, and mixing full-width and half-width in the same string can cause subtle inconsistencies in model output.

## Technique 4: Use Few-Shot Examples for Japanese Nuance

Japanese-specific linguistic nuance — understatement, indirect negation, honorific softening — is difficult to handle with zero-shot prompting alone. Few-shot examples work well here.

```python
model = genai.GenerativeModel("gemini-2.5-flash")

# Classify Japanese indirect expressions with few-shot
prompt = """
Classify each Japanese sentence as "positive", "negative", or "indirect negative".

Example 1:
Sentence: 「このサービスはとても使いやすいです」
Classification: positive

Example 2:
Sentence: 「このサービスは使いにくいです」
Classification: negative

Example 3:
Sentence: 「このサービスは慣れれば使えないことはないと思います」
Classification: indirect negative
Reason: "慣れれば" (conditional), "使えないことはない" (double negative = effectively negative), "と思います" (uncertain)

Classify this sentence: 「機能がないわけではないので、工夫次第では使えるかもしれません」
Classification:"""

response = model.generate_content(prompt)
print(response.text)
# Expected: indirect negative
# Reason: "ないわけではない", "かもしれません" are both indirect/uncertain forms
```

With zero-shot, Japanese double negatives and indirect expressions regularly trip up the model. Adding 3–4 examples in few-shot format brings accuracy back to acceptable levels for most production use cases.

## Technique 5: Chunk Long Japanese Documents

For long Japanese texts — meeting minutes, blog posts, detailed reports — splitting by semantic boundaries before passing to the API consistently produces better summaries and analyses than sending the full text at once.

```python
def split_japanese_text(text: str, max_chars: int = 2000) -> list:
    """
    Split Japanese text at semantic boundaries.
    Prioritizes paragraph breaks, then sentence-ending punctuation.
    Avoids cutting mid-sentence.
    """
    chunks = []
    current_chunk = ""

    paragraphs = text.split('\n\n')

    for para in paragraphs:
        if len(current_chunk) + len(para) <= max_chars:
            current_chunk += para + '\n\n'
        else:
            if current_chunk:
                chunks.append(current_chunk.strip())

            if len(para) > max_chars:
                # Split at Japanese sentence endings (。！？)
                sentences = re.split(r'(?<=[。！？])', para)
                temp = ""
                for sent in sentences:
                    if len(temp) + len(sent) <= max_chars:
                        temp += sent
                    else:
                        if temp:
                            chunks.append(temp.strip())
                        temp = sent
                if temp:
                    chunks.append(temp.strip())
                current_chunk = ""
            else:
                current_chunk = para + '\n\n'

    if current_chunk:
        chunks.append(current_chunk.strip())

    return chunks

def summarize_long_article(article_text: str) -> str:
    """Summarize a long Japanese article with chunk-based processing."""
    model = genai.GenerativeModel(
        model_name="gemini-2.5-pro",
        system_instruction="You are a Japanese article summarization expert. Always use polite Japanese (です・ます調)."
    )

    chunks = split_japanese_text(article_text, max_chars=2000)

    if len(chunks) == 1:
        prompt = f"以下の記事を200文字以内で要約してください:\n\n{chunks[0]}"
        return model.generate_content(prompt).text

    # For long articles: extract key points per chunk, then final synthesis
    key_points = []
    for i, chunk in enumerate(chunks):
        prompt = f"以下のテキスト（{i+1}/{len(chunks)}部）の要点を箇条書きで3つ以内に抽出:\n\n{chunk}"
        points = model.generate_content(prompt).text
        key_points.append(points)

    final_prompt = f"""
以下の要点リストをまとめて、記事全体の要約を200文字以内で作成してください:

{''.join(key_points)}
"""
    return model.generate_content(final_prompt).text
```

The key difference from English text splitting is using Japanese sentence-ending punctuation (`。！？`) as split boundaries rather than periods. A lookbehind regex (`(?<=[。！？])`) handles this cleanly.

## Two Common Issues to Watch For

**Over-formal output**: Asking Gemini to write business documents in Japanese often produces excessive keigo — phrases like 「〜させていただきます」 and 「〜となっております」 stacked together. Explicitly prohibiting specific phrases in your system instruction is more reliable than general instructions like "use natural Japanese."

**JSON output with markdown fences**: When asking for structured JSON, the API sometimes wraps the output in ` ```json ` code fences. The strip logic shown in the review analysis example above handles this reliably. Alternatively, setting `response_mime_type="application/json"` in `GenerationConfig` avoids the issue at the model level, though behavior may vary across model versions.

## Where to Start

If you're already using the Gemini API and want to improve Japanese output quality immediately, add a writing style specification to your `system_instruction`. A single line — "敬体（です・ます調）で回答する" — is enough to noticeably stabilize the register across your entire application.
