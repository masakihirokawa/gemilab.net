You write what feels like a trivial pipeline — feed a Japanese article to the Gemini API and ask for an English summary — and the response comes back with a rogue sentence of Japanese tacked onto the end. I ran a bilingual blog for over a year and hit this problem dozens of times. The official docs tell you to "set the language in System Instructions," but in practice that single line is not enough to stop it.

In this article I will walk through the combination I actually use to keep Gemini API output in a single target language: strong System Instructions, a couple of few-shot examples, a `response_schema` with a validator, and a retry strategy that raises the instruction pressure on the second attempt. Nothing exotic, nothing model-specific — this is what works today.

## Why does English-only output leak Japanese?

Gemini is trained on a massive multilingual corpus, and its attention tends to follow the dominant language of the input. If the prompt body is 1,500 tokens of Japanese and the instruction "Answer in English" sits at the end, the model's attention is mostly on the Japanese body. The weight of the instruction drops. The longer the input and the shorter the instruction, the more likely leakage becomes.

A second cause is what I call "proper-noun overflow." When Japanese product names, place names or technical terms appear in the source, the model sometimes judges that "this fragment is safer preserved as-is" and drops an entire Japanese sentence in. Unless you explicitly forbid this, the model defaults to the safer translation choice rather than the strict one.

In my testing, short prompts are stable on any model, but leakage becomes visible on Gemini 2.0 Flash beyond roughly 2,000 tokens of input. Moving up to 2.5 Pro or 3.1 Pro helps but does not reduce the rate to zero. It is more realistic to design around the problem than to hope that a future model will solve it for you.

## Write the target language as a top-priority constraint in System Instructions

The foundation is putting the language rule into the System Instructions field instead of appending it to the prompt body. System Instructions carry stronger weight than the content payload. I covered the mechanics in [Mastering System Instructions](/en/articles/gemini-api/system-instructions-guide); this article focuses on the language-control angle.

```python
from google import genai
from google.genai import types

client = genai.Client(api_key="YOUR_API_KEY")

system_instruction = """
You are a professional English-language technical editor.
RULES:
1. You MUST respond entirely in English.
2. Do not include any Japanese characters (hiragana, katakana, or kanji) in your output.
3. If a Japanese term is essential (e.g. a product name), render it in romaji with an English gloss in parentheses.
4. If you cannot comply, respond with "UNABLE_TO_COMPLY" and stop.
"""

response = client.models.generate_content(
    model="gemini-2.5-pro",
    contents="Summarize the following Japanese article in under 300 English words.\n\n" + article_body,
    config=types.GenerateContentConfig(
        system_instruction=system_instruction,
        temperature=0.2,
    ),
)
print(response.text)
```

Two things matter here. First, spell out an allow-list (romaji is acceptable) so the model has a legitimate fallback for untranslatable terms. Second, define the failure path: `UNABLE_TO_COMPLY`. Explicit failure is easier to handle in downstream code than a half-translated sentence, and it gives you a clean signal to route the input to a retry with stronger instructions or to human review.

Lower `temperature` to 0.2–0.4 as well. Language adherence benefits from less variance; creativity is not what we want in a translation pipeline.

## Show the expected output shape with few-shot exemplars

If System Instructions alone are not stopping leakage, add one or two few-shot exemplars. A general rule of prompt engineering applies here: showing examples outperforms stating rules, especially on long or complex tasks.

```python
few_shot_examples = [
    {
        "input": "Tell me about the weather in Tokyo.",
        "output": "Tokyo has four distinct seasons with hot humid summers (around 30 degC) and mild winters. Annual rainfall averages 1,500 mm."
    },
    {
        "input": "Describe this app's pricing plans.",
        "output": "The app offers three pricing tiers: Free, Pro (USD 5/month), and Team (USD 20/month per seat)."
    },
]

few_shot_block = "\n\n".join([
    f"### Example\nInput (Japanese): {e['input']}\nOutput (English only): {e['output']}"
    for e in few_shot_examples
])

prompt = f"""{few_shot_block}

### Task
Input (Japanese): {user_input}
Output (English only):"""

response = client.models.generate_content(
    model="gemini-2.5-pro",
    contents=prompt,
    config=types.GenerateContentConfig(
        system_instruction=system_instruction,
        temperature=0.2,
    ),
)
```

Few-shot shines on long complex inputs. On the bilingual blog I mentioned, adding two exemplars dropped the leakage rate by roughly 10x. The tradeoff is token cost, so for very short prompts System Instructions alone are often enough.

## Enforce language at the schema level with `response_schema`

If you are consuming the output programmatically, carry a `language` field in the schema and validate it on arrival. Combining this with Pydantic gives you machine-checkable guarantees with almost no extra code. I cover the full schema design in [Type-safe structured output with Gemini and Pydantic](/en/articles/gemini-api/gemini-api-pydantic-structured-output-type-safe-production); the snippet below is the language-specific subset.

```python
from pydantic import BaseModel, Field, field_validator
import re

class EnglishSummary(BaseModel):
    language: str = Field(description="Must be 'en'")
    title: str = Field(description="English title")
    summary: str = Field(description="English summary, 100-300 words")

    @field_validator("language")
    @classmethod
    def must_be_en(cls, v: str) -> str:
        if v.lower() \!= "en":
            raise ValueError(f"Expected language='en', got '{v}'")
        return v

    @field_validator("title", "summary")
    @classmethod
    def no_japanese(cls, v: str) -> str:
        if re.search(r"[\u3040-\u30ff\u4e00-\u9fff]", v):
            raise ValueError("Japanese characters detected in output field")
        return v

response = client.models.generate_content(
    model="gemini-2.5-pro",
    contents="Summarize this article in English:\n\n" + article_body,
    config=types.GenerateContentConfig(
        system_instruction=system_instruction,
        response_mime_type="application/json",
        response_schema=EnglishSummary,
    ),
)

parsed = response.parsed  # typed EnglishSummary instance
```

The `field_validator` checks the Unicode ranges for hiragana, katakana and CJK unified ideographs. A match throws `ValidationError`, which your caller catches and routes to a retry. Because `response.parsed` is auto-deserialized by the SDK, you do not need to write manual JSON handling.

## On violation, escalate the instruction rather than just retrying

When validation fails, re-sending the exact same prompt usually produces the exact same leak. The trick I rely on is a two-stage retry that raises the instruction pressure.

```python
def generate_english_with_retry(article_body: str, max_retries: int = 2) -> EnglishSummary:
    base_prompt = f"Summarize this article in English:\n\n{article_body}"

    for attempt in range(max_retries + 1):
        try:
            response = client.models.generate_content(
                model="gemini-2.5-pro",
                contents=base_prompt,
                config=types.GenerateContentConfig(
                    system_instruction=system_instruction,
                    response_mime_type="application/json",
                    response_schema=EnglishSummary,
                    temperature=0.2,
                ),
            )
            return response.parsed

        except Exception as e:
            if attempt == max_retries:
                raise
            # On retry, make the instruction stronger
            base_prompt = (
                "IMPORTANT: Your previous response contained Japanese characters. "
                "This is forbidden. Respond ONLY in English this time.\n\n"
                f"{base_prompt}"
            )

    raise RuntimeError("Should not reach here")
```

Telling the model "your previous response contained Japanese characters — do not repeat it" changes the behavior noticeably on the second try. Think of it as a lightweight form of self-correction. If the third attempt also fails, I route the input to a human-review queue as `UNABLE_TO_COMPLY`; spending more API calls rarely helps from there.

## Takeaways — System Instructions first, few-shot next, schema validation last

Language leakage in Gemini API output is not something you can model-shop your way out of. The durable fix is a layered design: write strong System Instructions, show the model what you want with one or two few-shot examples, and enforce the final check with `response_schema` plus a validator.

If you take one thing from this article, rewrite your current System Instructions in the form "English only. If you cannot comply, respond `UNABLE_TO_COMPLY`." Even before you add few-shot or Pydantic checks, that single change usually slashes the leakage rate. For broader prompt-design patterns behind this approach, [the Gemini prompt engineering guide](/en/articles/gemini-basics/gemini-prompt-engineering-guide) is a good companion read.
