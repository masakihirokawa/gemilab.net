## Introduction: Why Run Gemini API at the Edge?

Two things matter most when building AI-powered applications: speed and cost. Traditional serverless platforms like AWS Lambda suffer from cold starts and high per-request pricing. When your users are spread across the globe, latency compounds quickly.

**Cloudflare Workers** solves this by running your code at the edge — across 300+ data centers worldwide — with near-zero cold starts and extremely low latency. Paired with the **Gemini API**, you can serve intelligent AI responses from a location milliseconds away from any user on the planet.

This guide walks you through building a production-ready AI API server using **Hono.js** (a TypeScript-first edge web framework) and the **Gemini API**. We'll cover setup, a type-safe chat endpoint, streaming responses, and robust error handling.

If you're new to the Gemini API with TypeScript, start with the [Gemini API TypeScript Beginner's Complete Guide](/en/articles/gemini-api/gemini-api-typescript-complete-beginners-guide) first.

**Prerequisites:**

- Basic TypeScript knowledge
- A Cloudflare account (free tier is fine)
- A Gemini API key from [Google AI Studio](https://aistudio.google.com/)

## What Is Hono.js and Why Does It Pair Well with Gemini?

**Hono.js** is an ultrafast web framework built on Web Standards APIs. Its name comes from the Japanese word for "flame." It runs natively on Cloudflare Workers, Deno, Bun, and Node.js with the same codebase.

Three things make it an excellent match for Gemini API:

**Web Standards first.** Hono.js uses native `Request`, `Response`, and `ReadableStream`. The Gemini SDK's streaming output integrates seamlessly without any adapter layer.

**TypeScript-native.** Route types, middleware inference, and binding types all work with Gemini SDK's type definitions out of the box — no type gymnastics needed.

**Tiny bundle size.** Cloudflare Workers recommends keeping bundles under 1 MB. Hono.js core is under 14 KB, leaving plenty of room for your application logic and the Gemini SDK.

```bash
npm create hono@latest gemini-edge-api
cd gemini-edge-api
# When prompted, select "cloudflare-workers"
```

```toml
# wrangler.toml
name = "gemini-edge-api"
main = "src/index.ts"
compatibility_date = "2026-01-01"
compatibility_flags = ["nodejs_compat"]

[vars]
# Set via wrangler secret in production — never hardcode keys here
GEMINI_API_KEY = ""
```

Store your production API key securely:

```bash
wrangler secret put GEMINI_API_KEY
# Enter YOUR_GEMINI_API_KEY when prompted
```

For local development, create a `.dev.vars` file (it's git-ignored by default):

```
GEMINI_API_KEY=YOUR_GEMINI_API_KEY
```

## Building the Chat Endpoint

Here's the full `src/index.ts` with type-safe bindings and a chat endpoint:

```typescript
// src/index.ts
import { Hono } from "hono";
import { cors } from "hono/cors";
import { GoogleGenerativeAI } from "@google/generative-ai";

// Type definition for Cloudflare Workers environment bindings
type Bindings = {
  GEMINI_API_KEY: string;
};

// Typed request body for the chat endpoint
type ChatRequest = {
  message: string;
  history?: { role: "user" | "model"; parts: { text: string }[] }[];
};

const app = new Hono<{ Bindings: Bindings }>();

// Apply CORS middleware globally
app.use("*", cors({ origin: "*" }));

// Health check
app.get("/", (c) => {
  return c.json({ status: "ok", model: "gemini-2.5-flash" });
});

// Non-streaming chat endpoint
app.post("/api/chat", async (c) => {
  const body = await c.req.json<ChatRequest>();

  if (!body.message) {
    return c.json({ error: "message is required" }, 400);
  }

  // Retrieve API key from Cloudflare Workers Bindings — never from process.env
  const genAI = new GoogleGenerativeAI(c.env.GEMINI_API_KEY);
  const model = genAI.getGenerativeModel({ model: "gemini-2.5-flash" });

  // Support multi-turn conversations via history
  const chat = model.startChat({ history: body.history ?? [] });

  const result = await chat.sendMessage(body.message);
  const text = result.response.text();

  return c.json({
    reply: text,
    usage: result.response.usageMetadata,
  });
});

export default app;
```

Test it locally:

```bash
npx wrangler dev

# In another terminal
curl -X POST http://localhost:8787/api/chat \
  -H "Content-Type: application/json" \
  -d '{"message": "What makes edge computing useful for AI?"}'

# Expected output:
# {"reply":"Edge computing brings AI processing closer to the end user...","usage":{"promptTokenCount":12,...}}
```

## Adding Streaming Responses

Streaming dramatically improves perceived performance — users see words appear in real time rather than waiting for a complete response. Hono's `streamText` helper makes this straightforward:

```typescript
// Add to src/index.ts
import { streamText } from "hono/streaming";

// Streaming chat endpoint using Server-Sent Events
app.post("/api/chat/stream", async (c) => {
  const body = await c.req.json<ChatRequest>();

  if (!body.message) {
    return c.json({ error: "message is required" }, 400);
  }

  const genAI = new GoogleGenerativeAI(c.env.GEMINI_API_KEY);
  const model = genAI.getGenerativeModel({ model: "gemini-2.5-flash" });
  const chat = model.startChat({ history: body.history ?? [] });

  return streamText(c, async (stream) => {
    // sendMessageStream yields chunks as the model generates them
    const result = await chat.sendMessageStream(body.message);

    for await (const chunk of result.stream) {
      const text = chunk.text();
      if (text) {
        // Write each chunk in SSE format
        await stream.write(`data: ${JSON.stringify({ text })}\n\n`);
      }
    }

    // Signal the end of the stream
    await stream.write("data: [DONE]\n\n");
  });
});
```

Here's how to consume the stream from a frontend:

```typescript
// Client-side streaming consumer
const response = await fetch("/api/chat/stream", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ message: "Explain streaming in three sentences" }),
});

const reader = response.body!.getReader();
const decoder = new TextDecoder();

while (true) {
  const { done, value } = await reader.read();
  if (done) break;

  const lines = decoder.decode(value).split("\n\n");
  for (const line of lines) {
    if (!line.startsWith("data: ")) continue;
    const data = line.slice(6);
    if (data === "[DONE]") return;
    const { text } = JSON.parse(data);
    process.stdout.write(text); // Append text as it arrives
  }
}
```

## Error Handling and Rate Limit Resilience

Production APIs need to handle Gemini API errors gracefully — especially rate limit (429) errors. A Hono middleware lets you manage this in one place:

```typescript
// src/middleware/errorHandler.ts
import { Context, Next } from "hono";

export async function errorHandler(c: Context, next: Next) {
  try {
    await next();
  } catch (error: unknown) {
    if (error instanceof Error) {
      // Rate limit exceeded
      if (error.message.includes("429") || error.message.includes("RESOURCE_EXHAUSTED")) {
        return c.json(
          { error: "Rate limit reached. Please retry after a moment.", retryAfter: 60 },
          429
        );
      }
      // Content blocked by safety filters
      if (error.message.includes("SAFETY")) {
        return c.json({ error: "Content was blocked by safety filters." }, 400);
      }
    }
    console.error("Unexpected error:", error);
    return c.json({ error: "Internal server error." }, 500);
  }
}
```

Apply it in `src/index.ts`:

```typescript
import { errorHandler } from "./middleware/errorHandler";
app.use("*", errorHandler);
```

For comprehensive production error patterns, see [Gemini API Error Handling & Rate Limit Complete Guide](/en/articles/gemini-dev/gemini-api-error-handling-rate-limit-production-patterns).

## Frequently Asked Questions

**Q1. How does Hono.js compare to Express for Gemini API backends?**

If you're targeting edge environments like Cloudflare Workers, Hono.js is the clear winner — Express simply doesn't run in edge runtimes. Both share a similar routing API, so migration is minimal. If you're building on traditional Node.js infrastructure and don't need edge deployment, Express or Fastify remain solid choices. The good news is that Hono.js runs on Node.js too, so you get flexibility without sacrificing edge compatibility.

**Q2. Will the Cloudflare Workers CPU time limit affect Gemini API calls?**

Not for typical chat use cases. Cloudflare Workers measure CPU execution time, not wall-clock time — and network I/O (like waiting for the Gemini API response) doesn't count toward the CPU budget. The free tier's 10ms CPU limit is rarely hit for simple inference calls. For batch processing or complex chained requests, consider using Cloudflare Queues to handle work asynchronously.

**Q3. How do I handle API key security properly?**

Always use `wrangler secret put` to store your Gemini API key — never hardcode it in source files or commit `.env` to version control. The Cloudflare Workers Bindings system encrypts secrets at rest and injects them as environment variables at runtime. Additionally, consider creating a separate API key for each deployment environment (dev, staging, production) so you can rotate them independently. For a deeper look at type-safe security architecture, see [Gemini API × TypeScript Type-Safe Application Architecture Guide](/en/articles/gemini-api/gemini-api-typescript-typesafe-ai-application-architecture).
