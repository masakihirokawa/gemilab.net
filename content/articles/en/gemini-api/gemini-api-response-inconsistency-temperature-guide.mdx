If you've ever sent the exact same prompt to the Gemini API twice and received noticeably different answers, you're not alone. It's one of the first surprises many developers run into — especially when writing unit tests, building data pipelines, or debugging production issues where reproducibility matters.

The good news: this behavior is by design, not a bug. But that doesn't mean you're stuck with it. Let me walk you through what's actually happening and how to dial in the stability you need.

## Why Gemini API Responses Vary — The Role of Temperature

Every time the Gemini model generates a response, it's selecting tokens (words or word-pieces) based on a probability distribution. The `temperature` parameter controls how "sharp" or "flat" that distribution is.

- **High temperature (1.0–2.0):** The distribution is flat — many tokens have similar probabilities, so the model explores more diverse outputs. Great for creative writing, brainstorming.
- **Low temperature (0.0–0.5):** The distribution becomes sharp — the highest-probability token wins almost every time. More predictable, more consistent.

The default temperature in Gemini API is `1.0`. That's why you see variation.

```python
import google.generativeai as genai

genai.configure(api_key="YOUR_API_KEY")

model = genai.GenerativeModel(
    model_name="gemini-2.5-pro",
    generation_config=genai.types.GenerationConfig(
        temperature=0.0,  # Maximum consistency
        top_p=0.95,
        top_k=40,
    )
)

response = model.generate_content("What is the capital of Japan?")
print(response.text)
# → "Tokyo" — reliably, every time
```

Two other sampling parameters also matter: `top_p` (only sample from tokens whose cumulative probability reaches this threshold) and `top_k` (only consider the top N tokens). For maximum stability, try `temperature=0.0`, `top_p=0.95`, `top_k=1`.

## When temperature=0 Still Gives Different Results

Setting temperature to zero doesn't always produce perfectly identical responses. Here's why:

**Tied probabilities in the model's internal distribution**

When two or more tokens have the same probability, the model has to pick one — and that choice can vary depending on infrastructure details like load balancer routing or quantization settings on the server side. This is rare but real.

**Thinking Mode is active**

Gemini 2.5 Pro and Flash models have thinking enabled by default. The reasoning process itself involves sampling, which means even with temperature=0 on the final output, the internal thought process can vary and influence the response.

```python
# Controlling generation config for more determinism
model = genai.GenerativeModel(
    model_name="gemini-2.5-flash",
    generation_config=genai.types.GenerationConfig(
        temperature=0.0,
        top_k=1,
    )
)

response = model.generate_content("Classify this as positive, negative, or neutral: 'Great product\!'")
print(response.text)
```

**Dynamic context in your prompt**

If your system instruction or prompt template includes things like today's date or session IDs, the context changes on every call — which can shift the output even with temperature=0. To isolate temperature as a variable, test with a fully static prompt first.

## Recommended Settings by Use Case

Here are configurations I've found reliable in practice for different types of tasks:

**Classification and data extraction (high consistency required)**

```python
config_classification = genai.types.GenerationConfig(
    temperature=0.0,
    top_p=0.95,
    top_k=1,
    candidate_count=1,
)
```

**Summarization and translation (moderate consistency)**

```python
config_summarization = genai.types.GenerationConfig(
    temperature=0.2,
    top_p=0.95,
    top_k=20,
    candidate_count=1,
)
```

**Creative generation (diversity valued)**

```python
config_creative = genai.types.GenerationConfig(
    temperature=1.0,
    top_p=0.95,
    top_k=40,
    candidate_count=1,
)
```

For production data pipelines — things like review sentiment classification or form input parsing — I default to `temperature=0.0`. The slight edge cases where tied probabilities cause variation are usually acceptable, and you avoid the much larger variation that comes from higher temperatures.

## Fixing Format Inconsistency with Structured Output

Temperature handles *what* the model says; Structured Output handles *how* it formats the response. If you're seeing responses that sometimes come as JSON and sometimes as plain prose (or markdown-wrapped code blocks), `response_mime_type` and `response_schema` are your friends.

```python
import google.generativeai as genai
from pydantic import BaseModel

genai.configure(api_key="YOUR_API_KEY")

class ReviewAnalysis(BaseModel):
    sentiment: str       # "positive", "negative", or "neutral"
    confidence: float    # 0.0 to 1.0
    key_points: list[str]

model = genai.GenerativeModel(
    model_name="gemini-2.5-flash",
    generation_config=genai.types.GenerationConfig(
        temperature=0.0,
        response_mime_type="application/json",
        response_schema=ReviewAnalysis,
    )
)

review = "The coffee was excellent and the staff were incredibly friendly."
response = model.generate_content(f"Analyze this review: {review}")

import json
result = json.loads(response.text)
print(result)
# → {"sentiment": "positive", "confidence": 0.95, "key_points": ["excellent coffee", "friendly staff"]}
```

This eliminates the need to write "Please respond in JSON format" in your prompt — and removes the risk of the model wrapping JSON in markdown code fences. For a deeper dive, see the [Structured Output production guide](/articles/gemini-advanced/gemini-structured-output-production-guide).

## Using System Instructions to Lock Down Response Style

Even with low temperature, responses can vary in *style* — length, phrasing, language. System instructions give you another layer of control:

```python
system_instruction = """
You are a product review analysis API.

Rules:
- Always respond in English
- Always include sentiment (positive/negative/neutral)
- Keep responses under 80 words
- Base your analysis only on what is explicitly stated in the review text
"""

model = genai.GenerativeModel(
    model_name="gemini-2.5-pro",
    system_instruction=system_instruction,
    generation_config=genai.types.GenerationConfig(
        temperature=0.0,
    )
)
```

Think of system instructions as setting the model's "personality and constraints." Without them, even a low-temperature model might alternate between different answer formats across calls.

## The Three-Setting Combination That Works

The most reliable approach for production consistency is combining all three controls:

```python
model = genai.GenerativeModel(
    model_name="gemini-2.5-flash",
    system_instruction="Your detailed output format instructions here",
    generation_config=genai.types.GenerationConfig(
        temperature=0.0,                          # Sampling consistency
        response_mime_type="application/json",    # Format enforcement
        response_schema=YourPydanticModel,        # Schema enforcement
    )
)
```

Start with this combination and adjust temperature upward only when you actually want creative variation. For classification, extraction, translation, and any task where correctness matters more than novelty — `temperature=0.0` is the right starting point.
