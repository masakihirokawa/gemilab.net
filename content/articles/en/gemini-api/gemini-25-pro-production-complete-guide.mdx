Gemini 2.5 Pro is Google's most capable model — 1 million token context window, deep reasoning, multimodal support. Used well, it unlocks capabilities that were simply out of reach a year ago. Used carelessly, it generates surprisingly large API bills and unpredictable latency in production.

This guide focuses on implementation: what to build, what to avoid, and exactly how to wire it up correctly. Every code example here reflects patterns I've tested on real data, not toy examples.

## Understanding Gemini 2.5 Pro Before Writing Any Code

Three characteristics drive almost every production decision with this model:

**Context window**: 1 million tokens input, 8,192 tokens output. This is a genuinely useful limit — you can feed entire codebases, legal documents, or research papers in a single request.

**Thinking mode**: An optional reasoning layer where the model thinks through problems before responding. Dramatically improves accuracy on complex tasks but adds cost and latency. Needs to be budgeted explicitly.

**Pricing structure**: Input tokens cost differently depending on whether they're cached or not, which creates a meaningful incentive to use Context Caching on large repeated inputs.

Knowing these upfront changes how you design your API usage.

## Production-Ready Streaming Client

For any response expected to take more than 15 seconds, use streaming. Non-streaming requests on long generations will time out in most HTTP client configurations.

```python
import google.generativeai as genai
import os
import time
from google.api_core import exceptions
from typing import Generator, Optional

genai.configure(api_key=os.environ["GOOGLE_API_KEY"])

class GeminiProClient:
    """Production client for Gemini 2.5 Pro with retry and streaming support."""
    
    def __init__(self, model_name: str = "gemini-2.5-pro-preview-05-06"):
        self.model_name = model_name
        self.model = genai.GenerativeModel(
            model_name,
            generation_config=genai.GenerationConfig(
                max_output_tokens=8192,
                temperature=0.7,
                top_p=0.95,
            )
        )
    
    def stream(
        self, 
        prompt: str,
        system_instruction: Optional[str] = None,
        max_retries: int = 4
    ) -> Generator[str, None, None]:
        """
        Stream a response chunk by chunk.
        Compatible with Server-Sent Events for web applications.
        Retries on rate limit errors with exponential backoff.
        """
        model = self.model
        if system_instruction:
            model = genai.GenerativeModel(
                self.model_name,
                system_instruction=system_instruction,
                generation_config=self.model.generation_config
            )
        
        for attempt in range(max_retries):
            try:
                response = model.generate_content(prompt, stream=True)
                
                for chunk in response:
                    if chunk.text:
                        yield chunk.text
                
                # Log token usage after stream completes
                usage = response.usage_metadata
                print(f"[Done] input={usage.prompt_token_count}, "
                      f"output={usage.candidates_token_count} tokens")
                return
            
            except exceptions.ResourceExhausted:
                if attempt == max_retries - 1:
                    raise
                wait = 2 ** attempt
                print(f"Rate limited. Retrying in {wait}s...")
                time.sleep(wait)
            
            except exceptions.DeadlineExceeded:
                # Shouldn't happen with streaming, but handle it anyway
                print("Request timed out. Consider reducing prompt length.")
                raise
    
    def generate(self, prompt: str, **kwargs) -> Optional[str]:
        """Collect the full streamed response as a single string."""
        try:
            return "".join(self.stream(prompt, **kwargs))
        except Exception as e:
            print(f"Generation failed: {e}")
            return None

# Usage
client = GeminiProClient()

# Stream to stdout (long-form content)
for chunk in client.stream(
    "Write a detailed guide to async programming in Python.",
    system_instruction="You are a technical writer. Be precise and include code examples."
):
    print(chunk, end="", flush=True)

# Collect full response (when you need the complete text)
summary = client.generate("Summarize the key differences between Python 3.11 and 3.12.")
print(summary)
```

## Context Caching: 75% Cost Reduction on Repeated Inputs

If your application repeatedly sends the same large document or instruction set with each request, you're paying full price for those input tokens every time. Context Caching lets you pay once to store the content, then reference it cheaply on subsequent requests.

The cost math is compelling: cached input tokens are billed at 75% less than uncached. For a workflow that processes the same 100,000-token document 20 times per day, caching saves roughly 95% of your input token costs for that content.

```python
import google.generativeai as genai
from google.generativeai import caching
import datetime
import os

genai.configure(api_key=os.environ["GOOGLE_API_KEY"])

def create_document_cache(
    document_content: str,
    system_instruction: str,
    ttl_minutes: int = 60,
    display_name: str = "document-cache"
):
    """
    Cache a large document for repeated querying.
    
    Cost example: 500k-token document queried 10 times
    - Without caching: 500k × 10 = 5M input tokens billed
    - With caching: ~500k for initial cache + 10 × (500k × 0.25) = ~1.75M tokens billed
    - Savings: ~65%
    
    Args:
        document_content: The large text to cache (e.g., documentation, codebase, legal doc)
        system_instruction: Persistent system prompt for all queries against this cache
        ttl_minutes: How long to keep the cache (you're charged for storage time)
        display_name: Human-readable label for the cache in the console
    """
    cache = caching.CachedContent.create(
        model="models/gemini-2.5-pro-preview-05-06",
        display_name=display_name,
        system_instruction=system_instruction,
        contents=[document_content],
        ttl=datetime.timedelta(minutes=ttl_minutes)
    )
    
    print(f"Cache created: {cache.name}")
    print(f"Expires in: {ttl_minutes} minutes")
    print(f"Cache token count: {cache.usage_metadata.total_token_count:,}")
    return cache

def query_cached_document(cache, question: str) -> str:
    """Query the cached document. Input tokens in cache are billed at 75% discount."""
    model = genai.GenerativeModel.from_cached_content(cached_content=cache)
    response = model.generate_content(question)
    
    usage = response.usage_metadata
    cached_tokens = getattr(usage, 'cached_content_token_count', 0)
    print(f"Tokens: {usage.prompt_token_count} input "
          f"({cached_tokens} from cache), {usage.candidates_token_count} output")
    
    return response.text

# Example: analyze the same document with multiple questions
document = """
[Your large document content here — API documentation, legal text, codebase, etc.]
This example works best with documents over 32,768 tokens (the minimum cacheable size).
""" * 500  # Replace with actual document content

cache = create_document_cache(
    document_content=document,
    system_instruction=(
        "You are a precise document analyst. "
        "Only answer based on the provided document. "
        "If the information isn't in the document, say so clearly."
    ),
    ttl_minutes=120,
    display_name="api-docs-cache"
)

questions = [
    "What are the main rate limits described in this document?",
    "List all authentication methods mentioned.",
    "What error codes does the API return and what do they mean?",
    "Summarize the pricing structure.",
]

for question in questions:
    print(f"\nQ: {question}")
    answer = query_cached_document(cache, question)
    print(f"A: {answer[:300]}...")

# Always delete the cache when done to stop storage charges
cache.delete()
print("\nCache deleted.")
```

**When Context Caching is worth it:**

- Same document queried more than ~4 times within the TTL window
- Document is at least 32,768 tokens (the minimum cacheable size)
- The TTL matches your actual query frequency — don't set 24-hour TTLs for documents you query once every few hours

## Thinking Budget: Precision Over Reflexes

The Thinking feature lets you trade cost and latency for reasoning depth. The key is only enabling it for tasks that actually benefit from it.

```python
import google.generativeai as genai
import os
import time

genai.configure(api_key=os.environ["GOOGLE_API_KEY"])

def create_model_with_thinking(budget: int = 0):
    """
    Create a model with a specific thinking budget.
    
    budget=0:      No thinking (fast, cheapest — for simple tasks)
    budget=1024:   Light thinking (for straightforward reasoning)
    budget=8192:   Standard thinking (code review, analysis, comparison)
    budget=24576:  Maximum thinking (complex algorithms, multi-step math, architecture design)
    """
    return genai.GenerativeModel(
        "gemini-2.5-pro-preview-05-06",
        generation_config=genai.GenerationConfig(
            max_output_tokens=8192,
            thinking_config=genai.ThinkingConfig(thinking_budget=budget)
        )
    )

# Task classification → thinking budget selection
def classify_task_complexity(prompt: str) -> int:
    """
    Heuristic for selecting thinking budget based on prompt characteristics.
    Customize this based on your application's actual task distribution.
    """
    simple_patterns = ["translate", "summarize", "rewrite", "format", "convert"]
    complex_patterns = [
        "design", "architect", "algorithm", "optimize", "analyze trade-offs",
        "compare", "debug", "implement", "prove", "calculate"
    ]
    
    prompt_lower = prompt.lower()
    
    if any(p in prompt_lower for p in complex_patterns):
        return 8192  # Standard thinking for complex tasks
    if any(p in prompt_lower for p in simple_patterns):
        return 0    # No thinking for simple transformations
    
    return 1024  # Light thinking for ambiguous cases

# Example: adaptive thinking
prompts = [
    ("Translate this to French: 'Hello, world\!'", 0),
    ("Design a distributed rate limiter for 10k RPS with <5ms p99 latency", 16000),
    ("Review this Python function for bugs", 4096),
]

for prompt, budget_override in prompts:
    model = create_model_with_thinking(budget_override)
    
    start = time.time()
    response = model.generate_content(prompt)
    elapsed = time.time() - start
    
    usage = response.usage_metadata
    thoughts = getattr(usage, 'thoughts_token_count', 0)
    
    print(f"\nPrompt: {prompt[:60]}...")
    print(f"Budget: {budget_override} | Thinking tokens: {thoughts} | Time: {elapsed:.1f}s")
    print(f"Response: {response.text[:150]}...")
```

The latency difference between `budget=0` and `budget=24576` can be 10–30 seconds on complex prompts. For user-facing features, keep budgets low or add a loading indicator.

## Multi-Turn Conversation with Context Monitoring

Long conversations accumulate tokens fast. At 1M token limit and $3.50/M tokens, a 100-turn conversation with long messages can generate real costs. Monitor and prune proactively.

```python
import google.generativeai as genai
import os
from typing import Optional

genai.configure(api_key=os.environ["GOOGLE_API_KEY"])

class ManagedChatSession:
    """
    Multi-turn chat with active context monitoring and pruning.
    Warns before context limit, prunes old turns if needed.
    """
    
    CONTEXT_LIMIT = 900_000  # Leave buffer below 1M
    WARNING_THRESHOLD = 0.80  # Warn at 80% of limit
    
    def __init__(self, system_instruction: Optional[str] = None):
        self.model = genai.GenerativeModel(
            "gemini-2.5-pro-preview-05-06",
            system_instruction=system_instruction,
            generation_config=genai.GenerationConfig(max_output_tokens=4096)
        )
        self.chat = self.model.start_chat(history=[])
        self.token_count = 0
    
    def send(self, message: str) -> str:
        """Send a message and get a response with context monitoring."""
        
        # Pre-flight context check
        usage_ratio = self.token_count / self.CONTEXT_LIMIT
        if usage_ratio > self.WARNING_THRESHOLD:
            print(f"⚠️ Context at {usage_ratio:.0%}. Consider summarizing conversation history.")
        
        try:
            response = self.chat.send_message(message)
            self.token_count = response.usage_metadata.prompt_token_count
            return response.text
        
        except Exception as e:
            if "context" in str(e).lower() or "token" in str(e).lower():
                print("Context limit reached. Pruning conversation history.")
                return self._retry_with_pruned_history(message)
            raise
    
    def _retry_with_pruned_history(self, message: str) -> str:
        """Retry after dropping the oldest half of conversation history."""
        history = self.chat.history
        if len(history) > 4:
            # Keep the most recent 50% of turns
            self.chat.history = history[len(history) // 2:]
            print(f"Pruned to {len(self.chat.history)} history entries")
        
        response = self.chat.send_message(message)
        self.token_count = response.usage_metadata.prompt_token_count
        return response.text
    
    @property
    def stats(self) -> dict:
        return {
            "turns": len(self.chat.history) // 2,
            "tokens_used": self.token_count,
            "context_usage_pct": f"{self.token_count / self.CONTEXT_LIMIT:.1%}"
        }

# Usage
session = ManagedChatSession(
    system_instruction="You are a Python expert. Give concise, practical answers."
)

for question in [
    "What's the difference between a list and a tuple?",
    "When should I use generators instead of lists?",
    "How does Python's GIL affect multithreading?",
]:
    print(f"\nUser: {question}")
    reply = session.send(question)
    print(f"Gemini: {reply[:200]}...")
    print(f"Stats: {session.stats}")
```

## Production Checklist

Before going live with a Gemini 2.5 Pro integration:

- **Streaming enabled** for any request that might generate >500 tokens
- **Retry logic implemented** with exponential backoff on `ResourceExhausted`
- **Response validation** — never access `response.text` without checking `candidates`
- **Token logging** — record `prompt_token_count` and `candidates_token_count` for cost monitoring
- **Model name in config** — don't hardcode preview model names; read from environment
- **Context Caching evaluated** for any workflow processing the same large document repeatedly
- **Thinking budget calibrated** — don't use high budgets for simple tasks
- **TTL set correctly** for caches — match actual query frequency to avoid over-paying for storage

The most common production issues I've seen are: missing retry logic (one rate limit error takes down the whole feature), blindly accessing `response.text` (crashes on blocked responses), and using the default thinking budget everywhere (expensive and slow for simple tasks). Get these three right first.

## Exception-Level Error Handling Reference

Generic `except Exception` blocks hide the information you need to debug production issues. Here's a reference implementation that handles each exception type distinctly:

```python
import google.generativeai as genai
from google.api_core import exceptions as google_exceptions
import os
import time
import logging

logger = logging.getLogger(__name__)
genai.configure(api_key=os.environ["GOOGLE_API_KEY"])
model = genai.GenerativeModel("gemini-2.5-pro-preview-05-06")

def robust_generate(
    prompt: str,
    max_tokens: int = 4096,
    max_retries: int = 4
) -> str | None:
    """
    Production-grade API call with per-exception handling.
    
    Error categories:
    - ResourceExhausted (429): Rate limit — retry with backoff
    - InvalidArgument (400): Bad request — fix the prompt, don't retry
    - PermissionDenied (403): Auth failure — check API key, don't retry  
    - NotFound (404): Wrong model name — fix config, don't retry
    - ServiceUnavailable (503): Google outage — retry after delay
    - DeadlineExceeded (504): Timeout — use streaming instead
    """
    for attempt in range(max_retries):
        try:
            response = model.generate_content(
                prompt,
                generation_config=genai.GenerationConfig(max_output_tokens=max_tokens)
            )
            
            # Validate the response before returning
            if not response.candidates:
                logger.warning(f"Empty candidates. Prompt feedback: {response.prompt_feedback}")
                return None
            
            candidate = response.candidates[0]
            finish_reason = candidate.finish_reason.name
            
            if finish_reason == "SAFETY":
                logger.warning("Response blocked by safety filter.")
                return None
            if finish_reason == "RECITATION":
                logger.warning("Response blocked: copyright content detected.")
                return None
            if finish_reason == "MAX_TOKENS":
                logger.warning(f"Response truncated at {max_tokens} tokens.")
                # Return partial — caller decides whether to retry with higher limit
            
            return candidate.content.parts[0].text
        
        except google_exceptions.ResourceExhausted as e:
            # Retryable: rate limit
            if attempt == max_retries - 1:
                logger.error(f"Rate limit persists after {max_retries} retries.")
                raise
            wait = min(2 ** attempt * 2, 120)
            logger.info(f"Rate limited (attempt {attempt + 1}). Waiting {wait}s.")
            time.sleep(wait)
        
        except google_exceptions.ServiceUnavailable:
            # Retryable: temporary Google outage
            if attempt == max_retries - 1:
                logger.error("Google API unavailable. Check status.cloud.google.com.")
                raise
            time.sleep(30)
        
        except google_exceptions.InvalidArgument as e:
            # Not retryable: prompt is malformed or too long
            logger.error(f"Invalid request: {e.message}")
            logger.error("Check: prompt length, model name, GenerationConfig values")
            raise  # Caller must fix the prompt
        
        except google_exceptions.PermissionDenied as e:
            # Not retryable: authentication problem
            logger.error(f"Auth failure: {e.message}")
            logger.error("Check: GOOGLE_API_KEY is set and the API is enabled")
            raise
        
        except google_exceptions.NotFound as e:
            # Not retryable: model doesn't exist
            logger.error(f"Model not found: {e.message}")
            logger.error("Check model name at ai.google.dev/gemini-api/docs/models/gemini")
            raise
        
        except google_exceptions.DeadlineExceeded:
            # Non-streaming request timed out
            logger.error("Request timed out. Switch to streaming API for long generations.")
            raise
    
    return None  # Unreachable, but satisfies type checker

# Example: using the function with proper handling at call site
result = robust_generate(
    prompt="Explain the CAP theorem and its practical implications for distributed system design.",
    max_tokens=2048
)

if result is None:
    print("Generation failed — check logs for details.")
else:
    print(result)
```

## Monitoring Token Usage Over Time

Track `prompt_token_count` and `candidates_token_count` in your logs consistently. Over a few weeks, this data tells you:

- Which features are driving the most API cost
- Whether `max_output_tokens` is frequently being hit (signal to raise it)
- Whether thinking tokens are dominating cost unexpectedly

```python
import google.generativeai as genai
import json
import time
import os
from datetime import datetime

genai.configure(api_key=os.environ["GOOGLE_API_KEY"])
model = genai.GenerativeModel("gemini-2.5-pro-preview-05-06")

def logged_generate(prompt: str, feature_tag: str = "general") -> str | None:
    """Generate with structured logging for cost monitoring."""
    start = time.time()
    
    try:
        response = model.generate_content(prompt)
        elapsed_ms = (time.time() - start) * 1000
        
        usage = response.usage_metadata
        log_entry = {
            "timestamp": datetime.utcnow().isoformat(),
            "feature": feature_tag,
            "input_tokens": usage.prompt_token_count,
            "output_tokens": usage.candidates_token_count,
            "cached_tokens": getattr(usage, "cached_content_token_count", 0),
            "thinking_tokens": getattr(usage, "thoughts_token_count", 0),
            "stop_reason": response.candidates[0].finish_reason.name if response.candidates else "NONE",
            "latency_ms": round(elapsed_ms, 1)
        }
        
        # In production: send to your logging system (CloudWatch, Datadog, etc.)
        print(json.dumps(log_entry))
        
        if not response.candidates:
            return None
        return response.candidates[0].content.parts[0].text
    
    except Exception as e:
        elapsed_ms = (time.time() - start) * 1000
        print(json.dumps({
            "timestamp": datetime.utcnow().isoformat(),
            "feature": feature_tag,
            "error": type(e).__name__,
            "message": str(e),
            "latency_ms": round(elapsed_ms, 1)
        }))
        return None

# Usage with feature tagging
response = logged_generate(
    "What are the best practices for API error handling in Python?",
    feature_tag="documentation-search"
)
```

With consistent structured logs, building a cost dashboard in your monitoring tool of choice becomes straightforward — just aggregate by `feature` and sum `input_tokens + output_tokens`.
