When building voice AI agents, the instinctive first approach is a server-relay architecture: browser → backend server → Gemini Live API. It's straightforward to implement, but latency compounds quickly. Audio travels from the microphone to your server, then to Gemini, back to the server, and finally to the browser — adding 350–500ms of round-trip overhead that makes conversation feel sluggish and unnatural.

The Web Audio API's AudioWorklet changes this equation. By processing audio in a dedicated worklet thread and connecting directly to Gemini Live API using an Ephemeral Token, you can eliminate the relay overhead entirely and hit 150–250ms end-to-end latency — a difference you can feel in conversation.

This guide walks through building a complete browser-based voice agent from scratch: microphone capture with sample rate conversion, voice activity detection, Gemini Live API integration via Ephemeral Token, audio playback buffering, and automatic reconnection with exponential backoff.

## Why AudioWorklet + Gemini Live API Direct Connection?

### The Server-Relay Bottleneck

Most production implementations use a relay architecture because exposing API keys in the browser is a non-starter for security. The typical pattern looks like:

- Browser sends audio chunks to your WebSocket server
- Server forwards to Gemini Live API WebSocket
- Server receives response audio and relays it back to the browser

This architecture has real costs beyond latency. Every audio session requires persistent server-side WebSocket connections, relay bandwidth for the full audio stream, and sticky session routing since audio sessions are stateful. These costs scale linearly with concurrent users.

### Ephemeral Tokens Enable Secure Direct Connection

Gemini Live API supports generating short-lived Ephemeral Tokens — credentials that expire in 60 seconds and can only be used to establish a single Live API session. Here's what this enables:

```
Browser → Token Server (exchanges API Key for Token) → Browser
Browser → Gemini Live API (connects directly with Token)
        ↑ AudioWorklet streams mic audio here directly
```

Your API key never leaves the server. The token is useless after the session starts. The audio relay server disappears entirely.

## Architecture Overview

The system has four components, each with a single responsibility:

- **Token Server (Node.js)**: Accepts requests from the browser, exchanges your API key for a short-lived Ephemeral Token, and returns it
- **AudioWorklet**: Runs in a dedicated audio thread, downsamples microphone input to 16kHz PCM, and detects voice activity
- **GeminiLiveSession**: Manages the WebSocket connection to Gemini Live API, handles sending audio chunks and receiving responses
- **AudioPlaybackQueue**: Buffers incoming 24kHz PCM audio chunks and schedules smooth playback using Web Audio API

This clean separation makes each component independently testable and replaceable.

```javascript
// server.mjs
import express from 'express';
import cors from 'cors';

const app = express();

              }

              }]
            }
          },
          ttl: '60s'
        })
      }

    if (\!response.ok) {
      const err = await response.json().catch(() => ({}));
      throw new Error(err.error?.message || `HTTP ${response.status}`);
    }

    const data = await response.json();
    // Return token with 5-second safety margin on expiry
    res.json({ token: data.name, expiresAt: Date.now() + 55_000 });
  } catch (error) {
    console.error('[TokenServer]', error.message);
    res.status(500).json({ error: error.message });

app.listen(process.env.PORT || 3001, () =>
  console.log(`Token server on :${process.env.PORT || 3001}`)
);
```

The 60-second TTL isn't paranoia — it's defense in depth. Even if someone intercepts the token from browser memory or network traffic, it expires before they can do meaningful damage.

## AudioWorklet: Microphone Processing in a Dedicated Thread

Running audio processing on the main thread causes UI jank. AudioWorklet runs in a dedicated high-priority thread that can't be blocked by JavaScript garbage collection or layout reflows.

Gemini Live API expects **16kHz / 16-bit signed PCM**. Most browsers default to 44.1kHz or 48kHz, so we need downsampling.

```javascript
// public/audio-processor.worklet.js
// Runs in AudioWorkletGlobalScope (separate from main thread)

class VoiceActivityProcessor extends AudioWorkletProcessor {
  constructor() {
    super();
    this.targetSampleRate = 16000;
    this.sourceSampleRate = 0;   // Set from sampleRate global on first process()
    this.buffer = [];
    this.chunkSizeSamples = 1600; // 16kHz × 100ms = 1600 samples per chunk

    // VAD parameters
    this.energyThreshold = 0.001; // RMS energy threshold for voice detection
    this.silenceFrames = 0;
    this.silenceThreshold = 15;   // 15 frames ≈ 150ms of silence = turn end
    this.isSpeaking = false;
  }

  /**
   * Linear interpolation downsampling.
   *
   * Why not simple decimation? Decimation without an anti-aliasing filter
   * causes aliasing artifacts — frequencies above the Nyquist frequency
   * of the output rate fold back into the signal. Linear interpolation
   * acts as a crude low-pass filter that reduces (but doesn't eliminate)
   * this. For voice at 16kHz, it's sufficient.
   */
  downsample(inputBuffer, inputRate, outputRate) {
    if (inputRate === outputRate) return inputBuffer;

    const ratio = inputRate / outputRate;
    const outputLength = Math.floor(inputBuffer.length / ratio);
    const output = new Float32Array(outputLength);

    for (let i = 0; i < outputLength; i++) {
      const srcIdx = i * ratio;
      const srcIdxInt = Math.floor(srcIdx);
      const fraction = srcIdx - srcIdxInt;
      const a = inputBuffer[srcIdxInt] ?? 0;
      const b = inputBuffer[srcIdxInt + 1] ?? 0;
      output[i] = a + (b - a) * fraction;
    }

    return output;
  }

  /**
   * Convert Float32 PCM [-1, 1] to Int16 PCM [-32768, 32767].
   * Gemini Live API expects 16-bit signed integer PCM.
   */
  float32ToInt16(float32Array) {
    const int16Array = new Int16Array(float32Array.length);
    for (let i = 0; i < float32Array.length; i++) {
      const clamped = Math.max(-1, Math.min(1, float32Array[i]));
      int16Array[i] = Math.round(clamped * 32767);
    }
    return int16Array;
  }

  calculateRMS(samples) {
    let sum = 0;
    for (let i = 0; i < samples.length; i++) sum += samples[i] * samples[i];
    return Math.sqrt(sum / samples.length);
  }

  process(inputs) {
    const input = inputs[0];
    if (\!input?.[0]) return true;

    const channelData = input[0];

    // sampleRate is a global in AudioWorkletGlobalScope — the actual hardware rate
    if (this.sourceSampleRate === 0) this.sourceSampleRate = sampleRate;

    const downsampled = this.downsample(channelData, this.sourceSampleRate, this.targetSampleRate);

    // Voice activity detection
    const energy = this.calculateRMS(downsampled);
    const isVoice = energy > this.energyThreshold;

    if (isVoice) {
      this.silenceFrames = 0;
      if (\!this.isSpeaking) {
        this.isSpeaking = true;
        this.port.postMessage({ type: 'speech_start' });
      }
    } else {
      this.silenceFrames++;
      if (this.isSpeaking && this.silenceFrames > this.silenceThreshold) {
        this.isSpeaking = false;
        this.port.postMessage({ type: 'speech_end' });
      }
    }

    // Accumulate into buffer and emit chunks
    this.buffer.push(...downsampled);

    while (this.buffer.length >= this.chunkSizeSamples) {
      const chunk = this.buffer.splice(0, this.chunkSizeSamples);
      const int16 = this.float32ToInt16(new Float32Array(chunk));

      // Transfer ownership of the ArrayBuffer (zero-copy)
      this.port.postMessage(
        { type: 'audio_chunk', data: int16.buffer },
        [int16.buffer]  // Transferable — avoids memcopy
      );
    }

    return true;
  }
}

registerProcessor('voice-activity-processor', VoiceActivityProcessor);
```

The `[int16.buffer]` in the `postMessage` call is the key optimization. Passing the ArrayBuffer as a Transferable transfers ownership rather than copying the data. For 100ms chunks at 16kHz (3200 bytes), this saves a memcopy every 100ms — at 10 chunks per second, that adds up.

## Managing the Gemini Live API Connection

```javascript
// src/gemini-live-session.js
export class GeminiLiveSession {
  constructor({ onAudioChunk, onTurnComplete, onError }) {
    this.ws = null;
    this.token = null;
    this.tokenExpiresAt = 0;
    this.onAudioChunk = onAudioChunk;
    this.onTurnComplete = onTurnComplete;
    this.onError = onError;
    this.reconnectAttempts = 0;
    this.maxReconnectAttempts = 5;
    this.reconnectDelay = 1000;
    this.isConnected = false;
    this.systemInstruction = '';
  }

  /**
   * Get a valid token, reusing the existing one if it has 10+ seconds left.
   * Always call this immediately before connecting, never cache it long-term.
   */
  async getToken() {
    if (this.token && Date.now() < this.tokenExpiresAt - 10_000) {
      return this.token;
    }

    const response = await fetch('/api/token', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ systemInstruction: this.systemInstruction })
    });

    if (\!response.ok) throw new Error(`Token request failed: ${response.status}`);

    const data = await response.json();
    this.token = data.token;
    this.tokenExpiresAt = data.expiresAt;
    return this.token;
  }

  async connect(systemInstruction = 'You are a helpful assistant.') {
    this.systemInstruction = systemInstruction;

    try {
      const token = await this.getToken();

      const wsUrl = `wss://generativelanguage.googleapis.com/ws/google.ai.generativelanguage.v1beta.GenerativeService.BidiGenerateContent?token=${token}`;
      this.ws = new WebSocket(wsUrl);

      // Wait for connection with a timeout
      await new Promise((resolve, reject) => {
        const timeout = setTimeout(
          () => reject(new Error('Connection timeout after 10s')),
          10_000
        );

        this.ws.onopen = () => {
          clearTimeout(timeout);
          this.isConnected = true;
          this.reconnectAttempts = 0;
          resolve();
        };

        this.ws.onerror = () => {
          clearTimeout(timeout);
          reject(new Error('WebSocket connection refused'));
        };
      });

      this.ws.onmessage = (e) => this.handleMessage(e);
      this.ws.onclose = (e) => this.handleClose(e);
      this.ws.onerror = () => this.onError?.(new Error('WebSocket error'));

    } catch (error) {
      this.isConnected = false;
      this.onError?.(error);
      throw error;
    }
  }

  async handleMessage(event) {
    try {
      const text = event.data instanceof Blob
        ? await event.data.text()
        : event.data;
      const data = JSON.parse(text);

      const serverContent = data.serverContent;
      if (\!serverContent) return;

      // Extract audio from response
      for (const part of serverContent.modelTurn?.parts ?? []) {
        if (part.inlineData?.mimeType === 'audio/pcm;rate=24000') {
          const binaryStr = atob(part.inlineData.data);
          const bytes = new Uint8Array(binaryStr.length);
          for (let i = 0; i < binaryStr.length; i++) {
            bytes[i] = binaryStr.charCodeAt(i);
          }
          this.onAudioChunk?.(new Int16Array(bytes.buffer));
        }
      }

      if (serverContent.turnComplete) {
        this.onTurnComplete?.();
      }

    } catch (error) {
      console.error('[GeminiLive] Parse error:', error);
    }
  }

  /**
   * Reconnect with exponential backoff.
   *
   * Why exponential backoff? If your server or Gemini's service has a brief
   * outage, all clients reconnecting simultaneously (Thundering Herd) can
   * make the outage worse. Exponential backoff spreads reconnection attempts
   * over time. With 5 attempts at 1s/2s/4s/8s/16s, you cover 31 seconds of
   * potential outage without hammering the service.
   */
  async handleClose(event) {
    this.isConnected = false;

    if (event.code === 1000) return; // Clean disconnect, don't reconnect

    if (this.reconnectAttempts < this.maxReconnectAttempts) {
      this.reconnectAttempts++;
      const delay = this.reconnectDelay * Math.pow(2, this.reconnectAttempts - 1);
      console.log(`[GeminiLive] Reconnecting in ${delay}ms (${this.reconnectAttempts}/${this.maxReconnectAttempts})`);

      setTimeout(async () => {
        try {
          await this.connect(this.systemInstruction);
        } catch (err) {
          this.onError?.(err);
        }
      }, delay);
    } else {
      this.onError?.(new Error('Max reconnect attempts reached. Please refresh.'));
    }
  }

  sendAudio(int16Array) {
    if (\!this.isConnected || this.ws?.readyState \!== WebSocket.OPEN) return;

    const uint8 = new Uint8Array(int16Array.buffer ?? int16Array);
    const base64 = btoa(String.fromCharCode(...uint8));

    this.ws.send(JSON.stringify({
      realtimeInput: {
        mediaChunks: [{ mimeType: 'audio/pcm;rate=16000', data: base64 }]
      }
    }));
  }

  sendText(text) {
    if (\!this.isConnected || this.ws?.readyState \!== WebSocket.OPEN) return;
    this.ws.send(JSON.stringify({
      clientContent: {
        turns: [{ role: 'user', parts: [{ text }] }],
        turnComplete: true
      }
    }));
  }

  disconnect() {
    this.reconnectAttempts = this.maxReconnectAttempts; // Prevent reconnect loop
    this.ws?.close(1000, 'User disconnect');
    this.ws = null;
    this.isConnected = false;
  }
}
```

## Audio Playback Queue

Gemini's output is 24kHz PCM, but your AudioContext probably runs at 44.1kHz or 48kHz. Responses arrive in multiple chunks. Both issues are handled by the playback queue.

```javascript
// src/audio-playback-queue.js
export class AudioPlaybackQueue {
  constructor(audioContext) {
    this.audioContext = audioContext;
    this.queue = [];
    this.isPlaying = false;
    this.nextPlayTime = 0;
    this.sourceSampleRate = 24000;
    this.gainNode = audioContext.createGain();
    this.gainNode.connect(audioContext.destination);
  }

  /**
   * Add a chunk of Int16 audio to the playback queue.
   *
   * Key insight: passing the source sample rate (24000) to createBuffer()
   * tells the browser's audio engine to resample automatically. This uses
   * the browser's native, highly-optimized resampler — no manual
   * implementation needed.
   */
  enqueue(int16Array) {
    const float32 = new Float32Array(int16Array.length);
    for (let i = 0; i < int16Array.length; i++) {
      float32[i] = int16Array[i] / 32768.0;
    }

    const buffer = this.audioContext.createBuffer(
      1,                        // Mono
      float32.length,
      this.sourceSampleRate     // Source rate — browser resamples automatically
    );
    buffer.copyToChannel(float32, 0);
    this.queue.push(buffer);

    if (\!this.isPlaying) this.playNext();
  }

  playNext() {
    if (this.queue.length === 0) {
      this.isPlaying = false;
      return;
    }

    this.isPlaying = true;
    const buffer = this.queue.shift();
    const source = this.audioContext.createBufferSource();
    source.buffer = buffer;
    source.connect(this.gainNode);

    // Schedule each chunk to start exactly where the last one ends.
    // The 50ms floor (currentTime + 0.05) prevents buffer underruns when
    // a chunk arrives later than expected.
    const currentTime = this.audioContext.currentTime;
    const startTime = Math.max(currentTime + 0.05, this.nextPlayTime);

    source.start(startTime);
    this.nextPlayTime = startTime + buffer.duration;
    source.onended = () => this.playNext();
  }

  clear() {
    this.queue = [];
    this.isPlaying = false;
    this.nextPlayTime = 0;
  }
}
```

The scheduling math — `Math.max(currentTime + 0.05, this.nextPlayTime)` — is where smooth audio comes from. When chunks arrive on time, `nextPlayTime` dominates and each chunk starts exactly where the last one ended. When a chunk is delayed, `currentTime + 0.05` takes over as a floor, ensuring we always have 50ms of buffer before playback starts. This prevents both gaps (where the queue runs dry) and overlaps (where two chunks play simultaneously).

## Putting It All Together: The Controller

```javascript
// src/voice-agent-controller.js
import { GeminiLiveSession } from './gemini-live-session.js';
import { AudioPlaybackQueue } from './audio-playback-queue.js';

export class VoiceAgentController {
  constructor({ systemInstruction = 'You are a helpful assistant.', onStatusChange } = {}) {
    this.session = null;
    this.audioContext = null;
    this.workletNode = null;
    this.mediaStream = null;
    this.playbackQueue = null;
    this.systemInstruction = systemInstruction;
    this.onStatusChange = onStatusChange;
    this.status = 'idle'; // idle | connecting | listening | thinking | speaking | error
  }

  setStatus(status) {
    this.status = status;
    this.onStatusChange?.(status);
  }

  async start() {
    this.setStatus('connecting');

    try {
      // AudioContext MUST be created inside a user gesture handler.
      // Browsers suspend audio until user interaction.
      this.audioContext = new AudioContext();
      await this.audioContext.resume();

      // Request microphone with preferred settings.
      // Note: sampleRate hint is not always honored (especially macOS Safari).
      // The worklet handles downsampling regardless.
      this.mediaStream = await navigator.mediaDevices.getUserMedia({
        audio: {
          sampleRate: { ideal: 16000 },
          channelCount: 1,
          echoCancellation: true,   // Hardware AEC where available
          noiseSuppression: true,
          autoGainControl: true
        }
      });

      this.playbackQueue = new AudioPlaybackQueue(this.audioContext);

      this.session = new GeminiLiveSession({
        onAudioChunk: (int16) => {
          if (this.status \!== 'idle') {
            this.setStatus('speaking');
            this.playbackQueue.enqueue(int16);
          }
        },
        onTurnComplete: () => this.setStatus('listening'),
        onError: (err) => {
          console.error('[VoiceAgent]', err);
          this.setStatus('error');
        }
      });

      await this.session.connect(this.systemInstruction);

      // Load the AudioWorklet module
      await this.audioContext.audioWorklet.addModule('/audio-processor.worklet.js');

      const source = this.audioContext.createMediaStreamSource(this.mediaStream);
      this.workletNode = new AudioWorkletNode(this.audioContext, 'voice-activity-processor');

      this.workletNode.port.onmessage = ({ data }) => {
        switch (data.type) {
          case 'speech_start':
            if (this.status \!== 'speaking') this.setStatus('listening');
            break;

          case 'speech_end':
            // Worklet detected end of utterance
            break;

          case 'audio_chunk': {
            // Software echo prevention: don't send mic audio while Gemini is speaking.
            // Hardware AEC (echoCancellation: true) helps but isn't sufficient alone.
            if (this.status \!== 'speaking') {
              this.session.sendAudio(new Int16Array(data.data));
            }
            break;
          }
        }
      };

      // source → workletNode (NOT connected to destination — mic audio stays silent)
      source.connect(this.workletNode);

      this.setStatus('listening');

    } catch (error) {
      this.setStatus('error');
      // Clean up partial initialization
      this.mediaStream?.getTracks().forEach(t => t.stop());
      await this.audioContext?.close().catch(() => {});
      throw error;
    }
  }

  async stop() {
    this.session?.disconnect();
    this.workletNode?.disconnect();
    this.mediaStream?.getTracks().forEach(t => t.stop());
    this.playbackQueue?.clear();
    await this.audioContext?.close().catch(() => {});

    this.session = null;
    this.workletNode = null;
    this.mediaStream = null;
    this.audioContext = null;
    this.playbackQueue = null;

    this.setStatus('idle');
  }
}
```

## Common Pitfalls and How to Avoid Them

### Pitfall 1: Autoplay Policy Violations

```javascript
// WRONG: Creating AudioContext outside a user gesture
window.onload = () => {
  const ctx = new AudioContext(); // State: 'suspended', unusable
};

// RIGHT: Create AND resume inside a click/tap handler
button.addEventListener('click', async () => {
  const ctx = new AudioContext();
  await ctx.resume(); // Essential — don't skip this
  await agent.start();
});
```

Chrome, Safari, and Firefox all enforce autoplay policies that block audio contexts created without user interaction. `new AudioContext()` returns a suspended context. If you skip `resume()`, AudioWorklet processes silently but emits no data. This shows up as the microphone appearing to work (permissions granted, stream active) but no audio reaching Gemini.

### Pitfall 2: Sample Rate Mismatch Breaking Audio

```javascript
// WRONG: Assuming getUserMedia honored the sampleRate hint
const stream = await navigator.mediaDevices.getUserMedia({
  audio: { sampleRate: 16000 }
});
// On macOS Safari, stream.getAudioTracks()[0].getSettings().sampleRate
// returns 44100 regardless of what you asked for.
// Sending 44100Hz audio as 16kHz to Gemini produces chipmunk-speed garbled audio.

// RIGHT: Let the AudioWorklet handle downsampling unconditionally.
// The worklet reads `sampleRate` (the actual hardware rate) and downsamples accordingly.
```

Always check `stream.getAudioTracks()[0].getSettings().sampleRate` if you're debugging audio quality issues. The worklet's `sampleRate` global tells you the truth.

### Pitfall 3: Echo Feedback Loop

When Gemini's audio plays through speakers, your microphone picks it up and sends it back to Gemini, which responds to its own voice. Hardware AEC (`echoCancellation: true`) helps, but its effectiveness varies wildly by device and OS. Always combine hardware AEC with software gating:

```javascript
// In the audio_chunk handler — the status guard is the software gate
case 'audio_chunk': {
  if (this.status \!== 'speaking') {   // Don't send while Gemini is speaking
    this.session.sendAudio(new Int16Array(data.data));
  }
  break;
}
```

With both layers in place, echo is reliably suppressed across device types.

### Pitfall 4: Stack Overflow in Base64 Encoding

```javascript
// WRONG: Spread operator with large Uint8Array can overflow the call stack
const base64 = btoa(String.fromCharCode(...new Uint8Array(largeBuffer)));
// RangeError: Maximum call stack size exceeded

// RIGHT: Process in chunks if your audio chunks are large
function safeUint8ToBase64(uint8Array) {
  let binary = '';
  const chunkSize = 8192;
  for (let i = 0; i < uint8Array.length; i += chunkSize) {
    binary += String.fromCharCode(...uint8Array.subarray(i, i + chunkSize));
  }
  return btoa(binary);
}
```

At 100ms chunks (3200 bytes), the spread operator is safe. If you increase chunk size to 500ms (16000 bytes) or more, switch to chunked encoding.

### Pitfall 5: Token Management on Reconnect

The Ephemeral Token is only needed to establish a connection — once connected, it's useless. But on reconnect, you need a fresh token (the old one has expired). The `getToken()` method handles this transparently:

```javascript
// GeminiLiveSession.handleClose() calls connect() which calls getToken()
// getToken() checks expiry and fetches a fresh token if needed
// No special reconnect logic required on the calling side
```

Don't try to store and reuse tokens across sessions. They're designed to be disposable.

## Performance Monitoring in Production

```javascript
class VoiceLatencyMonitor {
  constructor() {
    this.speechEndTime = 0;
  }

  onSpeechEnd() {
    this.speechEndTime = performance.now();
  }

  onFirstAudioChunk() {
    if (this.speechEndTime === 0) return;
    const latency = performance.now() - this.speechEndTime;

    // Typical range: 150-250ms (direct) vs 400-600ms (relay)
    console.log(`[Latency] ${latency.toFixed(0)}ms`);

    if (latency > 350) {
      console.warn('[Latency] Above target. Check: network RTT, Gemini load, token server latency');
    }

    this.speechEndTime = 0;
  }
}
```

Typical latency breakdown for direct connection:
- Token fetch (if needed): 50–100ms (skip on reconnect)
- Gemini processing: 100–200ms
- Audio chunk delivery: <20ms (direct WebSocket)
- **Total: 150–250ms**

Compare to relay architecture: 350–600ms with additional variables from your server's location and load.

## Production Deployment Checklist

Before shipping to production:

- Run the token server on HTTPS — HTTP exposes tokens to network interception
- Set `ALLOWED_ORIGIN` to your exact production domain, not a wildcard
- Test on iOS Safari — it has unique getUserMedia behavior (always 44.1kHz, requires explicit user gesture for AudioContext)
- Implement user-facing error messages for: permission denied, connection timeout, max reconnects reached
- Add a fallback for environments where WebSocket to Gemini's domain is blocked (corporate firewalls often block non-port-443 WebSocket)
- Monitor latency in production — sustained high latency (>400ms) usually indicates network path issues, not code problems

## Wrapping Up

The combination of AudioWorklet and Gemini Live API's Ephemeral Token support makes browser-direct voice AI agents practical for production. You get sub-250ms latency, no relay server costs, and a clean security boundary through short-lived tokens.

The three implementation areas that trip up most developers are sample rate handling (always downsample in the worklet, never assume the hint was honored), echo prevention (layer hardware AEC with software gating), and reconnection (always fetch a fresh token, use exponential backoff).

The code in this guide is production-ready as a starting point. Add HTTPS, tighten your CORS configuration, and you have a voice AI agent infrastructure that scales with your users without scaling your relay server costs.

For the latest Gemini Live API model names, voice options, and streaming parameters, check [the official documentation](https://ai.google.dev/gemini-api/docs/live) — the API is evolving quickly and capabilities expand regularly.

## Browser Compatibility and Graceful Degradation

AudioWorklet and the WebSocket-based Gemini Live API connection work across all major modern browsers, but with nuances worth knowing before your first production incident.

### Compatibility Matrix

**Chrome / Edge (Chromium)**: Full support for AudioWorklet, AudioContext, and MediaDevices. The `sampleRate` hint in getUserMedia is usually honored when the device supports it. AEC quality varies by OS.

**Firefox**: Full AudioWorklet support. getUserMedia sampleRate hints are ignored — the hardware rate is always used. This means you'll always go through the worklet downsampling path.

**Safari (macOS)**: Full AudioWorklet support since Safari 14.1. getUserMedia always returns 44.1kHz regardless of hints. AudioContext requires a user gesture even when called from inside an async function that was triggered by a click — the gesture must be direct and synchronous.

**Safari (iOS)**: The most complex case. AudioContext must be created and `resume()` called in the *synchronous* part of the click handler, not after an `await`. If you `await` before calling `new AudioContext()`, iOS Safari may still suspend it.

```javascript
// iOS Safari-safe AudioContext initialization
button.addEventListener('click', () => {
  // SYNCHRONOUS: create and resume before any await
  const audioContext = new AudioContext();
  audioContext.resume(); // Don't await here on iOS

  // THEN: proceed with async setup
  agent.start(audioContext).catch(console.error);
});
```

### Testing Across Environments

Before deploying, test these scenarios manually:

```javascript
// Diagnostic helper — run in browser console before testing
async function diagnoseAudioEnvironment() {
  const stream = await navigator.mediaDevices.getUserMedia({ audio: true });
  const track = stream.getAudioTracks()[0];
  const settings = track.getSettings();

  console.log('Actual sampleRate:', settings.sampleRate);
  console.log('Actual channelCount:', settings.channelCount);
  console.log('echoCancellation:', settings.echoCancellation);
  console.log('noiseSuppression:', settings.noiseSuppression);

  const ctx = new AudioContext();
  console.log('AudioContext sampleRate:', ctx.sampleRate);
  console.log('AudioContext state:', ctx.state);

  track.stop();
  await ctx.close();
}

diagnoseAudioEnvironment();
```

Run this on each target device and browser combination before your first user test. The gap between what you requested and what you got is where most audio quality bugs hide.

## Integrating with React and Vue

The controller class is framework-agnostic by design. Wrapping it in React:

```javascript
// hooks/useVoiceAgent.js
import { useState, useRef, useCallback } from 'react';
import { VoiceAgentController } from '../src/voice-agent-controller.js';

export function useVoiceAgent({ systemInstruction } = {}) {
  const [status, setStatus] = useState('idle');
  const controllerRef = useRef(null);

  const start = useCallback(async () => {
    if (controllerRef.current) return; // Prevent double-start

    const controller = new VoiceAgentController({
      systemInstruction,
      onStatusChange: setStatus
    });

    controllerRef.current = controller;

    try {
      await controller.start();
    } catch (error) {
      controllerRef.current = null;
      throw error;
    }
  }, [systemInstruction]);

  const stop = useCallback(async () => {
    if (\!controllerRef.current) return;
    await controllerRef.current.stop();
    controllerRef.current = null;
  }, []);

  return { status, start, stop };
}

// Usage in a component
function VoiceButton() {
  const { status, start, stop } = useVoiceAgent({
    systemInstruction: 'You are a helpful assistant.'
  });

  const handleClick = async () => {
    if (status === 'idle' || status === 'error') {
      await start();
    } else {
      await stop();
    }
  };

  const labels = {
    idle: 'Start Conversation',
    connecting: 'Connecting...',
    listening: 'Listening... (click to stop)',
    speaking: 'Gemini is speaking...',
    error: 'Error — click to retry'
  };

  return (
    <button onClick={handleClick} disabled={status === 'connecting'}>
      {labels[status] ?? status}
    </button>
  );
}
```

The `useRef` pattern for the controller is important — React's strict mode renders components twice in development, and using `useState` for the controller would cause double-initialization. The ref persists across renders without triggering re-renders itself.

## Cost Considerations

Running voice sessions has real API costs. A few things to know:

Gemini Live API charges for input audio tokens (what the user says) and output audio tokens (what Gemini responds with). A typical two-minute conversation might use 1,000–2,000 audio tokens depending on how much each party speaks.

The direct connection architecture has no additional relay server costs — your token server handles only the brief token exchange, not the audio stream. A single $5/month VPS is sufficient to serve token requests for thousands of concurrent voice sessions.

Rate limits apply per API key, not per session. If you're building a multi-user product, plan for rate limit management: either per-user API keys, or a queuing system on the token server that enforces limits before they hit Gemini.

For cost monitoring, the Gemini API dashboard shows per-model usage. Filter by `gemini-2.5-flash-preview` to track Live API specifically. Set up billing alerts at 50% and 80% of your monthly budget to catch unexpected usage spikes before they become expensive surprises.
