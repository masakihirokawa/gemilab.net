If you've been building with multiple AI APIs, you've probably run into this exact scenario: you want to use Gemini for some tasks and Claude for others, but every provider has a different SDK and calling convention. Or maybe you've had Gemini's rate limits hit at the worst possible time and wish you had automatic fallback to another model.

LiteLLM solves both of these problems. It's a Python library that gives you a single unified interface for 100+ language models — Gemini, Claude, OpenAI, Mistral, and more — while handling fallbacks, cost tracking, and load balancing out of the box.

## What Is LiteLLM?

LiteLLM abstracts away the differences between AI providers by exposing an OpenAI-compatible interface for all of them. Change the `model` parameter, and you're talking to a completely different provider — no other code changes needed.

This works particularly well with Gemini because Google provides a native OpenAI-compatible endpoint (covered in detail in [Gemini API OpenAI-Compatible Endpoint Guide](/en/articles/gemini-api/gemini-api-openai-compatible-endpoint-guide)). With LiteLLM, you don't even need to think about that compatibility layer — just use the `google/gemini-2.5-pro` model name and it handles the rest.

Key features at a glance:

- **Unified interface**: Same calling code regardless of provider
- **Fallback configuration**: Automatically switch to another model on errors
- **Cost tracking**: Real-time usage and cost visibility across all providers
- **Load balancing**: Distribute requests across multiple API keys or models

## Installation and Setup

Install LiteLLM with a single pip command:

```bash
pip install litellm
```

Set your API keys as environment variables. If you're planning to use multiple providers for fallbacks, configure all of them upfront:

```bash
export GEMINI_API_KEY="YOUR_GEMINI_API_KEY"
export ANTHROPIC_API_KEY="YOUR_ANTHROPIC_API_KEY"
export OPENAI_API_KEY="YOUR_OPENAI_API_KEY"
```

## Basic Gemini API Calls via LiteLLM

Here's the simplest possible usage:

```python
import litellm

# Call Gemini 2.5 Pro
response = litellm.completion(
    model="gemini/gemini-2.5-pro",
    messages=[
        {"role": "user", "content": "Write a Python function to generate Fibonacci numbers"}
    ]
)

print(response.choices[0].message.content)
# Expected output: A working Python implementation with explanation
```

Notice the `model` format: `"gemini/gemini-2.5-pro"`. LiteLLM uses the provider name as a prefix to route requests to the right API. Switch to Gemini 2.5 Flash by changing just that one parameter:

```python
response = litellm.completion(
    model="gemini/gemini-2.5-flash",
    messages=[{"role": "user", "content": "Summarize this briefly: ..."}]
)
```

## Fallback Configuration — Running Gemini Alongside Claude and OpenAI

This is where LiteLLM really shines. When Gemini hits rate limits (429 errors), you can automatically fall back to Claude Sonnet, and then to GPT-4o if Claude also fails — all configured in a few lines.

Rate limit handling is covered in depth at [Gemini API Production Error Handling and Rate Limit Guide](/en/articles/gemini-api/gemini-api-production-error-handling-rate-limit-guide), but LiteLLM's fallback approach solves the problem more fundamentally by routing around failures entirely.

```python
import litellm

response = litellm.completion(
    model="gemini/gemini-2.5-pro",
    messages=[{"role": "user", "content": "Review this code: ..."}],
    fallbacks=[
        "anthropic/claude-sonnet-4-6",  # If Gemini fails, try Claude
        "openai/gpt-4o"                  # If Claude fails, try GPT-4o
    ],
    num_retries=2  # Retry each model up to 2 times
)

# See which model actually responded
print(f"Model used: {response.model}")
print(response.choices[0].message.content)
```

The `response.model` field tells you which model ultimately handled the request — useful for logging and debugging. Since adding this pattern to a production app, I've effectively eliminated user-facing errors from Gemini rate limiting.

## Cost Tracking and Usage Visibility

LiteLLM automatically calculates and attaches cost information to every response:

```python
response = litellm.completion(
    model="gemini/gemini-2.5-pro",
    messages=[{"role": "user", "content": "Test"}]
)

usage = response.usage
print(f"Input tokens: {usage.prompt_tokens}")
print(f"Output tokens: {usage.completion_tokens}")

cost = litellm.completion_cost(completion_response=response)
print(f"Request cost: ${cost:.6f}")
```

For cumulative cost tracking across many requests, use the callback system:

```python
import litellm

class CostTracker:
    def __init__(self):
        self.total_cost = 0.0
    
    def log_success_event(self, kwargs, response_obj, start_time, end_time):
        cost = litellm.completion_cost(completion_response=response_obj)
        self.total_cost += cost
        print(f"Running total: ${self.total_cost:.4f}")

tracker = CostTracker()
litellm.callbacks = [tracker]

# Normal calls are automatically tracked
litellm.completion(
    model="gemini/gemini-2.5-flash",
    messages=[{"role": "user", "content": "Hello"}]
)
```

## Automatic Model Selection Pattern

A practical pattern I've found useful: route different task types to the right model automatically.

```python
import litellm

def call_ai(prompt: str, task_type: str = "general") -> str:
    """
    Select the best model based on task type:
    - coding:  Gemini 2.5 Pro (strongest at code tasks)
    - quick:   Gemini 2.5 Flash (speed and cost optimized)
    - general: Gemini 2.5 Pro with Claude fallback
    """
    model_config = {
        "coding": {
            "model": "gemini/gemini-2.5-pro",
            "fallbacks": ["anthropic/claude-sonnet-4-6"]
        },
        "quick": {
            "model": "gemini/gemini-2.5-flash",
            "fallbacks": ["gemini/gemini-2.5-pro"]
        },
        "general": {
            "model": "gemini/gemini-2.5-pro",
            "fallbacks": ["anthropic/claude-sonnet-4-6", "openai/gpt-4o"]
        }
    }
    
    config = model_config.get(task_type, model_config["general"])
    
    response = litellm.completion(
        messages=[{"role": "user", "content": prompt}],
        num_retries=2,
        **config
    )
    
    return response.choices[0].message.content

# Usage
code_result = call_ai("Write async file reading code in Python", task_type="coding")
quick_result = call_ai("Summarize this in 3 sentences: ...", task_type="quick")
```

## Practical Considerations

A few things worth knowing before you deploy this in production:

**API key management**: All fallback providers need their keys configured before you need them — not after a failure occurs. I keep a checklist of all provider key expiration dates in one place to avoid surprises.

**Model name format**: It's `"gemini/gemini-2.5-pro"` — not `"gemini-2.5-pro"`. Missing the provider prefix results in authentication errors that can be confusing to debug initially.

**Keep LiteLLM updated**: New Gemini models get added to LiteLLM frequently. Running `pip install litellm --upgrade` regularly ensures you have access to the latest models as soon as they're available.
