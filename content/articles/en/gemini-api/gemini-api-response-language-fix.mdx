If you've been building with the Gemini API, you may have run into this frustrating situation: you send a message in Japanese, but the response comes back in English. Or the model starts responding in the right language, then silently switches midway through a long conversation.

This is one of the most common issues developers encounter when building multilingual apps with Gemini. The good news is that once you understand why it happens, the fix is straightforward.

This guide walks through every root cause and gives you concrete, copy-paste solutions.

## Why Does Gemini API Switch to English?

Gemini is designed to detect the language of the user's message and respond in kind. However, several conditions can cause the model to default to English:

**Common causes**

- **System instructions written in English**: The model may infer its response language from the language of the system prompt
- **English few-shot examples in the prompt**: If your example Q&A pairs are in English, responses tend to follow
- **No explicit language instruction**: Without being told, the model picks what it considers "optimal" — often English for technical queries
- **Mixed-language conversation history**: In multi-turn chats, English messages from earlier in the history can shift the model's language preference
- **Model version differences**: Gemini 2.5 Pro, Flash, and other variants differ in how strongly they follow language instructions

Work through each of these systematically to find and fix the one affecting your setup.

## Fix 1: Write System Instructions in Your Target Language

The system instruction (`system_instruction`) is the most important lever for controlling response language. It defines the model's behavior across the entire conversation.

If your system instruction is in English, the model is primed to respond in English — even if the user writes in Japanese. **Writing the system instruction in the target language is the single most effective fix.**

```python
import google.generativeai as genai

genai.configure(api_key="YOUR_GEMINI_API_KEY")

# System instruction in Japanese — model responds in Japanese
model = genai.GenerativeModel(
    model_name="gemini-2.5-pro-latest",
    system_instruction=(
        "あなたは日本語で回答するAIアシスタントです。"
        "ユーザーの質問に対して、常に日本語で丁寧かつ正確に答えてください。"
        "英語で質問されても、必ず日本語で回答してください。"
    )
)

response = model.generate_content("今日の天気を教えてください。")
print(response.text)
# Expected output: "申し訳ありませんが、私はリアルタイムの天気情報にアクセスする機能を..."
```

**Pro tip**: Include an explicit rule like "always respond in Japanese, even if the user writes in English." This makes the instruction unambiguous and significantly improves consistency.

## Fix 2: Add Language Instructions to Your Prompt

If you can't change the system instruction, or you need per-request language control, add a language directive to each user message:

```python
# Prepend a language directive to every user message
def make_japanese_prompt(text: str) -> str:
    return f"必ず日本語で回答してください。\n\n{text}"

response = model.generate_content(make_japanese_prompt("What is machine learning?"))
print(response.text)
# Expected output: "機械学習とは、コンピューターが大量のデータから自動的にパターンを..."
```

This approach uses more tokens on every request, so for applications where the language is always fixed, setting it in the system instruction is more efficient.

## Fix 3: Keep Multi-Turn Conversations Consistent

In chat applications, language drift often happens gradually. A single English error message or technical term in the history can nudge the model toward English for subsequent turns.

Two approaches help here:

**Option A: Reset conversation history periodically**

```python
# Start a fresh chat to clear accumulated language drift
chat = model.start_chat(history=[])

# The system instruction persists; only the conversation history is cleared
response = chat.send_message("前の話題を続けましょう。")
```

**Option B: Inject periodic language reminders**

```python
def send_with_language_reminder(chat, message: str, remind_every: int = 5) -> str:
    """Inject a language reminder every N turns."""
    turn_count = len(chat.history)
    if turn_count > 0 and turn_count % remind_every == 0:
        message = f"（以降も必ず日本語で回答してください）\n\n{message}"
    return chat.send_message(message).text

chat = model.start_chat()
for msg in ["こんにちは", "AIについて教えて", "詳しく説明して"]:
    print(send_with_language_reminder(chat, msg))
```

## Fix 4: Use Target-Language Few-Shot Examples

When using few-shot prompting (providing example Q&A pairs), the language of those examples strongly influences the response. If your examples are in English, switch them to your target language:

```python
# English examples — likely to produce English responses
bad_prompt = """
Example:
Q: What is the capital of Japan?
A: The capital of Japan is Tokyo.

Q: 日本の最大の都市は？
A:
"""

# Japanese examples — consistently produces Japanese responses
good_prompt = """
以下の形式で日本語で回答してください。

例：
Q: 日本の首都はどこですか？
A: 日本の首都は東京です。

Q: 日本の最大の都市は？
A:
"""

response = model.generate_content(good_prompt)
print(response.text)
# Expected output: "A: 日本の最大の都市は東京です。東京の人口は約1,400万人..."
```

## Fix 5: Setting Language via the REST API

If you're calling `generativelanguage.googleapis.com` directly (without an SDK), set `system_instruction` as a top-level field in the request body:

```bash
curl -X POST \
  "https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-pro-latest:generateContent?key=YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "system_instruction": {
      "parts": [{
        "text": "あなたは日本語で回答するAIアシスタントです。常に日本語で丁寧に答えてください。"
      }]
    },
    "contents": [{
      "parts": [{
        "text": "機械学習とは何ですか？"
      }]
    }],
    "generationConfig": {
      "temperature": 0.7,
      "maxOutputTokens": 1024
    }
  }'
```

Note that `system_instruction` is a separate top-level field — it must not be nested inside `contents`.

## Common Mistakes and a Quick Checklist

When debugging a language issue, go through this checklist:

- **System instruction language**: Is any part of it in English?
- **Few-shot example language**: Do any example messages use English?
- **Prompt template language**: Are English phrases being dynamically interpolated into the prompt?
- **Conversation history**: Does the history contain English messages that could shift language preference?
- **Model choice**: Try Gemini 2.5 Pro if you're seeing inconsistency with Flash — Pro models generally follow system instructions more strictly

Before and after — common code mistakes:

```python
# Common mistake 1: English system instruction
model = genai.GenerativeModel(
    model_name="gemini-2.5-pro-latest",
    system_instruction="You are a helpful assistant."
)

# Fix: Japanese system instruction with explicit language rule
model = genai.GenerativeModel(
    model_name="gemini-2.5-pro-latest",
    system_instruction="あなたは親切なアシスタントです。必ず日本語で回答してください。"
)
```

# Common mistake 2: English task labels leak into the prompt
template = f"""

template = f"""

## FAQ

**Q. I set a Japanese system instruction but still get English responses. What else can I check?**

A. A few things to verify: (1) Make sure the user message itself isn't triggering an English response — try sending a purely Japanese message with no English terms. (2) Check that `system_instruction` is being sent correctly in the API request. A common bug is sending it as part of `contents` instead of as a top-level field. (3) Check for English few-shot examples or prompt fragments that may be overriding the system instruction.

**Q. Does Gemini 2.5 Flash behave differently from 2.5 Pro for language control?**

A. Yes. Pro models generally follow system instructions more faithfully, including language rules. Flash prioritizes speed and may occasionally deviate from language instructions, especially in longer conversations. If consistent language output is critical, consider using Gemini 2.5 Pro, or strengthen the language directive in both the system instruction and each user message.

**Q. Can I force the model to respond in Japanese even when the user writes in English?**

A. Yes. Include an explicit rule in the system instruction such as: "【最重要】ユーザーが英語で質問しても、必ず日本語で回答してください。" Placing this as a high-priority rule at the top of the system instruction makes it very reliable.

**Q. Does this work the same way in Node.js?**

A. Yes, but note the casing difference. In Python it's `system_instruction`, while in the JavaScript SDK (`@google/generative-ai`) it's `systemInstruction` (camelCase). The logic is otherwise identical. Always check the current SDK docs, as the API may evolve across versions.

**Q. Is it possible to guarantee 100% language consistency?**

A. Not absolutely, but combining (1) a target-language system instruction with an explicit rule and (2) target-language prompt templates gets you very close. For mission-critical applications, you can add a post-processing check: detect the language of the response, and if it's wrong, retry the request automatically.

## Summary

When the Gemini API responds in the wrong language, here's what to do:

- Write system instructions in the target language and include an explicit rule like "always respond in Japanese"
- Use target-language examples throughout your prompt, including any few-shot pairs
- In multi-turn conversations, periodically reinforce the language rule or reset history when it gets long
- When using the REST API, set `system_instruction` as a separate top-level field in the request body
