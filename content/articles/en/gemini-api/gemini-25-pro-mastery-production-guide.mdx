## 1. The Essence of Gemini 2.5 Pro

### Decision Framework for Model Selection

Three models, three use cases:

- **Gemini 2.0**: Baseline, moderate speed, $2.50/$7.50 per 1M tokens (input/output)
- **Gemini 2.5 Pro**: +25% accuracy, strong reasoning, $1.50/$6.00, complex tasks
- **Gemini 2.5 Flash**: Baseline, high-speed, $0.075/$0.30, real-time applications

Real example: A SaaS company tried Flash for customer legal document analysis. It missed important clauses 3% of the time. Pro caught 99.9%. Monthly cost difference: $125. But the savings from fewer customer complaints? ROI recovered in one month.

### How Thinking Mode Works

Pro includes an internal "thinking" phase. This is where the accuracy gain comes from.

```python
import anthropic

client = anthropic.Anthropic(api_key="YOUR_GEMINI_API_KEY")

response = client.messages.create(
    model="gemini-2.5-pro-latest",
    max_tokens=16000,
    thinking={
        "type": "enabled",
        "budget_tokens": 10000
    },
    messages=[{
        "role": "user",
        "content": "Identify hidden legal risks in this contract."
    }]
)

for block in response.content:
    if block.type == "thinking":
        print(f"🧠 Thinking: {block.thinking}")
    elif block.type == "text":
        print(f"✅ Answer: {block.text}")
```

Critical: Never skip budget_tokens. Without it, the model thinks indefinitely and charges you accordingly.

### Exponential Backoff Implementation

```python
import time
import random

def call_with_backoff(prompt, max_retries=3):
    for attempt in range(max_retries):
        try:
            response = client.messages.create(
                model="gemini-2.5-pro-latest",
                max_tokens=4096,
                messages=[{"role": "user", "content": prompt}]
            )
            return response.content[0].text
        except Exception as e:
            if attempt < max_retries - 1:
                wait = (2 ** attempt) + random.uniform(0, 1)
                time.sleep(wait)
            else:
                raise
```

## 3. Streaming Responses for Instant UX

```python
from flask import Flask, Response, request
import json

@app.route("/api/chat", methods=["POST"])
def stream_chat():
    msg = request.json.get("message")
    
    def generate():
        with client.messages.stream(
            model="gemini-2.5-pro-latest",
            max_tokens=4096,
            messages=[{"role": "user", "content": msg}]
        ) as stream:
            for text in stream.text_stream:
                yield f"data: {json.dumps({'chunk': text})}\n\n"
    
    return Response(generate(), mimetype="text/event-stream")
```

Users perceive streaming responses as 3x faster than waiting 5 seconds for a complete response.

## Common Mistakes and Fixes

### Mistake 1: Exceeding Token Limits

```python
# Dangerous
response = client.messages.create(
    model="gemini-2.5-pro-latest",
    max_tokens=100000,
    messages=[{"role": "user", "content": huge}]
)

# Fixed
tokens = count_tokens(huge)
if tokens > 900000:
    huge = huge[:int(len(huge) * 0.9)]
response = client.messages.create(
    model="gemini-2.5-pro-latest",
    max_tokens=min(4096, 1000000 - tokens),
    messages=[{"role": "user", "content": huge}]
)
```

### Mistake 2: Missing Error Handling

```python
from google.api_core.exceptions import (
    ServiceUnavailable, DeadlineExceeded, ResourceExhausted
)

try:
    response = client.messages.create(...)
except ServiceUnavailable:
    logger.error("API temporarily unavailable")
except DeadlineExceeded:
    logger.error("Request timeout")
except ResourceExhausted:
    logger.error("Rate limit reached")
```

## Pre-Production Checklist

- Never store API keys in .env files
- Implement Exponential Backoff for all API calls
- Use ADC in production, never raw API keys
- Set budget_tokens for Thinking Mode
- Add error handling to every API call
- Set timeouts for streaming responses
- Limit Function Calling turns with max_turns
- Validate multimodal input sizes
- Log all API calls with structured logging
- Enable caching to reduce costs 10-20%
- Have a peer review sensitive code twice
