## Setup and context — Why Gemini API × Qdrant?

The single biggest factor determining the quality of a RAG (Retrieval-Augmented Generation) system is whether you can retrieve the right documents at the right time. Traditional semantic search using dense vectors alone has a known weakness: it can miss documents containing important exact-match keywords, because meaning and wording aren't always the same thing.

This is where **hybrid search** shines. By combining dense vector search (semantic similarity) with sparse vector search (keyword matching), you get the best of both worlds — documents that are both semantically relevant and lexically aligned with the query.

**Qdrant** is a high-performance vector database written in Rust that natively supports hybrid search — one of the very few vector DBs to do so. Paired with the **Gemini Embedding API** (`text-embedding-004`, producing 768-dimensional vectors), it forms a powerful foundation for production-grade RAG systems.

## Qdrant Core Concepts and Setup

### Understanding the Architecture

Qdrant is built around the following core concepts:

- **Collection**: A logical group of vector data (analogous to a database table)
- **Point**: The atomic unit of a collection, consisting of an ID, vector(s), and payload
- **Payload**: JSON metadata attached to each point, enabling rich filtering
- **Segment**: An on-disk data management unit that Qdrant auto-optimizes over time
- **Shard**: A partition for horizontal scaling across multiple nodes

## Generating Embeddings with Gemini Embedding API

### Choosing the Right Embedding Model

Gemini API offers several embedding models tailored to different needs:

- **`text-embedding-004`**: General-purpose text embeddings (768 dimensions). Best for RAG.
- **`gemini-embedding-exp-03-07`**: Experimental model with state-of-the-art accuracy
- **`embedding-001`**: Legacy model (768 dimensions, backward compatible)

This guide uses `text-embedding-004` for its stability and strong RAG performance.

### Implementing the Embedder Class

```python
import os
import time
from typing import Optional
import google.generativeai as genai
from dotenv import load_dotenv

load_dotenv()
genai.configure(api_key=os.getenv("GEMINI_API_KEY"))

class GeminiEmbedder:
    """Wrapper around the Gemini Embedding API."""

    def __init__(self, model: str = "text-embedding-004"):
        self.model = model
        self.dimension = 768  # Output dimension for text-embedding-004

    def embed_text(
        self,
        text: str,
        task_type: str = "RETRIEVAL_DOCUMENT"
    ) -> list[float]:
        """
        Convert text to an embedding vector.

        Args:
            text: The text to embed.
            task_type: The task type hint:
                - RETRIEVAL_DOCUMENT: When indexing documents
                - RETRIEVAL_QUERY: When embedding search queries
                - SEMANTIC_SIMILARITY: For similarity comparisons
                - CLASSIFICATION: For classification tasks

        Returns:
            A 768-dimensional list of floats.
        """
        result = genai.embed_content(
            model=self.model,
            content=text,
            task_type=task_type
        )
        return result["embedding"]

    def embed_batch(
        self,
        texts: list[str],
        task_type: str = "RETRIEVAL_DOCUMENT",
        batch_size: int = 100,
        sleep_seconds: float = 0.5
    ) -> list[list[float]]:
        """
        Embed a list of texts in batches, respecting API rate limits.

        Args:
            texts: List of texts to embed.
            batch_size: Number of texts per API call (max 100).
            sleep_seconds: Delay between batches to avoid rate limits.

        Returns:
            List of embedding vectors.
        """
        embeddings = []
        for i in range(0, len(texts), batch_size):
            batch = texts[i:i + batch_size]
            result = genai.embed_content(
                model=self.model,
                content=batch,
                task_type=task_type
            )
            embeddings.extend(result["embedding"])
            if i + batch_size < len(texts):
                time.sleep(sleep_seconds)
        return embeddings

# Quick sanity check
embedder = GeminiEmbedder()
vec = embedder.embed_text("Gemini API is a powerful AI model suite.", task_type="RETRIEVAL_DOCUMENT")
print(f"Dimension: {len(vec)}")
print(f"First 5 values: {vec[:5]}")
# Expected output:
# Dimension: 768
# First 5 values: [-0.023..., 0.041..., ...]
```

## Collection Design and Index Optimization

### Designing for Hybrid Search

A hybrid search collection requires defining **two vector spaces** — one for dense vectors and one for sparse vectors.

```python
from qdrant_client import QdrantClient
from qdrant_client.models import (
    Distance,
    VectorParams,
    SparseVectorParams,
    SparseIndexParams,
    HnswConfigDiff,
    OptimizersConfigDiff,
    ScalarQuantizationConfig,
    ScalarType,
    QuantizationConfig,
)

def create_hybrid_collection(
    client: QdrantClient,
    collection_name: str,
    dense_dimension: int = 768,
):
    """
    Create a Qdrant collection optimized for hybrid search.

    Args:
        collection_name: Name of the collection to create.
        dense_dimension: Dimension of dense vectors (768 for text-embedding-004).
    """
    client.create_collection(
        collection_name=collection_name,
        vectors_config={
            # Dense vector: semantic similarity via Gemini embeddings
            "dense": VectorParams(
                size=dense_dimension,
                distance=Distance.COSINE,
                hnsw_config=HnswConfigDiff(
                    m=16,             # Graph connectivity (precision vs. speed trade-off)
                    ef_construct=100, # Search width during index construction
                ),
                quantization_config=QuantizationConfig(
                    scalar=ScalarQuantizationConfig(
                        type=ScalarType.INT8,  # 4× memory reduction with minimal accuracy loss
                        quantile=0.99,
                        always_ram=True,  # Keep quantized vectors in RAM
                    )
                ),
            )
        },
        # Sparse vector: keyword matching (BM25/SPLADE)
        sparse_vectors_config={
            "sparse": SparseVectorParams(
                index=SparseIndexParams(
                    on_disk=False,  # Keep in RAM for fast access
                )
            )
        },
        optimizers_config=OptimizersConfigDiff(
            indexing_threshold=20000,  # Build HNSW index after this many points
            memmap_threshold=50000,    # Switch to memory-mapped files at this size
        ),
    )
    print(f"✅ Collection '{collection_name}' created")
    print(f"   Dense: {dense_dimension}D, COSINE, INT8 quantized")
    print(f"   Sparse: dynamic dims, keyword matching")

# Create the collection
client = QdrantClient(url="http://localhost:6333")
create_hybrid_collection(client, "knowledge_base")
```

### Setting Up Payload Indexes for Fast Filtering

Without payload indexes, every filter requires a full collection scan. Add indexes for fields you'll filter on:

```python
from qdrant_client.models import PayloadSchemaType

def setup_payload_indexes(client: QdrantClient, collection_name: str):
    """Set up payload indexes to enable fast filtered search."""

    # Keyword index for category-based filtering
    client.create_payload_index(
        collection_name=collection_name,
        field_name="category",
        field_schema=PayloadSchemaType.KEYWORD,
    )

    # Integer index for date range filtering
    client.create_payload_index(
        collection_name=collection_name,
        field_name="created_at",
        field_schema=PayloadSchemaType.INTEGER,
    )

    # Full-text index for title search
    client.create_payload_index(
        collection_name=collection_name,
        field_name="title",
        field_schema=PayloadSchemaType.TEXT,
    )

    print("✅ Payload indexes configured")

setup_payload_indexes(client, "knowledge_base")
```

## Indexing Documents and Implementing Hybrid Search

### Generating Sparse Vectors (BM25)

Sparse vectors capture keyword-level features. We use a BM25 encoder from the `fastembed` library:

```python
from qdrant_client.models import PointStruct, SparseVector
import uuid
from fastembed import SparseTextEmbedding

# Initialize BM25 encoder (downloads model on first run)
sparse_encoder = SparseTextEmbedding(model_name="Qdrant/bm25")

def encode_sparse(text: str) -> SparseVector:
    """Encode text as a BM25 sparse vector."""
    result = list(sparse_encoder.embed([text]))[0]
    return SparseVector(
        indices=result.indices.tolist(),
        values=result.values.tolist(),
    )

class DocumentIndexer:
    """Manages document indexing into Qdrant."""

    def __init__(
        self,
        qdrant_client: QdrantClient,
        embedder: GeminiEmbedder,
        collection_name: str,
    ):
        self.client = qdrant_client
        self.embedder = embedder
        self.collection_name = collection_name

    def index_documents(
        self,
        documents: list[dict],
        batch_size: int = 50,
    ) -> int:
        """
        Index a list of documents into Qdrant.

        Args:
            documents: List of dicts with keys: text, title, category, created_at, source_url.
            batch_size: Number of documents per upsert batch.

        Returns:
            Total number of indexed documents.
        """
        total_indexed = 0

        for i in range(0, len(documents), batch_size):
            batch = documents[i:i + batch_size]
            texts = [doc["text"] for doc in batch]

            # Generate dense embeddings for the batch
            dense_embeddings = self.embedder.embed_batch(
                texts, task_type="RETRIEVAL_DOCUMENT"
            )

            # Build point structs
            points = []
            for doc, dense_vec in zip(batch, dense_embeddings):
                sparse_vec = encode_sparse(doc["text"])
                point = PointStruct(
                    id=str(uuid.uuid4()),
                    vector={
                        "dense": dense_vec,
                        "sparse": sparse_vec,
                    },
                    payload={
                        "text": doc["text"],
                        "title": doc.get("title", ""),
                        "category": doc.get("category", "general"),
                        "created_at": doc.get("created_at", 0),
                        "source_url": doc.get("source_url", ""),
                    }
                )
                points.append(point)

            self.client.upsert(
                collection_name=self.collection_name,
                points=points,
                wait=True,
            )
            total_indexed += len(batch)
            print(f"  Indexed: {total_indexed}/{len(documents)}")

        return total_indexed

# Example usage
documents = [
    {
        "text": "Gemini 2.5 Pro is Google's most advanced multimodal AI model, supporting up to 1 million token context windows and excelling at complex reasoning tasks.",
        "title": "Overview of Gemini 2.5 Pro",
        "category": "gemini",
        "created_at": 1743000000,
        "source_url": "https://blog.google/technology/ai/gemini-2-5-pro",
    },
    {
        "text": "Qdrant is a high-performance vector database built in Rust. It natively supports hybrid search and is widely regarded as one of the best choices for production RAG systems.",
        "title": "Why Choose Qdrant",
        "category": "database",
        "created_at": 1743000001,
        "source_url": "https://qdrant.tech/documentation",
    },
]

indexer = DocumentIndexer(client, embedder, "knowledge_base")
count = indexer.index_documents(documents)
print(f"✅ Indexed {count} documents")
```

## Hybrid Search with RRF Score Fusion

### Reciprocal Rank Fusion (RRF) for Result Merging

Hybrid search runs two retrieval passes — dense and sparse — and merges the results using **Reciprocal Rank Fusion (RRF)**. RRF computes a blended score based on each result's rank in each pass, giving you a ranked list that reflects both semantic and lexical relevance.

```python
from qdrant_client.models import (
    FusionQuery,
    Fusion,
    Prefetch,
    Filter,
    FieldCondition,
    MatchValue,
    Range,
)

class HybridSearchEngine:
    """Hybrid search engine powered by Qdrant and Gemini embeddings."""

    def __init__(
        self,
        qdrant_client: QdrantClient,
        embedder: GeminiEmbedder,
        collection_name: str,
    ):
        self.client = qdrant_client
        self.embedder = embedder
        self.collection_name = collection_name

    def search(
        self,
        query: str,
        top_k: int = 5,
        category_filter: Optional[str] = None,
        min_date: Optional[int] = None,
        score_threshold: float = 0.0,
    ) -> list[dict]:
        """
        Run a hybrid search query with RRF score fusion.

        Args:
            query: The user's search query.
            top_k: Number of results to return.
            category_filter: Restrict results to this category (None = all).
            min_date: Minimum creation timestamp (Unix epoch).
            score_threshold: Minimum score; lower results are discarded.

        Returns:
            A list of result dicts with id, score, text, title, category, source_url.
        """
        # Vectorize the query
        dense_query = self.embedder.embed_text(query, task_type="RETRIEVAL_QUERY")
        sparse_query = encode_sparse(query)

        # Build filter conditions
        filter_conditions = []
        if category_filter:
            filter_conditions.append(
                FieldCondition(key="category", match=MatchValue(value=category_filter))
            )
        if min_date:
            filter_conditions.append(
                FieldCondition(key="created_at", range=Range(gte=min_date))
            )

        query_filter = (
            Filter(must=filter_conditions) if filter_conditions else None
        )

        # Execute hybrid search with RRF fusion
        results = self.client.query_points(
            collection_name=self.collection_name,
            prefetch=[
                # Pass 1: dense (semantic) search
                Prefetch(
                    query=dense_query,
                    using="dense",
                    limit=top_k * 3,  # Over-fetch for better RRF merging
                    filter=query_filter,
                ),
                # Pass 2: sparse (keyword) search
                Prefetch(
                    query=SparseVector(
                        indices=sparse_query.indices,
                        values=sparse_query.values,
                    ),
                    using="sparse",
                    limit=top_k * 3,
                    filter=query_filter,
                ),
            ],
            query=FusionQuery(fusion=Fusion.RRF),
            limit=top_k,
            score_threshold=score_threshold,
            with_payload=True,
        )

        return [
            {
                "id": str(point.id),
                "score": point.score,
                "text": point.payload.get("text", ""),
                "title": point.payload.get("title", ""),
                "category": point.payload.get("category", ""),
                "source_url": point.payload.get("source_url", ""),
            }
            for point in results.points
        ]

# Example search
search_engine = HybridSearchEngine(client, embedder, "knowledge_base")

results = search_engine.search(
    query="How do I implement vector search with Gemini API?",
    top_k=5,
)

for i, result in enumerate(results, 1):
    print(f"\n--- Result {i} (score: {result['score']:.4f}) ---")
    print(f"Title: {result['title']}")
    print(f"Text:  {result['text'][:100]}...")
```

## Integrating into a RAG Pipeline

### Generating Answers with Gemini API

Pass the retrieved context to Gemini API to generate grounded, accurate answers:

```python
import google.generativeai as genai

class HybridRAGSystem:
    """Production-ready RAG system powered by Gemini API and Qdrant hybrid search."""

    def __init__(
        self,
        search_engine: HybridSearchEngine,
        model_name: str = "gemini-2.5-pro",
    ):
        self.search_engine = search_engine
        self.model = genai.GenerativeModel(model_name)

    def answer(
        self,
        question: str,
        top_k: int = 5,
        category_filter: Optional[str] = None,
        temperature: float = 0.1,  # Low temperature for factual, stable answers
    ) -> dict:
        """
        Answer a question using hybrid RAG.

        Args:
            question: The user's question.
            top_k: Number of documents to retrieve.
            category_filter: Optional category filter.
            temperature: Generation temperature.

        Returns:
            Dict with 'answer' (str) and 'sources' (list).
        """
        # Step 1: Retrieve context via hybrid search
        search_results = self.search_engine.search(
            query=question,
            top_k=top_k,
            category_filter=category_filter,
        )

        if not search_results:
            return {
                "answer": "No relevant information found in the knowledge base.",
                "sources": [],
            }

        # Step 2: Build the context block
        context_parts = []
        for i, result in enumerate(search_results, 1):
            context_parts.append(
                f"[Document {i}] {result['title']}\n{result['text']}"
            )
        context = "\n\n".join(context_parts)

        # Step 3: Prompt Gemini to generate a grounded answer
        prompt = f"""Answer the question based solely on the provided documents.
If the answer is not contained in the documents, say "This information is not available in the provided documents."

[Reference Documents]
{context}

[Question]
{question}

[Answer]"""

        response = self.model.generate_content(
            prompt,
            generation_config={
                "temperature": temperature,
                "max_output_tokens": 1024,
            }
        )

        return {
            "answer": response.text,
            "sources": [
                {
                    "title": r["title"],
                    "score": r["score"],
                    "url": r["source_url"],
                }
                for r in search_results
            ],
        }

# Usage example
rag = HybridRAGSystem(search_engine)
result = rag.answer("What makes Qdrant a good choice for production RAG?")

print(f"Answer:\n{result['answer']}")
print(f"\nSources:")
for source in result["sources"]:
    print(f"  - {source['title']} (score: {source['score']:.4f})")
```

```python
            collection_name=collection_name,

        return True
    except Exception as e:
        logger.error(f"Qdrant health check FAILED: {e}")
        return False
```

## Performance Tuning and Cost Optimization

### Quantization to Reduce Memory Footprint

```python
from qdrant_client.models import SearchParams, QuantizationSearchParams

# INT8 quantization cuts memory usage by 4× with minimal accuracy loss.
# Use oversampling + rescoring to recover most of the lost precision.
search_params = SearchParams(
    quantization=QuantizationSearchParams(
        ignore=False,
        rescore=True,     # Re-rank using original full-precision vectors
        oversampling=2.0, # Fetch 2× candidates before rescoring
    )
)
```

### Caching Gemini API Embeddings

Query embeddings are often repeated — caching them dramatically reduces API costs:

```python
import hashlib

# In-memory cache (swap for Redis in production)
embedding_cache: dict[str, list[float]] = {}

def embed_with_cache(
    embedder: GeminiEmbedder,
    text: str,
    task_type: str = "RETRIEVAL_QUERY"
) -> list[float]:
    """
    Cache embedding calls to reduce Gemini API costs.
    Search queries are often repeated, making this especially effective.
    """
    cache_key = hashlib.md5(f"{text}:{task_type}".encode()).hexdigest()
    if cache_key not in embedding_cache:
        embedding_cache[cache_key] = embedder.embed_text(text, task_type)
    return embedding_cache[cache_key]

# Estimated costs (April 2026):
# text-embedding-004: ~$0.00001 per 1,000 characters
# 1M documents @ 500 chars each = ~$5 to index
# 10K search queries (no cache) = ~$0.05
# Monthly operational cost estimate: $7–15/month for most use cases
```

## Summary

In this guide, we built a complete production-ready hybrid RAG system using Gemini API and Qdrant — from local setup to cloud deployment.

Key takeaways:

- **Collection design**: Define separate dense (768D) and sparse vector spaces. Add payload indexes upfront for fast, filtered retrieval.
- **Hybrid search with RRF**: Combining semantic and keyword retrieval via Reciprocal Rank Fusion consistently outperforms either approach alone.
- **Quantization**: INT8 quantization cuts memory usage by 4× with minimal accuracy loss. Use oversampling + rescoring to maintain quality.
- **Cost optimization**: Cache embedding API calls — especially for search queries, which are often repeated.
- **Production deployment**: Qdrant Cloud removes infrastructure overhead. Pair it with health checks and structured logging from day one.

The quality of your RAG system is ultimately bounded by the quality of your retrieval layer. Combining Qdrant's hybrid search with Gemini Embedding API gives you a retrieval foundation that's both accurate and fast enough for demanding production workloads. Start with a local prototype, benchmark retrieval quality, then promote to cloud when you're ready.
