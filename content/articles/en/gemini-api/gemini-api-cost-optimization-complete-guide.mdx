## Pillar 1: Context Caching Mastery

Context Cache lets you send long text once to Gemini, then **reuse it across multiple requests** at 50% cost.

### Ideal Use Cases

- Long document Q&A (manuals, papers, books)
- Policy and rulebook lookups
- Codebase review and analysis
- Research database queries
- Customer knowledge base search

### Cost Savings Example

A 100-page company handbook (≈100K tokens) with 100 daily user queries:

**Without caching**:
- ¥0.15 × 1M tokens × 100 users/day = ¥15,000/day

**With Context Cache**:
- Cache creation (once): ¥0.15 × 1M = ¥150
- Cache reuse (99 queries): ¥0.075 × 1M × 99 = ¥742.50
- Daily total: ¥892.50
- **Savings: 94%**

### Implementation: Context Caching in Python

```python
import anthropic
import time

client = anthropic.Anthropic(api_key="YOUR_GEMINI_API_KEY")

# Long context (e.g., company handbook)
long_context = """
# Company Handbook 2026

## Vacation Policy
- 20 paid days off annually
- 5+ consecutive days requires 30-day advance notice

## Business Travel
- Domestic: no approval needed (report after)
- International: apply 30 days ahead

## Remote Work
- Up to 3 days/week from home
- 1 office day/month mandatory

... (thousands of lines of documentation)
"""

def create_context_cache():
    """Initialize Context Cache on first request"""
    response = client.messages.create(
        model="gemini-2.0-pro",
        max_tokens=1000,
        system=[
            {
                "type": "text",
                "text": "You are a company policy assistant.",
            },
            {
                "type": "text",
                "text": long_context,
                "cache_control": {"type": "ephemeral"}  # Enable Context Caching
            }
        ],
        messages=[
            {
                "role": "user",
                "content": "How many remote work days per week?"
            }
        ]
    )

    print(f"First request (cache creation)")
    print(f"Input tokens: {response.usage.input_tokens}")
    print(f"Cache creation tokens: {response.usage.cache_creation_input_tokens}")
    cost = (response.usage.input_tokens * 0.00015) + (response.usage.cache_creation_input_tokens * 0.00015)
    print(f"Cost: ¥{cost}\n")
    print(f"Response: {response.content[0].text}\n")

def query_cached_context():
    """Reuse cached context (50% discount applies)"""
    response = client.messages.create(
        model="gemini-2.0-pro",
        max_tokens=1000,
        system=[
            {
                "type": "text",
                "text": "You are a company policy assistant.",
            },
            {
                "type": "text",
                "text": long_context,
                "cache_control": {"type": "ephemeral"}  # Same declaration
            }
        ],
        messages=[
            {
                "role": "user",
                "content": "How many days advance notice for international travel?"
            }
        ]
    )

    print(f"Second request (cache reuse)")
    print(f"Input tokens: {response.usage.input_tokens}")
    print(f"Cache read tokens (50% discount): {response.usage.cache_read_input_tokens}")
    cost = (response.usage.input_tokens * 0.00015) + (response.usage.cache_read_input_tokens * 0.000075)
    print(f"Cost: ¥{cost}\n")
    print(f"Response: {response.content[0].text}")

# Execute
create_context_cache()
time.sleep(2)
query_cached_context()
```

Running this code shows how the first request creates the cache, and subsequent requests reuse it at 50% cost.

## Pillar 2: Smart Model Routing

Gemini offers three models—selecting the **right one per task** saves 40–60% in costs.

### Model Selection Rules

- **Flash**: Q&A, summarization, text generation (70% of tasks)
- **Pro**: Complex reasoning, code generation, multi-step analysis (20%)
- **Ultra**: Only when maximum quality is non-negotiable (10% or less)

### Implementation: Auto-Routing by Complexity

```python
import anthropic

client = anthropic.Anthropic(api_key="YOUR_GEMINI_API_KEY")

def detect_query_complexity(user_query: str) -> str:
    """Analyze query and select optimal model"""

    simple_keywords = ["weather", "date", "simple", "what is"]
    complex_keywords = ["why", "analyze", "compare", "complex"]
    ultra_keywords = ["paper summary", "legal analysis", "medical diagnosis"]

    query_lower = user_query.lower()

    if any(kw in query_lower for kw in ultra_keywords):
        return "gemini-2.0-pro-exp"  # Ultra
    elif any(kw in query_lower for kw in complex_keywords):
        return "gemini-2.0-pro"  # Pro
    else:
        return "gemini-2.0-flash"  # Flash

def query_with_auto_routing(user_query: str):
    """Auto-select model based on task complexity"""

    selected_model = detect_query_complexity(user_query)

    response = client.messages.create(
        model=selected_model,
        max_tokens=1000,
        messages=[
            {
                "role": "user",
                "content": user_query
            }
        ]
    )

    # Cost calculation
    model_prices = {
        "gemini-2.0-flash": {"input": 0.000075, "output": 0.0003},
        "gemini-2.0-pro": {"input": 0.00015, "output": 0.0006},
        "gemini-2.0-pro-exp": {"input": 0.0015, "output": 0.0045}
    }

    prices = model_prices[selected_model]
    cost = (response.usage.input_tokens * prices["input"]) + (response.usage.output_tokens * prices["output"])

    return {
        "model": selected_model,
        "response": response.content[0].text,
        "cost": cost
    }

# Test
queries = [
    "What is the weather today?",
    "Compare GPT-4, Claude, and Gemini across 10 dimensions",
    "Extract key findings from this medical paper"
]

for query in queries:
    result = query_with_auto_routing(query)
    print(f"Query: {query}")
    print(f"Model selected: {result['model']}")
    print(f"Cost: ¥{result['cost']:.4f}\n")
```

By routing simple queries to Flash (¥0.30/request) and complex ones to Pro (¥0.60/request), **average cost per request drops 40%**.

## Pillar 3: Batch Processing for 50% Savings

The Batch API processes requests asynchronously and offers a **50% discount** for non-urgent work.

### When to Use Batch

- Daily email response summarization (100+ emails)
- Async customer inquiry handling
- Nightly log analysis
- Weekly data analytics reports

### Implementation: Batch Processing Setup

```python
import anthropic
import time

client = anthropic.Anthropic(api_key="YOUR_GEMINI_API_KEY")

def submit_batch_job(queries: list[str]):
    """Submit multiple queries to Batch API"""

    requests = []
    for idx, query in enumerate(queries):
        requests.append({
            "custom_id": f"query-{idx}",
            "params": {
                "model": "gemini-2.0-flash",
                "messages": [
                    {
                        "role": "user",
                        "content": query
                    }
                ],
                "max_tokens": 1000
            }
        })

    batch = client.beta.batch.submit(requests)

    print(f"Batch job ID: {batch.id}")
    print(f"Requests queued: {len(requests)}")
    print(f"Discount: 50% (half the usual cost)\n")

    return batch.id

def wait_for_batch(batch_id: str):
    """Poll for batch completion"""

    while True:
        batch = client.beta.batch.retrieve(batch_id)
        print(f"Status: {batch.status}")
        print(f"Completed: {batch.request_counts.completed}, Processing: {batch.request_counts.processing}\n")

        if batch.status == "completed":
            return batch

        time.sleep(10)

def get_batch_results(batch_id: str):
    """Retrieve batch results"""

    batch = client.beta.batch.retrieve(batch_id)

    if batch.status != "completed":
        print(f"Batch not ready: {batch.status}")
        return

    results = client.beta.batch.results(batch_id)

    for result in results:
        print(f"ID: {result.custom_id}")
        print(f"Response: {result.result.message.content[0].text}")
        print(f"Tokens: Input {result.result.usage.input_tokens}, Output {result.result.usage.output_tokens}\n")

# Test batch processing
queries = [
    "Summarize Gemini API key features",
    "Best practices for cloud API implementation",
    "5 techniques to cut AI costs by 50%"
]

batch_id = submit_batch_job(queries)
batch = wait_for_batch(batch_id)
get_batch_results(batch_id)
```

**Cost Comparison**:
- Real-time processing (100 emails): ¥15,000
- Batch processing (100 emails): ¥7,500 (50% savings)

## Pillar 4: Token Optimization Techniques

Reducing input tokens dramatically cuts costs—even without changing functionality.

### Technique 1: Streamline System Instructions

```python
# Inefficient (verbose)
system_instruction_long = """
You are a customer service representative. Reply to customer emails following these rules:
1. Use polite language
2. Understand the problem clearly
3. Suggest a solution
4. Provide a follow-up schedule
...(100+ lines)
"""

# Efficient (concise, same functionality)
system_instruction_short = """
Customer service rep: polite reply, understand → solve → schedule follow-up.
"""

# Token cost comparison
def estimate_tokens(text: str) -> int:
    return len(text) // 4  # 1 word ≈ 4 chars

long_tokens = estimate_tokens(system_instruction_long)
short_tokens = estimate_tokens(system_instruction_short)

print(f"Long version: {long_tokens} tokens (¥{long_tokens * 0.00015:.4f})")
print(f"Short version: {short_tokens} tokens (¥{short_tokens * 0.00015:.4f})")
print(f"Savings: {((long_tokens - short_tokens) / long_tokens) * 100:.1f}%")
```

Shorter instructions often result in **faster responses and fewer output tokens**—a win-win.

### Technique 2: Structured Output for Efficiency

JSON output prevents unnecessary text generation:

```python
import anthropic
import json

# Unstructured (wasteful)
unstructured = """
The customer email is about a shipping delay. They are quite upset and demand immediate resolution.
The priority is high. Contact them immediately.
"""

# Structured (efficient)
structured = {
    "issue": "shipping_delay",
    "sentiment": "upset",
    "priority": "high",
    "action": "immediate_contact"

print(f"Unstructured: {len(unstructured)} chars")
print(f"Structured: {len(json.dumps(structured))} chars")
print(f"Savings: {(1 - len(json.dumps(structured)) / len(unstructured)) * 100:.1f}%")
```

## Pillar 5: Cost Dashboard and Monitoring

**Visibility drives optimization.** A cost dashboard helps your team identify inefficiencies naturally.

### Python Dashboard with Plotly

```python
import json
from datetime import datetime, timedelta
import anthropic
import plotly.graph_objects as go

api_call_log = []

def log_api_call(model: str, input_tokens: int, output_tokens: int, cache_tokens: int = 0):
    """Record API call for analysis"""
    api_call_log.append({
        "timestamp": datetime.now().isoformat(),
        "model": model,
        "input_tokens": input_tokens,
        "output_tokens": output_tokens,
        "cache_tokens": cache_tokens
    })

def calculate_cost(model: str, input_tokens: int, output_tokens: int, cache_tokens: int) -> float:
    """Calculate cost by model"""
    prices = {
        "gemini-2.0-flash": {"input": 0.000075, "output": 0.0003, "cache": 0.0000375},
        "gemini-2.0-pro": {"input": 0.00015, "output": 0.0006, "cache": 0.000075},
        "gemini-2.0-pro-exp": {"input": 0.0015, "output": 0.0045, "cache": 0.00075}
    }

    if model not in prices:
        model = "gemini-2.0-flash"

    price = prices[model]
    return (input_tokens * price["input"]) + (output_tokens * price["output"]) + (cache_tokens * price["cache"])

def create_dashboard():
    """Generate Plotly dashboard"""

    models = ["gemini-2.0-flash", "gemini-2.0-pro", "gemini-2.0-pro-exp"]
    daily_costs = {}

    for day in range(30):
        date = (datetime.now() - timedelta(days=day)).date()
        daily_costs[str(date)] = sum(
            calculate_cost(log["model"], log["input_tokens"], log["output_tokens"], log["cache_tokens"])
            for log in api_call_log
            if log["timestamp"][:10] == str(date)
        )

    dates = sorted(daily_costs.keys())
    costs = [daily_costs[d] for d in dates]

    fig = go.Figure()
    fig.add_trace(go.Scatter(x=dates, y=costs, mode='lines+markers', name='Daily Cost'))
    fig.update_layout(title="Gemini API Cost Trend", xaxis_title="Date", yaxis_title="Cost (¥)")
    fig.write_html("gemini_cost_dashboard.html")
    print("Dashboard saved to gemini_cost_dashboard.html")

# Log sample data
for i in range(50):
    log_api_call("gemini-2.0-flash", 1000, 500, cache_tokens=200)
    log_api_call("gemini-2.0-pro", 2000, 800)

create_dashboard()
```

This dashboard reveals:
- Daily costs by model
- Cache effectiveness
- Cost trends and anomalies

## Common Pitfalls and Solutions

### Pitfall 1: Cache Miss Rates

**Problem**: Context Cache enabled but only 10% hit rate

**Cause**: Cache expires after 1 hour; queries spaced too far apart

**Solution**: Batch similar queries within the 1-hour window

### Pitfall 2: Quality Degradation from Model Switch

**Problem**: Flash output quality drops vs. Pro

**Cause**: System instructions missing critical context

**Solution**: Use structured JSON instructions (smaller, clearer)

### Pitfall 3: Batch Processing Delays

**Problem**: Batch takes 1–2 hours; users want realtime

**Cause**: Batch API is inherently asynchronous

**Solution**: Use realtime API for interactive features, batch only for async reports
