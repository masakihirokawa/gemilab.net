You've uploaded a PDF or video to the Gemini Files API, passed the URI to your model, and hit an error. The response is empty, the file stays in `PROCESSING` forever, or you get a cryptic `404 NOT_FOUND` the next day. Sound familiar?

The Files API is a powerful tool for multimodal processing—but it has a distinct two-phase lifecycle that trips up most developers on their first implementation. Once you internalize how state transitions work and where the limits lie, these errors become easy to prevent and diagnose.

This guide walks through every common failure mode, with code that actually works.

## Understanding the Files API Lifecycle

Before diving into specific errors, it helps to understand the fundamental pattern: uploading a file and using it in a `generate_content` call are **two separate operations**, and there's a mandatory waiting period between them.

```python
import google.generativeai as genai
import time

genai.configure(api_key="YOUR_API_KEY")

# Phase 1: Upload the file
uploaded_file = genai.upload_file(path="document.pdf", mime_type="application/pdf")
print(f"Upload complete: {uploaded_file.name}, state: {uploaded_file.state.name}")

# Phase 2: Wait until ACTIVE — skipping this causes failures
while uploaded_file.state.name == "PROCESSING":
    time.sleep(2)
    uploaded_file = genai.get_file(uploaded_file.name)
    print(f"Current state: {uploaded_file.state.name}")

if uploaded_file.state.name == "FAILED":
    raise ValueError(f"File processing failed: {uploaded_file.name}")

# Phase 3: Use in generation
model = genai.GenerativeModel("gemini-2.5-pro")
response = model.generate_content([
    uploaded_file,
    "Summarize the key points in this document."
])
print(response.text)
```

Calling `generate_content` while a file is still in `PROCESSING` is the single most common mistake. The fix is always a polling loop—but a naive loop without backoff has its own problems.

## Fixing the PROCESSING Loop That Never Ends

Large video files can take several minutes to process. A tight polling loop (checking every second) can trigger rate limits before your file is ready. Use adaptive backoff instead:

```python
import google.generativeai as genai
import time

def wait_for_file_active(file, max_wait_seconds=300):
    """Poll until a file reaches ACTIVE state, with adaptive backoff."""
    elapsed = 0
    interval = 5  # start at 5 seconds

    while file.state.name == "PROCESSING":
        if elapsed >= max_wait_seconds:
            raise TimeoutError(
                f"File processing timed out after {max_wait_seconds}s: {file.name}"
            )
        print(f"Processing... {elapsed}s elapsed (state: {file.state.name})")
        time.sleep(interval)
        elapsed += interval
        interval = min(interval * 1.5, 30)  # cap at 30 seconds
        file = genai.get_file(file.name)

    if file.state.name \!= "ACTIVE":
        raise ValueError(f"File did not reach ACTIVE: current state = {file.state.name}")

    print(f"File ready: {file.name}")
    return file

# Usage
uploaded = genai.upload_file("long_video.mp4", mime_type="video/mp4")
active_file = wait_for_file_active(uploaded, max_wait_seconds=600)
```

For hour-long videos, 10–15 minutes of processing time is not unusual. Set `max_wait_seconds` generously for large media files.

## MIME Type Errors and Unsupported Formats

Omitting `mime_type` works in most cases, but auto-detection fails for files with incorrect extensions or unusual formats. Always specify it explicitly in production code.

```python
# ❌ Risky: relies on auto-detection
uploaded = genai.upload_file("scan.pdf")

# ✅ Reliable: explicit MIME type
uploaded = genai.upload_file("scan.pdf", mime_type="application/pdf")
```

The Files API supports these MIME types natively:

- **Images**: `image/jpeg`, `image/png`, `image/webp`, `image/heic`, `image/heif`
- **Video**: `video/mp4`, `video/mpeg`, `video/mov`, `video/webm`
- **Audio**: `audio/mp3`, `audio/wav`, `audio/aac`, `audio/flac`
- **Documents**: `application/pdf`
- **Text**: `text/plain`, `text/html`, `text/csv`, `text/xml`

A common gotcha: **Word (`.docx`) and Excel (`.xlsx`) files are not supported**. If you need to process them, either export to PDF first or extract the text content and pass it as `text/plain`.

## File Size Limits: When to Use Files API vs. Inline Data

There are two separate size limits to be aware of:

- **Inline data limit**: 20 MB (per request)
- **Files API upload limit**: 2 GB

For small images under 20 MB, you can skip the Files API entirely and send data directly. For anything larger, Files API is required. Files over 2 GB need to be compressed or split.

```python
import os
import google.generativeai as genai

def upload_file_auto(path: str, mime_type: str):
    """Automatically choose inline vs Files API based on file size."""
    size = os.path.getsize(path)
    inline_limit = 20 * 1024 * 1024     # 20 MB
    files_api_limit = 2 * 1024 * 1024 * 1024  # 2 GB

    if size > files_api_limit:
        raise ValueError(
            f"File exceeds 2 GB limit ({size / 1e9:.1f} GB). "
            "Compress or split the file before uploading."
        )

    if size > inline_limit:
        print(f"Using Files API ({size / 1e6:.1f} MB)")
        return ("file", genai.upload_file(path, mime_type=mime_type))
    else:
        print(f"Using inline data ({size / 1e6:.1f} MB)")
        with open(path, "rb") as f:
            return ("inline", {"mime_type": mime_type, "data": f.read()})
```

## NOT_FOUND Errors from Expired Files

Files uploaded via the Files API are automatically deleted after **48 hours**. This creates a subtle class of bug: your code works fine in development, but the next day—or in a nightly batch job—it throws a `404`.

```
google.api_core.exceptions.NotFound: 404 File not found: files/xxxxxxxx
```

The fix is to detect expired files and re-upload automatically:

```python
import google.generativeai as genai

def get_or_reupload(file_name: str, local_path: str, mime_type: str):
    """Return a valid file reference, re-uploading if the original expired."""
    try:
        file = genai.get_file(file_name)
        if file.state.name == "ACTIVE":
            print(f"Reusing existing file: {file_name}")
            return file
    except Exception:
        pass  # File not found or expired

    print(f"Re-uploading file: {local_path}")
    return genai.upload_file(local_path, mime_type=mime_type)
```

For long-running applications, store the `file.name` (e.g., `files/abc123`) in your database alongside a timestamp. Before each use, check whether 48 hours have elapsed and re-upload if necessary.

## Managing Costs: Preventing Token Overruns with Video

Video processing is token-intensive. Gemini charges approximately **258 tokens per second** of video, which means a 1-hour video consumes roughly 930,000 tokens per generation call. Accidentally looping over the same video multiple times can spike costs dramatically.

Three practices to keep costs under control:

**Delete files when you're done.** Don't let unused files linger in the Files API storage.

```python
def safe_delete(file):
    try:
        genai.delete_file(file.name)
        print(f"Deleted: {file.name}")
    except Exception as e:
        print(f"Delete failed (ignored): {e}")
```

**Reuse file references within the 48-hour window.** Save `file.name` after upload and pass it to subsequent calls instead of re-uploading.

**Use frame extraction for video when full playback analysis isn't needed.** If you only need to understand scene content, extracting representative frames as JPEG images and sending them as `image/jpeg` can be 10–100x cheaper than processing the full video.

## Error Code Quick Reference

When a Files API call fails, the HTTP status and reason field narrow down the cause quickly:

- **400 INVALID_ARGUMENT** — Wrong or unsupported MIME type. Check your `mime_type` parameter and refer to the supported formats list above.
- **403 PERMISSION_DENIED** — The API key lacks Files API permissions, or the key is invalid. Verify the key in Google AI Studio.
- **404 NOT_FOUND** — The file has expired (past 48 hours) or was never successfully uploaded. Re-upload.
- **413 REQUEST_TOO_LARGE** — You exceeded the 20 MB inline limit. Switch to Files API.
- **429 RESOURCE_EXHAUSTED** — Rate limit exceeded. Implement exponential backoff with jitter.
- **503 SERVICE_UNAVAILABLE** — Transient service issue. Retry after 30–60 seconds.

The [official Gemini API file prompting documentation](https://ai.google.dev/gemini-api/docs/file-prompting-strategies) covers additional edge cases, including best practices for prompting with different file types.

Once you have the Files API lifecycle internalized—upload → wait for ACTIVE → use → delete—most of these errors disappear. Start with a single PDF or short audio clip to validate your polling loop, then scale up to larger files with confidence.

## Frequently Asked Questions

**Can I upload the same file multiple times?**

Yes, but each upload creates a new file reference with a new expiration timer. If you need to use the same file in multiple sessions or batch jobs, save the `file.name` returned after the first upload and reuse it within 48 hours. Re-uploading the same content unnecessarily adds to your API usage without benefit.

**Why does my file show FAILED state instead of ACTIVE?**

A `FAILED` state typically means the file is corrupted, has an internal format that Gemini cannot parse, or the MIME type you specified doesn't match the actual file content. Try re-exporting the file from its source application, verifying the MIME type, and uploading again. PDFs that contain only scanned images (no text layer) process normally, but may produce lower quality results than text-native PDFs.

**Is there a limit on how many files I can have active at once?**

There is a per-project storage quota for the Files API. While Google has not published a hard numerical limit in the public documentation, best practice is to delete files as soon as you no longer need them. Accumulating thousands of files risks hitting undocumented quota ceilings and complicates any audit of your API usage.

**Why does the same video cost different amounts of tokens each time?**

Video token consumption is based on the number of frames sampled, which depends on both the video duration and the model version. If you are seeing unexpected variance, check whether the video duration is actually consistent and whether a model update may have changed the sampling rate. Logging `response.usage_metadata.total_token_count` on each call helps establish a baseline for cost monitoring.
