When I first made a successful call to the Gemini API from Python, my reaction was something like: "Wait, that's really all it takes?"

Between navigating the official docs, setting up credentials, and finding the right library, it's easy to feel like there are more steps than there actually are. But the truth is, once you have an API key and run one `pip install`, you can have your first working response in about five minutes.

This guide is for developers who are comfortable with Python basics but haven't used the Gemini API before. We'll walk through the `google-genai` library step by step — text generation, multi-turn chat, and streaming — with copy-paste-ready code for each.

## What Is the google-genai Library?

The older `google-generativeai` package has been around for a while, but since 2025, `google-genai` is the officially recommended library. Google rewrote it from the ground up with a cleaner API design, better type hints (your IDE will love you for it), and first-class support for async workflows.

If you have existing code written with `google-generativeai`, the migration is manageable but there are a few syntax differences to watch out for — we cover those in detail in the [google-genai SDK Complete Migration Masterguide](/en/articles/gemini-api/google-genai-python-sdk-complete-migration-masterguide). For everyone starting fresh, though, `google-genai` is the clear choice.

## Setup — Getting Your API Key and Installing the Library

Head over to [Google AI Studio](https://aistudio.google.com) to generate an API key. If you have a Google account, the whole process takes about two minutes. The free tier is generous enough for development and experimentation, so there's no need to add billing information right away. For a breakdown of what the free tier includes and its limits, see [Building Your First Project with Gemini API Free Tier](/en/articles/gemini-api/gemini-api-free-tier-beginner-first-project).

Install the library:

```bash
pip install google-genai
```

Never hardcode your API key directly in your source files — you'll eventually commit it to a repo by accident. Store it as an environment variable instead:

```bash
# Add to your .bashrc, .zshrc, or .env file
export GEMINI_API_KEY="YOUR_API_KEY"
```

On the Python side, read it with `os.environ["GEMINI_API_KEY"]`, or use the `python-dotenv` library if you prefer `.env` files.

## Your First Text Generation Request

With setup out of the way, let's run the simplest possible API call:

```python
import os
from google import genai

# Initialize the client with your API key
client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])

# Send a request to generate text
response = client.models.generate_content(
    model="gemini-2.5-flash",
    contents="List five commonly used Python list operations with brief examples"
)

# Access the response text safely
if response.text:
    print(response.text)
else:
    # This can happen if the safety filter blocks a response
    print("No text in response")
    print("finish_reason:", response.candidates[0].finish_reason)
```

`gemini-2.5-flash` is fast and available in the free tier — a solid default for most tasks. If you need higher quality output, swap in `gemini-2.5-pro`, keeping in mind that it has slightly stricter rate limits on the free tier.

The `if response.text:` guard is worth including from the start. When the safety filter blocks a response, `response.text` comes back as `None`, and you'll want to handle that gracefully rather than hitting an unexpected `AttributeError`.

## Multi-Turn Conversations with Chat Sessions

Once you're past basic generation, the next thing most people want is a back-and-forth conversation — where each reply can reference what was said before:

```python
import os
from google import genai

client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])

# Start a chat session
chat = client.chats.create(model="gemini-2.5-flash")

# First message
response1 = chat.send_message("Explain Python dictionaries to me")
print("Turn 1:")
print(response1.text)

# Second message — the model remembers the context from turn 1
response2 = chat.send_message("Can you show me a practical code example using what you just described?")
print("\nTurn 2:")
print(response2.text)
```

The chat object returned by `client.chats.create()` automatically manages the conversation history for you. That second message — "using what you just described" — works because the library sends the entire prior conversation along with each new message.

One thing to keep in mind: this history lives in memory only. Once your process ends, the conversation is gone. For user-facing apps where you need to persist conversations across sessions, you'll need to save and reload the history from a database or file.

## Streaming Responses in Real Time

For short replies, waiting for the full response to arrive is fine. But for longer generations — think detailed explanations or step-by-step instructions — streaming dramatically improves the experience:

```python
import os
from google import genai

client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])

print("Streaming response:")

# Use generate_content_stream instead of generate_content
for chunk in client.models.generate_content_stream(
    model="gemini-2.5-flash",
    contents="Explain Python's asyncio module in a way that's approachable for beginners"
):
    # Print each chunk as it arrives, without a newline between them
    print(chunk.text, end="", flush=True)

print()  # Final newline after the stream ends
```

The `flush=True` argument bypasses Python's output buffering, so text appears character by character rather than waiting for a full buffer to fill. Run it in your terminal and you'll see the response stream in live.

For production web applications, you'll typically want the async version using `async for chunk in ...`. We go deep on async patterns with the Gemini API in the [Gemini API Python asyncio Complete Guide](/en/articles/gemini-api/gemini-api-python-async-asyncio-guide).

## Three Things That Catch Beginners Off Guard

A few issues come up repeatedly when people first start working with this library. For a full troubleshooting reference, check out [Common Gemini API Errors for Beginners 2026](/en/articles/gemini-api/gemini-api-first-errors-beginners-guide-2026) — but here are the most frequent ones:

**1. Getting the model name wrong.** The model string needs to be exact: `gemini-2.5-flash`, not `gemini25flash` or `gemini_2.5_flash`. When the model name doesn't match, you'll get an error rather than a helpful "did you mean...?" message. Always double-check against the official model list.

**2. Hitting the rate limit (HTTP 429).** The free tier has a cap on requests per minute. If you're running a loop that makes many API calls in quick succession, you'll hit this limit fast. Adding `time.sleep(2)` between requests, or implementing exponential backoff retry logic, keeps things running smoothly.

**3. Using the old import path.** Stack Overflow answers and older tutorials often show `from google.generativeai import GenerativeModel`. That's the old library. With `google-genai`, the correct import is `from google import genai`. Mixing both in the same project will cause confusing errors.
