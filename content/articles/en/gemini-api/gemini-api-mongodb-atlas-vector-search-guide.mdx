## Setup and context — What You Can Build with Gemini API and MongoDB Atlas

RAG (Retrieval-Augmented Generation) is an architecture that lets large language models answer questions by searching external knowledge sources first. It's one of the most cost-effective ways to give an AI access to your own documents, internal knowledge bases, or private data.

In this guide, we'll combine the **Gemini Embedding API** with **MongoDB Atlas Vector Search** to build a simple but functional RAG system. MongoDB Atlas is a familiar choice for many developers, and its Vector Search feature makes it easy to add semantic search to an existing document database — no separate vector database required.

By the end of this guide, you'll know how to:
- Set up MongoDB Atlas Vector Search and configure the index
- Generate vector embeddings from text using the Gemini Embedding API
- Implement semantic search with Python
- Build a document Q&A system that retrieves relevant context before generating answers

This guide is aimed at developers who have some familiarity with Python and the Gemini API and are exploring RAG for the first time.

## How MongoDB Atlas Vector Search Works

MongoDB Atlas Vector Search stores data as high-dimensional vectors (arrays of numbers) and finds similar entries using **cosine similarity** or **Euclidean distance**.

The workflow is straightforward:
1. Convert each document to a vector using the Gemini Embedding API
2. Store those vectors alongside the document text in MongoDB
3. At query time, convert the user's question to a vector using the same model
4. MongoDB finds the documents whose vectors are closest to the query vector — meaning they're semantically similar

### Choosing an Embedding Model

The Gemini Embedding API offers several models:

- **`gemini-embedding-004`** — 768 dimensions, high accuracy, multilingual. Recommended for most use cases
- **`text-embedding-004`** — Lightweight option; useful when cost is a priority
- **`gemini-embedding-exp-03-07`** — Experimental latest model for maximum accuracy

This guide uses `gemini-embedding-004` (768 dimensions).

## Step-by-Step Implementation

### Step 1: Embed Documents and Store Them in MongoDB

```python
import os
import google.generativeai as genai
from pymongo import MongoClient
from dotenv import load_dotenv

load_dotenv()

# Configure Gemini API
genai.configure(api_key=os.environ["GEMINI_API_KEY"])

# Connect to MongoDB
client = MongoClient(os.environ["MONGODB_URI"])
db = client["rag_demo"]
collection = db["documents"]

# Sample documents (replace with your own data)
documents = [
    {
        "title": "Gemini API Overview",
        "content": "The Gemini API is Google's AI API supporting text generation, image understanding, code generation, and many other tasks."
    },
    {
        "title": "What is MongoDB Atlas",
        "content": "MongoDB Atlas is a fully managed cloud database service. Its Vector Search feature enables nearest-neighbor search over high-dimensional vectors."
    },
    {
        "title": "RAG Architecture Basics",
        "content": "RAG (Retrieval-Augmented Generation) combines a retrieval system with an LLM to generate answers grounded in external knowledge sources."
    },
    {
        "title": "Using Gemini Embedding API",
        "content": "The Gemini Embedding API converts text into high-dimensional vectors. Semantically similar texts end up close together in vector space, enabling semantic search."
    },
    {
        "title": "Cost Optimization Tips",
        "content": "To keep API costs low, use embedding caching, batch processing, and avoid redundant API calls wherever possible."
    },
]

def get_embedding(text: str) -> list[float]:
    """Get an embedding vector for a piece of text using the Gemini API."""
    result = genai.embed_content(
        model="models/gemini-embedding-004",
        content=text,
        task_type="retrieval_document"  # Use this task type for documents
    )
    return result["embedding"]

# Generate embeddings and store documents in MongoDB
print("Generating embeddings...")
for doc in documents:
    embedding = get_embedding(doc["content"])
    doc["embedding"] = embedding
    collection.insert_one(doc)
    print(f"Stored: {doc['title']}")

print(f"\n✅ Stored {len(documents)} documents successfully")
```

```
Stored: What is MongoDB Atlas
Stored: RAG Architecture Basics
Stored: Using Gemini Embedding API
Stored: Cost Optimization Tips

✅ Stored 5 documents successfully
```

### Step 2: Create a Vector Search Index in MongoDB Atlas

In the Atlas console:

1. Open your cluster and go to the **Atlas Search** tab
2. Click **Create Search Index** → select **JSON Editor**
3. Paste the following JSON and create the index

```json
{
  "fields": [
    {
      "numDimensions": 768,
      "path": "embedding",
      "similarity": "cosine",
      "type": "vector"
    }
  ]
}
```

Name the index `vector_index`. It may take a few minutes to become active.

### Step 3: Implement Semantic Search

```python
def semantic_search(query: str, top_k: int = 3) -> list[dict]:
    """Find documents that are semantically similar to the query."""

    # Embed the query (use retrieval_query task type for queries)
    query_embedding = genai.embed_content(
        model="models/gemini-embedding-004",
        content=query,
        task_type="retrieval_query"  # Different from document embedding!
    )["embedding"]

    # Atlas Vector Search aggregation pipeline
    pipeline = [
        {
            "$vectorSearch": {
                "index": "vector_index",
                "path": "embedding",
                "queryVector": query_embedding,
                "numCandidates": 50,  # Recommended: 10–20× top_k
                "limit": top_k
            }
        },
        {
            "$project": {
                "_id": 0,
                "title": 1,
                "content": 1,
                "score": {"$meta": "vectorSearchScore"}  # Include similarity score
            }
        }
    ]

    results = list(collection.aggregate(pipeline))
    return results

# Test it
query = "How do I convert text into vectors with AI?"
results = semantic_search(query)

print(f"Query: \"{query}\"\n")
for i, doc in enumerate(results, 1):
    print(f"{i}. {doc['title']} (score: {doc['score']:.4f})")
    print(f"   {doc['content'][:80]}...\n")
```

**Expected output:**
```

1. Using Gemini Embedding API (score: 0.9312)
   The Gemini Embedding API converts text into high-dimensional vectors...

2. Gemini API Overview (score: 0.8891)
   The Gemini API is Google's AI API supporting text generation...
```

### Step 4: Build the Complete Document Q&A System

```python
def answer_question(question: str) -> str:
    """Answer a question using RAG: retrieve relevant docs, then generate a response."""

    # 1. Retrieve relevant documents
    relevant_docs = semantic_search(question, top_k=3)

    if not relevant_docs:
        return "No relevant documents found."

    # 2. Build context from retrieved documents
    context = "\n\n".join([
        f"[{doc['title']}]\n{doc['content']}"
        for doc in relevant_docs
    ])

    # 3. Generate an answer with Gemini
    model = genai.GenerativeModel("gemini-2.5-flash")
    prompt = f"""Answer the question below based only on the provided documents.
If the documents don't contain the answer, say "I don't have that information."

=== Documents ===
{context}

=== Question ===
{question}

=== Answer ==="""

    response = model.generate_content(prompt)
    return response.text

# Try it out
question = "What are the best practices for reducing API costs?"
answer = answer_question(question)
print(f"Q: {question}")
print(f"A: {answer}")
```

## Common Errors and Fixes

### Error 1: `MongoServerError: PlanExecutor error: $vectorSearch`

The Vector Search index hasn't been created yet, or it's still initializing. Check the Atlas console and wait for the index status to show **Active**.

### Error 2: `google.api_core.exceptions.InvalidArgument: 400`

The `task_type` parameter may be wrong. Use `retrieval_document` when embedding documents for storage, and `retrieval_query` when embedding a search query. Mixing them up will reduce search quality.

### Error 3: Dimension mismatch

The `numDimensions` in your index definition must match the model's actual output. `gemini-embedding-004` outputs 768 dimensions. If you switch models, delete and recreate the index with the correct dimension count.

## Advanced Use Cases

### Combining Vector Search with Metadata Filters

MongoDB Atlas Vector Search supports pre-filtering by metadata alongside the vector search. This lets you limit results to a specific category, date range, or any other field:

```python
pipeline = [
    {
        "$vectorSearch": {
            "index": "vector_index",
            "path": "embedding",
            "queryVector": query_embedding,
            "numCandidates": 50,
            "limit": 5,
            "filter": {"category": "technical-docs"}  # Metadata filter
        }
    }
]
```

### Batch Embedding for Cost Efficiency

When processing large volumes of documents, batch your embedding requests to minimize API calls:

```python
def batch_embed(texts: list[str]) -> list[list[float]]:
    """Embed multiple texts in a single API call."""
    result = genai.embed_content(
        model="models/gemini-embedding-004",
        content=texts,  # Pass a list for batch processing
        task_type="retrieval_document"
    )
    return result["embedding"]
```

## Summary

In this guide, we built a functional RAG system using the Gemini Embedding API and MongoDB Atlas Vector Search. Key takeaways:

- Create a Vector Search index in MongoDB Atlas and store Gemini embedding vectors alongside your documents
- Always use the correct **task type** (`retrieval_document` for storage, `retrieval_query` for search) to maximize accuracy
- Use **batch embedding** and **metadata filters** to build scalable, efficient retrieval systems
- If you're already on MongoDB, Vector Search integrates seamlessly with no extra infrastructure
