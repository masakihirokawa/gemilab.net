When building agents with the Gemini API, most developers treat Function Calling and Search Grounding as alternatives — you use one or the other. I used to think the same way, until I realized they solve different problems and actually complement each other well when combined intentionally.

This post covers the design pattern I use to run both capabilities in the same agent loop, with working Python code. The example use case: an agent that researches competitor service pricing in real time and produces a structured report.

## Clarifying the Difference

Before the design, let's be precise about what each capability actually does.

**Function Calling** lets the AI invoke functions you define. Database queries, external API calls, file operations — anything you've explicitly wired up. You control the response structure completely.

**Search Grounding** lets Gemini run Google Search internally when generating a response, using those results as factual grounding. It reduces hallucination, surfaces current information, and cites sources. But how the search results are processed is Gemini's call, not yours.

This difference defines when to use each:

- Need structured data with a predictable schema → Function Calling
- Need current, natural-language information → Search Grounding
- Need both → combine them

## Architecture: A Two-Phase Agent Loop

The design I settled on splits the agent into two distinct phases.

**Phase 1 (Research):** Use Search Grounding to collect current information. Don't worry about structure here — just gather raw, up-to-date content.

**Phase 2 (Extraction/Structuring):** Use Function Calling to convert the Phase 1 output into structured data. No new searches — only transform what you already have.

This separation makes each phase's prompt easier to optimize and keeps the two concerns from interfering with each other.

## Implementation: Phase 1 (Search Grounding for Research)

```python
import google.generativeai as genai
from google.generativeai.types import Tool, GoogleSearchRetrieval

genai.configure(api_key="YOUR_GEMINI_API_KEY")

search_tool = Tool(
    google_search_retrieval=GoogleSearchRetrieval(
        dynamic_retrieval_config={
            "mode": "MODE_DYNAMIC",
            "dynamic_threshold": 0.3  # 0-1: lower = more aggressive search
        }
    )
)

research_model = genai.GenerativeModel(
    model_name="gemini-2.0-flash",
    tools=[search_tool],
    system_instruction="""You are a competitive research specialist.
Collect the latest pricing and feature information for the service the user specifies.
Base your response exclusively on current search results — do not infer or fill in gaps.
Format your findings as structured bullet points to make downstream parsing easier."""
)

def research_phase(service_name: str, focus_area: str) -> str:
    """Phase 1: Search and collect current information."""
    prompt = f"""
    Research the following service:
    Service: {service_name}
    Focus: {focus_area}
    
    Collect and summarize:
    - Pricing plans and costs
    - Key features and capabilities
    - Recent changes or updates
    - Commonly cited strengths and weaknesses in user reviews
    """
    response = research_model.generate_content(prompt)
    return response.text
```

The `dynamic_threshold` value matters. Closer to 0 means more aggressive searching; closer to 1 means relying more on training data. For competitive research where recency matters, 0.3 works well.

## Implementation: Phase 2 (Function Calling for Structuring)

```python
import json
from typing import Any

extraction_tools = [
    {
        "function_declarations": [
            {
                "name": "extract_pricing_data",
                "description": "Extract and structure pricing information from text",
                "parameters": {
                    "type": "object",
                    "properties": {
                        "service_name": {
                            "type": "string",
                            "description": "Name of the service"
                        },
                        "plans": {
                            "type": "array",
                            "items": {
                                "type": "object",
                                "properties": {
                                    "plan_name": {"type": "string"},
                                    "monthly_price_usd": {"type": "number"},
                                    "annual_price_usd": {"type": "number"},
                                    "key_features": {
                                        "type": "array",
                                        "items": {"type": "string"}
                                    }
                                }
                            },
                            "description": "List of pricing plans"
                        },
                        "last_updated": {
                            "type": "string",
                            "description": "Estimated date of information (if available)"
                        },
                        "confidence_level": {
                            "type": "string",
                            "enum": ["high", "medium", "low"],
                            "description": "Data confidence: high=verified from official source, medium=reliable secondary source, low=uncertain"
                        }
                    },
                    "required": ["service_name", "plans", "confidence_level"]
                }
            }
        ]
    }
]

extraction_model = genai.GenerativeModel(
    model_name="gemini-2.0-flash",
    tools=extraction_tools,
    system_instruction="""You are a data extraction specialist.
Extract the requested information from provided text by calling the appropriate tool.
Do not infer values not explicitly present in the source text.
Use null for any numeric fields that cannot be confirmed."""
)

def extraction_phase(research_text: str, service_name: str) -> dict[str, Any]:
    """Phase 2: Convert collected information into structured data."""
    prompt = f"""
    From the research below, extract pricing information for {service_name}
    using the extract_pricing_data tool.
    
    Research:
    {research_text}
    """
    response = extraction_model.generate_content(prompt)
    
    for part in response.candidates[0].content.parts:
        if hasattr(part, "function_call"):
            fc = part.function_call
            if fc.name == "extract_pricing_data":
                return dict(fc.args)
    
    return {"error": "Function calling was not invoked"}
```

Notice that Phase 2 has no search tool attached. This is intentional — adding Search Grounding here risks introducing data that contradicts what Phase 1 collected, which defeats the purpose of the two-phase design.

## Complete Pipeline with Parallel Execution

```python
import asyncio
from dataclasses import dataclass

@dataclass
class CompetitorReport:
    service_name: str
    raw_research: str
    structured_data: dict[str, Any]

async def analyze_competitor(service_name: str) -> CompetitorReport:
    """Full analysis pipeline for one competitor."""
    print(f"[1/2] Researching {service_name}...")
    raw = research_phase(
        service_name=service_name,
        focus_area="pricing plans, key features, recent updates"
    )
    
    print(f"[2/2] Structuring {service_name} data...")
    structured = extraction_phase(raw, service_name)
    
    return CompetitorReport(
        service_name=service_name,
        raw_research=raw,
        structured_data=structured
    )

async def run_competitor_analysis(competitors: list[str]) -> list[CompetitorReport]:
    """Analyze multiple competitors in parallel."""
    tasks = [analyze_competitor(name) for name in competitors]
    return await asyncio.gather(*tasks)

if __name__ == "__main__":
    competitors = ["ServiceA", "ServiceB", "ServiceC"]
    reports = asyncio.run(run_competitor_analysis(competitors))
    
    for report in reports:
        print(f"\n=== {report.service_name} ===")
        print(json.dumps(report.structured_data, ensure_ascii=False, indent=2))
```

Parallel execution reduces total time by roughly two-thirds for three competitors compared to sequential processing.

## Using `confidence_level` to Fight Hallucination

Including a `confidence_level` field in the Function Calling schema prompts Gemini to self-assess information reliability. In practice:

- `high`: Data confirmed from an official pricing page in search results
- `medium`: Data from news articles or comparison sites
- `low`: Information inferred from training data only

This lets you filter downstream:

```python
def filter_high_confidence(reports: list[CompetitorReport]) -> list[dict]:
    """Return only reports with high-confidence data."""
    return [
        r.structured_data for r in reports
        if r.structured_data.get("confidence_level") == "high"
    ]
```

When confidence comes back as `low`, you can ask Gemini to explain why, then decide whether to trigger a re-research cycle with a more targeted prompt.

## Operational Notes Worth Knowing

**Rate limits:** Requests with Search Grounding enabled consume more tokens than standard requests. If you're on the free tier, keep parallel execution at 3 or fewer concurrent requests.

**Search result freshness:** Search Grounding doesn't guarantee today's results. When you need information from a specific date range, make it explicit in the prompt: "Only reference information published after January 2026."

**Function Calling schema complexity:** Overly complex schemas cause Gemini to miss tool calls or fill fields incorrectly. Keep nesting to 2–3 levels and limit any single tool to roughly 10 properties for reliable behavior.

The two-phase pattern generalizes well beyond competitive pricing. Job listing collection and structuring, news gathering and categorization, product review aggregation with sentiment tagging — anywhere the workflow follows "search → structure," this design applies. Treating these two Gemini capabilities as complementary rather than competing is what makes the difference between a useful agent and a brittle one.
