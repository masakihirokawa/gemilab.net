Gemini API is incredibly powerful, but as your application scales, API costs can grow faster than expected. In this guide, you'll learn how to build a **Redis caching layer** that intercepts repeated and semantically similar queries — delivering responses in under 5ms while **cutting your API costs by up to 80%**.

## Why Cache Gemini API Responses?

Many AI applications receive the same or very similar questions repeatedly. A customer support chatbot, for example, might field hundreds of queries like "What are your business hours?" or "How do I return an item?" every single day.

Without caching, each of those requests incurs:

- **Token costs**: Even Gemini 3 Flash charges per input/output token
- **Latency overhead**: API round-trips add 100–500ms per request
- **Quota consumption**: High-frequency requests can hit rate limits unexpectedly

A Redis cache sits between your application and the Gemini API, returning stored responses instantly on cache hits — completely bypassing the API call.

## Two Caching Approaches

### Exact-match caching

The simplest approach: hash the query string, use it as a Redis key, and store the response. Works perfectly when users send identical requests.

### Semantic caching (similarity-based)

"What's the weather today?" and "Can you tell me today's temperature?" are different strings but carry the same meaning. Semantic caching converts queries into vector embeddings and uses cosine similarity to find matching cache entries — even when the wording differs.

## Exact-Match Cache Implementation

Let's start with the straightforward version:

```python
import hashlib
import json
import redis
import google.generativeai as genai

# Initialize clients
genai.configure(api_key=GEMINI_API_KEY)
model = genai.GenerativeModel("gemini-3-flash")
cache = redis.Redis(host=REDIS_HOST, port=REDIS_PORT, decode_responses=True)

# Cache TTL: 24 hours
CACHE_TTL = 86400

def get_gemini_response_cached(prompt: str) -> str:
    """
    Call Gemini API with Redis caching.
    Returns cached response instantly on hit; calls the API on miss.
    """
    # Use a SHA-256 hash of the prompt as the cache key
    cache_key = f"gemini:v1:{hashlib.sha256(prompt.encode()).hexdigest()}"

    # Check cache first
    cached = cache.get(cache_key)
    if cached:
        print(f"✅ Cache hit: {cache_key[:20]}...")
        return json.loads(cached)["text"]

    # Cache miss — call the API
    print("🌐 Calling Gemini API...")
    response = model.generate_content(prompt)
    result_text = response.text

    # Store in Redis with TTL
    cache.setex(
        cache_key,
        CACHE_TTL,
        json.dumps({"text": result_text, "prompt": prompt})
    )
    print(f"💾 Cached response (TTL: {CACHE_TTL}s)")

    return result_text

# Test it out
if __name__ == "__main__":
    query = "What is Function Calling in the Gemini API?"

    # First call: hits the API
    response1 = get_gemini_response_cached(query)
    print(response1[:100])

    # Second call: served from cache instantly
    response2 = get_gemini_response_cached(query)
    print(response2[:100])
```

## Semantic Cache Implementation

For similarity-based caching, we embed queries and compare cosine similarity against stored entries:

```python
import numpy as np
from typing import Optional

class SemanticCache:
    """
    Semantic cache using Gemini Embeddings and cosine similarity.
    Matches cache entries when query intent is similar, even if wording differs.
    """

    SIMILARITY_THRESHOLD = 0.92  # Tune this between 0.85 and 0.95
    EMBED_MODEL = "models/text-embedding-004"
    CACHE_PREFIX = "gemini:semantic:"
    INDEX_KEY = "gemini:semantic:index"

    def __init__(self, redis_client: redis.Redis):
        self.cache = redis_client

    def _embed(self, text: str) -> list[float]:
        """Convert text to an embedding vector"""
        result = genai.embed_content(
            model=self.EMBED_MODEL,
            content=text,
            task_type="retrieval_query"
        )
        return result["embedding"]

    def _cosine_similarity(self, vec_a: list, vec_b: list) -> float:
        """Compute cosine similarity between two vectors"""
        a = np.array(vec_a)
        b = np.array(vec_b)
        return float(np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b)))

    def get(self, query: str) -> Optional[str]:
        """
        Search for a semantically similar cached entry.
        Returns the cached response if similarity exceeds the threshold.
        """
        query_vec = self._embed(query)
        all_keys = self.cache.smembers(self.INDEX_KEY)

        best_score = 0.0
        best_response = None

        for key in all_keys:
            entry_data = self.cache.hgetall(key)
            if not entry_data:
                continue

            stored_vec = json.loads(entry_data["embedding"])
            score = self._cosine_similarity(query_vec, stored_vec)

            if score > best_score:
                best_score = score
                best_response = entry_data.get("response")

        if best_score >= self.SIMILARITY_THRESHOLD:
            print(f"✅ Semantic cache hit (similarity: {best_score:.3f})")
            return best_response

        return None

    def set(self, query: str, response: str, ttl: int = 86400):
        """Save a query-response pair to the semantic cache"""
        query_vec = self._embed(query)
        cache_key = f"{self.CACHE_PREFIX}{hashlib.sha256(query.encode()).hexdigest()}"

        self.cache.hset(cache_key, mapping={
            "query": query,
            "embedding": json.dumps(query_vec),
            "response": response
        })
        self.cache.expire(cache_key, ttl)
        self.cache.sadd(self.INDEX_KEY, cache_key)
        print(f"💾 Saved to semantic cache: {cache_key[:30]}...")

def get_response_with_semantic_cache(query: str) -> str:
    """Gemini call with semantic cache layer"""
    semantic_cache = SemanticCache(cache)

    cached_response = semantic_cache.get(query)
    if cached_response:
        return cached_response

    print("🌐 Calling Gemini API...")
    response = model.generate_content(query)
    result = response.text

    semantic_cache.set(query, result)
    return result

# Try it
if __name__ == "__main__":
    # First call: API invoked
    r1 = get_response_with_semantic_cache("How can I reduce Gemini API costs?")

    # Second call: semantically similar — should hit cache
    r2 = get_response_with_semantic_cache("What are some tips for saving money on Gemini API?")
    # Output: ✅ Semantic cache hit (similarity: 0.947)
```

## TTL Strategy and Cache Invalidation

Not all content ages at the same rate. Design TTLs based on how frequently the underlying information changes:

```python
# TTL configuration by content type
CACHE_TTL_CONFIG = {
    "faq": 7 * 24 * 3600,        # FAQs: 7 days (low change frequency)
    "product_info": 24 * 3600,    # Product details: 24 hours
    "news_summary": 3600,         # News summaries: 1 hour
    "realtime": 300,              # Real-time data: 5 minutes
}

def get_ttl_for_query_type(query_type: str) -> int:
    return CACHE_TTL_CONFIG.get(query_type, 86400)

# Tag-based cache invalidation
def invalidate_cache_by_tag(tag: str):
    """Bulk-delete cache entries associated with a specific tag"""
    pattern = f"gemini:*:{tag}:*"
    keys = cache.scan_iter(match=pattern)
    deleted = 0
    for key in keys:
        cache.delete(key)
        deleted += 1
    print(f"🗑️ Deleted {deleted} cache entries (tag: {tag})")
```

## Production Configuration

### Redis Sentinel for high availability

A single Redis instance is a single point of failure. For production, use **Redis Sentinel** or **Redis Cluster**:

```python
from redis.sentinel import Sentinel

sentinel = Sentinel(
    [("sentinel1.internal", 26379), ("sentinel2.internal", 26379)],
    socket_timeout=0.1
)

# Write to master, read from replica
master = sentinel.master_for("mymaster", socket_timeout=0.1)
slave = sentinel.slave_for("mymaster", socket_timeout=0.1)
```

### Monitoring cache metrics

```python
class CacheMetrics:
    """Track cache hit rate and estimated cost savings"""

    def __init__(self, redis_client: redis.Redis):
        self.cache = redis_client
        self.hits_key = "gemini:metrics:hits"
        self.misses_key = "gemini:metrics:misses"

    def record_hit(self):
        self.cache.incr(self.hits_key)

    def record_miss(self):
        self.cache.incr(self.misses_key)

    def get_stats(self) -> dict:
        hits = int(self.cache.get(self.hits_key) or 0)
        misses = int(self.cache.get(self.misses_key) or 0)
        total = hits + misses
        hit_rate = (hits / total * 100) if total > 0 else 0

        # Gemini 3 Flash: ~$0.30/1M output tokens (approximate)
        avg_tokens_per_request = 500
        cost_per_request = (avg_tokens_per_request / 1_000_000) * 0.30
        estimated_savings = hits * cost_per_request

        return {
            "hits": hits,
            "misses": misses,
            "hit_rate": f"{hit_rate:.1f}%",
            "estimated_savings_usd": f"${estimated_savings:.4f}"
        }
```

## Common Errors and Fixes

**ConnectionError: Error 111 connecting to localhost:6379**

Redis isn't running or the connection details are wrong. If using Docker, run `docker ps` to confirm the container is active. Double-check the host, port, and any firewall rules.

**ResponseError: WRONGTYPE Operation**

The key exists with a different data type than you're trying to use. This usually means a key naming collision. Either flush the cache with `FLUSHDB` or update your key prefix to avoid conflicts.

**Low semantic cache hit rate**

Try lowering `SIMILARITY_THRESHOLD` (e.g., from 0.92 to 0.88). Be careful not to go below 0.85, or you risk returning irrelevant cached responses. Also consider combining this with Gemini's built-in Context Caching — see [Gemini API Context Caching for Cost Optimization](/en/articles/gemini-api/gemini-api-context-caching-cost-optimization) for details.

## FAQ

**Q: Won't generating embeddings for every query add its own cost?**

A: Embedding API costs are roughly 10x cheaper than generation API costs. As long as your cache hit rate exceeds ~50%, the total savings from avoided generation calls more than offset the embedding overhead. If your hit rate is still low early on, start with exact-match caching and add semantic caching once you have enough traffic data.

**Q: What happens if Redis runs out of memory?**

A: Configure `maxmemory` and set `maxmemory-policy allkeys-lru` in your `redis.conf`. This evicts the least recently used keys when memory fills up, keeping your most frequently accessed responses warm.

**Q: Can I cache personalized responses?**

A: Personalized responses generally shouldn't be shared across users. You can include the user ID in the cache key, but this reduces cache efficiency significantly at scale. A cleaner architecture is to separate "generic questions" (cacheable) from "user-specific questions" (always call the API) at the routing layer.

## Summary

Adding a Redis caching layer to your Gemini API integration delivers measurable results:

- **Response speed**: From 100–500ms API latency down to under 5ms on cache hits
- **Cost reduction**: Up to 80% savings on applications with high query repetition

Start with exact-match caching to get quick wins, collect hit rate data, and then layer on semantic caching to capture similar-but-not-identical queries. Combined with Gemini's native Context Caching feature, this two-layer approach can dramatically reduce operational costs as your application scales.
