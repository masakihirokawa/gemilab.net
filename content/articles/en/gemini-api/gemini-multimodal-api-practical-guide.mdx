If you run a wallpaper app for long enough, one chore becomes unavoidable: sorting thousands of images into categories like "night scene," "minimal," or "animals."

Every time a few hundred new assets arrived, I used to look at each one and tag it by hand. That worked at first, but as the library grew it stopped being something a human should be doing. Handing image classification to Gemini's multimodal API came out of that very practical need.

This article shares the implementation patterns that settled out of that process — ones that actually run. The official snippets are fragmented, and dropping them straight into production tends to break on the details. Here, image input, resolution tuning, retries, and cost tracking are shown as one connected flow.

## Get the SDK and call shape right first

Gemini image input uses the `@google/generative-ai` package. The basic form is passing `generateContent` an array that mixes text with `inlineData` (a Base64 image).

```javascript
import { GoogleGenerativeAI } from "@google/generative-ai";
import fs from "node:fs";

const genAI = new GoogleGenerativeAI(process.env.GEMINI_API_KEY);

async function analyzeImage(imagePath, prompt) {
  const model = genAI.getGenerativeModel({ model: "gemini-2.5-flash" });

  const base64Image = fs.readFileSync(imagePath).toString("base64");

  const result = await model.generateContent([
    {
      inlineData: {
        mimeType: "image/jpeg",
        data: base64Image,
      },
    },
    prompt,
  ]);

  return result.response.text();
}
```

Three things matter: images go into `inlineData` with a `mimeType` and a Base64 string, the response text comes from `result.response.text()`, and the model name is set on `getGenerativeModel`. The structure differs completely from the OpenAI or Anthropic SDKs, so reusing another vendor's sample will fail here. I lost a good half hour early on, hunting for a `messages.create` that doesn't exist because another SDK's shape was still in my head.

## Resolution tuning sets both accuracy and cost

This was the single change that mattered most when I switched from manual work to automation. Wallpaper originals are often 4K, but sending them as-is for classification is wasteful. Gemini splits images into tiles for token counting, so higher resolution means a steeply higher cost per image.

For a classification task, shrinking the long edge to around 1024px barely dented accuracy. If anything, losing the extra detail made big-picture calls like "night versus day" more stable.

```javascript
import sharp from "sharp";

// Lighten for classification: 1024px long edge, JPEG quality 80 is plenty
async function toClassificationJpeg(inputPath) {
  return sharp(inputPath)
    .resize(1024, 1024, { fit: "inside", withoutEnlargement: true })
    .jpeg({ quality: 80 })
    .toBuffer();
}

async function classifyWallpaper(inputPath, categories) {
  const model = genAI.getGenerativeModel({ model: "gemini-2.5-flash" });
  const buffer = await toClassificationJpeg(inputPath);

  const prompt = `Classify this wallpaper into exactly one category.
Categories: ${categories.join(", ")}
Reply with this JSON only: {"category": "...", "confidence": 0.0-1.0}`;

  const result = await model.generateContent([
    { inlineData: { mimeType: "image/jpeg", data: buffer.toString("base64") } },
    prompt,
  ]);

  return JSON.parse(result.response.text().replace(/```json|```/g, "").trim());
}
```

Just inserting the resize step roughly halved the bill for processing the same number of images. For an app funded by ad revenue (AdMob), that gap turns directly into breathing room. Cutting cost in half while holding accuracy steady was a more realistic win, as a solo developer, than squeezing out one extra point of precision.

## Receive JSON, gate on confidence

Not making the classifier fully automatic was another lesson from running it. Always have Gemini return a confidence score, and only review the low ones by hand. That one step stopped misclassifications from going public unnoticed.

```javascript
async function classifyBatch(paths, categories, reviewThreshold = 0.7) {
  const auto = [];
  const needsReview = [];

  for (const path of paths) {
    const { category, confidence } = await classifyWallpaper(path, categories);
    const record = { path, category, confidence };

    if (confidence >= reviewThreshold) {
      auto.push(record);
    } else {
      needsReview.push(record); // collect only the uncertain ones
    }
  }

  return { auto, needsReview };
}
```

Out of thousands of images, only about one in ten needed a human look. The other 90% were auto-accepted above 0.7 confidence and flowed into the publish pipeline without review. "Send only the uncertain ones back to a person," rather than "let the AI do everything," is what lets quality and speed coexist.

## Retry only on 429 and 5xx

Run a real batch and you will hit transient errors. If you retry everything, you also hammer genuine request mistakes (400) forever. Limiting retries to rate limits (429) and temporary server failures (500/503) is the practical choice.

```javascript
async function generateWithRetry(parts, maxRetries = 3) {
  const model = genAI.getGenerativeModel({ model: "gemini-2.5-flash" });

  for (let attempt = 1; attempt <= maxRetries; attempt++) {
    try {
      const result = await model.generateContent(parts);
      return result.response.text();
    } catch (error) {
      const status = error?.status ?? error?.response?.status;

      // Bad input never succeeds on resend. Throw immediately.
      if (status === 400) throw error;

      // Back off only for rate limits and transient failures
      if (status === 429 || status === 500 || status === 503) {
        const wait = 1000 * 2 ** (attempt - 1);
        await new Promise((r) => setTimeout(r, wait));
        continue;
      }
      throw error;
    }
  }
  throw new Error(`Did not complete after ${maxRetries} attempts`);
}
```

After throwing 400 straight back, the logs became far easier to read. Where they had been buried in "waiting to retry," the input mistakes that actually needed fixing finally stood out.

## Track the running total, not the estimate

Last, a humble one that paid off: cumulative cost tracking. The per-image price is tiny, but run thousands of images several times a month and it adds up. The response's `usageMetadata` carries the tokens actually consumed, so summing that — rather than an estimate — is the accurate way.

```javascript
async function analyzeAndCount(parts, counter) {
  const model = genAI.getGenerativeModel({ model: "gemini-2.5-flash" });
  const result = await model.generateContent(parts);

  const usage = result.response.usageMetadata;
  counter.totalTokens += usage?.totalTokenCount ?? 0;

  return { text: result.response.text(), tokens: usage?.totalTokenCount };
}
```

I reset this total at the start of each month and read it next to AdMob revenue. Whether the API cost of automated classification is worth it against the hours saved and the ad income — that single comparison is what decides if a feature stays or gets retired.

## What to try next

Start with ten images on your machine and have `gemini-2.5-flash` return a JSON classification. Always request a confidence score, and check the low ones by hand. Once that minimal loop runs, you only need to grow the volume while dialing in resolution and threshold.

I hope it helps as a first step if you are sitting on a large pile of assets too.
