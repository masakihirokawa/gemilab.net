Documentation debt is real. You ship the feature, the PR gets merged, and the README sits at "TODO" for the next six months. By then, the original context is gone and you're reading your own code like a stranger wrote it.

Gemini API turns out to be exceptionally good at closing this gap — not because it writes perfect docs on the first try, but because it generates a solid first draft in seconds. That's the part that actually takes the longest when you're doing it manually. In this guide, I'll walk through three practical Python scripts: auto-generating README files, adding JSDoc-style docstrings, and producing OpenAPI specifications from API source code.

## Why Gemini API Works Well for Documentation

Most documentation tasks fail at the "understanding the whole picture" step. Writing a good README isn't just about listing functions — it requires understanding how the pieces fit together.

Gemini 2.5 Pro's context window goes up to one million tokens. That's enough to load the entire source of a medium-sized web application in a single request. Other models often require chunking and aggregation logic to handle real codebases; Gemini handles most projects in one shot.

Beyond raw context length, the model is genuinely good at inferring intent from code structure. Variable names, function signatures, and file organization give it enough signal to generate documentation that reads like a developer wrote it — not a template.

## Auto-Generate README Files

This script walks a project directory, collects source files, and sends them to Gemini with a structured prompt. The result is a markdown README draft.

```python
import google.generativeai as genai
import os
from pathlib import Path


def collect_source_files(project_dir: str, extensions: list[str]) -> str:
    """Collect source files from a directory and return as a single string."""
    collected = []
    for ext in extensions:
        for path in Path(project_dir).rglob(f"*{ext}"):
            # Skip build artifacts and dependency directories
            if any(skip in str(path) for skip in [
                "node_modules", ".git", "__pycache__", "dist", ".next", "build"
            ]):
                continue
            try:
                content = path.read_text(encoding="utf-8")
                collected.append(f"\n\n=== {path} ===\n{content}")
            except Exception:
                continue
    return "\n".join(collected)


def generate_readme(project_dir: str) -> str:
    """Generate a README.md for the given project directory."""
    genai.configure(api_key=os.environ["GEMINI_API_KEY"])
    model = genai.GenerativeModel("gemini-2.5-pro")

    source_code = collect_source_files(
        project_dir,
        extensions=[".py", ".ts", ".tsx", ".js", ".go", ".rs"]
    )

    prompt = f"""Analyze the following project source code and write a GitHub README.md in English.

Include:
- A one- or two-sentence project overview
- Key features (3–5 bullet points)
- Installation steps with real commands
- A usage example with a code snippet
- Tech stack

Source code:
{source_code[:300000]}
"""

    response = model.generate_content(prompt)
    return response.text


if __name__ == "__main__":
    import sys
    project_dir = sys.argv[1] if len(sys.argv) > 1 else "."
    readme = generate_readme(project_dir)
    print(readme)
    # Uncomment to write directly to file:
    # Path("README.md").write_text(readme, encoding="utf-8")
```

Run it:

```bash
python generate_readme.py /path/to/your/project
```

Sample output (excerpt):

```markdown
# my-api-service

A lightweight REST API service built on FastAPI with PostgreSQL support and JWT authentication.

## Key Features
- User registration and login with JWT tokens
- Full CRUD support via SQLAlchemy ORM
- Async database access with asyncpg
...
```

The `[:300000]` slice keeps the prompt within a safe token range. In practice, 300,000 characters covers most mid-sized projects. Very large monorepos need module-by-module processing, which I'll cover in the pitfalls section below.

## Auto-Add Docstrings and JSDoc Comments

This script takes a source file, sends it to Gemini, and gets back the same code with documentation comments added. The key constraint in the prompt: "do not modify the code itself."

```python
import google.generativeai as genai
import os


def add_docstrings(source_code: str, language: str = "python") -> str:
    """Add docstrings or JSDoc comments to source code without changing logic."""
    genai.configure(api_key=os.environ["GEMINI_API_KEY"])
    model = genai.GenerativeModel("gemini-2.5-pro")

    lang_instruction = {
        "python": "Python docstrings in Google style",
        "typescript": "TypeScript JSDoc comments",
        "javascript": "JavaScript JSDoc comments",
    }.get(language, "appropriate documentation comments")

    prompt = f"""Add {lang_instruction} to the following code.
Return the complete code with comments added. Do not change any existing logic.

Code:
```{language}
{source_code}
```"""

    response = model.generate_content(prompt)
    return response.text


if __name__ == "__main__":
    sample_code = """
def calculate_discount(price: float, rate: float) -> float:
    if rate < 0 or rate > 1:
        raise ValueError("rate must be between 0 and 1")
    return price * (1 - rate)
"""
    result = add_docstrings(sample_code, language="python")
    print(result)
```

Output:

```python
def calculate_discount(price: float, rate: float) -> float:
    """Calculate the discounted price.

    Args:
        price: The original price (must be non-negative).
        rate: The discount rate as a decimal between 0 and 1.
              For example, 0.2 represents a 20% discount.

    Returns:
        The price after applying the discount.

    Raises:
        ValueError: If rate is outside the range [0, 1].
    """
    if rate < 0 or rate > 1:
        raise ValueError("rate must be between 0 and 1")
    return price * (1 - rate)
```

The quality here is genuinely good. The `Args` descriptions go beyond restating the type hints — they explain what values are valid and give a concrete example. That's the kind of comment that actually helps someone using the function weeks later.

## Generate OpenAPI Specs from API Code

If you have FastAPI or Express routes, Gemini can infer request/response schemas and produce an OpenAPI 3.0 spec. Using `response_mime_type: "application/json"` ensures the output is clean JSON, not a markdown code block you'd have to parse.

```python
import google.generativeai as genai
import os
import json


def generate_openapi_spec(api_code: str) -> dict:
    """Generate an OpenAPI 3.0 spec from API route code."""
    genai.configure(api_key=os.environ["GEMINI_API_KEY"])
    model = genai.GenerativeModel(
        "gemini-2.5-pro",
        generation_config={"response_mime_type": "application/json"}
    )

    prompt = f"""Analyze the following API code and generate an OpenAPI 3.0 specification in JSON format.
Include all endpoints, path parameters, query parameters, and request/response schemas.
Only include endpoints that exist in the code — do not hallucinate additional routes.

API code:
{api_code}"""

    response = model.generate_content(prompt)

    try:
        return json.loads(response.text)
    except json.JSONDecodeError as e:
        raise ValueError(
            f"Failed to parse JSON response: {e}\nRaw response: {response.text[:500]}"
        )


if __name__ == "__main__":
    api_code = """
@app.get("/users/{user_id}")
async def get_user(user_id: int, include_posts: bool = False):
    user = db.get_user(user_id)
    if not user:
        raise HTTPException(status_code=404, detail="User not found")
    return user
"""
    spec = generate_openapi_spec(api_code)
    print(json.dumps(spec, indent=2))
```

Setting `response_mime_type` is one of those things that's not obvious from the docs but makes a huge practical difference. Without it, Gemini sometimes wraps the JSON in a markdown code block, which breaks `json.loads()`. With it, you get raw JSON every time.

## Common Pitfalls

**Generated docstrings don't match the actual behavior**

Gemini infers intent from naming and structure. If a function is named `process_data` but actually does something non-obvious, the generated comment will reflect the obvious interpretation, not the real one. Always review the output — especially `Returns` descriptions and any error conditions listed under `Raises`.

**Context limits on large codebases**

The 300,000-character cap works for most projects. For larger codebases, you'll need to process files in batches. When you're sending the same base prompt repeatedly, Context Caching can cut your token costs significantly. See [Gemini API Context Caching for Cost Optimization](/en/articles/gemini-api/gemini-api-context-caching-cost-optimization) for the implementation details.

**Rate limits when processing many files**

Sending one request per file in a tight loop will hit rate limits quickly. Add a `time.sleep(0.5)` between requests, or use `asyncio.Semaphore` to cap concurrent requests when using the async client.

**Invented endpoints in OpenAPI output**

Without the explicit "only include endpoints that exist" instruction, Gemini sometimes adds plausible-but-fictional routes to the spec. Including that constraint in the prompt reduces hallucination significantly. Validating the output spec against actual route definitions before committing it to your repo is worth the extra step.
