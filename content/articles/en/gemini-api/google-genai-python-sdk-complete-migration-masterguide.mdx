If your codebase still starts with `import google.generativeai as genai`, you've probably noticed something odd: new tutorials use different code, new features don't seem to work, and the documentation keeps pointing you somewhere unexpected.

The new Python SDK `google-genai`, released by Google in late 2024, shares a name with the old `google-generativeai` library but is an entirely different API design. A simple name swap won't cut it — the underlying architecture changed fundamentally, and that's why so many developers hit a wall during migration.

## 1. Why You Need to Migrate Now

### The Deprecation Reality

`google-generativeai` served developers well during Gemini's beta phase, but Google has been clear: new features are being built exclusively for `google-genai`. If you stay on the old SDK, you'll hit concrete limitations immediately.

- **Thinking mode is unavailable**: The `thinkingConfig` parameter only exists in the new SDK
- **Context Caching uses a different interface**: The updated cache creation flow isn't backported
- **Files API async handling differs**: Large file upload patterns diverged significantly  
- **Security patches are delayed**: Bug fixes and vulnerability patches are applied to the new SDK first

Running `pip show google-generativeai` on most older projects reveals versions far behind the current release. Many of those projects are quietly missing out on Gemini 2.5 Pro's best capabilities.

### The Core Architectural Difference

The old SDK followed a **function-based, procedural pattern**. You called `genai.configure()` once, then created a `GenerativeModel` object and called `.generate_content()` on it.

The new SDK adopts a **client-based, object-oriented pattern**. You create a `genai.Client()` instance and route all operations through its methods. This shift is the root cause of most migration failures.

```python
# ── Old SDK (google-generativeai) ──
import google.generativeai as genai

genai.configure(api_key="YOUR_GEMINI_API_KEY")
model = genai.GenerativeModel("gemini-1.5-pro")
response = model.generate_content("Hello, Gemini\!")
print(response.text)

# ── New SDK (google-genai) ──
from google import genai

client = genai.Client(api_key="YOUR_GEMINI_API_KEY")
response = client.models.generate_content(
    model="gemini-2.5-pro-latest",
    contents="Hello, Gemini\!",
)
print(response.text)
```

The import changes from `import google.generativeai as genai` to `from google import genai`. The model invocation shifts from `model.generate_content()` to `client.models.generate_content()`. Understanding just these two differences eliminates the majority of migration errors you'll encounter.

## 2. Pre-Migration: Assessing Your Codebase

### Inventory Your Dependencies

Before touching any code, find every place the old SDK is used.

```bash
# Find all files using the old SDK

  --include="*.py" | \

```

This gives you a migration scope. A handful of files suggests a full migration in one sprint. Dozens of files across multiple modules calls for a phased approach — migrate one service at a time, running the old and new SDKs in parallel during the transition.

## 3. Migrating the Core API

### Text Generation

Start here. Get this right and 80% of your migration is done.

```python
import os
from google import genai
from google.genai import types

client = genai.Client(api_key=os.environ.get("GEMINI_API_KEY"))

def generate_text(prompt: str, model: str = "gemini-2.5-pro-latest") -> str:
    """Basic text generation with explicit error handling."""
    try:
        response = client.models.generate_content(
            model=model,
            contents=prompt,
            config=types.GenerateContentConfig(
                temperature=0.7,
                max_output_tokens=2048,
                top_p=0.9,
            ),
        )
        return response.text
    except genai.errors.APIError as e:
        print(f"API error: {e.status_code} - {e.message}")
        raise
    except Exception as e:
        print(f"Unexpected error: {e}")
        raise

result = generate_text("Explain async/await in Python for beginners.")
print(result)
```

The old SDK accepted `generation_config` as a dict or `GenerationConfig` object passed to `GenerativeModel`. In the new SDK, all generation parameters live inside `types.GenerateContentConfig`, passed via the `config` argument. This one change accounts for most of the `TypeError` errors you'll see during migration.

### Streaming

Streaming changed more than any other feature.

```python
import asyncio
import os
from google import genai
from google.genai import types

client = genai.Client(api_key=os.environ.get("GEMINI_API_KEY"))

# Synchronous streaming (for scripts, CLIs, notebooks)
def stream_sync(prompt: str) -> None:
    for chunk in client.models.generate_content_stream(
        model="gemini-2.5-pro-latest",
        contents=prompt,
    ):
        if chunk.text:
            print(chunk.text, end="", flush=True)
    print()

# Asynchronous streaming (for FastAPI, asyncio-based servers)
async def stream_async(prompt: str) -> None:
    async_client = genai.AsyncClient(api_key=os.environ.get("GEMINI_API_KEY"))
    
    async for chunk in await async_client.aio.models.generate_content_stream(
        model="gemini-2.5-pro-latest",
        contents=prompt,
    ):
        if chunk.text:
            print(chunk.text, end="", flush=True)
    print()

stream_sync("Explain multi-agent system design principles.")
asyncio.run(stream_async("How does RAG work in production?"))
```

The old SDK used `model.generate_content(stream=True)`. The new SDK has a dedicated `generate_content_stream()` method and a separate `AsyncClient` class for async environments. The explicit split makes integration with FastAPI and other async frameworks far cleaner.

### Multi-turn Chat

```python
from google import genai
from google.genai import types

client = genai.Client(api_key=os.environ.get("GEMINI_API_KEY"))

def create_chat_session():

        ),

chat = create_chat_session()

    "What are the main features of Gemini 2.5 Pro?",
    "Which of those features matter most for real app development?",

```

The old `ChatSession` maps to `client.chats.create()` in the new SDK. The conversation history is accessible via `chat.history`, and `system_instruction` now lives cleanly inside `GenerateContentConfig`.

## 4. Migrating Function Calling and Structured Output

### Function Calling: The New Way

This is where the new SDK truly shines. You no longer need to manually write JSON schemas.

```python
from google import genai
from google.genai import types
from typing import Any

client = genai.Client(api_key=os.environ.get("GEMINI_API_KEY"))

def get_weather(city: str, unit: str = "celsius") -> dict[str, Any]:
    """Get current weather for a city. (Mock implementation)"""
    weather_data = {
        "tokyo": {"temp": 22, "condition": "sunny", "humidity": 60},
        "london": {"temp": 14, "condition": "cloudy", "humidity": 75},
        "new york": {"temp": 18, "condition": "partly cloudy", "humidity": 65},
    }
    city_lower = city.lower()
    if city_lower in weather_data:
        data = weather_data[city_lower]
        temp = data["temp"]
        if unit == "fahrenheit":
            temp = round(temp * 9 / 5 + 32, 1)
        return {"city": city, "temperature": temp, "unit": unit, **data}
    return {"error": f"No data found for {city}"}

# Pass Python functions directly — the SDK infers the schema from type hints
response = client.models.generate_content(
    model="gemini-2.5-pro-latest",
    contents="What's the weather like in Tokyo and London right now?",
    config=types.GenerateContentConfig(
        tools=[get_weather],
        automatic_function_calling=types.AutomaticFunctionCallingConfig(
            disable=False,
        ),
    ),
)

print(response.text)
# → "Tokyo is currently sunny at 22°C, while London is cloudy at 14°C."
```

The old SDK required verbose `FunctionDeclaration` objects with manually specified parameter schemas. The new SDK reads Python type hints and docstrings to generate those schemas automatically. This is one of the most developer-friendly improvements in the migration.

### Structured Output with Pydantic

```python
from google import genai
from google.genai import types
from pydantic import BaseModel

client = genai.Client(api_key=os.environ.get("GEMINI_API_KEY"))

class ArticleSummary(BaseModel):
    title: str
    main_points: list[str]
    difficulty: str  # "beginner", "intermediate", "advanced"
    estimated_read_time_minutes: int

def summarize_article(article_text: str) -> ArticleSummary:
    """Summarize an article into a structured JSON response."""
    response = client.models.generate_content(
        model="gemini-2.5-pro-latest",
        contents=f"Summarize this article:\n\n{article_text}",
        config=types.GenerateContentConfig(
            response_mime_type="application/json",
            response_schema=ArticleSummary,  # Pass Pydantic model directly
        ),
    )
    return ArticleSummary.model_validate_json(response.text)

sample = """
Gemini 2.5 Pro is Google's latest large language model, released in 2025.
It features a 1-million-token context window, multimodal inputs (text, images, audio, video),
and a new Thinking mode for complex multi-step reasoning tasks.
"""

result = summarize_article(sample)
print(f"Title: {result.title}")
print(f"Key Points: {result.main_points}")
print(f"Difficulty: {result.difficulty}")
print(f"Read Time: {result.estimated_read_time_minutes} min")
```

Passing a Pydantic model directly as `response_schema` is a major upgrade over the old SDK's approach. You get type-safe structured output with zero manual JSON parsing.

## 5. Gemini 2.5 Pro Features Unlocked by the New SDK

### Thinking Mode

Thinking mode lets Gemini 2.5 Pro work through complex problems step by step before producing a final answer. It's especially effective for code debugging, math, and multi-step reasoning.

```python
from google import genai
from google.genai import types

client = genai.Client(api_key=os.environ.get("GEMINI_API_KEY"))

def solve_with_thinking(problem: str, thinking_budget: int = 8000) -> dict:
    """
    Solve a problem using Gemini 2.5 Pro's Thinking mode.
    
    Args:
        problem: The problem or question to solve
        thinking_budget: Token limit for the reasoning phase (0 = disabled, -1 = unlimited)
    
    Returns:
        Dict with "thinking" (reasoning trace), "answer" (final output), and token counts
    """
    response = client.models.generate_content(
        model="gemini-2.5-pro-latest",
        contents=problem,
        config=types.GenerateContentConfig(
            thinking_config=types.ThinkingConfig(
                thinking_budget=thinking_budget,
                include_thoughts=True,
            ),
        ),
    )
    
    thinking_text = ""
    answer_text = ""
    
    for part in response.candidates[0].content.parts:
        if hasattr(part, "thought") and part.thought:
            thinking_text += part.text
        else:
            answer_text += part.text
    
    return {
        "thinking": thinking_text,
        "answer": answer_text,
        "thinking_tokens": response.usage_metadata.thoughts_token_count,
        "total_tokens": response.usage_metadata.total_token_count,
    }

result = solve_with_thinking("""
The following Python function has a bug. Identify it and provide a corrected version.

def find_duplicates(nums: list[int]) -> list[int]:
    seen = set()
    duplicates = []
    for num in nums:
        if num in seen:
            duplicates.append(num)
        seen.add(num)
    return list(set(duplicates))

# Expected: find_duplicates([1, 2, 3, 1, 2, 4]) → [1, 2]
# Actual behavior has an issue with ordering guarantees
""")

print(f"Thinking ({result['thinking_tokens']} tokens):")
print(result["thinking"][:400] + "...\n")
print(f"Final Answer:")
print(result["answer"])
```

Set `thinking_budget` between 4,000 and 16,000 depending on problem complexity. Higher budgets improve accuracy but increase cost and latency. For simple generation tasks, set it to 0 to disable the feature entirely.

### Context Caching for Cost Reduction

If your application repeatedly sends the same large system prompt or reference documents, Context Caching can cut your costs by up to 75%.

```python
import datetime
import os
from google import genai
from google.genai import types

client = genai.Client(api_key=os.environ.get("GEMINI_API_KEY"))

LARGE_SYSTEM_PROMPT = """
You are a senior backend engineer with 10+ years of experience.
You specialize in Python, FastAPI, PostgreSQL, Redis, Kubernetes,
distributed systems design, microservices, and event-driven architecture.
[... imagine this is thousands of tokens of specification ...]
""" * 50  # Simulating a very large prompt

def create_system_cache() -> str:
    """Cache the expensive system prompt. Run once per deployment."""
    cache = client.caches.create(
        model="gemini-2.5-pro-latest",
        config=types.CreateCachedContentConfig(
            contents=[LARGE_SYSTEM_PROMPT],
            ttl=datetime.timedelta(hours=1),
            display_name="senior-engineer-prompt-v1",
        ),
    )
    print(f"Cache created: {cache.name}")
    print(f"Cached tokens: {cache.usage_metadata.total_token_count}")
    return cache.name

def ask_with_cache(cache_name: str, question: str) -> str:
    """Generate a response using the cached context."""
    response = client.models.generate_content(
        model="gemini-2.5-pro-latest",
        contents=question,
        config=types.GenerateContentConfig(
            cached_content=cache_name,
        ),
    )
    usage = response.usage_metadata
    print(f"Prompt tokens: {usage.prompt_token_count}")
    print(f"Cache hit tokens: {usage.cached_content_token_count}")
    return response.text

cache_name = create_system_cache()

for question in [
    "How do I implement efficient pagination in PostgreSQL?",
    "What's the best pattern for session management with Redis?",
    "Walk me through a Blue-Green deployment on Kubernetes.",
]:
    print(f"\nQ: {question}")
    print(f"A: {ask_with_cache(cache_name, question)}\n")
```

## 6. Common Migration Errors and Fixes

### Error 1: `AttributeError: module 'google.generativeai' has no attribute 'Client'`

**Cause**: Calling new SDK methods on the old SDK's import.

```python
# ❌ Wrong: old SDK import, new SDK method
import google.generativeai as genai
client = genai.Client(api_key="...")  # AttributeError

# ✅ Correct: new SDK import
from google import genai
client = genai.Client(api_key="...")
```

### Error 2: `TypeError: generate_content() got an unexpected keyword argument 'generation_config'`

**Cause**: The `generation_config` argument was renamed to `config` and now requires a typed object.

```python
# ❌ Old SDK style
model.generate_content(prompt, generation_config={"temperature": 0.7})

# ✅ New SDK style
from google.genai import types
client.models.generate_content(
    model="gemini-2.5-pro-latest",
    contents=prompt,
    config=types.GenerateContentConfig(temperature=0.7),
)
```

### Error 3: `AttributeError: 'GenerateContentResponse' has no attribute 'parts'`

**Cause**: The response object structure changed.

```python
# ❌ Old pattern
text = response.parts[0].text

# ✅ Simple case: use .text directly
text = response.text

# ✅ Multi-part / Thinking mode: iterate over parts
for part in response.candidates[0].content.parts:
    if hasattr(part, "thought") and part.thought:
        print(f"[Thought]: {part.text}")
    else:
        print(f"[Answer]: {part.text}")
```

### Error 4: `google.auth.exceptions.DefaultCredentialsError` (Vertex AI backend)

**Cause**: The Vertex AI backend requires Google Cloud credentials, not just an API key.

```python
import os
from google import genai

# Vertex AI backend
client = genai.Client(
    vertexai=True,
    project=os.environ.get("GOOGLE_CLOUD_PROJECT"),
    location=os.environ.get("GOOGLE_CLOUD_LOCATION", "us-central1"),
)

# API key backend (default, no GCP auth needed)
client_api = genai.Client(api_key=os.environ.get("GEMINI_API_KEY"))
```

### Error 5: `RuntimeError: This event loop is already running` in async contexts

```python
# ❌ Wrong: calling asyncio.run() inside an already-running event loop
import asyncio
asyncio.run(some_async_function())  # RuntimeError in FastAPI/Jupyter

# ✅ Correct: use await directly in async context
from google import genai

async def generate():
    async_client = genai.AsyncClient(api_key=os.environ.get("GEMINI_API_KEY"))
    response = await async_client.aio.models.generate_content(
        model="gemini-2.5-pro-latest",
        contents="Test prompt",
    )
    return response.text

# In FastAPI
from fastapi import FastAPI
app = FastAPI()

@app.get("/generate")
async def endpoint(prompt: str):
    result = await generate()
    return {"text": result}
```

## 7. Production Configuration and Authentication

### Environment Variable Management

```python
import os
from pathlib import Path
from dotenv import load_dotenv

def load_config() -> dict:
    """Load configuration safely from environment."""
    env_file = Path(".env")
    if env_file.exists():
        load_dotenv(env_file)
    
    api_key = os.environ.get("GEMINI_API_KEY")
    if not api_key:
        raise ValueError(
            "GEMINI_API_KEY is not set. "
            "Add it to your environment variables or .env file."
        )
    
    return {
        "api_key": api_key,
        "project_id": os.environ.get("GOOGLE_CLOUD_PROJECT"),
        "location": os.environ.get("GOOGLE_CLOUD_LOCATION", "us-central1"),
        "use_vertex": os.environ.get("USE_VERTEX_AI", "false").lower() == "true",
    }

def create_client() -> genai.Client:
    """Create the appropriate client based on environment config."""
    from google import genai
    config = load_config()
    
    if config["use_vertex"]:
        return genai.Client(
            vertexai=True,
            project=config["project_id"],
            location=config["location"],
        )
    return genai.Client(api_key=config["api_key"])
```

Always add `.env` to `.gitignore`. Consider using `git-secrets` to prevent accidental API key commits.

### Retry Logic for Production

```python
import time
import random
from google import genai
from google.genai import errors

client = genai.Client(api_key=os.environ.get("GEMINI_API_KEY"))

def generate_with_retry(
    prompt: str,
    model: str = "gemini-2.5-pro-latest",
    max_retries: int = 3,
    base_delay: float = 1.0,
) -> str:
    """Generate content with exponential backoff retry."""
    for attempt in range(max_retries + 1):
        try:
            response = client.models.generate_content(
                model=model,
                contents=prompt,
            )
            return response.text
        except errors.APIError as e:
            if e.status_code in (429, 500, 503) and attempt < max_retries:
                delay = base_delay * (2 ** attempt) + random.uniform(0, 1)
                print(f"Error {e.status_code}. Retrying in {delay:.1f}s... ({attempt + 1}/{max_retries})")
                time.sleep(delay)
            else:
                raise
    raise RuntimeError("Exhausted all retries")
```

## 9. Real-World Migration Patterns: A Full Application Example

### Before: Old SDK Implementation

```python
# ── OLD SDK (google-generativeai) ──
import google.generativeai as genai
from google.generativeai import types as old_types

class OldGeminiService:
    """Pre-migration service using google-generativeai."""
    
    def __init__(self, api_key: str):
        genai.configure(api_key=api_key)
        self.model = genai.GenerativeModel(
            model_name="gemini-1.5-pro",
            generation_config=old_types.GenerationConfig(
                temperature=0.7,
                top_p=0.9,
                max_output_tokens=4096,
            ),
            system_instruction="You are a helpful assistant.",
        )
        self.chat_session = None
    
    def start_chat(self):
        self.chat_session = self.model.start_chat(history=[])
    
    def generate(self, prompt: str) -> str:
        response = self.model.generate_content(prompt)
        return response.text
    
    def chat(self, message: str) -> str:
        if not self.chat_session:
            self.start_chat()
        response = self.chat_session.send_message(message)
        return response.text
    
    def stream_generate(self, prompt: str):
        for chunk in self.model.generate_content(prompt, stream=True):
            yield chunk.text
```

### After: New SDK Implementation

```python
# ── NEW SDK (google-genai) ──
import os
from google import genai
from google.genai import types, errors
import time
import random

class GeminiService:
    """Post-migration service using google-genai."""
    
    DEFAULT_MODEL = "gemini-2.5-pro-latest"
    
    def __init__(self, api_key: str | None = None):
        self.client = genai.Client(
            api_key=api_key or os.environ.get("GEMINI_API_KEY")
        )
        self._base_config = types.GenerateContentConfig(
            temperature=0.7,
            top_p=0.9,
            max_output_tokens=4096,
            system_instruction="You are a helpful assistant.",
        )
        self._chat_session = None
    
    def start_chat(self) -> None:
        """Initialize a new chat session."""
        self._chat_session = self.client.chats.create(
            model=self.DEFAULT_MODEL,
            config=self._base_config,
        )
    
    def generate(self, prompt: str, max_retries: int = 3) -> str:
        """Generate a response with automatic retry on transient errors."""
        for attempt in range(max_retries + 1):
            try:
                response = self.client.models.generate_content(
                    model=self.DEFAULT_MODEL,
                    contents=prompt,
                    config=self._base_config,
                )
                return response.text
            except errors.APIError as e:
                if e.status_code in (429, 500, 503) and attempt < max_retries:
                    delay = 2 ** attempt + random.uniform(0, 0.5)
                    time.sleep(delay)
                else:
                    raise
        raise RuntimeError("Exhausted retries")
    
    def chat(self, message: str) -> str:
        """Send a message in the current chat session."""
        if not self._chat_session:
            self.start_chat()
        response = self._chat_session.send_message(message)
        return response.text
    
    def stream_generate(self, prompt: str):
        """Yield text chunks as they arrive from the API."""
        for chunk in self.client.models.generate_content_stream(
            model=self.DEFAULT_MODEL,
            contents=prompt,
            config=self._base_config,
        ):
            if chunk.text:
                yield chunk.text
    
    def generate_structured(self, prompt: str, schema) -> str:
        """Generate a structured JSON response matching the given schema."""
        response = self.client.models.generate_content(
            model=self.DEFAULT_MODEL,
            contents=prompt,
            config=types.GenerateContentConfig(
                response_mime_type="application/json",
                response_schema=schema,
            ),
        )
        return response.text

# Usage
service = GeminiService()

# Basic generation
answer = service.generate("What is the capital of Japan?")
print(answer)

# Streaming
for token in service.stream_generate("Write a haiku about Python programming."):
    print(token, end="", flush=True)
print()

# Multi-turn chat
service.start_chat()
print(service.chat("What's Gemini 2.5 Pro's main strength?"))
print(service.chat("How does that compare to Gemini 2.0?"))
```

The migration surface is clearly visible here. The biggest changes are:
1. `genai.configure()` → `genai.Client()`
2. `GenerativeModel(...)` → config stored in `GenerateContentConfig`
3. `model.generate_content(stream=True)` → `generate_content_stream()`
4. `model.start_chat()` → `client.chats.create()`

## 10. Cost Comparison: Old vs New SDK Patterns

One of the most practical reasons to migrate is cost control. The new SDK exposes cost-relevant data more transparently.

```python
from google import genai
from google.genai import types
from dataclasses import dataclass

client = genai.Client(api_key=os.environ.get("GEMINI_API_KEY"))

@dataclass
class CostBreakdown:
    prompt_tokens: int
    completion_tokens: int
    cached_tokens: int
    thinking_tokens: int
    estimated_cost_usd: float

def generate_with_cost_tracking(
    prompt: str,
    model: str = "gemini-2.5-pro-latest",
    cache_name: str | None = None,
    enable_thinking: bool = False,
) -> tuple[str, CostBreakdown]:
    """
    Generate content and return a detailed cost breakdown.
    
    Gemini 2.5 Pro pricing (approximate, verify at ai.google.dev/pricing):
    - Input: $1.25 per 1M tokens (≤200K context), $2.50 per 1M tokens (>200K)
    - Output: $10 per 1M tokens
    - Thinking: $3.50 per 1M tokens
    - Cached input: $0.31 per 1M tokens
    """
    config_args = {}
    if cache_name:
        config_args["cached_content"] = cache_name
    if enable_thinking:
        config_args["thinking_config"] = types.ThinkingConfig(
            thinking_budget=8000,
            include_thoughts=False,  # Don't need to read thoughts, just use them
        )
    
    response = client.models.generate_content(
        model=model,
        contents=prompt,
        config=types.GenerateContentConfig(**config_args) if config_args else None,
    )
    
    usage = response.usage_metadata
    
    # Rough cost estimate (prices vary — always check official pricing)
    INPUT_PRICE_PER_1M = 1.25
    OUTPUT_PRICE_PER_1M = 10.0
    CACHED_PRICE_PER_1M = 0.31
    THINKING_PRICE_PER_1M = 3.50
    
    cached = getattr(usage, "cached_content_token_count", 0) or 0
    thinking = getattr(usage, "thoughts_token_count", 0) or 0
    regular_input = usage.prompt_token_count - cached
    
    cost = (
        (regular_input / 1_000_000) * INPUT_PRICE_PER_1M
        + (cached / 1_000_000) * CACHED_PRICE_PER_1M
        + (usage.candidates_token_count / 1_000_000) * OUTPUT_PRICE_PER_1M
        + (thinking / 1_000_000) * THINKING_PRICE_PER_1M
    )
    
    breakdown = CostBreakdown(
        prompt_tokens=usage.prompt_token_count,
        completion_tokens=usage.candidates_token_count,
        cached_tokens=cached,
        thinking_tokens=thinking,
        estimated_cost_usd=round(cost, 6),
    )
    
    return response.text, breakdown

text, cost = generate_with_cost_tracking(
    "Explain the difference between supervised and unsupervised learning.",
    enable_thinking=True,
)
print(text)
print(f"\nCost breakdown:")
print(f"  Prompt: {cost.prompt_tokens} tokens")
print(f"  Completion: {cost.completion_tokens} tokens")
print(f"  Thinking: {cost.thinking_tokens} tokens")
print(f"  Estimated cost: ${cost.estimated_cost_usd}")
```

This kind of visibility into token usage and cost wasn't straightforward in the old SDK. The new SDK's `usage_metadata` exposes `thoughts_token_count` and `cached_content_token_count` directly, making it practical to build cost dashboards for production workloads.

## Why This Migration Matters for Your Production Systems

It's worth stepping back and thinking about what this migration actually unlocks, beyond fixing import errors.

The `google-genai` SDK is designed for how developers actually build production AI applications in 2025 and 2026 — with async-first architecture, typed interfaces, automatic schema generation from Python types, and explicit cost and performance observability. These aren't just developer experience improvements. They translate into systems that are easier to test, cheaper to run at scale, and faster to extend when Gemini releases new capabilities.

The old SDK served its purpose during Gemini's beta phase. The new SDK reflects a more mature understanding of what production AI applications need. Migrating now means you're working with the grain of Google's API roadmap rather than against it.

Start with the highest-impact change — swap the import and create the `Client` object. Everything else follows naturally from there.

## Frequently Asked Questions

**Can I use both SDKs in the same project during migration?**

Yes, `google-generativeai` and `google-genai` can be installed simultaneously, and you can import both in different files. What you should avoid is mixing them within the same Python module — maintaining two mental models for API calls in one file leads to hard-to-trace bugs. Plan your migration file by file, and remove the old SDK import immediately after migrating each module.

**Do I need to update my model name strings?**

The model naming conventions changed slightly. The old SDK commonly used strings like `"gemini-1.5-pro"` or `"gemini-1.5-flash"`. With the new SDK targeting Gemini 2.5, use `"gemini-2.5-pro-latest"` or `"gemini-2.5-flash-latest"` to always get the most current stable version. If you need a pinned version for reproducibility (for example, in production to avoid unexpected behavior changes), use specific version strings like `"gemini-2.5-pro-preview-03-25"` — check [ai.google.dev/gemini-api/docs/models](https://ai.google.dev/gemini-api/docs/models) for the current list.

**How do I handle the `safety_settings` parameter migration?**

Safety settings moved into `GenerateContentConfig` in the new SDK.

```python
from google.genai import types

# Old SDK
model.generate_content(
    prompt,
    safety_settings={"HARM_CATEGORY_HARASSMENT": "BLOCK_NONE"}
)

# New SDK
client.models.generate_content(
    model="gemini-2.5-pro-latest",
    contents=prompt,
    config=types.GenerateContentConfig(
        safety_settings=[
            types.SafetySetting(
                category="HARM_CATEGORY_HARASSMENT",
                threshold="BLOCK_NONE",
            )
        ],
    ),
)
```

**Does the new SDK support the Vertex AI backend?**

Yes, and switching is a single parameter. Pass `vertexai=True` to `genai.Client()` along with your project ID and location. The Vertex AI backend is recommended for production deployments that require enterprise SLAs, regional data residency, or integration with other Google Cloud services like Cloud Logging and Cloud Monitoring.

**What happens to my chat history when I switch SDKs?**

Chat history in `google-generativeai` was stored as a list of `Content` objects accessible via `chat.history`. In `google-genai`, the history is accessed the same way — `chat.history` — but the object types changed. If you're persisting history to a database, you'll need to serialize and deserialize it using the new `types.Content` and `types.Part` classes. For most applications, it's cleanest to start fresh sessions after migration rather than attempting to port old history objects.

**Is there a migration script that automates renaming?**

There's no official automated migration tool, and given the architectural differences (not just name changes), an automated approach would be fragile. The most reliable path is manual migration, file by file, with tests running after each change. The `generate_content` method name itself didn't change, but the object it's called on did — and that difference is semantic enough that a simple find-and-replace would produce broken code rather than working code.

What you can automate is the *discovery* phase. The grep commands in Section 2 of this guide give you an accurate inventory. From there, the migration is a focused, deliberate process that takes a day or two for most medium-sized codebases — far less time than debugging mysterious runtime errors caused by an incomplete automated migration.

The bottom line: migrate with intention, test as you go, and keep the old SDK installed until every module has been verified against the new one.
