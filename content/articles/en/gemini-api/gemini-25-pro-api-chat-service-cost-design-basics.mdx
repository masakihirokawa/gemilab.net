Individual developers can now build profitable chat services. Gemini 2.5 Pro brought lower API rates and ongoing improvements. But here's the trap: "cheap" and "profitab" are different things.

I've seen this pattern repeatedly. As usage grows, so does your API bill. One day you realize you're losing money. Cost design isn't something to figure out later—it's something you decide now, before you build.

## The Real Cost of Gemini 2.5 Pro API

The official page says "Input at $1.50 per 1M tokens." But what does a real request actually cost?

| Token Type | Price (per 1M tokens) | Per 1,000 tokens |
|---|---|---|
| Input | $1.50 | $0.0015 |
| Output | $6.00 | $0.006 |
| Cache Hit | $0.375 | $0.000375 |
| Cache Write | $2.25 | $0.00225 |

Looks cheap, right? Let's calculate a realistic chat request.

**Scenario: A user sends a system prompt + conversation history + their question**

- System prompt: 1,000 tokens
- Chat history (5 recent exchanges): 2,000 tokens
- User query: 500 tokens
- **Total Input: 3,500 tokens → $0.00525**

- Model response: 800 tokens
- **Total Output: 800 tokens → $0.0048**

**Cost per request: $0.01025 (about ¥1.50)**

100 requests per day? That's $1.03/day or roughly $31/month. Per user doing 30 requests monthly? Under ¥50.

The critical insight: longer conversations pile up Input tokens.

## The Game Changer: Context Caching

For a personal paid chat service, implement **Context Caching** first.

Context Caching stores frequently-referenced system prompts or reference material. After the first call, subsequent calls to that cached content are dramatically discounted.

**Real example: AI coaching SaaS**

- Shared system prompt (framework, constraints): 2,000 tokens
- Cache this once (Write: 2,000 × $0.00225 = $0.0045)
- Every future request hitting that cache (Hit: 2,000 × $0.000375 = $0.00075)

**Over 40 uses:**
- Without cache: 2,000 × 40 × $0.0015 = $1.20
- With cache: $0.0045 + (39 × $0.00075) = $0.03375
- **Savings: 97.2% for cached content alone**

But Context Caching has constraints:

1. Cache validity window is 5 minutes (manage by session)
2. Explicitly specify which content to cache per request
3. Most effective with longer fixed texts (1,024+ tokens)

## Batch API: Another 50% Off

Next cost lever: **Batch API**.

Batch API bundles multiple requests and Google processes them during off-peak hours. Cost is 50% of standard API calls.

Trade-off: responses arrive within 24 hours, not milliseconds.

**Good fits:** overnight analysis users approve next morning, daily scheduled processing, features where users accept deferred results

**Poor fits:** real-time chat responses, users awaiting immediate answers

**Example: AI diary analyzer**

Users upload daily diaries. System analyzes them batch-style at night. Results email at 6 AM.

```javascript
// Batch API request
const batchRequest = {
  requests: [
    {
      custom_id: "user-123-diary-001",
      params: {
        model: "gemini-2.5-pro",
        systemInstruction: "Provide empathetic analysis of diary entries",
        contents: [{
          role: "user",
          parts: [{ text: diaryContent }]
        }]
      }
    },
    // More requests...
  ]
};

await batchService.processBatch(batchRequest, { priority: "BATCH" });
```

**Process 30,000 requests monthly (1,000 users × 30 days):**
- Standard API: 30,000 × $0.01 = $300
- Batch API: 30,000 × $0.005 = $150
- **Savings: 50% ($150/month)**

## Hidden Costs You'll Hit

Beyond unit pricing, implementation reveals these expenses:

**1. Token Miscalculation**

Returned token counts (especially for Japanese) differ from estimates. Build in buffer.

**2. Error Retries**

Network failures and rate limits trigger retries. Each is an extra API call.

Use exponential backoff. Monitor failure patterns.

**3. Model Price Changes**

Gemini 3 may shift pricing. Your current math assumes 2026 rates.
