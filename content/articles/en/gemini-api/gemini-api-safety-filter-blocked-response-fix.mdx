## When Your Gemini API Responses Get Blocked

If you've been working with the Gemini API, you may have run into one of these frustrating scenarios:

- The API response returns with `finishReason` set to `SAFETY` and no text content
- Accessing `response.text` throws a "response was blocked" error
- You see `BlockedReason.SAFETY` or `HARM_CATEGORY_*` warnings in your logs
- Perfectly legitimate questions about medicine, law, or history get rejected

These are all symptoms of the Gemini API's safety filters triggering on content that shouldn't be blocked. This guide walks you through identifying the root cause, configuring `safetySettings` properly, and refining your prompts to prevent false positives.

## Why Legitimate Requests Get Blocked

Gemini's safety filters are designed to prevent the generation of harmful content. However, several factors can cause them to over-trigger on perfectly valid requests.

### Default Thresholds Are Conservative

When you don't explicitly set `safetySettings`, all harm categories default to `BLOCK_MEDIUM_AND_ABOVE`. This means any content the model rates as "medium risk" or higher gets blocked—which catches a surprisingly wide range of educational, medical, and historical topics.

### Both Input and Output Are Screened

The safety filter evaluates **both** your prompt (input) and the model's generated response (output). Even if your prompt is completely benign, the model's attempt at an answer might trigger the filter. This dual screening is a common source of confusion.

### Misclassification Across Categories

Gemini evaluates content across four harm categories:

- **HARM_CATEGORY_HARASSMENT** — Targeting individuals or groups
- **HARM_CATEGORY_HATE_SPEECH** — Discriminatory language
- **HARM_CATEGORY_SEXUALLY_EXPLICIT** — Adult content
- **HARM_CATEGORY_DANGEROUS_CONTENT** — Instructions for harm

Misclassification happens regularly. A cybersecurity tutorial might be flagged under "dangerous content," or a medical explanation might trigger the "sexually explicit" filter due to anatomical terminology.

## How to Configure safetySettings Correctly

### Python SDK Example

```python
import google.generativeai as genai

genai.configure(api_key="YOUR_GEMINI_API_KEY")

# Customize safety settings
safety_settings = [
    {
        "category": "HARM_CATEGORY_HARASSMENT",
        "threshold": "BLOCK_ONLY_HIGH"  # Block only high-risk content
    },
    {
        "category": "HARM_CATEGORY_HATE_SPEECH",
        "threshold": "BLOCK_ONLY_HIGH"
    },
    {
        "category": "HARM_CATEGORY_SEXUALLY_EXPLICIT",
        "threshold": "BLOCK_MEDIUM_AND_ABOVE"  # Keep default for this category
    },
    {
        "category": "HARM_CATEGORY_DANGEROUS_CONTENT",
        "threshold": "BLOCK_ONLY_HIGH"
    },
]

model = genai.GenerativeModel(
    model_name="gemini-2.5-flash",
    safety_settings=safety_settings
)

response = model.generate_content("Explain the fundamentals of vulnerability assessment in cybersecurity")
print(response.text)
# Expected output: A detailed explanation of vulnerability assessment methods
```

### Available Threshold Options

- **BLOCK_NONE** — Disables the filter entirely (Vertex AI only)
- **BLOCK_ONLY_HIGH** — Blocks only high-probability harmful content (recommended)
- **BLOCK_MEDIUM_AND_ABOVE** — Blocks medium and high-risk content (default)
- **BLOCK_LOW_AND_ABOVE** — Blocks nearly everything flagged (strictest)

## Step-by-Step Debugging Guide

When a response gets blocked, your first priority is identifying exactly what triggered the filter.

### Step 1: Check the finishReason

```python
response = model.generate_content("Your prompt text here")

# Inspect the full response structure
for candidate in response.candidates:
    print(f"finishReason: {candidate.finish_reason}")
    # Display safety ratings
    for rating in candidate.safety_ratings:
        print(f"  {rating.category}: {rating.probability}")
```

If `finishReason` is `SAFETY`, check which category has a `HIGH` or `MEDIUM` probability rating.

### Step 2: Check the Prompt Feedback

If the input itself is being blocked, the `prompt_feedback` field will contain the details:

```python
if response.prompt_feedback:
    print(f"Prompt blocked: {response.prompt_feedback.block_reason}")
    for rating in response.prompt_feedback.safety_ratings:
        print(f"  {rating.category}: {rating.probability}")
```

### Step 3: Adjust the Problematic Category

Once you've identified the offending category, lower its threshold to `BLOCK_ONLY_HIGH` and retry:

```python
# Example: DANGEROUS_CONTENT was the trigger
safety_settings = [
    {"category": "HARM_CATEGORY_DANGEROUS_CONTENT", "threshold": "BLOCK_ONLY_HIGH"},
]
response = model.generate_content("Your prompt text", safety_settings=safety_settings)
```

## Prompt Engineering to Avoid Blocks

Sometimes adjusting `safetySettings` alone isn't enough. Refining your prompts can make a significant difference.

### Provide Clear Context

```
❌ Likely to be blocked:
"Explain how toxins affect the human body"

✅ With proper context:
"For a pharmacology course, explain the pharmacological mechanisms
of common medications, focusing on detoxification pathways
and clinical safety management."
```

### Use System Instructions to Declare Purpose

```python
model = genai.GenerativeModel(
    model_name="gemini-2.5-flash",
    system_instruction="""You are an educational assistant for healthcare professionals.
Provide medically accurate information and share knowledge useful in clinical settings.
Answer questions from an academic perspective.""",
    safety_settings=safety_settings
)
```

### Break Down Complex Requests

Sending a long, complex request in one shot can cause partial context to trigger the filter. Breaking sensitive topics into sequential, well-contextualized steps makes each individual request less likely to be flagged.

## Verifying Your Fix

After making changes, run a systematic check to confirm everything is working:

```python
def verify_safety_fix(model, test_prompts):
    """Helper function to verify safety settings adjustments"""
    results = []
    for prompt in test_prompts:
        try:
            response = model.generate_content(prompt)
            finish_reason = response.candidates[0].finish_reason if response.candidates else "NO_CANDIDATE"
            has_text = bool(response.text) if hasattr(response, 'text') else False
            results.append({
                "prompt": prompt[:50],
                "finish_reason": str(finish_reason),
                "has_text": has_text,
                "blocked": finish_reason == 2  # SAFETY = 2
            })
        except Exception as e:
            results.append({
                "prompt": prompt[:50],
                "error": str(e),
                "blocked": True
            })
    
    # Summary
    blocked_count = sum(1 for r in results if r.get("blocked"))
    print(f"Results: {len(results) - blocked_count}/{len(results)} passed")
    for r in results:
        status = "❌ BLOCKED" if r.get("blocked") else "✅ OK"
        print(f"  {status}: {r['prompt']}...")
    return results

# Run verification
test_prompts = [
    "Previously blocked prompt 1",
    "Previously blocked prompt 2",
    "Normal question (control)",
]
verify_safety_fix(model, test_prompts)
# Expected output:
# Results: 3/3 passed
#   ✅ OK: Previously blocked prompt 1...
#   ✅ OK: Previously blocked prompt 2...
#   ✅ OK: Normal question (control)...
```

## Best Practices to Prevent Future Blocks

Build these patterns into your production code to avoid safety filter issues down the road.

### Make Safety Settings Explicit in Your Code

Don't rely on defaults. Define your project's safety thresholds in a centralized configuration:

```python
# config/safety.py — Project-wide safety configuration
SAFETY_SETTINGS_PRODUCTION = [
    {"category": "HARM_CATEGORY_HARASSMENT", "threshold": "BLOCK_ONLY_HIGH"},
    {"category": "HARM_CATEGORY_HATE_SPEECH", "threshold": "BLOCK_ONLY_HIGH"},
    {"category": "HARM_CATEGORY_SEXUALLY_EXPLICIT", "threshold": "BLOCK_MEDIUM_AND_ABOVE"},
    {"category": "HARM_CATEGORY_DANGEROUS_CONTENT", "threshold": "BLOCK_ONLY_HIGH"},
]
```

### Implement Fallback Handling

Add graceful degradation when blocks occur in production:

```python
def safe_generate(model, prompt, max_retries=2):
    """Retry with contextual refinement on safety blocks"""
    for attempt in range(max_retries + 1):
        response = model.generate_content(prompt)
        if response.candidates and response.candidates[0].finish_reason \!= 2:
            return response.text
        
        if attempt < max_retries:
            # Add context to help the model understand intent
            prompt = f"This is an educational question. Please respond from an academic perspective.\n\n{prompt}"
    
    return "Sorry, this request could not be processed. Please try rephrasing your question."
```

### Log and Analyze Block Patterns

Track which prompts get blocked and why. Understanding the patterns in your specific use case lets you proactively adjust prompts and settings before users encounter issues.

## Frequently Asked Questions

### Q: Can I use BLOCK_NONE to bypass all safety filters?

`BLOCK_NONE` is only available on **Vertex AI** (Google Cloud's paid platform). If you're using the Google AI Studio free API key, specifying `BLOCK_NONE` will either throw an error or be silently ignored. The most permissive setting available on the free tier is `BLOCK_ONLY_HIGH`.

### Q: I've adjusted safetySettings but responses are still blocked. What else can I try?

Prompt engineering is your next best tool. Three approaches that consistently help: explicitly state the purpose of your question (education, research, business), use System Instructions to define the AI's role, and replace sensitive keywords with academic terminology. If none of these work, consider migrating to Vertex AI for more granular control.

### Q: Does relaxing safety filters put my application at risk?

Setting thresholds to `BLOCK_ONLY_HIGH` still blocks clearly harmful content. However, if your application accepts user input that gets sent directly to the API, you should add your own input validation and content moderation layer on top of Gemini's built-in filters.

### Q: My multimodal requests with images or video are also getting blocked. How do I fix that?

The same `safetySettings` apply to multimodal inputs, but images and video are automatically scanned and tend to trigger filters more readily than text-only requests. For a comprehensive guide to multimodal troubleshooting, check out the [Gemini Multimodal Input Errors Troubleshooting Guide](/articles/gemini-advanced/gemini-multimodal-input-errors-complete-troubleshooting-guide).
