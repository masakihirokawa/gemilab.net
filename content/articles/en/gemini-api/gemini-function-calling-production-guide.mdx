Function Calling is one of Gemini's most powerful features, but there's a meaningful gap between "code that runs" and "code that holds up in production." This guide covers the design decisions that fill that gap, based on practical experience building production Function Calling systems.

---

## How Function Calling Actually Works

Before diving into implementation, it's worth being precise about the flow:

1. Your app sends Gemini a set of function definitions alongside the user's message
2. If Gemini decides a function call is needed, it returns a `functionCall` response (not a text answer)
3. Your app executes the actual function and sends the result back to Gemini
4. Gemini uses the result to generate a final response

This exchange can repeat multiple times in a single turn — multi-turn Function Calling. Gemini might receive the first function's result and decide it needs another function call before it can answer.

---

## Function Schema Design: Where Accuracy Is Won or Lost

The quality of your function definitions determines how accurately Gemini uses them. Gemini reads your descriptions to decide when to call a function, which function to call, and what arguments to pass.

**Vague definition** — Gemini makes poor decisions:
```javascript
{
  name: "search",
  description: "Searches for something",
  parameters: {
    type: "object",
    properties: {
      query: { type: "string" }
    }
  }
}
```

**Specific definition** — Gemini makes good decisions:
```javascript
{
  name: "search_products",
  description: "Search the product database by name, category, or price range. Use when the user is looking for specific products or asking for a product listing. For inventory availability, use check_inventory instead.",
  parameters: {
    type: "object",
    properties: {
      query: {
        type: "string",
        description: "Search keyword (product name, category, etc.)"
      },
      max_price: {
        type: "number",
        description: "Maximum price in USD. Omit for no upper limit."
      },
      in_stock_only: {
        type: "boolean",
        description: "If true, return only in-stock products",
        default: false
      }
    },
    required: ["query"]
  }
}
```

The most important parts of the description: when to use the function and how it differs from similar functions. When multiple functions have overlapping scope, Gemini needs explicit boundaries to choose correctly.

## TypeScript Implementation

```typescript
import { GoogleGenerativeAI, FunctionDeclarationSchemaType } from "@google/generative-ai";

const genAI = new GoogleGenerativeAI("YOUR_GEMINI_API_KEY");

const tools = [
  {
    functionDeclarations: [
      {
        name: "get_weather",
        description:
          "Get current weather for a specified city. Returns temperature, conditions, and humidity. Use when the user asks about weather.",
        parameters: {
          type: FunctionDeclarationSchemaType.OBJECT,
          properties: {
            city: {
              type: FunctionDeclarationSchemaType.STRING,
              description: "City name to check weather for (e.g. Tokyo, London)",
            },
            unit: {
              type: FunctionDeclarationSchemaType.STRING,
              description: "Temperature unit: 'celsius' or 'fahrenheit'",
              enum: ["celsius", "fahrenheit"],
            },
          },
          required: ["city"],
        },
      },
    ],
  },
];

const functions: Record<string, (args: Record<string, unknown>) => Promise<unknown>> = {
  get_weather: async ({ city, unit = "celsius" }) => {
    const response = await fetchWeatherAPI(city as string, unit as string);
    return {
      city,
      temperature: response.temp,
      condition: response.weather,
      humidity: response.humidity,
    };
  },
};

async function chat(userMessage: string): Promise<string> {
  const model = genAI.getGenerativeModel({ model: "gemini-2.5-pro", tools });
  const chatSession = model.startChat({ history: [] });

  let response = await chatSession.sendMessage(userMessage);

  // Function Calling loop — capped at 10 iterations
  let loopCount = 0;
  while (loopCount < 10) {
    const candidate = response.response.candidates?.[0];
    if (\!candidate) break;

    const functionCallParts = candidate.content.parts.filter(
      (part) => "functionCall" in part
    );

    if (functionCallParts.length === 0) {
      return response.response.text();
    }

    const functionResponses = await Promise.all(
      functionCallParts.map(async (part) => {
        if (\!("functionCall" in part)) return null;
        const { name, args } = part.functionCall;

        if (\!functions[name]) {
          return {
            functionResponse: {
              name,
              response: { error: `Function '${name}' not found` },
            },
          };
        }

        try {
          const result = await functions[name](args as Record<string, unknown>);
          return { functionResponse: { name, response: result } };
        } catch (error) {
          return {
            functionResponse: {
              name,
              response: { error: `Execution failed: ${String(error)}` },
            },
          };
        }
      })
    );

    response = await chatSession.sendMessage(
      functionResponses.filter(Boolean) as Parameters<typeof chatSession.sendMessage>[0]
    );
    loopCount++;
  }

  return "The request became too complex to resolve. Try a more specific question.";
}
```

The loop cap is essential. One of the most expensive bugs in Function Calling is an infinite loop — Gemini repeatedly calling the same function and never reaching a text response. Without a limit, API costs can spike before you notice.

## Parallel Function Calling

Gemini 2.5 can request multiple functions simultaneously in a single response:

```
User: What's the weather in Tokyo and London?

Gemini responds:
[
  { functionCall: { name: "get_weather", args: { city: "Tokyo" } } },
  { functionCall: { name: "get_weather", args: { city: "London" } } }
]
```

The `Promise.all()` in the implementation above handles this automatically — both weather calls execute in parallel rather than sequentially.

For parallel calling to work well, functions should represent independent operations. Functions with dependencies (where B needs A's output) won't benefit from parallel execution.

## Error Handling

Function Calling errors fall into two categories that need different handling.

**Function execution errors** — the function was called but failed. Return the error as a response rather than throwing:

```typescript
try {
  const result = await functions[name](args);
  return { functionResponse: { name, response: result } };
} catch (error) {
  // Don't throw — send the error back to Gemini
  return {
    functionResponse: {
      name,
      response: {
        error: "Failed to retrieve data",
        reason: String(error),
        suggestion: "Please try again in a moment",
      },
    },
  };
}
```

Returning the error as a response lets Gemini understand the situation and generate an appropriate answer — "I wasn't able to get that information right now, but..." — rather than crashing.

**API errors** — the Gemini API call itself fails. Use exponential backoff for rate limits:

```typescript
async function sendMessageWithRetry(
  chatSession: ReturnType<typeof model.startChat>,
  message: Parameters<typeof chatSession.sendMessage>[0],
  maxRetries = 3
) {
  for (let attempt = 1; attempt <= maxRetries; attempt++) {
    try {
      return await chatSession.sendMessage(message);
    } catch (error) {
      if (attempt === maxRetries) throw error;

      const isRateLimit = String(error).includes("429") || String(error).includes("RESOURCE_EXHAUSTED");
      const delay = isRateLimit ? 1000 * Math.pow(2, attempt) : 500 * attempt;
      await new Promise(resolve => setTimeout(resolve, delay));
    }
  }
  throw new Error("Max retries exceeded");
}
```

## Debugging Function Calling Issues

**Gemini isn't calling the function**

The most common issue: a question that should trigger a function call gets a text-only response instead.

The usual cause is an ambiguous description that doesn't clearly state when the function should be used. Gemini defaults to generating text when it's uncertain.

Diagnose by forcing function calls:

```typescript
const model = genAI.getGenerativeModel({
  model: "gemini-2.5-pro",
  tools,
  toolConfig: {
    functionCallingConfig: { mode: "ANY" }, // force a function call
  },
});
```

If `ANY` mode works, the problem is in the description or Gemini's `AUTO` mode judgment. Refine the description or use `ANY` mode for specific use cases that always require a function.

**Over-calling**

Functions being called in situations where they shouldn't be. Add explicit negative conditions to the description:

```javascript
description: "Use only when the user is asking about specific products. Do not use for general questions or conversational messages."
```

**Debugging loop behavior**

Log each iteration's function calls to understand how Gemini is reasoning:

```typescript
let loopCount = 0;
while (loopCount < 10) {
  // ... (loop logic)
  console.log(`Loop ${loopCount}: functions called = ${functionCallParts.map(p => p.functionCall?.name).join(", ")}`);
  loopCount++;
}
```

## Production Configuration

Two configurations worth having in production:

```typescript
const model = genAI.getGenerativeModel({
  model: "gemini-2.5-pro",
  tools,
  generationConfig: {
    maxOutputTokens: 2048, // cap output costs
  },
});

// Request-level timeout
const controller = new AbortController();
const timeout = setTimeout(() => controller.abort(), 30_000); // 30 seconds

try {
  const response = await chatSession.sendMessage(message, { signal: controller.signal });
  clearTimeout(timeout);
  return response;
} catch (error) {
  clearTimeout(timeout);
  if ((error as Error).name === "AbortError") {
    throw new Error("Request timed out");
  }
  throw error;
}
```

## The Three Things That Matter

After building several production Function Calling systems, I keep coming back to the same lessons:

1. **Write descriptions that say when NOT to use the function.** Gemini's accuracy with function selection is mostly determined by the quality of the description.

2. **Always cap the loop.** Infinite Function Calling loops happen in production. The cap isn't optional.

3. **Return errors as responses, not exceptions.** Gemini handles error responses gracefully. Exceptions just crash the loop.

These three things are the difference between a system that "mostly works" and one that holds up reliably.
