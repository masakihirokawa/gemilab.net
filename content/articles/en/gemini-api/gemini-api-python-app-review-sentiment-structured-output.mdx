Gemini API has a feature called Structured Output that lets you pass a JSON schema and get a response guaranteed to match it. The moment I learned about this, the first use case that came to mind was app review analysis.

Feed in a review text, get back a sentiment score, problem category, and response priority as clean JSON — no spreadsheet copying required. Here's a working implementation with full Python code.

## The Problem Structured Output Solves

Trying to categorize app reviews with a plain prompt leads to inconsistent output. Sometimes you get "bug," sometimes "issue," sometimes "crash problem." Parsing that downstream is brittle.

Structured Output changes this. Gemini won't return anything outside your specified JSON schema, which means `response.parsed` is usable as-is. No cleanup step needed.

## Defining the Schema with Pydantic

The Gemini Python SDK accepts Pydantic models directly. Start with the data model:

```python
from pydantic import BaseModel
from typing import Literal
from enum import Enum

class ReviewCategory(str, Enum):
    BUG_REPORT = "bug_report"
    FEATURE_REQUEST = "feature_request"
    UX_FEEDBACK = "ux_feedback"
    PERFORMANCE = "performance"
    PRAISE = "praise"
    OTHER = "other"

class ReviewAnalysis(BaseModel):
    sentiment_score: float          # -1.0 (strong negative) to 1.0 (strong positive)
    category: ReviewCategory
    priority: Literal["high", "medium", "low"]
    key_issue: str                  # One-sentence summary of the core issue
    should_respond: bool            # True if a response might change the rating
    reasoning: str                  # Why this category and priority were chosen
```

The `reasoning` field is worth highlighting. Asking the model to explain its classification improves accuracy (a form of chain-of-thought) and makes it easy to audit results later when something looks off.

## The Analysis Function

```python
import google.generativeai as genai
from google.generativeai import GenerativeModel

def analyze_review(review_text: str, app_name: str = "this app") -> ReviewAnalysis:
    model = GenerativeModel(
        model_name="gemini-2.5-pro",
        generation_config=genai.GenerationConfig(
            response_mime_type="application/json",
            response_schema=ReviewAnalysis,
        )
    )
    
    prompt = f"""The following is a user review for "{app_name}":

Review text:
{review_text}

Analyze this review using these criteria:
- sentiment_score: continuous value from -1.0 (strongly negative) to 1.0 (strongly positive)
- priority: high = affects multiple users, medium = affects specific users, low = suggestions or minor feedback
- should_respond: true if the review is based on a misunderstanding, a fixed bug, or deserves acknowledgment
"""
    
    response = model.generate_content(prompt)
    return response.parsed
```

## Batch Processing Multiple Reviews

Calling the API one review at a time isn't efficient. Here's a batch version with basic rate limiting:

```python
from typing import List, Dict
import time

def analyze_reviews_batch(
    reviews: List[str],
    app_name: str = "this app",
    delay_seconds: float = 0.5
) -> List[Dict]:
    results = []
    
    for i, review_text in enumerate(reviews):
        try:
            analysis = analyze_review(review_text, app_name)
            results.append({
                "review": review_text,
                "analysis": analysis.model_dump(),
                "success": True
            })
        except Exception as e:
            results.append({
                "review": review_text,
                "error": str(e),
                "success": False
            })
        
        if i < len(reviews) - 1:
            time.sleep(delay_seconds)
    
    return results

# Usage example
sample_reviews = [
    "App keeps crashing every time I open it after the last update. Please fix this.",
    "Love the clean design\! Would be perfect with a widget for the home screen.",
    "Loading is way too slow. Even on WiFi it takes over 10 seconds.",
    "Use this every day. The interface is exactly what I was looking for.",
]

results = analyze_reviews_batch(sample_reviews, app_name="MyApp")

for r in results:
    if r["success"]:
        a = r["analysis"]
        print(f"Priority: {a['priority']} | Category: {a['category']} | Sentiment: {a['sentiment_score']:.2f}")
        print(f"  Issue: {a['key_issue']}")
        print(f"  Respond: {'Yes' if a['should_respond'] else 'No'}")
```

Sample output:

```
Priority: high | Category: bug_report | Sentiment: -0.85
  Issue: App crashes on launch after recent update
  Respond: Yes

Priority: low | Category: feature_request | Sentiment: 0.72
  Issue: Request for home screen widget
  Respond: No
```

## Exporting to Google Sheets

```python
import gspread
from google.oauth2.service_account import Credentials
from datetime import datetime

def export_to_sheets(results: List[Dict], spreadsheet_id: str):
    scopes = [
        "https://spreadsheets.google.com/feeds",
        "https://www.googleapis.com/auth/drive"
    ]
    creds = Credentials.from_service_account_file(
        "service_account.json", scopes=scopes
    )
    client = gspread.authorize(creds)
    sheet = client.open_by_key(spreadsheet_id).worksheet("review_analysis")
    
    rows = []
    for r in results:
        if not r["success"]:
            continue
        a = r["analysis"]
        rows.append([
            datetime.now().strftime("%Y-%m-%d"),
            r["review"][:100],
            a["sentiment_score"],
            a["category"],
            a["priority"],
            a["key_issue"],
            "Yes" if a["should_respond"] else "No",
            a["reasoning"]
        ])
    
    sheet.append_rows(rows)
    print(f"✅ Exported {len(rows)} reviews")
```

## What Two Months of Use Taught Me

The `reasoning` field doubles as a debugging tool. When a classification looks wrong, the reasoning usually shows which part of the review text the model focused on — which makes prompt tuning much faster.

The `should_respond` predictions have been more accurate than I expected. They're good enough to narrow down the candidates for human review, even if I wouldn't automate the actual response decision.

Cost-wise: Gemini 2.5 Pro runs roughly $0.002 per review as of April 2026. Processing 200 reviews costs about $0.40. Well within free tier limits for most indie developers.

The real value of Structured Output isn't just the clean JSON — it's that you can trust the output structure enough to build automated pipelines on top of it. The moment you remove the "parse and hope" step, the whole workflow becomes substantially more reliable.
