## What Are Token Limit Exceeded Errors?

When sending large documents or lengthy conversation histories to the Gemini API, you may encounter errors like these:

```
google.api_core.exceptions.InvalidArgument: 400
Request contains too many tokens. Please reduce the input size.
```

```json
{
  "error": {
    "code": 400,
    "message": "Request payload size exceeds the limit: XXXXX tokens > YYYYY token limit",
    "status": "INVALID_ARGUMENT"
  }
}
```

This error means your request's token count exceeds the model's input limit. Every Gemini model has a context window — the maximum combined size of input tokens plus output tokens it can handle. When you go over this limit, the API rejects the request outright.

This is one of the most common issues developers face when working with large-scale text processing, multi-file analysis, or extended chat sessions. This guide walks you through identifying the root cause, implementing fixes, and preventing the error from happening again.

## Understanding Model Token Limits

Before troubleshooting, you need to know the exact limits of the model you're using. Here are the key figures as of April 2026:

- **Gemini 2.5 Pro**: 1,048,576 input tokens (~1M), 65,536 output tokens
- **Gemini 2.5 Flash**: 1,048,576 input tokens, 65,536 output tokens
- **Gemini 2.0 Flash**: 1,048,576 input tokens, 8,192 output tokens
- **Gemini 1.5 Pro**: 2,097,152 input tokens (~2M), 8,192 output tokens
- **Gemini 1.5 Flash**: 1,048,576 input tokens, 8,192 output tokens

An important detail: the context window covers input plus output combined. If you send 950,000 tokens to a model with a 1M context window and request 65,536 output tokens, the total exceeds the limit and you'll get an error.

Model specs change frequently, so always verify current limits in the [official documentation](https://ai.google.dev/gemini-api/docs/models/gemini).

## Five Common Causes of Token Limit Errors

Token limit errors typically stem from one of five patterns. Understanding which one applies to your situation will guide you to the right fix.

### Cause 1: Input Text Is Simply Too Large

This is the most frequent cause. Sending entire codebases, lengthy PDF documents, or multiple files at once can easily blow past the limit. Multimodal inputs (images, videos) are particularly tricky because their token cost is often higher than developers expect.

### Cause 2: Chat History Accumulation

In multi-turn conversations, if you include the full history in every request's `contents` array, token usage grows with each exchange. A conversation that starts with a few hundred tokens can balloon to hundreds of thousands over time.

### Cause 3: Oversized System Instructions

Detailed `system_instruction` content — including elaborate rules, extensive examples, and formatting templates — counts toward your input tokens. A system prompt with thousands of words can eat a significant chunk of your token budget.

### Cause 4: Too Many Function Definitions

Tool definitions in the `tools` parameter consume tokens too. If you've defined dozens of functions with detailed parameter schemas, that alone can use thousands or tens of thousands of tokens.

### Cause 5: Output Token Misconfiguration

Setting `max_output_tokens` to an excessively high value can push the input-plus-output total beyond the context window, even if your input alone would fit.

## Step-by-Step Solutions

Once you've identified the cause, apply the appropriate fix from the steps below.

### Step 1: Count Tokens Before Sending Requests

The `countTokens` API lets you check exactly how many tokens your request will use before sending it. This is your first line of defense.

```python
# Python: Count tokens before sending
from google import genai

client = genai.Client(api_key="YOUR_API_KEY")

# Count tokens for a text input
response = client.models.count_tokens(
    model="gemini-2.5-flash",
    contents="Your text content goes here"
)
print(f"Token count: {response.total_tokens}")
# Example output: Token count: 1523

# Count tokens for a full chat history
chat_contents = [
    {"role": "user", "parts": [{"text": "Hello"}]},
    {"role": "model", "parts": [{"text": "Hi! How can I help you?"}]},
    {"role": "user", "parts": [{"text": "Please summarize this long document..."}]},
]
response = client.models.count_tokens(
    model="gemini-2.5-flash",
    contents=chat_contents
)
print(f"Total conversation tokens: {response.total_tokens}")
# Example output: Total conversation tokens: 4821
```

```javascript
// JavaScript: Count tokens before sending
const { GoogleGenAI } = require("@google/genai");

const ai = new GoogleGenAI({ apiKey: "YOUR_API_KEY" });

async function checkTokens() {
  const response = await ai.models.countTokens({
    model: "gemini-2.5-flash",

  });
  console.log(`Token count: ${response.totalTokens}`);
  // Example output: Token count: 1523
}

checkTokens();
```

### Step 2: Split Large Inputs into Chunks

When a document exceeds the token limit, break it into manageable chunks and process each one separately.

```python
# Python: Chunk large text for processing
from google import genai

client = genai.Client(api_key="YOUR_API_KEY")

def split_text_by_tokens(text, max_tokens=500000):
    """Split text into chunks that fit within the token limit."""
    paragraphs = text.split("\n\n")
    chunks = []
    current_chunk = ""

    for para in paragraphs:
        test_chunk = current_chunk + "\n\n" + para if current_chunk else para

        # Check token count
        count_response = client.models.count_tokens(
            model="gemini-2.5-flash",
            contents=test_chunk
        )

        if count_response.total_tokens > max_tokens and current_chunk:
            chunks.append(current_chunk)
            current_chunk = para
        else:
            current_chunk = test_chunk

    if current_chunk:
        chunks.append(current_chunk)

    return chunks

# Usage
long_document = open("large_document.txt", "r").read()
chunks = split_text_by_tokens(long_document)

summaries = []
for i, chunk in enumerate(chunks):
    response = client.models.generate_content(
        model="gemini-2.5-flash",
        contents=f"Summarize the key points of the following text:\n\n{chunk}"
    )
    summaries.append(response.text)
    print(f"Chunk {i+1}/{len(chunks)} processed")

# Combine chunk summaries into a final summary
final_response = client.models.generate_content(
    model="gemini-2.5-flash",
    contents=f"Combine these partial summaries into a cohesive overall summary:\n\n{'---'.join(summaries)}"
)
print(final_response.text)
```

### Step 3: Manage Chat History with a Sliding Window

For long-running conversations, implement a sliding window that automatically trims old messages when the token count gets too high.

```python
# Python: Sliding window chat history management
from google import genai

client = genai.Client(api_key="YOUR_API_KEY")
MODEL = "gemini-2.5-flash"
MAX_HISTORY_TOKENS = 800000  # ~80% of the limit

chat_history = []

def add_and_trim_history(role, text):
    """Add a message and trim old ones if tokens exceed the limit."""
    chat_history.append({"role": role, "parts": [{"text": text}]})

    # Check current token count
    count = client.models.count_tokens(
        model=MODEL,
        contents=chat_history
    )

    # Remove oldest message pairs until under the limit
    while count.total_tokens > MAX_HISTORY_TOKENS and len(chat_history) > 2:
        chat_history.pop(0)  # Remove oldest user message
        chat_history.pop(0)  # Remove oldest model response
        count = client.models.count_tokens(
            model=MODEL,
            contents=chat_history
        )

    print(f"Current tokens: {count.total_tokens} / {MAX_HISTORY_TOKENS}")

def chat(user_message):
    """Chat with automatic token management."""
    add_and_trim_history("user", user_message)

    response = client.models.generate_content(
        model=MODEL,
        contents=chat_history
    )

    assistant_message = response.text
    add_and_trim_history("model", assistant_message)
    return assistant_message

# Usage
print(chat("How do I use the Gemini API?"))
print(chat("Show me a Python code example"))
# ...conversation continues with automatic trimming
```

### Step 4: Use Context Caching for Repeated Content

If you're sending the same reference documents or system instructions across multiple requests, context caching dramatically reduces redundant token usage and costs.

```python
# Python: Context caching for repeated content
from google import genai
from google.genai import types
import datetime

client = genai.Client(api_key="YOUR_API_KEY")

# Cache a large reference document
large_doc = open("reference_manual.txt", "r").read()

cache = client.caches.create(
    model="gemini-2.5-flash",
    config=types.CreateCachedContentConfig(
        display_name="Reference Manual Cache",
        system_instruction="You are a technical documentation expert.",
        contents=[{"role": "user", "parts": [{"text": large_doc}]}],
        ttl=datetime.timedelta(hours=1),  # Cache lifetime
    ),
)

print(f"Cache created: {cache.name}")
print(f"Cached tokens: {cache.usage_metadata.total_token_count}")

# Use the cache (no input token cost for cached content)
response = client.models.generate_content(
    model="gemini-2.5-flash",
    contents="Summarize Chapter 3 of the manual",
    config=types.GenerateContentConfig(
        cached_content=cache.name
    ),
)
print(response.text)
```

## Verifying the Fix

After applying your changes, confirm the issue is resolved with these checks:

1. **Pre-flight token check**: Use `countTokens` to verify your input stays below 90% of the model's limit.
2. **Test with small inputs**: Confirm requests succeed with short text first.
3. **Scale up gradually**: Incrementally increase input size and watch for boundary behavior.
4. **Test error handling**: Intentionally send an oversized request to confirm your `try/except` catches it properly.

```python
# Verification: Test error handling
from google import genai
from google.api_core import exceptions

client = genai.Client(api_key="YOUR_API_KEY")

def safe_generate(text, model="gemini-2.5-flash"):
    """Generate content with built-in token limit protection."""
    # Pre-flight check
    count = client.models.count_tokens(model=model, contents=text)
    print(f"Input tokens: {count.total_tokens}")

    if count.total_tokens > 900000:  # ~90% of limit
        print("Warning: Token count is near the limit. Consider splitting the input.")

    try:
        response = client.models.generate_content(
            model=model,
            contents=text
        )
        print("Request succeeded")
        return response.text
    except exceptions.InvalidArgument as e:
        print(f"Token limit exceeded: {e}")
        return None
    except exceptions.ResourceExhausted as e:
        print(f"Rate limited: {e}")
        return None

# Test
result = safe_generate("Tell me about the Gemini API")
print(result)
# Example output:
# Input tokens: 15
# Request succeeded
```

## Best Practices for Prevention

Build these practices into your development workflow to avoid token limit errors entirely.

**Always count tokens before sending**: Add a `countTokens` check before every API call and log a warning when usage exceeds 90% of the limit. In production, automate this as middleware or a wrapper function.

**Implement automatic history trimming**: For multi-turn conversations, the sliding window approach from Step 3 is essential. Manage history by token count, not by message count — a single long message can use more tokens than dozens of short ones.

**Choose the right model for the job**: Not every task needs the largest model. Use Gemini 2.5 Flash for quick questions and Gemini 2.5 Pro for heavy document processing. Matching model to workload keeps you well within limits.

**Keep system instructions lean**: If your system instructions run thousands of words, trim them. Models respond better to concise, clear rules than to walls of examples. Fewer tokens in system instructions means more room for actual content.

**Minimize function definitions per request**: Only include tool definitions that the current request actually needs. Instead of passing all 50 tools every time, create focused tool sets for different task types.

## Frequently Asked Questions

### Q1: How are tokens counted for images and videos?

Images are converted to tokens based on resolution. A typical image costs about 258 tokens (fixed). High-resolution images are tiled, with each tile costing 258 tokens. Video input costs approximately 263 tokens per second. Always use the `countTokens` API to get exact counts for multimodal inputs.

### Q2: Will switching to a model with a larger context window solve the problem?

It can help in many cases. Gemini 2.5 Pro supports up to 1 million input tokens, which is sufficient for most use cases. However, larger context windows tend to increase response latency. Optimizing your input is usually a better long-term strategy than simply upgrading to a bigger model.

### Q3: What happens if I don't set max_output_tokens?

The model uses its default value (typically 8,192 tokens). Even without an explicit setting, the context window calculation accounts for potential output. Setting this parameter explicitly to match your actual needs helps avoid unexpected limit issues.

### Q4: Do files uploaded via the File API count toward the token limit?

Yes, files uploaded through the File API are tokenized and count toward the context window. When uploading multiple large files, use `countTokens` to check the total beforehand and split processing across multiple requests if needed.

### Q5: Why does the error message show a different token count than countTokens?

This is a known discrepancy. The `countTokens` API counts your text content, but the actual request includes additional internal metadata — system instructions, tool definitions, safety settings, and message framing. The real token usage is slightly higher than what `countTokens` reports. That's why we recommend staying below 90% of the limit as a safety margin.
