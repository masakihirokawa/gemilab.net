Starting out with Google ADK, the moment that trips up most developers isn't the architecture or the agent design — it's when the code looks right, but nothing works. Official docs don't cover every edge case, and community resources are still sparse for ADK specifically.

This guide walks through the most common errors you'll hit in ADK development, with real error messages, root causes, and concrete fixes.

---

## Installation Errors

### `pip install google-adk` fails

One of the first hurdles when installing ADK is dependency conflicts with existing Google AI packages.

```
ERROR: Cannot install google-adk because these package versions have conflicting dependencies.
```

**Cause**: An older version of `google-generativeai` or `google-genai` is already installed and conflicts with what ADK requires.

**Fix**:

```bash
# Remove all existing Google AI packages
pip uninstall google-generativeai google-genai google-adk -y

# Create a fresh virtual environment
python -m venv adk-env
source adk-env/bin/activate  # Windows: adk-env\Scripts\activate

pip install google-adk
```

Installing ADK into a shared global environment is asking for trouble. Always use a dedicated virtual environment per project.

### Python version mismatch

```
ERROR: Package 'google-adk' requires a different Python: 3.9.x not in '>=3.10'
```

ADK requires Python 3.10 or higher. Check your version with `python --version` and upgrade if needed using pyenv or the official Python installer.

```bash
python --version  # Must be 3.10+
pip install --upgrade pip
pip install google-adk
```

## Authentication and API Key Errors

Authentication issues are by far the most common cause of ADK failures when starting a new project.

### `DefaultCredentialsError`

```
google.auth.exceptions.DefaultCredentialsError: Could not automatically determine credentials.
```

**Cause**: ADK can't find Google credentials. You need either the `GOOGLE_API_KEY` environment variable or Application Default Credentials (ADC) set up.

**Fix for Gemini API key**:

```python
import os
os.environ["GOOGLE_API_KEY"] = "YOUR_GEMINI_API_KEY"

# Better: manage via .env file
from dotenv import load_dotenv
load_dotenv()

from google.adk.agents import Agent
```

**Fix for Vertex AI**:

```bash
gcloud auth application-default login
export GOOGLE_CLOUD_PROJECT="your-project-id"
export GOOGLE_CLOUD_LOCATION="us-central1"
```

### Wrong model name

```
google.api_core.exceptions.NotFound: 404 models/gemini-pro is not found
```

ADK requires full model names, not the short aliases used in older SDKs.

```python
# ❌ Old-style shorthand
agent = Agent(model="gemini-pro")

# ✅ Current full model names (as of 2026)
agent = Agent(model="gemini-2.5-flash")
# or
agent = Agent(model="gemini-2.5-pro")
```

## Tool Definition Errors

### Missing type annotations cause silent failures

This is one of the most common reasons for "my tool isn't being called" complaints — and the fix is straightforward once you know what to look for.

```python
# ❌ No type annotations — ADK can't infer the schema, tool behaves unpredictably
def search_weather(city):
    return f"Searching weather for {city}..."

# ✅ With type annotations — ADK generates the correct JSON schema
def search_weather(city: str) -> str:
    """Search for weather information in the specified city.
    
    Args:
        city: The name of the city to search (e.g., Tokyo, London)
    
    Returns:
        A string with weather information
    """
    return f"Searching weather for {city}..."
```

The `Args:` section in the docstring matters too — ADK passes this to the LLM as the tool description. Without a clear description, Gemini may not know when to invoke the tool and will skip it entirely.

### Non-serializable types in tool arguments

```
TypeError: Object of type datetime is not JSON serializable
```

Tool arguments must be JSON-serializable types. This means `datetime`, `set`, and custom classes can't be passed directly.

```python
# ❌ datetime directly in the signature
def get_schedule(date: datetime) -> str:
    ...

# ✅ Accept a string, parse inside the function
def get_schedule(date_str: str) -> str:
    """Retrieve the schedule for a given date.
    
    Args:
        date_str: Date in ISO format (e.g., "2026-04-16")
    
    Returns:
        Schedule information for that date
    """
    from datetime import datetime
    date = datetime.strptime(date_str, "%Y-%m-%d")
    return f"Schedule for {date.strftime('%B %d, %Y')}"
```

## Session Management Errors

### `InMemorySessionService` resets every time

When building a conversational agent, sessions silently resetting is a common frustration. The usual culprit is generating a new session ID on each invocation.

```python
from google.adk.sessions import InMemorySessionService

session_service = InMemorySessionService()

# ❌ Generates a new session ID every time — context is lost
import uuid
session_id = str(uuid.uuid4())

# ✅ Use a stable session ID tied to the user or device
session_id = "user_123_session"  # Based on user ID, device ID, etc.
```

Keep in mind that `InMemorySessionService` doesn't survive process restarts. For persistent sessions in production, use `VertexAISessionService` or implement your own database-backed session store.

## Multi-Agent Routing Issues

When combining multiple subagents with `SequentialAgent` or `ParallelAgent`, getting the orchestrator to route tasks correctly is one of the trickier aspects of ADK.

### Vague descriptions cause routing failures

The orchestrator uses each subagent's `description` to decide which one to call. Vague descriptions mean the LLM can't distinguish between agents and may pick the wrong one — or none at all.

```python
from google.adk.agents import Agent

# ❌ Too vague — what does "get information" even mean?
search_agent = Agent(
    name="search_agent",
    model="gemini-2.5-flash",
    description="An agent that gets information.",
    tools=[search_web]
)

# ✅ Specific and actionable
search_agent = Agent(
    name="search_agent",
    model="gemini-2.5-flash",
    description="Executes web searches to retrieve up-to-date information. Use this agent for news, weather, prices, or any task requiring external data not available in training.",
    tools=[search_web]
)
```

Think of `description` as a routing rule written in natural language. The more clearly you describe what the agent does and when to use it, the better the orchestrator performs.

### Agents that loop without stopping

If an `LlmAgent` keeps calling tools without concluding, it usually means the instruction doesn't include a clear exit condition.

```python
agent = Agent(
    name="research_agent",
    model="gemini-2.5-pro",
    instruction="""
    Answer the user's question using the available tools.
    
    Important: Once you have a complete answer, respond with:
    "Research complete: [your answer here]"
    Do not call any more tools after providing the final answer.
    """,  # ← Clear termination instruction
    tools=[search_web, get_data]
)
```

## Streaming Output Issues

### Events not producing text output

When using `runner.run_async`, each event has a type — and printing the raw event object won't give you the text content you expect.

```python
import asyncio
from google.adk.runners import Runner
from google.adk.sessions import InMemorySessionService

async def run_agent():
    session_service = InMemorySessionService()
    runner = Runner(agent=agent, session_service=session_service)
    
    # ❌ Printing raw events produces little useful output
    async for event in runner.run_async(
        user_id="user_1",
        session_id="session_1",
        new_message={"role": "user", "parts": [{"text": "What's the weather in Tokyo?"}]}
    ):
        print(event)  # Often prints None or opaque object
    
    # ✅ Check event type before processing
    async for event in runner.run_async(
        user_id="user_1",
        session_id="session_1",
        new_message={"role": "user", "parts": [{"text": "What's the weather in Tokyo?"}]}
    ):
        if event.is_final_response():
            print(event.content.parts[0].text)
        elif event.content and event.content.parts:
            for part in event.content.parts:
                if hasattr(part, "text") and part.text:
                    print(part.text, end="", flush=True)

asyncio.run(run_agent())
```

## Jupyter Notebook: `asyncio.run()` Error

Jupyter already runs an event loop, so calling `asyncio.run()` inside a notebook raises:

```
RuntimeError: This event loop is already running.
```

**Fix**:

```python
import nest_asyncio
nest_asyncio.apply()  # Allow nested event loops

# In Jupyter, you can use await directly in a cell
async def run_agent():
    # your agent code here
    pass

await run_agent()
```

Install via `pip install nest_asyncio` if not already available.

## Debugging Tips

When something isn't working as expected, the fastest path to a fix is turning on debug logging to see exactly what ADK is doing internally.

```python
import logging

logging.basicConfig(level=logging.DEBUG)
logging.getLogger("google.adk").setLevel(logging.DEBUG)
```

This reveals the prompts being sent to the model, which tools are being called and with what arguments, and how events are flowing through the system. Most "mysterious behavior" becomes obvious once you can see the actual LLM inputs.

The ADK Web UI (`adk web` command) is also worth using during development. It gives you a visual view of agent execution that's much easier to interpret than raw log output when debugging multi-agent flows.
