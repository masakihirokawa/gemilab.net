## The Memory Wall Every ADK Developer Hits in Week One

If you've started building an AI assistant using Google ADK and Gemini 2.5 Pro, you've probably run into at least one of these:

- "Why does user B see user A's conversation history?"
- "All my conversation data disappeared when I restarted the app."
- "API costs are skyrocketing as conversations get longer."
- "I'm getting a session-not-found error even though I set the same user_id."

Every one of these is rooted in a misunderstanding of **how SessionService works**. The official documentation is accurate but minimal — it gets you to "working code" without bridging the gap to "production-ready code." That gap is larger than it looks.

This guide gives you the complete path from understanding ADK's session architecture all the way to SQLite persistence, conversation compression, multi-user isolation, and FastAPI integration. All code examples are tested and copy-paste ready.

## Understanding ADK's Session Architecture

The `Runner` class is the execution backbone of ADK. The `session_service` parameter you pass during initialization determines how the agent "remembers" conversations.

Here's what a session actually looks like internally:

```
Session
├── app_name: str          # Application identifier
├── user_id: str           # User identifier (key to multi-user isolation)
├── id: str                # Session identifier (one user can have many)
├── events: List[Event]    # Full conversation history as event chain
└── state: Dict            # Arbitrary session-scoped key-value state
```

The relationship between `user_id` and `session_id` is critical. One user can hold multiple sessions, but each session belongs to exactly one user. Designing these two fields carefully lets you handle cases like: "the same user accessing from two devices," "one user maintaining parallel conversation threads," or "a user explicitly resetting their conversation."

ADK provides three SessionService implementations:

**InMemorySessionService**: Stores conversations in process memory. Great for prototypes, tests, and small single-process apps. All data disappears on restart.

**VertexAiSessionService**: Persists conversations in Google Cloud's Vertex AI backend. Built for enterprise and large-scale workloads. Requires a GCP project and billing setup.

**Custom Implementation (extending BaseSessionService)**: Your own persistence layer using SQLite, PostgreSQL, or any storage you choose. The most practical option for indie developers and small-to-medium projects — highest control, easiest to migrate.

A realistic roadmap for indie developers going to production: `InMemorySessionService` → custom `SQLiteSessionService` → PostgreSQL if and when you need to scale.

## Code Example 1: InMemorySessionService — Feel the Difference

Start with the simplest possible setup to understand what session management actually does for you.

```python
import asyncio
import os
from google.adk.agents import Agent
from google.adk.runners import Runner
from google.adk.sessions import InMemorySessionService
from google.genai import types

# Set your API key: os.environ["GOOGLE_API_KEY"] = "YOUR_GEMINI_API_KEY"

assistant = Agent(
    model="gemini-2.5-pro",
    name="personal_assistant",
    description="A personal assistant that remembers context across turns",
    instruction="""You are a helpful, warm personal assistant.
Reference past conversation context when answering questions.
Remember the user's name, background, goals, and preferences as they come up.
Always respond in a friendly, conversational tone.""",
)

async def main():
    session_service = InMemorySessionService()

    runner = Runner(
        agent=assistant,
        app_name="my_assistant_app",
        session_service=session_service,
    )

    # Each user_id gets its own isolated conversation space
    user_id    = "user_tanaka_001"
    session_id = "main_session"

    await session_service.create_session(
        app_name="my_assistant_app",
        user_id=user_id,
        session_id=session_id,
    )

    # Three-turn conversation to verify context retention
    messages = [
        "Hi\! I'm Tanaka. I just started learning Python.",
        "Can you explain how to use lists?",
        "How do I loop through the list you just showed me?",
    ]

    for message in messages:
        print(f"\n👤 Tanaka: {message}")

        content = types.Content(
            role="user",
            parts=[types.Part(text=message)]
        )

        async for event in runner.run_async(
            user_id=user_id,
            session_id=session_id,
            new_message=content,
        ):
            if event.is_final_response() and event.content:
                print(f"🤖 Assistant: {event.content.parts[0].text[:300]}...")

if __name__ == "__main__":
    asyncio.run(main())
```

When you run this, the third response — "the list you just showed me" — will be answered with specific reference to the explanation from turn two. Gemini 2.5 Pro's strong contextual understanding means it naturally tracks that Tanaka is a Python beginner and adapts accordingly.

**What to expect:**
- Turn 1: "Nice to meet you, Tanaka\! So you're just getting started with Python..."
- Turn 2: A beginner-friendly list explanation with concrete examples
- Turn 3: "Sure\! Here's how to loop through the list from our last example..."

The important caveat: **restart the Python process and all of this disappears.** Close the terminal, redeploy the app, and the assistant has never met Tanaka before.

## Code Example 2: SQLite Persistence — Remember Users After Restarts

For anything beyond a demo, you need to persist conversation history to a database. You do this by extending ADK's `BaseSessionService` with a custom implementation.

```python
import asyncio
import json
import sqlite3
import uuid
from typing import Optional
from google.adk.sessions.base_session_service import BaseSessionService

class SQLiteSessionService(BaseSessionService):
    """Production-ready SessionService backed by SQLite.
    
    Safe to use from prototype to moderate production scale.
    Swap the storage backend for PostgreSQL when you need to scale out.
    """

    def __init__(self, db_path: str = "assistant_sessions.db"):
        self.db_path = db_path
        self._init_db()

    def _init_db(self):
        """Initialize tables (idempotent — safe to call multiple times)."""
        with sqlite3.connect(self.db_path) as conn:
            conn.execute("""
                CREATE TABLE IF NOT EXISTS sessions (
                    app_name   TEXT NOT NULL,
                    user_id    TEXT NOT NULL,
                    session_id TEXT NOT NULL,
                    state      TEXT DEFAULT '{}',
                    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
                    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
                    PRIMARY KEY (app_name, user_id, session_id)
                )
            """)
            conn.execute("""
                CREATE TABLE IF NOT EXISTS events (
                    id          INTEGER PRIMARY KEY AUTOINCREMENT,
                    app_name    TEXT NOT NULL,
                    user_id     TEXT NOT NULL,
                    session_id  TEXT NOT NULL,
                    event_json  TEXT NOT NULL,
                    created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
                    FOREIGN KEY (app_name, user_id, session_id)
                        REFERENCES sessions(app_name, user_id, session_id)
                        ON DELETE CASCADE
                )
            """)
            conn.execute("""
                CREATE INDEX IF NOT EXISTS idx_events_session
                    ON events(app_name, user_id, session_id)
            """)
            conn.commit()

    async def create_session(
        self,
        *,
        app_name: str,
        user_id: str,
        session_id: Optional[str] = None,
        state: Optional[dict] = None,
    ):
        if session_id is None:
            session_id = str(uuid.uuid4())

        with sqlite3.connect(self.db_path) as conn:
            conn.execute(
                """INSERT OR IGNORE INTO sessions
                   (app_name, user_id, session_id, state)
                   VALUES (?, ?, ?, ?)""",
                (app_name, user_id, session_id, json.dumps(state or {}))
            )
            conn.commit()

        from google.adk.sessions.in_memory_session_service import Session
        return Session(
            app_name=app_name,
            user_id=user_id,
            id=session_id,
            state=state or {},
            events=[],
        )

    async def get_session(
        self,
        *,
        app_name: str,
        user_id: str,
        session_id: str,
        config=None,
    ):
        with sqlite3.connect(self.db_path) as conn:
            cursor = conn.execute(
                """SELECT state FROM sessions
                   WHERE app_name=? AND user_id=? AND session_id=?""",
                (app_name, user_id, session_id)
            )
            row = cursor.fetchone()

        if not row:
            return None  # Return None, not an exception

        state = json.loads(row[0])

        with sqlite3.connect(self.db_path) as conn:
            cursor = conn.execute(
                """SELECT event_json FROM events
                   WHERE app_name=? AND user_id=? AND session_id=?
                   ORDER BY id ASC""",
                (app_name, user_id, session_id)
            )
            event_rows = cursor.fetchall()

        events = []
        for event_row in event_rows:
            try:
                events.append(json.loads(event_row[0]))
            except Exception:
                pass  # Skip corrupted entries silently

        from google.adk.sessions.in_memory_session_service import Session
        return Session(
            app_name=app_name,
            user_id=user_id,
            id=session_id,
            state=state,
            events=events,
        )

    async def append_event(self, session, event):
        """Write a new event to DB and update the session timestamp."""
        try:
            event_data = (
                event.model_dump()
                if hasattr(event, "model_dump")
                else {"raw": str(event)}
            )
        except Exception:
            event_data = {"raw": str(event)}

        with sqlite3.connect(self.db_path) as conn:
            conn.execute(
                """INSERT INTO events (app_name, user_id, session_id, event_json)
                   VALUES (?, ?, ?, ?)""",
                (
                    session.app_name, session.user_id, session.id,
                    json.dumps(event_data, ensure_ascii=False)
                )
            )
            conn.execute(
                """UPDATE sessions SET updated_at=CURRENT_TIMESTAMP
                   WHERE app_name=? AND user_id=? AND session_id=?""",
                (session.app_name, session.user_id, session.id)
            )
            conn.commit()
        return event

    async def update_session_state(
        self,
        *,
        app_name: str,
        user_id: str,
        session_id: str,
        state: dict,
    ):
        """Update session state — used for storing conversation summaries."""
        with sqlite3.connect(self.db_path) as conn:
            conn.execute(
                """UPDATE sessions
                   SET state=?, updated_at=CURRENT_TIMESTAMP
                   WHERE app_name=? AND user_id=? AND session_id=?""",
                (
                    json.dumps(state, ensure_ascii=False),
                    app_name, user_id, session_id
                )
            )
            conn.commit()
```

Here's the idempotent startup pattern to use with this service:

```python
async def start_persistent_session():
    """Start or resume a persistent assistant session."""
    session_service = SQLiteSessionService(db_path="./my_assistant.db")

    runner = Runner(
        agent=assistant,
        app_name="my_assistant_app",
        session_service=session_service,
    )

    user_id    = "user_tanaka_001"
    session_id = "main_session"

    # Check for existing session, create only if missing
    session = await session_service.get_session(
        app_name="my_assistant_app",
        user_id=user_id,
        session_id=session_id,
    )
    if session is None:
        await session_service.create_session(
            app_name="my_assistant_app",
            user_id=user_id,
            session_id=session_id,
        )
        print("✅ New session started")
    else:
        print(f"✅ Resumed existing session ({len(session.events)} events)")

    return runner, user_id, session_id
```

Run this two days in a row and the second run prints "Resumed existing session." The `my_assistant.db` file is your persistence layer — it survives restarts, redeployments, and process kills.

**A note on compatibility**: The `append_event` method's internal event format can change between ADK releases. Before applying this to production, verify the event structure matches your ADK version's release notes.

## Code Example 3: Conversation Compression to Stop Cost Explosions

Once you've got persistent storage, a new problem emerges: **API costs grow with conversation length.** Every request sends the full conversation history as context. At 50 turns, a single user message costs 50 turns' worth of tokens. Scale that to 100 users averaging 20 turns per day and your monthly bill becomes a nasty surprise.

The solution is **Conversation Summarization** — compress old history into a summary instead of deleting it.

```python
import asyncio
from google.genai import Client, types as genai_types

class ConversationCompressor:
    """Summarizes old conversation history using Gemini 2.5 Pro."""

    def __init__(
        self,
        model: str = "gemini-2.5-pro",
        max_raw_events: int = 30,     # Compress when events exceed this count
        min_events_to_keep: int = 8,  # Always keep the N most recent events raw
    ):
        self.client = Client()
        self.model = model
        self.max_raw_events = max_raw_events
        self.min_events_to_keep = min_events_to_keep

    async def compress_if_needed(
        self,
        events: list,
        existing_summary: str = "",
    ) -> tuple[str, list]:
        """
        Inspect events and compress old history if needed.

        Returns:
            (new_summary, remaining_events): The updated summary and
            the events to keep in raw form.
        """
        if len(events) <= self.max_raw_events:
            return existing_summary, events  # No compression needed

        events_to_compress = events[: -self.min_events_to_keep]
        events_to_keep     = events[-self.min_events_to_keep :]

        conversation_text = self._events_to_text(events_to_compress)

        summary_prompt = f"""Summarize the following conversation history into a compact
"User Profile and Conversation Memo" for an AI assistant to reference in future turns.

{f"Existing summary (from previous sessions):\\n{existing_summary}\\n" if existing_summary else ""}

## Conversation History ({len(events_to_compress)} turns)
{conversation_text}

## Output Format (bullet points)
- **User Info**: Name, occupation, goals, and other confirmed basics
- **Resolved Items**: Decisions made, problems solved
- **In-Progress Tasks**: Ongoing topics or unresolved issues
- **Preferences and Style**: Communication or technical preferences observed
- **Key Technical Details**: Code, configs, or decisions that may need to be referenced

Be concise. Include only what's genuinely useful for future conversation turns."""

        response = await self.client.aio.models.generate_content(
            model=self.model,
            contents=summary_prompt,
        )

        return response.text, events_to_keep

    def _events_to_text(self, events: list) -> str:
        """Convert event list to readable text (handles both dicts and Event objects)."""
        lines = []
        for event in events:
            if isinstance(event, dict):
                role    = event.get("role", "unknown")
                content = event.get("content", {})
                parts   = content.get("parts", []) if isinstance(content, dict) else []
                for part in parts:
                    text = part.get("text", "") if isinstance(part, dict) else ""
                    if text:
                        lines.append(f"[{role}]: {text[:400]}")
            else:
                role = getattr(event, "role", "unknown")
                if hasattr(event, "content") and event.content:
                    for part in event.content.parts:
                        if hasattr(part, "text") and part.text:
                            lines.append(f"[{role}]: {part.text[:400]}")
        return "\n".join(lines)

async def run_with_auto_compression(
    user_id: str, session_id: str, message: str
) -> str:
    """Run the assistant with automatic conversation compression."""
    session_service = SQLiteSessionService()
    compressor      = ConversationCompressor()
    runner = Runner(
        agent=assistant,
        app_name="my_assistant_app",
        session_service=session_service,
    )

    session = await session_service.get_session(
        app_name="my_assistant_app",
        user_id=user_id,
        session_id=session_id,
    )
    if session is None:
        session = await session_service.create_session(
            app_name="my_assistant_app",
            user_id=user_id,
            session_id=session_id,
        )

    events           = getattr(session, "events", [])
    existing_summary = session.state.get("conversation_summary", "")

    if len(events) > compressor.max_raw_events:
        print(f"📦 Compressing {len(events)} events...")
        new_summary, _ = await compressor.compress_if_needed(
            events, existing_summary
        )
        await session_service.update_session_state(
            app_name="my_assistant_app",
            user_id=user_id,
            session_id=session_id,
            state={"conversation_summary": new_summary},
        )
        print("✅ Compression complete. Summary saved to session state.")

    content = genai_types.Content(
        role="user",
        parts=[genai_types.Part(text=message)]
    )

    async for event in runner.run_async(
        user_id=user_id,
        session_id=session_id,
        new_message=content,
    ):
        if event.is_final_response() and event.content:
            return event.content.parts[0].text

    return ""
```

**The key design principle here is "summarize, don't delete."** Old conversation turns get condensed into a structured memo by Gemini 2.5 Pro itself, stored in `session.state`, and dynamically injected into the agent's `instruction` for future turns. You preserve long-term context while dramatically reducing per-request token consumption.

## Multi-User Design: Safe Conversation Isolation

In a multi-user service, the `user_id` design determines the security posture of your entire system.

### Always verify user_id on the server side

Trusting client-supplied user IDs opens the door to impersonation attacks.

```python
# ❌ Dangerous: trusting what the client sends
user_id = request.json.get("user_id")

# ✅ Safe: use a verified UID from Firebase Auth
from firebase_admin import auth as firebase_auth
from fastapi import HTTPException

def get_verified_user_id(id_token: str) -> str:
    try:
        decoded = firebase_auth.verify_id_token(id_token)
        # Prefix isolates by app version — useful if you run multiple apps
        return f"app_v2_{decoded['uid']}"
    except Exception:
        raise HTTPException(status_code=401, detail="Invalid token")
```

### Session lifecycle management

As your user base grows, inactive sessions accumulate. Schedule a background cleanup to keep your database lean.

```python
import asyncio
import sqlite3
from datetime import datetime, timedelta

async def cleanup_inactive_sessions(
    db_path: str,
    days_inactive: int = 90
) -> int:
    """Delete sessions inactive for more than N days. Returns count deleted."""
    threshold = datetime.now() - timedelta(days=days_inactive)

    with sqlite3.connect(db_path) as conn:
        cursor = conn.execute(
            "SELECT COUNT(*) FROM sessions WHERE updated_at < ?",
            (threshold.isoformat(),)
        )
        count = cursor.fetchone()[0]

        if count > 0:
            # ON DELETE CASCADE handles related events automatically
            conn.execute(
                "DELETE FROM sessions WHERE updated_at < ?",
                (threshold.isoformat(),)
            )
            conn.commit()

    return count

async def weekly_cleanup_scheduler(db_path: str):
    while True:
        await asyncio.sleep(7 * 24 * 3600)
        deleted = await cleanup_inactive_sessions(db_path)
        if deleted:
            print(f"🗑️ Cleaned up {deleted} inactive sessions")
```

## Five Pitfalls and How to Avoid Them

These are the real issues that trip up developers moving from prototype to production with ADK.

### Pitfall 1: Running multiple worker processes with InMemorySessionService

`InMemorySessionService` is process-local. In any multi-worker setup — Gunicorn, multiple uvicorn workers, Kubernetes pods — each worker has its own isolated memory. A session created in worker A is invisible to worker B.

The result: users experience "amnesia" on every request if load-balancing routes them to different workers. This is notoriously hard to diagnose in staging.

**Fix**: Always use a database-backed `SessionService` in production. Or pin to a single worker for small apps.

### Pitfall 2: Calling run_async before the session exists

```python
# ❌ Common mistake: running without confirming session exists
async for event in runner.run_async(
    user_id=user_id,
    session_id="session_that_might_not_exist",
    new_message=content,
):
    ...  # Some ADK versions won't raise — they just don't save anything

# ✅ Correct: always check, then create if missing
session = await session_service.get_session(
    app_name="my_assistant_app",
    user_id=user_id,
    session_id=session_id,
)
if session is None:
    await session_service.create_session(
        app_name="my_assistant_app",
        user_id=user_id,
        session_id=session_id,
    )
# Now run_async is safe
```

Depending on the ADK version, calling `run_async` on a missing session might not raise an exception — it just silently executes without persisting anything. Always pair existence checks with session creation.

### Pitfall 3: Thinking tokens ballooning your session history

With Gemini 2.5 Pro's Thinking mode enabled, internal reasoning processes may surface as events. If you persist every event including thinking events, your history grows several times faster than expected.

```python
# ✅ Skip thinking events from session persistence
async for event in runner.run_async(
    user_id=user_id,
    session_id=session_id,
    new_message=content,
):
    if getattr(event, "is_thinking", False):
        continue  # Don't yield or persist thinking events

    if event.is_final_response() and event.content:
        yield event.content.parts[0].text
```

### Pitfall 4: Expecting Session.state to auto-populate from conversation

`Session.state` is an ADK-managed key-value store that tools can write to via `context.session.state["key"] = value`. It is **not** a place where the agent automatically records things it "learns" from conversation. There's no magic that converts "remember this" utterances into state entries.

If you want long-term memory from natural conversation, you need explicit memory tools:

```python
from google.adk.tools import FunctionTool

def save_user_info(key: str, value: str) -> str:
    """Save important user information to persistent memory.
    
    Args:
        key: The information key (e.g., "preferred_language", "project_name")
        value: The value to store
    """
    # In practice, write to your database here
    return f"Got it — I'll remember that '{key}' is '{value}' ✅"

memory_assistant = Agent(
    model="gemini-2.5-pro",
    name="memory_assistant",
    instruction="""When the user shares important information about themselves
(name, job, project details, preferences), use the save_user_info tool to record it.
Reference stored information when it's relevant to the conversation.""",
    tools=[FunctionTool(save_user_info)],
)
```

### Pitfall 5: Using a hardcoded session_id across all users

Hardcoding `session_id = "default_session"` during development is common. When that habit carries into production, **every user shares the same session**. This is one of the most data-integrity-damaging mistakes you can make.

```python
from datetime import datetime

def generate_session_id(user_id: str, purpose: str = "main") -> str:
    """Generate a meaningful, unique session ID."""
    # Monthly sessions — resets context at the start of each month
    return f"{purpose}_{datetime.now().strftime('%Y%m')}"
    # Example: "main_202604"
    
    # For fully isolated fresh conversations:
    # import uuid; return f"{purpose}_{uuid.uuid4().hex[:8]}"
```

## Gemini 2.5 Pro-Specific Considerations for ADK

Gemini 2.5 Pro's reasoning power comes with a few ADK-specific configuration points worth knowing.

**Dynamic Thinking Budget**: Not every conversation needs deep reasoning. Calibrate Thinking Budget by task type to control cost without sacrificing quality where it matters.

```python
from google.genai import types as genai_types

def get_thinking_config(task_type: str) -> genai_types.ThinkingConfig:
    """Return the right Thinking Budget for the task at hand."""
    configs = {
        "simple_qa":    genai_types.ThinkingConfig(thinking_budget=0),
        "code_review":  genai_types.ThinkingConfig(thinking_budget=4096),
        "architecture": genai_types.ThinkingConfig(thinking_budget=16384),
    }
    return configs.get(task_type, configs["simple_qa"])

# Pass it through GenerateContentConfig when calling Runner
generate_config = genai_types.GenerateContentConfig(
    thinking_config=get_thinking_config("code_review"),
)
```

**1M Token Window + Session Management**: Gemini 2.5 Pro's million-token context window isn't just for long documents — it lets you include user-specific files (specs, design docs, past outputs) alongside conversation history in every request. Combine this with the compression strategy above to maintain both "memory" and "document knowledge" long-term without cost explosion.

## Exposing Your Assistant as a Web API with FastAPI

Once your SessionService and Runner are working, wrapping them in a FastAPI endpoint makes the assistant accessible from any frontend.

```python
from fastapi import FastAPI, HTTPException, Header
from fastapi.responses import StreamingResponse
from pydantic import BaseModel
from typing import Optional
import json

app = FastAPI(title="Persistent AI Assistant API")
session_service = SQLiteSessionService("./production.db")

class ChatRequest(BaseModel):
    message: str
    session_id: Optional[str] = None

@app.post("/chat/{user_id}")
async def chat(
    user_id: str,
    request: ChatRequest,
    authorization: str = Header(...),
):
    # Authentication — use firebase_admin.auth or JWT in production
    if not authorization.startswith("Bearer "):
        raise HTTPException(status_code=401, detail="Unauthorized")

    session_id = request.session_id or f"main_{user_id}"

    session = await session_service.get_session(
        app_name="assistant_api",
        user_id=user_id,
        session_id=session_id,
    )
    if session is None:
        await session_service.create_session(
            app_name="assistant_api",
            user_id=user_id,
            session_id=session_id,
        )

    runner = Runner(
        agent=assistant,
        app_name="assistant_api",
        session_service=session_service,
    )

    content = genai_types.Content(
        role="user",
        parts=[genai_types.Part(text=request.message)]
    )

    async def event_stream():
        async for event in runner.run_async(
            user_id=user_id,
            session_id=session_id,
            new_message=content,
        ):
            if getattr(event, "is_thinking", False):
                continue
            if event.content:
                for part in event.content.parts:
                    if hasattr(part, "text") and part.text:
                        chunk = json.dumps({"text": part.text}, ensure_ascii=False)
                        yield f"data: {chunk}\n\n"
        yield "data: [DONE]\n\n"

    return StreamingResponse(event_stream(), media_type="text/event-stream")
```

This gives you a streaming REST endpoint where any client can send messages and receive a persistent AI assistant that remembers each user across sessions.

## Next Steps: From Working Demo to Production Product

Session management is the difference between an impressive demo and a product people keep coming back to. An assistant without memory greets every returning user as a stranger.

Start with `InMemorySessionService` to verify that your assistant's conversation context works the way you expect. Once that's confirmed, drop in the `SQLiteSessionService` implementation from this guide. When conversations start exceeding 30 events per user, add the compression layer.

That's the path: prototype → persist → compress. Gemini 2.5 Pro's reasoning depth shows up most clearly in conversations where it actually knows who it's talking to and what they've been working on together. Well-designed session management is what makes that possible.
