Gemma 4 offers four distinct model sizes, native multimodal support, extended context windows, and a full suite of agent-ready features — all under an Apache 2.0 license. The challenge for developers is knowing how to deploy these capabilities together effectively.

## Choosing the Right Model Size

The first decision when building with Gemma 4 is which model to use. Each size involves trade-offs between capability, latency, and infrastructure cost.

### E2B and E4B: Edge and Mobile

Both edge models support 128K context, native multimodal input (video, images, audio), and run efficiently on constrained hardware. E2B is suitable for mobile apps and embedded systems where every MB of RAM matters. E4B provides meaningfully higher accuracy for edge use cases where inference quality matters more than raw efficiency — medical screening support, industrial inspection, and similar domains.

### 26B MoE: Production Cloud Baseline

The Mixture of Experts architecture activates only relevant sub-networks per token, making it efficient relative to its total parameter count. Ranked 6th globally among open models, it's a strong choice for API services that need to handle high request volumes with good accuracy and manageable compute costs.

### 31B Dense: Maximum Accuracy

The 31B Dense model activates all parameters for every inference — slower and more expensive, but currently ranked 3rd globally among all open models, outperforming some models in the 400B range. Use this for tasks where quality is non-negotiable: legal and medical document analysis, complex reasoning, production code generation.

## Vertex AI: Basic Setup

```python
import vertexai
from vertexai.preview.generative_models import GenerativeModel, Part

vertexai.init(project="YOUR_PROJECT_ID", location="us-central1")

# Choose model by size:
# "google/gemma-4-e2b" / "google/gemma-4-e4b"  (edge)
# "google/gemma-4-27b-it" / "google/gemma-4-31b-it"  (cloud)
model = GenerativeModel("google/gemma-4-31b-it")

response = model.generate_content(
    "Explain the difference between MoE and Dense architectures in three paragraphs.",
    generation_config={
        "temperature": 0.7,
        "max_output_tokens": 1024,
        "top_p": 0.9,
    }
)
print(response.text)
```

## Function Calling: Building Agents

Gemma 4's function calling capability lets the model interact with external tools — APIs, databases, search engines — rather than relying solely on its training data.

```python
import vertexai
from vertexai.preview.generative_models import (
    GenerativeModel, FunctionDeclaration, Tool, Part
)

vertexai.init(project="YOUR_PROJECT_ID", location="us-central1")

# Define the tools your agent can use
search_func = FunctionDeclaration(
    name="search_knowledge_base",
    description="Search the internal product knowledge base for relevant documentation",
    parameters={
        "type": "object",
        "properties": {
            "query": {
                "type": "string",
                "description": "The search query"
            },
            "max_results": {
                "type": "integer",
                "description": "Maximum number of results to return",
                "default": 5
            }
        },
        "required": ["query"]
    }
)

create_ticket_func = FunctionDeclaration(
    name="create_support_ticket",
    description="Create a support ticket in the issue tracker",
    parameters={
        "type": "object",
        "properties": {
            "title": {"type": "string"},
            "description": {"type": "string"},
            "priority": {
                "type": "string",
                "enum": ["low", "medium", "high", "critical"]
            }
        },
        "required": ["title", "description", "priority"]
    }
)

tools = [Tool(function_declarations=[search_func, create_ticket_func])]
model = GenerativeModel("google/gemma-4-31b-it", tools=tools)
chat = model.start_chat()

# Multi-turn agent interaction
response = chat.send_message(
    "A user is reporting that the payment API returns a 500 error "
    "when processing orders over $10,000. Can you search for related "
    "documentation and create a critical priority ticket?"
)

# Handle function call response
candidate = response.candidates[0]
if candidate.content.parts[0].function_call:
    fc = candidate.content.parts[0].function_call
    print(f"Agent calling: {fc.name} with args: {dict(fc.args)}")
    
    # Simulate function execution
    if fc.name == "search_knowledge_base":
        mock_results = [
            {"id": "KB-001", "title": "Payment API limits", "relevance": 0.95},
            {"id": "KB-042", "title": "Large transaction handling", "relevance": 0.87}
        ]
        
        final_response = chat.send_message(
            Part.from_function_response(
                name="search_knowledge_base",
                response={"results": mock_results, "total": 2}
            )
        )
        print(final_response.text)
```

## Structured JSON Output

For production pipelines where model output feeds into downstream systems, reliable structured output is essential.

```python
import json
from vertexai.preview.generative_models import GenerativeModel, GenerationConfig

model = GenerativeModel("google/gemma-4-31b-it")

# Data extraction with explicit schema
review_text = """
The laptop is lightweight and responsive. Battery life is excellent — 
easily 10+ hours of real-world use. The keyboard could be better for 
long typing sessions, and the price is on the high end. 
Overall I'd give it 4.2 out of 5.
"""

response = model.generate_content(
    f"""Extract structured information from this product review.
    Return ONLY valid JSON matching this exact schema, no other text:
    {{
      "product_category": "string",
      "positive_aspects": ["array of strings"],
      "negative_aspects": ["array of strings"],
      "overall_rating": "number between 0-5",
      "sentiment": "positive|negative|neutral|mixed",
      "would_recommend": "boolean"
    }}

    Review: {review_text}""",
    generation_config=GenerationConfig(
        response_mime_type="application/json",
        temperature=0.0
    )
)

result = json.loads(response.text)
print(f"Rating: {result['overall_rating']}/5")
print(f"Sentiment: {result['sentiment']}")
print(f"Pros: {', '.join(result['positive_aspects'])}")
```

## Large Context: Codebase Analysis with 256K Tokens

The 31B Dense model's 256K context window enables full-codebase analysis in a single prompt — a qualitatively different workflow from chunked analysis.

```python
import os

def collect_source_files(root_dir: str, extensions: tuple = ('.py', '.ts', '.js')) -> str:
    """Recursively collect source files, excluding generated directories."""
    excluded = {'node_modules', '.git', 'dist', 'build', '__pycache__'}
    collected = []
    
    for dirpath, dirnames, filenames in os.walk(root_dir):
        dirnames[:] = [d for d in dirnames if d not in excluded]
        for filename in filenames:
            if filename.endswith(extensions):
                filepath = os.path.join(dirpath, filename)
                try:
                    with open(filepath, 'r', encoding='utf-8') as f:
                        collected.append(f"### {filepath}\n```\n{f.read()}\n```")
                except (IOError, UnicodeDecodeError):
                    pass
    
    return "\n\n".join(collected)

codebase_content = collect_source_files("./my_app")

model = GenerativeModel("google/gemma-4-31b-it")
response = model.generate_content(
    f"""Analyze this codebase and provide:
    
    1. Architecture overview (2-3 paragraphs)
    2. Top 5 technical debt items with estimated remediation effort
    3. Security concerns ranked by severity
    4. Missing test coverage for critical paths
    5. Performance bottlenecks visible in the code
    
    Codebase:
    {codebase_content}""",
    generation_config={"max_output_tokens": 8192}
)
print(response.text)
```

## Local Deployment with LM Studio

For privacy-sensitive workloads or air-gapped environments, Gemma 4 can run locally via LM Studio's OpenAI-compatible API.

```python
from openai import OpenAI

# LM Studio exposes an OpenAI-compatible endpoint at localhost:1234
client = OpenAI(
    base_url="http://localhost:1234/v1",
    api_key="not-required"
)

response = client.chat.completions.create(
    model="gemma-4-31b-dense",  # Model name as loaded in LM Studio
    messages=[
        {
            "role": "system",
            "content": "You are a precise technical assistant. Always provide working code examples."
        },
        {
            "role": "user",
            "content": "Write a Python function to implement binary search with proper error handling."
        }
    ],
    temperature=0.3,
    max_tokens=1024
)

print(response.choices[0].message.content)
```

## Putting It All Together: A Production Pattern

The most effective Gemma 4 deployments combine several of these capabilities. A practical pattern for a customer support agent:

Use 26B MoE for high-volume first-pass categorization. Route complex cases to 31B Dense with full conversation history in context. Use function calling to retrieve account data and create tickets. Return structured JSON for clean integration with CRM systems.

This approach balances cost (most requests hit the cheaper 26B model) with quality (complex cases get the strongest model) while maintaining structured, auditable outputs.

## Conclusion

Gemma 4's combination of multimodal capability, 256K context, function calling, structured output, and Apache 2.0 licensing removes several constraints that have historically limited what developers can build with open models.

The code examples in this guide represent starting points. Production deployments will require appropriate error handling, rate limiting, and evaluation loops to ensure output quality — but the foundation Gemma 4 provides is genuinely strong.

Start with the use case that matters most to you, choose the model size that fits your constraints, and build from there.
