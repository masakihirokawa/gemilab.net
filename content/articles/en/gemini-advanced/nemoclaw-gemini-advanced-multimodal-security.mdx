## Why you should never hand an uploaded image straight to Gemini

I've built apps as an indie developer since 2014, and when I first wired Gemini's vision capability into one of them for image classification, the thing that made my stomach drop was finding GPS coordinates still sitting in the EXIF of a user-supplied test photo. The exact location where the picture was taken, embedded as latitude and longitude. Had I been passing that straight into logs or prompt context, I would have been quietly accumulating data that could pinpoint a user's home on my own server.

The danger of multimodal input is that, unlike text, you can't easily see what's inside. A file named `.jpg` might be something else entirely, and an innocent-looking photo may carry personal data in its metadata. This article builds the validation layer that belongs in front of any user-supplied media before it reaches Gemini, with Python you can actually run. We use the Gemini API (`google-genai` SDK) alone — no special external framework.

## Three risks to deal with first

When you handle user-supplied media, these are the three problems you actually hit in practice.

1. **Extension vs. real content (MIME spoofing)** — `photo.jpg` is really HTML, an executable, or a format Gemini can't read. The moment you trust the extension, validation is already broken.
2. **Leakage through metadata** — GPS, capture timestamp, device model in EXIF. The image itself may be harmless while the attached data becomes a leak vector.
3. **Resource exhaustion** — sending a high-resolution video inline and blowing past the request-size limit or available memory.

Let's close each one.

## Decide the format by the first bytes, not the extension

The most common mistake is deciding the MIME type from the filename's extension. Rewriting an extension costs an attacker nothing, so always read the file's leading bytes (the magic number) to confirm what it really is.

```python
# Determine the real format from the file's leading bytes.
# Never trust the extension.
MAGIC_SIGNATURES = {
    b"\xff\xd8\xff": "image/jpeg",
    b"\x89PNG\r\n\x1a\n": "image/png",
    b"RIFF": "image/webp",          # confirm with "WEBP" at byte 8
    b"\x00\x00\x00\x18ftyp": "video/mp4",
    b"\x00\x00\x00\x20ftyp": "video/mp4",
}

ALLOWED = {"image/jpeg", "image/png", "image/webp", "video/mp4"}

def sniff_mime(path: str) -> str | None:
    with open(path, "rb") as f:
        head = f.read(32)
    for sig, mime in MAGIC_SIGNATURES.items():
        if head.startswith(sig):
            # WebP is a RIFF container, so verify further
            if mime == "image/webp" and head[8:12] != b"WEBP":
                continue
            return mime
    return None

def validate_or_reject(path: str) -> str:
    mime = sniff_mime(path)
    if mime is None or mime not in ALLOWED:
        raise ValueError(f"Disallowed format: {path}")
    return mime
```

The key is to reject "unknown" (`None`) and "not allowed" equally. Make "if I can't identify it, it doesn't pass" your default, and an unfamiliar format slipping in fails safe. In production you could reach for `python-magic`, but when you only handle a handful of formats, owning the table as above cuts a dependency and makes your allowlist obvious from the code.

## Strip EXIF before you send

A JPEG's EXIF can hold GPS coordinates, capture time, and even the device model. If you want Gemini to interpret only the image's content, drop the metadata before sending. The reliable way with Pillow is to move just the pixel data into a fresh image.

```python
from PIL import Image

def strip_metadata(src_path: str, dst_path: str) -> None:
    with Image.open(src_path) as img:
        # Copy only pixel data into a new image; carry over
        # none of the attached info, including EXIF.
        clean = Image.new(img.mode, img.size)
        clean.putdata(list(img.getdata()))
        clean.save(dst_path, format="PNG")  # re-encoding to PNG drops EXIF
```

You could also blank the EXIF with `img.save(dst, exif=b"")`, but ICC profiles or comment blocks can survive. Moving only the pixels into a new image carries no attached information structurally, so nothing leaks through. To inspect what was there before stripping, `img.getexif()` lets you peek inside — that's exactly how I found those GPS coordinates the first time.

## Route video over 20MB through the Files API

In a Gemini request, inline data (passing `bytes` directly in `contents`) has a total-size ceiling; as a rule of thumb, media over roughly 20MB should be uploaded via the Files API and referenced by handle. Video crosses that threshold in an instant, so branch on size.

```python
import os
from google import genai

client = genai.Client(api_key="YOUR_GEMINI_API_KEY")

INLINE_LIMIT = 20 * 1024 * 1024   # 20MB
HARD_LIMIT = 500 * 1024 * 1024    # refuse anything larger

def build_content(path: str, mime: str):
    size = os.path.getsize(path)
    if size > HARD_LIMIT:
        raise ValueError("File is too large")
    if size <= INLINE_LIMIT and mime.startswith("image/"):
        # small images are fine inline
        with open(path, "rb") as f:
            return genai.types.Part.from_bytes(data=f.read(), mime_type=mime)
    # large media and video go through the Files API
    uploaded = client.files.upload(file=path)
    return uploaded

def analyze(path: str, prompt: str) -> str:
    mime = validate_or_reject(path)       # format check
    part = build_content(path, mime)      # branch send method by size
    resp = client.models.generate_content(
        model="gemini-2.5-pro",
        contents=[part, prompt],
        config=genai.types.GenerateContentConfig(
            safety_settings=[
                genai.types.SafetySetting(
                    category="HARM_CATEGORY_DANGEROUS_CONTENT",
                    threshold="BLOCK_MEDIUM_AND_ABOVE",
                ),
            ],
            max_output_tokens=1024,
        ),
    )
    return resp.text
```

Funnelling validation (`validate_or_reject`), the send-method branch (`build_content`), and safety settings through a single call path means adding a new input format is a one-place change. Beyond `HARM_CATEGORY_DANGEROUS_CONTENT` there are harassment and sexually-explicit categories; tune the thresholds to the nature of your service.

## A gotcha: Files API uploads expire

Files uploaded via the Files API have a retention window (around 48 hours), and referencing an expired handle returns a `403` or "not found." I once had a batch job fail because it tried to reuse the previous day's upload. If you need to reference the same media over a longer period, record the upload time yourself and re-upload as the deadline approaches.

```python
import time

def get_or_reupload(path: str, cache: dict):
    rec = cache.get(path)
    # re-upload past 40 hours (safely short of 48)
    if rec and (time.time() - rec["uploaded_at"]) < 40 * 3600:
        return rec["file"]
    uploaded = client.files.upload(file=path)
    cache[path] = {"file": uploaded, "uploaded_at": time.time()}
    return uploaded
```

## Don't pass the output through unchecked either

Even with the input locked down, the generated result can echo back the very secrets a user sent in. With OCR-style usage especially, a phone number or email address inside the image gets turned into plain text. Depending on the use case, a light masking pass before you store or display the response buys peace of mind.

```python
import re

def mask_pii(text: str) -> str:
    text = re.sub(r"[\w.+-]+@[\w-]+\.[\w.-]+", "[email]", text)
    text = re.sub(r"\d{2,4}-\d{2,4}-\d{4}", "[phone]", text)
    return text
```

Perfect PII detection is a separate hard problem, but simply drawing the line at "never log it in the clear" removes a lot of the risk.

## Your next step

Start by chaining your validation functions into a single pipeline in the order `sniff_mime → strip_metadata → build_content`, then run one EXIF-bearing test photo through it and confirm with `getexif()` that the coordinates are gone. Whether or not this "pause before you send" layer exists is what decides whether you can ship a multimodal feature to production with confidence. I hope it helps in your own build.
