When Gemini 3.1 Pro launched with a 2M token context window, my first question wasn't "what can I do with this?" It was "does it actually work when you fill it up?"

The same skepticism hit me when 1M tokens arrived. Technically 1 million tokens. But whether the model genuinely "reads" all of it, rather than just pattern-matching the edges — that's a different question. I ran the same test with 2M: fed it a mid-size Next.js project (~80 files, roughly 120,000 tokens), asked it to analyze the whole thing, and paid attention to what came back.

## What Fits in 2M Tokens

First, a scale reference. One token is roughly 3-4 characters of English code, or 1-2 Japanese characters.

2 million tokens is large enough to comfortably fit:

- A multi-hundred-file monorepo
- 500+ pages of PDF documentation
- A year of meeting transcripts
- The Next.js project I tested (~120k tokens) — about 16 times over

The jump from 1M to 2M mostly eliminates the need to "chunk" projects before passing them in. For mid-size projects, that's the meaningful change.

## The Test Setup

I used a Next.js 16 (App Router) + TypeScript project with this structure:

```
src/
  app/          (30 files)
  components/   (25 files)
  lib/          (15 files)
  types/        (5 files)
package.json, tsconfig.json, etc.
```

I wrote a Python script to concatenate the whole thing into one context string:

```python
import google.generativeai as genai
from pathlib import Path

def load_project_as_context(project_dir: str, include_extensions: list = None) -> str:
    """Flatten a project directory into a single context string."""
    if include_extensions is None:
        include_extensions = [".ts", ".tsx", ".js", ".json", ".md"]
    
    parts = []
    root = Path(project_dir)
    exclude_dirs = {"node_modules", ".next", ".git", "dist", "build"}
    
    for file_path in sorted(root.rglob("*")):
        if any(ex in file_path.parts for ex in exclude_dirs):
            continue
        if file_path.suffix not in include_extensions:
            continue
        if not file_path.is_file():
            continue
        
        try:
            content = file_path.read_text(encoding="utf-8")
            relative_path = file_path.relative_to(root)
            parts.append(f"=== {relative_path} ===\n{content}\n")
        except Exception:
            continue
    
    return "\n".join(parts)

def analyze_project(project_dir: str, question: str) -> str:
    model = genai.GenerativeModel("gemini-2.0-flash-exp")  # or gemini-3.1-pro
    
    context = load_project_as_context(project_dir)
    token_count = model.count_tokens(context).total_tokens
    print(f"Context: {token_count:,} tokens")
    
    prompt = f"""Here is the full source code for the project:

{context}

---

Question: {question}
"""
    
    response = model.generate_content(prompt)
    return response.text

answer = analyze_project(
    project_dir="./my-nextjs-app",
    question="""Analyze this entire codebase for:

1. Security concerns (API key handling, input validation gaps)
2. Performance issues (unnecessary re-renders, N+1 query patterns)
3. Type safety weaknesses (overuse of 'any', unsafe type assertions)
4. Dependency issues (unused imports, potential circular dependencies)

For each finding, provide the specific filename and line number."""
)

print(answer)
```

## What the Output Quality Was Like

The "whole-project awareness" was noticeable in a specific way: cross-file reasoning.

When I asked about security concerns, Gemini traced how a function in `lib/auth.ts` was being used in `app/api/admin/route.ts`, and pointed out that loose validation in the first file created a bypass risk in the second. When I was chunking the context manually under 1M tokens, this kind of cross-file chain rarely appeared — the model only saw what was in the window at the time.

There are genuine limitations worth being honest about, though.

Passing 80 files doesn't mean every file gets equal attention. The model gravitates toward files that are more "interesting" by some pattern — heavily imported modules, files with complex types, files near the entry point. Utility functions that are small and rarely imported tended to be overlooked unless specifically asked about.

## Where 2M Context Works Well

Three scenarios where the large context delivered clear value:

**Architecture-level questions**: "Map out the data flow in this project" or "Where are the main coupling points between modules?" — these require whole-project awareness and Gemini handled them well when given the full context.

**Root cause investigation**: "Find where this type error originates, across all files" with the error message and full source together was surprisingly accurate. It traced type definitions through multiple layers without losing the thread.

**Refactoring impact analysis**: "I want to replace `UserContext` with `useAuthStore` everywhere. List every affected file." — the coverage was nearly complete, with only one missed edge case in a rarely-used utility.

The prompt approach matters here. Vague requests ("generally improve this project") produce thin results. Specific, bounded questions ("find all files that import this module and check if they handle null correctly") produce much sharper output, even with the full context available.

## What Actually Changed Going from 1M to 2M

The most practical change: I stopped thinking about how to split the project.

Chunking context isn't just time-consuming — it requires judgment calls about which files to group together, which introduces its own errors. Passing the whole thing and saying "look at all of it" removes that layer of decision-making.

For individual developers and mid-size projects, 2M tokens is generous enough that you'll probably never hit the limit. For large monorepos with hundreds of thousands of files, you'll still need strategies. But the sweet spot just got significantly larger.

The honest summary: 2M context doesn't make Gemini read everything with perfect coverage. It does make the analysis more coherent when relationships between files matter — which, for architectural review and root cause investigation, is exactly when you need it most.
