## What Changes When You Analyze the Whole Codebase

Most AI-assisted code review today works file-by-file or snippet-by-snippet. You paste a function into ChatGPT and ask for feedback. That approach has a fundamental blind spot: **context disconnection**.

When you show only one file, the AI can't catch cross-project issues like: "Why is `this.authService` called directly here?" or "This data model is defined in three slightly different ways across the codebase." These are precisely the bugs that cause the most pain at scale.

Gemini 2.5 Pro's 1M-token window (roughly 750,000 words) fits an entire mid-size web application in a single request. When I measured my project — a Swift app with a Node.js backend, around 30,000 lines — it came in at roughly 180,000–220,000 tokens.

What becomes possible when you send the whole thing at once:
- "The `APIClient` class handles network I/O, response mapping, and error logging in one place — making it untestable by design."
- "Error handling uses three different patterns: try-catch in `src/workers/`, Promise.catch in `src/api/`, and callbacks in older utility files."
- "Environment variable access is scattered across seven files. `process.env.DATABASE_URL` is referenced independently in `db.ts`, `config.ts`, and `migration.ts` with no type safety."

None of that is detectable from a single-file view.

## Environment Setup and Code Collection Script

First, install the required libraries:

```bash
pip install google-generativeai tiktoken pathlib
```

Then create a script to consolidate your codebase into a single text block. This version respects `.gitignore` patterns, skips binaries, and caps collection before hitting token limits.

```python
# collect_codebase.py
import os
import sys
from pathlib import Path
from typing import Optional
import subprocess

EXCLUDE_DIRS = {
    '.git', 'node_modules', '.next', 'dist', 'build',
    '__pycache__', '.venv', 'venv', 'coverage', '.nyc_output'
}
EXCLUDE_EXTENSIONS = {
    '.png', '.jpg', '.jpeg', '.gif', '.svg', '.ico',
    '.pdf', '.zip', '.tar', '.gz', '.mp4', '.mp3',
    '.lock', '.map', '.min.js', '.min.css'
}
INCLUDE_EXTENSIONS = {
    '.py', '.ts', '.tsx', '.js', '.jsx', '.swift',
    '.kt', '.java', '.go', '.rs', '.cpp', '.c', '.h',
    '.json', '.yaml', '.yml', '.toml', '.env.example',
    '.md', '.sql', '.graphql'
}

def get_gitignore_patterns(root: Path) -> list[str]:
    """Load ignore patterns from the root .gitignore"""
    gitignore = root / '.gitignore'
    if not gitignore.exists():
        return []
    patterns = []
    with open(gitignore, 'r') as f:
        for line in f:
            line = line.strip()
            if line and not line.startswith('#'):
                patterns.append(line)
    return patterns

def collect_codebase(root_dir: str, max_tokens: int = 800_000) -> tuple[str, int]:
    """
    Collect and concatenate all source files into a single string.
    
    Returns:
        (combined code string, estimated token count)
    """
    root = Path(root_dir).resolve()
    collected = []
    total_chars = 0
    skipped_files = []
    
    for file_path in sorted(root.rglob('*')):
        if not file_path.is_file():
            continue
        
        relative = file_path.relative_to(root)
        parts = set(relative.parts[:-1])
        if parts.intersection(EXCLUDE_DIRS):
            continue
        
        suffix = file_path.suffix.lower()
        if suffix not in INCLUDE_EXTENSIONS:
            continue
        
        # Skip files over 1MB
        if file_path.stat().st_size > 1_000_000:
            skipped_files.append(str(relative))
            continue
        
        try:
            content = file_path.read_text(encoding='utf-8', errors='ignore')
        except Exception as e:
            skipped_files.append(f"{relative} ({e})")
            continue
        
        file_block = f"\n\n{'='*60}\nFILE: {relative}\n{'='*60}\n{content}"
        total_chars += len(file_block)
        
        # Simple estimate: ~4 chars per token
        estimated_tokens = total_chars // 4
        if estimated_tokens > max_tokens:
            print(f"⚠️  Stopping collection — estimated tokens exceeded {max_tokens:,}")
            print(f"   Collected: {len(collected)} files")
            break
        
        collected.append(file_block)
    
    if skipped_files:
        print(f"Skipped {len(skipped_files)} files")
    
    full_text = ''.join(collected)
    estimated_tokens = len(full_text) // 4
    return full_text, estimated_tokens


if __name__ == '__main__':
    root = sys.argv[1] if len(sys.argv) > 1 else '.'
    code, tokens = collect_codebase(root)
    print(f"Done: ~{tokens:,} tokens ({len(code):,} chars)")
    
    output_path = Path('codebase_collected.txt')
    output_path.write_text(code, encoding='utf-8')
    print(f"Saved to: {output_path}")
```

Running this gives you a single file with your entire codebase, plus a token estimate so you can gauge API cost before sending anything.

## Automating Architecture Reviews

With the codebase collected, the first analysis pass is an **architecture review**. The difference between "please review my code" and a structured review prompt is significant — the latter gets you actionable, categorized output.

```python
# architecture_review.py
import google.generativeai as genai
import json
import time
from pathlib import Path

def run_architecture_review(codebase_text: str, project_name: str) -> dict:
    """
    Run a full architecture review against the collected codebase.
    
    Returns:
        Structured review data as a dict
    """
    genai.configure(api_key='YOUR_GEMINI_API_KEY')
    model = genai.GenerativeModel(
        model_name='gemini-2.5-pro',
        generation_config={
            'temperature': 0.2,   # Lower for consistency
            'max_output_tokens': 8192,
        }
    )
    
    prompt = f"""
You are a senior software architect. Analyze the entire codebase below and report architectural issues.

Project: {project_name}

[Analysis dimensions]
1. Layer separation (Presentation / Business Logic / Data Access)
2. Single Responsibility Principle violations
3. Dependency inversion and DI patterns
4. Cross-cutting concerns (auth, logging, error handling) consistency
5. Naming convention consistency
6. Circular dependencies and dead code

[Output format]
Return valid JSON matching this schema:
{{
  "overall_score": integer 1-10,
  "summary": "Overall assessment in 2-3 sentences",
  "critical_issues": [
    {{
      "title": "Issue title",
      "location": "File or function name",
      "description": "Detailed explanation of the problem",
      "severity": "critical|high|medium|low",
      "fix_suggestion": "Recommended fix approach"
    }}
  ],
  "positive_patterns": ["Good patterns worth keeping"],
  "priority_refactoring": ["Ordered list of refactoring priorities"]
}}

Severity scale:
- critical: Risk of production bugs, fix immediately
- high: Will block future feature development
- medium: Affects readability/maintainability, plan for it
- low: Nice to have

Codebase:
{codebase_text}
"""
    
    print("🔍 Running architecture review...")
    start_time = time.time()
    
    try:
        response = model.generate_content(
            prompt,
            request_options={"timeout": 300}  # 5-minute timeout for large contexts
        )
        elapsed = time.time() - start_time
        print(f"✅ Done ({elapsed:.1f}s)")
        
        # Extract JSON from code block if wrapped
        text = response.text
        if '```json' in text:
            text = text.split('```json')[1].split('```')[0].strip()
        elif '```' in text:
            text = text.split('```')[1].split('```')[0].strip()
        
        result = json.loads(text)
        return result
        
    except json.JSONDecodeError as e:
        print(f"⚠️  JSON parse error: {e}")
        return {
            "overall_score": 0,
            "summary": "Analysis failed",
            "raw_response": response.text,
            "error": str(e)
        }
    except Exception as e:
        print(f"❌ Error: {e}")
        raise


def format_report(review: dict) -> str:
    """Convert review data to readable Markdown"""
    lines = [
        "# Architecture Review Report",
        "",
        f"**Overall Score**: {review.get('overall_score', 'N/A')}/10",
        "",
        "## Summary",
        review.get('summary', ''),
        "",
        "## Issues Found",
    ]
    
    for issue in review.get('critical_issues', []):
        emoji = {'critical': '🔴', 'high': '🟠', 'medium': '🟡', 'low': '🟢'}.get(
            issue.get('severity', 'medium'), '⚪'
        )
        lines.extend([
            "",
            f"### {emoji} {issue.get('title', '')}",
            f"- **Location**: `{issue.get('location', '')}`",
            f"- **Details**: {issue.get('description', '')}",
            f"- **Fix**: {issue.get('fix_suggestion', '')}",
        ])
    
    lines.extend(["", "## Patterns Worth Keeping"])
    for p in review.get('positive_patterns', []):
        lines.append(f"- {p}")
    
    lines.extend(["", "## Refactoring Priorities"])
    for i, item in enumerate(review.get('priority_refactoring', []), 1):
        lines.append(f"{i}. {item}")
    
    return '\n'.join(lines)


if __name__ == '__main__':
    from collect_codebase import collect_codebase
    
    code, tokens = collect_codebase('.')
    print(f"Collected: ~{tokens:,} tokens")
    
    review = run_architecture_review(code, project_name="MyApp")
    report = format_report(review)
    
    Path('architecture_review.md').write_text(report, encoding='utf-8')
    print("Report saved to architecture_review.md")
```

## Tech Debt Scoring and Prioritization

With the architectural picture clear, the next step is **quantifying technical debt**. The goal is turning a gut feeling of "this code feels messy" into actual scores you can act on.

```python
# tech_debt_scorer.py
import google.generativeai as genai
import json
from pathlib import Path
from dataclasses import dataclass
from typing import Optional
import time

@dataclass
class DebtItem:
    file_path: str
    debt_type: str          # "complexity" | "duplication" | "coupling" | "dead_code" | "naming"
    severity: int           # 1-10
    estimated_fix_hours: float
    description: str
    code_snippet: Optional[str] = None

def analyze_tech_debt(codebase_text: str, focus_areas: list[str] = None) -> list[DebtItem]:
    """
    Scan the codebase for technical debt and return scored, prioritized items.
    
    Args:
        codebase_text: Full codebase as text
        focus_areas: Specific file paths to focus on (None = full scan)
    
    Returns:
        List of DebtItem sorted by severity (highest first)
    """
    genai.configure(api_key='YOUR_GEMINI_API_KEY')
    model = genai.GenerativeModel(
        model_name='gemini-2.5-pro',
        generation_config={
            'temperature': 0.1,
            'max_output_tokens': 16384,
        }
    )
    
    focus_hint = ""
    if focus_areas:
        focus_hint = "\nPay particular attention to:\n" + "\n".join(f"- {p}" for p in focus_areas)
    
    prompt = f"""
Analyze the following codebase and identify technical debt items.{focus_hint}

[Debt categories]
- complexity: High cognitive complexity, deeply nested logic
- duplication: Repeated code, DRY violations
- coupling: Inappropriate tight coupling, circular dependencies
- dead_code: Unused variables, functions, imports
- naming: Unclear names, cryptic abbreviations

[Output format]
Return a JSON array. Up to 20 items:
[
  {{
    "file_path": "relative/path/to/file",
    "debt_type": "complexity|duplication|coupling|dead_code|naming",
    "severity": 1-10,
    "estimated_fix_hours": estimated hours as float,
    "description": "Specific description of the problem (under 100 chars)",
    "code_snippet": "Short snippet showing the issue (under 50 chars, optional)"
  }}
]

Severity scale:
- 9-10: Risk of production bugs, fix immediately
- 7-8: Will become a major obstacle when extending functionality
- 5-6: Affects readability and maintainability
- 1-4: Minor, fix if you have time

Codebase:
{codebase_text}
"""
    
    print("📊 Analyzing technical debt...")
    start_time = time.time()
    
    try:
        response = model.generate_content(
            prompt,
            request_options={"timeout": 300}
        )
        elapsed = time.time() - start_time
        print(f"✅ Done ({elapsed:.1f}s)")
        
        text = response.text
        if '```json' in text:
            text = text.split('```json')[1].split('```')[0].strip()
        elif '```' in text:
            text = text.split('```')[1].split('```')[0].strip()
        
        raw_items = json.loads(text)
        
        items = []
        for item in raw_items:
            try:
                items.append(DebtItem(
                    file_path=item['file_path'],
                    debt_type=item['debt_type'],
                    severity=int(item['severity']),
                    estimated_fix_hours=float(item.get('estimated_fix_hours', 1.0)),
                    description=item['description'],
                    code_snippet=item.get('code_snippet'),
                ))
            except (KeyError, ValueError) as e:
                print(f"⚠️  Skipping malformed item: {e}")
                continue
        
        items.sort(key=lambda x: x.severity, reverse=True)
        return items
        
    except json.JSONDecodeError as e:
        print(f"⚠️  JSON parse error: {e}")
        print(f"Raw response: {response.text[:500]}")
        return []
    except Exception as e:
        print(f"❌ Error: {e}")
        raise


def print_debt_summary(items: list[DebtItem]) -> None:
    if not items:
        print("No technical debt detected.")
        return
    
    total_hours = sum(i.estimated_fix_hours for i in items)
    critical = [i for i in items if i.severity >= 8]
    
    print(f"\n{'='*60}")
    print(f"Technical Debt Summary")
    print(f"{'='*60}")
    print(f"Total: {len(items)} items | Est. fix time: {total_hours:.1f}h | Critical: {len(critical)}")
    
    from collections import Counter
    type_counts = Counter(i.debt_type for i in items)
    print("\nBy category:")
    for debt_type, count in type_counts.most_common():
        print(f"  {debt_type:15s}: {count}")
    
    print(f"\n--- Critical items (severity >= 8) ---")
    for item in critical:
        print(f"[{item.severity}/10] {item.file_path}")
        print(f"  {item.description}")
        if item.code_snippet:
            print(f"  > {item.code_snippet}")
        print()
```

When the "estimated fix hours" number lands in front of you, it reframes how you think about the codebase. The first time I ran this on my own project, the output was "Total estimated fix time: 47.5 hours." A bit alarming — but also clarifying. You don't have to fix everything at once. The scoring is there so you can prioritize intelligently.

## Generating and Applying Refactoring Suggestions

With the debt list in hand, the final stage is **generating concrete refactoring suggestions** — with before/after code — for the highest-severity items.

```python
# refactoring_suggester.py
import google.generativeai as genai
from pathlib import Path
import time
import re

def generate_refactoring_suggestion(
    file_path: str,
    original_code: str,
    debt_description: str,
    context_code: str = ""
) -> dict:
    """
    Generate a specific refactoring suggestion with code for a given file.
    
    Args:
        file_path: Path to the target file
        original_code: Current code to refactor
        debt_description: Description of the technical debt
        context_code: Code from related files (for understanding dependencies)
    
    Returns:
        {
            "explanation": "Why and how to refactor",
            "refactored_code": "The updated code",
            "breaking_changes": ["List of breaking changes"],
            "test_suggestions": ["Tests to add"]
        }
    """
    genai.configure(api_key='YOUR_GEMINI_API_KEY')
    model = genai.GenerativeModel(
        model_name='gemini-2.5-pro',
        generation_config={
            'temperature': 0.3,
            'max_output_tokens': 8192,
        }
    )
    
    context_section = ""
    if context_code:
        context_section = f"\n\n[Related files for dependency context]\n{context_code}"
    
    prompt = f"""
Create a refactoring proposal for the following code.

**File**: {file_path}
**Problem**: {debt_description}

[Current code]
```
{original_code}
```
{context_section}

Provide all four of the following:

1. **Explanation** — Why this refactor is needed, and what specifically improves

2. **Refactored code** — In a code block, with comments marking what changed

3. **Breaking change risks** — Any changes that affect callers (can be "None")

4. **Tests to add** — Test cases to write before applying this change

Favor incremental changes over complete rewrites. The first step should be the smallest change that delivers real improvement.
"""
    
    print(f"🔧 Generating refactoring suggestion: {file_path}")
    start_time = time.time()
    
    try:
        response = model.generate_content(
            prompt,
            request_options={"timeout": 180}
        )
        elapsed = time.time() - start_time
        print(f"✅ Done ({elapsed:.1f}s)")
        
        text = response.text
        
        code_blocks = re.findall(r'```(?:\w+)?\n(.*?)```', text, re.DOTALL)
        refactored_code = code_blocks[0] if code_blocks else ""
        
        breaking_changes = []
        for keyword in ['Breaking change', 'breaking change']:
            if keyword in text:
                section = text.split(keyword)[1].split('\n\n')[0]
                breaking_changes = [
                    line.strip().lstrip('- ')
                    for line in section.split('\n')
                    if line.strip() and len(line.strip()) > 3
                ][:5]
                break
        
        test_suggestions = []
        for keyword in ['Tests to add', 'test cases', 'Test cases']:
            if keyword in text:
                section = text.split(keyword)[1].split('\n\n')[0]
                test_suggestions = [
                    line.strip().lstrip('- ')
                    for line in section.split('\n')
                    if line.strip() and len(line.strip()) > 5
                ][:5]
                break
        
        return {
            "explanation": text,
            "refactored_code": refactored_code,
            "breaking_changes": breaking_changes,
            "test_suggestions": test_suggestions,
            "elapsed_seconds": elapsed,
        }
        
    except Exception as e:
        print(f"❌ Error: {e}")
        return {
            "explanation": f"Error: {e}",
            "refactored_code": "",
            "breaking_changes": [],
            "test_suggestions": [],
        }


def apply_suggestions_to_project(
    debt_items: list,
    codebase_root: str,
    top_n: int = 5
) -> None:
    """
    Generate refactoring suggestions for the top N debt items
    and save each as a Markdown proposal file.
    """
    output_dir = Path('refactoring_suggestions')
    output_dir.mkdir(exist_ok=True)
    
    for i, item in enumerate(debt_items[:top_n], 1):
        print(f"\n[{i}/{top_n}] Processing: {item.file_path}")
        
        file_full_path = Path(codebase_root) / item.file_path
        if not file_full_path.exists():
            print(f"⚠️  File not found: {file_full_path}")
            continue
        
        original_code = file_full_path.read_text(encoding='utf-8', errors='ignore')
        
        suggestion = generate_refactoring_suggestion(
            file_path=item.file_path,
            original_code=original_code,
            debt_description=item.description,
        )
        
        safe_name = item.file_path.replace('/', '_').replace('.', '_')
        output_path = output_dir / f"{i:02d}_{safe_name}.md"
        
        content = f"""# Refactoring Proposal: {item.file_path}

**Severity**: {item.severity}/10
**Category**: {item.debt_type}
**Estimated fix time**: {item.estimated_fix_hours}h
**Problem**: {item.description}

---

{suggestion['explanation']}

## Before You Apply

**Breaking change risks:**
{chr(10).join(f'- {c}' for c in suggestion['breaking_changes']) if suggestion['breaking_changes'] else '- None identified'}

**Tests to write first:**
{chr(10).join(f'- {t}' for t in suggestion['test_suggestions']) if suggestion['test_suggestions'] else '- No specific tests suggested'}
"""
        output_path.write_text(content, encoding='utf-8')
        print(f"💾 Saved: {output_path}")
        
        # Rate limit buffer — Gemini Pro has limits on requests per minute
        if i < top_n:
            time.sleep(10)
    
    print(f"\n✅ Done. {top_n} proposals saved to {output_dir}/")
```

Note the explicit `time.sleep(10)` between requests. Gemini API has per-minute request limits, and batching large-context requests without any delay will hit `429 Too Many Requests` faster than you'd expect. For production-scale usage with many files, see [Gemini API rate limiting and quota management](/articles/gemini-api/gemini-api-rate-limiting-quota-management-production-guide) for queue-based retry patterns.

## Common Pitfalls and How to Handle Them

Three things tripped me up when I first built this pipeline:

**Pitfall 1: Underestimating token count**

The "chars ÷ 4 = tokens" rule breaks down when your codebase has mixed-language comments. Japanese text can run 2–3 tokens per character, so codebases with Japanese comments may run 1.5–2x more tokens than the simple estimate. When precision matters, use the `tiktoken` library with the `cl100k_base` encoder, or hit the Gemini API's token counting endpoint directly before sending a large payload.

**Pitfall 2: More JSON parse failures than expected**

Gemini doesn't always produce perfectly valid JSON, especially when explanation fields contain quotes or newlines. Never pass `response.text` directly to `json.loads()`. Always: extract from code block → strip surrounding text → parse. The scripts above implement this three-step approach.

**Pitfall 3: Full scans are expensive to run frequently**

A near-1M-token request to Gemini 2.5 Pro can cost $2–5 per run. Running that on every commit isn't realistic. My recommendation: weekly full scans + diff-only scans on pull requests. For the diff-only approach, [Gemini API Context Caching](/articles/gemini-api/context-caching-guide) can dramatically reduce costs by caching the unchanged portions of your codebase across repeated requests.

**Pitfall 4: Timeouts on large context requests**

Requests near the 1M token limit can take 30–60 seconds to respond. Most HTTP clients default to 30-second timeouts, which means large requests get cut off. Always set an explicit timeout:

```python
response = model.generate_content(
    prompt,
    request_options={"timeout": 300}  # 5 minutes
)
```

## Continuous Code Quality Management

Once the pipeline is set up, it fits naturally into ongoing quality workflows.

**Weekly automated reports**: I run a full scan every Sunday night via GitHub Actions. If the architecture score drops week-over-week, or new critical debt items appear, a summary hits my Slack. Early detection of quality regressions before they become load-bearing.

**PR-level spot reviews**: For pull requests, I send only the changed files — not the full codebase. The cost per PR drops to a few cents. It catches newly introduced issues before they merge.

**Monthly architecture snapshots**: I commit each month's architecture review as a Markdown file in the repo. It creates a design history you can reference six months later when you're wondering "why did we build it this way?"

For deeper coverage of handling large text inputs effectively, [Gemini Long Context practical patterns](/articles/gemini-advanced/gemini-long-context-practical-patterns) covers chunking strategies, prompt structuring, and retrieval patterns when context gets complex.


## Putting It All Together: The Full Pipeline

Here's how the three scripts work together in practice. This wrapper ties them into a single command you can run from the project root.

```python
# run_analysis.py — Full pipeline runner
import sys
import json
import time
from pathlib import Path
from datetime import datetime

from collect_codebase import collect_codebase
from architecture_review import run_architecture_review, format_report
from tech_debt_scorer import analyze_tech_debt, print_debt_summary
from refactoring_suggester import apply_suggestions_to_project

def run_full_analysis(
    project_root: str = '.',
    project_name: str = 'MyProject',
    top_refactoring: int = 3,
    skip_refactoring: bool = False
) -> None:
    """
    Run the full codebase analysis pipeline.

## When the Output Surprises You

One thing I want to prepare you for: the first run will almost certainly surface issues you didn't expect. That's not a sign that your code is bad — it's a sign that the tool is working.

A few things that might happen, and how to interpret them:

**"Overall score: 5/10"** — This doesn't mean your project is broken. The scoring calibrates against ideal enterprise-grade code, not working indie apps. A score of 5-6 is common for solo projects that actually ship and iterate. What matters is the trend over time, not the absolute value.

**Lots of "dead code" items** — Feature flags, legacy code paths, and half-removed experiments all get flagged. Before deleting anything, check git blame and recent commit messages. Some "dead" code is intentionally preserved.

**Coupling issues in your main entry point** — Entry points (index.ts, App.swift, etc.) naturally accumulate dependencies. These will show up as coupling issues almost universally. In practice, they're lower priority than coupling in business logic layers.

**The same file appearing multiple times** — If one file has both a complexity issue and a naming issue, it appears in the debt list twice. This is correct behavior and a signal that the file needs more comprehensive attention.

The architecture review output is a starting point for conversation with yourself — or with a team. Use it to make deliberate decisions, not as a checklist to clear mechanically.

## Adapting the Prompts for Your Stack

The review quality improves significantly when you tailor the architecture analysis prompt to your specific tech stack. The default prompts in this guide work reasonably well across projects, but the highest-value insights come when Gemini has clear context about what "good code" looks like for your particular combination of frameworks and patterns.

Here are concrete customizations by stack type:

**React / Next.js frontend:**
Add to the "Analysis dimensions" section:
- Hook dependency arrays (missing deps, unnecessary deps in useEffect)
- Server Component vs. Client Component boundary placement
- Data fetching patterns (RSC vs. client-side fetch vs. SWR/React Query)
- Prop drilling depth and unnecessary context usage

**Node.js / Express backend:**
- Middleware ordering and error propagation
- Async/await vs. callback mixing
- Missing request validation (body, query params, path params)
- Database query placement (queries in routes vs. repository layer)

**Swift / iOS:**
- View controller size (>300 lines is a signal)
- Memory management (retain cycles in closures)
- Main thread violations in async callbacks
- Codable model completeness for API responses

**Python / FastAPI:**
- Pydantic model validation coverage
- Dependency injection correctness
- Background task vs. async endpoint usage
- Exception handler completeness

You can inject these additions into the prompt dynamically:

```python
def build_architecture_prompt(codebase_text: str, project_name: str, stack_hints: list[str]) -> str:
    """Build a stack-aware architecture review prompt."""
    
    stack_section = ""
    if stack_hints:
        stack_section = "\n\n[Stack-specific review dimensions]\n" + "\n".join(
            f"- {hint}" for hint in stack_hints
        )
    
    return f"""
You are a senior software architect specializing in {", ".join(stack_hints[:2]) if stack_hints else "modern web applications"}.

Analyze the codebase below and report architectural issues.

Project: {project_name}{stack_section}

[Standard analysis dimensions]
1. Layer separation (Presentation / Business Logic / Data Access)
2. Single Responsibility Principle violations
3. Cross-cutting concerns consistency (auth, logging, error handling)
4. Naming convention consistency
5. Dead code and circular dependencies

[Output format]
{{
  "overall_score": integer 1-10,
  "summary": "2-3 sentence assessment",
  "critical_issues": [...],
  "positive_patterns": [...],
  "priority_refactoring": [...]
}}

Codebase:
{codebase_text}
"""

One more tip: when you're analyzing a project you inherited rather than built yourself, add this line to the prompt: "Note any patterns that suggest this code was originally written for a different architecture or framework than the one it's currently deployed with." This surfaces migration artifacts that would otherwise look like ordinary tech debt.
