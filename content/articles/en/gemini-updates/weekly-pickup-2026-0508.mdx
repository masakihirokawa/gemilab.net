## A Minimal Implicit Caching Setup

A small piece of the #2 article — the most basic shape for keeping your cached prefix stable.

```python
import os
from google import genai
from google.genai import types

client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])

# Pass the same system instruction and tool definitions in the same
# order and with the same byte shape on every call.
SYSTEM_INSTRUCTION = (
    "You are a careful editor. "
    "Always preserve original meaning and tone."
)

def cached_request(user_text: str) -> str:
    response = client.models.generate_content(
        model="gemini-3.2-pro",
        contents=user_text,
        config=types.GenerateContentConfig(
            system_instruction=SYSTEM_INSTRUCTION,
            temperature=0.2,
        ),
    )
    return response.text

# Reusing the same SYSTEM_INSTRUCTION across requests maximizes
# the benefit of implicit caching's prefix reuse.
for line in ["Hello.", "Have a good day.", "Thank you."]:
    print(cached_request(line))
```

The habit that matters: define `SYSTEM_INSTRUCTION` at module scope, never inside the function. The visible behavior is the same; the *byte-level* identity is what stabilizes the SDK's serialization and lifts cache-hit rates.

## Reader Questions

### Should I move to Gemini 3.2 Pro right away?

The honest answer depends on the depth of your prompt test coverage. If you have a meaningful golden set, it's absolutely worth running the 7-day playbook from #1. If your tests are thin, build them first; rushing a migration you can't measure is how you sleepwalk into a quality regression.

### PWA or browser extension?

My current take: PWAs win on window management; extensions win on context sharing with whatever you're doing on the page. The #4 article maps this out by use case so you don't have to pick blindly.

### Why build a homemade data agent instead of using Looker?

For solo developers building "an assistant for myself," tools like Looker carry too much process overhead and limit how much you can customize the natural-language interface. As long as your data is small, DuckDB + Streamlit is dramatically lighter — that's the spirit of the #3 article.
