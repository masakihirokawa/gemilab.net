A model you picked yesterday isn't in today's list. On September 18, a thread appeared on the AI Studio community forum saying exactly that: Gemini 2.5 Pro was there in the afternoon and gone by evening. Replies mentioned conversations freezing when the picker emptied. Reading it, I felt that small sinking feeling in my stomach.

What I'd like to say first is that **"not in the list" and "deprecated" are different things.** Here is how I tell them apart, and the order in which I now keep my history safe.

## Check the official page before deciding

I opened the deprecations page on October 21, 2026. It listed these rows:

The same page says access to the 2.5 models is limited to people who have actively used them in the past, that the models are not deprecated, and that they'll keep being served until further notice. For new projects it points to 3.5 Flash-Lite or 3.8 Flash.

So no shutdown date exists, but visibility has been narrowed. New users, or accounts judged inactive, may simply not see the models.

## Which one are you seeing?

Checking both the UI and the API speeds this up.

1. In AI Studio, click the blank area of the model picker to expand the list. A forum user reported that this worked; I haven't reproduced it myself.
2. Call the same model name with a key from a different project and compare results.
3. If you get a 404, suspect the access restriction before a typo. I wrote up that triage in [the 2.5 Flash 404 with no announced shutdown date](/articles/gemini-api/gemini-25-flash-404-no-longer-available-shutdown-date-unannounced).

Some forum posters guessed it was about plan tiers or cost. That rested on a video, not on anything official, so I'm leaving it out of my assumptions.

## Check from the API whether the model is visible to your key

The picker only shows you what it shows you. So I ask the API for the models my key can see and look for the 2.5 names.

```bash
# Replace YOUR_API_KEY with your own key
curl -s "https://generativelanguage.googleapis.com/v1beta/models?pageSize=200" \
  -H "x-goog-api-key: YOUR_API_KEY" \
  | grep '"name"' | grep -E "gemini-2\.5"
```

Each `name` comes back with a `models/` prefix, such as `models/gemini-2.5-pro`. When you call the model, you use the name without the prefix.

If no 2.5 line appears, the plain reading is that the project behind that key can't see them. If lines do appear, only the picker is narrowed. Neither result **proves a shutdown date has been set**; this check tells you about your own view, nothing more. I haven't verified how the output varies across accounts, so don't be surprised if two keys disagree.

## Triage by symptom

Here are three symptoms, with the order in which I suspect causes.

<thead>
<tr><th>Symptom</th><th>Suspect first</th><th>Check next</th><th>Avoid</th></tr>
</thead>
<tbody>
<tr><td>2.5 Pro is missing from the picker</td><td>Access narrowed to past users</td><td>The 2.5 rows on the deprecations page; expanding the list</td><td>Assuming deprecation and abandoning the chat</td></tr>
<tr><td>The API returns 404</td><td>A different project, or a typo in the model name</td><td>A key from another project; the model list above</td><td>Rewriting to another model before you know why</td></tr>
<tr><td>A past conversation won't continue</td><td>The model it is tied to can't be selected</td><td>Whether you have an exported copy</td><td>Closing the tab before exporting, or starting over</td></tr>
</tbody>
</table>

The third row deserves action before diagnosis. A conversation you can no longer continue can still be copied out while it's on screen, and you can paste it into another model later.

## Note the page's "last updated" date

The deprecations page shows an update date at the bottom. When I read it, it said October 20, 2026 (UTC). Copying the table isn't enough; **write down the date with it**, and a few weeks later you can see what moved.

My routine: one line in the project notes with the day I checked and the three 2.5 rows. Next time, if the page's date is newer, I read only the difference. That's far less tiring than rereading the whole page.

## Keep history independent of the model

As an indie developer, I tend to leave prototype conversations sitting in AI Studio. I knew a model could disappear from under them, and I hadn't prepared. That did not go well. Now I do three things regardless of what any model does:

- Export conversations I care about to a document at milestones. Check who can see the export first, as I describe in [checking sharing before sending an export](/articles/gemini-advanced/gemini-export-to-docs-check-sharing-before-sending).
- Write the model name and date on the first line of each conversation, so I know what to paste where later.
- For API work, pin the model name and log the model that comes back. I covered that in [pinning defaults and detecting silent swaps](/articles/gemini-api/gemini-api-default-model-pinning-silent-upgrade-detection-production).

**Models may move; the record stays on my side.** I try to hold that line even in busy weeks.

## One next step

Pick a single conversation you can't afford to lose, export it, and add the model name and date at the top. Official pages change, and this reflects October 21, 2026, so open the deprecations page first whenever something stops working.
