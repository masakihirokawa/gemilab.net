## はじめに — Django × Gemini API という組み合わせの魅力

PythonのWebフレームワークとしてDjangoは長年にわたり多くの開発者に支持されてきましました。認証システム、管理画面、ORM、セッション管理など、本番運用に必要な機能が最初から揃っている「バッテリー同梱」の設計思想は、AIアプリケーション開発においても大きな強みとなります。

一方、Gemini APIはテキスト生成・マルチモーダル理解・Function Callingなど、幅広いAI機能を提供しています。この2つを組み合わせることで、認証付きのAIチャットアプリや、管理画面からプロンプトを管理できるシステムなど、実用的なAIアプリケーションを効率よく構築できます。

ここではDjangoプロジェクトのセットアップからチャット機能の実装、さらにストリーミングレスポンスの配信まで、段階的に解説していきます。Djangoの基本的な知識がある方を対象としていますが、AI連携が初めてでも理解できるよう丁寧に進めます。

## 環境構築 — Django プロジェクトと Gemini API のセットアップ

まず、必要なパッケージをインストールしてDjangoプロジェクトを作成します。

```bash
# 仮想環境の作成と有効化
python -m venv venv
source venv/bin/activate

# パッケージのインストール
pip install django google-genai python-dotenv

# Djangoプロジェクトとアプリの作成
django-admin startproject mysite
cd mysite
python manage.py startapp ai_chat
```

APIキーを安全に管理するため、プロジェクトのルートに `.env` ファイルを作成します。

```bash
# .env
GEMINI_API_KEY=YOUR_API_KEY
```

次に、`settings.py` で環境変数を読み込む設定を行います。

```python
# mysite/settings.py
import os
from dotenv import load_dotenv

load_dotenv()

INSTALLED_APPS = [
    # ... 既存のアプリ
    'ai_chat',
]

GEMINI_API_KEY = os.getenv('GEMINI_API_KEY')
```

`ai_chat` アプリを `INSTALLED_APPS` に追加し、APIキーを設定から参照できるようにしました。`.env` ファイルは必ず `.gitignore` に追加してください。

## 基本実装 — Django ビューから Gemini API を呼び出す

Gemini APIとの連携ロジックをサービス層として分離することで、ビューをシンプルに保ちます。

```python
# ai_chat/services.py
from google import genai
from django.conf import settings

# クライアントをモジュールレベルで初期化（リクエストごとの再生成を防ぐ）
client = genai.Client(api_key=settings.GEMINI_API_KEY)

def generate_response(prompt: str, model: str = "gemini-2.5-flash") -> str:
    """Gemini APIにプロンプトを送信し、テキストレスポンスを返す"""
    response = client.models.generate_content(
        model=model,
        contents=prompt,
    )
    return response.text
```

このサービスをビューから呼び出します。

```python
# ai_chat/views.py
import json
from django.http import JsonResponse
from django.views.decorators.csrf import csrf_exempt
from django.views.decorators.http import require_http_methods
from .services import generate_response

@csrf_exempt
@require_http_methods(["POST"])
def chat_api(request):
    """AIチャットのAPIエンドポイント"""
    try:
        body = json.loads(request.body)
        user_message = body.get("message", "")

        if not user_message:
            return JsonResponse({"error": "メッセージが空です"}, status=400)

        # Gemini APIを呼び出し
        ai_response = generate_response(user_message)

        return JsonResponse({
            "response": ai_response,
            "model": "gemini-2.5-flash",
        })

    except Exception as e:
        return JsonResponse({"error": str(e)}, status=500)
```

URL設定も忘れずに行います。

```python
# ai_chat/urls.py
from django.urls import path
from . import views

urlpatterns = [
    path('api/chat/', views.chat_api, name='chat_api'),
]

# mysite/urls.py
from django.urls import path, include

urlpatterns = [
    path('', include('ai_chat.urls')),
]
```

これで `POST /api/chat/` にメッセージを送ると、Gemini APIからの応答が返ってくる基本的なエンドポイントが完成しました。

## マルチターン会話の実装 — セッションで会話履歴を管理する

実用的なチャットアプリでは、会話の文脈を維持する必要があります。Djangoのセッション機能を使って会話履歴を管理する方法を紹介します。

```python
# ai_chat/services.py（拡張版）
from google import genai
from google.genai import types
from django.conf import settings

client = genai.Client(api_key=settings.GEMINI_API_KEY)

def generate_chat_response(
    message: str,
    history: list[dict],
    model: str = "gemini-2.5-flash"
) -> str:
    """会話履歴を含めてGemini APIを呼び出す"""
    # 履歴をGemini API形式に変換
    contents = []
    for entry in history:
        contents.append(
            types.Content(
                role=entry["role"],
                parts=[types.Part(text=entry["text"])]
            )
        )
    # 今回のユーザーメッセージを追加
    contents.append(
        types.Content(
            role="user",
            parts=[types.Part(text=message)]
        )
    )

    response = client.models.generate_content(
        model=model,
        contents=contents,
    )
    return response.text
```

ビュー側でセッションに履歴を保存します。

```python
# ai_chat/views.py（拡張版）
import json
from django.http import JsonResponse
from django.views.decorators.csrf import csrf_exempt
from django.views.decorators.http import require_http_methods
from .services import generate_chat_response

@csrf_exempt
@require_http_methods(["POST"])
def chat_api(request):
    """マルチターン対応のチャットAPIエンドポイント"""
    try:
        body = json.loads(request.body)
        user_message = body.get("message", "")

        if not user_message:
            return JsonResponse({"error": "メッセージが空です"}, status=400)

        # セッションから会話履歴を取得
        history = request.session.get("chat_history", [])

        # Gemini APIを呼び出し
        ai_response = generate_chat_response(user_message, history)

        # 履歴を更新
        history.append({"role": "user", "text": user_message})
        history.append({"role": "model", "text": ai_response})

        # 履歴が長くなりすぎないよう直近20件に制限
        if len(history) > 20:
            history = history[-20:]

        request.session["chat_history"] = history

        return JsonResponse({
            "response": ai_response,
            "history_length": len(history),
        })

    except Exception as e:
        return JsonResponse({"error": str(e)}, status=500)

@csrf_exempt
@require_http_methods(["POST"])
def reset_chat(request):
    """会話履歴をリセットする"""
    request.session["chat_history"] = []
    return JsonResponse({"status": "reset"})
```

Djangoのセッションミドルウェアが自動的にCookieベースのセッション管理を行うため、ユーザーごとに独立した会話履歴を保持できます。本番環境ではRedisやデータベースバックエンドを使ったセッション管理を検討すると良いでしょう。

より高度なセッション管理パターンや、大規模チャットボットのアーキテクチャについては、[Gemini API の長期記憶とセッション永続化ガイド](/articles/gemini-advanced/gemini-api-long-memory-session-persistence-chatbot-architecture) で詳しく解説しています。

## ストリーミングレスポンスの実装 — リアルタイムにAI応答を配信する

ChatGPTのようにトークンが一つずつ表示される体験を実現するには、ストリーミングレスポンスが必要です。DjangoではStreamingHttpResponseを使って実装できます。

```python
# ai_chat/services.py（ストリーミング対応追加）
def generate_stream_response(
    message: str,
    history: list[dict],
    model: str = "gemini-2.5-flash"
):
    """ストリーミングでGemini APIを呼び出すジェネレータ"""
    contents = []
    for entry in history:
        contents.append(
            types.Content(
                role=entry["role"],
                parts=[types.Part(text=entry["text"])]
            )
        )
    contents.append(
        types.Content(
            role="user",
            parts=[types.Part(text=message)]
        )
    )

    response = client.models.generate_content_stream(
        model=model,
        contents=contents,
    )

    for chunk in response:
        if chunk.text:
            yield chunk.text
```

ビュー側でServer-Sent Events（SSE）として配信します。

```python
# ai_chat/views.py（ストリーミング対応追加）
import json
from django.http import StreamingHttpResponse
from .services import generate_stream_response

@csrf_exempt
@require_http_methods(["POST"])
def chat_stream_api(request):
    """SSEでストリーミングレスポンスを返すエンドポイント"""
    body = json.loads(request.body)
    user_message = body.get("message", "")
    history = request.session.get("chat_history", [])

    def event_stream():
        full_response = ""
        for chunk_text in generate_stream_response(user_message, history):
            full_response += chunk_text
            # SSE形式でチャンクを送信
            yield f"data: {json.dumps({'text': chunk_text})}\n\n"

        # ストリーム完了を通知
        yield f"data: {json.dumps({'done': True})}\n\n"

        # 会話履歴を更新（注意: ストリーミング中はセッション更新不可のため
        # 完了後にフロントエンドから別途リクエストで更新する設計が推奨）

    response = StreamingHttpResponse(
        event_stream(),
        content_type='text/event-stream'
    )
    response['Cache-Control'] = 'no-cache'
    response['X-Accel-Buffering'] = 'no'
    return response
```

フロントエンド側では、`EventSource` またはfetchのReadableStreamで受信します。

```javascript
// フロントエンドでのストリーミング受信例
async function sendMessage(message) {
  const response = await fetch('/api/chat/stream/', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ message }),
  });

  const reader = response.body.getReader();
  const decoder = new TextDecoder();

  while (true) {
    const { done, value } = await reader.read();
    if (done) break;

    const text = decoder.decode(value);
    const lines = text.split('\n');

    for (const line of lines) {
      if (line.startsWith('data: ')) {
        const data = JSON.parse(line.slice(6));
        if (data.done) break;
        // UIにテキストを追記
        appendToChat(data.text);
      }
    }
  }
}
```

ストリーミングとFunction Callingの組み合わせなど、より高度な手法については [Gemini APIストリーミング×Function Calling統合ガイド](/articles/gemini-api/gemini-api-streaming-function-calling-guide) もあわせてご確認ください。

## 本番環境への準備 — セキュリティとパフォーマンスの考慮事項

DjangoでGemini APIを利用するアプリを本番環境にデプロイする際には、いくつかの重要なポイントがあります。

**APIキーの保護**: 環境変数で管理するだけでなく、レート制限ミドルウェアを導入して不正利用を防止しましょう。Django REST Frameworkのthrottlingクラスを活用すると、IPアドレスやユーザー単位でのリクエスト制限を簡単に設定できます。

**非同期処理の活用**: Django 4.1以降では非同期ビューがサポートされています。Gemini APIの呼び出しはI/Oバウンドな処理であるため、非同期ビューを使うことでスループットを大幅に改善できます。

```python
# 非同期ビューの例
import asyncio
from django.http import JsonResponse
from asgiref.sync import sync_to_async

async def async_chat_api(request):
    """非同期版チャットAPIエンドポイント"""
    body = json.loads(request.body)
    user_message = body.get("message", "")

    # 同期関数を非同期で呼び出す
    ai_response = await sync_to_async(generate_response)(user_message)

    return JsonResponse({"response": ai_response})
```

**Celeryによるバックグラウンド処理**: 長時間かかるAIタスク（大量の文書解析、バッチ処理など）はCeleryキューに委任することで、ユーザー体験を損なわずに処理できます。

**エラーハンドリング**: API呼び出しが失敗した場合のリトライロジックとグレースフルデグレーデーションを実装しましょう。本番環境でのより包括的なエラーハンドリングパターンについては、[Gemini API エラーハンドリング＆レート制限 完全攻略](/articles/gemini-dev/gemini-api-error-handling-rate-limit-production-patterns) で体系的に解説しています。
