Chrome の DevTools を開いて `await LanguageModel.availability()` と打ち込むと、条件さえ揃っていれば `"available"` が返ってきます。その瞬間、目の前のブラウザが Gemini Nano を搭載した推論エンジンに変わったことに気づくはずです。

ここ半年ほどで Chrome の Built-in AI API は安定版に近づいてきました。私自身、個人開発している Web ツールで実際に本番投入してみて、「サーバーを持たずに軽い要約・分類を返す」機能がローカル完結することの気持ちよさを何度も感じています。ここではPrompt API と Summarizer API を中心に、ブラウザから Gemini Nano を呼ぶ実装の流れを整理します。

2014年からアプリ事業を続けている個人開発者の経験から、この問題に普段から向き合ってきた立場で、要点を整理します。

## どんなときにブラウザ内蔵 AI を選ぶか

サーバー側で Gemini API を叩く構成に比べ、ブラウザ内蔵 AI には次のような明確な向き・不向きがあります。

- **向いているケース**: ユーザーの入力内容をサーバーに送りたくない（プライバシー）・レスポンス体感を最優先したい・API コストをゼロにしたい・オフラインでも動いてほしい
- **向いていないケース**: 100万トークン級の長文処理・高精度の推論（複雑な数理・コーディング）・最新知識の参照が必須なタスク

私は「ユーザーが入力した文章の下書き整形」「クリップボードの内容を3行で要約」「入力の感情分析でアイコン切り替え」といった、失敗しても大きな実害がない UX 補助用途に絞って使っています。重要な判断に関わる処理は、引き続きクラウド側の Gemini 2.5 Pro / Flash に任せる設計が実用的です。

## 実行環境の前提条件（2026年4月時点）

Prompt API を使うには、以下の条件をすべて満たしている必要があります。

- Chrome 安定版（128 以降が推奨、本記事執筆時点の最新は Chrome 135）
- Windows 10/11、macOS 13 以降、Linux、ChromeOS のいずれか
- 空きストレージ 22 GB 以上（モデルは約 2 GB だがダウンロード時に余裕が必要）
- GPU VRAM 4 GB 以上、またはデバイス側で Gemini Nano がオンになっていること
- インターネット接続（初回モデルダウンロード時のみ）

Android 版 Chrome でも順次展開されていますが、本記事ではデスクトップ版を前提にします。

### 有効化の手順

1. `chrome://flags/#prompt-api-for-gemini-nano` を開き、「Enabled」に切り替える
2. `chrome://flags/#optimization-guide-on-device-model` を「Enabled BypassPerfRequirement」にする
3. Chrome を再起動する
4. `chrome://components/` で「Optimization Guide On Device Model」のバージョンが `0.0.0.0` でないことを確認し、必要なら「アップデートを確認」をクリック

私は初回、モデルのダウンロードに 10 分ほどかかりました。進捗は `chrome://components/` に戻って眺めるか、後述の `monitor` コールバックで確認できます。

## Prompt API の最小実装

まずは最も単純な「1回だけプロンプトを送って結果を受け取る」パターンから始めます。このコードを HTML ファイルに貼り付け、Chrome で開いて DevTools コンソールから実行すれば動きます。

```html
<!doctype html>
<meta charset="utf-8" />
<title>Prompt API Minimum</title>
<button id="run">要約する</button>
<textarea id="input" rows="6" cols="60">
最近、個人開発の Web ツールにブラウザ内蔵 AI を組み込んでみたところ、サーバー費用がゼロのまま「軽いAI機能」を提供できるようになりました。ユーザー体験は滑らかで、プライバシーの懸念も抑えられます。
</textarea>
<pre id="output"></pre>
<script type="module">
const $input = document.querySelector("#input");
const $output = document.querySelector("#output");

document.querySelector("#run").addEventListener("click", async () => {
  // 1. 使えるかチェック（"available" / "downloadable" / "downloading" / "unavailable"）
  const status = await LanguageModel.availability();
  if (status === "unavailable") {
    $output.textContent = "この環境では Prompt API は使えません";
    return;
  }

  // 2. セッションを作る（ダウンロードが必要な場合は monitor で進捗を表示）
  const session = await LanguageModel.create({
    monitor(m) {
      m.addEventListener("downloadprogress", (e) => {
        $output.textContent = `モデル取得中: ${(e.loaded * 100).toFixed(1)}%`;
      });
    },
    initialPrompts: [
      { role: "system", content: "あなたは日本語の文章を2文以内で要約するアシスタントです。" },
    ],
  });

  // 3. プロンプトを送る
  const result = await session.prompt($input.value);
  $output.textContent = result;

  // 4. 使い終わったら破棄（メモリを返す）
  session.destroy();
});
</script>
```

期待する出力例: 「個人開発の Web ツールに Chrome の内蔵 AI を組み込むと、サーバー費用ゼロで軽い AI 機能を提供できます。体験は滑らかで、プライバシー面でも有利です。」

ポイントは 3 つあります。**`availability()` を必ず最初に呼ぶこと**、**`system` プロンプトを `initialPrompts` で渡すこと**（`create({ systemPrompt })` は 2026 年に入って非推奨になりました）、そして**使い終わったら `destroy()` を呼んでリソースを解放すること**です。

## ストリーミングで UX を滑らかにする

要約や説明文生成では、結果が徐々に現れるほうが体感速度が劇的に上がります。Prompt API は `promptStreaming()` で非同期イテレータを返してくれます。

```js
async function streamRewrite(text) {
  const session = await LanguageModel.create({
    initialPrompts: [
      { role: "system", content: "入力された日本語を、敬体（ですます調）で自然に書き直してください。" },
    ],
  });

  const stream = session.promptStreaming(text);
  let full = "";
  for await (const chunk of stream) {
    full += chunk; // 2025年終盤から差分（delta）のみが流れてくる仕様に統一されました
    document.querySelector("#output").textContent = full;
  }
  session.destroy();
  return full;
}
```

以前は「これまでの累積文字列」が毎回流れてきたため重複除去が必要でしたが、現在は純粋な差分が流れてきます。古い記事を参考にするときは `for await` の中で `+=` しているか、代入しているかに注意してください。

## 会話を続ける — マルチターンのセッション管理

`session` は会話履歴を保持します。`prompt()` を何度呼んでも、それまでのやり取りを踏まえて応答が返ります。ただし、Gemini Nano はコンテキストウィンドウが小さいため、長い会話になるほど古い発話を落とす工夫が必要です。

```js
const session = await LanguageModel.create({
  initialPrompts: [
    { role: "system", content: "入力内容を3段階（低・中・高）のリスクで分類してください。出力はラベル1語のみ。" },
  ],
});

console.log(await session.prompt("明日、仕事終わりに友人と会う予定を入れました。"));
// → "低"
console.log(await session.prompt("海外出張で深夜便に乗ります。空港で仮眠のみです。"));
// → "中"

// 履歴が長くなったら clone して新セッションにする
const fresh = await session.clone();
session.destroy();
```

`tokensLeft` プロパティで残容量を確認できるので、一定値を切ったら `clone()` または `destroy()` して再生成するのが安全です。

## Summarizer API — 専用タスクはこちらが早い

要約に限れば、汎用の Prompt API より専用の Summarizer API のほうが結果が安定し、起動も軽いです。私はブログ下書きの自動要約で使っていますが、タイトルや TL;DR の下敷きには十分使える品質です。

```js
const summarizer = await Summarizer.create({
  type: "tl;dr",        // "key-points" / "teaser" / "headline" も選べます
  format: "plain-text", // "markdown" を選ぶと箇条書きに整形されます
  length: "short",      // "medium" / "long"
  sharedContext: "技術ブログの記事本文を、読者が忙しくても要点を掴めるようにまとめる",
});

const text = document.querySelector("#article").innerText;
const summary = await summarizer.summarize(text);
console.log(summary);

summarizer.destroy();
```

`sharedContext` はこのインスタンスで扱う文章の性格を伝えるメタ情報です。ここに「技術ブログ」「カスタマーレビュー」「議事録」など書いておくと、期待するトーンに寄ってくれます。

## よくある落とし穴

実装していて何度か踏んだ罠を共有します。

- **`availability()` が `"downloadable"` を返しっぱなし**: ユーザー操作を伴うイベント（クリック等）の中で `LanguageModel.create()` を呼ばないとダウンロードが始まりません。ページ読み込み時のスクリプト内では開始されない仕様です
- **エラー `NotSupportedError: The model execution service is not available`**: `chrome://components/` でモデルのバージョンが古い、または `optimization-guide-on-device-model` フラグを有効化し忘れているケースが大半です
- **1セッションで `prompt()` を並行で呼べない**: 同時に複数のリクエストを投げると 2 つめが `InvalidStateError` を投げます。複数並行したいときは `session.clone()` か `LanguageModel.create()` で別セッションを作ってください
- **安全性フィルタで空文字が返る**: 入力内容によっては安全性判定でブロックされます。本番では `result.trim().length === 0` のフォールバックを必ず入れておくのが無難です
- **オフライン時のフォールバック**: モデル取得後はオフラインでも動きますが、ユーザーの初回利用時にオフラインだと何も起きません。`navigator.onLine` と `availability()` の組み合わせでエラーメッセージを出し分けましょう

## 機能検出と段階的な実装

全ユーザーが Prompt API を使える環境にいるわけではないので、**機能検出を入れてサーバー側 API とのハイブリッドに倒す**のが現実解です。

```js
async function getAvailableAI() {
  if (typeof LanguageModel === "undefined") return "none";
  const status = await LanguageModel.availability().catch(() => "unavailable");
  if (status === "available") return "on-device";
  if (status === "downloadable" || status === "downloading") return "on-device-pending";
  return "server";
}

const mode = await getAvailableAI();
if (mode === "on-device") {
  // ブラウザ内蔵 AI を使う
} else if (mode === "server") {
  // サーバー側の Gemini API にフォールバック
  await fetch("/api/summarize", { method: "POST", body: text });
}
```

この 2 本立てにしておくと、対応していないブラウザやモバイルからのアクセスでも同じ機能を提供できます。詳しい API 側の実装は [Gemini 2.5 Pro API 完全ガイド 2026](/articles/gemini-api/gemini-25-pro-api-complete-guide-2026) や [Gemini Nano オンデバイス AI 入門](/articles/gemini-dev/gemini-nano-on-device-ai-guide) が参考になります。

## 本番に出す前のチェックリスト

自分が個人プロジェクトで `chrome.dev` のドメインにデプロイする前に通しているチェック項目です。

- 機能検出でフォールバックが効くか（非対応ブラウザで致命的に壊れていないか）
- `monitor` でダウンロード進捗をユーザーに可視化しているか
- `destroy()` をページ離脱時（`beforeunload`）にも呼んでいるか
- プロンプトに個人情報が入る可能性がある場合、ローカルで完結することを UI で明示しているか
- `tokensLeft` を監視して、長時間使うセッションを `clone()` で入れ替える運用になっているか
