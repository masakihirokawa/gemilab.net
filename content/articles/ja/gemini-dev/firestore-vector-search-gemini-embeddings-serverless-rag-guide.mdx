## はじめに — なぜ Firestore でベクトル検索なのか

RAG（Retrieval-Augmented Generation）システムを構築する際、多くの開発者が Pinecone、Qdrant、pgvector などの専用ベクトルデータベースを検討します。しかし、すでに Firebase / Firestore をバックエンドに使っているプロジェクト（[Gemini × Firebase 連携ガイド](/articles/gemini-dev/gemini-firebase-integration-guide)も参照）では、インフラの複雑さとコストが大きな障壁になります。

Firestore が2024年後半にネイティブのベクトル検索機能をリリースしたことで、状況は大きく変わりましました。Firestore のドキュメントにベクトルフィールドを直接格納し、KNN（K-Nearest Neighbors）クエリでセマンティック検索を実行できるようになったのです。

ここではGemini の Embedding モデル（`text-embedding-004` / `embedding-001`、詳しくは[Gemini Embeddings API ガイド](/articles/gemini-api/embeddings-api-guide)を参照）と Firestore Vector Search を組み合わせて、外部ベクトル DB を一切使わないサーバーレス RAG システムを本番品質で構築する方法を、設計思想からコスト最適化まで体系的に解説します。

**対象読者:**

- Firebase / Firestore をすでに使っているプロジェクトで RAG を導入したい開発者
- 専用ベクトル DB のインフラ管理コストを削減したいチーム
- Gemini API の Embeddings を本番で活用したい方

**前提知識:**

- Firebase / Firestore の基本操作（ドキュメント CRUD）
- Node.js / TypeScript の基礎
- Gemini API の基本的な使い方（API キー取得済み）

## Firestore Vector Search の仕組みとアーキテクチャ

### ベクトル検索の基本原理

Firestore のベクトル検索は、ドキュメント内に `FieldValue.vector()` でベクトルデータを格納し、`findNearest()` メソッドで類似ベクトルを検索する仕組みです。内部的には Google のインフラ上で ANN（Approximate Nearest Neighbors）アルゴリズムが実行されます。

**サポートされる距離メトリクス:**

- `COSINE` — コサイン類似度（テキスト検索に最適、正規化済みベクトル向け）
- `EUCLIDEAN` — ユークリッド距離（空間的な近さを重視する場合）
- `DOT_PRODUCT` — 内積（高次元ベクトルでの高速計算）

Gemini Embeddings では正規化済みベクトルが返されるため、**`COSINE` を推奨**します。

### アーキテクチャ全体像

本番 RAG システムの全体アーキテクチャは以下の通りです。

**Embedding 生成パイプライン:**
ドキュメント追加 → Cloud Functions Trigger → Gemini Embeddings API → Firestore ベクトルフィールド更新

**検索・生成パイプライン:**
ユーザークエリ → Gemini Embeddings（クエリベクトル化） → Firestore findNearest() → 関連ドキュメント取得 → Gemini Pro で回答生成

この設計の最大のメリットは、**Firebase エコシステム内で完結する**点です。認証（Firebase Auth）、ストレージ（Cloud Storage）、関数実行（Cloud Functions）、データベース（Firestore）がすべて統合されているため、IAM やネットワーク設定の複雑さが大幅に軽減されます。

## Gemini Embeddings モデルの選択と特性

### モデル比較

Gemini で利用可能な Embedding モデルは複数あります。

**text-embedding-004（推奨）:**
- 次元数: 768（デフォルト）、256/512 にも縮小可能
- 最大入力トークン: 2,048
- 用途: テキスト検索、分類、クラスタリング
- コスト: 無料枠あり、超過分は $0.00001/1,000文字

**embedding-001:**
- 次元数: 768 固定
- 最大入力トークン: 2,048
- 用途: 汎用（旧モデル）
- 注意: 新規プロジェクトでは text-embedding-004 を推奨

**次元数の選択指針:**
Firestore のベクトルフィールドは最大2,048次元をサポートしますが、次元数が多いほどストレージコストとクエリレイテンシが増加します。本番環境では以下を目安にしてください。

- **768次元**: 精度重視（ドキュメント数が10万件未満の場合）
- **512次元**: バランス重視（10万〜100万件）
- **256次元**: コスト重視（100万件超、またはレイテンシが厳しい場合）

### Embedding 生成の実装

```typescript
// lib/embeddings.ts
import { GoogleGenerativeAI } from "@google/generative-ai";

const genAI = new GoogleGenerativeAI(process.env.GEMINI_API_KEY\!);

// text-embedding-004 モデルを使用
const embeddingModel = genAI.getGenerativeModel({
  model: "text-embedding-004",
});

/**
 * テキストから Embedding ベクトルを生成する
 * @param text - 入力テキスト（最大2,048トークン）
 * @param taskType - タスクタイプ（検索精度に影響）
 * @returns 768次元のベクトル配列
 */
export async function generateEmbedding(
  text: string,
  taskType: "RETRIEVAL_DOCUMENT" | "RETRIEVAL_QUERY" = "RETRIEVAL_DOCUMENT"
): Promise<number[]> {
  const result = await embeddingModel.embedContent({
    content: { parts: [{ text }], role: "user" },
    taskType,
  });

  return result.embedding.values;
}

/**
 * バッチ Embedding 生成（最大100テキスト/リクエスト）
 * レート制限: 1,500 RPM（text-embedding-004）
 */
export async function generateEmbeddingsBatch(
  texts: string[],
  taskType: "RETRIEVAL_DOCUMENT" | "RETRIEVAL_QUERY" = "RETRIEVAL_DOCUMENT"
): Promise<number[][]> {
  const result = await embeddingModel.batchEmbedContents({
    requests: texts.map((text) => ({
      content: { parts: [{ text }], role: "user" },
      taskType,
    })),
  });

  return result.embeddings.map((e) => e.values);
}
```

**重要なポイント:**

`taskType` パラメータは検索精度に直接影響します。ドキュメント格納時は `RETRIEVAL_DOCUMENT`、検索クエリ時は `RETRIEVAL_QUERY` を指定してください。これにより、Gemini の Embedding モデルがそれぞれの用途に最適化されたベクトルを生成します。

## Firestore ベクトルインデックスの作成と管理

### ベクトルフィールドの格納

Firestore にベクトルデータを格納する際は、`FieldValue.vector()` を使います。

```typescript
// lib/firestore-vector.ts
import {
  getFirestore,
  FieldValue,
  CollectionReference,
} from "firebase-admin/firestore";
import { generateEmbedding } from "./embeddings";

const db = getFirestore();

interface DocumentData {
  title: string;
  content: string;
  category: string;
  createdAt: FirebaseFirestore.Timestamp;
  embedding?: FirebaseFirestore.VectorValue;
}

/**
 * ドキュメントを Embedding 付きで Firestore に格納する
 */
export async function addDocumentWithEmbedding(
  collectionName: string,
  data: { title: string; content: string; category: string }
): Promise<string> {
  // テキストを結合して Embedding 生成（タイトル + コンテンツ）
  const textForEmbedding = `${data.title}\n\n${data.content}`;

  // 2,048トークン制限に対応するためテキストを切り詰め
  const truncated = truncateToTokenLimit(textForEmbedding, 2000);
  const vector = await generateEmbedding(truncated, "RETRIEVAL_DOCUMENT");

  const docRef = await db.collection(collectionName).add({
    title: data.title,
    content: data.content,
    category: data.category,
    createdAt: FieldValue.serverTimestamp(),
    // ベクトルフィールドとして格納
    embedding: FieldValue.vector(vector),
  });

  return docRef.id;
}

/**
 * トークン数推定で切り詰め（日本語は1文字≒1.5トークン）
 */
function truncateToTokenLimit(text: string, maxTokens: number): string {
  // 日本語テキストの場合、文字数×1.5がおおよそのトークン数
  const estimatedCharsLimit = Math.floor(maxTokens / 1.5);
  if (text.length <= estimatedCharsLimit) return text;
  return text.slice(0, estimatedCharsLimit) + "...";
}
```

### ベクトルインデックスの作成

Firestore でベクトル検索を実行するには、事前にベクトルインデックスを作成する必要があります。これは Firebase CLI または Google Cloud Console から行います。

```bash
# Firebase CLI でベクトルインデックスを作成
gcloud firestore indexes composite create \
  --collection-group=documents \
  --query-scope=COLLECTION \
  --field-config=vector-config='{"dimension":"768","flat":{}}',field-path=embedding

# インデックスの状態を確認
gcloud firestore indexes composite list --format="table(name,state)"
```

**注意点:**

- インデックス作成には数分〜数十分かかる場合があります
- `dimension` は Embedding モデルの出力次元数と一致させてください
- `flat` 設定は小〜中規模データセット向け。100万件超の場合は Google に問い合わせてください
- 複合インデックス（ベクトル + カテゴリフィルターなど）も作成可能です

### 複合インデックスの活用

実際の本番環境では、ベクトル検索にメタデータフィルターを組み合わせることが頻繁にあります。

```bash
# カテゴリフィルター + ベクトル検索の複合インデックス
gcloud firestore indexes composite create \
  --collection-group=documents \
  --query-scope=COLLECTION \
  --field-config=field-path=category,order=ASCENDING \
  --field-config=vector-config='{"dimension":"768","flat":{}}',field-path=embedding
```

## セマンティック検索の実装

### 基本的な類似検索

```typescript
// lib/search.ts
import { getFirestore, VectorQuery } from "firebase-admin/firestore";
import { generateEmbedding } from "./embeddings";

const db = getFirestore();

interface SearchResult {
  id: string;
  title: string;
  content: string;
  category: string;
  score: number;
}

/**
 * セマンティック検索を実行する
 * @param query - ユーザーの検索クエリ
 * @param collectionName - 検索対象コレクション
 * @param limit - 取得件数（デフォルト5件）
 * @param category - カテゴリフィルター（オプション）
 */
export async function semanticSearch(
  query: string,
  collectionName: string,
  limit: number = 5,
  category?: string
): Promise<SearchResult[]> {
  // クエリテキストを Embedding に変換（RETRIEVAL_QUERY タイプ）
  const queryVector = await generateEmbedding(query, "RETRIEVAL_QUERY");

  let collectionRef = db.collection(collectionName);

  // カテゴリフィルターが指定されている場合
  let baseQuery: FirebaseFirestore.Query = collectionRef;
  if (category) {
    baseQuery = collectionRef.where("category", "==", category);
  }

  // findNearest() でベクトル検索を実行
  const vectorQuery: VectorQuery = baseQuery.findNearest({
    vectorField: "embedding",
    queryVector,
    limit,
    distanceMeasure: "COSINE",
    // distanceResultField でスコアを取得可能
    distanceResultField: "vector_distance",
  });

  const snapshot = await vectorQuery.get();

  return snapshot.docs.map((doc) => {
    const data = doc.data();
    return {
      id: doc.id,
      title: data.title,
      content: data.content,
      category: data.category,
      // コサイン距離を類似度スコアに変換（0〜1、1が最も類似）
      score: 1 - (data.vector_distance || 0),
    };
  });
}
```

### スコアしきい値によるフィルタリング

ベクトル検索の結果には、関連性の低いドキュメントが含まれることがあります。本番環境では、スコアしきい値を設けて品質を担保します。

```typescript
/**
 * スコアしきい値付きセマンティック検索
 * しきい値以下の結果を除外して、高品質な検索結果のみ返す
 */
export async function semanticSearchWithThreshold(
  query: string,
  collectionName: string,
  options: {
    limit?: number;
    category?: string;
    minScore?: number; // 0.0〜1.0（デフォルト: 0.7）
  } = {}
): Promise<SearchResult[]> {
  const { limit = 10, category, minScore = 0.7 } = options;

  // 多めに取得してからフィルタリング
  const results = await semanticSearch(
    query,
    collectionName,
    limit * 2,
    category
  );

  // スコアしきい値でフィルタリング
  const filtered = results.filter((r) => r.score >= minScore);

  // 指定件数に切り詰め
  return filtered.slice(0, limit);
}
```

## Cloud Functions による自動 Embedding パイプライン

### Firestore Trigger でドキュメント追加時に自動生成

本番環境で最も重要なのは、ドキュメントが追加・更新されるたびに Embedding を自動生成する仕組みです。Cloud Functions の Firestore Trigger を使えば、完全に自動化できます。

```typescript
// functions/src/embedding-pipeline.ts
import { onDocumentCreated, onDocumentUpdated } from "firebase-functions/v2/firestore";
import { getFirestore, FieldValue } from "firebase-admin/firestore";
import { GoogleGenerativeAI } from "@google/generative-ai";
import { defineSecret } from "firebase-functions/params";

const geminiApiKey = defineSecret("GEMINI_API_KEY");
const db = getFirestore();

/**
 * ドキュメント作成時に Embedding を自動生成
 */
export const onDocumentCreate = onDocumentCreated(
  {
    document: "documents/{docId}",
    secrets: [geminiApiKey],
    // リトライを有効化（Embedding API の一時的なエラーに対応）
    retry: true,
    // メモリとタイムアウトの設定
    memory: "512MiB",
    timeoutSeconds: 120,
  },
  async (event) => {
    const data = event.data?.data();
    if (\!data || data.embedding) return; // すでに Embedding がある場合はスキップ

    const genAI = new GoogleGenerativeAI(geminiApiKey.value());
    const model = genAI.getGenerativeModel({ model: "text-embedding-004" });

    const textForEmbedding = `${data.title}\n\n${data.content}`;
    const truncated = textForEmbedding.slice(0, 1300); // 安全マージン

    try {
      const result = await model.embedContent({
        content: { parts: [{ text: truncated }], role: "user" },
        taskType: "RETRIEVAL_DOCUMENT",
      });

      // Embedding をドキュメントに書き戻す
      await event.data?.ref.update({
        embedding: FieldValue.vector(result.embedding.values),
        embeddingModel: "text-embedding-004",
        embeddingGeneratedAt: FieldValue.serverTimestamp(),
      });

      console.log(`Embedding generated for document: ${event.params.docId}`);
    } catch (error) {
      console.error(`Embedding generation failed: ${error}`);
      // リトライ可能なエラーの場合は例外を再スロー
      if (isRetryableError(error)) {
        throw error; // Cloud Functions が自動リトライ
      }
      // 永続的なエラーの場合はエラーフラグを設定
      await event.data?.ref.update({
        embeddingError: String(error),
        embeddingErrorAt: FieldValue.serverTimestamp(),
      });
    }
  }
);

/**
 * ドキュメント更新時に Embedding を再生成
 * （title または content が変更された場合のみ）
 */
export const onDocumentUpdate = onDocumentUpdated(
  {
    document: "documents/{docId}",
    secrets: [geminiApiKey],
    retry: true,
    memory: "512MiB",
    timeoutSeconds: 120,
  },
  async (event) => {
    const before = event.data?.before.data();
    const after = event.data?.after.data();
    if (\!before || \!after) return;

    // title と content が変更されていない場合はスキップ
    if (before.title === after.title && before.content === after.content) {
      return;
    }

    const genAI = new GoogleGenerativeAI(geminiApiKey.value());
    const model = genAI.getGenerativeModel({ model: "text-embedding-004" });

    const textForEmbedding = `${after.title}\n\n${after.content}`;
    const truncated = textForEmbedding.slice(0, 1300);

    const result = await model.embedContent({
      content: { parts: [{ text: truncated }], role: "user" },
      taskType: "RETRIEVAL_DOCUMENT",
    });

    await event.data?.after.ref.update({
      embedding: FieldValue.vector(result.embedding.values),
      embeddingModel: "text-embedding-004",
      embeddingGeneratedAt: FieldValue.serverTimestamp(),
      embeddingError: FieldValue.delete(), // エラーフラグをクリア
    });
  }
);

function isRetryableError(error: unknown): boolean {
  const message = String(error);
  return (
    message.includes("429") || // レート制限
    message.includes("503") || // サービス一時停止
    message.includes("ECONNRESET") ||
    message.includes("ETIMEDOUT")
  );
}
```

### バッチ Embedding 生成スクリプト

既存のドキュメントに一括で Embedding を付与するバッチ処理も本番運用では必須です。

```typescript
// scripts/batch-embed.ts
import { initializeApp, cert } from "firebase-admin/app";
import { getFirestore, FieldValue } from "firebase-admin/firestore";
import { GoogleGenerativeAI } from "@google/generative-ai";

// Firebase Admin 初期化
initializeApp({ credential: cert("./service-account.json") });
const db = getFirestore();

const genAI = new GoogleGenerativeAI(process.env.GEMINI_API_KEY\!);
const model = genAI.getGenerativeModel({ model: "text-embedding-004" });

async function batchEmbedDocuments(
  collectionName: string,
  batchSize: number = 20, // Firestore の書き込みバッチ上限は500だが、API制限を考慮
  delayMs: number = 1000  // レート制限対策
) {
  // Embedding が未生成のドキュメントを取得
  const snapshot = await db
    .collection(collectionName)
    .where("embedding", "==", null)
    .limit(batchSize)
    .get();

  if (snapshot.empty) {
    console.log("✅ All documents have embeddings");
    return;
  }

  console.log(`Processing ${snapshot.size} documents...`);
  let processed = 0;
  let errors = 0;

  // バッチ処理
  const texts = snapshot.docs.map((doc) => {
    const data = doc.data();
    return `${data.title}\n\n${data.content}`.slice(0, 1300);
  });

  // Gemini のバッチ Embedding API を使用
  const batchResult = await model.batchEmbedContents({
    requests: texts.map((text) => ({
      content: { parts: [{ text }], role: "user" },
      taskType: "RETRIEVAL_DOCUMENT" as const,
    })),
  });

  // Firestore バッチ書き込み
  const writeBatch = db.batch();
  snapshot.docs.forEach((doc, index) => {
    writeBatch.update(doc.ref, {
      embedding: FieldValue.vector(batchResult.embeddings[index].values),
      embeddingModel: "text-embedding-004",
      embeddingGeneratedAt: FieldValue.serverTimestamp(),
    });
    processed++;
  });

  await writeBatch.commit();
  console.log(`✅ Processed: ${processed}, Errors: ${errors}`);

  // レート制限対策で待機
  await new Promise((resolve) => setTimeout(resolve, delayMs));

  // 再帰的に次のバッチを処理
  await batchEmbedDocuments(collectionName, batchSize, delayMs);
}

// 実行
batchEmbedDocuments("documents")
  .then(() => console.log("🎉 Batch embedding complete"))
  .catch(console.error);
```

## RAG パイプラインの構築

### コンテキスト付き回答生成

検索結果を Gemini Pro に渡して、コンテキストに基づいた回答を生成する本番パイプラインです。

```typescript
// lib/rag-pipeline.ts
import { GoogleGenerativeAI } from "@google/generative-ai";
import { semanticSearchWithThreshold, SearchResult } from "./search";

const genAI = new GoogleGenerativeAI(process.env.GEMINI_API_KEY\!);

interface RAGResponse {
  answer: string;
  sources: Array<{ id: string; title: string; score: number }>;
  tokensUsed: number;
}

/**
 * RAG パイプライン: 検索 → コンテキスト構築 → 回答生成
 */
export async function ragQuery(
  userQuery: string,
  collectionName: string,
  options: {
    maxContextDocs?: number;
    maxContextTokens?: number;
    category?: string;
    systemPrompt?: string;
  } = {}
): Promise<RAGResponse> {
  const {
    maxContextDocs = 5,
    maxContextTokens = 8000,
    category,
    systemPrompt = "あなたは正確で親切なアシスタントです。提供されたコンテキスト情報のみに基づいて回答してください。コンテキストに含まれない情報については「その情報は見つかりませんでした」と正直に答えてください。",
  } = options;

  // Step 1: セマンティック検索で関連ドキュメントを取得
  const searchResults = await semanticSearchWithThreshold(
    userQuery,
    collectionName,
    { limit: maxContextDocs, category, minScore: 0.65 }
  );

  if (searchResults.length === 0) {
    return {
      answer: "申し訳ありません。ご質問に関連する情報が見つかりませんでした。",
      sources: [],
      tokensUsed: 0,
    };
  }

  // Step 2: コンテキストを構築（トークン上限を考慮）
  const context = buildContext(searchResults, maxContextTokens);

  // Step 3: Gemini Pro で回答生成
  const model = genAI.getGenerativeModel({
    model: "gemini-2.5-pro-preview-05-06",
    systemInstruction: systemPrompt,
  });

  const prompt = `## コンテキスト情報

${context}

## ユーザーの質問

${userQuery}

上記のコンテキスト情報に基づいて、ユーザーの質問に正確に回答してください。回答の根拠となったドキュメントのタイトルを引用してください。`;

  const result = await model.generateContent(prompt);
  const response = result.response;

  return {
    answer: response.text(),
    sources: searchResults.map((r) => ({
      id: r.id,
      title: r.title,
      score: r.score,
    })),
    tokensUsed: response.usageMetadata?.totalTokenCount || 0,
  };
}

/**
 * 検索結果からコンテキスト文字列を構築する
 * トークン上限を超えないように切り詰める
 */
function buildContext(
  results: SearchResult[],
  maxTokens: number
): string {
  let context = "";
  let estimatedTokens = 0;

  for (const result of results) {
    const docText = `### ${result.title}\n${result.content}\n\n`;
    // 日本語: 1文字 ≈ 1.5トークン、英語: 1単語 ≈ 1.3トークン
    const docTokens = Math.ceil(docText.length * 1.5);

    if (estimatedTokens + docTokens > maxTokens) {
      // 残りのトークン数分だけテキストを追加
      const remainingChars = Math.floor(
        (maxTokens - estimatedTokens) / 1.5
      );
      if (remainingChars > 100) {
        context += `### ${result.title}\n${result.content.slice(0, remainingChars)}...\n\n`;
      }
      break;
    }

    context += docText;
    estimatedTokens += docTokens;
  }

  return context;
}
```

## コスト最適化とパフォーマンスチューニング

### コスト構造の理解

このシステムの主なコスト要素は3つです。

**Firestore のストレージコスト:**
768次元ベクトル = 768 × 4バイト（float32） = 3,072バイト/ドキュメント。10万ドキュメントで約292MBのベクトルデータ。Firestore のストレージ料金は $0.18/GB/月なので、ベクトル部分だけなら月額約 $0.05 です。

**Gemini Embeddings API コスト:**
text-embedding-004 は無料枠（1,500 RPM / 1日あたり最大リクエスト数）が比較的大きいため、中規模サイトなら無料枠内で運用できます。超過分は $0.00001/1,000文字と非常に安価です。

**Gemini Pro の回答生成コスト:**
RAG クエリ1回あたり、入力トークン（コンテキスト + クエリ）と出力トークンの合計で課金されます。Gemini 2.5 Pro の場合、入力 $1.25/100万トークン、出力 $10/100万トークンです。

### コスト削減テクニック

```typescript
// lib/cost-optimization.ts

/**
 * Embedding キャッシュ（同一テキストの再生成を防止）
 * Firestore のサブコレクションにキャッシュを格納
 */
export async function getOrCreateEmbedding(
  text: string,
  taskType: "RETRIEVAL_DOCUMENT" | "RETRIEVAL_QUERY"
): Promise<number[]> {
  const cacheKey = createHash("sha256")
    .update(`${taskType}:${text}`)
    .digest("hex");

  // キャッシュを確認
  const cacheRef = db.collection("embedding_cache").doc(cacheKey);
  const cached = await cacheRef.get();

  if (cached.exists) {
    return cached.data()\!.vector;
  }

  // キャッシュミス: 新規生成
  const vector = await generateEmbedding(text, taskType);

  // キャッシュに保存（TTL: 30日）
  await cacheRef.set({
    vector,
    text: text.slice(0, 100), // デバッグ用の先頭100文字
    taskType,
    createdAt: FieldValue.serverTimestamp(),
    expiresAt: new Date(Date.now() + 30 * 24 * 60 * 60 * 1000),
  });

  return vector;
}

/**
 * 次元削減による コスト最適化
 * 768次元 → 256次元に PCA で圧縮
 * ストレージコストを約66%削減
 */
export function reduceDimensions(
  vector: number[],
  targetDim: number = 256
): number[] {
  // text-embedding-004 は outputDimensionality パラメータで
  // サーバー側で次元削減が可能（推奨）
  // クライアント側で切り詰める場合は先頭N次元を使用
  // （Matryoshka Representation Learning 対応モデルの場合有効）
  return vector.slice(0, targetDim);
}
```

## 本番運用のベストプラクティス

### セキュリティ

Firestore Security Rules でベクトルフィールドへの直接アクセスを制限してください。Embedding は内部処理用であり、クライアントに公開する必要はありません。

```javascript
// firestore.rules
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /documents/{docId} {
      // 読み取り: 認証済みユーザーのみ
      allow read: if request.auth \!= null;
      // 書き込み: embedding フィールドはクライアントから書き込み不可
      allow create: if request.auth \!= null
        && \!("embedding" in request.resource.data);
      allow update: if request.auth \!= null
        && \!("embedding" in request.resource.data);
    }
    // Embedding キャッシュはサーバーのみ
    match /embedding_cache/{cacheId} {
      allow read, write: if false;
    }
  }
}
```

### エラーハンドリングとフォールバック

```typescript
/**
 * フォールバック付き RAG クエリ
 * ベクトル検索が失敗した場合、テキスト検索にフォールバック
 */
export async function ragQueryWithFallback(
  query: string,
  collectionName: string
): Promise<RAGResponse> {
  try {
    // 1. ベクトル検索を試行
    return await ragQuery(query, collectionName);
  } catch (vectorError) {
    console.warn("Vector search failed, falling back to text search:", vectorError);

    try {
      // 2. テキストベースのフォールバック検索
      const snapshot = await db
        .collection(collectionName)
        .orderBy("createdAt", "desc")
        .limit(5)
        .get();

      // キーワードマッチングで簡易フィルタリング
      const keywords = query.toLowerCase().split(/\s+/);
      const matched = snapshot.docs.filter((doc) => {
        const data = doc.data();
        const text = `${data.title} ${data.content}`.toLowerCase();
        return keywords.some((kw) => text.includes(kw));
      });

      if (matched.length === 0) {
        return {
          answer: "申し訳ありません。現在検索機能に問題が発生しています。しばらく経ってからお試しください。",
          sources: [],
          tokensUsed: 0,
        };
      }

      // フォールバック結果で回答生成
      const context = matched
        .map((doc) => `### ${doc.data().title}\n${doc.data().content}`)
        .join("\n\n");

      const model = genAI.getGenerativeModel({
        model: "gemini-2.5-flash-preview-04-17",
      });
      const result = await model.generateContent(
        `以下の情報に基づいて質問に回答してください。\n\n${context}\n\n質問: ${query}`
      );

      return {
        answer: result.response.text(),
        sources: matched.map((doc) => ({
          id: doc.id,
          title: doc.data().title,
          score: 0,
        })),
        tokensUsed: result.response.usageMetadata?.totalTokenCount || 0,
      };
    } catch (fallbackError) {
      console.error("Fallback search also failed:", fallbackError);
      throw fallbackError;
    }
  }
}
```

### スケーリング指針

本番環境でのスケーリングを考える際の指針です。

**ドキュメント数 1万件未満:** Firestore の flat インデックスで十分。レイテンシは50〜100ms。

**ドキュメント数 1万〜100万件:** 複合インデックスの最適化、次元削減（768→256）、Embedding キャッシュの導入を検討。レイテンシ目標は200ms以下。

**ドキュメント数 100万件超:** Firestore 単体では限界に近づく可能性があります。この規模では Vertex AI Vector Search への移行、またはハイブリッド構成（Firestore メタデータ + 専用ベクトル DB）を検討してください。

## まとめ

Firestore Vector Search と Gemini Embeddings の組み合わせは、Firebase をすでに使っているプロジェクトにとって、最もシンプルかつ低コストな RAG 構築手段です。専用ベクトル DB を別途運用する必要がなく、Cloud Functions のトリガーで Embedding の生成・更新を完全に自動化できます。

本記事で紹介した設計パターン — Embedding パイプラインの自動化、スコアしきい値によるフィルタリング、コスト最適化、フォールバック戦略 — を組み合わせることで、中規模プロジェクトであれば十分に本番品質の RAG システムを構築できます。
