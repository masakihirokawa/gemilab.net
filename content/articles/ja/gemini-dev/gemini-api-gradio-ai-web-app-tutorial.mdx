## 取り組みの背景 — Gradio で AI アプリを「最速」で公開する

AI モデルの性能がいくら高くても、ユーザーが触れる UI がなければ価値は伝わりません。Gemini API を使った AI 機能を素早くデモ可能な Web アプリに仕上げたいとき、Python の UI フレームワーク **Gradio** は最有力の選択肢です。

Gradio を使えば、フロントエンド開発の経験がなくても、数十行の Python コードで以下のような AI アプリを構築できます。

- テキスト生成・要約アプリ
- 画像アップロード → AI 分析アプリ
- リアルタイムチャットボット
- ファイルアップロード → ドキュメント解析アプリ

Gemini API と Gradio を組み合わせた **3 つの実践的なアプリ** をステップバイステップで構築し、Hugging Face Spaces への公開までを順を追って整理していきます。Gemini API の基本的な使い方については [Gemini API クイックスタートガイド](/articles/gemini-api/gemini-api-quickstart) も併せてご覧ください。

## 環境準備 — Python と必要なライブラリのインストール

まずは開発環境をセットアップします。Python 3.10 以上が必要です。

```bash
# 仮想環境の作成（推奨）
python -m venv gemini-gradio-env
source gemini-gradio-env/bin/activate  # Windows: gemini-gradio-env\Scripts\activate

# 必要なライブラリのインストール
pip install google-genai gradio pillow
```

次に、Gemini API キーを取得します。[Google AI Studio](https://aistudio.google.com/) にアクセスし、左メニューの「Get API key」から API キーを発行してください。

```bash
# 環境変数に API キーを設定
export GEMINI_API_KEY="YOUR_API_KEY"
```

API キーの取得方法について詳しく知りたい場合は、[Google AI Studio の使い方ガイド](/articles/gemini-dev/google-ai-studio-guide) を参照してください。

## アプリ 1 — テキスト生成・要約アプリ

最初に、ユーザーが入力したテキストを Gemini が要約するシンプルなアプリを作ります。

```python
import os
import gradio as gr
from google import genai

# Gemini クライアントの初期化
client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])

def summarize_text(text: str, style: str) -> str:
    """テキストを指定されたスタイルで要約する"""
    prompt = f"""以下のテキストを{style}で要約してください。
要点を箇条書きで3〜5個にまとめ、最後に一文で結論を述べてください。

テキスト:
{text}
"""
    response = client.models.generate_content(
        model="gemini-2.5-flash",
        contents=prompt,
    )
    return response.text

# Gradio UI の定義
demo = gr.Interface(
    fn=summarize_text,
    inputs=[
        gr.Textbox(
            label="要約したいテキスト",
            placeholder="ここにテキストを貼り付けてください...",
            lines=10,
        ),
        gr.Radio(
            choices=["ビジネス向け", "カジュアル", "技術者向け"],
            label="要約スタイル",
            value="ビジネス向け",
        ),
    ],
    outputs=gr.Markdown(label="要約結果"),
    title="Gemini テキスト要約アプリ",
    description="Gemini API を使ってテキストを素早く要約します。",
)

# 期待される出力:
# ブラウザに要約アプリのUIが表示され、テキスト入力と
# スタイル選択で即座にGeminiが要約を生成する

demo.launch()
```

このコードを `app_summary.py` として保存し、`python app_summary.py` で実行すると、ブラウザに要約アプリが表示されます。`gr.Interface` の引数を変更するだけで、入力フォームや出力形式を自由にカスタマイズできます。

## アプリ 2 — 画像分析チャットアプリ

次に、Gemini のマルチモーダル機能を活かして、画像をアップロードすると AI が分析結果を返すアプリを作ります。

```python
import os
import gradio as gr
from google import genai
from PIL import Image

client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])

def analyze_image(image: Image.Image, question: str) -> str:
    """アップロードされた画像を分析し、質問に回答する"""
    if image is None:
        return "画像をアップロードしてください。"

    prompt = question if question else "この画像の内容を詳しく説明してください。"

    response = client.models.generate_content(
        model="gemini-2.5-flash",
        contents=[prompt, image],
    )
    return response.text

demo = gr.Interface(
    fn=analyze_image,
    inputs=[
        gr.Image(type="pil", label="分析する画像"),
        gr.Textbox(
            label="質問（任意）",
            placeholder="例: この画像に写っている食べ物のカロリーは？",
        ),
    ],
    outputs=gr.Markdown(label="分析結果"),
    title="Gemini 画像分析アプリ",
    description="画像をアップロードすると、Gemini が内容を分析します。",
    examples=[
        ["https://upload.wikimedia.org/wikipedia/commons/thumb/a/a7/Camponotus_flavomarginatus_ant.jpg/320px-Camponotus_flavomarginatus_ant.jpg", "この画像に写っている生物は何ですか？"],
    ],
)

# 期待される出力:
# 画像アップロードエリアとテキスト入力欄が表示され、
# 画像を送信するとGeminiがマルチモーダル分析結果を返す

demo.launch()
```

Gemini 2.5 Flash は画像・テキストの同時処理に対応しており、`contents` にリストとして渡すだけでマルチモーダル推論が実行されます。さらに高度なマルチモーダル活用テクニックを学びたい方は、[Gemini API マルチモーダル実践テクニック集](/articles/gemini-api/gemini-api-multimodal-techniques) で詳しく解説しています。

## アプリ 3 — リアルタイムチャットボット

Gradio の `gr.ChatInterface` を使うと、チャットボット UI を簡単に構築できます。ストリーミング応答にも対応させてみましょう。

```python
import os
import gradio as gr
from google import genai

client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])

def chat_with_gemini(message: str, history: list) -> str:
    """Gemini とのチャット（履歴付き）"""
    # チャット履歴を Gemini API 形式に変換
    contents = []
    for user_msg, bot_msg in history:
        contents.append({"role": "user", "parts": [{"text": user_msg}]})
        contents.append({"role": "model", "parts": [{"text": bot_msg}]})
    contents.append({"role": "user", "parts": [{"text": message}]})

    response = client.models.generate_content(
        model="gemini-2.5-flash",
        contents=contents,
        config={
            "system_instruction": "あなたは親切で知識豊富なAIアシスタントです。日本語で丁寧に回答してください。",
        },
    )
    return response.text

demo = gr.ChatInterface(
    fn=chat_with_gemini,
    title="Gemini チャットボット",
    description="Gemini API を使ったリアルタイムチャットボットです。",
    examples=["Pythonの効率的な学習方法を教えてください", "今日の天気に合う料理のレシピを3つ提案して"],
    theme="soft",
)

# 期待される出力:
# チャットUIが表示され、メッセージを送信するたびに
# Geminiが会話履歴を考慮した応答を返す

demo.launch()
```

`gr.ChatInterface` は会話履歴の管理を自動で行ってくれるため、`history` パラメータに過去のやり取りがリスト形式で渡されます。これを Gemini API の `contents` 形式に変換するだけでマルチターン会話が実現できます。

## UI をカスタマイズする — Gradio Blocks API

より自由度の高い UI が必要な場合は、`gr.Blocks` を使ってレイアウトをカスタマイズできます。以下は、テキスト要約と画像分析を **タブで切り替えられる統合アプリ** の例です。

```python
import os
import gradio as gr
from google import genai
from PIL import Image

client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])

def summarize(text: str) -> str:
    response = client.models.generate_content(
        model="gemini-2.5-flash",
        contents=f"以下のテキストを要約してください:\n{text}",
    )
    return response.text

def analyze(image: Image.Image) -> str:
    if image is None:
        return "画像を選択してください。"
    response = client.models.generate_content(
        model="gemini-2.5-flash",
        contents=["この画像を詳しく分析してください。", image],
    )
    return response.text

with gr.Blocks(title="Gemini AI ツールキット", theme=gr.themes.Soft()) as demo:
    gr.Markdown("# Gemini AI ツールキット")
    gr.Markdown("Gemini API を活用した AI ツール集です。")

    with gr.Tabs():
        with gr.TabItem("テキスト要約"):
            text_input = gr.Textbox(label="テキスト", lines=8)
            text_btn = gr.Button("要約する", variant="primary")
            text_output = gr.Markdown(label="結果")
            text_btn.click(fn=summarize, inputs=text_input, outputs=text_output)

        with gr.TabItem("画像分析"):
            img_input = gr.Image(type="pil", label="画像")
            img_btn = gr.Button("分析する", variant="primary")
            img_output = gr.Markdown(label="結果")
            img_btn.click(fn=analyze, inputs=img_input, outputs=img_output)

# 期待される出力:
# タブ切り替え式のUIが表示され、
# 「テキスト要約」タブと「画像分析」タブを切り替えて使える

demo.launch()
```

`gr.Blocks` を使うと、行・列レイアウト（`gr.Row`, `gr.Column`）やアコーディオン（`gr.Accordion`）なども自在に組み合わせられるため、複雑な UI も Python だけで構築できます。

## Streamlit との比較 — どちらを選ぶべきか

Gradio と並んで人気の高い Python UI フレームワークに **Streamlit** があります。それぞれの特徴を整理します。

- **Gradio**: ML デモに特化した設計。`gr.Interface` で入出力を定義するだけで UI が完成します。Hugging Face との統合が強く、モデルのデモ公開に最適
- **Streamlit**: 汎用的なデータアプリ向け。ダッシュボードやデータ可視化に強い。独自のデプロイ基盤（Streamlit Cloud）を持つ

選択の目安として、**AI モデルのデモ・プロトタイプなら Gradio**、**データダッシュボードや複雑な業務アプリなら Streamlit** がおすすめです。Streamlit で AI アプリを作る方法については [Gemini API × Streamlit で AI Web アプリを効率的にプロトタイピング](/articles/gemini-dev/gemini-api-streamlit-ai-web-app-rapid-prototyping) で解説しています。

ここではDjangoプロジェクトのセットアップからチャット機能の実装、さらにストリーミングレスポンスの配信まで、段階的に解説していきます。Djangoの基本的な知識がある方を対象としていますが、AI連携が初めてでも理解できるよう丁寧に進めます。

## 基本実装 — Django ビューから Gemini API を呼び出す

Gemini APIとの連携ロジックをサービス層として分離することで、ビューをシンプルに保ちます。

```python
# ai_chat/services.py
from google import genai
from django.conf import settings

# クライアントをモジュールレベルで初期化（リクエストごとの再生成を防ぐ）
client = genai.Client(api_key=settings.GEMINI_API_KEY)

def generate_response(prompt: str, model: str = "gemini-2.5-flash") -> str:
    """Gemini APIにプロンプトを送信し、テキストレスポンスを返す"""
    response = client.models.generate_content(
        model=model,
        contents=prompt,
    )
    return response.text
```

このサービスをビューから呼び出します。

```python
# ai_chat/views.py
import json
from django.http import JsonResponse
from django.views.decorators.csrf import csrf_exempt
from django.views.decorators.http import require_http_methods
from .services import generate_response

@csrf_exempt
@require_http_methods(["POST"])
def chat_api(request):
    """AIチャットのAPIエンドポイント"""
    try:
        body = json.loads(request.body)
        user_message = body.get("message", "")

        if not user_message:
            return JsonResponse({"error": "メッセージが空です"}, status=400)

        # Gemini APIを呼び出し
        ai_response = generate_response(user_message)

        return JsonResponse({
            "response": ai_response,
            "model": "gemini-2.5-flash",
        })

    except Exception as e:
        return JsonResponse({"error": str(e)}, status=500)
```

URL設定も忘れずに行います。

```python
# ai_chat/urls.py
from django.urls import path

    path('api/chat/', views.chat_api, name='chat_api'),
]

# mysite/urls.py
from django.urls import path, include

]
```

これで `POST /api/chat/` にメッセージを送ると、Gemini APIからの応答が返ってくる基本的なエンドポイントが完成しました。

## マルチターン会話の実装 — セッションで会話履歴を管理する

実用的なチャットアプリでは、会話の文脈を維持する必要があります。Djangoのセッション機能を使って会話履歴を管理する方法を紹介します。

```python
# ai_chat/services.py（拡張版）
from google import genai
from google.genai import types
from django.conf import settings

client = genai.Client(api_key=settings.GEMINI_API_KEY)

def generate_chat_response(
    message: str,
    history: list[dict],
    model: str = "gemini-2.5-flash"
) -> str:
    """会話履歴を含めてGemini APIを呼び出す"""
    # 履歴をGemini API形式に変換
    contents = []
    for entry in history:
        contents.append(
            types.Content(
                role=entry["role"],
                parts=[types.Part(text=entry["text"])]
            )
        )
    # 今回のユーザーメッセージを追加
    contents.append(
        types.Content(
            role="user",
            parts=[types.Part(text=message)]
        )
    )

    response = client.models.generate_content(
        model=model,
        contents=contents,
    )
    return response.text
```

ビュー側でセッションに履歴を保存します。

```python
# ai_chat/views.py（拡張版）
import json
from django.http import JsonResponse
from django.views.decorators.csrf import csrf_exempt
from django.views.decorators.http import require_http_methods
from .services import generate_chat_response

@csrf_exempt
@require_http_methods(["POST"])
def chat_api(request):
    """マルチターン対応のチャットAPIエンドポイント"""
    try:
        body = json.loads(request.body)
        user_message = body.get("message", "")

        if not user_message:
            return JsonResponse({"error": "メッセージが空です"}, status=400)

        # セッションから会話履歴を取得
        history = request.session.get("chat_history", [])

        # Gemini APIを呼び出し
        ai_response = generate_chat_response(user_message, history)

        # 履歴を更新
        history.append({"role": "user", "text": user_message})
        history.append({"role": "model", "text": ai_response})

        # 履歴が長くなりすぎないよう直近20件に制限
        if len(history) > 20:
            history = history[-20:]

        request.session["chat_history"] = history

        return JsonResponse({
            "response": ai_response,
            "history_length": len(history),
        })

    except Exception as e:
        return JsonResponse({"error": str(e)}, status=500)

@csrf_exempt
@require_http_methods(["POST"])
def reset_chat(request):
    """会話履歴をリセットする"""
    request.session["chat_history"] = []
    return JsonResponse({"status": "reset"})
```

Djangoのセッションミドルウェアが自動的にCookieベースのセッション管理を行うため、ユーザーごとに独立した会話履歴を保持できます。本番環境ではRedisやデータベースバックエンドを使ったセッション管理を検討すると良いでしょう。

より高度なセッション管理パターンや、大規模チャットボットのアーキテクチャについては、[Gemini API の長期記憶とセッション永続化ガイド](/articles/gemini-advanced/gemini-api-long-memory-session-persistence-chatbot-architecture) で詳しく解説しています。

## ストリーミングレスポンスの実装 — リアルタイムにAI応答を配信する

ChatGPTのようにトークンが一つずつ表示される体験を実現するには、ストリーミングレスポンスが必要です。DjangoではStreamingHttpResponseを使って実装できます。

```python
# ai_chat/services.py（ストリーミング対応追加）
def generate_stream_response(
    message: str,
    history: list[dict],
    model: str = "gemini-2.5-flash"
):
    """ストリーミングでGemini APIを呼び出すジェネレータ"""
    contents = []
    for entry in history:
        contents.append(
            types.Content(
                role=entry["role"],
                parts=[types.Part(text=entry["text"])]
            )
        )
    contents.append(
        types.Content(
            role="user",
            parts=[types.Part(text=message)]
        )
    )

    response = client.models.generate_content_stream(
        model=model,
        contents=contents,
    )

    for chunk in response:
        if chunk.text:
            yield chunk.text
```

ビュー側でServer-Sent Events（SSE）として配信します。

```python
# ai_chat/views.py（ストリーミング対応追加）
import json
from django.http import StreamingHttpResponse
from .services import generate_stream_response

@csrf_exempt
@require_http_methods(["POST"])
def chat_stream_api(request):
    """SSEでストリーミングレスポンスを返すエンドポイント"""
    body = json.loads(request.body)
    user_message = body.get("message", "")
    history = request.session.get("chat_history", [])

    def event_stream():
        full_response = ""
        for chunk_text in generate_stream_response(user_message, history):
            full_response += chunk_text
            # SSE形式でチャンクを送信
            yield f"data: {json.dumps({'text': chunk_text})}\n\n"

        # ストリーム完了を通知
        yield f"data: {json.dumps({'done': True})}\n\n"

        # 会話履歴を更新（注意: ストリーミング中はセッション更新不可のため
        # 完了後にフロントエンドから別途リクエストで更新する設計が推奨）

    response = StreamingHttpResponse(
        event_stream(),
        content_type='text/event-stream'
    )
    response['Cache-Control'] = 'no-cache'
    response['X-Accel-Buffering'] = 'no'
    return response
```

フロントエンド側では、`EventSource` またはfetchのReadableStreamで受信します。

```javascript
// フロントエンドでのストリーミング受信例
async function sendMessage(message) {
  const response = await fetch('/api/chat/stream/', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ message }),
  });

  const reader = response.body.getReader();
  const decoder = new TextDecoder();

  while (true) {
    const { done, value } = await reader.read();
    if (done) break;

    const text = decoder.decode(value);
    const lines = text.split('\n');

    for (const line of lines) {
      if (line.startsWith('data: ')) {
        const data = JSON.parse(line.slice(6));
        if (data.done) break;
        // UIにテキストを追記
        appendToChat(data.text);
      }
    }
  }
}
```

## 本番環境への準備 — セキュリティとパフォーマンスの考慮事項

DjangoでGemini APIを利用するアプリを本番環境にデプロイする際には、いくつかの重要なポイントがあります。

**APIキーの保護**: 環境変数で管理するだけでなく、レート制限ミドルウェアを導入して不正利用を防止しましょう。Django REST Frameworkのthrottlingクラスを活用すると、IPアドレスやユーザー単位でのリクエスト制限を簡単に設定できます。

**非同期処理の活用**: Django 4.1以降では非同期ビューがサポートされています。Gemini APIの呼び出しはI/Oバウンドな処理であるため、非同期ビューを使うことでスループットを大幅に改善できます。

```python
# 非同期ビューの例
import asyncio
from django.http import JsonResponse
from asgiref.sync import sync_to_async

async def async_chat_api(request):
    """非同期版チャットAPIエンドポイント"""
    body = json.loads(request.body)
    user_message = body.get("message", "")

    # 同期関数を非同期で呼び出す
    ai_response = await sync_to_async(generate_response)(user_message)

    return JsonResponse({"response": ai_response})
```

**Celeryによるバックグラウンド処理**: 長時間かかるAIタスク（大量の文書解析、バッチ処理など）はCeleryキューに委任することで、ユーザー体験を損なわずに処理できます。

**エラーハンドリング**: API呼び出しが失敗した場合のリトライロジックとグレースフルデグレーデーションを実装しましょう。本番環境でのより包括的なエラーハンドリングパターンについては、[Gemini API エラーハンドリング＆レート制限 完全攻略](/articles/gemini-dev/gemini-api-error-handling-rate-limit-production-patterns) で体系的に解説しています。

## まとめ

Gemini API と Gradio の組み合わせは、AI アプリのプロトタイピングにおいて非常に強力です。本記事で紹介した 3 つのパターン（テキスト要約・画像分析・チャットボット）をベースに、さまざまな AI アプリを素早く構築・公開できます。

Gradio の `gr.Interface` でシンプルに始め、必要に応じて `gr.Blocks` で UI をカスタマイズし、Hugging Face Spaces で世界に公開します。この一連のフローを身につければ、アイデアを形にするまでの時間を大幅に短縮できます。
