Gemini Code Assist のエージェントモードを有効にしたのに、チャットに話しかけてもコードを自動で修正してくれない——そんな経験はありませんか。「エージェントモードってそういうものじゃないの？」と半信半疑のまま使い続けている方も多いのではないかと思います。

私もエージェントモードを試し始めたころ、期待通りに動かない状況が続いて原因がよくわかりませんでした。調べてみると、設定の見落としや認証の問題、あるいはエディタ拡張機能のバージョン不一致など、いくつかのパターンに集約されることが分かってきました。ここではよくある原因とその対処法を整理しておきます。

2014年からアプリ事業を続けている個人開発者の経験から、この問題に普段から向き合ってきた立場で、要点を整理します。

## エージェントモードとは何か、まず確認しよう

Gemini Code Assist のエージェントモードは、単純なコード補完やインラインサジェストとは異なり、複数ファイルにまたがる変更の計画・実行、コマンドの提案、テストの生成などを半自動で行える機能です。2025年後半から段階的に展開が始まり、2026年現在は Enterprise・Individual の両プランで利用可能になっています。

ただし、**有効化に必要な手順が通常の補完機能と異なります**。「拡張機能を入れたら使えるはず」と思っていると、エージェントとして動いていないことに気づかないまま時間を過ごすことになります。

まず確認してほしいのは、VS Code であればチャットパネルの入力欄に「agent」モードのトグルが表示されているかどうかです。表示されていない場合、以下のいずれかが原因として考えられます。

- 拡張機能のバージョンが古い（後述）
- ライセンスの有効化が完了していない
- 組織の管理者によってエージェントモードが無効化されている（Workspace 環境）

## 拡張機能のバージョンを確認する

エージェントモードは比較的新しい機能であるため、古いバージョンの拡張機能では利用できません。VS Code の場合、**拡張機能バージョン `2.x` 以降** が必要です。

確認方法：
1. VS Code の拡張機能ビュー（`Ctrl+Shift+X` / `Cmd+Shift+X`）を開く
2. 「Gemini Code Assist」で検索し、インストール済みの拡張機能のバージョンを確認する
3. 古い場合は「更新」ボタンをクリックしてアップデートする

```bash
# VS Code のコマンドラインからバージョン確認
code --list-extensions --show-versions | grep -i gemini
# 例: GoogleCloudTools.cloudcode@2.3.1
```

JetBrains（IntelliJ IDEA・PyCharm 等）の場合は、`Preferences > Plugins > Installed` から「Gemini Code Assist」プラグインを確認してください。バージョン `1.8` 以降がエージェントモードに対応しています。

## ライセンスと認証の問題を切り分ける

エージェントモードが表示されない・利用できないもう一つの原因がライセンス認証の問題です。

**Individual プランの場合**、Google アカウントでのサインインが必要です。VS Code 左下のステータスバーか、コマンドパレット（`Ctrl+Shift+P`）から「Gemini Code Assist: Sign In」を実行して、ブラウザ経由で認証してください。

```
// 認証確認のチェックリスト
✅ VS Code ステータスバーに「Gemini」アイコンが表示されている
✅ アイコンをクリックしてサインイン済みのアカウントが表示される
✅ 「Pro」または「Enterprise」ライセンスが適用されている
❌ 「Free」表示の場合、エージェントモードは利用不可
```

**Enterprise プランの場合**、組織の管理者が Gemini for Google Cloud の管理コンソールでエージェントモードを許可設定している必要があります。自分の環境での利用可否が分からない場合は、IT 管理者に確認するのが最短です。

## エージェントが途中で止まる・応答しない

認証と拡張機能の問題をクリアしてもエージェントが途中で止まる場合は、次のパターンを確認してください。

### コンテキストが大きすぎる

エージェントモードはリポジトリ全体を参照できますが、**一度に処理できるコンテキスト量には上限があります**。特に大きなプロジェクトで「プロジェクト全体を分析して」のような広い指示を出すと、途中でタイムアウトするか無応答になることがあります。

対処策：指示を具体的に絞り込む

```
# 悪い例（広すぎる指示）
「このプロジェクトのバグを全部見つけて修正して」

# 良い例（スコープを限定した指示）
「src/api/auth.ts の認証ロジックを見て、JWT トークンの検証に問題がないか確認して」
```

### ネットワークタイムアウト

企業のプロキシや VPN 環境では、エージェントモードの WebSocket 接続がタイムアウトすることがあります。VS Code の設定で `http.proxy` が正しく設定されているか確認しましょう。

```json
// settings.json
{
  "http.proxy": "http://your-proxy.example.com:8080",
  "http.proxyAuthorization": null,
  "http.proxyStrictSSL": false
}
```

### `@workspace` / `@file` 参照が機能しない

エージェントモードでは `@workspace` でプロジェクト全体、`@file` で特定ファイルを参照できますが、**ワークスペースのインデックスが作成されていない**と参照に失敗します。

VS Code の場合、ウィンドウをリロード（`Ctrl+Shift+P` → 「Developer: Reload Window」）するとインデックスが再構築されることが多いです。また、`.gitignore` に除外されているファイルはエージェントが参照できません。重要なファイルが除外されていないか確認してください。

## エラーメッセージ別の対処法

エージェントモード使用時に表示される主なエラーと対処法を整理します。

**`Failed to complete task: context limit exceeded`**
→ 指示のスコープが広すぎます。特定のファイルや機能に絞って依頼してください。

**`Agent mode is not available for your plan`**
→ 現在のライセンスがエージェントモードに対応していません。プランのアップグレードが必要です。

**`Unable to index workspace`**
→ ワークスペースのサイズが大きすぎるか、アクセス権限の問題です。VS Code の出力パネルで詳細ログを確認してください。

**`Connection to Gemini service failed`**
→ ネットワーク問題またはサービス障害です。[Google Cloud Status](https://status.cloud.google.com/) でサービス状態を確認してください。

## ログを見て原因を特定する

エラーメッセージだけでは原因が分からない場合、VS Code の出力ログが手がかりになります。

```
// ログの確認手順
1. メニュー「View > Output」を開く
2. ドロップダウンから「Gemini Code Assist」または「Gemini Code Assist - Agent」を選択
3. エラーが発生したタイミングのログを確認する
```

よく見かけるログパターンと意味：

```
[ERROR] Agent: Task execution failed after 3 retries
→ API 呼び出しが繰り返し失敗。認証かネットワークの問題

[WARN] Workspace indexing incomplete: 2847 files skipped
→ 大規模リポジトリでインデックスが部分的。.gitignore の見直しを

[INFO] Agent mode: Using gemini-2.5-pro-latest
→ 正常にモデルが選択されている（このメッセージが出ていれば接続は正常）
```

## まとめ

エージェントモードのトラブルは、大半が「拡張機能のバージョンが古い」「ライセンス認証の見落とし」「指示のスコープが広すぎる」の三点に集約されます。順番に確認していくと、多くの場合はどこかで引っかかっているポイントが見つかります。

それでも解決しない場合は、VS Code の出力ログをコピーして [GitHub Issues（google/gemini-code-assist）](https://github.com/google/gemini-code-assist/issues) に報告するのが、最も確実な次の一手です。ログには個人情報が含まれることがあるため、提出前に確認・マスキングしてください。
