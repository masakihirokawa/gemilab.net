## 動くデモと、配布できるアプリの間にある溝

バイブコーディングで組んだ最初のプロトタイプが数分で動いたとき、「これでアプリ作りは様変わりするな」と素直に感じました。私が個人開発を始めたのは2014年で、壁紙アプリや癒し系のアプリを中心に、累計5,000万ダウンロードほどを世に届けてきました。その実感から言えるのは、画面が動くところまでは本当に速くなった一方で、動くデモを「毎日数万人が触るアプリ」に育てる工程は、相変わらず地道だということです。Google AI Studio と Gemini 2.5 は、その地道な工程まで含めて手伝ってくれる相棒になりつつあります。今回は、私自身が実際に使っている進め方を、つまずきどころも交えてお話しします。

## バイブコーディングは「仕様書」ではなく「会話」で進む

従来の受託開発では、50〜100ページの仕様書を固めてから着手し、完成まで数週間かかるのが普通でした。バイブコーディングでは、5〜10行の自然な日本語で意図を伝え、数日で形にします。違いは速度だけではありません。仕様書を書く開発が「決めてから作る」のに対して、バイブコーディングは「作りながら決める」点が本質だと感じています。

私が手放せないと思っているのは、次の3つの性質です。

- スクリーンショットを渡すと、その画面に近い実装をそのまま起こしてくれるマルチモーダル性
- 会話履歴を保ったまま「ここの配色だけ変えて」と頼める文脈の維持
- 一つ直すたびに全体を作り直さず、差分で返してくれる反復の速さ

特に2つ目は、個人開発のように仕様が頭の中にしかない場面で効きます。仕様書がない代わりに、会話そのものが仕様の履歴になってくれるからです。

## Google AI Studio で最初の一歩を踏み出す

まずは [aistudio.google.com](https://aistudio.google.com) を開き、新しいチャットを作ります。最初にやるべきは、システムプロンプトで「どんな開発者として振る舞ってほしいか」を固定することです。ここを省くと、生成されるコードの粒度が毎回ぶれて、後の修正が増えます。私が壁紙アプリ系のツールを試作するときに使っているのは、次のようなプロンプトです。

```
あなたは10年以上の経験を持つフルスタック開発者です。
ユーザーの感覚的な指示を、実装可能な完全なコードへ翻訳してください。

守ってほしい原則:
- 動く最小構成を最初に出す（説明は後回し）
- コメントは日本語で、なぜそう書いたかを一言添える
- 例外処理とローディング状態を最初から含める
- 外部ライブラリは理由がある時だけ使う
```

最後の2行が地味に効きます。指定しないと、Gemini は「正常系だけ動く美しいコード」を返しがちで、エラー処理やローディング表示が抜け落ちてしまうからです。

## タスク管理アプリを例にした生成の流れ

具体例として、定番のタスク管理アプリを作ってみます。指示は次の数行で十分です。

```
やることリストのアプリを作ってください。
- タスクの追加・削除・完了の切り替え
- ブラウザを閉じても残るように保存
- 明るく親しみやすい配色
```

Gemini はこの指示から、HTML・CSS・JavaScript を一式そろえて返します。ここまでは数十秒です。次に、保存先をブラウザ内からサーバーへ移したくなったら、同じ会話の続きで「保存をサーバー側に移したい」と頼みます。すると、たとえば次のような FastAPI のひな形が返ってきます。

```python
from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware
from pydantic import BaseModel

app = FastAPI()
app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:5173"],  # 本番では自分のドメインに絞る
    allow_methods=["*"],
    allow_headers=["*"],
)

class Task(BaseModel):
    title: str
    done: bool = False

tasks: list[Task] = []

@app.get("/tasks")
def list_tasks():
    return {"tasks": tasks}

@app.post("/tasks")
def add_task(task: Task):
    tasks.append(task)
    return {"ok": True, "count": len(tasks)}
```

ここで一点だけ、生成されたまま公開してはいけない箇所があります。Gemini は CORS の許可オリジンをワイルドカード（すべて許可）で返すことが多いのですが、これは開発中だけにとどめ、本番では自分のドメインに絞ってください。便利さに任せて全許可のまま公開すると、思わぬところからアクセスを招いてしまいます。

## 最後の2割でつまずく場所と、その埋め方

バイブコーディングが本当に試されるのは、プロトタイプができてからです。私が繰り返しつまずいてきたのは、公式ドキュメントには出てこない次のような場所でした。

一つ目は、状態の保存です。生成直後のコードは、データをブラウザのローカルストレージに置くことが多いのですが、これは1台の端末でしか共有されません。複数端末で同じデータを見たいなら、最初の段階で「保存はサーバーのデータベースに」と明示しておくと、後の作り直しが減ります。

二つ目は、Gemini に渡すコンテキストの肥大化です。会話を続けるほど履歴が長くなり、ある時点から修正の精度が落ちます。私の体感では、画面1つあたりの会話が30往復を超えたあたりが境目で、そこからは「今のコード全文を貼り直して、ここだけ直して」と仕切り直したほうが速くなります。

実例を一つ挙げます。壁紙アプリで、画像を内容ごとに自動分類する機能を Gemini に任せたときのことです。最初は「風景・動物・抽象…と分類して」とだけ頼みました。返ってきた分類は一見それらしいのですが、実データで試すと「夕焼けの海」が風景にも抽象にも入る、といった揺れが多発しました。そこで指示を、次のように具体化しました。

- 分類は1枚につき必ず1カテゴリだけにする
- 判断に迷う場合は、最も面積を占める被写体を優先する
- カテゴリ名は事前に渡した12個の中からのみ選ぶ

この3点を足しただけで、手作業での振り分け直しが目に見えて減りました。バイブコーディングでは、抽象的な指示で8割まで一気に進み、残りの2割は「例外をどう扱うか」を言葉で詰めていく——この役割分担を意識すると、生成物が一気に実用へ近づきます。

## 私が毎月見ている運用の数字

アプリを公開した後は、生成して終わりではなく、数字を見ながら手を入れ続けます。私が Gemini を組み込んだ機能について、毎月必ず確認しているのは次の3つです。

- API 呼び出しの成功率と、失敗したときのエラー内訳
- 1リクエストあたりの平均トークン消費と、そこから逆算した1ユーザーあたりの月額コスト
- その機能を載せた画面の継続率が、載せる前と比べて動いたかどうか

3つ目が一番大事だと考えています。技術的にうまく動いても、ユーザーの行動が変わらなければ、その機能はコストだけがかかっている状態だからです。私の壁紙アプリでは、自動分類を入れてから目的の画像にたどり着くまでのタップ数が減り、それが滞在時間と AdMob の表示機会にもつながりました。Google Play のレビューでも「探しやすくなった」という声が増えたのが、何よりの手応えでした。

逆に、期待したほど効かなかった機能は、潔く外します。生成が速いということは、作り直すコストも低いということです。だからこそ、思いついた機能を一度載せてみて、数字で判断するという回し方が、個人開発でも現実的になりました。

## Google AI Studio が「フルスタック IDE」に生まれ変わった

2026年3月18日、Google は AI Studio に大規模なアップデートを実施し、テキストプロンプトから本番対応のアプリケーションを構築できる **フルスタックバイブコーディング環境** を発表しました。これまでの「プロンプトを試す場所」から、「プロンプトでアプリを作る場所」へと大きく進化したことになります。

Google 社内でも数十万のアプリがこのプラットフォーム上で構築されており、その実用性はすでに実証されています。新しく追加された機能の詳細と、実際にどのように使うのかを順を追って整理していきます。

## バイブコーディングとは

バイブコーディング（Vibe Coding）とは、厳密なコードを手書きする代わりに、自然言語の指示だけで AI にアプリケーションを生成させる開発手法です。「こういうアプリが欲しい」という雰囲気（バイブ）を伝えるだけで、AI がコード全体を書き上げてくれます。

従来のバイブコーディングツールはフロントエンドの生成に留まることが多かったのですが、Google AI Studio の新バージョンではバックエンド、データベース、認証まで含めたフルスタックの構築が可能になりましました。

## 新機能の全体像

### Antigravity エージェント

今回のアップデートの核となるのが **Antigravity** というコーディングエージェントです。Antigravity は2025年11月にスタンドアロンの VS Code ベース IDE としてリリースされていましたが、今回ブラウザベースの AI Studio に直接統合されましました。

Antigravity が従来のコード生成と異なるのは、**プロジェクト全体の構造を理解** した上でコードを書くという点です。複数のファイルを管理し、複雑な指示を解釈して、堅牢なフルスタックアプリケーションを構築します。

```python
# Antigravity が自動で処理する範囲の例
# 1. フロントエンド（React / Next.js）
# 2. バックエンド（API ルート）
# 3. データベース（Cloud Firestore）
# 4. 認証（Firebase Authentication）
# 5. 外部ライブラリのインストール

# ユーザーがやること：プロンプトを書くだけ
prompt = """
ToDoアプリを作ってください。
- Googleアカウントでログインできるようにする
- タスクをデータベースに保存する
- リアルタイムで同期される
- Framer Motion でアニメーションを付ける
"""

# Antigravity がこのプロンプトから
# フルスタックアプリを自動生成
```

### Firebase 統合

Antigravity はアプリの要件を自動検出し、必要に応じて Firebase の統合を提案します。

データベースが必要ですと判断すると **Cloud Firestore** を、ログイン機能が必要ですと判断すると **Firebase Authentication** を自動でプロビジョニングします。開発者が Firebase のセットアップを手動で行う必要はありません。

```javascript
// Antigravity が自動生成するコードの例
import { initializeApp } from "firebase/app";
import { getFirestore, collection, addDoc } from "firebase/firestore";
import { getAuth, signInWithPopup, GoogleAuthProvider } from "firebase/auth";

// Firebase の設定は Antigravity が自動で注入
const app = initializeApp(firebaseConfig);
const db = getFirestore(app);
const auth = getAuth(app);

// Google ログインの実装
const signIn = async () => {
  const provider = new GoogleAuthProvider();
  const result = await signInWithPopup(auth, provider);
  console.log("Logged in as:", result.user.displayName);
  // 期待する出力: "Logged in as: ユーザー名"
};

// Firestore へのデータ保存
const addTask = async (task) => {
  await addDoc(collection(db, "tasks"), {
    text: task,
    createdAt: new Date(),
    userId: auth.currentUser.uid,
  });
};
```

### マルチプレイヤー対応

リアルタイムのマルチプレイヤー体験を構築できるようになりましました。複数のユーザーが同時に接続するゲーム、共同作業ワークスペース、共有ツールなどを、プロンプトひとつで生成できます。

### Next.js サポート

これまで React と Angular のみがサポートされていましたが、新たに **Next.js** フレームワークが追加されましました。サーバーサイドレンダリング（SSR）、App Router、API Routes といった Next.js の機能をフル活用したアプリケーションを生成できます。

### シークレットマネージャー

外部サービスの API キーを安全に管理するための **Secrets Manager** が追加されましました。決済プロセッサ（Stripe など）、Google Maps、その他のサードパーティ API との連携時に、キーをコードにハードコードすることなく安全に使用できます。

### プロジェクトの永続化

ブラウザを閉じてもプロジェクトの状態が自動保存されるようになりましました。別のデバイスからアクセスしても、作業を中断したところから再開できます。

## 実際に使ってみる

Google AI Studio でバイブコーディングを始める手順は非常にシンプルです。

```bash
# ステップ 1: Google AI Studio にアクセス
# https://aistudio.google.com にブラウザでアクセス

# ステップ 2: 「Build」モードを選択
# 画面上部のナビゲーションから Build を選択

# ステップ 3: プロンプトを入力
# 作りたいアプリを自然言語で記述

# ステップ 4: 生成されたアプリをプレビュー
# リアルタイムでアプリが生成される

# ステップ 5: 必要に応じて修正指示を追加
# 「ボタンの色を青にして」「ダークモードを追加して」など
```

Antigravity はサードパーティライブラリ（Framer Motion、Shadcn など）を自動検出してインストールしてくれるため、依存関係の管理を手動で行う必要がありません。

## 従来のバイブコーディングツールとの比較

| 機能 | Google AI Studio | 他のツール |
|------|-----------------|-----------|
| フロントエンド生成 | React / Next.js / Angular | React 中心 |
| バックエンド | Firebase 自動統合 | 手動設定が必要 |
| データベース | Cloud Firestore 自動構築 | 外部サービス連携 |
| 認証 | Firebase Auth 自動統合 | 手動実装 |
| マルチプレイヤー | ネイティブ対応 | 非対応が多い |
| 外部ライブラリ | 自動検出＆インストール | 手動追加 |
| プロジェクト永続化 | 自動保存・デバイス間対応 | ツールによる |
| 料金 | 無料（Google アカウントのみ） | 有料プランが一般的 |
