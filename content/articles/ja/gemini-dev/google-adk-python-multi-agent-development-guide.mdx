## Google ADK とは — AI エージェント開発の新スタンダード

Google Agent Development Kit（ADK）は、Gemini API を活用した AI エージェントを効率的に構築するためのオープンソースフレームワークです。2026年に入り急速にエコシステムが拡大しており、とくに Python 向けの SDK は、データサイエンスや業務自動化の現場で高い注目を集めています。

ADK の最大の特長は、**複数のエージェントを組み合わせて一つのタスクを遂行する「マルチエージェントアーキテクチャ」** をシンプルに実装できる点です。たとえば、調査エージェント・分析エージェント・レポート作成エージェントを連携させて、情報収集から報告書生成までを自動化するといった構成が、わずか数十行のコードで実現できます。

この記事では、ADK の Python SDK を使ったマルチエージェントシステムの設計と実装を、実践的なコード例とともに解説します。

## 環境準備とインストール

まず、ADK の Python パッケージをインストールします。Python 3.10 以上が必要です。

```bash
# ADK のインストール
pip install google-adk

# 環境変数の設定
export GOOGLE_API_KEY="YOUR_API_KEY"
```

Google AI Studio でAPIキーを取得し、環境変数に設定してください。Gemini 3.1 Pro または Gemini 3.1 Flash のいずれかのモデルを使用できます。

プロジェクトの基本構成は以下の通りです。

```
my_agents/
├── __init__.py
├── agent.py          # エージェント定義
├── tools.py          # カスタムツール
└── .env              # 環境変数
```

## マルチエージェントの基本構造

ADK のマルチエージェントシステムは、**親エージェント（Orchestrator）** が **子エージェント（Sub-agents）** にタスクを委譲する階層構造をとります。

以下は、最もシンプルなマルチエージェント構成の例です。

```python
from google.adk.agents import Agent

# --- 子エージェント：調査担当 ---
research_agent = Agent(
    name="research_agent",
    model="gemini-3.1-pro",
    instruction="""
    あなたは調査担当エージェントです。
    ユーザーが指定したトピックについて、要点を整理して報告してください。
    箇条書きで5つ以上のポイントをまとめてください。
    """,
)

# --- 子エージェント：要約担当 ---
summary_agent = Agent(
    name="summary_agent",
    model="gemini-3.1-flash",
    instruction="""
    あなたは要約担当エージェントです。
    渡された情報を300文字以内の日本語で簡潔に要約してください。
    技術的な正確さを維持しつつ、わかりやすい表現を心がけてください。
    """,
)

# --- 親エージェント：オーケストレーター ---
orchestrator = Agent(
    name="orchestrator",
    model="gemini-3.1-pro",
    instruction="""
    あなたはチームリーダーです。
    ユーザーのリクエストに応じて、適切なエージェントにタスクを振り分けてください。
    - 情報の調査が必要な場合は research_agent に依頼
    - 情報の要約が必要な場合は summary_agent に依頼
    最終的な回答はあなたがまとめて返してください。
    """,
    sub_agents=[research_agent, summary_agent],
)
```

このように、`sub_agents` パラメータに子エージェントのリストを渡すだけで、親エージェントが状況に応じてタスクを委譲する仕組みが動作します。

## カスタムツールを持つエージェントの実装

実用的なエージェントには、外部APIとの連携やデータベースへのアクセスといった「ツール」が必要です。ADK では、Python の関数をそのままツールとして登録できます。

```python
from google.adk.agents import Agent
import json
from datetime import datetime

# --- ツール定義 ---
def get_current_weather(city: str) -> dict:
    """指定された都市の現在の天気を取得します。

    Args:
        city: 天気を取得する都市名（例: "Tokyo", "Osaka"）

    Returns:
        天気情報を含む辞書
    """
    # 実際のアプリではここで天気APIを呼び出す
    weather_data = {
        "city": city,
        "temperature": 18,
        "condition": "晴れ",
        "humidity": 45,
        "timestamp": datetime.now().isoformat(),
    }
    return weather_data


def search_database(query: str, limit: int = 5) -> list:
    """社内データベースを検索します。

    Args:
        query: 検索キーワード
        limit: 返す結果の最大数（デフォルト: 5）

    Returns:
        検索結果のリスト
    """
    # 実際のアプリではここでDB検索を実行
    return [
        {"id": 1, "title": f"{query}に関するレポート", "relevance": 0.95},
        {"id": 2, "title": f"{query}の分析結果", "relevance": 0.87},
    ]


# --- ツール付きエージェント ---
data_agent = Agent(
    name="data_agent",
    model="gemini-3.1-pro",
    instruction="""
    あなたはデータ収集エージェントです。
    利用可能なツールを使って情報を集め、ユーザーに報告してください。
    """,
    tools=[get_current_weather, search_database],
)
```

ポイントは、関数の **docstring（説明文）と型ヒント** をしっかり記述することです。ADK は docstring を解析して Gemini の Function Calling に渡すため、説明が不十分だとエージェントがツールを正しく呼び出せません。

## 実践例：調査→分析→レポート生成パイプライン

ここからは、より実践的なマルチエージェントパイプラインを構築してみましょう。3つの専門エージェントが順番に処理を行い、最終的なレポートを生成するシステムです。

```python
from google.adk.agents import Agent, SequentialAgent

# --- 1. 調査エージェント ---
researcher = Agent(
    name="researcher",
    model="gemini-3.1-pro",
    instruction="""
    あなたは技術調査の専門家です。
    指定されたトピックについて、以下の観点で調査結果をまとめてください:
    1. 現状の概要
    2. 主要な技術やツール
    3. メリットとデメリット
    4. 最新のトレンド
    結果はJSON形式で出力してください。
    """,
    output_key="research_result",
)

# --- 2. 分析エージェント ---
analyst = Agent(
    name="analyst",
    model="gemini-3.1-pro",
    instruction="""
    あなたはデータアナリストです。
    research_result を受け取り、以下の分析を行ってください:
    - 市場の成長性（高/中/低）
    - 導入の難易度（高/中/低）
    - 推奨度（1-10）
    - 具体的な活用シナリオを3つ
    結果をJSON形式で出力してください。
    """,
    output_key="analysis_result",
)

# --- 3. レポート生成エージェント ---
reporter = Agent(
    name="reporter",
    model="gemini-3.1-flash",
    instruction="""
    あなたはビジネスレポートライターです。
    research_result と analysis_result を基に、
    経営層向けの簡潔なレポート（800字程度）を日本語で作成してください。
    見出し・箇条書き・数値データを効果的に使ってください。
    """,
)

# --- シーケンシャル実行パイプライン ---
pipeline = SequentialAgent(
    name="report_pipeline",
    sub_agents=[researcher, analyst, reporter],
)
```

`SequentialAgent` を使うことで、エージェントが定義した順序で実行されます。各エージェントの `output_key` に格納された結果は、後続のエージェントが自動的に参照できます。

## エージェントの実行とセッション管理

作成したエージェントを実際に実行する方法を見てみましょう。

```python
from google.adk.runners import Runner
from google.adk.sessions import InMemorySessionService
from google.genai import types

# セッションサービスの初期化
session_service = InMemorySessionService()

# Runner の作成
runner = Runner(
    agent=pipeline,  # 上で定義したパイプライン
    app_name="tech_report_generator",
    session_service=session_service,
)

# セッションの作成
session = session_service.create_session(
    app_name="tech_report_generator",
    user_id="user-001",
)

# ユーザー入力
user_message = types.Content(
    role="user",
    parts=[types.Part(text="Gemini APIを活用したマルチエージェントシステムの現状と展望を調査してください")],
)

# 実行（ストリーミング）
async def run_pipeline():
    async for event in runner.run_async(
        user_id="user-001",
        session_id=session.id,
        new_message=user_message,
    ):
        if event.content and event.content.parts:
            # 各エージェントの出力を表示
            print(f"[{event.author}] {event.content.parts[0].text[:200]}")

# 期待する出力例:
# [researcher] {"overview": "マルチエージェントシステムは...", ...}
# [analyst] {"growth_potential": "高", "difficulty": "中", ...}
# [reporter] # マルチエージェントシステム調査レポート ...
```

`InMemorySessionService` はプロトタイピングに便利ですが、本番環境では永続化が必要です。ADK は `DatabaseSessionService` や `VertexAiSessionService` も提供しています。

## エラーハンドリングとリトライ戦略

マルチエージェントシステムでは、個々のエージェントが失敗する可能性を考慮した設計が重要です。

```python
from google.adk.agents import Agent
import logging

logger = logging.getLogger(__name__)

def safe_api_call(endpoint: str, params: str = "{}") -> dict:
    """外部APIを安全に呼び出します。

    Args:
        endpoint: APIエンドポイントURL
        params: JSONフォーマットのパラメータ文字列

    Returns:
        APIレスポンスまたはエラー情報
    """
    import json
    import urllib.request
    import urllib.error

    try:
        req = urllib.request.Request(
            endpoint,
            data=json.dumps(json.loads(params)).encode(),
            headers={"Content-Type": "application/json"},
        )
        with urllib.request.urlopen(req, timeout=10) as resp:
            return json.loads(resp.read())
    except urllib.error.HTTPError as e:
        logger.error(f"API error: {e.code} - {e.reason}")
        return {"error": f"APIエラー: {e.code}", "fallback": True}
    except Exception as e:
        logger.error(f"Unexpected error: {e}")
        return {"error": str(e), "fallback": True}


# フォールバック付きエージェント
resilient_agent = Agent(
    name="resilient_agent",
    model="gemini-3.1-pro",
    instruction="""
    あなたは外部データ取得を担当するエージェントです。
    ツールの結果に "error" キーが含まれている場合は、
    エラー内容を報告し、取得済みの情報だけで最善の回答をしてください。
    決してエラーを隠さず、透明性を保ってください。
    """,
    tools=[safe_api_call],
)
```

エージェントの instruction に「エラー時の振る舞い」を明記しておくことで、障害発生時でもシステム全体が停止せず、部分的な結果を返すグレースフルデグラデーションが実現できます。

## ADK と LangChain の使い分け

Python でエージェントを構築する際、ADK と LangChain のどちらを選ぶべきか迷う方も多いでしょう。それぞれの特長を整理します。

- **Google ADK**: Gemini モデルとの親和性が高く、Function Calling・Grounding・Code Execution といった Gemini 固有機能にネイティブ対応しています。Google Cloud（Vertex AI、Firebase Genkit）との統合もシームレスです
- **LangChain**: モデル非依存のアーキテクチャで、OpenAI・Anthropic・ローカルモデルを切り替えられます。コミュニティが大きく、プラグインやチュートリアルが豊富です

Gemini をメインモデルとして使い、Google Cloud にデプロイする場合は ADK を選ぶのが自然です。一方、マルチモデル対応やベンダーロックインの回避を優先するなら LangChain が適しています。両者の詳しい比較については、[Google ADK vs LangChain — AIエージェントフレームワーク比較ガイド](/articles/gemini-dev/google-adk-vs-langchain-ai-agent-framework-comparison) で掘り下げています。

## FAQ

### Q. ADK は無料で使えますか？

ADK 自体はオープンソース（Apache 2.0 ライセンス）なので無料です。ただし、Gemini API の呼び出しには Google AI Studio の無料枠（1分あたり15リクエスト）を超える分に料金が発生します。開発段階では無料枠で十分検証できます。

### Q. マルチエージェントシステムでコストを抑えるには？

調査やコード生成など高精度が求められるタスクには Gemini 3.1 Pro を、要約や整形など軽量なタスクには Gemini 3.1 Flash を割り当てるのが効果的です。上のコード例でも、reporter に Flash を使っています。

### Q. TypeScript 版の ADK との違いは？

機能面ではほぼ同等ですが、Python 版はデータサイエンス系ライブラリ（pandas、NumPy、scikit-learn）との組み合わせが容易な点が強みです。TypeScript 版は Web アプリケーションとの統合に適しています。TypeScript での本番構成については [Google ADK × Gemini — TypeScript本番マルチエージェントシステム構築](/articles/gemini-advanced/google-adk-gemini-typescript-production-agents) で詳しく解説しています。

### Q. Vertex AI 環境でも同じコードで動きますか？

はい、ADK は Google AI Studio と Vertex AI の両方に対応しています。`model` パラメータで Vertex AI のエンドポイントを指定するだけで、認証やリージョン設定以外のコードはそのまま動作します。
