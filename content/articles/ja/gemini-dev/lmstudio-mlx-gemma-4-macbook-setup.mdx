昨年の秋から冬にかけて、Gemini API を使いながらもローカル推論の選択肢がほしい、という悩みを抱えていました。GGUF 版のモデルはあるものの、MLX ランタイムが Gemma 4 に対応せず、M シリーズ Mac で最適なパフォーマンスを引き出せなかったからです。

先週、LMStudio が MLX ランタイムをアップデートし、Gemma 4（26B パラメータ・4bit 量子化版）が M5 Pro 32GB MacBook Pro で **41 tokens/秒** のスピードで動作することを確認しました。セットアップから初回推論まで、実際に手を動かした手順を実例とともに整理しました。

## 前提 — 必要なハードウェアとモデルの選定

M シリーズ Mac で Gemma 4 を動かすには、メモリに余裕が必要です。推奨は以下の通りです。

| MacBook モデル | メモリ | 動作状況 |
|---|---|---|
| M3 MacBook Air | 16GB | 可（余裕なし）|
| M4 MacBook Pro | 16GB | 可（推奨） |
| M5 Pro/Max | 32GB | 推奨（余裕あり） |

LMStudio で使う Gemma 4 モデルは、MLX コミュニティがプロビジョンしている `mlx-community/gemma-4-26b-a4b-it-4bit` です。このモデルは、Google 公式の Gemma 4 26B パラメータ版を 4bit 量子化したもので、ディスク容量は約 16GB、メモリ使用量は約 10〜12GB です。

より軽量な 2bit 版（`mlx-community/gemma-4-26b-a4b-it-2bit`）も存在しますが、精度が大きく落ちるため、16GB 以上のメモリがあれば 4bit 版をお勧めします。

## LMStudio のインストールと MLX ランタイム更新の確認

LMStudio は Mac App Store、または公式サイト（[lmstudio.ai](https://lmstudio.ai)）からダウンロードできます。インストール後、初回起動時に MLX ランタイムのバージョンを確認しましょう。

アプリを開いて、左側のナビゲーションメニューから **Settings（設定）** を選択します。その中の **About** セクションで、「MLX Runtime Version」が表示されます。2026年4月中旬以降のバージョンであれば、Gemma 4 対応です。

もし古いバージョンの場合は、App Store または公式サイトから最新版へのアップデートを行ってください。アップデート後は LMStudio を一度完全に終了し、再起動することで、新しい MLX ランタイムが有効になります。

## モデルのダウンロードと初回推論

MLX ランタイムの確認が済んだら、モデルをダウンロードします。

LMStudio のメイン画面で、上部の **Search models** 検索ボックスに `gemma-4-26b-a4b-it-4bit` と入力します。MLX コミュニティのモデルが表示されたら、右側の **Download** ボタンをクリックします。ダウンロードサイズは約 16GB のため、WiFi 接続で 10〜30 分程度かかります。

ダウンロード完了後、モデル名をクリックして起動します。初回起動時には、数秒のロード時間がありますが、その後はプロンプト画面が表示されます。

試しに以下のプロンプトを入力してみてください。

```
You are a helpful AI assistant. Explain in one paragraph why Apple Silicon Macs are efficient for running local LLMs.
```

実行ボタンを押すと、推論が開始します。筆者の M5 Pro 環境では、約 41 tokens/秒のスピードで出力されました。これは十分な速度で、API レイテンシを気にせずローカル推論を活用できる領域です。

Python SDK を使ってプログラムから呼び出すこともできます。

```python
import requests
import json

# LMStudio ローカルサーバーへのリクエスト（デフォルト: localhost:1234）
response = requests.post(
    "http://localhost:1234/v1/chat/completions",
    json={
        "model": "local-model",
        "messages": [
            {"role": "user", "content": "What is Gemma 4?"}
        ],
        "temperature": 0.7,
        "max_tokens": 256
    }
)

result = response.json()
print(result["choices"][0]["message"]["content"])
```

LMStudio を起動した状態で、このスクリプトを実行すれば、ローカル推論の結果が JSON で返されます。

## よくあるつまずきと対処法

### VRAM 不足のエラー

モデル起動時に「Out of memory」というエラーが出た場合は、メモリが不足しています。同時に開いているアプリを減らすか、より軽量な 2bit 版モデルへの切り替えを検討してください。ただし 2bit 版は精度が落ちるため、まずはメモリ管理の工夫をお勧めします。

### Reasoning 機能が使えない

MLX 版 Gemma 4 には、Google が Gemini 2.0 で導入した Reasoning（思考連鎖）機能が実装されていません。複雑な論理推論が必要なタスクでは、Gemini API と組み合わせる設計が必要です。詳しくは後編ガイドで解説します。

### モデル選択時の迷い

LMStudio には Google 公式提供の Gemma 4 モデルもリストされています。これらは GGUF 形式であり、MLX 版より速度が劣ります。明示的に「mlx-community」ブランドのモデルを選んでください。

## 次に試すべきこと

ローカル推論が動作確認できたら、以下の2つを検討してみてください。

1. **API コスト見直し**: 月間のプロンプト利用が多い場合、Gemini API 課金を削減できないか、試算してみます。

2. **オフライン利用シナリオ**: インターネット接続がない環境でも、ローカル推論なら即座に結果が得られます。開発中の試行錯誤や、ネットワーク不安定な環境での利用を想定しましょう。

より深い運用ノウハウ（量子化ビット選定、本番環境での監視、Reasoning 機能の補い方）については、後編の [Gemma 4 on MLX 本番運用チューニング](/articles/gemini-advanced/gemma-4-mlx-tuning-production-deployment) で詳しく解説しています。
