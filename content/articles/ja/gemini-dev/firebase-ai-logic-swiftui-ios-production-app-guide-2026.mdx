「Gemini を iOS アプリに組み込みたい」と思ったとき、最初の壁になるのは「どのSDKを使えばいいのか」という選択です。

直接 Gemini API を呼ぶ方法、Google AI SDK for Swift を使う方法、そして Firebase AI Logic SDK を使う方法があります。個人開発者が iOS アプリに Gemini を組み込むなら、私は Firebase AI Logic SDK を強く推奨します。

理由は 3 つあります。Firebase Authentication との自然な統合によりユーザーごとのアクセス制御が簡単にできること、App Attest と Firebase App Check によりバックエンドなしで安全な API 呼び出しが実現できること、そして Firebase プロジェクトとの一体管理でコスト・ログ・配信設定が一元化できることです。

この記事では、Firebase AI Logic × SwiftUI で Gemini を組み込む全工程を、実際に動くコードとともに解説します。

## Firebase プロジェクトのセットアップ

まず Firebase コンソールで AI Logic を有効化します。

Firebase コンソール → プロジェクト設定 → AI → Firebase AI Logic を有効化という手順です。Gemini Developer API（無料枠あり）と Vertex AI Gemini API（従量課金）を選択できます。個人開発の初期フェーズでは Gemini Developer API から始め、ユーザーが増えたら Vertex AI に移行するのがスムーズです。

Podfile への追加です。

```ruby
pod 'FirebaseAI', '~> 11.0'
pod 'FirebaseAuth', '~> 11.0'
pod 'FirebaseAppCheck', '~> 11.0'
```

App Check の設定も忘れずに。これがないと、ビルドされた IPA から API キーを逆アセンブルされた場合にリクエストを拒否できません。

```swift
// AppDelegate.swift
import Firebase
import FirebaseAppCheck

class AppDelegate: NSObject, UIApplicationDelegate {
    func application(_ application: UIApplication,
                     didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey: Any]? = nil) -> Bool {
        
        #if DEBUG
        let providerFactory = AppCheckDebugProviderFactory()
        #else
        let providerFactory = DeviceCheckProviderFactory()
        #endif
        
        AppCheck.setAppCheckProviderFactory(providerFactory)
        FirebaseApp.configure()
        return true
    }
}
```

## Firebase AI Logic クライアントの実装

Swift 6 対応の `@Observable` マクロを使ったクライアント実装です。

```swift
import FirebaseAI
import FirebaseAuth
import Observation

@Observable
final class GeminiClient {
    private var model: GenerativeModel?
    private(set) var isInitialized = false
    
    // コスト管理用のトークンカウンター
    private(set) var sessionTokensUsed: Int = 0
    private let maxSessionTokens: Int = 50000  // セッションあたりの上限
    
    func initialize() async throws {
        guard Auth.auth().currentUser != nil else {
            throw GeminiClientError.notAuthenticated
        }
        
        let ai = FirebaseAI.firebaseAI(backend: .googleAI())
        
        model = ai.generativeModel(
            modelName: "gemini-2.0-flash",
            generationConfig: GenerationConfig(
                temperature: 0.7,
                maxOutputTokens: 2048,
                responseMIMEType: "text/plain"
            ),
            safetySettings: [
                SafetySetting(
                    harmCategory: .harassment,
                    threshold: .blockMediumAndAbove
                ),
                SafetySetting(
                    harmCategory: .hateSpeech,
                    threshold: .blockMediumAndAbove
                )
            ]
        )
        isInitialized = true
    }
    
    func generateText(prompt: String) async throws -> String {
        guard let model = model else {
            throw GeminiClientError.notInitialized
        }
        
        guard sessionTokensUsed < maxSessionTokens else {
            throw GeminiClientError.sessionBudgetExceeded(limit: maxSessionTokens)
        }
        
        let response = try await model.generateContent(prompt)
        
        if let usageMetadata = response.usageMetadata {
            sessionTokensUsed += usageMetadata.totalTokenCount ?? 0
        }
        
        return response.text ?? ""
    }
    
    enum GeminiClientError: LocalizedError {
        case notAuthenticated
        case notInitialized
        case sessionBudgetExceeded(limit: Int)
        
        var errorDescription: String? {
            switch self {
            case .notAuthenticated:
                return "ログインしてから AI 機能をお使いください"
            case .notInitialized:
                return "AI 機能の初期化に失敗しました"
            case .sessionBudgetExceeded(let limit):
                return "このセッションの利用上限（\(limit)トークン）に達しました"
            }
        }
    }
}
```

## ストリーミングレスポンスの実装

ユーザー体験を大きく向上させるストリーミングは、Firebase AI Logic でも対応しています。

```swift
@Observable
final class ChatViewModel {
    private let geminiClient: GeminiClient
    private(set) var messages: [ChatMessage] = []
    private(set) var isGenerating = false
    private(set) var streamingText = ""
    
    init(geminiClient: GeminiClient) {
        self.geminiClient = geminiClient
    }
    
    func sendMessage(_ userText: String) async {
        guard !userText.trimmingCharacters(in: .whitespacesAndNewlines).isEmpty else { return }
        guard !isGenerating else { return }
        
        let userMessage = ChatMessage(role: .user, content: userText)
        messages.append(userMessage)
        
        isGenerating = true
        streamingText = ""
        
        do {
            guard let model = geminiClient.model else { throw GeminiClientError.notInitialized }
            
            let history = buildHistory()
            let chat = model.startChat(history: history)
            
            let stream = try chat.sendMessageStream(userText)
            
            for try await chunk in stream {
                if let text = chunk.text {
                    streamingText += text
                }
            }
            
            messages.append(ChatMessage(role: .model, content: streamingText))
            
        } catch {
            messages.append(ChatMessage(
                role: .system,
                content: "エラーが発生しました: \(error.localizedDescription)"
            ))
        }
        
        streamingText = ""
        isGenerating = false
    }
    
    private func buildHistory() -> [ModelContent] {
        // 最新10件のメッセージのみコンテキストに含める（コスト削減）
        return messages.suffix(10).map { message in
            ModelContent(
                role: message.role == .user ? "user" : "model",
                parts: [.text(message.content)]
            )
        }
    }
}
```

`suffix(10)` でコンテキストに含めるメッセージ数を制限しているのがポイントです。会話履歴をすべて送ると入力トークンが増え、コストが急増します。ユーザー体験と費用のバランスを取るために、10〜20 件程度に制限するのが実際の運用では効果的です。

## SwiftUI での表示実装

```swift
struct ChatView: View {
    @Environment(ChatViewModel.self) private var viewModel
    @State private var inputText = ""
    @FocusState private var isInputFocused: Bool
    
    var body: some View {
        VStack(spacing: 0) {
            ScrollViewReader { proxy in
                ScrollView {
                    LazyVStack(alignment: .leading, spacing: 12) {
                        ForEach(viewModel.messages) { message in
                            MessageBubble(message: message)
                                .id(message.id)
                        }
                        
                        // ストリーミング中の仮表示
                        if viewModel.isGenerating && !viewModel.streamingText.isEmpty {
                            MessageBubble(
                                message: ChatMessage(
                                    role: .model,
                                    content: viewModel.streamingText
                                )
                            )
                            .id("streaming")
                        }
                    }
                    .padding()
                }
                .onChange(of: viewModel.streamingText) { _, _ in
                    withAnimation {
                        proxy.scrollTo("streaming", anchor: .bottom)
                    }
                }
            }
            
            Divider()
            
            HStack(spacing: 12) {
                TextField("メッセージを入力", text: $inputText, axis: .vertical)
                    .textFieldStyle(.plain)
                    .lineLimit(1...5)
                    .focused($isInputFocused)
                
                Button {
                    Task {
                        let text = inputText
                        inputText = ""
                        await viewModel.sendMessage(text)
                    }
                } label: {
                    Image(systemName: "arrow.up.circle.fill")
                        .font(.title2)
                        .foregroundStyle(inputText.isEmpty ? .secondary : .blue)
                }
                .disabled(inputText.isEmpty || viewModel.isGenerating)
            }
            .padding()
        }
    }
}
```

## App Store 審査で引っかかりやすいポイント

AI 機能を搭載した iOS アプリの審査は、通常のアプリより慎重に見られます。私が実際に経験した注意点を整理します。

プライバシーポリシーには AI 機能の明記が必要です。「ユーザーのメッセージを AI サービス（Google Gemini）に送信すること」「そのデータがどのように扱われるか」を明記しないとリジェクトされます。

App Privacy の設定で「使用されるデータの種類」に AI プロバイダーへの送信を含めておかないと、審査通過後も問題になることがあります。

生成されたコンテンツに対するコンテンツモデレーションのポリシーが必要です。SafetySettings を適切に設定していることを、スクリーンショットで示せるようにしておくと審査がスムーズです。

子ども向けカテゴリ（Kids Category）に設定する場合は AI 機能の使用は原則不可です。

## コスト暴走の防止設計

個人開発でよくあるコスト事故は「悪意あるユーザーがリクエストを大量送信する」パターンです。Firebase との組み合わせで効果的に防ぐ設計を紹介します。

Firebase Firestore に使用量を記録し、1ユーザーあたりの上限を設ける方法が最もシンプルです。

```swift
// Firestoreで1日あたりの使用量を管理
func checkAndUpdateDailyUsage(userId: String, tokensToUse: Int) async throws -> Bool {
    let db = Firestore.firestore()
    let today = Calendar.current.startOfDay(for: Date())
    let docRef = db.collection("usage").document("\(userId)_\(today.timeIntervalSince1970)")
    
    return try await db.runTransaction { transaction, errorPointer in
        let document = try? transaction.getDocument(docRef)
        let currentTokens = document?.data()?["tokens"] as? Int ?? 0
        let dailyLimit = 10000  // 1ユーザー1日あたりのトークン上限
        
        if currentTokens + tokensToUse > dailyLimit {
            return false  // 上限超過
        }
        
        transaction.setData(
            ["tokens": currentTokens + tokensToUse, "updatedAt": Timestamp()],
            forDocument: docRef,
            merge: true
        )
        return true
    } as! Bool
}
```

## まとめ：Firebase AI Logic は個人 iOS 開発者の現実解

Firebase AI Logic × SwiftUI の組み合わせは、個人開発者がバックエンドを最小化しながら Gemini を iOS アプリに組み込む現実的な選択肢です。

特に Firebase をすでに使っているプロジェクトへの追加は非常にスムーズで、認証・セキュリティ・コスト管理が既存の Firebase インフラに自然に乗ります。

App Store 審査の注意点、コスト暴走防止、ストリーミング実装という 3 つのポイントを押さえれば、品質の高い AI 機能をアプリに組み込めます。まずは Gemini Developer API の無料枠で実装を完成させ、ユーザーが増えてから Vertex AI に移行するという段階的なアプローチがお勧めです。
