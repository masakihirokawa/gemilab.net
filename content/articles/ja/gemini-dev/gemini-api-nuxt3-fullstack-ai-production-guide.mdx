## はじめに — Nuxt 3 × Gemini API を選ぶ理由

Vue.js エコシステムを代表するフルスタックフレームワーク Nuxt 3 は、2026 年現在も多くの開発者に選ばれ続けています。その理由は、ファイルシステムベースのルーティング・自動コード分割・強力な SSR 機能といった生産性向上の仕組みが、フロントエンドとバックエンドを一体的に管理できる点にあります。

AI 機能を組み込む観点で見ると、Nuxt 3 には特有の強みがあります。`server/api/` 配下に配置するだけで即座に API ルートが生成される「サーバールート」機能は、クライアントサイドに API キーを露出させずに Gemini API を呼び出すための理想的な実装基盤です。また、Composable（`useXxx`）によるステート管理の抽象化が、マルチターンチャットの実装コストを大幅に下げてくれます。

本記事では、Nuxt 3 × Gemini API を使ったフルスタック AI アプリを、**本番環境で安定稼働させる**ことを最終ゴールとして設定します。単なる「動くデモ」ではなく、ストリーミング・レート制限・認証・コスト最適化・デプロイ戦略まで一貫して解説します。

### 環境変数の設定

Gemini API キーをクライアントサイドに漏洩させないために、`.env` ファイルで管理し、サーバー側のみからアクセスします。

```bash
# .env（Gitにコミットしないこと）
GEMINI_API_KEY=YOUR_GEMINI_API_KEY

# nuxt.config.ts で runtimeConfig に設定
```

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  runtimeConfig: {
    // サーバーサイドのみ（クライアントに公開しない）
    geminiApiKey: process.env.GEMINI_API_KEY,
    // パブリックに公開してよい設定
    public: {
      appName: 'Gemini Nuxt App'
    }
  },
  nitro: {
    // Cloudflare Workers 向けプリセット（本番デプロイ時）
    preset: 'cloudflare-pages'
  }
})
```

この設定により、`useRuntimeConfig()` を通してサーバールート内からのみ API キーにアクセスできます。クライアントサイドの Vue コンポーネントから `runtimeConfig.geminiApiKey` を呼び出しても `undefined` が返るため、意図せずキーが流出するリスクを排除できます。

## サーバールートによる安全な Gemini API 連携

### 基本的なサーバールートの実装

```typescript
// server/api/chat.post.ts
import { GoogleGenAI } from '@google/genai'

export default defineEventHandler(async (event) => {
  const config = useRuntimeConfig()
  const body = await readBody(event)

  // バリデーション
  if (!body.message || typeof body.message !== 'string') {
    throw createError({ statusCode: 400, message: 'message is required' })
  }
  if (body.message.length > 4000) {
    throw createError({ statusCode: 400, message: 'message too long' })
  }

  const genai = new GoogleGenAI({ apiKey: config.geminiApiKey })

  try {
    const response = await genai.models.generateContent({
      model: 'gemini-2.5-flash',
      contents: body.message,
      config: {
        maxOutputTokens: 2048,
        temperature: 0.7
      }
    })
    return {
      text: response.text,
      usageMetadata: response.usageMetadata
    }
  } catch (error: any) {
    // Gemini API エラーの適切な変換
    if (error.status === 429) {
      throw createError({
        statusCode: 429,
        message: 'Rate limit exceeded. Please try again later.'
      })
    }
    throw createError({ statusCode: 500, message: 'AI generation failed' })
  }
})
```

## ストリーミングレスポンスの実装（SSE）

AI アプリのユーザー体験を大きく左右するのが「ストリーミング」です。レスポンス全文が生成されてから表示するのではなく、生成されたトークンをリアルタイムに表示することで、体感速度が劇的に改善されます。

### サーバールートのストリーミング対応

```typescript
// server/api/chat-stream.post.ts
import { GoogleGenAI } from '@google/genai'

export default defineEventHandler(async (event) => {
  const config = useRuntimeConfig()
  const body = await readBody(event)

  // SSE ヘッダーを設定
  setHeader(event, 'Content-Type', 'text/event-stream')
  setHeader(event, 'Cache-Control', 'no-cache')
  setHeader(event, 'Connection', 'keep-alive')
  setHeader(event, 'X-Accel-Buffering', 'no') // nginx バッファリング無効化

  const genai = new GoogleGenAI({ apiKey: config.geminiApiKey })

  // Nuxt の sendStream でストリームを返す
  return sendStream(event, async (stream) => {
    try {
      const result = await genai.models.generateContentStream({
        model: 'gemini-2.5-flash',
        contents: body.message,
        config: { maxOutputTokens: 2048 }
      })

      for await (const chunk of result) {
        const text = chunk.text
        if (text) {
          // SSE フォーマット: "data: ...\n\n"
          stream.write(`data: ${JSON.stringify({ text })}\n\n`)
        }
      }
      // 完了シグナル
      stream.write(`data: ${JSON.stringify({ done: true })}\n\n`)
    } catch (error) {
      stream.write(`data: ${JSON.stringify({ error: 'Generation failed' })}\n\n`)
    } finally {
      stream.end()
    }
  })
})
```

### クライアントサイドの EventSource 受信

```vue
<!-- composables/useGeminiStream.ts -->
<script setup lang="ts">
export function useGeminiStream() {
  const streamText = ref('')
  const isStreaming = ref(false)

  async function startStream(message: string) {
    isStreaming.value = true
    streamText.value = ''

    // fetch を使って POST + ReadableStream でストリーム受信
    const response = await fetch('/api/chat-stream', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ message })
    })

    const reader = response.body!.getReader()
    const decoder = new TextDecoder()
    let buffer = ''

    while (true) {
      const { value, done } = await reader.read()
      if (done) break

      buffer += decoder.decode(value, { stream: true })
      const lines = buffer.split('\n')
      buffer = lines.pop() || ''

      for (const line of lines) {
        if (line.startsWith('data: ')) {
          const data = JSON.parse(line.slice(6))
          if (data.done) {
            isStreaming.value = false
          } else if (data.text) {
            streamText.value += data.text
          }
        }
      }
    }
  }

  return { streamText, isStreaming, startStream }
}
</script>
```

## マルチターンチャットと状態管理

Gemini API のマルチターンチャットを Nuxt 3 で実装する際、チャット履歴の管理が重要になります。Pinia ストアと組み合わせることで、クリーンなアーキテクチャを実現できます。

```typescript
// stores/chat.ts
import { defineStore } from 'pinia'

interface Message {
  role: 'user' | 'model'
  content: string
  timestamp: number
}

export const useChatStore = defineStore('chat', () => {
  const messages = ref<Message[]>([])
  const sessionId = ref(crypto.randomUUID())

  function addMessage(role: Message['role'], content: string) {
    messages.value.push({
      role,
      content,
      timestamp: Date.now()
    })
  }

  function clearChat() {
    messages.value = []
    sessionId.value = crypto.randomUUID()
  }

  // API に送る履歴形式に変換
  const apiHistory = computed(() =>
    messages.value.map(m => ({
      role: m.role,
      parts: [{ text: m.content }]
    }))
  )

  return { messages, sessionId, addMessage, clearChat, apiHistory }
})
```

```typescript
// server/api/chat-multi.post.ts
import { GoogleGenAI } from '@google/genai'

export default defineEventHandler(async (event) => {
  const config = useRuntimeConfig()
  const body = await readBody(event)
  const { message, history = [] } = body

  const genai = new GoogleGenAI({ apiKey: config.geminiApiKey })
  const model = genai.models

  // 会話履歴を含めてコンテキストを構築
  const contents = [
    ...history,
    { role: 'user', parts: [{ text: message }] }
  ]

  const response = await model.generateContent({
    model: 'gemini-2.5-flash',
    contents,
    config: {
      systemInstruction: 'あなたは親切で丁寧なアシスタントです。日本語で回答してください。',
      maxOutputTokens: 2048
    }
  })

  return { text: response.text }
})
```

## Nuxt ミドルウェアでのレート制限と認証

本番環境では、無制限の API 呼び出しを許可するとコストが膨大になります。Nuxt の `server/middleware/` を使ってレート制限を実装しましょう。

### メモリベースのシンプルなレート制限

```typescript
// server/middleware/rate-limit.ts
const requestCounts = new Map<string, { count: number; resetAt: number }>()

const RATE_LIMIT = {
  maxRequests: 10,   // 1分間の最大リクエスト数
  windowMs: 60_000   // ウィンドウサイズ（1分）
}

export default defineEventHandler((event) => {
  // /api/chat* パスのみ適用
  if (!event.path.startsWith('/api/chat')) return

  const ip =
    getHeader(event, 'x-forwarded-for')?.split(',')[0].trim() ||
    event.node.req.socket.remoteAddress ||
    'unknown'

  const now = Date.now()
  const record = requestCounts.get(ip)

  if (!record || now > record.resetAt) {
    // 新しいウィンドウを開始
    requestCounts.set(ip, { count: 1, resetAt: now + RATE_LIMIT.windowMs })
    return
  }

  if (record.count >= RATE_LIMIT.maxRequests) {
    const retryAfter = Math.ceil((record.resetAt - now) / 1000)
    setHeader(event, 'Retry-After', String(retryAfter))
    throw createError({
      statusCode: 429,
      message: `レート制限に達しました。${retryAfter}秒後に再試行してください。`
    })
  }

  record.count++
})
```

> **本番環境ではメモリではなく KV や Redis でカウントを永続化することを推奨します。** Cloudflare Workers 環境では Cloudflare KV を、Vercel 環境では Vercel KV（Redis）を利用してください。

## エラーハンドリングとコスト最適化

### 指数バックオフによるリトライ

Gemini API の一時的なエラー（429・503）には、指数バックオフでリトライするのが定石です。エラーハンドリングの実装パターンについては [Gemini API エラーハンドリングとリトライパターン完全ガイド](/articles/gemini-api/gemini-api-error-handling-retry-patterns) も参照してください。

```typescript
// server/utils/retry.ts
export async function withRetry<T>(
  fn: () => Promise<T>,
  maxAttempts = 3,
  baseDelay = 1000
): Promise<T> {
  for (let attempt = 1; attempt <= maxAttempts; attempt++) {
    try {
      return await fn()
    } catch (error: any) {
      const isRetryable = error.status === 429 || error.status === 503
      if (!isRetryable || attempt === maxAttempts) throw error

      const delay = baseDelay * Math.pow(2, attempt - 1)
      const jitter = Math.random() * 1000
      await new Promise(r => setTimeout(r, delay + jitter))
    }
  }
  throw new Error('Unreachable')
}
```

### コスト最適化の実践テクニック

API コストを最小化するために、以下の設定を組み合わせましょう。詳しくは [Gemini API コスト最適化完全ガイド](/articles/gemini-api/gemini-api-cost-optimization-complete-guide) で解説しています。

**1. `maxOutputTokens` の適切な制限**
```typescript
config: {
  maxOutputTokens: 512,    // 短い回答で十分な場合は制限する
  temperature: 0.5         // 創造性が不要な場合は低めに
}
```

**2. Context Caching の活用**
```typescript
// 長いシステムプロンプトや固定コンテキストはキャッシュ
const cachedContent = await genai.caches.create({
  model: 'gemini-2.5-flash',
  contents: [/* 固定コンテキスト */],
  ttl: '3600s'
})
```

**3. Gemini 2.5 Flash の優先使用**
大半のユースケースでは `gemini-2.5-flash` で十分なパフォーマンスが出ます。`gemini-2.5-pro` は複雑な推論が必要な場合のみ使用することで、コストを 5〜10 倍削減できます。

**4. リクエストのキャッシング**
```typescript
// server/api/chat.post.ts 内でのシンプルなキャッシング
const responseCache = new Map<string, string>()

// 同一メッセージは API を呼ばずキャッシュから返す
const cacheKey = JSON.stringify({ message: body.message })
if (responseCache.has(cacheKey)) {
  return { text: responseCache.get(cacheKey), cached: true }
}
```

## よくある質問（FAQ）

**Q1. Nuxt 3 の `server/api/` ルートは Cloudflare Workers でも動きますか？**

はい。Nuxt 3 の Nitro エンジンは Cloudflare Workers プリセットを公式サポートしており、`server/api/` 配下のルートは Worker として実行されます。ただし、Workers 環境では Node.js のネイティブモジュール（`fs` など）が利用できないため、`@google/genai` SDK の Web API 対応版（`@google/genai/web`）を使用するか、`compatibility_flags = ["nodejs_compat"]` を有効化してください。

**Q2. マルチターンチャットの会話履歴はどこに保存すべきですか？**

セッションあたりのメッセージ数が少ない場合（20〜30 件程度）は、クライアントサイドの Pinia ストアか `localStorage` で十分です。長期間の履歴保持や複数デバイス間の同期が必要な場合は、Cloudflare KV・Supabase・Firebase などのバックエンドストレージに保存してください。会話履歴が増えると入力トークン数（コスト）も増えるため、最新 N 件に絞るか Context Caching を活用しましょう。

**Q3. 本番環境でストリーミングが突然切れる問題の対処法は？**

Cloudflare Workers 環境では、デフォルトで 30 秒のタイムアウトが設定されています。長い生成タスクでは `wrangler.toml` の `[limits]` でタイムアウトを延長するか、生成を分割するアーキテクチャを採用してください。また、nginx や CDN のバッファリングが原因でストリームが遅延する場合は、`X-Accel-Buffering: no` ヘッダーを付与してください（本記事のサーバールートに実装済み）。
