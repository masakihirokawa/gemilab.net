## はじめに：SvelteKit × Gemini API が注目される理由

AIチャットアプリの開発において、フレームワーク選びは開発体験と最終的な品質を大きく左右します。近年、**SvelteKit** はその軽量さ・高速なSSR（サーバーサイドレンダリング）・シンプルな記法から、フルスタック開発の有力な選択肢として注目を集めています。そこに **Gemini API** のストリーミング応答を組み合わせることで、応答性の高いリアルタイムAIチャットアプリを効率よく構築できます。

この記事では、次のことを学べます。

- SvelteKit プロジェクトへの Gemini API の組み込み方
- サーバーサイドでのAPIキー安全管理
- ストリーミングレスポンスの実装と Svelte ストアへのリアルタイム反映
- チャット履歴の管理とマルチターン会話の実装
- Vercel・Cloudflare Pages へのデプロイ手順

**対象読者**: TypeScript の基礎知識があり、SvelteKit の基本構造を理解している方。Gemini API の利用経験は問いません。

## SvelteKit と Gemini API の組み合わせが優れている理由

SvelteKit は Next.js や Nuxt.js と比較して次の強みがあります。

**バンドルサイズの小ささ**: Svelte はコンパイル時に仮想DOMを使わず、ネイティブ JavaScript に変換します。その結果、クライアントに送信される JS は非常に小さく、初回ロードが速くなります。

**Server Actions との親和性**: SvelteKit の `+page.server.ts` と `+server.ts` を使えば、APIキーをサーバーサイドに閉じ込めたまま、フロントエンドからシームレスにデータを取得できます。

**シンプルなリアクティビティ**: Svelte の `$state` や `$derived` を使うと、ストリーミングテキストの逐次表示が非常に少ないコードで実現できます。

これらの特性が、**Gemini API のストリーミング応答を扱うアプリ**と非常に相性よく機能します。

## 環境準備：APIキーの取得と SvelteKit セットアップ

### Gemini API キーの取得

[Google AI Studio](https://aistudio.google.com/) にアクセスし、「Get API key」からキーを発行します。発行したキーは安全な場所に保管してください。

### SvelteKit プロジェクトの作成

```bash
# SvelteKit プロジェクト作成（TypeScript + ESLint）
npm create svelte@latest my-gemini-chat
cd my-gemini-chat
npm install

# Google Generative AI SDK をインストール
npm install @google/generative-ai
```

プロジェクト作成時は「SvelteKit demo app」ではなく「Skeleton project」を選び、TypeScript を有効にします。

### 環境変数の設定

プロジェクトルートに `.env` ファイルを作成します。

```bash
# .env（Gitにコミットしないこと）
GEMINI_API_KEY=YOUR_GEMINI_API_KEY
```

> ⚠️ SvelteKit では、`VITE_` プレフィックスのない変数はサーバーサイドのみで参照できます。クライアントに露出しないよう、`GEMINI_API_KEY` はプレフィックスなしで設定してください。

## サーバーサイド API エンドポイントの実装

`src/routes/api/chat/+server.ts` を作成し、Gemini API との通信を実装します。

```typescript
// src/routes/api/chat/+server.ts
import { GoogleGenerativeAI } from '@google/generative-ai';
import { GEMINI_API_KEY } from '$env/static/private';
import type { RequestHandler } from './$types';

const genAI = new GoogleGenerativeAI(GEMINI_API_KEY);

export const POST: RequestHandler = async ({ request }) => {
  const { messages } = await request.json();

  // Gemini 2.5 Flash を使用（高速・コスト効率が高い）
  const model = genAI.getGenerativeModel({ model: 'gemini-2.5-flash' });

  // チャット履歴を Gemini のフォーマットに変換
  const history = messages.slice(0, -1).map((msg: { role: string; content: string }) => ({
    role: msg.role === 'user' ? 'user' : 'model',
    parts: [{ text: msg.content }],
  }));

  const chat = model.startChat({ history });
  const lastMessage = messages[messages.length - 1].content;

  // ストリーミングレスポンスを生成
  const result = await chat.sendMessageStream(lastMessage);

  // ReadableStream でクライアントにチャンク送信
  const stream = new ReadableStream({
    async start(controller) {
      const encoder = new TextEncoder();
      for await (const chunk of result.stream) {
        const text = chunk.text();
        if (text) {
          controller.enqueue(encoder.encode(`data: ${JSON.stringify({ text })}\n\n`));
        }
      }
      controller.enqueue(encoder.encode('data: [DONE]\n\n'));
      controller.close();
    },
  });

  return new Response(stream, {
    headers: {
      'Content-Type': 'text/event-stream',
      'Cache-Control': 'no-cache',
      Connection: 'keep-alive',
    },
  });
};
```

ポイントは `sendMessageStream()` を使ってストリーミングを有効にし、**Server-Sent Events（SSE）** 形式でクライアントにチャンクを配信している点です。

## フロントエンドのチャット UI 実装

`src/routes/+page.svelte` にチャットインターフェースを実装します。

```svelte
<!-- src/routes/+page.svelte -->
<script lang="ts">
  let messages = $state<{ role: 'user' | 'assistant'; content: string }[]>([]);
  let input = $state('');
  let isStreaming = $state(false);

  async function sendMessage() {
    if (!input.trim() || isStreaming) return;

    const userMessage = input.trim();
    input = '';
    messages.push({ role: 'user', content: userMessage });
    messages.push({ role: 'assistant', content: '' });
    isStreaming = true;

    const assistantIndex = messages.length - 1;

    try {
      const response = await fetch('/api/chat', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ messages: messages.slice(0, -1) }),
      });

      // SSE のストリームを読み取る
      const reader = response.body!.getReader();
      const decoder = new TextDecoder();

      while (true) {
        const { done, value } = await reader.read();
        if (done) break;

        const text = decoder.decode(value);
        const lines = text.split('\n').filter(l => l.startsWith('data: '));

        for (const line of lines) {
          const data = line.replace('data: ', '');
          if (data === '[DONE]') break;
          const parsed = JSON.parse(data);
          messages[assistantIndex].content += parsed.text;
        }
        // Svelte のリアクティビティを発火
        messages = [...messages];
      }
    } catch (error) {
      console.error('チャットエラー:', error);
      messages[assistantIndex].content = 'エラーが発生しました。再度お試しください。';
    } finally {
      isStreaming = false;
    }
  }
</script>

<main class="chat-container">
  <div class="messages">
    {#each messages as msg}
      <div class="message {msg.role}">
        <p>{msg.content}</p>
      </div>
    {/each}
    {#if isStreaming}
      <div class="typing-indicator">Gemini が入力中...</div>
    {/if}
  </div>

  <form on:submit|preventDefault={sendMessage} class="input-area">
    <input
      type="text"
      bind:value={input}
      placeholder="メッセージを入力..."
      disabled={isStreaming}
    />
    <button type="submit" disabled={isStreaming || !input.trim()}>
      送信
    </button>
  </form>
</main>
```

このコードでは Svelte 5 の `$state` ルーンを使い、ストリーミング中のテキスト更新を効率的にリアクティブ管理しています。`messages = [...messages]` の行でスプレッド演算子を使って配列の参照を更新し、DOM の再レンダリングを確実に発火させるのがポイントです。

## Vercel・Cloudflare Pages へのデプロイ

### Vercel へのデプロイ

```bash
npm install -D @sveltejs/adapter-vercel
```

`svelte.config.js` を更新します。

```javascript
// svelte.config.js
import adapter from '@sveltejs/adapter-vercel';
import { vitePreprocess } from '@sveltejs/vite-plugin-svelte';

export default {
  preprocess: vitePreprocess(),
  kit: {
    adapter: adapter()
  }
};
```

Vercel ダッシュボードの「Environment Variables」に `GEMINI_API_KEY` を設定し、`vercel deploy` でデプロイします。

### Cloudflare Pages へのデプロイ

```bash
npm install -D @sveltejs/adapter-cloudflare
```

`svelte.config.js` の adapter を `@sveltejs/adapter-cloudflare` に変更し、Cloudflare Dashboard の「Pages」→「Settings」→「Environment variables」にキーを追加します。

> 💡 Gemini API の利用には**レート制限**があります。本番環境では、Gemini API のクォータ（1分あたりのリクエスト数）を確認し、必要に応じてキャッシュや再試行ロジックを実装することをおすすめします。さらに詳しい本番向けフルスタック実装については、[Gemini API × Next.js 15 App Router フルスタック本番構築完全ガイド](/articles/gemini-dev/gemini-api-nextjs15-app-router-fullstack-production) もあわせてご覧ください。

## よくある質問（FAQ）

**Q1. SvelteKit 以外のフレームワーク（Next.js、Nuxt.js など）との比較は？**

SvelteKit は仮想DOM を使わないため、クライアントサイドのバンドルサイズが最小になります。AIチャットアプリのようにリアルタイム更新が多いインターフェースでは、この軽量さがスムーズなユーザー体験に直結します。ただし、エコシステムの広さでは Next.js が有利です。チームの習熟度や要件にあわせて選択してください。

**Q2. Gemini のモデルは何を選べばよいですか？**

チャットアプリには **Gemini 2.5 Flash** が最初の選択肢としておすすめです。応答速度が速く、コストも低く抑えられます。複雑な推論が必要な場合は **Gemini 2.5 Pro** や **Gemini 3 Pro** への切り替えを検討してください。モデル選定の詳しい基準は [Gemini モデル選定ガイド](/articles/gemini-basics/gemini-model-selection-guide) を参照してください。

**Q3. チャット履歴はどのように永続化すればよいですか？**

シンプルな実装では `localStorage` や `sessionStorage` を使えますが、ユーザー間でのデータ共有や端末をまたいだ同期が必要な場合は、**Supabase** や **Firebase** との連携をおすすめします。Gemini API の `startChat()` に渡す `history` 配列をデータベースから取得・保存するだけで、マルチセッションのチャット履歴管理が実現できます。
