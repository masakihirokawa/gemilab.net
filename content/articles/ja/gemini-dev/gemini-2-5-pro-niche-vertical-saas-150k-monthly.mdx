「個人開発で SaaS を作っても、汎用ツールはどこも競合だらけで疲弊する」——多くの方が一度はこの感覚を持つのではないでしょうか。私自身、汎用の文章生成ツールやタスク管理アプリで何度かトライして、何度も「気づけば値段競争」「使われ方が散漫で改善が当たらない」というループに入りました。

そこから抜け出した手応えがあったのは、**特定業界の・特定業務に・縦に深く入り込む**設計に切り替えたときでした。汎用ツールが「広く浅く」なら、縦深ニッチは「狭く深く」。Gemini 2.5 Pro の長文処理能力と構造化応答は、この縦深ニッチに圧倒的に合います。

この記事では、月15万円という現実的な目標を、Gemini 2.5 Pro を核としたマイクロSaaS で達成するための実装と運用を丁寧にまとめます。動くコードと、なぜそう設計するかの理由を一緒に見ていきましょう。

## なぜ汎用 SaaS で疲弊し、縦深ニッチで勝てるのか

汎用 SaaS が疲弊するのは、ユーザーごとの「使い方」が違いすぎることが根本原因です。同じ「文章生成」でも、マーケターは Twitter コピーが欲しく、編集者はコラムの構成案が欲しく、士業は契約書の条項が欲しい。すべてに合わせると焦点がぼやけ、結果として「なんとなく便利だけど決め手に欠ける」プロダクトになります。

縦深ニッチは、この問題を**ターゲットを絞ることで解決**します。たとえば「税理士事務所のスタッフ向け、決算前の試算表チェックアシスタント」と決めれば、必要な機能は一気に絞れます。「日本語の会計用語を理解する Gemini プロンプト」「日税連の様式に近い出力フォーマット」「過去の試算表との差分検出」——汎用 SaaS が触らない領域に踏み込めるのです。

縦深ニッチの強みはもう1つあります。**口コミが効きます**。ターゲット業界のコミュニティは思った以上に狭く、3〜5社に導入されると、業界内で名前が出始めます。汎用 SaaS のように「広告費で勝負」する世界ではないので、個人開発者でも勝負できる土俵になるのです。

## 縦深ニッチの選び方 — 3つの判断軸

「どの業界に絞るか」は、月15万円達成を左右する最大の判断です。私が今使っている判断軸は3つあります。

**1. 自分が最低限の業務知識を持っているか、または1週間で学べるか**

業界知識ゼロから入ると、要件定義そのものが難しくなります。経験がある業界か、家族・知人に話を聞ける業界、または公開情報で1週間学べる業界に絞ります。

**2. ターゲットの方々が PC を1日3時間以上使っているか**

紙とハンコ文化が強すぎる業界は、SaaS の導入ハードルが上がります。日常的に PC を使う業務に絞るほうが、最初の有料ユーザー獲得が速いです。

**3. 「同じ作業を月10回以上繰り返す」業務があるか**

月1回の作業に課金するのは難しいですが、月10回以上の繰り返し業務には、月¥3,000〜¥5,000の課金が成立しやすくなります。Gemini 2.5 Pro が得意な「構造化された繰り返し業務」と相性が良いポイントです。

私が実際に手応えを感じたニッチを挙げると、税理士・社労士の補助業務、Web制作会社のクライアント向けレポート作成、不動産会社の物件説明文生成、医療系クリニックの問診票要約などです。いずれも、汎用ツールでは届かない深さの要件があります。

## 実装パターン1: Gemini 2.5 Pro の構造化応答で業界用フォーマットを担保する

縦深ニッチでは、出力の「形式」が業界基準に揃っていることが信頼の鍵になります。Gemini 2.5 Pro の `responseSchema` を使った構造化応答が、ここで威力を発揮します。

```typescript
// 税理士向け試算表チェックの構造化応答
import { GoogleGenerativeAI, SchemaType } from "@google/generative-ai";

interface BalanceCheck {
  warnings: { account: string; reason: string; severity: "info" | "warn" | "error" }[];
  suggested_actions: string[];
  next_review_date: string;
}

async function checkTrialBalance(env: Env, csv: string): Promise<BalanceCheck> {
  const genai = new GoogleGenerativeAI(env.GEMINI_API_KEY);
  const model = genai.getGenerativeModel({
    model: "gemini-2.5-pro",
    generationConfig: {
      responseMimeType: "application/json",
      responseSchema: {
        type: SchemaType.OBJECT,
        properties: {
          warnings: {
            type: SchemaType.ARRAY,
            items: {
              type: SchemaType.OBJECT,
              properties: {
                account: { type: SchemaType.STRING },
                reason: { type: SchemaType.STRING },
                severity: { type: SchemaType.STRING },
              },
              required: ["account", "reason", "severity"],
            },
          },
          suggested_actions: {
            type: SchemaType.ARRAY,
            items: { type: SchemaType.STRING },
          },
          next_review_date: { type: SchemaType.STRING },
        },
        required: ["warnings", "suggested_actions", "next_review_date"],
      },
    },
  });

  try {
    const result = await model.generateContent(
      `次の試算表(CSV)に対して、税理士の視点で疑義のある勘定科目を抽出してください。\n\n${csv}`
    );
    const text = result.response.text();
    return JSON.parse(text) as BalanceCheck;
  } catch (error) {
    console.error("checkTrialBalance failed:", error);
    // フォールバック: 空の構造を返してUIが落ちないようにする
    return { warnings: [], suggested_actions: [], next_review_date: "" };
  }
}
```

ここで重要なのは、**出力の構造を業務側の言葉で固定**していることです。「warnings」「suggested_actions」のキーは、ユーザー（税理士）が普段使う「疑義」「対応」という業務語と1:1で対応します。これを汎用的な `summary` や `text` にすると、業界の方々の信頼を一瞬で失います。

また、エラー時に空配列を返すフォールバックを必ず入れます。Gemini API が一時的に応答しない場合でも、画面が落ちずに「異常なし」と読める状態を維持できます。

## 実装パターン2: Cloud Run + Cloudflare KV でユーザー別利用量を制御する

縦深ニッチでも、課金プランのフェアな運用は必要です。Cloud Run でホスティングしつつ、ユーザーごとの月次利用量を Cloudflare KV に集約する構成が、低コストかつスケールに耐えます。

```typescript
// 利用量をカウントしながら API を実行
interface UsageQuota {
  monthlyLimit: number;
  used: number;
  resetAt: string;
}

async function consumeQuota(env: Env, userId: string): Promise<{ allowed: boolean; quota: UsageQuota }> {
  const key = `quota:${userId}:${new Date().toISOString().slice(0, 7)}`; // YYYY-MM
  const raw = await env.QUOTA.get(key, "json") as UsageQuota | null;
  const quota: UsageQuota = raw ?? {
    monthlyLimit: 100, // 標準プラン
    used: 0,
    resetAt: nextMonthStart(),
  };
  if (quota.used >= quota.monthlyLimit) {
    return { allowed: false, quota };
  }
  quota.used += 1;
  await env.QUOTA.put(key, JSON.stringify(quota), { expirationTtl: 60 * 60 * 24 * 35 });
  return { allowed: true, quota };
}

function nextMonthStart(): string {
  const d = new Date();
  d.setMonth(d.getMonth() + 1, 1);
  d.setHours(0, 0, 0, 0);
  return d.toISOString();
}

// 実際の処理ハンドラ
export async function handle(req: Request, env: Env): Promise<Response> {
  const userId = await authenticate(req, env);
  if (!userId) return new Response("Unauthorized", { status: 401 });

  const { allowed, quota } = await consumeQuota(env, userId);
  if (!allowed) {
    return new Response(
      JSON.stringify({ error: "monthly_quota_exceeded", quota }),
      { status: 429, headers: { "Content-Type": "application/json" } }
    );
  }

  const csv = await req.text();
  const result = await checkTrialBalance(env, csv);
  return new Response(JSON.stringify(result), { headers: { "Content-Type": "application/json" } });
}
```

このパターンの肝は、**月次キーを `YYYY-MM` で切る**ことです。月跨ぎの処理を別途書く必要がなく、自然に翌月にリセットされます。KV の TTL を35日に設定することで、データが消えるタイミングも自動で揃います。

## 実装パターン3: 業務特化のオンボーディングを Gemini で半自動化する

縦深ニッチで最も差がつくのは、**初回利用での「これは私たちの業界を分かっている」という信頼形成**です。汎用 SaaS の登録フォームをそのまま使うと、業界の方々はすぐ離脱します。Gemini を使って、初期設定を業界文脈で対話的に進めます。

```typescript
// オンボーディング対話
async function onboardingStep(env: Env, userInput: string, history: { role: string; content: string }[]) {
  const genai = new GoogleGenerativeAI(env.GEMINI_API_KEY);
  const model = genai.getGenerativeModel({ model: "gemini-2.5-pro" });
  const systemContext = `
あなたは税理士事務所向け SaaS のオンボーディング担当です。
利用者が普段使う業務用語（試算表、月次、決算月、関与先 など）で語りかけてください。
質問は1度に1つだけ。3往復以内で初期設定を完了できる順序で進めてください。
`.trim();

  const messages = [
    { role: "user", parts: [{ text: systemContext }] },
    ...history.map(h => ({ role: h.role, parts: [{ text: h.content }] })),
    { role: "user", parts: [{ text: userInput }] },
  ];

  try {
    const result = await model.generateContent({ contents: messages });
    return result.response.text();
  } catch (error) {
    console.error("onboarding failed:", error);
    return "申し訳ありません、もう一度お聞かせいただけますか？";
  }
}
```

「業界用語で話す」という指示が、初回体験を決定的に変えます。汎用的な「ようこそ！まずはお名前を教えてください」というフローでは届かない深さの信頼が、最初の3問で生まれます。

## 価格設計と月15万円までのマイルストーン

縦深ニッチの価格は、**業界の代替コストから逆算**して決めます。たとえば税理士事務所のスタッフが手作業で同じチェックをすると、1社あたり月2〜3時間。時給換算で月¥6,000〜¥9,000の人件費がかかっています。これに対して月¥4,980 の SaaS なら、迷うほどの価格ではありません。

私が設計するときの基準価格テーブルはこうです。

- スタータープラン: 月¥2,980（月50回まで）
- 標準プラン: 月¥4,980（月150回まで・実質メインプラン）
- 拡張プラン: 月¥9,800（月500回まで）

月15万円までのマイルストーンは次の通り。

- 1か月目: スタータープラン3社、標準プラン2社（月¥18,940）
- 3か月目: 標準プラン10社、拡張プラン1社（月¥59,600）
- 6か月目: 標準プラン20社、拡張プラン4社（月\¥138,800）

このペースは、業界コミュニティ内での口コミと、業界紙・業界向けポータルへの寄稿で十分に到達できる規模です。広告費に頼らない代わりに、**業界の方々と直接話す時間**を毎週2〜3時間確保することが運用上のポイントになります。

## よくある間違い・落とし穴

縦深ニッチの SaaS で見かける落とし穴を3つ挙げます。

**1. 業界外の意見で機能を増やしてしまう**
SNS で他業界の方から「こういう機能もほしい」と言われると、つい応えたくなります。けれど、業界外のリクエストに従うと、せっかくの縦深ニッチ性が失われます。**機能追加は、ターゲット業界の有料ユーザーからの要望に限定**するのが鉄則です。

**2. 業界の規制や法令を軽視する**
税理士向けなら税理士法、医療向けなら医師法、士業向けなら個人情報保護法。**「データを Gemini に送る範囲」を業界の規制に合わせて設計**することが、信頼の根本です。プロンプトに個人情報を含めない、要約は匿名化された数字のみ送る、といったガードを実装段階から組み込みます。

**3. ローンチ直後に値下げをしてしまう**
最初の数社が獲得しづらいと、つい「特別価格」を提示したくなります。しかし、最初に下げた価格は**業界内に出回って戻せなくなる**ものです。ディスカウントは「初月のみ」「年契約のみ」のように、構造で正当化できる形に絞るのが安全です。

## まとめ — ニッチを選ぶことは、競争の土俵を選ぶこと

縦深ニッチで月15万円を作るのは、汎用 SaaS で月15万円を作るより**確実に速い**というのが、私の今の実感です。汎用は競合に追いつくまでの距離が長すぎる。縦深は最初の3社で「業界内で知られたサービス」になり、そこから自然に広がっていきます。

今回紹介した3つの実装パターン（構造化応答・利用量制御・業務特化オンボーディング）は、いずれも独立して導入できます。私のおすすめは、まず**1業界1業務に絞ってランディングページとオンボーディング対話を作り、2社にだけ手売りで導入する**ところから始めることです。

業界特化の課金導線をさらに精緻にしたい場合は、[Gemini API で『使用量課金』を実装する完全ガイド](/articles/gemini-api/gemini-api-cloud-run-usage-based-saas-complete-guide) も合わせて読むと、Stripe Metered Billing と組み合わせた設計判断が深まります。コスト面の不安があれば、[Gemini API 無料枠 完全攻略ガイド 2026](/articles/gemini-api/gemini-api-free-tier-complete-guide-2026) も併読をおすすめします。

書籍では、[ベンチャー創造の作法（大江 建）](https://www.amazon.co.jp/dp/4334039944/?tag=pinocchio-22) のような、業界文脈と顧客との関係構築を扱う本が、月15万円から月50万円へ抜けるための判断軸を授けてくれます。

最初の30分でやれるのは、「**自分が業務語で話せる業界はどこか**」を5つ書き出し、それぞれに「月10回以上の繰り返し業務はあるか」を付け加えることです。そこに残った業界が、あなたの縦深ニッチの候補になります。
