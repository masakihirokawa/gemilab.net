Gemini Code Assist を導入したのにコード補完が動かない、VS Code の拡張機能が応答しない、Outline 機能が表示されない――こういったトラブルに直面したことはないでしょうか。ここでは実際によくあるトラブルを症状別に整理し、すぐに試せる対処法をご紹介します。

## まず確認すること：基本チェックリスト

トラブルシューティングを始める前に、以下の基本事項を確認してください。

**1. ログインと認証の確認**

VS Code の左側サイドバーに表示される Gemini アイコンをクリックし、Google アカウントでサインインしているかを確認します。サインインが必要なメッセージが表示されている場合は、認証から再スタートです。

**2. 拡張機能のバージョン確認**

VS Code の拡張機能タブで「Gemini Code Assist」を検索し、最新バージョンがインストールされているかを確認します。古いバージョンでは動作しない機能があります。

**3. ネットワーク接続の確認**

Gemini Code Assist はクラウドサービスであるため、安定したインターネット接続が必要です。社内プロキシや VPN 環境の場合は、後述の設定が必要になることがあります。

## 症状別トラブルシューティング

### 症状1：コード補完（インラインサジェスト）が一切表示されない

**原因と対処法：**

まず VS Code の設定で Gemini Code Assist が有効になっているかを確認します。コマンドパレット（`Cmd+Shift+P` / `Ctrl+Shift+P`）を開いて「Gemini: Enable/Disable Suggestions」と入力し、現在の状態を確認してください。

次に、インラインサジェストの設定を確認します。`settings.json` に以下の設定が含まれているか確認してください。

```json
{
  "editor.inlineSuggest.enabled": true,
  "geminiCode.enableInlineSuggestions": true
}
```

設定変更後は VS Code を再起動してください。

また、`Tab` キーで候補を受け入れる設定になっているかも確認しましょう。`editor.tabCompletion` が `"off"` になっていると、候補が表示されても受け入れられません。

**それでも動かない場合：** 拡張機能を一度アンインストールし、VS Code を再起動してから再インストールしてみてください。

### 症状2：VS Code 拡張機能はインストールされているのにサインインできない

**対処法：**

1. VS Code のコマンドパレットで「Gemini Code Assist: Sign Out」を実行してサインアウトします。
2. OS のキーチェーン/認証情報マネージャーから Google 関連のキャッシュをクリアします。
3. 再度「Gemini Code Assist: Sign In」を実行してサインインします。

**ブラウザのデフォルト設定が原因の場合：** VS Code が外部ブラウザを開いて認証を行う際に問題が起きることがあります。VS Code の設定で `"workbench.externalBrowser"` が正しく設定されているか確認してください。

**企業アカウント（Google Workspace）をお使いの場合：** 管理者が Gemini Code Assist の使用を許可していない可能性があります。Google Workspace 管理コンソールで Gemini Code Assist が有効化されているかを管理者に確認してもらう必要があります。

### 症状3：Outline 機能が表示されない・機能しない

Gemini Code Assist には、コードの概要（Outline）を生成してナビゲーションを助ける機能があります。この機能が動作しない場合の対処法を説明します。

**対処法1：言語サポートの確認**

Outline 機能は現時点では一部の言語でのみ利用可能です。Python、JavaScript、TypeScript、Java、Go などが主要な対応言語です。使用している言語が対応しているかを公式ドキュメントで確認してください。

**対処法2：設定の確認**

```json
{
  "geminiCode.enableOutline": true
}
```

上記の設定が `settings.json` に含まれているか確認してください。

**対処法3：ファイルサイズの確認**

非常に大きなファイル（数千行以上）では Outline の生成に時間がかかることがあります。処理中はステータスバーにスピナーが表示されます。しばらく待ってみてください。

### 症状4：補完の精度が低い・的外れな候補が出る

Gemini Code Assist の補完精度は、コンテキスト（周囲のコード）の量と質に依存します。

**改善のためのヒント：**

コメントで意図を明示することで精度が向上します。

```python
# ユーザーのメールアドレスのバリデーション関数
# RFC 5322に準拠した形式チェックを行う
def validate_email(email: str) -> bool:
    # ← ここでGeminiの補完がより正確な実装を提案するようになる
```

また、ファイルの先頭に使用するライブラリや技術スタックを記載することも効果的です。

```typescript
// Framework: Next.js 15 App Router
// State: Zustand
// Styling: Tailwind CSS
```

### 症状5：プロキシ環境・VPN 環境でつながらない

社内ネットワークのプロキシ設定が必要な環境では、VS Code の設定でプロキシを指定する必要があります。

**VS Code のプロキシ設定：**

```json
{
  "http.proxy": "http://your-proxy-server:port",
  "http.proxyStrictSSL": false,
  "http.proxyAuthorization": null
}
```

上記の設定でも解決しない場合は、`HTTPS_PROXY` 環境変数を設定してから VS Code を起動してみてください。

```bash
# macOS / Linux
export HTTPS_PROXY=http://your-proxy-server:port
code .

# Windows (PowerShell)
$env:HTTPS_PROXY="http://your-proxy-server:port"
code .
```

### 症状6：JetBrains IDE（IntelliJ IDEA / PyCharm 等）で動作しない

Gemini Code Assist は JetBrains IDE にも対応しています。動作しない場合は以下を確認してください。

IDE のプラグインマーケットプレースで「Google Cloud Code」または「Gemini Code Assist」プラグインを検索し、最新版がインストールされているか確認します。プラグインのインストール後は IDE の再起動が必要です。

また、JetBrains IDE 向けの設定は VS Code とは異なる場所にあります。「Settings → Tools → Google Cloud Code」から設定を確認してください。

## ログを確認して原因を特定する

症状が特定できない場合は、Gemini Code Assist のログを確認することで詳細な原因がわかります。

**VS Code でのログ確認方法：**

1. メニューの「Help → Toggle Developer Tools」を開く
2. Console タブで「gemini」または「google」で検索してエラーメッセージを確認する

または、VS Code の Output パネル（`Ctrl+Shift+U`）で「Gemini Code Assist」を選択するとログが表示されます。

## よくあるエラーメッセージと対処

「Authentication failed」というエラーが出る場合は、サインアウト後に再サインインしてください。「Quota exceeded」が表示される場合は、利用制限に達しています。しばらく時間をおいてから試すか、利用プランのアップグレードを検討してください。「Network error」が続く場合は、ファイアウォールやプロキシの設定を確認してください。「Extension host terminated unexpectedly」の場合は VS Code を完全に終了し再起動してください。

## 全体を振り返って

Gemini Code Assist のトラブルは、多くの場合、認証の問題・拡張機能の設定・ネットワーク環境のいずれかに原因があります。本記事のチェックリストを順番に試していただくことで、多くの問題は解決できるかと思います。それでも解決しない場合は、公式の [Gemini Code Assist サポートページ](https://cloud.google.com/gemini/docs/codeassist/overview) もあわせてご確認ください。困っている方のお役に立てれば幸いです。

## エージェントモードとは（まず確認しよう

Gemini Code Assist のエージェントモードは、単純なコード補完やインラインサジェストとは異なり、複数ファイルにまたがる変更の計画・実行、コマンドの提案、テストの生成などを半自動で行える機能です。2025年後半から段階的に展開が始まり、2026年現在は Enterprise・Individual の両プランで利用可能になっています。

ただし、**有効化に必要な手順が通常の補完機能と異なります**。「拡張機能を入れたら使えるはず」と思っていると、エージェントとして動いていないことに気づかないまま時間を過ごすことになります。

まず確認してほしいのは、VS Code であればチャットパネルの入力欄に「agent」モードのトグルが表示されているかどうかです。表示されていない場合、以下のいずれかが原因として考えられます。

- 拡張機能のバージョンが古い（後述）
- ライセンスの有効化が完了していない
- 組織の管理者によってエージェントモードが無効化されている（Workspace 環境）

## 拡張機能のバージョンを確認する

エージェントモードは比較的新しい機能であるため、古いバージョンの拡張機能では利用できません。VS Code の場合、**拡張機能バージョン `2.x` 以降** が必要です。

確認方法：
1. VS Code の拡張機能ビュー（`Ctrl+Shift+X` / `Cmd+Shift+X`）を開く
2. 「Gemini Code Assist」で検索し、インストール済みの拡張機能のバージョンを確認する
3. 古い場合は「更新」ボタンをクリックしてアップデートする

```bash
# VS Code のコマンドラインからバージョン確認
code --list-extensions --show-versions | grep -i gemini
# 例: GoogleCloudTools.cloudcode@2.3.1
```

JetBrains（IntelliJ IDEA・PyCharm 等）の場合は、`Preferences > Plugins > Installed` から「Gemini Code Assist」プラグインを確認してください。バージョン `1.8` 以降がエージェントモードに対応しています。

## ライセンスと認証の問題を切り分ける

エージェントモードが表示されない・利用できないもう一つの原因がライセンス認証の問題です。

**Individual プランの場合**、Google アカウントでのサインインが必要です。VS Code 左下のステータスバーか、コマンドパレット（`Ctrl+Shift+P`）から「Gemini Code Assist: Sign In」を実行して、ブラウザ経由で認証してください。

```
// 認証確認のチェックリスト
✅ VS Code ステータスバーに「Gemini」アイコンが表示されている
✅ アイコンをクリックしてサインイン済みのアカウントが表示される
✅ 「Pro」または「Enterprise」ライセンスが適用されている
❌ 「Free」表示の場合、エージェントモードは利用不可
```

**Enterprise プランの場合**、組織の管理者が Gemini for Google Cloud の管理コンソールでエージェントモードを許可設定している必要があります。自分の環境での利用可否が分からない場合は、IT 管理者に確認するのが最短です。

## エージェントが途中で止まる・応答しない

認証と拡張機能の問題をクリアしてもエージェントが途中で止まる場合は、次のパターンを確認してください。

### コンテキストが大きすぎる

エージェントモードはリポジトリ全体を参照できますが、**一度に処理できるコンテキスト量には上限があります**。特に大きなプロジェクトで「プロジェクト全体を分析して」のような広い指示を出すと、途中でタイムアウトするか無応答になることがあります。

対処策：指示を具体的に絞り込む

```
# 悪い例（広すぎる指示）
「このプロジェクトのバグを全部見つけて修正して」

# 良い例（スコープを限定した指示）
「src/api/auth.ts の認証ロジックを見て、JWT トークンの検証に問題がないか確認して」
```

### ネットワークタイムアウト

企業のプロキシや VPN 環境では、エージェントモードの WebSocket 接続がタイムアウトすることがあります。VS Code の設定で `http.proxy` が正しく設定されているか確認しましょう。

```json
// settings.json
{
  "http.proxy": "http://your-proxy.example.com:8080",
  "http.proxyAuthorization": null,
  "http.proxyStrictSSL": false
}
```

### `@workspace` / `@file` 参照が機能しない

エージェントモードでは `@workspace` でプロジェクト全体、`@file` で特定ファイルを参照できますが、**ワークスペースのインデックスが作成されていない**と参照に失敗します。

VS Code の場合、ウィンドウをリロード（`Ctrl+Shift+P` → 「Developer: Reload Window」）するとインデックスが再構築されることが多いです。また、`.gitignore` に除外されているファイルはエージェントが参照できません。重要なファイルが除外されていないか確認してください。

## エラーメッセージ別の対処法

エージェントモード使用時に表示される主なエラーと対処法を整理します。

**`Failed to complete task: context limit exceeded`**
→ 指示のスコープが広すぎます。特定のファイルや機能に絞って依頼してください。

**`Agent mode is not available for your plan`**
→ 現在のライセンスがエージェントモードに対応していません。プランのアップグレードが必要です。

**`Unable to index workspace`**
→ ワークスペースのサイズが大きすぎるか、アクセス権限の問題です。VS Code の出力パネルで詳細ログを確認してください。

**`Connection to Gemini service failed`**
→ ネットワーク問題またはサービス障害です。[Google Cloud Status](https://status.cloud.google.com/) でサービス状態を確認してください。

## ログを見て原因を特定する

エラーメッセージだけでは原因が分からない場合、VS Code の出力ログが手がかりになります。

```
// ログの確認手順
1. メニュー「View > Output」を開く
2. ドロップダウンから「Gemini Code Assist」または「Gemini Code Assist - Agent」を選択
3. エラーが発生したタイミングのログを確認する
```

よく見かけるログパターンと意味：

```
[ERROR] Agent: Task execution failed after 3 retries
→ API 呼び出しが繰り返し失敗。認証かネットワークの問題

[WARN] Workspace indexing incomplete: 2847 files skipped
→ 大規模リポジトリでインデックスが部分的。.gitignore の見直しを

[INFO] Agent mode: Using gemini-2.5-pro-latest
→ 正常にモデルが選択されている（このメッセージが出ていれば接続は正常）
```
