Gemma 4がリリースされてから、「ローカルで動かしてみたい」という方が一気に増えました。ゼロコストで高性能なモデルを手元で使えるのは魅力的ですが、実際にセットアップしてみると意外なところで詰まることがあります。

この記事では、OllamaとLM StudioでGemma 4を動かす際に多くの方がぶつかるエラーを、原因と解決策とともに紹介します。「なぜかモデルが読み込めない」「推論が極端に遅い」「メモリ不足でクラッシュする」といった状況をお持ちの方は、ぜひ参考にしてください。

## Ollamaでのよくある3つのエラー

### エラー1：`Error: pull model manifest: file does not exist`

Ollamaでモデル名を指定して実行したのに、このエラーが出るケースがあります。

```bash
ollama run gemma4
# Error: pull model manifest: file does not exist
```

**原因**: Ollamaのモデル名は大文字小文字・バージョン指定に厳格です。`gemma4` ではなく `gemma4:27b` や `gemma4:2b` のように正式なタグ名を使う必要があります。

**解決策**: まず利用可能なタグ一覧を確認してから実行します。

```bash
# 利用可能なGemma 4モデルを確認
ollama search gemma4

# 正しいタグ名で実行（例: 27B版）
ollama run gemma4:27b

# 軽量版（2B）はこちら
ollama run gemma4:2b
```

`ollama list` で現在ダウンロード済みのモデルを確認しておくと、ミスが減ります。

---

### エラー2：ダウンロードが途中で止まる・再開できない

Gemma 4の27BモデルはファイルサイズがGB単位になるため、ネットワーク状況によってダウンロードが途中で止まってしまうことがあります。

```
pulling manifest...
pulling xxxxxxxx: 34% ▕████████      ▏ 5.9 GB/17.4 GB  ...stopped
```

**解決策**: Ollamaはダウンロードの再開（レジューム）に対応しています。同じコマンドを再実行すると、中断した箇所から再開できます。

```bash
# 再実行するだけで再開できる
ollama run gemma4:27b
```

ただし、ダウンロード中にプロセスをKillした場合は部分ファイルが残ることがあります。その場合は一度削除して再取得します。

```bash
# モデルを削除して再ダウンロード
ollama rm gemma4:27b
ollama run gemma4:27b
```

---

### エラー3：VRAMが不足して起動しない

```
Error: model requires more system memory (24 GB) than is available (16 GB)
```

これはGPUのVRAMではなく、システムRAMが不足しているときに表示されるエラーです（Ollamaは環境によってCPU推論も行います）。

**解決策その1**: より小さいモデルに切り替えます。Gemma 4は2B・9B・27Bとサイズが選べます。

```bash
# 27B → 9B に切り替え
ollama run gemma4:9b
```

**解決策その2**: GPU専有で動かしたい場合は、`OLLAMA_NUM_GPU` 環境変数でGPUレイヤー数を調整できます。

```bash
# GPUレイヤーを全て使用（VRAM上限に注意）
OLLAMA_NUM_GPU=999 ollama run gemma4:27b
```

4bit量子化版（`gemma4:27b-it-q4_K_M` 等）があればVRAM消費を大幅に削減できます。Ollamaのタグ一覧で `q4` や `q8` が付いているものを選ぶと良いでしょう。

## LM Studioでのよくある問題と解決策

### モデルが読み込まれない・起動ボタンを押しても反応しない

LM Studioでダウンロードしたモデルを選んで「Load」を押したのに何も起きない、あるいはすぐにクラッシュするケースです。

**確認点1**: ハードウェア設定の見直し

LM Studioの「Model Settings」パネルで **GPU Offload Layers** の値を確認してください。スライダーを0にするとCPU推論になりますが、GPUを使いたい場合は正の値にします。ただし高すぎるとVRAMを超過してクラッシュします。

実用的な設定の目安（Gemma 4 27B、VRAM 8GB環境の場合）:
- GPU Offload Layers: 15〜20（全43層のうち一部をGPUに、残りをCPUに割り当て）
- Context Length: 4096（デフォルトより下げると消費メモリが減ります）

**確認点2**: モデルファイルの整合性チェック

ダウンロードが不完全だと読み込み失敗の原因になります。LM Studioの「My Models」タブで当該モデルを右クリックし、「Reveal in Finder / Explorer」からファイルサイズを確認してください。Hugging FaceのModel Cardに記載されているサイズと一致しているかを確認します。

---

### 推論が異常に遅い（1トークン/秒以下）

出力が極端に遅い場合、ほぼ確実にCPU推論になっています。

**Mac（Apple Silicon）の場合**: LM StudioはMPS（Metal Performance Shaders）に対応しているため、GPUが自動で使われるはずです。設定が反映されていない場合は、アプリを完全終了してから再起動してみてください。

**WindowsのNVIDIA GPU環境の場合**: CUDA対応版のLM Studioをインストールしているか確認します。ページ下部の「Download」から「With CUDA」を選んでください。

```
# LM Studio ログで確認できるコード例
[INFO] GPU layers: 0/43  ← 0だとCPU推論
[INFO] GPU layers: 43/43 ← 全層GPUに乗っている
```

GPU Offload Layersを上げてもGPUが認識されない場合、グラフィックドライバのアップデートが必要な場合があります。

---

### 日本語の出力が文字化けする・途中で止まる

Gemma 4は多言語対応ですが、LM Studioのデフォルトテンプレートが英語向けに最適化されていると、日本語の出力が不安定になることがあります。

**解決策**: LM Studioの「Chat」画面で「Preset」を「Gemma Instruct」または「ChatML」に変更してみてください。システムプロンプトに日本語で指示を入れることで安定性が向上します。

```
システムプロンプト例:
あなたは日本語で回答するアシスタントです。必ず日本語で回答してください。
```

## Ollama API（localhost:11434）に接続できない

Ollamaのサーバー起動後にPythonから接続を試みると、以下のエラーが出ることがあります。

```python
import requests
response = requests.post("http://localhost:11434/api/generate", json={
    "model": "gemma4:9b",
    "prompt": "こんにちは"
})
# ConnectionRefusedError: [Errno 111] Connection refused
```

**原因1**: Ollamaサービスが起動していない

```bash
# サービスの状態確認
ollama serve

# または systemctl を使っている場合（Linux）
systemctl start ollama
```

**原因2**: ポートがファイアウォールでブロックされている

ローカル接続のみなら問題ないはずですが、別マシンからアクセスする場合はOllamaのデフォルト設定が `localhost` に限定されています。

```bash
# 全インターフェースで受け付けるよう変更（セキュリティに注意）
OLLAMA_HOST=0.0.0.0:11434 ollama serve
```

**動作確認の方法**（シンプルに試す）:

```bash
# curlで疎通確認
curl http://localhost:11434/api/generate \
  -d '{
    "model": "gemma4:9b",
    "prompt": "1+1は？",
    "stream": false
  }'
```

これでレスポンスが返ってくれば、Ollamaサーバー自体は正常に動いています。

## それでも解決しない場合のチェックリスト

これまでのどのケースにも当てはまらない場合、以下を順番に確認してみてください。

- **OSとツールのバージョン確認**: `ollama --version` や LM Studio のバージョンが古い場合、Gemma 4の新しい量子化フォーマットに対応していないことがあります
- **モデルのGGUF形式確認**: Hugging FaceからGGUFファイルを手動でダウンロードした場合、LLaMA系フォーマットで変換されたものかどうかを確認してください
- **ディスク空き容量**: 27Bモデルは量子化後でも15〜20GB程度必要です。`df -h` でディスクを確認します
- **ログの確認**: LM Studioは `~/.cache/lm-studio/logs/` にログが出力されます。エラーの詳細がわかることがあります

Gemma 4のローカル実行については、[Gemma 4をゼロコストでローカル実行する方法](/articles/gemini-updates/gemma-4-local-execution-zero-cost-app)も参考にしてください。また、クラウドAPI経由で試したい場合は[Gemma 4の完全ガイド](/articles/gemini-advanced/gemma-4-complete-guide)に詳細が載っています。

ローカルLLMはセットアップのハードルがあるぶん、動いたときの達成感があります。この記事のケースを参考に、ぜひ手元でGemma 4を動かしてみてください。
