Gemini Code Assist は、Google が提供する AI コーディングアシスタントです。VS Code や JetBrains IDE、Google Cloud Shell などに統合でき、コードの補完・生成・説明・テスト作成まで幅広く対応しています。

「コード補完ツール」として使っている人は多いですが、真の力はコンテキストを深く理解した上での**ペアプログラマーとしての対話**にあります。このガイドでは、単純な補完を超えた高度な活用法を、実際のプロンプトと使用例とともに解説します。

## Gemini Code Assist を最大限に活用する準備

### インストールと基本設定

VS Code の場合、拡張機能マーケットプレイスで「Gemini Code Assist」を検索してインストールします。Google アカウントでサインインすれば、個人向けは無料枠内で利用開始できます。

インストール後、設定ファイルに次のオプションを追加することで挙動をカスタマイズできます。

```json
{
  "geminicodeassist.inlineSuggestions.enableAuto": true,
  "geminicodeassist.chat.enableContextualSuggestions": true,
  "geminicodeassist.enableCodeActions": true
}
```

### コンテキストの与え方が品質を決める

Gemini Code Assist への質問の質は、コンテキストの与え方に大きく依存します。

**弱いプロンプト**：
```
この関数を修正して
```

**強いプロンプト**：
```
以下の関数はユーザー認証処理を行っています。
現在の問題：JWTトークンの有効期限チェックが実装されていないため、
期限切れトークンでもAPIアクセスが通ってしまいます。

修正要件：
1. トークンの exp クレームを検証する
2. 期限切れの場合は 401 エラーを返す
3. 既存のテスト（test/auth.test.ts）を壊さないこと

使用しているライブラリ：jsonwebtoken@9.0

[関数のコードを貼り付け]
```

コンテキストが充実しているほど、修正案の精度が上がります。

## コードレビューの自動化：PR品質を劇的に上げる

### セルフレビューの習慣化

PR を出す前に Gemini Code Assist でセルフレビューを行うことで、レビュアーへの負担を減らしつつ、コード品質を引き上げられます。

VS Code のチャット（Ctrl+Shift+I）でコードを選択した状態で次のプロンプトを使います。

```
このコード差分についてコードレビューを行ってください。

観点：
1. バグや潜在的な問題（null参照、境界値、競合状態など）
2. セキュリティ上のリスク（SQLインジェクション、XSS、認証漏れなど）
3. パフォーマンスの懸念（N+1クエリ、不要なレンダリングなど）
4. コードの可読性・保守性
5. 既存のコーディング規約からの逸脱

問題の深刻度を「高・中・低」で分類し、修正案も提示してください。
```

このプロセスを PR 作成前の必須ステップにすることで、**レビュアーからのリテイク数が平均30〜50%削減**されるという報告があります。

### アーキテクチャレベルのレビュー

単一ファイルのレビューだけでなく、複数ファイルにまたがる設計の問題も Gemini Code Assist で相談できます。

```
以下のコンポーネント設計について、アーキテクチャ観点でのフィードバックをください。

[コンポーネントの構造や主要なファイルのコードを貼り付け]

特に確認したいこと：
- 依存関係の方向は適切か
- 責務の分離は明確か
- テスタビリティへの影響
- 将来の機能拡張時の懸念点
```

## バグ検出と修正：デバッグを加速する

### エラーメッセージからの原因特定

スタックトレースやエラーメッセージを Gemini Code Assist に投げると、原因の仮説と修正案を提示してくれます。

```
以下のエラーが本番環境で発生しています。

エラーメッセージ：
[エラー内容をそのまま貼り付け]

実行環境：Node.js 22, Express 5.x, PostgreSQL 17
発生頻度：1日に20〜30回程度

関連しそうなコード：
[エラーが出ているファイルの関連部分を貼り付け]

考えられる原因のトップ3と、それぞれの調査・確認方法を教えてください。
```

### 型エラーの解消

TypeScript の型エラーは初心者から経験者まで悩まされる問題です。

```
以下の TypeScript エラーを解消したいです。

エラー：
Type 'string | undefined' is not assignable to type 'string'.

エラーが出ている箇所：
[コードを貼り付け]

型の安全性を保ちながら、このエラーを解消する方法を3パターン提示してください。
それぞれのトレードオフも教えてください。
```

### 非同期処理のデバッグ

Promise チェーンや async/await の問題は特にデバッグが難しい領域です。

```
以下の非同期処理でメモリリークが発生していると疑っています。
1時間程度の運用でメモリ使用量が増え続けます。

[コードを貼り付け]

考えられる原因と、メモリリークを確認するためのデバッグ手順を教えてください。
Node.js のヒープダンプの取り方も含めてください。
```

## テスト自動生成：カバレッジを短時間で引き上げる

テストコードの作成は重要だとわかっていても後回しにしがちです。Gemini Code Assist を使うと、既存コードからテストの骨格を素早く生成できます。

### ユニットテストの生成

```
以下の関数のユニットテストを Jest で生成してください。

[テスト対象の関数を貼り付け]

カバーしてほしいケース：
1. 正常系：典型的な入力に対する期待する出力
2. 境界値：空文字列、null、undefined、最大値/最小値
3. 異常系：不正な入力に対するエラーハンドリング
4. 非同期エラー：Promise が reject される場合（async 関数の場合）

モックが必要な依存関係は jest.mock() で適切に設定してください。
テストの説明文は日本語で書いてください。
```

### 統合テストのシナリオ設計

```
以下の API エンドポイントの統合テストを Supertest + Jest で生成してください。

エンドポイント：POST /api/orders
処理概要：注文を作成し、在庫を減らし、確認メールを送信する

テストすべきシナリオ：
1. 正常な注文作成
2. 在庫不足の場合のエラー
3. 認証されていないリクエスト
4. バリデーションエラー（必須フィールド欠落）
5. データベースエラー時のロールバック確認

[エンドポイントの実装コードを貼り付け]

テストデータのセットアップ・クリーンアップも含めてください。
```

### スナップショットテストの活用

React コンポーネントの場合、スナップショットテストも Gemini Code Assist で生成できます。

```
以下の React コンポーネントのテストを生成してください。

[コンポーネントコードを貼り付け]

要件：
- React Testing Library を使用
- ユーザーインタラクション（クリック・入力）のテストを含む
- アクセシビリティ（aria-label など）の確認を含む
- 必要に応じてスナップショットテストも追加
```

## リファクタリング：コードの品質を段階的に上げる

### レガシーコードの現代化

古い JavaScript コードを現代的な構文に書き換える作業も、Gemini Code Assist に任せられます。

```
以下のレガシーコードを現代的な JavaScript/TypeScript にリファクタリングしてください。

対象コード：
[古いコードを貼り付け]

要件：
- ES2022以降の構文を使用（async/await, optional chaining, nullish coalescingなど）
- TypeScript の型を追加
- 動作は変えずに可読性・保守性を向上させる
- 変更の理由と各変更点の解説を添えてください
```

### パフォーマンス最適化

```
以下のコードのパフォーマンスを改善してください。

現在の問題：10万件のデータを処理する際に15秒以上かかっています。
目標：5秒以内に短縮したい

[コードを貼り付け]

最適化の方針と、変更後の期待される改善効果を教えてください。
ベンチマーク測定の方法も含めてください。
```

## 生産性を最大化するためのワークフロー例

最後に、Gemini Code Assist を使った日常的な開発フローの例を示します。

**午前の開発セッション（2時間）**：
1. 前日の TODO を確認し、今日実装する機能を Gemini に説明してアプローチを相談（5分）
2. 実装開始：複雑な箇所はチャットで相談しながら進める（60分）
3. 実装完了後、セルフレビュープロンプトで品質チェック（10分）
4. テストコード生成プロンプトでテストの骨格を作成（15分）
5. テストを修正・追加して完成させる（30分）

このサイクルにより、**ドキュメント作成・コードレビュー・テスト作成の時間を合計40〜50%削減**しつつ、品質を高く保つことができます。

## まとめ

Gemini Code Assist は、単純なコード補完を超えた AI ペアプログラマーです。コンテキストを丁寧に伝えるほど精度の高い提案が返ってくるため、「いかにうまく相談するか」というスキルが重要になります。

まずは「セルフレビュープロンプト」と「テスト生成プロンプト」から始めてみてください。この2つだけでも、日々の開発効率に明確な変化を感じることができるはずです。
