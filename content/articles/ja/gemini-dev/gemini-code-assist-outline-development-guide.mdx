開発チームの課題の一つが「コード設計書の作成」です。プロジェクトが大規模になるほど、複雑な構造や機能仕様をドキュメント化する時間が増加します。

Gemini Code Assist（Google の AI コーディングアシスタント）と、その **Outline 機能**を組み合わせることで、こうしたドキュメント作成を大幅に効率化できるようになります。

本ガイドでは、Gemini Code Assist の基本から、実際のプロジェクトで設計書やアウトラインを自動生成する方法、そしてコードレビュー機能まで、実践的なテクニックを紹介します。

## Gemini Code Assist とは？——Google の AI コーディングアシスタント

**Gemini Code Assist** は、Google が提供する AI コーディングアシスタントです。VS Code や JetBrains IDE などの開発環境に統合され、以下の機能を提供します：

- **コード自動補完**：入力途中のコードを先読みして、複数の候補を提案
- **コード生成**：自然言語のコメントから機能全体を自動生成
- **バグ検出**：潜在的なバグやセキュリティ問題を指摘
- **テスト生成**：ユニットテストやE2Eテストのスケルトン自動作成
- **ドキュメント生成**：関数やモジュール全体の Outline（概要）を自動生成

特に、**Outline 機能**は、既存のコードを読み込んで、その構造や機能を簡潔にまとめたドキュメントを生成する強力な機能です。

## Outline（コード概要・設計書）を自動生成する機能

### Outline 機能の概要

Outline 機能は、コードの構造を自動的に分析して、以下の情報をまとめたドキュメントを生成します：

- **ファイル・モジュール構成**：プロジェクト全体のファイルツリー
- **主要な関数・クラス定義**：各モジュールで定義されている関数やクラスの一覧
- **関数の役割説明**：各関数が何をするのかを1〜2文で説明
- **データフロー**：モジュール間のデータの流れや依存関係
- **API仕様**：公開されている関数のパラメータと戻り値

### なぜ Outline が必要か？

従来、こうした設計書は開発者が手作業で作成していました：

- **作成時間が長い**：大規模プロジェクトなら数日〜数週間
- **最新の状態に保つのが難しい**：コード変更のたびに手動更新が必要
- **ドキュメント漏れが発生しやすい**：重要な機能をうっかり漏らす

Gemini Code Assist の Outline 機能を使えば、こうした問題を大幅に改善できます。

## セットアップ：VS Code / JetBrains での Gemini Code Assist 導入

### VS Code での インストール

1. **VS Code を開く**
2. **Extensions（拡張機能）** パネルで「Gemini Code Assist」を検索
3. **Install** をクリック
4. Google アカウントでサインイン
5. 確認コードをコピー → ブラウザで認証 → VS Code に戻る

### JetBrains IDE（IntelliJ IDEA / WebStorm など）での インストール

1. **Settings / Preferences** → **Plugins**
2. **Marketplace** タブで「Gemini Code Assist」を検索
3. **Install** をクリック
4. IDE を再起動
5. **Tools** → **Gemini Code Assist** → **Sign In** で Google アカウント認証

### 基本設定

導入後、以下の設定を確認・調整します：

```json
// VS Code の settings.json に追加（例）
{
  "geminiFx.enableAutocomplete": true,
  "geminiFx.autocompleteDelay": 300,
  "geminiFx.enableOutlineGeneration": true
}
```

## 実践：プロジェクト全体の設計ドキュメントを生成する

### ステップ1：コマンドパレットから Outline 生成を実行

VS Code の場合：

1. **Ctrl + Shift + P**（Mac: **Cmd + Shift + P**）でコマンドパレットを開く
2. **「Generate Project Outline」** を検索して実行
3. プロジェクトルートを選択

### ステップ2：生成結果を確認・編集

Outline が生成されると、エディタに以下のような内容が表示されます：

```
# Project Outline: MyApp

## Directory Structure

src/
  ├── components/
  │   ├── Header.tsx
  │   ├── Footer.tsx
  │   └── Card.tsx
  ├── pages/
  │   ├── index.tsx
  │   ├── dashboard.tsx
  │   └── settings.tsx
  ├── utils/
  │   ├── api.ts
  │   ├── validators.ts
  │   └── formatters.ts
  └── styles/
      └── globals.css

## Main Modules

### 1. components/ — UI コンポーネント集

- **Header.tsx** — ナビゲーションヘッダー。ロゴ、メニュー、ユーザープロフィールを表示
- **Footer.tsx** — フッター。サイト情報とリンク集を含む
- **Card.tsx** — 再利用可能なカード UI。タイトル、説明、アクションボタンを備える

### 2. pages/ — ページコンポーネント

- **index.tsx** — ホームページ。フィーチャー紹介と CTA ボタン
- **dashboard.tsx** — ダッシュボード（認証必須）。ユーザー統計とグラフを表示
- **settings.tsx** — ユーザー設定ページ。プロフィール編集と権限管理

### 3. utils/ — ユーティリティ関数

- **api.ts** — REST API 呼び出しをラップ。`fetchUser()`, `createPost()` 等
- **validators.ts** — フォーム入力検証。メール、パスワード、URL の妥当性チェック
- **formatters.ts** — 日付・数値・通貨のフォーマット関数
```

### ステップ3：Outline を Markdown ファイルとして保存

生成された Outline をマークダウンファイルとしてプロジェクトに保存します：

```bash
# Outline を ARCHITECTURE.md として保存
echo "# Outline 出力結果をコピー&ペースト"
```

## Gemini Code Assist のコードレビューと補完機能

### コードレビュー機能

Outline と並行して、Gemini Code Assist のコードレビュー機能も活用しましょう：

**使用方法：**
1. レビュー対象のファイルを開く
2. コマンドパレットで「Gemini: Review Code」を実行
3. AI が以下をチェック：
   - セキュリティ脆弱性（SQLインジェクション、XSS など）
   - パフォーマンス最適化の余地
   - コーディング規約の遵守状況
   - テストカバレッジの不足

### オートコンプリート機能

**自動補完の活用シーン：**

- **関数実装**：`function validateEmail()` と入力すると、メール検証ロジックを自動補完
- **テスト記述**：`describe('User')` でユニットテストのスケルトンを自動生成
- **ドキュメント記述**：`/** @param` で JSDoc テンプレートを自動補完

オートコンプリートは遅延設定で制御できます。デフォルトは 300ms ですが、高速マシンなら 100ms に短縮することで応答性が向上します。

## 活用のコツとベストプラクティス

### Tips 1：初回 Outline 生成は段階的に

大規模プロジェクトなら、一度に全体の Outline を生成するのではなく、ディレクトリごとに分割して生成することをお勧めします。

```bash
# 例：components/ ディレクトリのみ Outline 生成
src/components → Generate Outline
```

### Tips 2：生成後は必ず人間がレビュー

AI が生成した Outline は、正確ですがすべて完璧とは限りません。特に以下の点を確認します：

- **内部ロジックの説明が正確か**
- **古い関数が列挙されていないか**（リファクタリング後）
- **セキュリティ上の懸念がないか**

### Tips 3：バージョン管理に含める

Outline を Markdown や JSON として保存し、Git で version control します。コード変更のたびに Outline も更新することで、ドキュメントの鮮度を保ちます。

```bash
# Git で tracking
git add ARCHITECTURE.md
git commit -m "Update ARCHITECTURE.md — add new authentication module"
```

### Tips 4：チームメンバー間で共有

Outline を README に含めたり、Confluence や Notion に貼り付けたりすることで、プロジェクト全体の構造をチームメンバー全員で共有できます。

新しく参加したメンバーも Outline を読むだけで、コードベースの全体像を素早く理解できます。
