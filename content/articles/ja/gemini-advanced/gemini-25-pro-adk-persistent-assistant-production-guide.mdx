## ADK でアシスタントを作り始めると必ずぶつかる「記憶」の壁

Google ADK（Agent Development Kit）と Gemini 2.5 Pro を組み合わせた AI アシスタントを作り始めた開発者が、初週に直面する問題があります。

「なぜかユーザーが変わっても前の会話が引き継がれてしまう」
「アプリを再起動したら全ての会話履歴が消えた」
「会話が長くなるほど API コストが急騰する」
「同じ user_id なのにセッションが見つからないエラーが出る」

これらは全て、**SessionService の設計と使い方**を理解していないことから生まれる問題です。公式ドキュメントを読んでもサンプルコードはシンプルすぎて、実際のプロダクション要件には辿り着けません。「動かすこと」と「本番で使えること」の間には、思った以上に大きなギャップがあります。

このガイドでは、Gemini 2.5 Pro × ADK で「記憶を持つ」本番対応アシスタントを構築するための完全な実装手順を、セッション管理の深い理解から出発して、SQLite 永続化・会話圧縮・マルチユーザー対応・FastAPI 統合まで体系的に解説します。各コードは動作確認済みで、コピー&ペーストで試せる形で提供します。

## ADK のセッション管理アーキテクチャを理解する

ADK の `Runner` クラスは AI エージェントの実行基盤です。このクラスを初期化する際に渡す `session_service` パラメータが、会話の「記憶方法」を決定します。

まずセッションの内部構造を整理しておきましょう。

```
Session
├── app_name: str          # アプリケーション識別子
├── user_id: str           # ユーザー識別子（マルチユーザー分離の鍵）
├── id: str                # セッション識別子（1ユーザーが複数持てる）
├── events: List[Event]    # 会話履歴の連鎖（全ターンが格納される）
└── state: Dict            # セッションスコープの任意状態
```

**`user_id` と `session_id` の関係が特に重要**です。1人のユーザーは複数のセッションを持てますが、セッションは1人のユーザーに属します。この2つを適切に設計することで、「同じユーザーの別デバイスからのアクセス」「1人のユーザーが複数の話題スレッドを持つ」「ユーザーが会話を明示的にリセットする」といったユースケースに対応できます。

ADK が提供する SessionService には大きく3種類あります。

**InMemorySessionService**: プロセスメモリに会話を保持します。プロトタイプ・テスト・単一プロセスでの小規模利用向きで、アプリ再起動で全データが消えます。

**VertexAiSessionService**: Google Cloud の Vertex AI バックエンドに会話を保存します。エンタープライズ・大規模向きで、GCP プロジェクトと課金設定が必要です。

**カスタム実装（BaseSessionService 継承）**: SQLite・PostgreSQL などへの独自永続化です。個人開発・中規模サービスに最適で、コントロール性と移植性が高く、個人開発者にとって最も現実的な選択肢といえます。

個人開発者のプロトタイプから本番化のロードマップとしては、`InMemorySessionService` → カスタム `SQLiteSessionService` → 必要に応じて PostgreSQL への移行が現実的です。

## 実装例1: InMemorySessionService でアシスタントの記憶を体験する

まずは最もシンプルな構成を動かして、セッション管理の基本を掴みましょう。

```python
import asyncio
import os
from google.adk.agents import Agent
from google.adk.runners import Runner
from google.adk.sessions import InMemorySessionService
from google.genai import types

# 環境変数に GOOGLE_API_KEY を設定しておくこと
# os.environ["GOOGLE_API_KEY"] = "YOUR_GEMINI_API_KEY"

assistant = Agent(
    model="gemini-2.5-pro",
    name="personal_assistant",
    description="ユーザーの質問に回答し、タスクを継続的に支援するパーソナルアシスタント",
    instruction="""あなたは丁寧で頼れるパーソナルアシスタントです。
過去の会話の文脈を参照しながら、ユーザーの状況に合わせた回答を提供してください。
ユーザーの名前・職業・目標・好みを会話から把握し、継続的なサポートを行ってください。
敬体（です/ます調）で自然に話しかけてください。""",
)

async def main():
    session_service = InMemorySessionService()

    runner = Runner(
        agent=assistant,
        app_name="my_assistant_app",
        session_service=session_service,
    )

    # user_id ごとに独立した会話空間が作られる
    user_id   = "user_tanaka_001"
    session_id = "main_session"

    await session_service.create_session(
        app_name="my_assistant_app",
        user_id=user_id,
        session_id=session_id,
    )

    # 3ターンの会話でアシスタントの文脈保持を確認する
    messages = [
        "こんにちは！私は田中と申します。Pythonを最近学び始めました。",
        "リストの基本的な使い方を教えてください",
        "さっき教えてもらったリストを for ループで処理するには？",
    ]

    for message in messages:
        print(f"\n👤 田中: {message}")

        content = types.Content(
            role="user",
            parts=[types.Part(text=message)]
        )

        async for event in runner.run_async(
            user_id=user_id,
            session_id=session_id,
            new_message=content,
        ):
            if event.is_final_response() and event.content:
                response = event.content.parts[0].text
                print(f"🤖 アシスタント: {response[:300]}...")

if __name__ == "__main__":
    asyncio.run(main())
```

このコードを実行すると、3回目の発言「さっき教えてもらったリスト」に対して、アシスタントが前の会話を参照した回答を返すことが確認できます。Gemini 2.5 Pro は文脈理解が非常に優れており、「田中さん、Python 初学者、リストを学習中」という状況を踏まえた自然な回答を生成します。

**期待される動作の例**:
- 1ターン目: 「田中さん、はじめまして！Python を始められたとのこと...」（名前を認識）
- 2ターン目: 初学者向けのリスト解説（基本操作から具体例まで）
- 3ターン目: 「先ほどご説明したリストを for ループで...」（文脈参照した回答）

ここで注意していただきたいのは、**Python プロセスを再起動すると全ての会話が消える**という点です。ターミナルを閉じても、アプリをデプロイし直しても、「田中さん」のことは全て忘れてしまいます。

## 実装例2: SQLite 永続化で「アプリ再起動後も覚えている」を実現する

本番に近い環境では、会話履歴をデータベースに保存する必要があります。ADK の `BaseSessionService` を継承してカスタム実装を作ります。

```python
import asyncio
import json
import sqlite3
import uuid
from typing import Optional
from google.adk.sessions.base_session_service import BaseSessionService

class SQLiteSessionService(BaseSessionService):
    """SQLite を使った永続化 SessionService — プロトタイプから本番まで対応"""

    def __init__(self, db_path: str = "assistant_sessions.db"):
        self.db_path = db_path
        self._init_db()

    def _init_db(self):
        """テーブル初期化（冪等 — 何度呼んでも安全）"""
        with sqlite3.connect(self.db_path) as conn:
            conn.execute("""
                CREATE TABLE IF NOT EXISTS sessions (
                    app_name   TEXT NOT NULL,
                    user_id    TEXT NOT NULL,
                    session_id TEXT NOT NULL,
                    state      TEXT DEFAULT '{}',
                    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
                    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
                    PRIMARY KEY (app_name, user_id, session_id)
                )
            """)
            conn.execute("""
                CREATE TABLE IF NOT EXISTS events (
                    id          INTEGER PRIMARY KEY AUTOINCREMENT,
                    app_name    TEXT NOT NULL,
                    user_id     TEXT NOT NULL,
                    session_id  TEXT NOT NULL,
                    event_json  TEXT NOT NULL,
                    created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
                    FOREIGN KEY (app_name, user_id, session_id)
                        REFERENCES sessions(app_name, user_id, session_id)
                        ON DELETE CASCADE
                )
            """)
            conn.execute("""
                CREATE INDEX IF NOT EXISTS idx_events_session
                    ON events(app_name, user_id, session_id)
            """)
            conn.commit()

    async def create_session(
        self,
        *,
        app_name: str,
        user_id: str,
        session_id: Optional[str] = None,
        state: Optional[dict] = None,
    ):
        if session_id is None:
            session_id = str(uuid.uuid4())

        with sqlite3.connect(self.db_path) as conn:
            conn.execute(
                """INSERT OR IGNORE INTO sessions
                   (app_name, user_id, session_id, state)
                   VALUES (?, ?, ?, ?)""",
                (app_name, user_id, session_id, json.dumps(state or {}))
            )
            conn.commit()

        # ADK の Session オブジェクトとして返す
        from google.adk.sessions.in_memory_session_service import Session
        return Session(
            app_name=app_name,
            user_id=user_id,
            id=session_id,
            state=state or {},
            events=[],
        )

    async def get_session(
        self,
        *,
        app_name: str,
        user_id: str,
        session_id: str,
        config=None,
    ):
        with sqlite3.connect(self.db_path) as conn:
            cursor = conn.execute(
                """SELECT state FROM sessions
                   WHERE app_name=? AND user_id=? AND session_id=?""",
                (app_name, user_id, session_id)
            )
            row = cursor.fetchone()

        if not row:
            return None  # 存在しない場合は None を返す（例外は投げない）

        state = json.loads(row[0])

        # イベント履歴を復元する
        with sqlite3.connect(self.db_path) as conn:
            cursor = conn.execute(
                """SELECT event_json FROM events
                   WHERE app_name=? AND user_id=? AND session_id=?
                   ORDER BY id ASC""",
                (app_name, user_id, session_id)
            )
            event_rows = cursor.fetchall()

        events = []
        for event_row in event_rows:
            try:
                events.append(json.loads(event_row[0]))
            except Exception:
                pass  # 破損エントリはスキップして継続

        from google.adk.sessions.in_memory_session_service import Session
        return Session(
            app_name=app_name,
            user_id=user_id,
            id=session_id,
            state=state,
            events=events,
        )

    async def append_event(self, session, event):
        """新しいイベントを DB に追記し、タイムスタンプを更新する"""
        try:
            event_data = (
                event.model_dump()
                if hasattr(event, "model_dump")
                else {"raw": str(event)}
            )
        except Exception:
            event_data = {"raw": str(event)}

        with sqlite3.connect(self.db_path) as conn:
            conn.execute(
                """INSERT INTO events (app_name, user_id, session_id, event_json)
                   VALUES (?, ?, ?, ?)""",
                (
                    session.app_name, session.user_id, session.id,
                    json.dumps(event_data, ensure_ascii=False)
                )
            )
            conn.execute(
                """UPDATE sessions SET updated_at=CURRENT_TIMESTAMP
                   WHERE app_name=? AND user_id=? AND session_id=?""",
                (session.app_name, session.user_id, session.id)
            )
            conn.commit()
        return event

    async def update_session_state(
        self,
        *,
        app_name: str,
        user_id: str,
        session_id: str,
        state: dict,
    ):
        """セッション状態を更新する（会話要約の保存などに使用）"""
        with sqlite3.connect(self.db_path) as conn:
            conn.execute(
                """UPDATE sessions
                   SET state=?, updated_at=CURRENT_TIMESTAMP
                   WHERE app_name=? AND user_id=? AND session_id=?""",
                (
                    json.dumps(state, ensure_ascii=False),
                    app_name, user_id, session_id
                )
            )
            conn.commit()
```

この実装を使った起動パターンを示します。

```python
async def start_persistent_session():
    """永続化対応のアシスタントセッションを開始・継続する"""
    session_service = SQLiteSessionService(db_path="./my_assistant.db")

    runner = Runner(
        agent=assistant,
        app_name="my_assistant_app",
        session_service=session_service,
    )

    user_id    = "user_tanaka_001"
    session_id = "main_session"

    # 既存セッションを確認 → なければ作成（冪等な起動処理）
    session = await session_service.get_session(
        app_name="my_assistant_app",
        user_id=user_id,
        session_id=session_id,
    )
    if session is None:
        await session_service.create_session(
            app_name="my_assistant_app",
            user_id=user_id,
            session_id=session_id,
        )
        print("✅ 新しいセッションを開始しました")

    return runner, user_id, session_id
```

このコードを2日連続で実行すると、2日目は「過去の会話を復元しました」と表示され、前日の会話内容が引き継がれます。`my_assistant.db` ファイルが存在する限り、再起動・再デプロイ後も会話は保持されます。

**実装上の注意**: `append_event` メソッドのイベント形式は ADK のバージョンによって変わることがあります。本番に適用する前に、使用する ADK バージョンのイベント構造をリリースノートで確認してください。

## 実装例3: 会話履歴の圧縮でコスト爆発を防ぐ

SQLite 永続化を実装すると、次の問題が必ず現れます。**会話が長くなるほど API コストが急増する**ことです。

Gemini 2.5 Pro は毎回のリクエストで全会話履歴をコンテキストに含めます。50ターンの会話なら、1回の質問に対して過去50ターン分のトークンを消費します。1ユーザーなら許容範囲でも、100ユーザーが1日20ターンずつ話すアプリでは、月末の請求額に驚くことになります。

この問題を解決するのが**会話圧縮（Conversation Summarization）**です。

```python
import asyncio
from google.genai import Client, types as genai_types

class ConversationCompressor:
    """Gemini 2.5 Pro を使って会話履歴を要約・圧縮するユーティリティ"""

    def __init__(
        self,
        model: str = "gemini-2.5-pro",
        max_raw_events: int = 30,    # この件数を超えたら圧縮を検討
        min_events_to_keep: int = 8, # 直近 N 件は生のまま保持（文脈の鮮度を保つ）
    ):
        self.client = Client()
        self.model = model
        self.max_raw_events = max_raw_events
        self.min_events_to_keep = min_events_to_keep

    async def compress_if_needed(
        self,
        events: list,
        existing_summary: str = "",
    ) -> tuple[str, list]:
        """
        イベントリストを検査し、必要なら古い履歴を要約する。

        Returns:
            (new_summary, remaining_events): 新しい要約テキストと保持するイベントリスト
        """
        if len(events) <= self.max_raw_events:
            return existing_summary, events  # 圧縮不要

        events_to_compress = events[: -self.min_events_to_keep]
        events_to_keep     = events[-self.min_events_to_keep :]

        conversation_text = self._events_to_text(events_to_compress)

        summary_prompt = f"""以下の会話履歴を、AIアシスタントが今後の会話で参照するための
コンパクトな「ユーザープロファイルと会話メモ」として要約してください。

{f"既存の要約（前回までの内容）:\\n{existing_summary}\\n" if existing_summary else ""}

## 今回の会話履歴（{len(events_to_compress)} ターン）
{conversation_text}

## 出力形式
- **ユーザー情報**: 名前・職業・目標など判明している基本情報
- **確認済み事項**: 解決した問題・決定した内容
- **進行中のタスク**: まだ完了していない話題・課題
- **好みとスタイル**: コミュニケーションや技術的な好み
- **重要な技術的詳細**: 参照が必要なコード・設定・決定事項（あれば）

次の会話で役立つ情報だけを箇条書きで簡潔に記述してください。"""

        response = await self.client.aio.models.generate_content(
            model=self.model,
            contents=summary_prompt,
        )

        return response.text, events_to_keep

    def _events_to_text(self, events: list) -> str:
        """イベントリストを可読テキストに変換（dict / Event オブジェクト両対応）"""
        lines = []
        for event in events:
            if isinstance(event, dict):
                role    = event.get("role", "unknown")
                content = event.get("content", {})
                parts   = content.get("parts", []) if isinstance(content, dict) else []
                for part in parts:
                    text = part.get("text", "") if isinstance(part, dict) else ""
                    if text:
                        lines.append(f"[{role}]: {text[:400]}")
            else:
                role = getattr(event, "role", "unknown")
                if hasattr(event, "content") and event.content:
                    for part in event.content.parts:
                        if hasattr(part, "text") and part.text:
                            lines.append(f"[{role}]: {part.text[:400]}")
        return "\n".join(lines)


async def run_with_auto_compression(
    user_id: str, session_id: str, message: str
) -> str:
    """会話圧縮を組み込んだアシスタント実行フロー"""
    session_service = SQLiteSessionService()
    compressor      = ConversationCompressor()
    runner = Runner(
        agent=assistant,
        app_name="my_assistant_app",
        session_service=session_service,
    )

    session = await session_service.get_session(
        app_name="my_assistant_app",
        user_id=user_id,
        session_id=session_id,
    )
    if session is None:
        session = await session_service.create_session(
            app_name="my_assistant_app",
            user_id=user_id,
            session_id=session_id,
        )

    events           = getattr(session, "events", [])
    existing_summary = session.state.get("conversation_summary", "")

    # イベント数が閾値を超えたら圧縮を実行
    if len(events) > compressor.max_raw_events:
        print(f"📦 {len(events)} 件の会話を圧縮中...")
        new_summary, _ = await compressor.compress_if_needed(
            events, existing_summary
        )
        await session_service.update_session_state(
            app_name="my_assistant_app",
            user_id=user_id,
            session_id=session_id,
            state={"conversation_summary": new_summary},
        )
        print("✅ 圧縮完了。要約をセッション状態に保存しました。")

    content = genai_types.Content(
        role="user",
        parts=[genai_types.Part(text=message)]
    )

    async for event in runner.run_async(
        user_id=user_id,
        session_id=session_id,
        new_message=content,
    ):
        if event.is_final_response() and event.content:
            return event.content.parts[0].text

    return ""
```

**この設計のポイントは「完全削除ではなく要約として保持」すること**です。古い会話は捨てるのではなく、Gemini 2.5 Pro 自身に要約させてセッション状態（`state` フィールド）に保存します。次回の会話では、この要約をエージェントの `instruction` に動的に組み込むことで、長期的な文脈を維持しながらトークン消費を大幅に削減できます。

## マルチユーザー設計: 安全な会話分離のパターン

ADK でマルチユーザーのサービスを作る際、`user_id` の設計がシステム全体の安全性を決定します。

### user_id は必ずサーバー側で検証する

クライアントが送信した user_id をそのまま使うのは、なりすまし攻撃の温床になります。

```python
# ❌ 危険な実装: クライアントの申告を信用している
user_id = request.json.get("user_id")

# ✅ 安全な実装: Firebase Auth で検証済みの UID を使う
from firebase_admin import auth as firebase_auth
from fastapi import HTTPException

def get_verified_user_id(id_token: str) -> str:
    try:
        decoded = firebase_auth.verify_id_token(id_token)
        # プレフィックスでアプリ・バージョンを分離
        return f"app_v2_{decoded['uid']}"
    except Exception:
        raise HTTPException(status_code=401, detail="Invalid token")
```

### セッションのライフサイクル管理

ユーザーが増えると、古いセッションがデータベースを圧迫します。定期的なクリーンアップをバックグラウンドタスクとして設定しておくことをお勧めします。

```python
import asyncio
import sqlite3
from datetime import datetime, timedelta

async def cleanup_inactive_sessions(
    db_path: str,
    days_inactive: int = 90  # 90日間更新がなければ削除
) -> int:
    """非アクティブなセッションを自動クリーンアップする。削除件数を返す。"""
    threshold = datetime.now() - timedelta(days=days_inactive)

    with sqlite3.connect(db_path) as conn:
        cursor = conn.execute(
            "SELECT COUNT(*) FROM sessions WHERE updated_at < ?",
            (threshold.isoformat(),)
        )
        count = cursor.fetchone()[0]

        if count > 0:
            # ON DELETE CASCADE により関連 events も自動削除される
            conn.execute(
                "DELETE FROM sessions WHERE updated_at < ?",
                (threshold.isoformat(),)
            )
            conn.commit()

    return count

# 週次クリーンアップのスケジューラ
async def weekly_cleanup_scheduler(db_path: str):
    while True:
        await asyncio.sleep(7 * 24 * 3600)  # 1週間ごとに実行
        deleted = await cleanup_inactive_sessions(db_path)
        if deleted > 0:
            print(f"🗑️ {deleted} 件の非アクティブセッションを削除しました")
```

## よくある落とし穴と解決策

ADK の SessionService を本番に持っていく過程で、多くの開発者がつまずくポイントを整理します。

### 落とし穴1: 複数のワーカープロセスで InMemorySessionService を共有しようとする

`InMemorySessionService` はプロセス内メモリのみを参照します。Gunicorn や uvicorn でワーカーを複数起動する環境では、各ワーカーが独立したメモリ空間を持つため、ワーカー A で作成したセッションがワーカー B には見えません。

ユーザーがリクエストのたびに異なるワーカーに振り分けられると、「毎回初対面」になります。デプロイ直後に「なんかおかしい」と気づきにくい問題です。

**解決策**: 本番では必ずデータベースベースの `SessionService` を使うこと。単一ワーカーに固定する（小規模な場合）か、Redis などの共有メモリも有効な選択肢です。

### 落とし穴2: セッション未作成のまま runner を呼び出す

```python
# ❌ よくあるミス: セッション存在確認なしに run_async を実行
async for event in runner.run_async(
    user_id=user_id,
    session_id="session_that_might_not_exist",  # 存在しない可能性
    new_message=content,
):
    ...  # ADK バージョンによっては例外が出ないケースがある

# ✅ 正しい実装: 取得 → なければ作成 → 実行
session = await session_service.get_session(
    app_name="my_assistant_app",
    user_id=user_id,
    session_id=session_id,
)
if session is None:
    await session_service.create_session(
        app_name="my_assistant_app",
        user_id=user_id,
        session_id=session_id,
    )
# 以降に run_async を実行する
```

ADK のバージョンによっては、存在しないセッションで `run_async` を呼んでも例外が発生せず、会話が保存されないまま実行されます。**セッションの存在確認と作成は常に組み合わせる**ことを習慣にしてください。

### 落とし穴3: Gemini 2.5 Pro の Thinking トークンがセッション履歴を急速に膨らませる

Gemini 2.5 Pro の Thinking モードを有効にすると、思考プロセスがイベントとして生成されることがあります。これを全てセッションに保存すると、思考トークンだけで履歴が数倍に膨らみます。

```python
# ✅ thinking イベントをセッション保存の対象から外す
async for event in runner.run_async(
    user_id=user_id,
    session_id=session_id,
    new_message=content,
):
    # is_thinking フラグがある場合はスキップ
    if getattr(event, "is_thinking", False):
        continue

    if event.is_final_response() and event.content:
        response_text = event.content.parts[0].text
        yield response_text
```

### 落とし穴4: Session.state をエージェントの自動記憶領域だと誤解する

`Session.state` は ADK レベルの状態管理フィールドで、ツール関数内から `context.session.state["key"] = value` で書き込むことはできます。しかし、**エージェントが会話中に「覚えておいて」と言われたことを自動的に `state` に保存する機能はありません**。

長期記憶が必要なら、専用のメモリツールを定義してエージェントに渡す設計が必要です。

```python
from google.adk.tools import FunctionTool

def save_user_info(key: str, value: str) -> str:
    """ユーザーの重要情報をメモリに保存する

    Args:
        key: 保存するキー（例: "preferred_language", "project_name"）
        value: 保存する値
    """
    # 実際はデータベースや外部ストレージに保存する実装を追加
    return f"「{key}」として「{value}」を記憶しました ✅"

memory_enabled_assistant = Agent(
    model="gemini-2.5-pro",
    name="memory_assistant",
    instruction="""ユーザーから重要な情報（名前・職業・プロジェクト詳細・好みなど）を
聞いた場合は、save_user_info ツールを使って記録してください。
記録した情報は次回の会話でも参照し、継続的なサポートに活用してください。""",
    tools=[FunctionTool(save_user_info)],
)
```

### 落とし穴5: session_id を固定値にしてしまう

開発中のデバッグしやすさから `session_id = "test_session"` のような固定値を使うことがありますが、本番環境でユーザーごとに同じ固定値を使うと**全ユーザーの会話が混在**します。

```python
from datetime import datetime

def generate_session_id(user_id: str, purpose: str = "main") -> str:
    """意味があり、かつユニークなセッション ID を生成する"""
    # 月ごとにセッションをリセットしたい場合はこのパターン
    return f"{purpose}_{datetime.now().strftime('%Y%m')}"
    # 例: "main_202604"
    # 完全に新しい会話を始めたい場合は uuid を使う:
    # import uuid; return f"{purpose}_{uuid.uuid4().hex[:8]}"
```

## Gemini 2.5 Pro を ADK で使うときの固有の考慮事項

Gemini 2.5 Pro は高い推論能力を持つ一方、ADK と組み合わせる際にいくつかの固有の設定が重要になります。

**Thinking Budget のタスク別最適化**: タスクの複雑さに応じて Thinking Budget を動的に調整することで、コストと品質のバランスを最適化できます。日常的な質問応答では thinking を無効化し、複雑な設計判断では高いbudgetを設定する使い分けが効果的です。

```python
from google.genai import types as genai_types

def get_thinking_config(task_type: str) -> genai_types.ThinkingConfig:
    """タスク種別に応じた Thinking Budget を返す"""
    configs = {
        "simple_qa":   genai_types.ThinkingConfig(thinking_budget=0),
        "code_review": genai_types.ThinkingConfig(thinking_budget=4096),
        "architecture": genai_types.ThinkingConfig(thinking_budget=16384),
    }
    return configs.get(task_type, configs["simple_qa"])

# Runner 実行時に GenerateContentConfig で渡す
generate_config = genai_types.GenerateContentConfig(
    thinking_config=get_thinking_config("code_review"),
)
```

**100万トークンウィンドウとセッション管理の組み合わせ**: Gemini 2.5 Pro のコンテキストウィンドウは、会話履歴だけでなく、ユーザー固有のドキュメント（仕様書・設計書・過去の成果物）を毎回のコンテキストに含めることで深い文脈理解を実現します。前述の圧縮戦略と組み合わせることで、「会話記憶」と「ドキュメント知識」の両方を長期間維持できます。

## FastAPI との統合でウェブ API として公開する

構築した SessionService + Runner を REST API として公開するには、FastAPI との統合が自然な選択です。

```python
from fastapi import FastAPI, HTTPException, Header
from fastapi.responses import StreamingResponse
from pydantic import BaseModel
from typing import Optional
import json

app = FastAPI(title="Persistent AI Assistant API")
session_service = SQLiteSessionService("./production.db")

class ChatRequest(BaseModel):
    message: str
    session_id: Optional[str] = None

@app.post("/chat/{user_id}")
async def chat(
    user_id: str,
    request: ChatRequest,
    authorization: str = Header(...),
):
    # 認証: 本番では firebase_admin.auth などで検証
    if not authorization.startswith("Bearer "):
        raise HTTPException(status_code=401, detail="Unauthorized")

    session_id = request.session_id or f"main_{user_id}"

    # セッション取得または作成（冪等）
    session = await session_service.get_session(
        app_name="assistant_api",
        user_id=user_id,
        session_id=session_id,
    )
    if session is None:
        await session_service.create_session(
            app_name="assistant_api",
            user_id=user_id,
            session_id=session_id,
        )

    runner = Runner(
        agent=assistant,
        app_name="assistant_api",
        session_service=session_service,
    )

    content = genai_types.Content(
        role="user",
        parts=[genai_types.Part(text=request.message)]
    )

    # Server-Sent Events でストリーミングレスポンスを返す
    async def event_stream():
        async for event in runner.run_async(
            user_id=user_id,
            session_id=session_id,
            new_message=content,
        ):
            if getattr(event, "is_thinking", False):
                continue
            if event.content:
                for part in event.content.parts:
                    if hasattr(part, "text") and part.text:
                        chunk = json.dumps({"text": part.text}, ensure_ascii=False)
                        yield f"data: {chunk}\n\n"
        yield "data: [DONE]\n\n"

    return StreamingResponse(
        event_stream(),
        media_type="text/event-stream"
    )
```

これでフロントエンドから HTTP リクエストを送るだけで、永続的な記憶を持つ AI アシスタントが利用できるようになります。
