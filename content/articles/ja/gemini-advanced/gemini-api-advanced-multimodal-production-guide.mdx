## はじめに：Gemini API の「上級機能」が変えるもの

Gemini API の基本的な使い方（テキスト生成・チャット）を習得した次のステップは、**上級機能を組み合わせてプロダクションレベルのアプリケーションを構築すること**です。

Gemini 2.5 Pro はマルチモーダル処理（テキスト・画像・動画・音声・PDF）、最大 100 万トークンのコンテキストウィンドウ、強力な Function Calling、Google 検索によるリアルタイムグラウンディングを備えており、これらを適切に組み合わせることで、従来は難しかったアプリケーションが実現できます。

## マルチモーダル処理：テキスト以外の入力を扱う

Gemini の最大の強みのひとつが、テキスト・画像・動画・音声・PDFを統合的に処理できる**マルチモーダル能力**です。

### 画像解析の実践

商品画像から情報を抽出する例：

```python
import google.generativeai as genai
from pathlib import Path

genai.configure(api_key="YOUR_GEMINI_API_KEY")
model = genai.GenerativeModel("gemini-2.5-pro")

# 画像ファイルを読み込む
image_path = Path("product.jpg")
image_data = image_path.read_bytes()

response = model.generate_content([
    {
        "mime_type": "image/jpeg",
        "data": image_data,
    },
    "この商品画像から以下の情報をJSON形式で抽出してください：\n"
    "- product_name: 商品名\n"
    "- category: カテゴリ（電化製品/食品/衣料品/その他）\n"
    "- condition: 状態（新品/中古/不明）\n"
    "- estimated_price_jpy: 推定価格（円）\n"
    "- description: 100字以内の説明",
])

print(response.text)
# 期待する出力例:
# {
#   "product_name": "Apple iPhone 15 Pro",
#   "category": "電化製品",
#   "condition": "新品",
#   "estimated_price_jpy": 159800,
#   "description": "チタニウムボディのスマートフォン..."
# }
```

### 動画ファイルの解析

Gemini File API を使うと、大きな動画ファイルを効率的に処理できます。

```python
import time

# 動画をアップロード（File API 経由）
video_file = genai.upload_file(
    path="meeting_recording.mp4",
    mime_type="video/mp4",
    display_name="会議録画 2026-04-04",

    print("処理中...")
    time.sleep(5)
    video_file = genai.get_file(video_file.name)

if video_file.state.name != "ACTIVE":
    raise ValueError(f"File processing failed: {video_file.state.name}")

# 動画を分析
response = model.generate_content([
    video_file,
    """この会議録画を分析して以下を出力してください：
    1. 主な議題（箇条書き）
    2. 決定事項（箇条書き）
    3. アクションアイテム（担当者と期限付き）
    4. 次回会議で継続する議題
    出力形式: JSON"""
])

# 使用後はファイルを削除（ストレージ節約）
genai.delete_file(video_file.name)
```

### マルチモーダルの本番設計のポイント

- **MIME タイプを正確に指定する**: `image/jpeg` と `image/png` など、ファイルタイプを正確に指定しないとエラーになる
- **File API のファイル保存期間に注意**: アップロードしたファイルは 48 時間で自動削除される
- **Base64 vs File API の使い分け**: 小さいファイル（1MB未満）はBase64インライン、大きいファイルはFile APIが効率的

## Function Calling：外部システムとのリアルタイム連携

Function Calling は、Gemini が外部 API・データベース・ツールを呼び出せるようにする機能です。これにより、Gemini がリアルタイムデータにアクセスし、実際にアクションを実行できます。

### Function Calling の基本フロー

```
ユーザー: "東京の今の気温は？"
→ Gemini: get_weather(location="Tokyo") を呼び出すべきと判断
→ アプリ: 実際に天気 API を呼び出す
→ アプリ: API結果をGeminiに返す
→ Gemini: "東京の現在の気温は20°Cです" と自然言語で回答
```

### 実践例：データベース検索エージェント

```python
import google.generativeai as genai
import json

genai.configure(api_key="YOUR_GEMINI_API_KEY")

# 使用可能な関数を定義
tools = [
    genai.protos.Tool(
        function_declarations=[
            genai.protos.FunctionDeclaration(
                name="search_products",
                description="商品データベースを検索する。カテゴリ・価格範囲・キーワードで絞り込み可能。",
                parameters=genai.protos.Schema(
                    type=genai.protos.Type.OBJECT,
                    properties={
                        "keyword": genai.protos.Schema(
                            type=genai.protos.Type.STRING,
                            description="検索キーワード"
                        ),
                        "category": genai.protos.Schema(
                            type=genai.protos.Type.STRING,
                            description="カテゴリ（electronics/clothing/food）"
                        ),
                        "max_price": genai.protos.Schema(
                            type=genai.protos.Type.NUMBER,
                            description="最大価格（円）"
                        ),
                    },
                    required=["keyword"]
                )
            ),
            genai.protos.FunctionDeclaration(
                name="get_product_detail",
                description="商品IDを指定して詳細情報を取得する",
                parameters=genai.protos.Schema(
                    type=genai.protos.Type.OBJECT,
                    properties={
                        "product_id": genai.protos.Schema(
                            type=genai.protos.Type.STRING,
                            description="商品ID"
                        ),
                    },
                    required=["product_id"]
                )
            ),
        ]
    )
]

model = genai.GenerativeModel("gemini-2.5-flash", tools=tools)

def handle_function_call(func_name: str, args: dict) -> dict:
    """実際の関数実行（ここで実際のDBやAPIを呼び出す）"""
    if func_name == "search_products":
        # 実際のDB検索
        return {
            "products": [
                {"id": "P001", "name": "ワイヤレスイヤホン", "price": 8980},
                {"id": "P002", "name": "Bluetoothスピーカー", "price": 4980},
            ],
            "total": 2
        }
    elif func_name == "get_product_detail":
        return {
            "id": args["product_id"],
            "name": "ワイヤレスイヤホン",
            "price": 8980,
            "stock": 15,
            "rating": 4.3,
            "description": "ノイズキャンセリング対応の高音質イヤホン"
        }
    return {"error": "Unknown function"}

def run_agent(user_message: str) -> str:
    """Function Calling ループ"""
    chat = model.start_chat()
    response = chat.send_message(user_message)

    # 関数呼び出しが発生する限りループ
    while response.candidates[0].content.parts[0].function_call.name:
        func_call = response.candidates[0].content.parts[0].function_call
        func_name = func_call.name
        func_args = dict(func_call.args)

        print(f"🔧 関数呼び出し: {func_name}({func_args})")

        # 実際に関数を実行
        result = handle_function_call(func_name, func_args)

        # 結果をGeminiに返す
        response = chat.send_message(
            genai.protos.Content(
                parts=[genai.protos.Part(
                    function_response=genai.protos.FunctionResponse(
                        name=func_name,
                        response={"result": result}
                    )
                )]
            )
        )

    return response.text

# 実行例
result = run_agent("予算1万円以内でワイヤレスイヤホンを探しています")
print(result)
```

### Function Calling の設計パターン

**パラレル Function Calling**: Gemini 2.5 では、複数の関数を同時に呼び出せます。

```python
# Gemini が複数の関数を一度に呼び出す場合の処理
def handle_parallel_function_calls(response):
    results = []
    for part in response.candidates[0].content.parts:
        if part.function_call.name:
            result = handle_function_call(
                part.function_call.name,
                dict(part.function_call.args)
            )
            results.append({
                "name": part.function_call.name,
                "result": result
            })
    return results
```

## 100 万トークンコンテキスト：大規模データを丸ごと処理する

Gemini 2.5 Pro は最大 100 万トークン（約 75 万単語）のコンテキストウィンドウを持ちます。これを活用すると、大規模なコードベース・長い書類・大量のログを一度に処理できます。

### 大規模コードベースの解析

```python
import os
from pathlib import Path

def load_codebase(root_dir: str, extensions: list[str]) -> str:
    """コードベース全体をテキストとして読み込む"""
    files_content = []

    for path in Path(root_dir).rglob("*"):
        if path.suffix in extensions and ".git" not in str(path):
            try:
                content = path.read_text(encoding="utf-8")
                files_content.append(f"=== {path} ===\n{content}\n")
            except Exception:
                pass

    return "\n".join(files_content)

# コードベース全体を読み込む
codebase = load_codebase("./src", [".py", ".ts", ".tsx"])
token_estimate = len(codebase) // 4  # 大まかな推定

print(f"推定トークン数: {token_estimate:,}")

model = genai.GenerativeModel("gemini-2.5-pro")

response = model.generate_content([
    codebase,
    """このコードベースを分析して以下を報告してください：
    1. アーキテクチャの概要（レイヤー構造・主要コンポーネント）
    2. 技術的負債と改善が必要な箇所（優先度付き）
    3. セキュリティ上の懸念点
    4. パフォーマンスの改善余地
    5. テストカバレッジの評価
    各項目を Markdown 形式で詳細に記述してください。"""
])
```

### 長文コンテキストのコスト管理

長いコンテキストはトークンコストが高くなります。以下の戦略でコストを最適化します。

```python
import tiktoken  # OpenAI のトークンカウンター（Geminiの参考値として使用）

def estimate_cost(text: str, model: str = "gemini-2.5-pro") -> dict:
    """コストを推定する（参考値）"""
    # Gemini のトークン数は概算 (1 token ≈ 4文字)
    token_count = len(text) // 4

    # Gemini 2.5 Pro の価格（参考: $1.25/1M tokens for input ≦ 200K tokens）
    # 200K トークンを超えると $2.50/1M tokens
    if token_count <= 200_000:
        cost_usd = (token_count / 1_000_000) * 1.25
    else:
        cost_usd = (token_count / 1_000_000) * 2.50

    return {
        "estimated_tokens": token_count,
        "estimated_cost_usd": round(cost_usd, 4),
        "estimated_cost_jpy": round(cost_usd * 150, 1),
    }

# 送信前にコストを確認
context = load_codebase("./src", [".py"])
cost = estimate_cost(context)
print(f"推定コスト: {cost}")
# → {'estimated_tokens': 50000, 'estimated_cost_usd': 0.0625, 'estimated_cost_jpy': 9.4}
```

## Grounding（グラウンディング）：リアルタイム情報の活用

Grounding with Google Search を使うと、Gemini がリアルタイムの Google 検索結果をもとに回答を生成できます。最新ニュース・株価・天気・製品情報など、学習データに含まれない最新情報が必要な場合に必須の機能です。

```python
from google.ai.generativelanguage_v1beta.types import Tool as GlTool

model = genai.GenerativeModel(
    model_name="gemini-2.5-flash",
    tools=[
        GlTool(
            google_search=genai.protos.GoogleSearch()
        )
    ]
)

response = model.generate_content(
    "2026年4月現在の日本の主要 AI スタートアップのニュースを教えてください"
)

# グラウンディングのソース情報を確認
if response.candidates[0].grounding_metadata:
    print("参照ソース:")
    for chunk in response.candidates[0].grounding_metadata.grounding_chunks:
        print(f"  - {chunk.web.title}: {chunk.web.uri}")

print("\n回答:")
print(response.text)
```

## コスト最適化：本番運用での費用管理

### モデル選択戦略

すべてのリクエストに最高性能モデルを使う必要はありません。タスクの複雑さに応じてモデルを使い分けることが重要です。

```python
def select_model(task_complexity: str, requires_multimodal: bool = False) -> str:
    """タスクに応じた最適モデルを選択"""
    if requires_multimodal and task_complexity == "high":
        return "gemini-2.5-pro"  # 複雑なマルチモーダルタスク
    elif task_complexity == "high":
        return "gemini-2.5-pro"  # 高度な推論・長文処理
    elif task_complexity == "medium":
        return "gemini-2.5-flash"  # バランス型（コスト効率が高い）
    else:
        return "gemini-2.0-flash-lite"  # 単純なテキスト処理・高速
```

### キャッシュの活用（Context Caching）

同じプロンプトやシステム指示を繰り返し使う場合、Context Caching でコストを大幅削減できます。

```python
import google.generativeai as genai
from google.generativeai.caching import CachedContent
from datetime import timedelta

# キャッシュするシステム指示（長いドキュメントなど）
large_system_instruction = """
あなたは〇〇社の製品に関する専門カスタマーサポートエージェントです。
以下は製品マニュアル全文です：
（ここに数万文字のマニュアルが続く）
"""

# キャッシュを作成（TTL: 1時間）
cached_content = CachedContent.create(
    model="gemini-2.5-flash",
    contents=[{"role": "user", "parts": [{"text": large_system_instruction}]}],
    ttl=timedelta(hours=1),
)

# キャッシュされたコンテンツを使ってモデルを初期化
model = genai.GenerativeModel.from_cached_content(cached_content)

# 以降のリクエストではキャッシュされた部分のコストが大幅削減
response = model.generate_content("製品の保証期間はどのくらいですか？")
```

### レート制限の対処

本番環境でのレート制限エラー対策：

```python
import time
import random
from typing import TypeVar, Callable

T = TypeVar("T")

def retry_with_backoff(
    func: Callable[..., T],
    max_retries: int = 5,
    base_delay: float = 1.0,
) -> T:
    """指数バックオフ付きリトライ"""
    for attempt in range(max_retries):
        try:
            return func()
        except Exception as e:
            error_str = str(e)
            if "429" in error_str or "RESOURCE_EXHAUSTED" in error_str:
                if attempt < max_retries - 1:
                    # ジッター付き指数バックオフ
                    delay = base_delay * (2 ** attempt) + random.uniform(0, 1)
                    print(f"レート制限に達しました。{delay:.1f}秒後にリトライ ({attempt + 1}/{max_retries})")
                    time.sleep(delay)
                else:
                    raise
            else:
                raise  # レート制限以外のエラーは即座にリスロー
```

## よくあるエラーと対処法

### エラー 1：INVALID_ARGUMENT（無効なMIMEタイプ）

**症状**: 画像や動画を渡したときに INVALID_ARGUMENT エラーが発生する

**対処法**: MIME タイプが正確か確認します。`image/jpg` は無効で `image/jpeg` が正しい。Gemini がサポートするMIMEタイプは公式ドキュメントを参照のこと。

### エラー 2：SAFETY エラー（安全フィルター）

**症状**: 生成コンテンツが安全フィルターでブロックされる

**対処法**: `response.prompt_feedback` でブロック理由を確認する。プロダクションでは `safety_settings` を必要に応じて調整し、システム指示で「教育目的の回答のみ生成する」などの制約を追加することが有効。

### エラー 3：関数呼び出しループの無限化

**症状**: Function Calling で、Gemini が同じ関数を繰り返し呼び出し続ける

**対処法**: `max_iterations` を設定してループを制限する。また、関数の説明に「この関数は1回の会話で最大3回まで呼び出される」という制約を追加することも有効。

## FAQ

**Q1. Gemini 2.5 Pro と 2.5 Flash の使い分けはどうすればよいですか？**

A. 高度な推論・複雑なコード解析・長文処理（100K トークン超）には Gemini 2.5 Pro を使い、速度とコストのバランスが重要なユースケース（チャット・要約・分類）には Gemini 2.5 Flash をおすすめします。Flash の方が Pro の約 1/5 のコストで動作し、レスポンスも速いです。迷った場合はまず Flash で試し、品質が不十分な場合に Pro に切り替えるのが合理的です。

**Q2. Context Caching は必ず使った方がよいですか？**

A. 同じシステム指示や大きなドキュメントを 10 回以上繰り返し使う場合は、Context Caching でコストを 50〜90% 削減できるため非常に有効です。一方、使用頻度が低い（1〜2回程度）場合はキャッシュ作成コスト自体がかさむため、通常リクエストの方が安くなることがあります。目安として、同じコンテキストを 5 回以上使うなら Caching を検討してください。

**Q3. Function Calling と通常のプロンプトはどちらが適していますか？**

A. リアルタイムデータが必要・外部システムを操作する・構造化データを確実に取得したい場合は Function Calling が適しています。一方、外部システムへのアクセスが不要で、既存の知識の範囲内で処理が完結する場合は通常のプロンプトの方がシンプルです。Function Calling は設計とデバッグのコストが高いため、必要な場合にのみ使うのがベストプラクティスです。

## まとめ

Gemini API の上級機能を本番で活用するためのポイントをまとめます。

- **マルチモーダルは MIME タイプと File API の使い分けが鍵**: 小ファイルはインライン、大ファイルは File API。MIME タイプを正確に指定する
- **Function Calling は外部システムとの橋渡し**: 適切な関数定義・パラレル対応・ループ制限で安全に使う
- **100 万トークンコンテキストはコスト意識が必要**: 送信前にトークン数を推定し、必要なデータのみを渡す設計にする
- **Grounding でリアルタイム情報を統合する**: 最新データが必要なユースケースでは Google 検索グラウンディングが不可欠
- **モデル選択とキャッシュでコストを最適化する**: タスク複雑度に応じたモデル選択と Context Caching で本番コストを大幅削減できる

Gemini API の上級機能を組み合わせることで、単純なテキスト生成を超えた、実用的で価値の高いアプリケーションが構築できます。本記事のコード例を出発点に、自分のプロジェクトに適した活用方法を探ってみてください。
