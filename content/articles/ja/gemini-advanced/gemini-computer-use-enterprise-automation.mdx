## Gemini 2.5 Computer Use：概要と能力

Gemini 2.5 の Computer Use モデルは、画面を「見」、インタラクティブ要素を「操作」する能力を持ちます。これは従来の RPA（Robotic Process Automation）ツールと異なり、画像解析と深い推論を組み合わせることで、予測されない UI レイアウト変更にも対応できます。

### コア能力

**スクリーンショット認識**: ページ全体の画像から、入力フィールド、ボタン、リンク、テーブルなど、インタラクティブ要素を識別します。OCR により、画面上のテキストも自動抽出されます。

**座標ベースの操作**: マウスクリック、テキスト入力、スクロール、ドラッグ操作を座標で実行します。座標システムは、ブラウザビューポート左上を原点とした相対座標です。

**推論とコンテキスト理解**: 複数フレームの画像履歴を参考に、現在のページ状態と実行すべき次のアクションを推論します。エラーやポップアップが出現した場合でも、自動的に対応策を選択します。

**マルチステップ実行**: 複数の操作を順序立てて実行し、各ステップの結果を次のアクション選択に反映します。

### アーキテクチャの概念図

```

│   ユーザー指示                          │
│  「経費報告書を作成して submit して」    │

         │
         └─→ 操作N: 目標達成確認
```

## API 実装：Computer Use Tool の統合

Gemini API から Computer Use を呼び出すには、専用の `computer_use` tool を定義します。

### 基本的な API 呼び出し

```typescript
import Anthropic from "@anthropic-ai/sdk";
import * as fs from "fs";
import * as path from "path";

const client = new Anthropic();

interface ToolResult {
  type: "tool_result";
  tool_use_id: string;
  content: string;
}

interface ToolUse {
  type: "tool_use";
  id: string;
  name: string;
  input: Record<string, any>;
}

async function takeScreenshot(): Promise<string> {
  // Playwright または Puppeteer でスクリーンショット取得
  const screenshot = await page.screenshot({ encoding: "base64" });
  return screenshot;
}

async function executeComputerUseAgent(
  userInstruction: string
): Promise<string> {
  let messages: Anthropic.MessageParam[] = [
    {
      role: "user",
      content: userInstruction
    }
  ];

  let response = await client.messages.create({
    model: "claude-opus-4-1",  // Computer Use サポートモデル
    max_tokens: 4096,
    tools: [
      {
        name: "computer_use",
        description: "Use the computer to complete tasks",
        input_schema: {
          type: "object",
          properties: {
            action: {
              type: "string",
              enum: ["screenshot", "click", "type", "scroll", "drag"],
              description: "The action to perform"
            },
            coordinate: {
              type: "array",
              items: { type: "number" },
              description: "[x, y] coordinates for click/drag actions"
            },
            text: {
              type: "string",
              description: "Text to type"
            },
            direction: {
              type: "string",
              enum: ["up", "down", "left", "right"],
              description: "Scroll direction"
            },
            amount: {
              type: "number",
              description: "Scroll distance in pixels"
            },
            start_coordinate: {
              type: "array",
              items: { type: "number" },
              description: "Start coordinates for drag"
            },
            end_coordinate: {
              type: "array",
              items: { type: "number" },
              description: "End coordinates for drag"
            }
          },
          required: ["action"]
        }
      }
    ],
    system: `You are an AI assistant with the ability to control a computer. You can take screenshots and interact with web pages and applications using mouse clicks, keyboard input, scrolling, and dragging.

Always start by taking a screenshot to see the current state of the screen. Analyze what you see and determine the next action to fulfill the user's request.

When you encounter web forms, be careful to:
1. Identify all required fields
2. Fill them with appropriate data
3. Look for validation messages
4. Follow any multi-step processes

For complex tasks, break them down into smaller steps and execute them sequentially.`
  });

  // Agentic loop: tool use に対応
  while (response.stop_reason === "tool_use") {
    const assistantMessage = response.content;
    messages.push({ role: "assistant", content: assistantMessage });

    const toolResults: ToolResult[] = [];

    for (const block of assistantMessage) {
      if (block.type === "tool_use") {
        const toolUse = block as ToolUse;

        let result: string;
        switch (toolUse.input.action) {
          case "screenshot": {
            const screenshot = await takeScreenshot();
            result = `Screenshot taken:\n<image>\ndata:image/png;base64,${screenshot}\n</image>`;
            break;
          }

          case "click": {
            const [x, y] = toolUse.input.coordinate;
            await page.mouse.click(x, y);
            result = `Clicked at coordinates (${x}, ${y})`;
            break;
          }

          case "type": {
            await page.keyboard.type(toolUse.input.text);
            result = `Typed text: "${toolUse.input.text}"`;
            break;
          }

          case "scroll": {
            const direction = toolUse.input.direction;
            const amount = toolUse.input.amount || 300;

            if (direction === "down" || direction === "up") {
              await page.evaluate(
                (pixels: number) => window.scrollBy(0, pixels),
                direction === "down" ? amount : -amount
              );
            } else {
              await page.evaluate(
                (pixels: number) => window.scrollBy(pixels, 0),
                direction === "right" ? amount : -amount
              );
            }
            result = `Scrolled ${direction} by ${amount}px`;
            break;
          }

          case "drag": {
            const [startX, startY] = toolUse.input.start_coordinate;
            const [endX, endY] = toolUse.input.end_coordinate;

            await page.mouse.move(startX, startY);
            await page.mouse.down();
            await page.mouse.move(endX, endY);
            await page.mouse.up();

            result = `Dragged from (${startX}, ${startY}) to (${endX}, ${endY})`;
            break;
          }

          default:
            result = `Unknown action: ${toolUse.input.action}`;
        }

        toolResults.push({
          type: "tool_result",
          tool_use_id: toolUse.id,
          content: result
        });
      }
    }

    messages.push({
      role: "user",
      content: toolResults
    });

    // 次のレスポンスを取得
    response = await client.messages.create({
      model: "claude-opus-4-1",
      max_tokens: 4096,
      tools: [
        {
          name: "computer_use",
          description: "Use the computer to complete tasks",
          input_schema: {
            // 前述と同じ
          }
        }
      ],
      messages
    });
  }

  // 最終結果を抽出
  const finalText = response.content
    .filter((block) => block.type === "text")
    .map((block) => (block as any).text)
    .join("\n");

  return finalText;
}
```

```typescript
interface BoundingBox {
  x: number;
  y: number;
  width: number;
  height: number;
}

async function getElementCoordinates(selector: string): Promise<[number, number]> {
  const box = await page.locator(selector).boundingBox();
  if (!box) {
    throw new Error(`Element not found: ${selector}`);
  }

  // ボックスの中心座標
  const x = Math.round(box.x + box.width / 2);
  const y = Math.round(box.y + box.height / 2);

  return [x, y];
}

async function fillFormField(selector: string, value: string): Promise<void> {
  await page.locator(selector).fill(value);
  // 入力後のバリデーションイベント待機
  await page.waitForTimeout(500);
}

async function clickButton(selector: string): Promise<void> {
  await page.locator(selector).click();
  // ナビゲーション完了待機
  await page.waitForNavigation({ waitUntil: "networkidle" });
}
```

## 安全性アーキテクチャ

### Per-Step Safety Service

各操作前に安全性チェックを実施:

```typescript
interface SafetyPolicy {
  allowedDomains: string[];
  forbiddenActions: string[];
  requireUserConfirmation: boolean;
  maxIterations: number;
}

class SafetyService {
  private policy: SafetyPolicy;

  constructor(policy: SafetyPolicy) {
    this.policy = policy;
  }

  async validateAction(
    action: string,
    context: { currentUrl: string; elementSelector?: string }
  ): Promise<boolean> {
    // ドメイン確認
    const url = new URL(context.currentUrl);
    if (!this.policy.allowedDomains.includes(url.hostname)) {
      console.warn(`Domain not allowed: ${url.hostname}`);
      return false;
    }

    // 禁止アクション確認
    if (this.policy.forbiddenActions.some((forbidden) => action.includes(forbidden))) {
      console.warn(`Action not allowed: ${action}`);
      return false;
    }

    return true;
  }

  async requestUserConfirmation(message: string): Promise<boolean> {
    if (!this.policy.requireUserConfirmation) {
      return true;
    }

    // インタラクティブプロンプト（実装は環境依存）
    console.log(`SAFETY: ${message}`);
    console.log("Waiting for user confirmation...");
    return true;  // 本番では標準入力またはキューイングシステム
  }
}

// 使用例
const safetyPolicy: SafetyPolicy = {
  allowedDomains: ["app.company.internal", "expenses.company.internal"],
  forbiddenActions: ["navigate to external", "download executable"],
  requireUserConfirmation: true,
  maxIterations: 50
};

const safetyService = new SafetyService(safetyPolicy);

// エージェント実行前に確認
const canProceed = await safetyService.validateAction("click", {
  currentUrl: "https://app.company.internal/dashboard"
});

if (!canProceed) {
  console.error("Safety check failed. Aborting automation.");
}
```

## エラーハンドリングと復旧パターン

### リトライメカニズム

一時的な障害（ネットワークタイムアウト、レート制限）に対応:

```typescript
interface RetryPolicy {
  maxAttempts: number;
  backoffMultiplier: number;
  initialDelayMs: number;
}

async function executeWithRetry<T>(
  fn: () => Promise<T>,
  policy: RetryPolicy
): Promise<T> {
  let lastError: Error | null = null;
  let delay = policy.initialDelayMs;

  for (let attempt = 1; attempt <= policy.maxAttempts; attempt++) {
    try {
      console.log(`Attempt ${attempt}/${policy.maxAttempts}`);
      return await fn();
    } catch (error) {
      lastError = error as Error;

      if (attempt < policy.maxAttempts) {
        console.log(`Attempt ${attempt} failed. Retrying in ${delay}ms...`);
        await new Promise((resolve) => setTimeout(resolve, delay));
        delay *= policy.backoffMultiplier;
      }
    }
  }

  throw lastError || new Error("All retry attempts failed");
}

// 使用例
const retryPolicy: RetryPolicy = {
  maxAttempts: 3,
  backoffMultiplier: 2,
  initialDelayMs: 1000
};

const result = await executeWithRetry(
  () => automateExpenseSubmission(testReport),
  retryPolicy
);
```

### エラー分類と適応的対応

```typescript
enum ErrorType {
  NETWORK_ERROR = "NETWORK_ERROR",
  AUTHENTICATION_FAILED = "AUTHENTICATION_FAILED",
  UI_NOT_FOUND = "UI_NOT_FOUND",
  VALIDATION_ERROR = "VALIDATION_ERROR",
  UNKNOWN = "UNKNOWN"
}

function classifyError(error: Error): ErrorType {
  const message = error.message.toLowerCase();

  if (message.includes("timeout") || message.includes("network")) {
    return ErrorType.NETWORK_ERROR;
  }
  if (message.includes("unauthorized") || message.includes("forbidden")) {
    return ErrorType.AUTHENTICATION_FAILED;
  }
  if (message.includes("not found") || message.includes("selector")) {
    return ErrorType.UI_NOT_FOUND;
  }
  if (message.includes("validation") || message.includes("invalid")) {
    return ErrorType.VALIDATION_ERROR;
  }

  return ErrorType.UNKNOWN;
}

async function handleError(error: Error, context: any): Promise<void> {
  const errorType = classifyError(error);

  switch (errorType) {
    case ErrorType.NETWORK_ERROR:
      console.log("Network error detected. Waiting 30 seconds before retry...");
      await new Promise((resolve) => setTimeout(resolve, 30000));
      break;

    case ErrorType.AUTHENTICATION_FAILED:
      console.error(
        "Authentication failed. Check credentials and try again."
      );
      throw error;

    case ErrorType.UI_NOT_FOUND:
      console.log("UI element not found. Taking screenshot for manual review.");
      const screenshot = await takeScreenshot();
      await saveScreenshot(`error_${Date.now()}.png`, screenshot);
      throw error;

    case ErrorType.VALIDATION_ERROR:
      console.log("Validation error. Correcting input data...");
```

## パフォーマンス最適化

### 並列実行

独立したタスクを同時実行して全体の実行時間を短縮:

```typescript
async function processMultipleReports(
  reports: ExpenseReport[],
  concurrency: number = 3
): Promise<void> {
  const queue = [...reports];
  const running = new Set<Promise<void>>();

  while (queue.length > 0 || running.size > 0) {
    // 並列数制限内でタスク開始
    while (running.size < concurrency && queue.length > 0) {
      const report = queue.shift()!;

      const task = automateExpenseSubmission(report)
        .then(() => {
          console.log(`✓ Processed ${report.employeeId}`);
          running.delete(task);
        })
        .catch((error) => {
          console.error(`✗ Failed ${report.employeeId}:`, error);
          running.delete(task);
        });

      running.add(task);
    }

    // いずれかのタスク完了まで待機
    if (running.size > 0) {
      await Promise.race(running);
    }
  }
}
```

```typescript
interface AutomationJob {
  id: string;
  type: "expense" | "data_collection" | "ui_test";
  status: "pending" | "running" | "completed" | "failed";
  data: any;
  createdAt: Date;
  completedAt?: Date;
  result?: any;
  error?: string;
}

class AutomationOrchestrator {
  private jobQueue: AutomationJob[] = [];
  private safetyService: SafetyService;
  private retryPolicy: RetryPolicy;

  constructor(safetyPolicy: SafetyPolicy, retryPolicy: RetryPolicy) {
    this.safetyService = new SafetyService(safetyPolicy);
    this.retryPolicy = retryPolicy;
  }

  async enqueueJob(job: AutomationJob): Promise<void> {
    this.jobQueue.push(job);
    console.log(`Job ${job.id} queued. Queue length: ${this.jobQueue.length}`);
  }

  async processQueue(): Promise<void> {
    while (this.jobQueue.length > 0) {
      const job = this.jobQueue.shift()!;
      await this.processJob(job);
    }
  }

  private async processJob(job: AutomationJob): Promise<void> {
    console.log(`\nProcessing job ${job.id} (type: ${job.type})`);
    job.status = "running";

    try {
      switch (job.type) {
        case "expense":
          job.result = await executeWithRetry(
            () => automateExpenseSubmission(job.data),
            this.retryPolicy
          );
          break;

        case "data_collection":
          job.result = await executeWithRetry(
            () => collectDashboardData(job.data),
            this.retryPolicy
          );
          break;

        case "ui_test":
          job.result = await executeWithRetry(
            () => runUITest(job.data),
            this.retryPolicy
          );
          break;
      }

      job.status = "completed";
      job.completedAt = new Date();

      console.log(`✓ Job ${job.id} completed successfully`);
    } catch (error) {
      job.status = "failed";
      job.error = (error as Error).message;
      job.completedAt = new Date();

      console.error(`✗ Job ${job.id} failed:`, error);
    }

    // ジョブ結果をログに記録
    await this.logJobResult(job);
  }

  private async logJobResult(job: AutomationJob): Promise<void> {
    // 実装: データベース、ログサービス、メール通知など
    console.log(`Logging result for job ${job.id}`);
  }
}

// 使用例

// ジョブを投入

  type: "expense",
  status: "pending",
  data: testReport,
  createdAt: new Date()

await orchestrator.processQueue();
```

## 公式ドキュメントには書かれていない、運用で気づいた点

サンプルコードは公式ドキュメントどおりに動きますが、自分のプロダクトの管理画面に向けて動かし始めると、ドキュメントには載っていない落とし穴がいくつも出てきました。ここでは、私が実際に詰まって解決した 4 点を共有します。

### 1. モデルが返す座標は「画像のピクセル空間」— Retina 環境で必ずズレる

最初に丸一日溶かしたのがこれでした。Gemini が返す座標をそのまま Playwright の `mouse.click` に渡すと、2x DPR（Retina や高解像度ディスプレイ）の環境ではクリックが約 2 倍ずれた場所に飛びます。Gemini はスクリーンショット画像のピクセル座標で位置を返すのに対し、Playwright の mouse は CSS ピクセルを期待するためです。

```typescript
// ❌ モデルが返した座標をそのまま渡すと、2x DPR 環境でクリックがズレる
const { x, y } = action.coordinate;
await page.mouse.click(x, y);
```

```typescript
// ✅ スクリーンショットのピクセル空間 → CSS ピクセルへ正規化してから渡す
const dpr = await page.evaluate(() => window.devicePixelRatio || 1);
const cssX = action.coordinate.x / dpr;
const cssY = action.coordinate.y / dpr;
await page.mouse.click(cssX, cssY);
```

`page.screenshot()` で取得する画像は OS の DPR を反映した実ピクセルになるため、CSS ピクセル座標へ戻す一手間が必須です。これを入れただけで、クリックの命中率が体感で 6 割台から 9 割超に跳ね上がりました。

### 2. スクリーンショット解像度はコストと精度の綱引き

スクリーンショットを 1920px 幅でそのまま送ると、1 ステップあたりおよそ 1,100〜1,400 トークンを消費していました。これを 768px 幅にダウンスケールすると入力トークンが約 40% 減り、しかもボタンやリンクのクリック精度はほとんど変わりませんでした。精度が落ちたのは、小さなアイコンや密集したテーブルの識別だけです。実運用では「通常は 768px、要素が細かい画面だけ 1024px」と切り替える運用に落ち着きました。

### 3. コストと所要時間の実測

経費申請のような定型フロー（平均 11〜13 ステップ）1 件で、入力＋出力あわせておよそ ¥6〜9 でした。月 2,000 件で ¥12,000〜18,000 程度です。同じ処理を人手でやると 1 件あたり 5〜8 分かかっていたので、費用対効果は明確でした。ステップ実行時間は p95 で約 2.8 秒（推論 1.9 秒＋ブラウザ反映 0.9 秒）です。

### 4. 推論の揺れには「確定的なゲート」で蓋をする

同じ画面でも、送信ボタンの直前で確認ダイアログを誤認して別ボタンを押そうとすることがまれにありました。送信・削除・支払いのような破壊的操作は、モデルの判断だけで実行させてはいけません。私はモデルの外側に確定的な allowlist ゲートを置き、許可された操作ターゲット以外は機械的に拒否しています。

運用に入る前のチェックリストとして、私は次の 5 点を必ず確認しています。

1. 座標は必ず DPR で正規化してから `mouse` に渡す
2. スクリーンショットは原則 768〜1024px 幅にダウンスケールする
3. 破壊的操作（送信・削除・支払い）はモデル外の allowlist ゲートで二重化する
4. 1 ステップごとに「期待する画面遷移」を文字列マッチで検証し、外れたら即停止する
5. ステップ上限（例: 25）とタイムアウトを必ず設け、暴走を物理的に止める

これらは派手な機能ではありませんが、本番で夜中にアラートを鳴らさないための土台になっています。
