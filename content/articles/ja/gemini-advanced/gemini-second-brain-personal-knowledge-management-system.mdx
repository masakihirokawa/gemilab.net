## はじめに：情報過多時代に「第二の脳」が必要な理由

毎日大量のウェブ記事、技術ドキュメント、ミーティングメモ、アイデアメモが積み重なっていく。数ヶ月後に「あのときメモした内容がどこかにあったはず」と思い出せずに同じ調査を繰り返す――。そんな経験に心当たりはないでしょうか。

「セカンドブレイン（第二の脳）」という概念は、Tiago Forte が提唱した個人知識管理（Personal Knowledge Management / PKM）の手法です。デジタルノートシステムを「外部の記憶装置」として設計し、情報を取り込み・整理し・活用するサイクルを確立します。[Building a Second Brain（Tiago Forte 著）](https://www.amazon.co.jp/dp/B09MDNDYYF/?tag=pinocchio-22)は、この概念をシステムとして実装するための優れた入門書です。

### この記事で構築するシステムの全体像

今回実装するシステムは以下の4つのコアコンポーネントから構成されます。

- **インジェスタ（Ingestor）**: Obsidian や Markdown ファイルからノートを取り込み、Gemini API でサマリーと埋め込みベクトルを生成する
- **セマンティック検索エンジン**: ChromaDB にベクトルを保存し、自然言語クエリで関連ノートを高精度に検索する
- **ナレッジグラフビルダー**: Gemini API で自動タグ付け・エンティティ抽出・関連ノートリンクを生成し、知識グラフを構築する
- **スペース反復スケジューラ（SRS）**: 記憶定着を最適化するため、Gemini API がノートの復習タイミングを動的に判定する

### 技術スタック

今回のセカンドブレインシステムは以下の技術を組み合わせて構築します。

- **Gemini API**: `text-embedding-004` モデルで埋め込みベクトル生成、`gemini-2.5-flash` でテキスト処理・タグ付け
- **ChromaDB**: ベクトルデータベース（ローカル）または Chroma Cloud（本番環境）
- **Python 3.12**: メインの実装言語
- **FastAPI**: REST API サーバー（Obsidian plugin との連携用）
- **SQLite**: メタデータ・SRS スケジュール管理用

### データフローの全体設計

```
[ノートファイル]
    → [インジェスタ] → [Gemini Embedding API]
                     → [ChromaDB (ベクトルDB)]
                     → [Gemini Flash (タグ・サマリー生成)]
                     → [SQLite (メタデータ)]

[検索クエリ]
    → [Gemini Embedding API] → [ChromaDB 類似検索]
    → [上位N件のノート返却]

[Obsidian Plugin]
    → [FastAPI サーバー] → [セマンティック検索]
                         → [関連ノートリンク挿入]
                         → [SRS スケジュール取得]
```

## コアモジュールの実装

### 1. Gemini クライアントの初期化

```python
# gemini_client.py
import google.generativeai as genai
from config import GEMINI_API_KEY, EMBEDDING_MODEL, GENERATION_MODEL

genai.configure(api_key=GEMINI_API_KEY)

def get_embedding(text: str) -> list[float]:
    """テキストの埋め込みベクトルを取得する"""
    result = genai.embed_content(
        model=EMBEDDING_MODEL,
        content=text,
        task_type="retrieval_document",  # ドキュメント検索用に最適化
    )
    return result["embedding"]

def get_query_embedding(query: str) -> list[float]:
    """検索クエリの埋め込みベクトルを取得する"""
    result = genai.embed_content(
        model=EMBEDDING_MODEL,
        content=query,
        task_type="retrieval_query",  # クエリ用（ドキュメントより精度向上）
    )
    return result["embedding"]

def generate_summary(content: str, max_words: int = 150) -> str:
    """ノートのAIサマリーを生成する"""
    model = genai.GenerativeModel(GENERATION_MODEL)
    prompt = f"""以下のノートを{max_words}文字以内で要約してください。
重要な概念・キーワード・アクションアイテムを含めて簡潔にまとめてください。

--- ノート ---
{content[:3000]}  # 長いノートは先頭3000文字を使用
--- 終了 ---

要約："""
    response = model.generate_content(prompt)
    return response.text.strip()

def extract_tags_and_entities(content: str) -> dict:
    """ノートからタグとエンティティを自動抽出する"""
    model = genai.GenerativeModel(GENERATION_MODEL)
    prompt = f"""以下のノートからメタデータを JSON 形式で抽出してください。

--- ノート ---
{content[:2000]}
--- 終了 ---

以下の JSON 形式で返してください（他の文字は含めないこと）：
{{
  "tags": ["タグ1", "タグ2", "タグ3"],
  "entities": {{
    "technologies": ["技術名1", "技術名2"],
    "people": ["人名1"],
    "concepts": ["概念1", "概念2"]
  }},
  "category": "技術/ビジネス/アイデア/学習/その他",
  "importance": 1〜5の整数（5が最重要）
}}"""

    import json, re
    response = model.generate_content(prompt)
    json_text = re.search(r'\{.*\}', response.text, re.DOTALL)
    if json_text:
        return json.loads(json_text.group())
    return {"tags": [], "entities": {}, "category": "その他", "importance": 3}
```

### 2. ノートインジェスタの実装

```python
# ingestor.py
import frontmatter
from pathlib import Path
from datetime import datetime
from gemini_client import get_embedding, generate_summary, extract_tags_and_entities
from database import save_note_metadata
from vector_store import add_to_chroma

def ingest_note(file_path: Path) -> dict:
    """Markdown ノートを取り込み、ベクトル化・メタデータ抽出を行う"""

    # フロントマターとコンテンツを解析
    with open(file_path, "r", encoding="utf-8") as f:
        post = frontmatter.load(f)

    content = str(post.content)
    existing_metadata = dict(post.metadata)

    print(f"📝 取り込み中: {file_path.name}")

    # AIサマリーを生成
    summary = generate_summary(content)

    # タグとエンティティを抽出
    extracted = extract_tags_and_entities(content)

    # 全文の埋め込みベクトルを生成（タイトル + サマリー + 本文先頭部分）
    embed_text = f"{existing_metadata.get('title', file_path.stem)}\n{summary}\n{content[:1500]}"
    embedding = get_embedding(embed_text)

    # ノートIDを生成（ファイルパスのハッシュ）
    import hashlib
    note_id = hashlib.md5(str(file_path).encode()).hexdigest()

    note_data = {
        "id": note_id,
        "file_path": str(file_path),
        "title": existing_metadata.get("title", file_path.stem),
        "content": content,
        "summary": summary,
        "tags": extracted.get("tags", []),
        "entities": extracted.get("entities", {}),
        "category": extracted.get("category", "その他"),
        "importance": extracted.get("importance", 3),
        "embedding": embedding,
        "created_at": datetime.fromtimestamp(file_path.stat().st_ctime),
        "updated_at": datetime.fromtimestamp(file_path.stat().st_mtime),
    }

    # ChromaDB に保存
    add_to_chroma(note_data)

    # SQLite にメタデータを保存
    save_note_metadata(note_data)

    print(f"  ✅ 完了: tags={extracted.get('tags', [])[:3]}")
    return note_data

def ingest_directory(notes_dir: Path, force_update: bool = False) -> int:
    """ディレクトリ内の全 Markdown ファイルを取り込む"""
    mdx_files = list(notes_dir.glob("**/*.md")) + list(notes_dir.glob("**/*.mdx"))

    count = 0
    for file_path in mdx_files:
        try:
            ingest_note(file_path)
            count += 1
        except Exception as e:
            print(f"  ❌ エラー ({file_path.name}): {e}")

    print(f"\n📊 取り込み完了: {count}/{len(mdx_files)} 件")
    return count
```

### 3. ChromaDB ベクトルストアの実装

```python
# vector_store.py
import chromadb
from config import CHROMA_DIR

# ChromaDB クライアントを初期化（永続化モード）
chroma_client = chromadb.PersistentClient(path=str(CHROMA_DIR))
collection = chroma_client.get_or_create_collection(
    name="notes",
    metadata={"hnsw:space": "cosine"}  # コサイン類似度を使用
)

def add_to_chroma(note_data: dict):
    """ノートをChromaDBに追加・更新する"""
    # 既存エントリを削除してから追加（upsert）
    try:
        collection.delete(ids=[note_data["id"]])
    except Exception:
        pass

    collection.add(
        ids=[note_data["id"]],
        embeddings=[note_data["embedding"]],
        documents=[note_data["summary"]],  # 表示用テキスト
        metadatas=[{
            "title": note_data["title"],
            "file_path": note_data["file_path"],
            "category": note_data["category"],
            "importance": note_data["importance"],
            "tags": ",".join(note_data["tags"]),
        }]
    )

def semantic_search(query_embedding: list[float], n_results: int = 5,
                    category_filter: str = None) -> list[dict]:
    """セマンティック検索を実行する"""
    where_clause = {"category": category_filter} if category_filter else None

    results = collection.query(
        query_embeddings=[query_embedding],
        n_results=n_results,
        where=where_clause,
        include=["documents", "metadatas", "distances"]
    )

    # 結果を整形して返す
    formatted = []
    for i, (doc, meta, dist) in enumerate(zip(
        results["documents"][0],
        results["metadatas"][0],
        results["distances"][0]
    )):
        formatted.append({
            "rank": i + 1,
            "title": meta["title"],
            "file_path": meta["file_path"],
            "summary": doc,
            "category": meta["category"],
            "tags": meta["tags"].split(",") if meta["tags"] else [],
            "similarity_score": 1 - dist,  # コサイン距離を類似度に変換
        })

    return formatted
```

## 自動タグ付けと関連ノートの知識グラフ構築

### 関連ノートの自動リンク生成

セカンドブレインの真価は、ノート間のつながりを自動で発見する点にあります。Gemini API を使って、新しいノートと既存ノートの類似度を計算し、関連ノートを自動的にリンクします。

```python
# knowledge_graph.py
from vector_store import semantic_search
from gemini_client import get_query_embedding, get_embedding
from database import get_all_notes, update_note_links

def build_note_links(note_data: dict, threshold: float = 0.75, max_links: int = 5):
    """新しいノートと関連する既存ノートを自動でリンクする"""

    # ノートのタイトル+サマリーで検索
    search_text = f"{note_data['title']} {note_data['summary']}"
    query_emb = get_query_embedding(search_text)

    # 類似ノートを検索（自身は除く）
    candidates = semantic_search(query_embedding=query_emb, n_results=max_links + 1)
    related = [
        c for c in candidates
        if c["file_path"] != note_data["file_path"]
        and c["similarity_score"] >= threshold
    ][:max_links]

    # リンク情報をDBに保存
    update_note_links(note_data["id"], related)

    # Obsidian 形式の WikiLink を生成
    wikilinks = [f"[[{r['title']}]]" for r in related]
    return {"related_notes": related, "wikilinks": wikilinks}

def generate_related_section(note_data: dict) -> str:
    """関連ノートセクションのMarkdownを生成する"""
    links = build_note_links(note_data)
    if not links["wikilinks"]:
        return ""

    lines = ["", "## 関連ノート", ""]
    for note in links["related_notes"]:
        score_pct = int(note["similarity_score"] * 100)
        lines.append(f"- [[{note['title']}]] （関連度: {score_pct}%）")

    return "\n".join(lines)
```

## Obsidianとのリアルタイム連携

Obsidian は Markdown ベースのノートアプリで、大量のプラグインエコシステムを持ちます。FastAPI サーバーを立て、Obsidian の Community Plugin から REST API を呼ぶことで、今回構築したシステムを Obsidian から直接利用できます。

### Obsidian 連携フロー

1. Obsidian で新しいノートを保存する
2. ファイル変更を Python の `watchdog` ライブラリが検知する
3. 自動的にインジェスタが起動し、Gemini API でベクトル化・タグ付けを実行
4. 関連ノートのリンクが自動生成され、ノートに追記される

```python
# obsidian_watcher.py
from watchdog.observers import Observer
from watchdog.events import FileSystemEventHandler
from pathlib import Path
from ingestor import ingest_note
from knowledge_graph import generate_related_section
import time

class NoteChangeHandler(FileSystemEventHandler):
    def __init__(self, notes_dir: Path):
        self.notes_dir = notes_dir
        self._processing = set()  # 処理中のファイルを追跡（二重処理防止）

    def on_modified(self, event):
        if event.is_directory:
            return

        file_path = Path(event.src_path)
        if file_path.suffix not in [".md", ".mdx"]:
            return
        if str(file_path) in self._processing:
            return

        self._processing.add(str(file_path))
        try:
            print(f"\n🔄 変更検知: {file_path.name}")
            time.sleep(0.5)  # ファイル書き込み完了を待機

            # ノートを取り込みベクトル化
            note_data = ingest_note(file_path)

            # 関連ノートセクションを生成・追記
            related_section = generate_related_section(note_data)
            if related_section:
                with open(file_path, "a", encoding="utf-8") as f:
                    f.write(related_section)
                print(f"  🔗 関連ノートリンクを追記しました")
        finally:
            self._processing.discard(str(file_path))

def start_watching(notes_dir: Path):
    """Obsidian Vault の監視を開始する"""
    handler = NoteChangeHandler(notes_dir)
    observer = Observer()
    observer.schedule(handler, str(notes_dir), recursive=True)
    observer.start()
    print(f"👁️ 監視開始: {notes_dir}")
    print("Ctrl+C で停止")
    try:
        while True:
            time.sleep(1)
    except KeyboardInterrupt:
        observer.stop()
    observer.join()
```

## スペース反復学習（SRS）システムの実装

スペース反復学習（Spaced Repetition System）は、記憶定着を最大化するために、記憶が薄れる直前に復習するタイミングを計算する手法です。Gemini API を使って、ノートの難易度と重要度に基づいた動的なスケジューリングを実装します。

```python
# srs.py
from datetime import datetime, timedelta
from database import get_notes_due_for_review, update_review_result
from gemini_client import get_embedding
import google.generativeai as genai
from config import SRS_INTERVALS_DAYS, SRS_MAX_DAILY_REVIEWS, GENERATION_MODEL

def get_today_reviews() -> list[dict]:
    """今日復習すべきノートを取得する（最大N件）"""
    due_notes = get_notes_due_for_review(limit=SRS_MAX_DAILY_REVIEWS)
    return due_notes

def generate_review_quiz(note_content: str, difficulty: str = "medium") -> dict:
    """ノートから復習クイズを自動生成する"""
    model = genai.GenerativeModel(GENERATION_MODEL)

    difficulty_prompt = {
        "easy": "簡単な確認問題（1問）",
        "medium": "理解確認の問題（2問）",
        "hard": "応用・深掘り問題（3問）",
    }.get(difficulty, "理解確認の問題（2問）")

    prompt = f"""以下のノートから{difficulty_prompt}を生成してください。

--- ノート ---
{note_content[:1500]}
--- 終了 ---

以下の JSON 形式で返してください：
{{
  "questions": [
    {{
      "question": "問題文",
      "answer": "模範回答"
    }}
  ]
}}"""

    import json, re
    response = model.generate_content(prompt)
    json_match = re.search(r'\{.*\}', response.text, re.DOTALL)
    if json_match:
        return json.loads(json_match.group())
    return {"questions": []}

def update_schedule(note_id: str, recall_quality: int):
    """復習結果に基づいて次回スケジュールを更新する（0〜5: 0=完全に忘れた, 5=完璧）"""

    # SM-2 アルゴリズムに基づく間隔計算
    if recall_quality >= 4:
        interval_index = min(5, get_current_interval_index(note_id) + 1)
    elif recall_quality >= 2:
        interval_index = get_current_interval_index(note_id)
    else:
        interval_index = 0  # リセット

    next_review = datetime.now() + timedelta(days=SRS_INTERVALS_DAYS[interval_index])
    update_review_result(note_id, interval_index, next_review, recall_quality)

    print(f"⏰ 次回復習: {next_review.strftime('%Y/%m/%d')} "
          f"（{SRS_INTERVALS_DAYS[interval_index]}日後）")
```

## 本番運用・スケーリング戦略

### バッチ処理による定期更新

大量のノートを定期的に再インデックスするために、非同期バッチ処理を実装します。

```python
# scheduler.py
import asyncio
from pathlib import Path
from config import NOTES_DIR
from ingestor import ingest_directory
from srs import get_today_reviews

async def daily_maintenance():
    """毎朝実行するメンテナンス処理"""
    print("🌅 デイリーメンテナンス開始")

    # 1. 最近更新されたノートのみ再インデックス
    recently_updated = [
        p for p in NOTES_DIR.glob("**/*.md")
        if (Path(p).stat().st_mtime > (datetime.now() - timedelta(days=1)).timestamp())
    ]
    print(f"  📝 更新ノート: {len(recently_updated)} 件")
    for note_path in recently_updated:
        ingest_note(note_path)

    # 2. 今日の復習リストを生成
    reviews = get_today_reviews()
    print(f"  📚 今日の復習: {len(reviews)} 件")

    print("✅ デイリーメンテナンス完了")

if __name__ == "__main__":
    asyncio.run(daily_maintenance())
```

### パフォーマンス最適化のポイント

- **埋め込みバッチ処理**: `genai.embed_content` はバッチ対応しているため、100件ずつまとめてリクエストするとAPIコストと時間を大幅削減できます
- **キャッシュ戦略**: 同一コンテンツの埋め込みはハッシュキーでキャッシュし、不要なAPI呼び出しを防ぎます
- **インクリメンタル更新**: ファイルのMtime（更新日時）を比較し、変更があったノートのみ再インデックスします
- **モデル選択**: 埋め込み生成は `text-embedding-004`、テキスト生成は `gemini-2.5-flash` を使い、コストを最適化します

Gemini API の埋め込みと検索の詳細については、[Gemini Embeddings によるセマンティック検索の本番実装](/articles/gemini-api/gemini-embeddings-semantic-search-production)もあわせてご参照ください。また、pgVector を使った構成に興味がある方は[Gemini API × pgVector セマンティック検索エンジン構築ガイド](/articles/gemini-api/gemini-api-pgvector-semantic-search-engine)も参考になります。

## よくある質問（FAQ）

**Q. ChromaDB とPinecone・pgVector の違いは何ですか？**

A. ChromaDB は設定不要でローカル環境からすぐ使えるため、個人プロジェクトや開発環境に最適です。Pinecone はマネージドサービスで本番スケールに強く、pgVector は既存の PostgreSQL 環境に組み込みやすいという特徴があります。本記事のセカンドブレインシステムはまず ChromaDB で構築し、スケールアウトが必要になったら Pinecone や Chroma Cloud へ移行するアプローチを推奨します。

**Q. Obsidian 以外のノートアプリ（Notion・Logseq・Roam Research）でも使えますか？**

A. はい、使えます。インジェスタ部分は Markdown ファイルを読み込む設計になっているため、Logseq（Markdown モード）であれば同じコードが使えます。Notion については公式の Notion API からページを取得し、Markdown に変換してから取り込むアダプターを実装することで対応可能です。`notion-client` と `markdownify` ライブラリを組み合わせると効率的です。

**Q. API コストはどれくらいかかりますか？**

A. `text-embedding-004` の料金は 100 万トークンあたり約 $0.02（2026年4月現在）です。1,000 件のノートを初回インデックスする場合、平均ノート長を 500 単語（約 750 トークン）と仮定すると、約 75 万トークンで約 $0.015（約 2 円）になります。日次更新（変更ノートのみ）はさらに低コストです。テキスト生成（タグ付け・サマリー）は `gemini-2.5-flash` を使えば 1 件あたり数十円以下に抑えられます。

**Q. スペース反復学習は必ず使わないといけませんか？**

A. SRS は完全にオプションです。セマンティック検索と自動タグ付けだけでも十分に実用的なセカンドブレインとして機能します。SRS は「意図的に知識を定着させたい」（資格勉強・言語学習・技術習得など）というユースケースで特に効果を発揮します。

**Q. プライバシー面での注意点はありますか？**

A. ノートの内容は Gemini API を通じて Google のサーバーに送信されます。機密情報や個人情報が含まれるノートは、ローカルで動作するオープンソースの埋め込みモデル（例: `sentence-transformers` の `multilingual-e5-large`）を代替として使うことを検討してください。企業環境では Vertex AI（VPC Service Controls 対応）の利用を推奨します。

## まとめ

本記事では、Gemini API を活用したAI駆動のセカンドブレインシステムを段階的に構築しましました。

- **インジェスタ**: Obsidian/Markdown ノートを自動取り込み、Gemini Embeddings でベクトル化
- **セマンティック検索**: ChromaDB + FastAPI で自然言語検索 API を実装
- **ナレッジグラフ**: 自動タグ付け・エンティティ抽出・関連ノートリンク生成
- **Obsidian 連携**: `watchdog` による変更検知とリアルタイム自動処理
- **SRS**: SM-2 アルゴリズム × Gemini API によるインテリジェントな復習スケジューリング
- **本番スケーリング**: Chroma Cloud 移行・バッチ処理・API コスト最適化

このシステムを日常の知識管理に組み込むことで、蓄積したノートが「眠った資産」から「即座にアクセスできる知識基盤」に変わります。Gemini の長大なコンテキストウィンドウを活用したアーキテクチャ設計については、[Gemini 長コンテキスト活用戦略](/articles/gemini-api/gemini-long-context-strategies)も参考にしてください。

個人知識管理の方法論をさらに体系的に学びたい方には、[Building a Second Brain（Tiago Forte 著）](https://www.amazon.co.jp/dp/B09MDNDYYF/?tag=pinocchio-22)がおすすめです。デジタルノートの設計思想をより深く理解することで、今回構築したシステムをより効果的に活用できるようになります。
