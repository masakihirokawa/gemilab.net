「AIがコンピュータを操作する」というデモ映像を見ると、すごいと思いつつも「実際の業務でどれくらい使えるのか」という点で半信半疑になることが多いと思います。Gemini の Computer Use 機能について、実際に3つのシナリオで試した結果を共有します。成功した部分も、うまくいかなかった部分も含めて書きます。

Gemini API を実プロダクトで運用してきた知見から、この問題に普段から向き合ってきた立場で、要点を整理します。

## Gemini Computer Use が他のAIの画面操作と違う点

Computer Use 系の機能は、現在いくつかのAIプロバイダーが提供していますが、Gemini のアプローチにはいくつかの特徴があります。

最も大きな違いは**マルチモーダルな画面理解**です。Gemini は Google の Vision モデルをベースにしているため、スクリーンショットから UI 要素を認識する精度が高く、特にテキストが小さい箇所や、アイコンベースのインターフェースの解釈が得意です。試したところ、解像度の低いスクリーンショットでも文字を正しく読み取ることができました。

もう一つの特徴は **Google サービスとの親和性**です。Google Workspace（Docs、Sheets、Calendar 等）の操作において、UIの意味をより深く理解しているように見えます。これは学習データの違いによるものと思われます。

ただし、これらの特徴は万能ではありません。以下に示す実検証が示す通り、得意不得意がはっきりしています。

## 実際に試した3つのシナリオ

### シナリオ1：Webからのデータ収集とスプレッドシートへの記録

**タスク内容**: 複数のECサイトから商品の価格・在庫情報を収集し、Google Sheetsに記録する。

**結果**: ほぼ成功でしたが、条件があります。

単一のECサイトを繰り返し操作するタスクでは非常に安定していました。ページの構造を一度学習すると、その後の操作がスムーズになりました。Google Sheetsへの入力も、セルの指定・値の入力・保存がほぼ確実にできました。

問題が出たのはサイトによって UI が大きく異なる場合です。「在庫あり」という表示の仕方がサイトによって異なり（「残りわずか」「在庫○点」「入荷未定」など）、これを統一的に判断することが難しいケースがありました。

**所要時間と精度**: 10サイト・各3商品の収集で約8分（手動なら約20分）。誤記録は2件ありました。

### シナリオ2：PDF文書のデータ抽出とメール下書き作成

**タスク内容**: 請求書PDF（複数ページ）から金額・取引先・日付を抽出し、社内向けの確認メール下書きを Gmail で作成する。

**結果**: かなり有効でした。

PDF の読み取りについては、スキャン画像ではなくデジタルテキストを含むPDFであれば精度が高く、日本語の複雑なレイアウト（縦書き混在、表形式）でも大部分を正確に読み取れました。

Gmail での下書き作成は、Google サービスということもあり非常にスムーズでした。「宛先：総務部、件名：○月請求書確認の件」という指示を与えると、本文の骨格まで適切に作成してくれました。

一点注意が必要なのは、金額の桁区切りや単位（円・万円・税込・税抜）の判断に稀にミスが出ることです。金融・経理用途では必ず人間のレビューを入れることをお勧めします。

**所要時間と精度**: 5枚のPDFで約3分（手動なら約10分）。金額の誤読1件（小計と合計の混同）。

### シナリオ3：複数ウィンドウをまたいだ情報照合

**タスク内容**: CRMシステムの顧客データとスプレッドシートの注文データを照合し、不一致があった行をハイライトする。

**結果**: この用途には向いていませんでした。

複数ウィンドウ間での文脈維持が弱く、「さっきCRMで見た顧客ID」を正確にスプレッドシートと照合する操作で、しばしば取り違えが発生しました。特にIDが数字だけで構成されている場合に顕著でした。

また、照合ルールが複雑になると（「名前の揺れを考慮して」など）、途中でループに入って同じ操作を繰り返すことがありました。

**教訓**: 複数の情報源を横断する照合作業は、Computer Use ではなく API を経由した構造化されたデータ処理に任せる方が確実です。

## APIからの利用：セッション管理とコスト感

開発者として Computer Use を API から使う場合、いくつかの実装ポイントがあります。

セッション管理については、Gemini の Computer Use API は操作ごとにスクリーンショットを送信して次のアクションを判断するループ構造です。各ステップでのレイテンシが積み重なるため、タスクが複雑になるほど全体の実行時間が長くなります。タイムアウト設定は長めに取っておく必要があります。

```python
# Gemini Computer Use の基本的な実装パターン（擬似コード）
from google import genai

client = genai.Client()

def execute_computer_task(task_description: str, max_steps: int = 20):
    history = []
    
    for step in range(max_steps):
        # 現在の画面状態を取得
        screenshot = capture_screen()
        
        # Gemini に次のアクションを判断させる
        response = client.models.generate_content(
            model="gemini-2.5-pro",
            contents=[
                {"text": f"Task: {task_description}\nHistory: {history}"},
                {"inline_data": {"mime_type": "image/png", "data": screenshot}}
            ]
        )
        
        action = parse_action(response.text)
        
        if action.type == "complete":
            return action.result
        
        # アクションを実行
        execute_action(action)
        history.append(action)
    
    raise TimeoutError("タスクが最大ステップ数内に完了しませんでした")
```

コスト面では、ステップごとにスクリーンショット画像をトークンとして消費するため、通常のテキスト生成より費用がかかります。複雑なタスクで20〜30ステップになると、1タスクあたりのコストが想定より大きくなることがあります。本番運用前に実際のユースケースでコストを計測しておくことをお勧めします。

## 実運用で使えるかどうか：正直な評価

Computer Use を使うべきケースと、使わない方がいいケースを整理します。

**向いているケース**: 繰り返し性が高く、同じUIを複数回操作するタスク。Google Workspace を中心とした業務フロー。スキャンでないPDF等の非構造化ドキュメントの読み取り。人間がレビューを入れることを前提とした「下書き作成」業務。

**向いていないケース**: 複数のデータソースを高精度で照合するタスク（構造化APIを使う方が確実）。金融・医療など誤りの許容度が低い用途（必ず人間レビューを）。UIが頻繁に変わるシステム（毎回の変更への対応が必要）。

現時点での Gemini Computer Use は「業務の自動化補助ツール」としては十分な実力があります。ただし「完全な自律実行」には向いていません。人間が操作のレビューポイントを設け、適切に監視しながら使うことで、単純作業の時間を大幅に削減できるツールです。

次のステップとして、まずは社内でコピー作業や定型フォームへの記入など、シンプルで繰り返し性が高いタスクから試してみることをお勧めします。そこで精度を確認できれば、徐々に複雑なタスクへ展開していくのが現実的な進め方です。
