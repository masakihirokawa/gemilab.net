# Gemini Computer Use 実践活用ガイド — フォーム自動入力・データ抽出・ブラウザRPA

## はじめに

Gemini 3 の Computer Use ツールは、AI がスクリーンショットを読み込んでブラウザやデスクトップ UI を自律操作できる強力な機能です。しかし、概念を理解するだけでなく、**実際のプロダクト環境で動かす**には、エラーハンドリング、タイムアウト対策、信頼性確保など、多くの実装上の工夫が必要です。

本記事は、Computer Use をビジネス価値に変えるための実践ガイドです。フォーム自動入力、複数サイトからのデータ抽出、API の代替として機能する RPA パイプラインの構築方法を、実装例を交えて詳しく解説します。

## 実践例1：Web フォーム自動入力ツール

### ユースケース

営業チーム向けの「見積もり自動生成システム」を想像してください。顧客の情報を CSV から読み込み、Web フォームに自動入力する。従来は人間が 1 件 30 秒かかるタスクが、Computer Use なら秒単位で完了します。

### 実装コード例

```python
import anthropic
import base64
import time
from selenium import webdriver
from selenium.webdriver.common.by import By

# Anthropic クライアントを初期化
client = anthropic.Anthropic(api_key="YOUR_GEMINI_API_KEY")

def capture_screenshot(driver):
    """ブラウザの現在の画面をスクリーンショット"""
    screenshot = driver.get_screenshot_as_png()
    return base64.standard_b64encode(screenshot).decode('utf-8')

def fill_form_with_gemini(driver, form_data):
    """Computer Use を使ってフォームを自動入力"""
    max_steps = 20
    step_count = 0

    while step_count < max_steps:
        screenshot_b64 = capture_screenshot(driver)

        # Gemini に操作指示を求める
        message = client.messages.create(
            model="gemini-2.0-flash",
            max_tokens=1024,
            tools=[
                {
                    "type": "computer_use",
                    "name": "computer",
                    "display_width": 1920,
                    "display_height": 1080,
                }
            ],
            messages=[
                {
                    "role": "user",
                    "content": [
                        {
                            "type": "image",
                            "source": {
                                "type": "base64",
                                "media_type": "image/png",
                                "data": screenshot_b64
                            }
                        },
                        {
                            "type": "text",
                            "text": f"フォーム入力: {form_data}"
                        }
                    ]
                }
            ]
        )

        for block in message.content:
            if block.type == "tool_use":
                tool_input = block.input
                if tool_input.get("action") == "click":
                    x, y = tool_input["coordinate"]
                    execute_click(driver, x, y)

        step_count += 1
        time.sleep(0.5)

    return True

def execute_click(driver, x, y):
    """スクリーンショット座標から実際の要素をクリック"""
    window_width = driver.execute_script("return window.innerWidth")
    window_height = driver.execute_script("return window.innerHeight")
    element = driver.execute_script(
        f"return document.elementFromPoint({int(x * window_width / 1920)}, {int(y * window_height / 1080)})"
    )
    if element:
        driver.execute_script("arguments[0].click();", element)
```

### ポイント

- スクリーンショット → Gemini → 操作のループを最大回数制限で安全にする
- Selenium と連携して、スクリーンショット座標を実際の DOM 要素にマッピング
- エラーが発生した場合のリトライロジック実装

## 実践例2：複数サイトからのデータ抽出

### ユースケース

「競合 5 社の商品価格を毎日抽出して Google Sheets に記録」のような定期タスクです。Computer Use なら、HTML パース不要で、UI が変わってもロバストに対応できます。

### 実装フロー

```python
def scrape_product_prices(urls, product_name):
    """複数サイトから商品価格を抽出"""
    results = {}

    for url in urls:
        driver = webdriver.Chrome()
        driver.get(url)
        time.sleep(2)

        message = client.messages.create(
            model="gemini-2.0-flash",
            max_tokens=2048,
            tools=[{"type": "computer_use", "name": "computer", ...}],
            messages=[{
                "role": "user",
                "content": [
                    {
                        "type": "image",
                        "source": {
                            "type": "base64",
                            "media_type": "image/png",
                            "data": capture_screenshot(driver)
                        }
                    },
                    {
                        "type": "text",
                        "text": f"商品名 {product_name} の価格を抽出してください"
                    }
                ]
            }]
        )

        for block in message.content:
            if block.type == "text" and "¥" in block.text:
                results[url] = block.text

        driver.quit()

    return results
```

### 利点

- JavaScript レンダリング対応：動的コンテンツも自動抽出
- UI 変更への耐性：HTML 構造が変わってもビジュアルから判断可能
- 複雑な操作に対応：ドロップダウン選択、ポップアップ閉鎖など

## 実践例3：顧客サポート自動化パイプライン

### ユースケース

「お客様がウェブサイトで特定ページへ到達できていない」という問い合わせに対し、Computer Use で実際にアクセスして問題を再現・診断するボット。

```python
def diagnose_website_issue(issue_description, target_url):
    """ウェブサイトの問題を自動診断"""
    driver = webdriver.Chrome()
    diagnostic_report = []

    try:
        driver.get(target_url)
        time.sleep(3)

        for iteration in range(5):
            screenshot_b64 = capture_screenshot(driver)

            message = client.messages.create(
                model="gemini-2.0-flash",
                max_tokens=1024,
                tools=[{"type": "computer_use", "name": "computer", ...}],
                messages=[{
                    "role": "user",
                    "content": [
                        {
                            "type": "image",
                            "source": {
                                "type": "base64",
                                "media_type": "image/png",
                                "data": screenshot_b64
                            }
                        },
                        {
                            "type": "text",
                            "text": f"問題診断: {issue_description}"
                        }
                    ]
                }]
            )

            for block in message.content:
                if block.type == "text":
                    diagnostic_report.append(block.text)

    finally:
        driver.quit()

    return "\n".join(diagnostic_report)
```

## ベストプラクティス：エラーハンドリングと信頼性確保

### 1. タイムアウト管理

常に **max_tokens と max_steps を明示的に設定**してください。

```python
max_tokens = 2048
max_steps = 15
timeout_seconds = 60

def safe_computer_use_call(max_tokens=2048, max_steps=15, timeout=60):
    """タイムアウト対応のラッパー"""
    try:
        message = client.messages.create(
            model="gemini-2.0-flash",
            max_tokens=max_tokens,
            tools=[{"type": "computer_use", "name": "computer", ...}],
            messages=[...],
            timeout=timeout
        )
        return message
    except Exception as e:
        print(f"タイムアウトまたはエラー：{e}")
        return None
```

### 2. 操作の確認と検証

自動操作後、必ず **スクリーンショットを取得して意図通りの状態になっているか確認**してください。

```python
def verify_operation(driver, expected_state):
    """操作が成功したかビジュアルで確認"""
    time.sleep(0.5)
    screenshot = capture_screenshot(driver)

    message = client.messages.create(
        model="gemini-2.0-flash",
        max_tokens=256,
        messages=[{
            "role": "user",
            "content": [
                {
                    "type": "image",
                    "source": {
                        "type": "base64",
                        "media_type": "image/png",
                        "data": screenshot
                    }
                },
                {
                    "type": "text",
                    "text": f"以下の状態が達成されましたか？{expected_state}"
                }
            ]
        }]
    )

    return "はい" in message.content[0].text
```

### 3. リトライロジック

一度失敗しても自動リトライする仕組みを用意しましょう。

```python
def robust_form_fill(driver, form_data, max_retries=3):
    """失敗時は自動リトライ"""
    for attempt in range(max_retries):
        try:
            result = fill_form_with_gemini(driver, form_data)
            if result:
                return True
        except Exception as e:
            print(f"試行 {attempt + 1} 失敗：{e}")
            if attempt < max_retries - 1:
                time.sleep(2 ** attempt)
                driver.refresh()

    return False
```

## 他の自動化ツールとの比較

- **Selenium**：定型化された UI 自動化に強い / JavaScript の複雑な変化に弱い
- **Playwright**：ブラウザ自動化全般 / 人間的な判断が必要なシーンに対応不可
- **Computer Use**：UI の変化への耐性 / 予期しない状況対応 / セットアップが複雑

Computer Use の最大の強みは、AI が画面を見て意思判断するため、マークアップ言語の変更やレイアウトの微調整に自動適応することです。

## よくある質問（FAQ）

### Q1. Computer Use は日本語サイトに対応していますか？

**A.** はい、対応しています。Gemini 自体が日本語を理解するため、日本語でのテキスト入力、日本語ラベルの読み込み、日本語エラーメッセージの解釈も可能です。

### Q2. Computer Use で認証（ログイン）を自動化できますか？

**A.** 技術的には可能ですが、**セキュリティ上推奨されません**。本番環境では、Selenium の `add_cookie()` で事前にセッション Cookie を注入するか、API トークンを環境変数から読み込むアプローチを推奨します。

```python
session_token = os.getenv("SESSION_TOKEN")
driver.add_cookie({"name": "session", "value": session_token})
```

### Q3. Computer Use のコスト（API 料金）はいくらですか？

**A.** Gemini API の利用料金に含まれます。詳細は [Google Cloud Pricing](https://cloud.google.com/pricing/details/generative-ai) を確認してください。大量実行する場合は、キャッシング機能で重複リクエストを削減できます。

### Q4. Computer Use は複数タブ / ウィンドウの操作に対応していますか？

**A.** 現在、1 つのスクリーンショットは 1 つのウィンドウ / タブに対応しています。複数タブを操作する場合は、`driver.switch_to.window()` で明示的に切り替えた後、スクリーンショットを再取得してください。

## まとめ

Gemini の Computer Use は、従来の RPA やブラウザ自動化ツールでは実現困難だった **「AI が状況を判断して動く」**自動化を実現します。フォーム入力、データ抽出、ウェブサイト診断など、実務的なユースケースは多岐に渡ります。

本記事で紹介したコード例やベストプラクティスを参考に、まずは小規模なプロトタイプから始めることをお勧めします。エラーハンドリングとリトライロジックを組み込むことで、本番環境でも安定した自動化パイプラインを構築できます。
