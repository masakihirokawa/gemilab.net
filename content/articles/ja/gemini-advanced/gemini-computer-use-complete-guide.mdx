## Gemini Computer Use とは？——AI がPC を「見て・操作する」新機能

Gemini Computer Use は、Google の最新 AI モデル **Gemini 2.5 Pro** に搭載された革新的な機能です。これまで AI は「テキストを読む」「画像を分析する」といった受け身のタスクに限定されていましたが、Computer Use は AI が**スクリーンショットを見て状況を理解し、マウスクリックやキーボード入力などの PC 操作を自ら実行できる**という段階へ進化させましました。

### どのように機能するのか

Computer Use の動作メカニズムは以下の通りです：

1. **スクリーンショット取得** — AI がユーザーの画面全体、または特定領域のスクリーンショットを受け取ります
2. **状況認識** — Gemini が画面に映っているテキスト、UI要素、ウィンドウの配置などを深く分析します
3. **操作意図の判断** — ユーザーの指示（例：「このメールに返信して」「レポートのデータを更新して」）を理解し、必要な操作を計画します
4. **自動操作実行** — マウス座標へのクリック、テキスト入力、キーボードショートカットなどを逐次実行します
5. **フィードバック取得** — 操作結果の新しいスクリーンショットを確認し、次のステップを判断します

このサイクルを繰り返すことで、複雑で多段階のタスク（データ入力、フォーム記入、ウェブスクレイピング、テスト実行など）を AI が完全に自動化できるのです。

### Gemini 2.5 Pro での実装

Computer Use は Gemini 2.5 Pro、および Google AI Studio（無料）で利用可能です。特に Gemini 2.5 Pro は以下の高度な機能を備えています：

- **より正確な座標認識** — UI要素の位置を正確に特定
- **複雑な操作シーケンス** — 10個以上の連続操作を安定して実行
- **エラーリカバリー** — 操作に失敗した場合の自動リトライ

## できること・できないこと

Computer Use の活用シーンと制限を正確に理解することが、効果的な実装の鍵です。

### できること

**ブラウザ操作**
- ウェブサイトのフォーム入力と送信
- オンラインサービスでの検索・フィルタリング
- ウェブスクレイピングと情報抽出
- SNS や CMS への投稿

**ファイル操作**
- テキストエディタでの文章作成・編集
- Excel / Google Sheets でのデータ入力・計算
- PDF の読み込みと情報抽出
- フォルダ構造の確認と整理

**アプリケーション操作**
- デスクトップアプリ（Word、PowerPoint 等）の操作
- Slack や Zoom などのコミュニケーションツール
- カスタムビジネスツールの利用

**品質保証**
- ウェブアプリケーションの自動テスト
- UI要素の動作検証
- クロスブラウザテストの一部自動化

### できないこと（セキュリティ・技術制限）

**セキュリティ理由による制限**
- 金銭取引（オンライン決済、銀行口座操作）
- 個人情報の入力（本人確認書類のスキャン、パスポート入力）
- パスワードやAPIキーの入力
- 機密ファイルの移動・削除

**技術的制限**
- リアルタイムストリーミングビデオには未対応（静止画スクリーンショットのみ）
- Ctrl+Alt+Delete などのシステムレベルキー操作
- VPN や認証デバイス（セキュリティキー）を経由した複雑な認証
- スマートフォンやタブレットの操作（PC 環境のみ）

## Google AI Studio / Gemini API での利用方法

Computer Use を実際に活用するには、2つの主要な方法があります。

### Google AI Studio での利用（最もシンプル）

[Google AI Studio](https://aistudio.google.com) にアクセスし、以下の手順で即座に試験できます：

1. **Google アカウントでログイン** — 既存のアカウントで利用可能（無料枠あり）
2. **「新しいプロンプト」を作成**
3. **「Enter」の横の「+」から「スクリーンショット」を追加**
4. **画面全体または指定領域のスクリーンショットをアップロード**
5. **指示を入力**（例：「このフォームを日本語で埋めてください」）
6. **「送信」をクリック**

AI が画面を分析し、どのような操作を行うかの説明を提示します。スクリーンショットを追加して視覚的に確認できるため、デバッグも容易です。

### Python SDK を使った API 統合

より高度な自動化には、Gemini API を Python で呼び出すアプローチが推奨されます：

```python
import anthropic
import base64
from pathlib import Path

# クライアント初期化
client = anthropic.Anthropic(api_key="YOUR_GEMINI_API_KEY")

# スクリーンショット画像をBase64エンコード
def encode_image(image_path: str) -> str:
    with open(image_path, "rb") as image_file:
        return base64.standard_b64encode(image_file.read()).decode("utf-8")

# Computer Use リクエスト
screenshot_data = encode_image("desktop_screenshot.png")

message = client.messages.create(
    model="gemini-2.5-pro",
    max_tokens=1024,
    messages=[
        {
            "role": "user",
            "content": [
                {
                    "type": "image",
                    "source": {
                        "type": "base64",
                        "media_type": "image/png",
                        "data": screenshot_data
                    }
                },
                {
                    "type": "text",
                    "text": "このウェブサイトの検索ボックスに『Python API』と入力し、検索してください。"
                }
            ]
        }
    ]
)

print(message.content[0].text)
```

**重要:** `YOUR_GEMINI_API_KEY` は環境変数として安全に管理してください：

```bash
export GEMINI_API_KEY="your_actual_api_key"
```

API レスポンスには、AI が実行する予定のマウスクリック座標やキーボード入力が JSON 形式で含まれます。このデータを基に、実際にシステムコマンド（`pyautogui` など）でマウス・キーボード操作を実行するワーカープロセスを構築します。

## 安全な使い方と注意点

Computer Use は強力な機能ですが、誤用や予期しない操作を避けるために、いくつかの重要な注意事項があります。

### サンドボックス環境での事前検証

本番環境での自動操作を行う前に、**必ず隔離されたテスト環境で動作確認を行ってください**：

- 専用のテスト用 VM や Docker コンテナを用意
- 本番データベースには接続しない
- テスト用ダミーアカウントを使用

これにより、AI が予期しない操作を実行した場合でも、実ビジネスへの影響を防げます。

### センシティブ操作での人間による承認

AI が以下の操作を実行する場合は、自動実行ではなく、**人間による事前承認フローを必須にしてください**：

- 削除操作（ファイル削除、メール削除、DB削除）
- 金銭・コスト関連の操作（請求書発行、支払い承認）
- アクセス権限の変更（ユーザー追加・削除、権限割り当て）

Python コード例（承認フロー）：

```python
# AI が操作を計画した後、実行前に人間の確認を取る
proposed_actions = extract_ai_planned_actions(message.content[0].text)

print(f"AI が以下を実行する予定です:\n{proposed_actions}")
user_approval = input("実行を承認しますか？ (yes/no): ")

if user_approval.lower() == "yes":
    execute_actions(proposed_actions)
else:
    print("操作はキャンセルされました")
```

### ログ記録と監査

すべての自動操作を記録し、問題が発生した場合に追跡可能にしてください：

- 各操作前後のスクリーンショットをログに記録
- API リクエスト・レスポンスを JSON 形式で保存
- 実行結果（成功・失敗・エラー内容）を記録
- 定期的に監査ログを検索

## Computer Use ツールとは

Computer Use ツールは、Gemini がスクリーンショット（画面画像）を受け取り、次に実行すべき UI 操作（マウスクリック、キーボード入力、スクロールなど）を判断して返す仕組みです。アプリケーション側がその指示を受け取り、実際の操作を実行します。

### 主なアクションタイプ

| アクション | 説明 |
|-----------|------|
| `click` | 指定座標をクリック |
| `type` | テキストを入力 |
| `key` | キーボードショートカットを送信 |
| `scroll` | 指定方向にスクロール |
| `screenshot` | 現在の画面をキャプチャ（ループ内で使用） |
| `move` | マウスカーソルを移動 |

## Step 2: 基本的な Computer Use ループの実装

Computer Use の基本は「スクリーンショット → Gemini に送信 → アクション取得 → 実行 → 繰り返し」のループです。

```python
import base64
from google import genai
from google.genai import types

# クライアントの初期化
client = genai.Client(api_key="YOUR_API_KEY")

def encode_screenshot(image_path: str) -> str:
    """スクリーンショットを base64 エンコード"""
    with open(image_path, "rb") as f:
        return base64.b64encode(f.read()).decode("utf-8")

def run_computer_use_step(screenshot_b64: str, task: str, history: list) -> dict:
    """
    スクリーンショットを Gemini に送り、次のアクションを取得
    """
    # Computer Use ツール定義
    computer_use_tool = types.Tool(
        computer_use=types.ComputerUseTool(
            display_width=1280,
            display_height=800,
        )
    )

    # メッセージ構築
    messages = history + [
        {
            "role": "user",
            "content": [
                {
                    "type": "image",
                    "source": {
                        "type": "base64",
                        "media_type": "image/png",
                        "data": screenshot_b64,
                    },
                },
                {
                    "type": "text",
                    "text": f"現在の画面です。タスク: {task}\n次に実行すべき操作を指示してください。",
                },
            ],
        }
    ]

    response = client.models.generate_content(
        model="gemini-3-flash-preview",
        contents=messages,
        config=types.GenerateContentConfig(
            tools=[computer_use_tool],
            system_instruction="あなたはコンピュータを操作するエージェントです。ユーザーのタスクを達成するために、画面を見て最適な操作を実行してください。",
        ),
    )

    return response
```

## Step 3: Playwright と組み合わせたブラウザ操作エージェント

```python
import asyncio
from playwright.async_api import async_playwright
import io
from PIL import Image

async def browser_agent(task: str):
    """ブラウザを自律操作するエージェント"""
    async with async_playwright() as p:
        browser = await p.chromium.launch(headless=False)
        page = await browser.new_page(viewport={"width": 1280, "height": 800})

        # 最初のページに移動
        await page.goto("https://www.google.com")
        history = []
        max_steps = 10  # 無限ループ防止

        for step in range(max_steps):
            # 現在の画面をキャプチャ
            screenshot_bytes = await page.screenshot()
            screenshot_b64 = base64.b64encode(screenshot_bytes).decode("utf-8")

            print(f"\n--- Step {step + 1} ---")

            # Gemini にアクションを問い合わせ
            response = run_computer_use_step(screenshot_b64, task, history)

            # レスポンスを解析
            action = None
            for part in response.candidates[0].content.parts:
                if hasattr(part, "computer_use") and part.computer_use:
                    action = part.computer_use
                    break
                elif hasattr(part, "text") and "TASK_COMPLETE" in part.text:
                    print("タスク完了！")
                    await browser.close()
                    return

            if not action:
                print("アクションなし。タスク完了と判断します。")
                break

            # アクションを実行
            print(f"実行: {action.action} - {action}")
            await execute_action(page, action)

            # 履歴に追加（文脈を維持）
            history.append({
                "role": "assistant",
                "content": response.candidates[0].content.parts,
            })

            # 操作後に少し待機
            await asyncio.sleep(0.5)

        await browser.close()

async def execute_action(page, action):
    """Gemini が返したアクションを Playwright で実行"""
    if action.action == "click":
        await page.mouse.click(action.coordinate[0], action.coordinate[1])
    elif action.action == "type":
        await page.keyboard.type(action.text)
    elif action.action == "key":
        await page.keyboard.press(action.key)
    elif action.action == "scroll":
        await page.mouse.wheel(
            action.coordinate[0],
            action.coordinate[1],
            delta_x=action.delta_x if hasattr(action, "delta_x") else 0,
            delta_y=action.delta_y if hasattr(action, "delta_y") else 0,
        )

# 実行
asyncio.run(browser_agent("Google で 'Gemini 3 API' を検索して、最初の結果を開いてください"))
```

## Computer Use 使用時のベストプラクティス

### 1. タスクは具体的に記述する

曖昧な指示では、AI が誤った操作を実行する可能性があります。「ボタンをクリックして」ではなく、「ページ右上の青い『送信』ボタンをクリックして」のように具体的に記述します。

### 2. 最大ステップ数を設定する

無限ループを防ぐために、必ず `max_steps` などの終了条件を設定します。

### 3. 操作前に確認ステップを入れる

重要な操作（送信、削除など）の前に確認プロンプトを挿入することで、意図しない操作を防止できます。

### 4. エラーハンドリング

ネットワークエラーや予期しない UI 変化に対応するため、try-except を適切に実装します。

```python
try:
    await execute_action(page, action)
except Exception as e:
    print(f"操作エラー: {e}")
    # エラー状態のスクリーンショットを Gemini に送り、回復方法を問い合わせる
```

## 実践例1：Web フォーム自動入力ツール

### ユースケース

営業チーム向けの「見積もり自動生成システム」を想像してください。顧客の情報を CSV から読み込み、Web フォームに自動入力します。従来は人間が 1 件 30 秒かかるタスクが、Computer Use なら秒単位で完了します。

### 実装コード例

```python
import anthropic
import base64
import time
from selenium import webdriver
from selenium.webdriver.common.by import By

# Anthropic クライアントを初期化
client = anthropic.Anthropic(api_key="YOUR_GEMINI_API_KEY")

def capture_screenshot(driver):
    """ブラウザの現在の画面をスクリーンショット"""
    screenshot = driver.get_screenshot_as_png()
    return base64.standard_b64encode(screenshot).decode('utf-8')

def fill_form_with_gemini(driver, form_data):
    """Computer Use を使ってフォームを自動入力"""
    max_steps = 20
    step_count = 0

    while step_count < max_steps:
        screenshot_b64 = capture_screenshot(driver)

        # Gemini に操作指示を求める
        message = client.messages.create(
            model="gemini-2.0-flash",
            max_tokens=1024,
            tools=[
                {
                    "type": "computer_use",
                    "name": "computer",
                    "display_width": 1920,
                    "display_height": 1080,
                }
            ],
            messages=[
                {
                    "role": "user",
                    "content": [
                        {
                            "type": "image",
                            "source": {
                                "type": "base64",
                                "media_type": "image/png",
                                "data": screenshot_b64
                            }
                        },
                        {
                            "type": "text",
                            "text": f"フォーム入力: {form_data}"
                        }
                    ]
                }
            ]
        )

        for block in message.content:
            if block.type == "tool_use":
                tool_input = block.input
                if tool_input.get("action") == "click":
                    x, y = tool_input["coordinate"]
                    execute_click(driver, x, y)

        step_count += 1
        time.sleep(0.5)

    return True

def execute_click(driver, x, y):
    """スクリーンショット座標から実際の要素をクリック"""
    window_width = driver.execute_script("return window.innerWidth")
    window_height = driver.execute_script("return window.innerHeight")
    element = driver.execute_script(
        f"return document.elementFromPoint({int(x * window_width / 1920)}, {int(y * window_height / 1080)})"
    )
    if element:
        driver.execute_script("arguments[0].click();", element)
```

### ポイント

- スクリーンショット → Gemini → 操作のループを最大回数制限で安全にする
- Selenium と連携して、スクリーンショット座標を実際の DOM 要素にマッピング
- エラーが発生した場合のリトライロジック実装

### ユースケース

「競合 5 社の商品価格を毎日抽出して Google Sheets に記録」のような定期タスクです。Computer Use なら、HTML パース不要で、UI が変わってもロバストに対応できます。

### ユースケース

### 3. リトライロジック

一度失敗しても自動リトライする仕組みを用意しましょう。

```python
def robust_form_fill(driver, form_data, max_retries=3):
    """失敗時は自動リトライ"""
    for attempt in range(max_retries):
        try:
            result = fill_form_with_gemini(driver, form_data)
            if result:
                return True
        except Exception as e:
            print(f"試行 {attempt + 1} 失敗：{e}")
            if attempt < max_retries - 1:
                time.sleep(2 ** attempt)
                driver.refresh()

    return False
```

## 他の自動化ツールとの比較

- **Selenium**：定型化された UI 自動化に強い / JavaScript の複雑な変化に弱い
- **Playwright**：ブラウザ自動化全般 / 人間的な判断が必要なシーンに対応不可
- **Computer Use**：UI の変化への耐性 / 予期しない状況対応 / セットアップが複雑

Computer Use の最大の強みは、AI が画面を見て意思判断するため、マークアップ言語の変更やレイアウトの微調整に自動適応することです。
