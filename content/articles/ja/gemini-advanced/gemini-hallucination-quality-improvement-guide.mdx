## はじめに

Gemini を使っていると、時々「これ、本当？」と思うような回答が返されることがあります。確実に存在する事実を否定したり、存在しない情報を自信満々に述べたり、完全に的外れなアドバイスをしたり。

このような現象を「ハルシネーション」と呼びます。これは AI の知識に関する幻覚ではなく、学習中の統計的パターンマッチングの副作用です。

ここでは以下のポイントを徹底的に解説します。

- ハルシネーションが発生する真の原因
- Gemini の回答品質が低くなる5つのシチュエーション
- ハルシネーションを劇的に減らすプロンプトテクニック
- Google検索と連携した事実確認機能（Grounding）
- API パラメータの最適なチューニング方法

これらを実践することで、Gemini の回答の信頼性を大幅に向上させることができます。

## ハルシネーションとは何か

### 定義：AI が事実と異なる情報を「確信を持って」生成する現象

ハルシネーションは単なる「間違い」ではなく、AI モデルが事実でない情報を自信満々に述べる現象です。言い換えると、「本当だと思い込んで」間違った情報を生成しているのです。

#### よくある例

**例1：存在しない書籍を紹介する**

```
ユーザー: 「田中太郎という作家が書いた『AI革命の正体』という本について教えてください」

Gemini（ハルシネーション）: 「『AI革命の正体』は、2023年に発行された田中太郎の著作で、
AI 技術の未来について深く考察した名著です。特に第3章の『量子コンピュータとAIの融合』は、
業界で大きな注目を集めました...」

実際：そのような本は存在しません。著者も架空です。
```

**例2：存在しない関数やメソッドを示唆する**

```
ユーザー: 「Python で配列をシャッフルする方法は？」

Gemini（ハルシネーション）: 「numpy.array_shuffle() 関数を使います」

実際：そのような関数は存在しません。正しくは random.shuffle() です。
```

**例3：統計データを作り上げる**

```
ユーザー: 「日本の2025年GDP成長率は？」

Gemini（ハルシネーション）: 「日本の2025年GDP成長率は3.2%と予測されています」

実際：2026年3月時点で、2025年の確定データはまだ発表されていません。
```

### なぜハルシネーションが起きるのか

Gemini のような言語モデルは、膨大なテキストデータから「パターン」を学習して、次の単語を予測する仕組みで動作しています。学習データに含まれる曖昧さや矛盾が、時に「もっともらしい」が「実は間違っている」情報を生成させてしまうのです。

## Gemini の回答品質が低くなる5つの原因

### 原因1：プロンプトが曖昧・指示が不明確

最も一般的な原因はプロンプト自体の問題です。

**NG例（曖昧）**

```
ユーザー: 「AI について教えてください」
```

このプロンプトでは、Gemini は「AI について何を知りたいのか」を推測する必要があります。その結果、汎用的で浅い回答が返されることが多いです。

**OK例（具体的・明確）**

```
ユーザー: 「Gemini API で function calling を使う際、
複数の関数を定義する場合の注意点を、
Python コード例を含めて説明してください。
特に、関数の返り値の型定義が重要な理由を含めてください」
```

この場合、Gemini は「function calling」「複数定義」「Python」「返り値の型」という具体的な要素を理解して、質問に直結した回答ができます。

**改善テクニック**

プロンプトを改善する際は、以下の要素を明確にしてください。

- **対象者**：「初級者向けに」「専門家向けに」など
- **用途**：「ブログ記事として」「会社の報告書として」など
- **形式**：「箇条書きで」「コード例を含めて」など
- **詳細度**：「簡潔に」「詳しく」「中程度」など
- **背景情報**：「なぜこの情報が必要か」という文脈

### 原因2：コンテキスト（文脈）が不足している

AI は前後の文脈を読むことで、より正確な回答ができます。コンテキストが不足すると、推測に頼らざるを得なくなり、ハルシネーションのリスクが高まります。

**NG例（コンテキスト不足）**

```
ユーザー: 「この関数はどう改善できますか？」

（コードを提示していない）
```

**OK例（充分なコンテキスト）**

```
ユーザー: 「以下の Python 関数があります。
大量の API リクエストを処理する際に、
レート制限エラーを回避しながら効率的に
データを取得する改善案を教えてください。

【現在のコード】
```
def fetch_data(api_urls):
    results = []
    for url in api_urls:
        response = requests.get(url)
        results.append(response.json())
    return results
```

この関数は...」
```

このように背景情報が含まれると、Gemini はより正確な改善案を提示できます。

### 原因3：古い知識や学習データの時代的なズレ

Gemini の学習データには一定の時代的なカットオフがあります。リアルタイム情報が必要な場合、特にニュースやトレンド、最新技術については、ハルシネーションのリスクが高まります。

**リスク分野**

- **最新ニュース**：「2026年3月現在の最新情報は」と聞くと、学習データ以降の事実を推測で補う可能性
- **テック業界**：新しい API、新しい言語バージョン、廃止予定の機能
- **統計データ**：過去数年のデータは正確でも、最新の予測値は推測の可能性
- **人物情報**：著名人の現在の職務や所属が変わっていても、古い情報のまま

**対策**

古い知識が影響しそうな質問では、以下の工夫をしてください。

- 「2024年時点の情報として」と明示的に時代を指定
- 「以下のドキュメントに基づいて」と最新資料を提供
- 後述の「Grounding」機能で Google 検索と連携

### 原因4：複雑すぎるタスク要求

1つのプロンプトで複数の異なるタスクを要求すると、AI が各タスクを完全に理解できず、部分的に推測で埋める可能性があります。

**NG例（複雑すぎる）**

```
ユーザー: 「AI の歴史、現在の技術、将来の可能性をまとめて、
さらに日本と海外の産業応用の違いを比較し、
最後に学習リソースをリストアップしてください」
```

**OK例（段階的に分割）**

```
プロンプト1: 「AI の歴史を時代順に説明してください」
プロンプト2: 「2026年時点の主流な AI 技術は何ですか」
プロンプト3: 「日本での AI 産業応用と海外での応用の違いを比較してください」
プロンプト4: 「AI を学ぶための初級向け学習リソースを5つ紹介してください」
```

複雑なタスクは細分化して、段階的に処理することで、各ステップでの精度が向上します。

### 原因5：パラメータ設定が不適切

API パラメータの設定（特に temperature）が、直接ハルシネーション率に影響します。

## ハルシネーションを減らす実践的なプロンプトテクニック

### テクニック1：「ファクトチェック前提」で指示する

ハルシネーションを起こしそうな内容では、先制的に「根拠の明示」を要求しましょう。

```javascript
const prompt = `
次の質問に答える際、必ず以下のルールに従ってください：

【ルール】
1. 一般的な知識（99%以上の人が知っている事実）の場合は「出典なし」でもOK
2. 業界知識や統計データの場合は、必ず「出典」を記載
3. 個人の意見と事実を明確に区別
4. 確実でない情報には「推測」や「2026年時点では未確認」と明示

【質問】
Gemini 2.0 の新機能について、
最新の変更点をまとめてください。
`;
```

このように「根拠を示してね」という指示をあらかじめ含めることで、Gemini は推測での補足を避けるようになります。

### テクニック2：「制約条件」を明確に設定

何をしてはいけないか、という負の指示もハルシネーション低減に有効です。

```javascript
const prompt = `
以下の文章を Python コードに変換してください。

【制約条件】
- 存在しないライブラリを使用しない
- 存在しないメソッドを呼び出さない
- コードが実際に実行可能なこと
- NumPy や Pandas など、広く使われるライブラリのみを使う
- わからない場合は「このタスクには標準ライブラリだけでは対応できません」と明示

【変換対象の文章】
「リスト内の重複を削除した後、昇順でソートしたい」
`;
```

このような制約条件は、モデルに「わからないなら無理に作るな」というメッセージを送ります。

### テクニック3：「確信度」を明示させる

回答の信頼度を自己評価させることで、推測部分が減ります。

```javascript
const prompt = `
以下の質問に答えた後、
あなたの確信度を 0-100% で示してください。

確信度が 50% 以下の場合は、
根拠を詳しく説明するか、
確実でない旨を明記してください。

【質問】
「Gemini API の価格表（2026年3月時点）を説明してください。
特に、1000トークンあたりの入力・出力料金を記載してください」
`;
```

### テクニック4：「参考資料」を提供する

AI の知識を「補強」すれば、ハルシネーションのリスクは劇的に下がります。

```javascript
const prompt = `
以下の参考資料に基づいて、
質問に答えてください。
参考資料に記載されていない情報については、
「参考資料には記載されていませんが」と前置きしてください。

【参考資料】
${documentContent}

【質問】
Gemini API で function calling を使う際の
セキュリティベストプラクティスは何ですか？
`;
```

参考資料を含めることで、Gemini は学習データだけでなく、提供された「確実な情報」に基づいて回答するようになります。

### テクニック5：「例」を示して期待値を明確にする

事前に「こういう形式の回答を望んでいる」と示すだけで、品質が向上します。

```javascript
const prompt = `
以下のような形式で、API エラーの対処法をリストアップしてください。

【形式の例】
エラー1: "Model not found"
- 原因: 指定したモデル名が存在しない、または廃止されている
- 対処: \`models.list()\` でサポートされているモデル一覧を確認
- コード例:
\`\`\`python
from google.generativeai import models
for model in models.list():
    print(model.name)
\`\`\`

【実際の対処法を教えてください】
Gemini API でよくあるエラー TOP 5
`;
```

具体例を示すことで、Gemini はその形式を「テンプレート」として理解し、より構造化された回答ができます。

## Grounding：Google 検索との連携で事実確認

最も確実なハルシネーション対策は、AI の生成内容を「リアルタイム情報」で検証することです。Gemini の「Grounding」機能を使えば、生成中に Google 検索を実行して、事実確認ができます。

### Grounding の仕組み

Gemini は、まず Google 検索を実行して関連情報を取得し、その上で回答を生成します。これにより、学習データの時代的ズレや推測による間違いが大幅に減少します。

### API での Grounding の実装

```javascript
const { GoogleGenerativeAI } = require("@google/generative-ai");

const client = new GoogleGenerativeAI({
  apiKey: process.env.GEMINI_API_KEY,
});

async function generateWithGrounding(prompt) {
  const model = client.getGenerativeModel({
    model: "gemini-2.0-pro",
  });

  const response = await model.generateContent({
    contents: [
      {
        parts: [
          {
            text: prompt,
          },
        ],
      },
    ],
    // Grounding を有効化
    tools: [
      {
        googleSearch: {}, // Google Search Tool を有効化
      },
    ],
  });

  // レスポンスで使用された検索結果を確認
  if (response.groundingMetadata) {
    console.log("Grounding metadata:", response.groundingMetadata);
    console.log("使用された検索結果数:", response.groundingMetadata.searchResults.length);
  }

  return response.text();
}

// 使用例
const result = await generateWithGrounding(
  "Gemini API の最新の価格情報を教えてください（2026年3月時点）"
);

console.log(result);
```

### Grounding を使うべき質問

Grounding が特に有効な場面：

- **最新ニュース**：「2026年3月のテック業界のニュースは」
- **統計データ**：「日本のスマートフォン普及率は」
- **商品情報**：「Google Gemini Pro の現在の価格は」
- **文献の存在確認**：「『○○』という本は存在しますか」
- **イベント情報**：「PyCon Japan 2026 の日程は」

### Grounding を使う際の注意

- Grounding を使うと、通常より処理時間が長くなります（Google 検索の時間分）
- 常に Grounding が必要なわけではありません。汎用知識は Grounding 不要です
- ユーザーが最新情報を求めている場合にのみ有効化しましょう

## API パラメータのチューニング

### パラメータ1：temperature（創造性と正確さのバランス）

temperature は「AI がどの程度、クリエイティブになるか」を制御します。

- **temperature = 0.0**（最低）：最も予測確度の高い単語を選ぶ（確実性重視）
- **temperature = 0.5**（中程度）：バランス型
- **temperature = 2.0**（最高）：ランダム性が高い（創造性重視）

```javascript
// ハルシネーション低減（事実重視）
const factualResponse = await model.generateContent({
  contents: [{ parts: [{ text: "日本の首都は？" }] }],
  generationConfig: {
    temperature: 0.1, // 非常に低い
  },
});

// 創造的な回答（アイデア出し）
const creativeResponse = await model.generateContent({
  contents: [{ parts: [{ text: "キャッチコピーを3つ提案してください" }] }],
  generationConfig: {
    temperature: 1.5, // 高い
  },
});
```

### パラメータ2：topP（多様性の制御）

topP は、次の単語として検討する候補の幅を制御します。

- **topP = 0.1**：最も確度の高い10%の単語のみ検討（堅い回答）
- **topP = 0.8**（デフォルト）：バランス
- **topP = 1.0**：すべての単語を検討（多様だが推測が増える）

```javascript
// 堅実な回答
const response = await model.generateContent({
  contents: [{ parts: [{ text: prompt }] }],
  generationConfig: {
    temperature: 0.2,
    topP: 0.1,
  },
});
```

### パラメータ3：topK（候補単語数の制限）

topK は、次の単語として検討する「上位K個」の単語に限定します。

```javascript
// 狭い検討範囲（堅実）
const response = await model.generateContent({
  contents: [{ parts: [{ text: prompt }] }],
  generationConfig: {
    topK: 5, // 上位5個のみ検討
  },
});

// 広い検討範囲（多様）
const response = await model.generateContent({
  contents: [{ parts: [{ text: prompt }] }],
  generationConfig: {
    topK: 40, // 上位40個を検討
  },
});
```

### 推奨設定（シーン別）

| 用途 | temperature | topP | topK |
|---|---|---|---|
| 事実情報（ニュース、統計） | 0.1-0.2 | 0.1-0.3 | 5-10 |
| テクニカル回答（コード、API） | 0.2-0.3 | 0.3-0.5 | 10-20 |
| バランス型（一般的な質問） | 0.5-0.7 | 0.7-0.9 | 20-40 |
| 創造的（アイデア、執筆） | 0.8-1.5 | 0.8-1.0 | 30-50 |

## ハルシネーション検出・防止チェックリスト

本番環境で Gemini を使う際は、以下のチェックリストを実行してください。

```javascript
async function evaluateResponse(prompt, response) {
  const checks = [];

  // チェック1: 外部リンクが含まれているか
  const hasLinks = /https?:\/\/[^\s]+/.test(response);
  checks.push({
    name: "外部リンクの有無",
    passed: hasLinks,
    note: "根拠となるリンクがあると信頼度が上がります",
  });

  // チェック2: 確信度が明示されているか
  const hasConfidence = /[0-9]{1,3}%|確信度/i.test(response);
  checks.push({
    name: "確信度の表明",
    passed: hasConfidence,
    note: "「○○だと思いますが、確実ではありません」のような表現があるか",
  });

  // チェック3: 「推測」や「おそらく」が適切に使われているか
  const hasQualifiers = /推測|おそらく|可能性|思われます|一般的には/i.test(
    response
  );
  checks.push({
    name: "慎重表現の使用",
    passed: hasQualifiers,
    note: "確実でない内容には慎重な表現が使われているか",
  });

  // チェック4: 出典が明示されているか
  const hasSource = /出典|参考|ソース|https?:/i.test(response);
  checks.push({
    name: "出典の明示",
    passed: hasSource,
    note: "具体的なデータや事実には出典があるか",
  });

  // チェック5: 回答が具体的か（あまりに一般的ではないか）
  const isVague = response.length < 100;
  checks.push({
    name: "具体性の確認",
    passed: !isVague,
    note: "100文字未満は一般的すぎる可能性",
  });

  return checks;
}
```

## よくある質問（FAQ）

### Q1：ハルシネーションを 100% 防ぐことはできますか？

**A**：残念ながら、完全には防げません。ただし、このガイドで紹介したテクニックを組み合わせることで、ハルシネーション率を 50-80% 減らすことは十分可能です。特に「Grounding + 明確なプロンプト + 低い temperature」の組み合わせは非常に有効です。

### Q2：どのパラメータが最も重要ですか？

**A**：「温度（temperature）」です。これを 0.1-0.3 に下げるだけで、ハルシネーションが大幅に減ります。ただし、創造的な回答が必要な場合は、この方法は使えません。

### Q3：Grounding はいつも有効にすべきですか？

**A**：いいえ。Grounding を有効にすると処理時間が 2-3 倍長くなります。最新情報が必要な場合のみ、つまりニュースや統計情報の質問の時だけ有効にしましょう。

### Q4：ユーザーが「本当ですか？」と聞いてきた場合、何をすべきですか？

**A**：即座に Grounding を有効にして、その質問を再度処理する、または「申し訳ありません。このトピックは確実ではありません。最新の情報を確認してください」と正直に答えるべきです。無理に根拠を作ってはいけません。

### Q5：コード生成でハルシネーションが多いです。何ができますか？

**A**：コード生成は特にハルシネーション率が高いです。対策：(1) 「実際に実行可能なコード」という制約条件を明記 (2) 存在しないライブラリを禁止 (3) Python/JavaScript など確立した言語のみ (4) 標準ライブラリを優先

## まとめ

Gemini のハルシネーションは、AI の性質上、完全には避けられません。ただし、適切なプロンプトエンジニアリングと API パラメータの調整により、大幅に低減できます。

重要なポイント：

1. **プロンプトの明確さが最優先** — 曖昧な質問は曖昧な回答を招きます
2. **Grounding を活用** — 最新情報が必要な場面では必須
3. **パラメータを調整** — 事実重視なら temperature を低く
4. **根拠を明示させる** — 「なぜそう言えるのか」を問う
5. **チェックリストで検証** — 本番環境では常に品質をチェック

さらに詳しい情報については、[Gemini API のエラーハンドリングガイド](/articles/gemini-api/gemini-api-error-handling-troubleshooting)や[Function Calling の完全ガイド](/articles/gemini-advanced/function-calling-guide)もご参考ください。

Gemini を正しく使いこなせば、強力なツールになります。ハルシネーション対策を念頭に置きながら、信頼性の高い AI ツールとして活用してください。
