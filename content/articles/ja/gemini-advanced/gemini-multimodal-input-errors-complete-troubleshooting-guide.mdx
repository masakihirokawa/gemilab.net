# Gemini マルチモーダル入力エラー完全解決ガイド — 画像・音声・動画・PDFの処理失敗を根本から直す

Gemini 2.5 Proは画像・音声・動画・PDFといったマルチモーダルな入力を扱える点が大きな強みですが、実装してみると「なぜか認識されない」「エラーの原因がわからない」という壁にぶつかることがあります。

## マルチモーダル入力の基本構造とよくある誤解

Gemini APIでマルチモーダルコンテンツを送信するには2つの方法があります。

**方法1: inline_data（データをリクエストに直接埋め込む）**

```python
import google.generativeai as genai
import base64

genai.configure(api_key="YOUR_API_KEY")
model = genai.GenerativeModel("gemini-2.5-pro")

# 画像をbase64エンコードして直接送信
with open("photo.jpg", "rb") as f:
    image_data = base64.b64encode(f.read()).decode("utf-8")

response = model.generate_content([
    {
        "inline_data": {
            "mime_type": "image/jpeg",
            "data": image_data
        }
    },
    "この画像に何が写っていますか？"
])
print(response.text)
```

**方法2: File API（ファイルを事前にアップロードして参照する）**

```python
import google.generativeai as genai

# File APIでアップロード
uploaded_file = genai.upload_file(
    path="large_video.mp4",
    mime_type="video/mp4"
)

# アップロード完了を待つ（重要！）
import time
while uploaded_file.state.name == "PROCESSING":
    time.sleep(5)
    uploaded_file = genai.get_file(uploaded_file.name)

if uploaded_file.state.name == "FAILED":
    raise ValueError(f"ファイル処理失敗: {uploaded_file.state}")

# アップロード済みファイルを参照
response = model.generate_content([
    uploaded_file,
    "この動画の内容を要約してください"
])
```

**どちらを使うべきか**:
- 20MB未満の画像・短い音声: `inline_data`が手軽
- 動画・大きなPDF・音声ファイル: `File API`（上限2GB）
- 同じファイルを繰り返し使う: `File API`（48時間キャッシュされる）

## エラーパターン①：MIME typeの不一致で画像が認識されない

**症状**: 画像を送ったのに「画像を確認できません」「テキストのみのリクエストとして処理しました」と返ってくる。

MIME typeの指定ミスが最も多い原因です。

```python
# ❌ よくある間違い
{
    "inline_data": {
        "mime_type": "image/jpg",  # ← "jpg"は不正。"jpeg"が正しい
        "data": image_data
    }
}

# ❌ 拡張子の判断ミス
# .png画像を "image/jpeg" で送ると認識エラー

# ✅ 正しいMIME typeの自動判定
import mimetypes
import pathlib

def get_mime_type(file_path: str) -> str:
    """ファイルから正しいMIME typeを取得する"""
    mime, _ = mimetypes.guess_type(file_path)
    
    # Geminiがサポートする形式の確認
    supported = {
        "image/jpeg", "image/png", "image/gif", "image/webp",
        "image/heic", "image/heif",
        "audio/wav", "audio/mp3", "audio/mpeg", "audio/ogg",
        "audio/flac", "audio/aac",
        "video/mp4", "video/mpeg", "video/mov", "video/avi",
        "video/webm", "video/wmv", "video/flv",
        "application/pdf",
        "text/plain", "text/html", "text/csv", "text/markdown"
    }
    
    if mime not in supported:
        raise ValueError(
            f"サポートされていないMIME type: {mime}\n"
            f"サポートリスト: {supported}"
        )
    
    return mime

def embed_file_inline(file_path: str, prompt: str) -> str:
    """MIME typeを自動判定してinline_dataで送信する"""
    mime_type = get_mime_type(file_path)
    
    with open(file_path, "rb") as f:
        data = base64.b64encode(f.read()).decode("utf-8")
    
    response = model.generate_content([
        {"inline_data": {"mime_type": mime_type, "data": data}},
        prompt
    ])
    return response.text
```

**よくあるMIME typeの間違い対照表:**

- `image/jpg` → ❌（`image/jpeg` が正しい）
- `audio/mp3` → ✓（`audio/mpeg` も同等）
- `video/quicktime` → ❌（`.mov`は `video/mov` を使う）
- `application/pdf` → ✓

## エラーパターン②：ファイルサイズ超過

**症状**: `400 Request payload too large` または `File exceeds maximum size`.

inline_dataで送れる上限は約20MBです。これを超える場合はFile APIを使います。

```python
import os
import google.generativeai as genai

MAX_INLINE_SIZE = 20 * 1024 * 1024  # 20MB

def smart_embed_file(file_path: str, prompt: str) -> str:
    """ファイルサイズに応じてinline_dataとFile APIを自動切り替え"""
    
    file_size = os.path.getsize(file_path)
    mime_type = get_mime_type(file_path)
    
    if file_size <= MAX_INLINE_SIZE:
        # 小さいファイルはinline_dataで直接送信
        with open(file_path, "rb") as f:
            data = base64.b64encode(f.read()).decode("utf-8")
        
        content = [
            {"inline_data": {"mime_type": mime_type, "data": data}},
            prompt
        ]
    else:
        # 大きいファイルはFile APIでアップロード
        print(f"ファイルサイズ {file_size / 1024 / 1024:.1f}MB → File APIを使用")
        
        uploaded = genai.upload_file(path=file_path, mime_type=mime_type)
        
        # 処理完了を待機
        import time
        while uploaded.state.name == "PROCESSING":
            print("処理中...", end="\r")
            time.sleep(3)
            uploaded = genai.get_file(uploaded.name)
        
        if uploaded.state.name == "FAILED":
            raise RuntimeError(f"File APIアップロード失敗: {uploaded.state}")
        
        content = [uploaded, prompt]
    
    response = model.generate_content(content)
    return response.text
```

## エラーパターン③：動画処理のタイムアウトと長尺動画の扱い

**症状**: 長い動画（10分以上）を送ると処理が極端に遅い、またはタイムアウトします。

```python
import google.generativeai as genai
import time

def process_long_video(video_path: str, prompt: str, timeout_seconds: int = 300) -> str:
    """長尺動画をFile API + ポーリングで処理する"""
    
    print(f"動画アップロード中: {video_path}")
    uploaded_file = genai.upload_file(
        path=video_path,
        mime_type="video/mp4"
    )
    
    # 処理完了を待機（タイムアウト付き）
    start_time = time.time()
    while uploaded_file.state.name == "PROCESSING":
        elapsed = time.time() - start_time
        if elapsed > timeout_seconds:
            raise TimeoutError(
                f"動画処理が{timeout_seconds}秒でタイムアウト。"
                f"動画を短く分割するか、解像度を下げてください。"
            )
        print(f"処理中... ({elapsed:.0f}秒経過)", end="\r")
        time.sleep(5)
        uploaded_file = genai.get_file(uploaded_file.name)
    
    if uploaded_file.state.name != "ACTIVE":
        raise RuntimeError(f"動画処理失敗: {uploaded_file.state.name}")
    
    print(f"\n処理完了。Geminiに分析リクエスト送信中...")
    
    # 動画分析（長い動画は応答にも時間がかかる）
    response = model.generate_content(
        [uploaded_file, prompt],
        request_options={"timeout": 120}  # 応答タイムアウトを延ばす
    )
    
    return response.text

def split_video_for_processing(video_path: str, segment_minutes: int = 10) -> list[str]:
    """長い動画をセグメントに分割する（ffmpegが必要）"""
    import subprocess
    import pathlib
    
    output_dir = pathlib.Path(video_path).parent / "segments"
    output_dir.mkdir(exist_ok=True)
    
    output_pattern = str(output_dir / "segment_%03d.mp4")
    segment_seconds = segment_minutes * 60
    
    cmd = [
        "ffmpeg", "-i", video_path,
        "-c", "copy",
        "-map", "0",
        "-segment_time", str(segment_seconds),
        "-f", "segment",
        "-reset_timestamps", "1",
        output_pattern
    ]
    
    subprocess.run(cmd, check=True, capture_output=True)
    
    return sorted(str(p) for p in output_dir.glob("segment_*.mp4"))
```

**動画処理のベストプラクティス:**

- 1時間以上の動画はFile APIの処理時間が10〜20分かかることがある
- 解像度を1080p以下に下げると処理速度が改善
- 長い動画は10〜15分単位でセグメント化し、それぞれの要約を後で統合する設計にする

## エラーパターン④：音声入力の品質問題と対応フォーマット

**症状**: 音声を送ったが文字起こし精度が低い、または「音声が含まれていません」エラーが出る。

```python
import google.generativeai as genai

def transcribe_audio(audio_path: str, language: str = "ja") -> str:
    """音声ファイルを文字起こしする"""
    
    # Geminiがサポートする音声形式
    supported_audio_formats = {
        ".wav": "audio/wav",
        ".mp3": "audio/mp3", 
        ".aac": "audio/aac",
        ".ogg": "audio/ogg",
        ".flac": "audio/flac",
        ".m4a": "audio/mp4",
        ".opus": "audio/opus"
    }
    
    import pathlib
    ext = pathlib.Path(audio_path).suffix.lower()
    
    if ext not in supported_audio_formats:
        raise ValueError(
            f"サポートされていない音声形式: {ext}\n"
            f"サポート形式: {list(supported_audio_formats.keys())}\n"
            f"ffmpegで.mp3に変換してください: ffmpeg -i input{ext} output.mp3"
        )
    
    mime_type = supported_audio_formats[ext]
    
    # 5MB以下はinline_data、以上はFile API
    file_size = pathlib.Path(audio_path).stat().st_size
    
    if file_size < 5 * 1024 * 1024:
        import base64
        with open(audio_path, "rb") as f:
            audio_data = base64.b64encode(f.read()).decode("utf-8")
        
        content = [
            {"inline_data": {"mime_type": mime_type, "data": audio_data}},
            f"この音声を文字起こしして、[{language}]言語で出力してください。"
            "句読点も適切に含めてください。"
        ]
    else:
        uploaded = genai.upload_file(path=audio_path, mime_type=mime_type)
        import time
        while uploaded.state.name == "PROCESSING":
            time.sleep(3)
            uploaded = genai.get_file(uploaded.name)
        
        content = [
            uploaded,
            f"この音声を文字起こしして、[{language}]言語で出力してください。"
        ]
    
    response = model.generate_content(content)
    return response.text

def convert_audio_to_supported_format(input_path: str, output_path: str = None) -> str:
    """サポートされていない音声形式をmp3に変換する（ffmpegが必要）"""
    import subprocess
    import pathlib
    
    if output_path is None:
        output_path = str(pathlib.Path(input_path).with_suffix(".mp3"))
    
    subprocess.run(
        ["ffmpeg", "-i", input_path, "-acodec", "libmp3lame", "-q:a", "2", output_path],
        check=True, capture_output=True
    )
    return output_path
```

## エラーパターン⑤：PDF処理の精度問題

**症状**: PDFのテキストが正しく抽出されない、または特定のページが無視されます。

```python
import google.generativeai as genai
import pathlib

def analyze_pdf_document(pdf_path: str, query: str) -> str:
    """PDFドキュメントをGeminiで分析する"""
    
    file_size = pathlib.Path(pdf_path).stat().st_size
    
    if file_size > 20 * 1024 * 1024:
        # 20MB超はFile APIを使用
        uploaded = genai.upload_file(path=pdf_path, mime_type="application/pdf")
        import time
        while uploaded.state.name == "PROCESSING":
            time.sleep(3)
            uploaded = genai.get_file(uploaded.name)
        
        content = [uploaded, query]
    else:
        # 小さいPDFはinline_data
        import base64
        with open(pdf_path, "rb") as f:
            pdf_data = base64.b64encode(f.read()).decode("utf-8")
        
        content = [
            {"inline_data": {"mime_type": "application/pdf", "data": pdf_data}},
            query
        ]
    
    response = model.generate_content(content)
    return response.text

def analyze_pdf_pages_selectively(pdf_path: str, page_numbers: list[int], query: str) -> str:
    """PDFの特定ページだけを抽出して分析する（pypdfが必要）"""
    import pypdf
    import io
    import base64
    
    reader = pypdf.PdfReader(pdf_path)
    writer = pypdf.PdfWriter()
    
    for page_num in page_numbers:
        if 0 <= page_num < len(reader.pages):
            writer.add_page(reader.pages[page_num])
    
    # 抽出したページを一時バッファに書き出す
    buffer = io.BytesIO()
    writer.write(buffer)
    buffer.seek(0)
    
    pdf_data = base64.b64encode(buffer.read()).decode("utf-8")
    
    response = model.generate_content([
        {"inline_data": {"mime_type": "application/pdf", "data": pdf_data}},
        f"ページ番号 {page_numbers} の内容について: {query}"
    ])
    return response.text
```

**PDF処理の精度を上げるコツ:**

1. スキャンされたPDFはOCR処理が必要な場合があります。Geminiは画像として処理するが、解像度が低いと認識精度が下がる
2. 大量ページのPDFは関連ページのみ抽出して送ることで処理速度と精度が向上
3. テキストベースのPDF（コピー可能なもの）は一般的により高精度

## マルチモーダルプロンプト設計のベストプラクティス

```python
def create_effective_multimodal_prompt(
    image_path: str,
    task: str,
    context: str = "",
    output_format: str = "structured"
) -> str:
    """効果的なマルチモーダルプロンプトのテンプレート"""
    
    import base64
    
    with open(image_path, "rb") as f:
        image_data = base64.b64encode(f.read()).decode("utf-8")
    
    mime_type = get_mime_type(image_path)
    
    # プロンプトの構造化
    if output_format == "structured":
        prompt = f"""
{context}

タスク: {task}

回答形式:
1. 主要な観察事項（箇条書き）
2. 詳細分析
3. 結論または推奨事項

日本語で回答してください。
""".strip()
    else:
        prompt = f"{context}\n\n{task}" if context else task
    
    response = model.generate_content([
        {"inline_data": {"mime_type": mime_type, "data": image_data}},
        prompt
    ])
    return response.text

# 複数画像の比較分析
def compare_images(image_paths: list[str], comparison_prompt: str) -> str:
    """複数の画像を比較分析する"""
    
    content = []
    
    for i, path in enumerate(image_paths, 1):
        with open(path, "rb") as f:
            data = base64.b64encode(f.read()).decode("utf-8")
        
        content.append(f"=== 画像 {i}: {path} ===")
        content.append({
            "inline_data": {
                "mime_type": get_mime_type(path),
                "data": data
            }
        })
    
    content.append(comparison_prompt)
    
    response = model.generate_content(content)
    return response.text
```

## エラー発生時のデバッグチェックリスト

実際にエラーが発生したときは、以下の順序で確認してください。

1. **MIME typeの確認**: `print(get_mime_type(file_path))` で実際の値を確認
2. **ファイルサイズの確認**: `os.path.getsize(file_path)` で20MB超かどうかを確認
3. **File APIの状態確認**: `uploaded.state.name` が `"ACTIVE"` になるまで待機しているか
4. **応答のstop_reasonを確認**: `response.candidates[0].finish_reason` が `"STOP"` 以外なら警告
5. **セーフティフィルター確認**: `response.prompt_feedback` に安全フィルターによるブロックがないか

```python
def debug_multimodal_response(response):
    """マルチモーダルレスポンスのデバッグ情報を出力する"""
    
    print(f"=== Multimodal Response Debug ===")
    
    if response.prompt_feedback:
        print(f"Prompt feedback: {response.prompt_feedback}")
    
    for i, candidate in enumerate(response.candidates):
        print(f"\nCandidate {i}:")
        print(f"  finish_reason: {candidate.finish_reason}")
        
        if candidate.finish_reason.name != "STOP":
            print(f"  ⚠ 異常な終了理由: {candidate.finish_reason.name}")
            if hasattr(candidate, "safety_ratings"):
                print(f"  safety_ratings: {candidate.safety_ratings}")
        
        if candidate.content and candidate.content.parts:
            for part in candidate.content.parts:
                if hasattr(part, "text"):
                    print(f"  text preview: {part.text[:200]}...")
```

## まとめ

Gemini APIのマルチモーダル入力エラーの多くは、以下の原因に集約できます。

- MIME typeの誤り → 自動判定ユーティリティを実装して防ぐ
- ファイルサイズ超過 → 20MB以上はFile API、それ以下はinline_dataと使い分ける
- File APIの処理待ちを無視 → ACTIVE状態になるまでポーリングする
- 長尺動画のタイムアウト → セグメント分割と適切なタイムアウト設定
- 音声フォーマット非対応 → ffmpegでmp3/wavに変換してから送る

マルチモーダル処理は正しいファイル前処理と送信方法の選択が鍵です。本記事のパターンを組み合わせることで、ほとんどの実装課題は解決できます。
