Gemini にまとめてもらった企画メモを「Docs にエクスポート」で書き出し、そのまま関係者に送ろうとして、共有ダイアログの前でふと手が止まることがあります。開いたドキュメントは見慣れた画面なのに、これを誰が開けるのか、自分の側から説明できないのです。

公式ヘルプを読み直すと、理由が分かりました。書き出しの手順と「新しいドキュメントがドライブに保存される」ことは載っていますが、そのファイルの所有者や共有の初期状態には触れていません。書かれていないものを、私は「たぶん自分だけ」と思い込んで進めようとしていたのです。

**書き出した直後は、共有する前に、まず誰が開けるかを自分の目で確かめます。** この線引きにしてから、送る前の確認が一分で済むようになりました。

以下では、確かめる場所を三つ、共有フォルダに移したときの注意、数が増えたときの棚卸しを、順にお伝えします。

## 公式ヘルプが書いていること、書いていないこと

Gemini アプリのヘルプ「Export responses from Gemini Apps」には、書き出し先ごとの手順が載っています。共有に関わる部分だけ抜き出すと、次のとおりです。

仕事用や学校用のアカウントでは、書き出せる先が管理者の設定で変わるとも書かれています。つまり、同じ操作をしても、隣の席の方と同じ結果になるとは限りません。

もう一つ、見落としやすいのは Replit の行です。書き出し先のサービスの規約がそのまま適用され、無料アカウントでは公開になります。Docs の話ではありませんが、「書き出す」という操作が外へ出ることを意味する例として、頭に置いておく価値があります。

## 書き出した直後に開く三か所

書き出したら、共有の相手を選ぶ前に、次の三か所を上から順に見ます。

1. **共有ダイアログの「一般的なアクセス」**: 右上の「共有」を開き、「制限付き」になっているかを見ます。「リンクを知っている全員」や、組織内の全員になっていないかを確かめる場所です。
2. **ファイルの置き場所**: タイトルの横のフォルダのアイコン、またはドライブ側の表示で、どのフォルダの中にあるかを見ます。次の節で書くとおり、フォルダの共有設定は中のファイルへ引き継がれます。
3. **自分以外の追加済みの人**: ダイアログ上部の一覧に、自分以外の名前が並んでいないかを見ます。

どれも十秒で終わります。ただ、三か所を見るという順番が、あとで効いてきます。一般的なアクセスが「制限付き」でも、置き場所が共有フォルダなら、フォルダの権限で開ける人がいるからです。

## 共有フォルダに移すと、権限がついてきます

ドライブのヘルプ「Google ドライブでフォルダを共有する」には、親フォルダの権限は中のすべてのファイルとフォルダに引き継がれ、あとから追加したファイルも同じ権限を受け継ぐと書かれています。共有フォルダの中のファイルは、フォルダと同じか、それより高い共有権限になるとも説明されています。

ここで、Gemini の書き出しと組み合わせたときの落とし穴が見えてきます。

- 書き出した直後は、自分しか開けない状態かもしれません（ヘルプには書かれていないので、私は確かめるまで断定しません）。
- そのドキュメントを「あとで整理しよう」と、チームの共有フォルダへ移します。
- 移した瞬間から、そのフォルダを見られる全員が、下書きのメモを開けるようになります。

回答の中に、取引先の名前や、まだ決まっていない金額が入っていたらどうでしょう。共有のボタンを一度も押していないのに、見える範囲が広がるのです。

だから、共有フォルダへ移す前にも、同じ三か所を見ます。移す先のフォルダの共有範囲を知らないまま移す、というのが、いちばん起きやすい場面です。

## 書き出したものが増えてきたら、Apps Script で棚卸しします

私自身、個人開発の資料づくりで書き出しを重ねるうちに、どれを共有してどれを残したのか、目では追えなくなりました。ドキュメントが十件を超えたあたりから、一覧で確かめる方が早いと感じています。

Apps Script の DriveApp には、ファイルの共有状態を返すメソッドがあります。確認したいドキュメントの ID を並べて、状態を一行ずつ出す最小の例です。

```javascript
function listSharingState() {
  // 確認したいドキュメントの ID（URL の /d/ と /edit の間の文字列）
  const ids = ['YOUR_DOC_ID_1', 'YOUR_DOC_ID_2'];
  ids.forEach(function (id) {
    const f = DriveApp.getFileById(id);
    const parents = f.getParents();
    const folder = parents.hasNext() ? parents.next().getName() : '(親フォルダなし)';
    // getSharingAccess: PRIVATE / DOMAIN / ANYONE_WITH_LINK など
    console.log([
      f.getName(),
      f.getSharingAccess(),
      f.getSharingPermission(),
      '編集者 ' + f.getEditors().length + ' 人',
      '置き場所: ' + folder
    ].join(' | '));
  });
}
```

実行時に、ドライブへのアクセス許可を求める画面が出ます。許可の範囲を読んで、自分のドキュメントだけを対象にする使い方に限るのが安心です。

出力の見方は単純です。`PRIVATE` 以外が並んだ行と、置き場所が共有フォルダの行だけを拾って、そのファイルの共有ダイアログを開き直します。コードは、確認の入り口を作るものにとどめておくのがちょうどよいと、いまは思っております。

## 迷ったとき、直らないときの次の一手

- **ダイアログの表示が、想像と違う**: 仕事用や学校用アカウントでは、管理者が外部共有や「リンクを知っている全員」を制限していることがあります。画面に選択肢が出ないのは、不具合ではなく管理側の設定の可能性が高いです。管理者に聞くときは、「どの共有範囲が組織で許されているか」を一文で尋ねると話が早く済みます。
- **Sheets に書き出したのに、保存されない**: 画像を含む表は書き出せません。表だけを回答に残す形で、もう一度頼み直します。
- **Gmail に書き出したのに、送られていない**: 下書きが作られるだけです。送信ボタンを押すまで、相手には届きません。

どの場合も、先に確かめるのは自分の画面です。ヘルプに書かれていないことは、想像で埋めずに、共有ダイアログと置き場所で答えを取りにいきます。

## 次にやること

次に Gemini の回答を Docs へ書き出すときは、共有する前に、共有ダイアログの「一般的なアクセス」だけ開いてみてください。最初は一か所で十分です。三か所を見る習慣は、その次の書き出しで足せばよいと思います。

私もこの確認だけは、どれほど急いでいる日でも省かないようにしています。
