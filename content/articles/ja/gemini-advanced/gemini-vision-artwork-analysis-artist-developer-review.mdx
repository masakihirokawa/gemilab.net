2019 年の春、吉祥寺駅のホームから空を見上げたとき、光の輪が浮かんでいました。

肉眼では説明のつかない円弧が、曇天を背景に静かに広がっていた。その瞬間から、私の視覚表現に対するアプローチが変わったと今でも感じています。光が持つ構造、空間に刻まれる意味、見る人の視線がどこに引き寄せられるか。絵を描くことも、アプリの UI を設計することも、以来ずっとその問いと一緒にあります。

だから「Gemini Vision が画像をどう読むか」という問いは、純粋に興味深いテーマでした。AI は光の輪をどう分析するのか。国際芸術賞 17 冠を受賞した自分の作品を、どのくらい正確に読み取るのか。2025 年末から 2026 年にかけて、実際に試してきたことをここに書きます。

## Gemini Vision に渡した 4 枚のアートワーク

私が Gemini Vision に渡したのは、自分の作品の中から意図的に選んだ 4 枚です。

- **作品 A**: 光の散乱をテーマにした抽象画。神社で撮影した写真から色彩を抽出し、デジタルで再構成したもの
- **作品 B**: 群衆の動きを記録した長時間露光写真。「集団心理の可視化」を意図した作品
- **作品 C**: 余白を大量に使ったシンプルな構図。和紙の質感を模したテクスチャが特徴
- **作品 D**: 壁紙アプリで高評価を得たパターン系の作品。2014 年から個人開発を続けてきた壁紙アプリシリーズで、累計 5,000 万ダウンロードを超えた中でも特に人気の高いシリーズ

4 枚を選んだ理由は「AI が何を見るか」のスペクトルを広げたかったからです。意図が明確な作品、意図が複数ある作品、意図を隠した作品、ビジネス的に成功した作品、それぞれを混ぜました。

## Gemini Vision の分析コード（Python）

分析には Gemini 2.5 Flash を使いました。Flash は応答が速く、画像 1 枚あたりのコストが抑えられるため、複数枚を試すのに向いています。

```python
import google.generativeai as genai
from pathlib import Path
import json, base64

genai.configure(api_key="YOUR_GEMINI_API_KEY")
model = genai.GenerativeModel("gemini-2.5-flash")

def analyze_artwork(image_path: str, mode: str = "general") -> dict:
    """アートワークを Gemini Vision で分析する"""
    
    prompts = {
        "general": """
            この画像を視覚的に分析してください。
            以下の観点で JSON 形式で答えてください:
            - "dominant_colors": 支配的な色 3〜5 色（hex コードと名称）
            - "composition_style": 構図の特徴（3 文以内）
            - "emotional_tone": 感情的なトーン（例: 内省的・静寂・緊張）
            - "visual_focus": 視線が最初に向かう場所
            - "cultural_hints": 文化的・地域的な要素があれば
            - "keywords": タグとして使える英語キーワード 5〜7 個
        """,
        "wallpaper_fit": """
            この画像がスマートフォン壁紙として機能するか評価してください（JSON形式）:
            - "suitability_score": 壁紙適合度 1〜10
            - "target_mood": 想定されるユーザーの気分・場面
            - "icon_readability": アイコンの視認性への影響（良い・普通・悪い）
            - "suggested_category": 壁紙カテゴリの提案
            - "improvement_hints": 改善の提案（あれば）
        """
    }
    
    image_bytes = Path(image_path).read_bytes()
    encoded = base64.b64encode(image_bytes).decode()
    
    ext = Path(image_path).suffix.lower()
    mime_map = {
        ".jpg": "image/jpeg", ".jpeg": "image/jpeg",
        ".png": "image/png", ".webp": "image/webp"
    }
    mime_type = mime_map.get(ext, "image/jpeg")
    
    response = model.generate_content([
        prompts[mode],
        {"mime_type": mime_type, "data": encoded}
    ])
    
    text = response.text
    start, end = text.find("{"), text.rfind("}") + 1
    if start != -1 and end > start:
        return json.loads(text[start:end])
    return {"raw_response": text}

# 使用例
result = analyze_artwork("artwork_a.jpg", "general")
print(json.dumps(result, ensure_ascii=False, indent=2))
# 期待する出力例:
# {
#   "dominant_colors": [{"hex": "#F5E6C8", "name": "温かみのある白"},...],
#   "emotional_tone": "内省的・静寂",
#   "visual_focus": "画面中央やや上"
# }
```

実行時間は 1 枚あたり 1.5〜3 秒、コストは 1 枚あたり約 0.003 円（2026 年 5 月時点の Flash 料金）です。

## 何が正確で、何がずれていたか

結果を正直に書きます。

**作品 A（光の散乱・抽象画）**: Gemini の分析はかなり的確でした。「支配的な色」として返ってきた 5 色はほぼ意図通りで、「感情的なトーン」も「内省的・静寂」と返ってきました。ただし「文化的な要素」については「日本の禅的な美意識」と表現されました。私の作品テーマは「日本特有の祈りを背景にした、集団心理と認知世界の構造の探求」です。表面的な「静寂」は拾えていたものの、その奥にある緊張感は読み取れていませんでした。

**作品 B（群衆・長時間露光）**: ここが一番面白かったです。Gemini は「視線が最初に向かう場所」として画面中央ではなく、左上の光源を指摘しました。私自身は中央の群衆の流れを意図していたのに、AI は別の場所を優先した。後から作品を見直すと、確かに左上への引力があります。自分では意識していなかった構成要素を、Gemini が抽出していました。

**作品 C（余白・和紙）**: キーワードとして "minimalism", "Japanese aesthetic", "meditative" が返ってきました。これは悪くありません。ただ「壁紙適合度」は 6/10 と低く、「アイコンの視認性への影響: 普通」という評価でした。アート作品としては正しく読まれているのに、壁紙という用途に対しては保守的な評価が出ました。

**作品 D（パターン・商業成功）**: 壁紙適合度が 9/10 と高く評価されました。「target_mood: 日常使いでリラックスできる」「suggested_category: Nature / Texture」という結果は、実際にアプリ内でユーザーからよく選ばれるカテゴリと一致していました。ビジネス的に成功した作品を、AI も適切に評価していた点は興味深い確認でした。

## 壁紙アプリへの実用的な応用

この実験を経て、壁紙アプリの開発ワークフローに Gemini Vision を組み込んでいます。具体的には以下の 3 つです。

### アプリ説明文の自動生成

App Store の壁紙説明文は、これまで手動で書いていました。同じような文言が続くと SEO 的にも不利ですし、何より飽きます。今は Gemini Vision の分析結果をベースに説明文を生成しています。

```python
def generate_app_description(analysis: dict, locale: str = "ja") -> str:
    """分析結果から App Store 向け説明文を生成"""
    model = genai.GenerativeModel("gemini-2.5-flash")
    
    if locale == "ja":
        prompt = f"""
        以下のアートワーク分析データをもとに、
        壁紙アプリ向けの説明文を日本語 80 字前後で書いてください。
        ユーザーが壁紙を使うシーンを想起させ、SEO キーワードを自然に含める形で。
        
        分析データ: {json.dumps(analysis, ensure_ascii=False)}
        """
    else:
        prompt = f"""
        Write a 50-word App Store description for a wallpaper app.
        Based on: {json.dumps(analysis)}
        Evoke the scene where users would use this wallpaper. Include natural SEO keywords.
        """
    
    return model.generate_content(prompt).text.strip()
```

実際に使ってみると、作り手の視点ではなく「壁紙を使う人の朝」を書いてくれることが多く、ユーザー視点の説明文が出やすいと感じています。

### カテゴリタグの自動付与とパフォーマンス予測

`suggested_category` と `keywords` を組み合わせてカテゴリ候補を自動生成するようにしました。正答率はおよそ 85〜90% で、残りの 10〜15% を自分でレビューしています。また `suitability_score` と実際のダウンロード数を比較したところ、スコア 7 以上の作品はダウンロード数が高い傾向がありました。完全な予測ツールにはなりませんが、一次スクリーニングとして機能しています。

## Gemini Vision の現在の限界

正直に書いておくべきことがあります。

**抽象表現の「意図」は読めない**: Gemini は形と色は読めますが、作品に込められた概念的な意図は取れません。作品 A の「集団心理の構造」という主題は、どうやっても分析テキストには出てきませんでした。文化的な文脈、制作者の意図、作品の背景知識が必要な読み取りは、現状では人間の目が必要です。

**「アート的価値」と「機能的価値」を混同する**: 壁紙として優秀かどうかと、アートとして優れているかどうかは別物です。Gemini は前者を評価するのが得意ですが、後者の判断は苦手です。この区別を明確にして使うことが重要だと感じています。

**光の質感の表現に限界がある**: 吉祥寺で見た光の輪のような、言語化しにくい光の体験を画像で表現しても、Gemini はそれを「glare effect」「lens flare like pattern」と表現します。機能的な説明はできても、体験の核心には届かありません。この限界は批判ではなく、確認です。Gemini Vision がどこまでできてどこからは人間の判断が必要か、明確になったことは大きな収穫でした。

## Gemini Vision は私の作品を「正しく」見たか

私の作品の主題は「日本特有の祈りを背景に、集団心理と認知世界の構造、根源意識を探る」というものです。写真と映像を主な表現媒体とし、IAA（国際芸術賞）や ARC Salon、London Photo Festival など国際的な場で17の受賞歴があります。

この作品群のうち数点を Gemini Vision API に送り、「この画像が伝えようとしていることを分析してください」と問いかけました。

返ってきた回答は、色彩の分布、構図のバランス、光と影の関係、そして「静謐さ」「内省的なトーン」を丁寧に言語化したものでした。一読して、正直に言えば「だいたい合っている」という感触でした。

**的確だった点**

色温度と光の方向性の読み取りは、かなり精度が高かったです。「遠景と前景の間に意図的な張力がある」「中心から外縁に向かうにつれ焦点が意図的にぼかされている」という指摘は、制作時に意識していた要素と一致していました。また、「人物が主体ではなく、空間そのものが主語になっている」という解釈は、自分が最も大切にしているコンセプトの核心に近い読み取りでした。

**限界を感じた点**

「祈り」という日本文化に深く根ざした概念は、Gemini にはやはり薄く見えるようです。「spiritual atmosphere」という英語的な解釈に落とし込まれてしまい、東アジアの信仰構造に特有の「静けさの中の緊張」「見えないものへの畏れ」は十分に読み取れませんでした。

これは Gemini の限界というより、英語中心のトレーニングデータの構造的な問題だと理解しています。日本語で同じ作品を問いかけると、多少ニュアンスが変わる場面もありました。

## Gemini Vision API を使った作品分析の実装

技術的な検証として、次のようなコードで画像を送信し、分析結果を取得しました。

```python
import google.generativeai as genai
from pathlib import Path

genai.configure(api_key="YOUR_GEMINI_API_KEY")

model = genai.GenerativeModel("gemini-2.5-pro")

def analyze_artwork(image_path: str, prompt: str = None) -> str:
    """
    アート作品の画像を Gemini Vision で分析する。
    image_path: 画像ファイルのパス（JPEG/PNG対応）
    prompt: 分析の観点（省略時はデフォルトのアート分析プロンプトを使用）
    """
    if prompt is None:
        prompt = """
        この作品が持つ視覚的な特徴と、伝えようとしているテーマについて分析してください。
        以下の観点を含めて説明してください：
        - 構図と空間の使い方
        - 色彩と光の特性
        - 感情的なトーンと雰囲気
        - 作品が示唆するテーマや物語
        日本語で回答してください。
        """
    
    image_data = Path(image_path).read_bytes()
    
    # 画像の MIME タイプを拡張子から判定
    suffix = Path(image_path).suffix.lower()
    mime_map = {".jpg": "image/jpeg", ".jpeg": "image/jpeg", ".png": "image/png"}
    mime_type = mime_map.get(suffix, "image/jpeg")
    
    response = model.generate_content([
        {"mime_type": mime_type, "data": image_data},
        prompt
    ])
    
    return response.text

# 使用例
result = analyze_artwork("my_artwork.jpg")
print(result)

# 期待する出力例:
# この作品は、強い水平線を軸に遠景と前景を分断した構図を持ちます。
# 光源が画面右上に設定されており、影の方向性が画面左下に統一されています。
# 全体のトーンはモノクロームに近い低彩度で統一されており、
# 人物の不在が逆に「気配」として空間を支配しています。
# 静謐で内省的でありながら、どこか緊張を含んだ情景です。
```

処理時間は通常2〜5秒。1点あたりのコストは Gemini 2.5 Pro で0.02〜0.06円程度でした（解像度と入力トークン数による）。アート作品は情報量が多いため、通常の壁紙画像より若干コストが高くなる傾向があります。

## 壁紙アプリ開発との接点 — 「使える」と判断した場面

アート作品の分析とは別に、壁紙アプリ運営の文脈でも Gemini Vision は効果的でした。累計5,000万ダウンロードを超えるアプリを運営していると、日々大量の画像を扱います。その中で「どの画像がユーザーに好まれるか」「どのカテゴリに分類すべきか」という判断を、従来は手動かルールベースの分類器で行っていました。

Gemini Vision に切り替えてみて感じたのは、**「色調の一貫性チェック」が特に精度高く機能した**ことです。「この壁紙は午前中の光のトーンか夕方のトーンか」という問いに対して、かなり人間の感覚に近い答えが返ってきました。また、「この画像は縦画面でスマートフォン壁紙として使ったとき、通知アイコンが読みやすいか」という実用的な問いにも、概ね正確な判断ができます。

一方で、「引き寄せ系」「癒し系」という日本のアプリジャンル特有のニュアンスは、英語で学習したモデルには難しい部分があります。「healing」「calming」という英語訳では拾えない感性的な要素があり、この点はジャンル固有のプロンプト設計で補完する必要があります。詳しい実装については[壁紙アプリの自動カテゴリ分類の実装例](/articles/gemini-api/gemini-api-wallpaper-image-auto-categorization-mobile-app)も参考になります。

## 「見る」という行為の非対称性

この検証を通じて、最も興味深かったのは技術的な精度の問題ではありませんでした。

AI が「見る」とき、それは常に既存の言語化されたパターンへの照合です。色とテクスチャとコンポジションを既知の概念に結びつける処理です。一方、アーティストが「見る」とき、それは既存の言語を超えたものへの到達を目指す行為でもあります。作品を作るとき、私は「言えないこと」を画面に残そうとしています。

Gemini はその「言えないこと」を非常に上手に言語化します。それは能力の証明であると同時に、根本的な非対称性の露わになる瞬間でもあります。

2019年、吉祥寺駅上空に光の輪を見た瞬間、視覚表現への確信が来ました。それ以来、「直感が先にあり、言葉はその後を追う」という作り方を意識してきました。Gemini はこの順序を逆に、言葉から始めて視覚に向かいます。どちらが正しいという話ではなく、この方向性の違いが「見ている」という動詞の意味を問いかけます。

この体験は、AI が「作品を見ている」のか「作品を読んでいる」のかという問いを私に残しました。どちらでも正しいかもしれませんし、どちらでもないかもしれません。しかし、この問いは制作の姿勢を鋭くするためにも有効でした。

## 不完全な解釈の価値

批判的な観察をしつつも、私はいまも Gemini Vision API を使い続けています。

理由はシンプルです。「完璧でない視点が、新しい気づきを生む」から。

自分の作品への解説として納得できない部分があるとき、それは「なぜ Gemini はそう読んだのか」という問いに変わります。その問いの向こうに、自分が無意識に込めていた意図が見つかることがあります。こう言えば聞こえが良いかもしれませんが、実際のところ「そうじゃない」と思いながら AI の解釈を読む時間は、制作のフィードバックとして機能し始めています。

両家の祖父が宮大工だったので、「手を動かすことが一つの信心」という感覚を近くで見て育ちました。コードを書くことも、作品を作ることも、この感覚に近いと思っています。AI との対話もその一つになりつつあります。
