## 取り組みの背景

「会議が終わった後の議事録作成に毎回1時間かかっている」「タスクの抜け漏れが多く、フォローアップが大変」——こうした課題を抱えているチームは非常に多いでしょう。

Gemini APIのマルチモーダル機能とFunction Callingを組み合わせることで、Google Meet会議を**完全に自動化されたデータ処理パイプライン**に変えることができます。会議終了から5分以内に、整形された議事録・担当者別タスクリスト・次回アクションがメールで届く——そんなシステムを本番レベルで構築するのがこの記事の目標です。

[Gemini で議事録を自動作成・要約する実践ガイド](/articles/gemini-workspace/gemini-meeting-notes-auto-summary-guide)では、Gemini + Google Docsの基本的な活用法を紹介しました。本記事はその**上級編**として、Gemini APIとPython、Apps Scriptを組み合わせた本番グレードのシステム実装に焦点を当てます。

### この記事で実装するシステムの全体像

会議終了 → Google Drive録音ファイル保存 → Google Apps Script がトリガー → Python Cloud Function で Gemini API 呼び出し → 文字起こし・要約・タスク抽出 → Google Sheets 登録 + Gmail 送信 + Google Calendar フォローアップ登録

## Google Drive × Apps Script: 自動トリガー設定

### Step 1: Driveフォルダへの録音ファイル保存

Google Meetの録音は、管理者設定によりGoogle Driveの指定フォルダに自動保存されます。この仕組みを利用して、ファイル保存イベントをトリガーにパイプラインを起動します。

### Step 2: Apps Scriptによるファイル検知

以下のApps Scriptをプロジェクトに追加し、時間主導トリガー（5分間隔）として設定します。

```javascript
// Code.gs — Google Apps Script
const DRIVE_FOLDER_ID = 'YOUR_DRIVE_FOLDER_ID';
const CLOUD_FUNCTION_URL = 'https://YOUR_REGION-YOUR_PROJECT.cloudfunctions.net/process-meeting';
const PROCESSED_LABEL = 'processed';

function checkNewMeetingRecordings() {
  const folder = DriveApp.getFolderById(DRIVE_FOLDER_ID);
  const files = folder.getFiles();

  while (files.hasNext()) {
    const file = files.next();
    const fileName = file.getName();

    // Google Meet録音ファイルの識別（.mp4形式）
    // かつ未処理タグがついていないもの
    if (fileName.includes('Meet') &&
        fileName.endsWith('.mp4') &&
        !file.getDescription().includes(PROCESSED_LABEL)) {

      const fileId = file.getId();
      const createdDate = file.getDateCreated();

      // 直近1時間以内のファイルのみ処理
      const oneHourAgo = new Date(Date.now() - 60 * 60 * 1000);
      if (createdDate > oneHourAgo) {
        triggerProcessing(fileId, fileName, file);
      }
    }
  }
}

function triggerProcessing(fileId, fileName, file) {
  // Cloud FunctionへPOSTリクエスト
  const payload = {
    file_id: fileId,
    file_name: fileName,
    created_at: new Date().toISOString()
  };

  const options = {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    payload: JSON.stringify(payload),
    muteHttpExceptions: true
  };

  const response = UrlFetchApp.fetch(CLOUD_FUNCTION_URL, options);

  if (response.getResponseCode() === 200) {
    // 処理済みフラグを設定
    file.setDescription(PROCESSED_LABEL);
    console.log(`処理開始: ${fileName}`);
  } else {
    console.error(`エラー: ${response.getContentText()}`);
  }
}
```

## Pythonパイプライン: 文字起こしと構造化要約

### Step 3: Gemini APIによる音声文字起こし

Gemini 2.5 Proは音声ファイルを直接入力として受け取り、高精度な文字起こしが可能です。以下はCloud Functionとして実装するメインパイプラインです。

```python
# main.py — Cloud Function エントリポイント
import os
import json
from pathlib import Path
from datetime import datetime
import google.generativeai as genai
from google.oauth2 import service_account
from googleapiclient.discovery import build
from googleapiclient.http import MediaIoBaseDownload
import io
import functions_framework

# Gemini API設定
genai.configure(api_key=os.environ['GEMINI_API_KEY'])
model = genai.GenerativeModel('gemini-2.5-pro')

@functions_framework.http
def process_meeting(request):
    """Cloud Function: 会議録音を処理するメインエントリポイント"""
    request_json = request.get_json()
    file_id = request_json.get('file_id')
    file_name = request_json.get('file_name')

    try:
        # 1. Drive からファイルをダウンロード
        audio_data = download_from_drive(file_id)

        # 2. Gemini API で文字起こし
        transcript = transcribe_audio(audio_data, file_name)

        # 3. 構造化要約の生成
        summary = generate_structured_summary(transcript)

        # 4. Function Calling でタスク抽出
        tasks = extract_tasks_with_function_calling(transcript)

        # 5. Sheets へ保存
        save_to_sheets(summary, tasks, file_name)

        # 6. メール送信
        send_meeting_report(summary, tasks, file_name)

        return {'status': 'success', 'tasks_count': len(tasks)}, 200

    except Exception as e:
        print(f"Error processing {file_name}: {e}")
        return {'status': 'error', 'message': str(e)}, 500

def download_from_drive(file_id: str) -> bytes:
    """Google Drive からファイルをダウンロード"""
    creds = service_account.Credentials.from_service_account_file(
        'service-account.json',
        scopes=['https://www.googleapis.com/auth/drive.readonly']
    )
    service = build('drive', 'v3', credentials=creds)

    request = service.files().get_media(fileId=file_id)
    buffer = io.BytesIO()
    downloader = MediaIoBaseDownload(buffer, request)

    done = False
    while not done:
        _, done = downloader.next_chunk()

    return buffer.getvalue()

def transcribe_audio(audio_data: bytes, file_name: str) -> str:
    """Gemini APIで音声を文字起こし"""
    # Gemini Files APIにアップロード
    import tempfile
    with tempfile.NamedTemporaryFile(suffix='.mp4', delete=False) as tmp:
        tmp.write(audio_data)
        tmp_path = tmp.name

    uploaded_file = genai.upload_file(tmp_path, mime_type='video/mp4')

    prompt = """
    この会議録音を正確に文字起こしてください。
    - 発言者が特定できる場合は「[話者A]:」のように記載してください
    - 聞き取れない箇所は[不明]と記載してください
    - 技術用語や固有名詞はそのままカタカナ/英語で記載してください
    - タイムスタンプを[MM:SS]形式で5分ごとに挿入してください
    """

    response = model.generate_content([prompt, uploaded_file])

    # 一時ファイルとアップロードファイルのクリーンアップ
    os.unlink(tmp_path)
    uploaded_file.delete()

    return response.text
```

### Step 4: 構造化要約の生成

単なる文字起こしではなく、**構造化されたビジネス向け要約**を生成します。

```python
def generate_structured_summary(transcript: str) -> dict:
    """Gemini APIで構造化要約を生成"""

    prompt = f"""
    以下の会議の文字起こしから、構造化されたビジネス要約を生成してください。

    # 出力フォーマット（JSON）
    {{
      "meeting_title": "会議タイトルまたはトピック",
      "date": "YYYY-MM-DD",
      "duration_minutes": 数値,
      "attendees": ["参加者リスト（推定）"],
      "executive_summary": "3文以内のエグゼクティブサマリー",
      "key_decisions": ["決定事項リスト"],
      "discussion_points": [
        {{"topic": "議題名", "summary": "議論の要約", "outcome": "結論"}}
      ],
      "risks_concerns": ["懸念事項・リスク"],
      "next_meeting_agenda": ["次回の議題候補"]
    }}

    # 文字起こし
    {transcript[:8000]}  # トークン制限を考慮して先頭8000文字

    必ずJSON形式のみで返答してください。
    """

    response = model.generate_content(
        prompt,
        generation_config=genai.GenerationConfig(
            response_mime_type='application/json',
            temperature=0.2  # 構造化出力は低temperatureで安定性向上
        )
    )

    return json.loads(response.text)
```

## Function Calling: タスク抽出の実装

Function Callingは、Gemini APIの最も強力な機能の一つです。会議の文字起こしから**担当者・期限・優先度が付いたタスクリスト**を構造化データとして抽出できます。

### Step 5: Function定義とタスク抽出

```python
def extract_tasks_with_function_calling(transcript: str) -> list[dict]:
    """Function Callingでタスクを構造化抽出"""

    # タスク登録用のFunction定義
    register_task_func = genai.protos.FunctionDeclaration(
        name='register_task',
        description='会議で発生したタスクや決定事項を登録する',
        parameters=genai.protos.Schema(
            type=genai.protos.Type.OBJECT,
            properties={
                'task_title': genai.protos.Schema(
                    type=genai.protos.Type.STRING,
                    description='タスクの簡潔なタイトル（30文字以内）'
                ),
                'description': genai.protos.Schema(
                    type=genai.protos.Type.STRING,
                    description='タスクの詳細説明'
                ),
                'assignee': genai.protos.Schema(
                    type=genai.protos.Type.STRING,
                    description='担当者名（不明な場合は「未定」）'
                ),
                'due_date': genai.protos.Schema(
                    type=genai.protos.Type.STRING,
                    description='期限（YYYY-MM-DD形式、言及がない場合は「未定」）'
                ),
                'priority': genai.protos.Schema(
                    type=genai.protos.Type.STRING,
                    enum=['高', '中', '低'],
                    description='優先度'
                ),
                'category': genai.protos.Schema(
                    type=genai.protos.Type.STRING,
                    enum=['調査', '実装', '確認', '連絡', '設計', 'その他'],
                    description='タスクカテゴリ'
                )
            },
            required=['task_title', 'description', 'assignee', 'priority']
        )
    )

    tool = genai.protos.Tool(function_declarations=[register_task_func])
    model_with_tools = genai.GenerativeModel(
        model_name='gemini-2.5-pro',
        tools=[tool]
    )

    prompt = f"""
    以下の会議の文字起こしを分析し、明示的または暗黙的に発生した
    全てのタスク・アクションアイテムを register_task 関数で登録してください。

    重要: 以下のパターンに注意して抽出してください
    - 「〜しておきます」「〜やっておきます」→ タスク
    - 「〜を確認します」「〜を調べます」→ タスク
    - 「〜までに」「来週まで」→ 期限
    - 名前 + 動詞 → 担当者の特定

    全タスクを漏れなく登録した後、"完了"とだけ返答してください。

    文字起こし:
    {transcript[:6000]}
    """

    response = model_with_tools.generate_content(prompt)

    tasks = []
    # Function Callsを解析してタスクリストを構築
    for part in response.candidates[0].content.parts:
        if hasattr(part, 'function_call') and part.function_call.name == 'register_task':
            task_args = dict(part.function_call.args)
            tasks.append(task_args)

    print(f"抽出されたタスク数: {len(tasks)}")
    return tasks
```

## Google Sheets連携: タスク管理ダッシュボード

### Step 6: Sheetsへの自動登録

抽出したタスクをGoogle Sheetsに自動登録し、チーム全体で可視化できる状態にします。

```python
def save_to_sheets(summary: dict, tasks: list[dict], file_name: str):
    """Google Sheetsにデータを保存"""
    creds = service_account.Credentials.from_service_account_file(
        'service-account.json',
        scopes=['https://www.googleapis.com/auth/spreadsheets']
    )
    service = build('sheets', 'v4', credentials=creds)
    spreadsheet_id = os.environ['SPREADSHEET_ID']

    # 1. 議事録サマリーシートに追記
    summary_row = [[
        datetime.now().strftime('%Y-%m-%d %H:%M'),
        summary.get('meeting_title', ''),
        summary.get('duration_minutes', ''),
        ', '.join(summary.get('attendees', [])),
        summary.get('executive_summary', ''),
        '\n'.join(summary.get('key_decisions', [])),
        file_name
    ]]

    service.spreadsheets().values().append(
        spreadsheetId=spreadsheet_id,
        range='議事録サマリー!A:G',
        valueInputOption='USER_ENTERED',
        body={'values': summary_row}
    ).execute()

    # 2. タスクシートに各タスクを追記
    meeting_date = datetime.now().strftime('%Y-%m-%d')
    task_rows = []
    for task in tasks:
        task_rows.append([
            meeting_date,
            summary.get('meeting_title', ''),
            task.get('task_title', ''),
            task.get('description', ''),
            task.get('assignee', '未定'),
            task.get('due_date', '未定'),
            task.get('priority', '中'),
            task.get('category', 'その他'),
            '未着手'  # ステータス（初期値）
        ])

    if task_rows:
        service.spreadsheets().values().append(
            spreadsheetId=spreadsheet_id,
            range='タスク管理!A:I',
            valueInputOption='USER_ENTERED',
            body={'values': task_rows}
        ).execute()

    print(f"Sheetsへの保存完了: 議事録1件、タスク{len(task_rows)}件")
```

### Sheetsの推奨構成

**「議事録サマリー」シート**: 日付・タイトル・参加者・要約・決定事項

**「タスク管理」シート**: 会議日・タイトル・タスク名・説明・担当者・期限・優先度・カテゴリ・ステータス

タスク管理シートでは、Google Sheetsの**条件付き書式**を使って優先度（高=赤、中=黄、低=緑）や期限切れタスク（赤背景）を視覚化することをお勧めします。

## Google Calendar連携: フォローアップタスクの自動登録

期限が設定されたタスクをGoogle Calendarに自動登録することで、担当者への自然なリマインダーを実現します。

```python
def create_calendar_followups(tasks: list[dict], summary: dict):
    """期限付きタスクをGoogle Calendarに登録"""
    creds = service_account.Credentials.from_service_account_file(
        'service-account.json',
        scopes=['https://www.googleapis.com/auth/calendar']
    )
    calendar_service = build('calendar', 'v3', credentials=creds)

    created_count = 0
    for task in tasks:
        due_date = task.get('due_date')
        if not due_date or due_date == '未定':
            continue

        try:
            event = {
                'summary': f"[タスク] {task.get('task_title', '')}",
                'description': (
                    f"会議: {summary.get('meeting_title', '')}\n"
                    f"担当: {task.get('assignee', '未定')}\n"
                    f"詳細: {task.get('description', '')}\n"
                    f"優先度: {task.get('priority', '中')}"
                ),
                'start': {'date': due_date},  # 終日予定として登録
                'end': {'date': due_date},
                'colorId': '11' if task.get('priority') == '高' else '5',
                'reminders': {
                    'useDefault': False,
                    'overrides': [
                        {'method': 'email', 'minutes': 24 * 60},  # 1日前
                        {'method': 'popup', 'minutes': 60}        # 1時間前
                    ]
                }
            }

            calendar_service.events().insert(
                calendarId='primary',
                body=event
            ).execute()
            created_count += 1

        except Exception as e:
            print(f"Calendar登録エラー ({task.get('task_title')}): {e}")

    print(f"Calendarへの登録完了: {created_count}件")
```

## 本番運用: エラーハンドリングとコスト最適化

### エラーハンドリングのベストプラクティス

本番システムでは、以下の3層のエラーハンドリングを実装することを推奨します。

**第1層: リトライ機構**

```python
import time
from functools import wraps

def retry_with_exponential_backoff(max_retries=3, base_delay=1.0):
    """指数バックオフ付きリトライデコレータ"""
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            for attempt in range(max_retries):
                try:
                    return func(*args, **kwargs)
                except Exception as e:
                    if attempt == max_retries - 1:
                        raise e

                    # 429 (レート制限) の場合は長めに待機
                    if '429' in str(e):
                        wait_time = base_delay * (2 ** attempt) * 5
                    else:
                        wait_time = base_delay * (2 ** attempt)

                    print(f"リトライ {attempt + 1}/{max_retries}: {wait_time}秒後に再試行")
                    time.sleep(wait_time)
            return None
        return wrapper
    return decorator

@retry_with_exponential_backoff(max_retries=3)
def transcribe_audio_with_retry(audio_data: bytes, file_name: str) -> str:
    return transcribe_audio(audio_data, file_name)
```

**第2層: 部分失敗への対応**

各処理ステップを独立させ、一部が失敗しても他の処理は継続できるよう設計します。たとえば文字起こしは成功したがCalendar登録が失敗した場合でも、メール送信は完了させるべきです。

**第3層: エラーログとアラート**

Cloud Loggingへのエラーログ記録と、重大エラー時のCloud Monitoringアラートを設定しておくことで、サイレント失敗を防ぎます。

### コスト最適化戦略

Gemini APIの利用コストを最小化するための実践的な手法を紹介します。

**文字起こしのチャンク分割**: 1時間超の会議は30分ごとに分割して処理することで、コンテキスト長の制限を回避しつつトークン効率を改善できます。

**要約の段階的精緻化**: まず`gemini-2.5-flash`（低コスト）で粗い要約を生成し、重要度の高い会議のみ`gemini-2.5-pro`で詳細分析する2段階アプローチが効果的です。

**キャッシュの活用**: 同じプロンプトテンプレートは[Context Caching](/articles/gemini-api/context-caching-guide)を使って再利用することでコストを60〜80%削減できます。

**月間コスト試算（チーム10名・週20回の会議）**:

- 文字起こし（gemini-2.5-flash）: 1会議 1時間 × 約20万トークン × $0.075/1Mトークン ≈ $0.015
- 要約・タスク抽出（gemini-2.5-pro）: 約30万トークン × $1.25/1Mトークン ≈ $0.375
- 月間（80回の会議）: 約$31 — チームの時間コスト削減と比べて非常に費用対効果が高い
