ChatGPTの音声モードが話題になっているが、独自の音声対話アプリを作りたいなら、Gemini Live APIが現時点で最も柔軟な選択肢です。WebSocket上でリアルタイムの音声ストリーミングが可能で、ユーザーが途中で話し始めたとき、Gemini の応答を割り込みでキャンセルするといった細かい制御もできます。

ただしLive APIの実装は、REST APIより複雑です。WebSocket通信、音声エンコーディング、ストリーミング処理、接続管理——これらが絡み合う。公式ドキュメントは機能説明には詳しいが、「実装の全体像」と「本番環境を想定した誤り処理」の説明が不足しています。

本ガイドでは、Live APIで音声対話アプリを構築するために必要な知識を、実装パターンとともに順追って解説する。Node.js環境で、実際に動作するコード例を示しながら進めていく。

## Live API のアーキテクチャ——なぜ REST ではなく WebSocket か

Gemini Live APIが WebSocket を採用した理由を理解すると、設計判断が明確になります。

REST APIは「リクエスト→レスポンス」の単方向で、ユーザーの音声入力を完全に送ってから、AI の応答を受け取る方式です。対話アプリには向かない。

一方、Live API は双方向 WebSocket 通信をベースにしています。こうすることで：

1. **ユーザーが話しながら、リアルタイムで音声をバッファに貯める**：音声チャンクを即座に送信でき、全体を待たない
2. **AI が応答を途中から送信開始**：ユーザーの入力完了を待たずに、推測応答を返し始める（低レイテンシ）
3. **割り込み応答**：ユーザーが話し始めたら、AI の前の応答をキャンセルして新しい入力で再生成
4. **セッション保持**：同じWebSocket接続内で複数ターンの対話を継続、文脈を保ったまま進められる

REST では これらが難しいです。だからLive API はWebSocketを選んでいます。

### Live API のセッションライフサイクル

Live API のセッションは以下のサイクルで動く：

[1] WebSocket接続確立 → [2] セッション初期化 → [3] 音声入力ストリーム開始 → [4] リアルタイム応答受信 → [5] 出力音声再生 → [6] 割り込みハンドリング → [7] セッション終了

重要なのは[3]から[5]が並行して動く点です。入力を送りながら応答を受け取り、同時に再生する——これが低レイテンシ対話の鍵です。

## 基本実装——WebSocket 接続と音声ストリーミング

### Step 1: WebSocket接続確立

```typescript
import WebSocket from 'ws';
import dotenv from 'dotenv';

dotenv.config();

const API_KEY = process.env.GOOGLE_API_KEY\!;
const LIVE_API_URL = process.env.GOOGLE_GEMINI_LIVE_API_URL\!;

class GeminiLiveSession {
  private ws: WebSocket | null = null;
  private isConnected: boolean = false;

  async connect(): Promise<void> {
    const url = `${LIVE_API_URL}?key=${API_KEY}`;
    
    this.ws = new WebSocket(url);

    this.ws.on('open', () => {
      console.log('✓ WebSocket connected');
      this.isConnected = true;
    });

    this.ws.on('message', (data: Buffer) => {
      this.handleMessage(data);
    });

    this.ws.on('error', (error) => {
      console.error('✗ WebSocket error:', error);
    });

    this.ws.on('close', () => {
      this.isConnected = false;
    });

    return new Promise((resolve, reject) => {
      const timeout = setTimeout(() => {
        reject(new Error('Connection timeout'));
      }, 5000);

      const checkConnection = () => {
        if (this.isConnected) {
          clearTimeout(timeout);
          resolve();
        } else {
          setTimeout(checkConnection, 100);
        }
      };
      checkConnection();
    });
  }

  private handleMessage(data: Buffer): void {
    try {
      const message = JSON.parse(data.toString());
      console.log('Message:', message.type || 'unknown');
    } catch (e) {
      console.error('Parse error:', e);
    }
  }

  disconnect(): void {
    if (this.ws) this.ws.close();
  }
}
```

### Step 3: マイク入力と音声チャンク送信

```typescript
import * as portaudio from 'node-portaudio';

async startAudioInput(durationMs: number = 10000): Promise<void> {
  const SAMPLE_RATE = 16000;
  const stream = portaudio.AudioIO({
    inChannels: 1,
    outChannels: 0,
    sampleRate: SAMPLE_RATE,
    frameSize: 1024
  });

  stream.on('data', (audioBuffer: Buffer) => {
    this.sendAudioChunk(audioBuffer);
  });

  stream.start();
  setTimeout(() => stream.quit(), durationMs);
}

private sendAudioChunk(audioBuffer: Buffer): void {
  if (\!this.ws || \!this.isConnected) return;

  const audioMessage = {
    realtime_input: {
      media_chunks: [{
        data: audioBuffer.toString('base64'),
        mime_type: 'audio/pcm;rate=16000'
      }]
    }
  };

  this.ws.send(JSON.stringify(audioMessage));
}
```

**設計判断**：16kHz PCMはGemini APIの標準。チャンクサイズ1024は約64msの遅延で最適。

## リアルタイム応答の受信と音声再生

### Step 4: ストリーミング応答処理

```typescript
private audioPlaybackBuffer: Buffer[] = [];
private isPlaying: boolean = false;

private handleMessage(data: Buffer): void {
  const message = JSON.parse(data.toString());
  
  if (message.serverContent?.modelTurn?.parts) {
    for (const part of message.serverContent.modelTurn.parts) {
      if (part.inlineData?.mimeType.startsWith('audio/')) {
        const chunk = Buffer.from(part.inlineData.data, 'base64');
        this.queueAudioForPlayback(chunk);
      }
    }
  }
}

private queueAudioForPlayback(chunk: Buffer): void {
  this.audioPlaybackBuffer.push(chunk);
  if (\!this.isPlaying) this.playAudio();
}

private async playAudio(): Promise<void> {
  if (this.isPlaying || this.audioPlaybackBuffer.length === 0) return;

  this.isPlaying = true;
  const stream = portaudio.AudioIO({
    inChannels: 0,
    outChannels: 1,
    sampleRate: 24000,
    frameSize: 1024
  });

  stream.start();
  while (this.audioPlaybackBuffer.length > 0) {
    stream.write(this.audioPlaybackBuffer.shift()\!);
    await new Promise(r => setTimeout(r, 50));
  }
  stream.quit();
  this.isPlaying = false;
}
```

## エラーハンドリングとリカバリ

### 接続切断時の自動リトライ

```typescript
private maxRetries = 3;
private retryCount = 0;

async reconnect(): Promise<void> {
  if (this.retryCount >= this.maxRetries) {
    console.error('Max retries reached');
    return;
  }

  const delay = 1000 * Math.pow(2, this.retryCount);
  await new Promise(r => setTimeout(r, delay));

  try {
    await this.connect();
    this.retryCount = 0;
  } catch (error) {
    this.retryCount++;
    await this.reconnect();
  }
}
```

### タイムアウト対策

```typescript
private messageTimeout = 30000;
private lastMessageTime = Date.now();

private startTimeoutCheck(): void {
  setInterval(() => {
    const elapsed = Date.now() - this.lastMessageTime;
    if (elapsed > this.messageTimeout && this.isConnected) {
      console.warn('No response, reconnecting...');
      this.reconnect();
    }
  }, 5000);
}
```

## 完全な実装例

```typescript
async function main() {
  const session = new GeminiLiveSession();

  try {
    await session.connect();
    await session.initializeSession(
      'You are a helpful voice assistant. Keep responses concise.'
    );
    
    await session.startAudioInput(10000);
    await new Promise(r => setTimeout(r, 15000));
  } catch (error) {
    console.error('Error:', error);
  } finally {
    session.disconnect();
  }
}

main();
```

## 実装時の重要なポイント

1. **WebSocket の安定性**: キープアライブとリトライロジックは必須
2. **音声フォーマット**: 16kHz PCM は固定、他のフォーマットは非対応
3. **バッファ管理**: 大きすぎるとレイテンシが増す、小さすぎると音声が途切れる
4. **セッション保持時間**: 5分程度が実用的な目安
5. **エラーから の復帰**: 指数バックオフリトライは必須

Live API を使うことで、遅延が少なく、自然な音声対話が実現できます。本ガイドを参考に、本番環境で動作するアプリを構築してほしい。
