## Gemini API で応答がブロックされる症状

Gemini API を使ったアプリケーション開発で、次のような症状に遭遇したことはないでしょうか。

- API レスポンスの `finishReason` が `SAFETY` になり、テキストが空で返ってくる
- `response.text` にアクセスすると「response was blocked」エラーが発生する
- `BlockedReason.SAFETY` や `HARM_CATEGORY_*` の警告がログに出力される
- 医療・法律・歴史など正当なトピックを質問しただけなのにブロックされる

これらはすべて Gemini API のセーフティフィルタが意図せず発動しているケースです。本記事では、ブロックの原因を体系的に分析し、正しい `safetySettings` の設定方法からプロンプト改善まで、実践的な解決手順を解説します。

## なぜ正当なリクエストがブロックされるのか

Gemini API のセーフティフィルタは、有害コンテンツの生成を防ぐために設計されています。しかし、以下のような理由で正当なリクエストまでブロックされることがあります。

### デフォルト設定が厳しすぎる

`safetySettings` を明示的に指定しない場合、すべてのカテゴリで `BLOCK_MEDIUM_AND_ABOVE`（中程度以上をブロック）が適用されます。医療情報、歴史的事件、法的助言などのトピックは、文脈によってフィルタに引っかかりやすくなります。

### 入力と出力の両方がチェックされる

フィルタはユーザーのプロンプト（入力）とモデルの生成内容（出力）の**両方**に適用されます。プロンプト自体が安全でも、モデルが生成しようとした回答がフィルタに引っかかるケースがあります。

### カテゴリの誤判定

Gemini のセーフティフィルタは以下の4カテゴリで判定を行います。

- **HARM_CATEGORY_HARASSMENT** — ハラスメント
- **HARM_CATEGORY_HATE_SPEECH** — ヘイトスピーチ
- **HARM_CATEGORY_SEXUALLY_EXPLICIT** — 性的コンテンツ
- **HARM_CATEGORY_DANGEROUS_CONTENT** — 危険なコンテンツ

たとえば、サイバーセキュリティに関する質問が「危険なコンテンツ」と誤判定されたり、医療情報の説明が「性的コンテンツ」と誤判定されるケースがあります。

## safetySettings の正しい設定方法

### Python SDK での設定例

```python
import google.generativeai as genai

genai.configure(api_key="YOUR_GEMINI_API_KEY")

# セーフティ設定をカスタマイズ
safety_settings = [
    {
        "category": "HARM_CATEGORY_HARASSMENT",
        "threshold": "BLOCK_ONLY_HIGH"  # 高リスクのみブロック
    },
    {
        "category": "HARM_CATEGORY_HATE_SPEECH",
        "threshold": "BLOCK_ONLY_HIGH"
    },
    {
        "category": "HARM_CATEGORY_SEXUALLY_EXPLICIT",
        "threshold": "BLOCK_MEDIUM_AND_ABOVE"  # デフォルト維持
    },
    {
        "category": "HARM_CATEGORY_DANGEROUS_CONTENT",
        "threshold": "BLOCK_ONLY_HIGH"
    },
]

model = genai.GenerativeModel(
    model_name="gemini-2.5-flash",
    safety_settings=safety_settings
)

response = model.generate_content("サイバーセキュリティにおける脆弱性診断の基本手法を教えてください")
print(response.text)
# 期待する出力: 脆弱性診断の手法についての詳細な解説
```

### JavaScript/TypeScript SDK での設定例

```javascript
import { GoogleGenerativeAI, HarmCategory, HarmBlockThreshold } from "@google/generative-ai";

const genAI = new GoogleGenerativeAI("YOUR_GEMINI_API_KEY");

const safetySettings = [
  {
    category: HarmCategory.HARM_CATEGORY_HARASSMENT,
    threshold: HarmBlockThreshold.BLOCK_ONLY_HIGH,
  },
  {
    category: HarmCategory.HARM_CATEGORY_HATE_SPEECH,
    threshold: HarmBlockThreshold.BLOCK_ONLY_HIGH,
  },
  {
    category: HarmCategory.HARM_CATEGORY_SEXUALLY_EXPLICIT,
    threshold: HarmBlockThreshold.BLOCK_MEDIUM_AND_ABOVE,
  },
  {
    category: HarmCategory.HARM_CATEGORY_DANGEROUS_CONTENT,
    threshold: HarmBlockThreshold.BLOCK_ONLY_HIGH,
  },
];

const model = genAI.getGenerativeModel({
  model: "gemini-2.5-flash",
  safetySettings,
});

const result = await model.generateContent("歴史上の戦争における戦略的意思決定を分析してください");
console.log(result.response.text());
// 期待する出力: 戦争史における意思決定の分析
```

### 閾値オプション一覧

- **BLOCK_NONE** — フィルタを完全に無効化（Vertex AI のみ利用可能）
- **BLOCK_ONLY_HIGH** — 高リスクのみブロック（推奨）
- **BLOCK_MEDIUM_AND_ABOVE** — 中程度以上をブロック（デフォルト）
- **BLOCK_LOW_AND_ABOVE** — 低リスク以上をすべてブロック（最も厳しい）

## ブロック原因を特定するデバッグ手順

応答がブロックされた場合、まずは原因を正確に特定することが重要です。

### Step 1: finishReason を確認する

```python
response = model.generate_content("あなたの質問テキスト")

# レスポンス全体の構造を確認
for candidate in response.candidates:
    print(f"finishReason: {candidate.finish_reason}")
    # セーフティレーティングを表示
    for rating in candidate.safety_ratings:
        print(f"  {rating.category}: {rating.probability}")
```

`finishReason` が `SAFETY` の場合、`safety_ratings` のどのカテゴリが `HIGH` または `MEDIUM` になっているかを確認します。

### Step 2: プロンプトフィードバックを確認する

入力自体がブロックされている場合は `prompt_feedback` に情報が含まれます。

```python
if response.prompt_feedback:
    print(f"Prompt blocked: {response.prompt_feedback.block_reason}")
    for rating in response.prompt_feedback.safety_ratings:
        print(f"  {rating.category}: {rating.probability}")
```

### Step 3: 問題のあるカテゴリの閾値を調整する

特定のカテゴリが原因と判明したら、そのカテゴリの閾値を `BLOCK_ONLY_HIGH` に変更して再試行します。

```python
# 例: DANGEROUS_CONTENT が原因だった場合
safety_settings = [
    {"category": "HARM_CATEGORY_DANGEROUS_CONTENT", "threshold": "BLOCK_ONLY_HIGH"},
]
response = model.generate_content("質問テキスト", safety_settings=safety_settings)
```

## プロンプト改善によるブロック回避

`safetySettings` の調整だけでは解決しない場合、プロンプト自体を改善することで回避できるケースがあります。

### 文脈を明確にする

```
❌ ブロックされやすい:
「毒物の作用機序について教えてください」

✅ 文脈を明確にする:
「薬学の教育目的で、医薬品の薬理学的な作用機序について説明してください。
特に解毒メカニズムと臨床での安全管理について詳しく教えてください。」
```

### System Instructions で用途を宣言する

```python
model = genai.GenerativeModel(
    model_name="gemini-2.5-flash",
    system_instruction="""あなたは医療従事者向けの教育アシスタントです。
医学的に正確な情報を提供し、臨床現場で役立つ知識を共有してください。
質問には学術的な観点から回答してください。""",
    safety_settings=safety_settings
)
```

### 段階的にリクエストする

長いリクエストを一度に送ると、部分的な文脈がフィルタに引っかかることがあります。複雑なトピックは段階的に質問することで、各ステップの文脈が明確になりブロックを回避しやすくなります。

## 解決できたかの確認方法

修正後、以下のチェックリストで正常に動作しているか確認しましょう。

```python
def verify_safety_fix(model, test_prompts):
    """セーフティ設定の修正を検証するヘルパー関数"""
    results = []
    for prompt in test_prompts:
        try:
            response = model.generate_content(prompt)
            finish_reason = response.candidates[0].finish_reason if response.candidates else "NO_CANDIDATE"
            has_text = bool(response.text) if hasattr(response, 'text') else False
            results.append({
                "prompt": prompt[:50],
                "finish_reason": str(finish_reason),
                "has_text": has_text,
                "blocked": finish_reason == 2  # SAFETY = 2
            })
        except Exception as e:
            results.append({
                "prompt": prompt[:50],
                "error": str(e),
                "blocked": True
            })
    
    # 結果サマリー
    blocked_count = sum(1 for r in results if r.get("blocked"))
    print(f"テスト結果: {len(results) - blocked_count}/{len(results)} 成功")
    for r in results:
        status = "❌ BLOCKED" if r.get("blocked") else "✅ OK"
        print(f"  {status}: {r['prompt']}...")
    return results

# テスト実行
test_prompts = [
    "以前ブロックされた質問テキスト1",
    "以前ブロックされた質問テキスト2",
    "通常の質問（コントロール）",
]
verify_safety_fix(model, test_prompts)
# 期待する出力:
# テスト結果: 3/3 成功
#   ✅ OK: 以前ブロックされた質問テキスト1...
#   ✅ OK: 以前ブロックされた質問テキスト2...
#   ✅ OK: 通常の質問（コントロール）...
```

## 再発防止のベストプラクティス

本番環境でブロックが発生しないよう、以下のプラクティスを取り入れましょう。

### セーフティ設定をコードに明示する

デフォルト値に依存せず、プロジェクトに適した閾値を設定ファイルで一元管理します。

```python
# config/safety.py — プロジェクト共通のセーフティ設定
SAFETY_SETTINGS_PRODUCTION = [
    {"category": "HARM_CATEGORY_HARASSMENT", "threshold": "BLOCK_ONLY_HIGH"},
    {"category": "HARM_CATEGORY_HATE_SPEECH", "threshold": "BLOCK_ONLY_HIGH"},
    {"category": "HARM_CATEGORY_SEXUALLY_EXPLICIT", "threshold": "BLOCK_MEDIUM_AND_ABOVE"},
    {"category": "HARM_CATEGORY_DANGEROUS_CONTENT", "threshold": "BLOCK_ONLY_HIGH"},
]
```

### フォールバック処理を実装する

ブロックが発生した場合に適切に処理するロジックを組み込みます。

```python
def safe_generate(model, prompt, max_retries=2):
    """ブロック時にプロンプトを調整してリトライする関数"""
    for attempt in range(max_retries + 1):
        response = model.generate_content(prompt)
        if response.candidates and response.candidates[0].finish_reason \!= 2:
            return response.text
        
        if attempt < max_retries:
            # プロンプトに文脈を追加してリトライ
            prompt = f"教育目的での質問です。学術的な観点から回答してください。\n\n{prompt}"
    
    return "申し訳ございません。この質問には現在お答えできません。別の表現でお試しください。"
```

### ログを記録して傾向を分析する

どのようなプロンプトがブロックされやすいかを記録し、パターンを把握することで事前に対策できます。

## よくある質問（FAQ）

### Q: BLOCK_NONE を使えばすべてのブロックを回避できますか？

`BLOCK_NONE` は **Vertex AI（有料の Google Cloud 環境）** でのみ利用可能です。Google AI Studio の無料 API キーでは `BLOCK_NONE` を指定してもエラーまたは無視されます。最も緩い設定として `BLOCK_ONLY_HIGH` を使用してください。

### Q: safetySettings を変更してもまだブロックされます。他に方法はありますか？

プロンプトの改善が効果的です。具体的には、質問の目的（教育・研究・業務）を明記する、System Instructions で AI の役割を定義する、センシティブなキーワードを学術的な表現に置き換える、の3つを試してください。それでも解決しない場合は Vertex AI への移行を検討しましょう。

### Q: セーフティフィルタの設定を緩めるとアプリの安全性に問題はありませんか？

閾値を `BLOCK_ONLY_HIGH` に変更しても、明らかに有害なコンテンツはブロックされ続けます。ただし、ユーザー入力を直接 API に渡すアプリケーションでは、入力バリデーションやコンテンツモデレーションの独自レイヤーを追加することを推奨します。

### Q: 画像や動画を含むマルチモーダルリクエストでもブロックされます。対処法は？

マルチモーダル入力にも同じ `safetySettings` が適用されます。画像・動画コンテンツは自動的にスキャンされるため、テキストのみのリクエストよりフィルタが発動しやすい傾向があります。詳しくは[Gemini マルチモーダル入力エラー完全解決ガイド](/articles/gemini-advanced/gemini-multimodal-input-errors-complete-troubleshooting-guide)を参照してください。

## まとめ

Gemini API のセーフティフィルタは安全性を確保するための重要な機能ですが、設定を理解し正しくカスタマイズすることで、正当なリクエストがブロックされる問題を解決できます。デバッグ時は `finishReason` と `safety_ratings` を必ず確認し、原因となるカテゴリを特定してから閾値を調整しましょう。
