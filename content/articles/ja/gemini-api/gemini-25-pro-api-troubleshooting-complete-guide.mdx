Gemini 2.5 Pro APIは高い言語理解力と推論能力を持つ最先端モデルですが、本番環境での運用には多くの落とし穴があります。認証エラー、レート制限、モデル名の誤指定、思わぬエラーハンドリング不足―こうした問題に直面すると、デバッグに数時間を費やすことになりかねません。

このガイドでは、実際のプロダクション運用で起こりうるエラーと、その根本的な解決策を体系的に解説します。generativelanguage.googleapis.comの仕組みを深く理解することで、安心してGemini 2.5 Proを本番環境で活用できるようになります。

## Gemini 2.5 Pro API の基本構成とエンドポイント

Gemini 2.5 Pro APIへのアクセスは、generativelanguage.googleapis.comというエンドポイント経由で行われます。この基本構成を理解することが、トラブルシューティングの第一歩です。

### モデル名の正確な指定方法

Gemini 2.5 Proには複数のバージョン表記があります。これが多くのエラーの原因になっています：

**推奨される呼び出し方法:**
- `gemini-2.5-pro` — 安定版（推奨）
- `gemini-2.5-pro-latest` — 最新版（機能が先行）
- `gemini-2.5-pro-exp` — 実験版（動作不安定）

注意すべき点は：

- `gemini-2.5-pro` と `gemini-2.5-pro-latest` は異なるモデルである
- 実験版（`-exp`）は急に廃止されることがあるため、本番環境では避けるべき
- バージョン名はタイプミスしやすい（例：`gemini-2.5-pro-latest` を `gemini-2.5-latest-pro` と書いてしまう）

### リクエスト構造の基本

generativelanguage.googleapis.comへのリクエストは、以下の要素で構成されます：

```
POST https://generativelanguage.googleapis.com/v1beta/models/{model-id}:generateContent
```

ここで重要なのは：

- `{model-id}` には上述のモデル名を指定
- APIキーは `?key=YOUR_API_KEY` でクエリパラメータとして渡す、または `Authorization: Bearer` ヘッダーで渡す
- リクエストボディはJSON形式で、`contents` フィールドに質問を含める
- `generationConfig` でレスポンス設定（temperature、max_output_tokens等）を指定可能

### 認証方法：APIキーとサービスアカウント

Gemini 2.5 Pro APIの認証には2つの方法があります：

**APIキー認証（開発用）:**
```
?key=YOUR_GEMINI_API_KEY
```

**サービスアカウント認証（本番環境推奨）:**
```
Authorization: Bearer {access_token}
```

APIキー認証は簡単ですが、キーが漏洩しやすいため開発環境に限定すべきです。本番環境ではサービスアカウント認証を使用し、認可情報は環境変数で管理してください。

## 認証エラーのトラブルシューティング

### 403 Forbidden: 権限がない

原因は大きく3つです：

**1. APIキーが無効または有効期限切れ**

```python
import google.generativeai as genai

try:
    genai.configure(api_key="YOUR_GEMINI_API_KEY")
    model = genai.GenerativeModel("gemini-2.5-pro")
    response = model.generate_content("こんにちは")
except ValueError as e:
    print(f"認証エラー: {e}")
```

**2. Gemini API がプロジェクトで有効化されていない**

Google Cloud Consoleで：
1. プロジェクトを選択
2. 「APIs & Services」→「Enabled APIs」で「Google Generative AI API」を検索
3. 「Enable」をクリック

有効化には1〜5分かかることもあります。

**3. 無料プランの制限を超過した**

Gemini APIの無料プランには、以下の制限があります：

- 1分あたり60リクエスト
- 1日あたり1500リクエスト
- 月あたり100万トークン

これを超えると403エラーになります。`billing_account` を設定してアップグレードしてください。

### 401 Unauthorized: 認証情報が不正

この場合、APIキーそのものが正しく送信されていません。

```python
import requests

url = "https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-pro:generateContent"
headers = {
    "Content-Type": "application/json"
}
params = {
    "key": "YOUR_GEMINI_API_KEY"  # ← クエリパラメータとして指定
}
payload = {
    "contents": [
        {
            "parts": [
                {"text": "質問をここに書く"}
            ]
        }
    ]
}

response = requests.post(url, headers=headers, params=params, json=payload)
print(response.status_code)
```

ここで重要なのは `?key=` がURL末尾に正しくアタッチされているかです。

## よくあるAPIエラーコード別解決策

### 400 Bad Request: リクエスト構造が不正

これは、JSONペイロードの形式が間違っている場合に発生します。

**よくある間違い:**

```python
# ❌ 間違った例
response = model.generate_content("テキスト")  # contents フィールドがない

# ✅ 正しい例
response = model.generate_content(
    content=[{"text": "テキスト"}]
)
```

google.generativeai ライブラリを使用すれば、大多数の形式エラーは自動処理されます。

### 429 Too Many Requests: レート制限に達した

APIへのリクエストが多すぎると、429エラーが返されます。

**原因:**
- 1分間に同時リクエストが多すぎる
- 無料プランの制限を超えた
- ループの中で無制限にリクエストを送っている

**解決策：指数バックオフの実装**

```python
import time
import random

def call_with_retry(model, prompt, max_retries=5):
    for attempt in range(max_retries):
        try:
            response = model.generate_content(prompt)
            return response.text
        except Exception as e:
            if "429" in str(e) or "quota" in str(e).lower():
                # 指数バックオフ: 2^attempt + ランダム
                wait_seconds = (2 ** attempt) + random.uniform(0, 1)
                print(f"レート制限。{wait_seconds:.1f}秒待機...")
                time.sleep(wait_seconds)
            else:
                raise
    raise RuntimeError("Max retries exceeded")
```

### 500 Internal Server Error / 503 Service Unavailable: サーバー側の障害

一時的なサーバー問題です。リトライアブルなエラーなので、指数バックオフで対応します。

```python
def call_api_with_server_error_handling(model, prompt):
    max_retries = 3
    for attempt in range(max_retries):
        try:
            return model.generate_content(prompt).text
        except Exception as e:
            if "500" in str(e) or "503" in str(e):
                if attempt < max_retries - 1:
                    wait_time = 5 * (2 ** attempt)
                    print(f"サーバーエラー。{wait_time}秒後に再試行...")
                    time.sleep(wait_time)
                else:
                    raise RuntimeError("Max server retries exceeded")
            else:
                raise
```

### 404 Model Not Found: モデル名が存在しない

typoか、廃止されたモデル名を使用している可能性があります。

```python
# ❌ 間違い
model = genai.GenerativeModel("gemini-2.5-latest-pro")  # 順序が違う

# ✅ 正しい
model = genai.GenerativeModel("gemini-2.5-pro-latest")
```

## Gemini 2.5 Pro 特有の設定ポイント

### Thinking モードの有効化

Gemini 2.5 Proは「thinking」モードをサポートしており、複雑な推論が必要なタスクで活用できます。

```python
response = model.generate_content(
    "複雑な数学問題を解いてください",
    generation_config=genai.types.GenerationConfig(
        thinking={
            "type": "enabled",
            "budget_tokens": 10000  # 最大で10,000トークン推論に費やす
        }
    )
)

print("思考プロセス:", response.thinking)
print("最終回答:", response.text)
```

thinkingモードは以下の場合に有効です：

- 複雑な推論が必要な問題（数学、論理パズル）
- 複数ステップの計画立案
- コード生成と検証

### Safety Settings の調整

デフォルトでは、Gemini 2.5 Proは安全性フィルタを適用しています。必要に応じて調整できます：

```python
import google.generativeai as genai

safety_settings = [
    {
        "category": genai.types.HarmCategory.HARM_CATEGORY_UNSPECIFIED,
        "threshold": genai.types.HarmBlockThreshold.BLOCK_NONE,
    },
    {
        "category": genai.types.HarmCategory.HARM_CATEGORY_DANGEROUS_CONTENT,
        "threshold": genai.types.HarmBlockThreshold.BLOCK_MEDIUM_AND_ABOVE,
    },
]

response = model.generate_content(
    "質問",
    safety_settings=safety_settings
)
```

### Generation Config の最適化

レスポンス品質やコストを調整します：

```python
config = genai.types.GenerationConfig(
    temperature=0.7,              # 0=確定的, 1=創造的
    max_output_tokens=1024,       # 最大出力トークン
    top_p=0.95,                   # サンプリング分布（nucleus sampling）
    top_k=40,                     # トップKサンプリング
)

response = model.generate_content(
    prompt="文章を生成してください",
    generation_config=config
)
```

**設定ガイドライン:**
- **確定的な応答** (Q&Aなど): `temperature=0.2`
- **バランス型** (一般的な用途): `temperature=0.7`
- **創造的な応答** (創作など): `temperature=1.0`

## ストリーミング API のトラブルシューティング

大規模なレスポンスをリアルタイムで取得する場合、ストリーミングが便利です。

```python
def stream_response(model, prompt):
    try:
        response = model.generate_content(
            prompt,
            stream=True
        )
        
        for chunk in response:
            if chunk.text:
                print(chunk.text, end="", flush=True)
        
        print()  # 改行
        
    except StopIteration:
        print("ストリーム完了")
    except Exception as e:
        print(f"ストリーミングエラー: {e}")

# 使用例
model = genai.GenerativeModel("gemini-2.5-pro")
stream_response(model, "長い物語を書いてください")
```

**ストリーミング時の注意点:**

- ネットワーク接続が不安定な場合、途中で切断される可能性がある
- 部分的なJSONオブジェクトが返される場合がある（チャンク分割）
- timeout設定を明示的に行う

## コスト最適化とクォータ管理

### トークン数の計算方法

Gemini APIの課金はトークン数ベースです。予め見積もりを取ることが重要です。

```python
# count_tokens API を使用
model = genai.GenerativeModel("gemini-2.5-pro")

prompt = "日本の桜について1000文字で説明してください"

token_count = model.count_tokens(prompt)
print(f"入力トークン数: {token_count.total_tokens}")

# レスポンス生成
response = model.generate_content(prompt)
output_tokens = response.usage_metadata.output_tokens
input_tokens = response.usage_metadata.prompt_token_count

print(f"実際の入力: {input_tokens}, 出力: {output_tokens}")
```

### バッチ処理によるコスト削減

複数リクエストを一度に送信することで、オーバーヘッドを削減できます。

```python
from google.generativeai import batch

# バッチ内容を定義
requests = [
    {"prompt": "質問1"},
    {"prompt": "質問2"},
    {"prompt": "質問3"},
]

model = genai.GenerativeModel("gemini-2.5-pro")

# バッチ送信（処理の優先度が下がる代わりにコスト削減）
batch_response = model.batch_generate_content(
    [{"text": r["prompt"]} for r in requests]
)
```

## 本番環境での安定稼働パターン

### 本番対応の実装例

以下は、本番環境向けのクラスベース実装です：

```python
import time
import logging
from typing import Optional
import google.generativeai as genai
from google.api_core import exceptions

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger(__name__)

class GeminiProClient:
    """本番環境向けGemini 2.5 Pro クライアント"""
    
    def __init__(
        self,
        api_key: str,
        model_name: str = "gemini-2.5-pro",
        max_retries: int = 3,
        timeout_seconds: int = 30
    ):
        genai.configure(api_key=api_key)
        self.model = genai.GenerativeModel(model_name)
        self.max_retries = max_retries
        self.timeout_seconds = timeout_seconds
    
    def generate_with_retry(
        self,
        prompt: str,
        temperature: float = 0.7,
        max_tokens: Optional[int] = None
    ) -> str:
        """リトライ機能付きのテキスト生成"""
        
        for attempt in range(self.max_retries):
            try:
                logger.info(f"Attempt {attempt + 1}/{self.max_retries}")
                
                response = self.model.generate_content(
                    prompt,
                    generation_config=genai.types.GenerationConfig(
                        temperature=temperature,
                        max_output_tokens=max_tokens or 1024,
                    )
                )
                
                logger.info(f"Success on attempt {attempt + 1}")
                return response.text
            
            except exceptions.ResourceExhausted:
                wait_time = (2 ** attempt) * 1.0
                logger.warning(f"Rate limited. Waiting {wait_time}s...")
                time.sleep(wait_time)
            
            except exceptions.ServiceUnavailable:
                logger.warning(f"Service unavailable. Waiting 5s...")
                time.sleep(5)
            
            except Exception as e:
                logger.error(f"Unexpected error: {e}")
                if attempt == self.max_retries - 1:
                    raise
        
        raise RuntimeError("Max retries exceeded")
    
    def count_tokens_before_call(self, prompt: str) -> int:
        """コスト見積もり"""
        token_count = self.model.count_tokens(prompt)
        return token_count.total_tokens

# 使用例
client = GeminiProClient(api_key="YOUR_GEMINI_API_KEY")
result = client.generate_with_retry(
    prompt="Pythonでマルチスレッド処理の例を書いてください",
    temperature=0.3
)
print(result)
```

## デバッグとモニタリング

### ログ記録戦略

本番環境では、すべてのAPI呼び出しをログに記録し、後の監査・分析に備えます：

```python
import logging
from datetime import datetime

logging.basicConfig(
    format='%(asctime)s - %(name)s - %(levelname)s - %(message)s',
    level=logging.INFO,
    handlers=[
        logging.FileHandler('gemini_api.log'),
        logging.StreamHandler()
    ]
)

logger = logging.getLogger(__name__)

def log_api_call(prompt: str, response_text: str, tokens_used: int):
    logger.info(f"API Call - Prompt length: {len(prompt)}, Response tokens: {tokens_used}")
    logger.debug(f"Prompt: {prompt[:100]}...")
    logger.debug(f"Response: {response_text[:100]}...")
```

### usage_metadata の活用

応答に含まれるusage_metadataから、コスト情報を抽出できます：

```python
response = model.generate_content(prompt)

metadata = response.usage_metadata
print(f"入力トークン: {metadata.prompt_token_count}")
print(f"出力トークン: {metadata.output_tokens}")
print(f"合計: {metadata.prompt_token_count + metadata.output_tokens}")
```

このデータをシステムに集約すれば、日々のAPI使用状況をダッシュボード化できます。
