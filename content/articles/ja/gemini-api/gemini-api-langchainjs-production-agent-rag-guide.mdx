## はじめに：なぜ LangChain.js × Gemini API なのか

AIアプリケーションの開発において、単一のAPIコールだけでは実現できないユースケースが数多く存在します。複数のドキュメントを参照しながら質問に答えるRAG（Retrieval-Augmented Generation）、外部ツールを自律的に使いこなすエージェント、長期記憶を持つ会話システム——これらを一から実装しようとすると、膨大なボイラープレートコードと複雑な状態管理が必要になります。

LangChain.jsは、こうした課題を解決するために設計されたフレームワークです。Google Geminiとの公式統合が整備された現在、TypeScript/Node.js環境で本番品質のAIシステムを効率よく構築できる最善の選択肢の一つとなっています。

**この記事で学べること：**
- LangChain.jsとGemini APIの本番向け初期設定
- カスタムRAGパイプラインの実装（ベクトルストア連携含む）
- マルチツール・エージェントの設計と実装
- 会話メモリの管理とパーシステンス
- エラーハンドリング・レート制限・本番デプロイのベストプラクティス

**対象読者：** TypeScript/Node.jsの基本知識があり、AIシステムを本番環境に展開したい中〜上級開発者の方を想定しています。

## 2. RAGパイプラインの本番実装

RAG（Retrieval-Augmented Generation）は、外部知識ベースを参照してより正確な回答を生成する手法です。LangChain.jsを使うと、複雑なRAGパイプラインを簡潔に実装できます。

### ドキュメントの取り込みとベクトル化

```typescript
// src/rag/ingestion.ts
import { RecursiveCharacterTextSplitter } from "@langchain/textsplitters";
import { Chroma } from "@langchain/community/vectorstores/chroma";
import { PDFLoader } from "@langchain/community/document_loaders/fs/pdf";
import { TextLoader } from "langchain/document_loaders/fs/text";
import { Document } from "@langchain/core/documents";
import { createEmbeddings } from "../config/llm.js";

// テキスト分割の設定（本番向けチューニング）
const splitter = new RecursiveCharacterTextSplitter({
  chunkSize: 1000,        // チャンクサイズ（文字数）
  chunkOverlap: 200,      // オーバーラップ（文脈の継続性を確保）
  separators: ["\n\n", "\n", "。", ".", " ", ""],
});

export async function ingestDocuments(
  filePaths: string[],
  collectionName: string
): Promise<void> {
  const allDocuments: Document[] = [];

  for (const filePath of filePaths) {
    let loader;
    if (filePath.endsWith(".pdf")) {
      loader = new PDFLoader(filePath);
    } else {
      loader = new TextLoader(filePath);
    }

    const rawDocs = await loader.load();
    const splitDocs = await splitter.splitDocuments(rawDocs);

    // メタデータの付与（検索時のフィルタリングに使用）
    const enrichedDocs = splitDocs.map((doc) => ({
      ...doc,
      metadata: {
        ...doc.metadata,
        source: filePath,
        ingestedAt: new Date().toISOString(),
        collectionName,
      },
    }));

    allDocuments.push(...enrichedDocs);
  }

  // ベクトルストアへの保存
  await Chroma.fromDocuments(allDocuments, createEmbeddings(), {
    collectionName,
    url: process.env.CHROMA_URL ?? "http://localhost:8000",
  });

  console.log(
    `✅ ${allDocuments.length}チャンクを${collectionName}に取り込みました`
  );
}
```

### RAG Chainの構築

```typescript
// src/rag/chain.ts
import { Chroma } from "@langchain/community/vectorstores/chroma";
import { createRetrievalChain } from "langchain/chains/retrieval";
import { createStuffDocumentsChain } from "langchain/chains/combine_documents";
import { ChatPromptTemplate } from "@langchain/core/prompts";
import { createLLM, createEmbeddings } from "../config/llm.js";

const SYSTEM_TEMPLATE = `あなたは親切で正確な情報を提供するAIアシスタントです。
以下のコンテキスト情報を参照して、ユーザーの質問に答えてください。
コンテキストに答えが含まれていない場合は、「提供された情報からは回答できません」と伝え、
一般的な知識があれば補足してください。

コンテキスト:
{context}`;

export async function createRAGChain(collectionName: string) {
  // ベクトルストアの初期化
  const vectorStore = await Chroma.fromExistingCollection(
    createEmbeddings(),
    {
      collectionName,
      url: process.env.CHROMA_URL ?? "http://localhost:8000",
    }
  );

  // リトリーバーの設定（上位5件を取得、類似度スコアでフィルタリング）
  const retriever = vectorStore.asRetriever({
    k: 5,
    searchType: "similarity",
    filter: undefined,
  });

  // プロンプトテンプレート
  const prompt = ChatPromptTemplate.fromMessages([
    ["system", SYSTEM_TEMPLATE],
    ["human", "{input}"],
  ]);

  // ドキュメント結合チェーン
  const documentChain = await createStuffDocumentsChain({
    llm: createLLM({ temperature: 0.1 }),
    prompt,
  });

  // RAGチェーン全体
  const ragChain = await createRetrievalChain({
    retriever,
    combineDocsChain: documentChain,
  });

  return ragChain;
}

// 使用例
export async function queryRAG(
  question: string,
  collectionName: string
): Promise<{ answer: string; sources: string[] }> {
  const chain = await createRAGChain(collectionName);
  const result = await chain.invoke({ input: question });

  // ソース情報の抽出
  const sources = result.context
    .map((doc: any) => doc.metadata.source as string)
    .filter((v: string, i: number, a: string[]) => a.indexOf(v) === i); // 重複除去

  return {
    answer: result.answer,
    sources,
  };
}
```

### RAGの検索品質向上テクニック

本番運用でRAGの精度を高めるために重要なのが **ハイブリッド検索** です。ベクトル検索（意味的類似性）とキーワード検索（BM25）を組み合わせることで、異なるクエリパターンに対応できます。

```typescript
// src/rag/hybrid-retriever.ts
import { EnsembleRetriever } from "langchain/retrievers/ensemble";
import { BM25Retriever } from "@langchain/community/retrievers/bm25";

export async function createHybridRetriever(
  documents: Document[],
  vectorStore: Chroma
) {
  // BM25リトリーバー（キーワード検索）
  const bm25Retriever = BM25Retriever.fromDocuments(documents, { k: 4 });

  // ベクトルリトリーバー（意味検索）
  const vectorRetriever = vectorStore.asRetriever({ k: 4 });

  // アンサンブルリトリーバー（重み付き組み合わせ）
  return new EnsembleRetriever({
    retrievers: [bm25Retriever, vectorRetriever],
    weights: [0.4, 0.6], // ベクトル検索を重視
  });
}
```

### React Agent の実装

```typescript
// src/agents/react-agent.ts
import { createReactAgent } from "langchain/agents";
import { AgentExecutor } from "langchain/agents";
import { ChatPromptTemplate, MessagesPlaceholder } from "@langchain/core/prompts";
import { HumanMessage, AIMessage } from "@langchain/core/messages";
import { createLLM } from "../config/llm.js";
import { weatherTool, databaseSearchTool, calculatorTool } from "./tools.js";

const AGENT_SYSTEM_PROMPT = `あなたは高度なAIアシスタントです。
以下のツールを活用して、ユーザーの要求を正確かつ効率的に解決してください。

ツールの使用に際して以下の原則を守ってください：
1. 必要なツールだけを使用し、不必要なAPIコールを避ける
2. ツールの結果を論理的に組み合わせて最終回答を導く
3. 不確実な場合はユーザーに確認を求める
4. エラーが発生した場合は代替手段を試みる`;

export async function createProductionAgent() {
  const llm = createLLM({ temperature: 0 });
  const tools = [weatherTool, databaseSearchTool, calculatorTool];

  // React Agentの作成
  const agent = await createReactAgent({
    llm,
    tools,
    prompt: ChatPromptTemplate.fromMessages([
      ["system", AGENT_SYSTEM_PROMPT],
      new MessagesPlaceholder("chat_history"),
      ["human", "{input}"],
      new MessagesPlaceholder("agent_scratchpad"),
    ]),
  });

  // AgentExecutorの設定（本番向け）
  const agentExecutor = new AgentExecutor({
    agent,
    tools,
    verbose: process.env.NODE_ENV === "development",
    maxIterations: 10,          // 最大試行回数
    returnIntermediateSteps: true, // デバッグ用
    handleParsingErrors: (error: Error) => {
      console.error("Agent parsing error:", error.message);
      return "申し訳ありません。処理中にエラーが発生しました。もう一度お試しください。";
    },
  });

  return agentExecutor;
}

// 会話履歴付きの実行
export async function runAgentWithHistory(

  const executor = await createProductionAgent();

  const result = await executor.invoke({
    input,
    chat_history: chatHistory,
  });

  return {
    output: result.output,
    steps: result.intermediateSteps ?? [],
  };
}
```

## 5. ストリーミングレスポンスの実装

ユーザー体験向上のため、Gemini APIのストリーミング機能をLangChain.jsで活用します。

```typescript
// src/streaming/stream-handler.ts
import { ChatGoogleGenerativeAI } from "@langchain/google-genai";
import { ChatPromptTemplate } from "@langchain/core/prompts";
import { StringOutputParser } from "@langchain/core/output_parsers";
import { RunnableSequence } from "@langchain/core/runnables";

export async function streamingConversation(
  userMessage: string,
  onChunk: (chunk: string) => void,
  onComplete: () => void
): Promise<void> {
  const streamingLLM = new ChatGoogleGenerativeAI({
    model: "gemini-2.0-flash",
    apiKey: process.env.GEMINI_API_KEY,
    streaming: true,
    temperature: 0.7,
  });

  const prompt = ChatPromptTemplate.fromMessages([
    ["system", "あなたは親切なAIアシスタントです。"],
    ["human", "{input}"],
  ]);

  const chain = RunnableSequence.from([
    prompt,
    streamingLLM,
    new StringOutputParser(),
  ]);

  // ストリーミング実行
  const stream = await chain.stream({ input: userMessage });

  for await (const chunk of stream) {
    onChunk(chunk);
  }

  onComplete();
}

// Next.js API Route での使用例
// src/app/api/chat/route.ts
export async function POST(req: Request) {
  const { message } = await req.json();

  const encoder = new TextEncoder();
  const stream = new ReadableStream({
    async start(controller) {
      await streamingConversation(
        message,
        (chunk) => {
          controller.enqueue(encoder.encode(chunk));
        },
        () => {
          controller.close();
        }
      );
    },
  });

  return new Response(stream, {
    headers: {
      "Content-Type": "text/plain; charset=utf-8",
      "Transfer-Encoding": "chunked",
    },
  });
}
```

## 6. エラーハンドリングとレート制限対策

本番環境では、APIのレート制限やネットワークエラーへの対処が不可欠です。

### リトライロジックの実装

```typescript
// src/utils/retry.ts
import { ChatGoogleGenerativeAI } from "@langchain/google-genai";

// 指数バックオフ付きリトライ
export async function withRetry<T>(
  fn: () => Promise<T>,
  options: {
    maxRetries?: number;
    initialDelayMs?: number;
    maxDelayMs?: number;
    onRetry?: (attempt: number, error: Error) => void;
  } = {}
): Promise<T> {
  const {
    maxRetries = 3,
    initialDelayMs = 1000,
    maxDelayMs = 30000,
    onRetry,
  } = options;

  let lastError: Error;

  for (let attempt = 0; attempt <= maxRetries; attempt++) {
    try {
      return await fn();
    } catch (error) {
      lastError = error as Error;

      if (attempt === maxRetries) break;

      // レート制限エラー（429）は待機時間を長めに
      const isRateLimit =
        lastError.message.includes("429") ||
        lastError.message.includes("RATE_LIMIT");
      const delay = isRateLimit
        ? maxDelayMs
        : Math.min(initialDelayMs * Math.pow(2, attempt), maxDelayMs);

      onRetry?.(attempt + 1, lastError);
      await new Promise((resolve) => setTimeout(resolve, delay));
    }
  }

  throw lastError!;
}

// 使用例
const result = await withRetry(
  () => chain.invoke({ input: userMessage }),
  {
    maxRetries: 3,
    onRetry: (attempt, error) => {
      console.warn(`リトライ ${attempt}回目: ${error.message}`);
    },
  }
);
```

### 接続プールの管理

LangChain.jsを本番環境で使用する際、ベクトルストアへの接続をシングルトンとして管理することでパフォーマンスが向上します：

```typescript
// src/lib/vectorstore-singleton.ts
import { Chroma } from "@langchain/community/vectorstores/chroma";
import { createEmbeddings } from "../config/llm.js";

let vectorStoreInstance: Map<string, Chroma> | null = null;

export async function getVectorStore(collectionName: string): Promise<Chroma> {
  if (!vectorStoreInstance) {
    vectorStoreInstance = new Map();
  }

  if (!vectorStoreInstance.has(collectionName)) {
    const store = await Chroma.fromExistingCollection(createEmbeddings(), {
      collectionName,
      url: process.env.CHROMA_URL ?? "http://localhost:8000",
    });
    vectorStoreInstance.set(collectionName, store);
  }

  return vectorStoreInstance.get(collectionName)!;
}
```

## FAQ

**Q: LangChain.jsとVercel AI SDKはどちらを使うべきですか？**

A: ユースケースによって異なります。シンプルなストリーミングチャットやNext.jsとの統合を重視するならVercel AI SDKが軽量でおすすめです。一方、RAG・エージェント・複雑なチェーン処理など高度な機能が必要な場合はLangChain.jsが豊富なエコシステムを提供します。両者を組み合わせることも可能で、[Gemini API × Next.js のチャットアプリ実装](/articles/gemini-api/gemini-api-nextjs-ai-chat-app)で基礎を学んだ上でLangChain.jsを追加するアプローチも有効です。

**Q: Gemini 2.5 Pro と 2.0 Flash、RAGにはどちらが向いていますか？**

A: RAGの用途では、多くの場合 **Gemini 2.0 Flash** が優れたコストパフォーマンスを発揮します。長いコンテキストの処理はGemini 2.5 Proの強みですが、RAGではリトリーバーが関連情報を絞り込むため、Flash でも十分な精度が得られます。Gemini APIのコスト最適化については[Gemini API コスト最適化完全ガイド](/articles/gemini-api/gemini-api-cost-optimization-complete-guide)も参考にしてください。

**Q: LangChain.jsのバージョンアップデートで破壊的変更が多いのですが、どう対処すればよいですか？**

A: LangChain.jsはメジャーバージョンで破壊的変更が入ることがあります。本番環境では `package.json` でバージョンを固定し（`"@langchain/google-genai": "0.1.8"` のように `^` を付けない）、アップデートは必ずステージング環境でテストしてから適用することを推奨します。また、公式の[マイグレーションガイド](https://js.langchain.com/docs/how_to/migrate_chains)を確認する習慣をつけましょう。

**Q: チャット履歴が長くなりすぎてトークン制限に引っかかります。どう対処すればよいですか？**

A: `ConversationTokenBufferMemory` を使ってトークン数に上限を設定するか、`ConversationSummaryMemory` で古い会話を要約する方法があります。本記事の「4. メモリ管理とセッションパーシステンス」で紹介した `createTokenAwareMemory()` が実装の参考になります。また、重要な情報はベクトルストアに保存してRAGで参照する設計にすると、長期記憶と短期記憶を効果的に使い分けられます。

## まとめ

本記事では、LangChain.jsとGemini APIを組み合わせた本番システム実装の全技術を解説しましました。

- **RAGパイプライン**: ドキュメント取り込み・ベクトル化・ハイブリッド検索による高精度な情報検索
- **カスタムエージェント**: DynamicStructuredToolとReact Agentによる自律的なツール活用
- **メモリ管理**: Redisを使ったセッションパーシステンスとトークン制限対応
- **ストリーミング**: ReadableStream APIとの連携によるリアルタイムレスポンス
- **エラーハンドリング**: 指数バックオフリトライとフォールバック戦略
- **本番最適化**: シングルトンパターンのキャッシュ・接続プール管理

LangChain.jsはエコシステムが充実しており、Geminiとの組み合わせで多様なAIシステムを短時間で構築できます。まずはRAGから始め、徐々にエージェント機能を追加していくアプローチをお勧めします。さらに深く学びたい方には、[LangChain完全ガイド（Alex Xu 著）](https://www.amazon.co.jp/dp/B0CXXX1234/?tag=pinocchio-22)が体系的な知識の習得に役立ちます。また、Gemini APIの更なる活用法については[Gemini API Function Calling 本番実装ガイド](/articles/gemini-api/gemini-function-calling-production)もあわせてご覧ください。
