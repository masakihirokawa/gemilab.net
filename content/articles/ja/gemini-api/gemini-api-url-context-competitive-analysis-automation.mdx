競合サイトのチェックを毎朝手作業でやっていませんか。3サイト回って価格を比べて、気になった記事をメモして — 気づくと30分経っている、という経験は私にも覚えがあります。

Gemini API には `url_context` というツールがあり、URLを渡すだけでページのコンテンツをAIが読み込んで処理してくれます。これを使えば、「複数の競合サイトを一括比較してまとめてほしい」「特定ページの価格が変わったら教えてほしい」といった作業をコードで自動化できます。

この記事では、URL Context ツールの基本から始めて、競合分析・価格監視という実用的なシステムを段階的に組み上げるコードをご紹介します。

## URL Context ツールの基本

[URL Context の基本的な呼び出し方](/articles/gemini-api/gemini-url-context-guide)はすでに解説記事がありますが、実践的な自動化に向けてポイントをおさらいします。

```python
from google import genai
from google.genai.types import Tool, GenerateContentConfig

client = genai.Client(api_key="YOUR_GEMINI_API_KEY")

# url_context ツールを有効化
url_tool = Tool(url_context={})

response = client.models.generate_content(
    model="gemini-2.5-pro-preview-05-06",
    contents="このページの概要と主な料金プランを教えてください: https://example.com/pricing",
    config=GenerateContentConfig(
        tools=[url_tool],
        temperature=0.2,
    ),
)

print(response.text)
```

ポイントは `temperature=0.2` を設定していることです。競合分析や価格抽出のような事実確認タスクでは、創造性より正確さが求められます。高めの temperature だと存在しない数字を「補完」してしまうことがあるので、この種の用途では低い値に設定することをおすすめします。

## 複数サイトを一括比較する競合分析システム

単一URLでの動作を確認したら、次は複数サイトを比較するシステムを組みます。鍵は「比較軸を明示したプロンプト」と「構造化出力」の組み合わせです。

```python
import json
from google import genai
from google.genai.types import Tool, GenerateContentConfig, Schema, Type

client = genai.Client(api_key="YOUR_GEMINI_API_KEY")

def analyze_competitors(competitor_urls: list[str], product_category: str) -> dict:
    """
    複数の競合サイトを分析して比較レポートを返す。
    価格・機能・差別化ポイントを構造化データとして抽出する。
    """
    url_tool = Tool(url_context={})

    # レスポンスの型を定義（これで出力が必ずJSONになる）
    competitor_schema = Schema(
        type=Type.OBJECT,
        properties={
            "site_name": Schema(type=Type.STRING),
            "main_price": Schema(
                type=Type.STRING,
                description="主力プランの価格（通貨含む）。記載なければ「要問い合わせ」"
            ),
            "key_features": Schema(
                type=Type.ARRAY,
                items=Schema(type=Type.STRING),
                description="主要機能（最大5つ）"
            ),
            "target_user": Schema(type=Type.STRING),
            "differentiator": Schema(type=Type.STRING, description="他社との差別化ポイント"),
        },
        required=["site_name", "main_price", "key_features", "target_user", "differentiator"],
    )
    report_schema = Schema(
        type=Type.OBJECT,
        properties={
            "product_category": Schema(type=Type.STRING),
            "competitors": Schema(type=Type.ARRAY, items=competitor_schema),
            "market_insights": Schema(
                type=Type.STRING,
                description="市場全体の傾向・共通点・差異のサマリー"
            ),
        },
        required=["product_category", "competitors", "market_insights"],
    )

    urls_text = "\n".join(f"- {url}" for url in competitor_urls)
    prompt = f"""
以下の{len(competitor_urls)}つのサービスサイトを読み込み、
{product_category}市場における競合比較レポートを作成してください。

対象URL:
{urls_text}

各サービスについて: サービス名・価格・主要機能(最大5つ)・
想定ターゲット・差別化ポイントを抽出してください。
最後に市場全体のインサイトをまとめてください。
"""

    response = client.models.generate_content(
        model="gemini-2.5-pro-preview-05-06",
        contents=prompt,
        config=GenerateContentConfig(
            tools=[url_tool],
            response_mime_type="application/json",
            response_schema=report_schema,
            temperature=0.1,
        ),
    )

    return json.loads(response.text)

# 使用例
if __name__ == "__main__":
    urls = [
        "https://notion.so/pricing",
        "https://www.atlassian.com/software/confluence/pricing",
        "https://coda.io/pricing",
    ]

    report = analyze_competitors(urls, "ナレッジ管理ツール")
    print(json.dumps(report, ensure_ascii=False, indent=2))
```

`response_schema` に型定義を渡すことで、AIの出力を確実に JSON として受け取れます。このパターンは[構造化出力を使った Web スクレイピング自動化](/articles/gemini-api/gemini-api-structured-output-web-scraping-automation)でも詳しく解説していますが、「複数ソースを比較してまとめる」タスクとの相性が特によいです。

実行すると、各サービスの情報がオブジェクトの配列として返ってきます。これをそのままスプレッドシートに書き込んだり、差分を比較したりといった後続処理につなげられます。

## 価格変動監視システム

競合の価格が変わったときに Slack で通知を受け取れると、対応が早くなります。以下は定期実行を想定した価格監視スクリプトです。

```python
import json
import os
import hashlib
from datetime import datetime
from pathlib import Path
from google import genai
from google.genai.types import Tool, GenerateContentConfig, Schema, Type
import urllib.request

client = genai.Client(api_key="YOUR_GEMINI_API_KEY")
PRICE_CACHE_FILE = Path("price_cache.json")

def extract_pricing(url: str) -> dict:
    """指定URLから価格情報を抽出する。"""
    url_tool = Tool(url_context={})

    price_schema = Schema(
        type=Type.OBJECT,
        properties={
            "plans": Schema(
                type=Type.ARRAY,
                items=Schema(
                    type=Type.OBJECT,
                    properties={
                        "plan_name": Schema(type=Type.STRING),
                        "price": Schema(type=Type.STRING),
                        "billing_cycle": Schema(
                            type=Type.STRING,
                            description="月額/年額/買い切りなど"
                        ),
                    },
                    required=["plan_name", "price", "billing_cycle"],
                ),
            ),
            "currency": Schema(type=Type.STRING),
        },
        required=["plans", "currency"],
    )

    response = client.models.generate_content(
        model="gemini-2.5-flash-preview-04-17",  # 監視タスクはFlashで十分・低コスト
        contents=f"このページの料金プランをすべて抽出してください: {url}",
        config=GenerateContentConfig(
            tools=[url_tool],
            response_mime_type="application/json",
            response_schema=price_schema,
            temperature=0.0,
        ),
    )
    return json.loads(response.text)

def check_price_change(url: str) -> tuple[bool, dict, dict | None]:
    """
    価格変動を検知する。
    戻り値: (変化あり, 最新データ, 前回データ)
    変化の判定はJSONのハッシュ比較で行う（シンプルかつ確実）。
    """
    current_pricing = extract_pricing(url)

    cache = {}
    if PRICE_CACHE_FILE.exists():
        with open(PRICE_CACHE_FILE) as f:
            cache = json.load(f)

    current_hash = hashlib.md5(
        json.dumps(current_pricing, sort_keys=True, ensure_ascii=False).encode()
    ).hexdigest()

    url_key = hashlib.md5(url.encode()).hexdigest()
    previous_entry = cache.get(url_key)
    changed = previous_entry is None or previous_entry.get("hash") \!= current_hash

    # キャッシュを更新
    cache[url_key] = {
        "url": url,
        "hash": current_hash,
        "data": current_pricing,
        "checked_at": datetime.now().isoformat(),
    }
    with open(PRICE_CACHE_FILE, "w") as f:
        json.dump(cache, f, ensure_ascii=False, indent=2)

    previous_data = previous_entry.get("data") if previous_entry else None
    return changed, current_pricing, previous_data

def send_slack_notification(url: str, current: dict, previous: dict | None):
    """価格変更を Slack に通知する。"""
    webhook_url = os.environ["SLACK_WEBHOOK_URL"]
    label = "（初回検出）" if previous is None else "価格変更を検出"
    message = {
        "text": (
            f"💰 *{label}*\n"
            f"対象: {url}\n"
            f"```{json.dumps(current, ensure_ascii=False, indent=2)}```"
        )
    }
    req = urllib.request.Request(
        webhook_url,
        data=json.dumps(message).encode(),
        headers={"Content-Type": "application/json"},
    )
    urllib.request.urlopen(req)

# 監視対象URLリスト（環境に合わせて変更してください）
MONITOR_URLS = [
    "https://openai.com/api/pricing",
    "https://www.anthropic.com/pricing",
]

for target_url in MONITOR_URLS:
    changed, current, previous = check_price_change(target_url)
    if changed:
        print(f"変化あり: {target_url}")
        send_slack_notification(target_url, current, previous)
    else:
        print(f"変化なし: {target_url}")
```

監視タスクには `gemini-2.5-flash` を使っています。Proモデルは精度が高い分コストも高くなりますが、価格抽出のような単純なタスクには Flash で十分です。[API コストの最適化](/articles/gemini-api/gemini-api-cost-optimization)という観点からも、タスクの性質に合わせてモデルを使い分けることをおすすめします。

このスクリプトを cron や GitHub Actions で1日1〜2回実行するだけで、競合の価格変更を見逃さない仕組みが完成します。

## 実運用でわかった3つの制限と回避策

URL Context ツールを実際のシステムに組み込んで気づいた点を正直にお伝えします。

**JavaScript で動的に生成されるページは読めないことがある**

SPA（シングルページアプリケーション）や、ログイン後にしか表示されないコンテンツは取得できません。React で価格が動的にレンダリングされているサービスでは「価格情報が見つかりませんでした」と返ることがありました。静的な HTML として確認できるページを対象にすると安定します。もし取得できないページがある場合は、キャッシュ版（Google の検索結果にある「キャッシュ」リンク）のURLを試してみる方法もあります。

**同じURLへのリクエストは間隔をあけて**

価格監視のような定期実行タスクで頻度を上げすぎると、対象サイト側からブロックされる可能性があります。実運用では1日1〜2回の実行で十分なことがほとんどです。また、Gemini API 自体のレート制限にも注意が必要で、監視URLが多い場合は `time.sleep(5)` を挟んでリクエスト間隔を確保してください。

**取得結果は必ずバリデーションする**

AI がページを読み込んだとき、意図通りに解釈されないこともあります。価格のように数値の精度が重要なデータは、取得後に期待する形式に合っているかチェックするコードを必ず入れてください。上記のコードでも `response_schema` で型を強制していますが、それでも稀に想定外の値が返ることはあります。プロダクション運用では、取得した価格が数値に変換できることを確認するアサーションを追加しておくと安心です。

## まとめ

URL Context ツールの価値は「ブラウザを開かずに Web ページの内容をAIに処理させられる」点にあります。競合の価格チェックに毎朝かけていた時間が、夜間バッチと Slack 通知に変わる — そういう小さな効率化の積み重ねが、個人開発者としての時間を生み出してくれます。

まずは手元の環境で単一 URL に対してAPIを呼び出してみてください。動いたら、今回のコードを参考にご自身のユースケースに合わせて拡張していただければと思います。
