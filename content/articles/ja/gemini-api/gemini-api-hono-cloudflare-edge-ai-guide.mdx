## はじめに：なぜエッジで Gemini API を動かすのか

AI アプリケーションの開発において、レスポンス速度とコストは常に重要な課題です。従来のサーバーレス関数（AWS Lambda など）は起動レイテンシが大きく、グローバルなユーザーへの提供に課題がありましました。

そこで注目されているのが **Cloudflare Workers** に代表するエッジコンピューティングです。世界 300 以上のデータセンターにデプロイされ、ユーザーに最も近い拠点からコードが実行されるため、コールドスタートがほぼゼロで超低レイテンシを実現できます。

この記事では、近年急速に人気を集めているウェブフレームワーク **Hono.js** と **Gemini API** を組み合わせて、エッジ対応の AI API サーバーを構築する方法をステップバイステップで解説します。TypeScript の型安全な実装例と、ストリーミング対応の実践的なコードまで丁寧に紹介していきます。

対象読者は以下のような方を想定しています。

- Gemini API の基本的な使い方は知っている
- TypeScript の基礎がある
- エッジ環境での AI 活用に興味がある

Gemini API 自体が初めての方は、まず [Gemini API TypeScript 完全入門ガイド](/articles/gemini-api/gemini-api-typescript-complete-beginners-guide) をご覧いただくと理解が深まります。

## Hono.js とは？Gemini API との相性

**Hono.js**（炎、を意味する日本語が語源）は、TypeScript ファーストで設計された超高速ウェブフレームワークです。Cloudflare Workers・Deno・Bun・Node.js など主要なエッジランタイムで動作し、Express ライクな直感的 API を持ちながらバンドルサイズが非常に小さいのが特徴です。

Gemini API との相性が特に優れている理由を挙げてみましょう。

- **Web Standards API 準拠**: Hono.js は `Request`/`Response`/`ReadableStream` などの標準 Web API を使用。Gemini SDK のストリーミングレスポンスとそのまま統合できます。
- **TypeScript ネイティブ**: ルートの型付け、ミドルウェアの型推論が強力で、Gemini SDK の型定義と自然に組み合わせられます。
- **ゼロ依存に近い軽量設計**: エッジ環境のバンドルサイズ制限（Cloudflare Workers は 1 MB 以下を推奨）に収まりやすい設計です。

## Gemini API チャットエンドポイントの実装

プロジェクトの中核となる `src/index.ts` を実装しましょう。型安全性を意識した設計にしています。

```typescript
// src/index.ts
import { Hono } from "hono";
import { cors } from "hono/cors";
import { GoogleGenerativeAI } from "@google/generative-ai";

// 環境変数の型定義（Cloudflare Workers Bindings）
type Bindings = {
  GEMINI_API_KEY: string;
};

// リクエストボディの型定義
type ChatRequest = {
  message: string;
  history?: { role: "user" | "model"; parts: { text: string }[] }[];
};

const app = new Hono<{ Bindings: Bindings }>();

// CORS ミドルウェアを全ルートに適用
app.use("*", cors({ origin: "*" }));

// ヘルスチェックエンドポイント
app.get("/", (c) => {
  return c.json({ status: "ok", model: "gemini-2.5-flash" });
});

// チャットエンドポイント（非ストリーミング）
app.post("/api/chat", async (c) => {
  // リクエストボディを型付きで取得
  const body = await c.req.json<ChatRequest>();

  if (!body.message) {
    return c.json({ error: "message is required" }, 400);
  }

  // Cloudflare Workers の Bindings から API キーを取得
  const genAI = new GoogleGenerativeAI(c.env.GEMINI_API_KEY);
  const model = genAI.getGenerativeModel({ model: "gemini-2.5-flash" });

  // チャット履歴がある場合はマルチターン会話を継続
  const chat = model.startChat({ history: body.history ?? [] });

  const result = await chat.sendMessage(body.message);
  const text = result.response.text();

  return c.json({
    reply: text,
    usage: result.response.usageMetadata,
  });
});

export default app;
```

ローカルで動作確認をしてみましょう。


## ストリーミングレスポンスの実装

AI のレスポンスを文字が生成されるたびにリアルタイムで返すストリーミングは、ユーザー体験を大幅に向上させます。Hono.js の `streamText` ヘルパーを使えばシンプルに実装できます。

```typescript
// src/index.ts に追記
import { streamText } from "hono/streaming";

// ストリーミング対応チャットエンドポイント
app.post("/api/chat/stream", async (c) => {
  const body = await c.req.json<ChatRequest>();

  if (!body.message) {
    return c.json({ error: "message is required" }, 400);
  }

  const genAI = new GoogleGenerativeAI(c.env.GEMINI_API_KEY);
  const model = genAI.getGenerativeModel({ model: "gemini-2.5-flash" });
  const chat = model.startChat({ history: body.history ?? [] });

  // Hono の streamText を使って Server-Sent Events 形式でストリーミング
  return streamText(c, async (stream) => {
    const result = await chat.sendMessageStream(body.message);

    for await (const chunk of result.stream) {
      const text = chunk.text();
      if (text) {
        // SSE 形式で送信
        await stream.write(`data: ${JSON.stringify({ text })}\n\n`);
      }
    }

    // ストリーム終了シグナル
    await stream.write("data: [DONE]\n\n");
  });
});
```

フロントエンドからは以下のように受信できます。

```typescript
// フロントエンドでのストリーミング受信例
const response = await fetch("/api/chat/stream", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ message: "Hono.js の特徴を教えて" }),
});

const reader = response.body!.getReader();
const decoder = new TextDecoder();

while (true) {
  const { done, value } = await reader.read();
  if (done) break;

  const lines = decoder.decode(value).split("\n\n");
  for (const line of lines) {
    if (line.startsWith("data: ")) {
      const data = line.slice(6);
      if (data === "[DONE]") break;
      const { text } = JSON.parse(data);
      process.stdout.write(text); // 生成されるたびに出力
    }
  }
}
```

## エラーハンドリングとレート制限対応

本番環境では、Gemini API のレート制限（429 エラー）や一時的なサービス障害への対処が欠かせません。Hono.js のミドルウェアを活用して一元的に処理しましょう。

```typescript
// src/middleware/errorHandler.ts
import { Context, Next } from "hono";

export async function errorHandler(c: Context, next: Next) {
  try {
    await next();
  } catch (error: unknown) {
    // Gemini API のエラーを分類して適切なレスポンスを返す
    if (error instanceof Error) {
      if (error.message.includes("429") || error.message.includes("RESOURCE_EXHAUSTED")) {
        return c.json(
          { error: "レート制限に達しました。しばらく待ってから再試行してください。", retryAfter: 60 },
          429
        );
      }
      if (error.message.includes("SAFETY")) {
        return c.json({ error: "安全フィルターによりコンテンツが生成されませんでした。" }, 400);
      }
    }
    console.error("Unexpected error:", error);
    return c.json({ error: "サーバーエラーが発生しました。" }, 500);
  }
}
```

`src/index.ts` でミドルウェアを適用します。

```typescript
import { errorHandler } from "./middleware/errorHandler";
app.use("*", errorHandler);
```

レート制限の詳細なパターンについては、[Gemini API エラーハンドリング＆レート制限 完全攻略](/articles/gemini-dev/gemini-api-error-handling-rate-limit-production-patterns) で体系的に解説しています。

## よくある質問（FAQ）

**Q1. Hono.js と Express はどちらが Gemini API との相性が良いですか？**

エッジ環境（Cloudflare Workers・Deno Deploy など）での動作を前提とする場合は Hono.js が最適です。Express は Node.js 専用で、エッジランタイムでは動作しません。一方、既存の Node.js サーバーと統合する場合は Express も選択肢になります。Hono.js は Express ライクな API を持つため、Express に慣れた開発者でも違和感なく移行できます。

**Q2. Cloudflare Workers の CPU 時間制限が心配です。Gemini API の呼び出しに影響しますか？**

Cloudflare Workers には CPU 時間の制限（無料プランは 10ms、有料プランは 30 秒）がありますが、`waitUntil` を使えばレスポンス送信後もバックグラウンド処理を続けられます。Gemini API の呼び出し自体はネットワーク I/O のため CPU 時間としてカウントされず、通常のチャット程度であれば制限に引っかかることはほぼありません。ただし、複雑なバッチ処理は Cloudflare Workers よりも Queue + Worker の組み合わせを検討してください。

**Q3. API キーのセキュリティはどのように確保しますか？**

`wrangler secret put` で設定したシークレットは Cloudflare の暗号化されたシークレットストアに保存され、コード中に平文で現れることはありません。絶対にソースコードや `.env` ファイルをリポジトリにコミットしないでください。また、本番環境では Gemini API のキーに IP 制限やリファラー制限を設けることも検討してください。型安全な設計パターンについては [Gemini API × TypeScript 型安全アプリケーション設計ガイド](/articles/gemini-api/gemini-api-typescript-typesafe-ai-application-architecture) が参考になります。

## まとめ

この記事では、Hono.js と Gemini API を組み合わせたエッジ対応 AI API サーバーの構築方法を解説しましました。要点をまとめると以下のとおりです。

- **Hono.js** は Web Standards 準拠・軽量・TypeScript ファーストでエッジ環境に最適なフレームワーク
- **Cloudflare Workers Bindings** で API キーを安全に管理し、型安全な実装が可能
- **ストリーミング対応**は `streamText` ヘルパーと `sendMessageStream` の組み合わせで簡潔に実現
- **エラーハンドリング**はミドルウェアで一元管理し、429 エラーなど本番特有のケースに備える

エッジ AI の活用は、レスポンス速度の改善だけでなく、グローバルな展開コストの削減にも大きく貢献します。Hono.js の軽量さと Gemini API の高い能力を組み合わせることで、スケーラブルで高品質な AI バックエンドをシンプルに構築できます。ぜひ実際にプロジェクトで試してみてください。
