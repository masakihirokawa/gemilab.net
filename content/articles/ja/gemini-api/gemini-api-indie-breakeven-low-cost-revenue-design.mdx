## 「Gemini API は安い」は本当か — 個人開発者の現実

Gemini API は、Claude や OpenAI と比較しても価格レンジが安く、特に Flash 系モデルは個人開発者にとって非常に魅力的な選択肢です。ただ、「安い」と聞いて飛び込むと、ユーザーの使い方しだいで月のコストが想像の3〜4倍に跳ね上がることがあります。私自身、最初にチャット系のサービスを Gemini Flash で立ち上げたとき、長文の会話履歴を毎回まるごと送る実装にしてしまい、想定の月額¥1,500が実際には月額¥6,000を超えました。

この記事では、Gemini API で個人開発者が**月3,000円のコストで月3万円の収益を出す**最小設計を、私自身の運用データに基づいてご紹介します。月10万円や月100万円ではなく、まずは「黒字化」と「黒字幅2万円台」を目標にする現実的な話です。

## 黒字化のための前提式 — 1ユーザーあたりの粗利を計算する

最初にやるべきは、1ユーザーあたりのコストを計算することです。これを把握しないまま値付けをすると、ユーザーが増えるほど赤字が広がる地獄に陥ります。

```
1ユーザーあたり月コスト = 1日あたり平均トークン消費 × 30 × Gemini モデル単価
```

たとえば Gemini 2.5 Flash で、1ユーザーあたり1日に入出力合わせて10,000トークン消費する想定なら、月コストはおよそ¥30〜¥80程度に収まります。月額¥580のサブスクで提供する場合、粗利は1ユーザーあたり約¥500、粗利率は85〜90%です。

ここで重要なのは、**入力トークンと出力トークンの単価が大きく違う**ことです。Gemini 2.5 Flash では入力1Mトークンあたり約¥45、出力1Mトークンあたり約¥360（為替レートにより変動）と、出力単価が入力の8倍ほどになります。出力を短く抑える設計が、コスト最適化の最重要ポイントです。

## Free Tier を「リリース後3ヶ月」までフル活用する

Gemini API の最大の武器は、寛大な Free Tier です。2026年4月時点で、Gemini 2.5 Flash Lite には1分あたり15リクエスト、1日あたり1,500リクエストの無料枠があります。

個人開発者が黒字化に到達するまでの最短ルートは、**リリース後3ヶ月は Free Tier だけで動かす**設計を最初から組むことです。具体的には次のようにします。

第一に、**初期はモデル選択を Flash Lite に固定する**ことです。Flash Lite は精度よりレスポンス速度とコスト優先のモデルですが、テキスト要約・分類・タグ抽出・短い質問応答といった用途には十分以上の性能があります。

第二に、**1ユーザーあたりの日次リクエスト上限を5回に制限する**ことです。1,500リクエスト/日 ÷ 5回 = 300人までは Free Tier 内で運用できます。月3万円の収益（月額¥580 × 50人継続）に到達するまでの距離なら、ほとんどの個人開発者が Free Tier 圏内に収まります。

第三に、**バッチ処理を1日1回に集約する**ことです。たとえば「毎日のニュース要約」のような機能は、ユーザーごとにリクエストを送るのではなく、1日1回まとめて処理して結果を全ユーザーに配信します。

## コスト爆発を防ぐ3つの設計パターン

Free Tier を超えても、月3,000円のコストで運用するためのコスト最適化パターンは、次の3つを最低限押さえておきます。

### パターン1: Context Caching を使う

Gemini API には Context Caching という機能があり、同じシステムプロンプトや同じドキュメントを繰り返し送る場合に、キャッシュされたトークンの単価が約4分の1になります。チャットボットのようにシステムプロンプトが固定の場合、これを使うとコストが体感で半分以下になります。

```typescript
import { GoogleGenAI } from "@google/genai";

const ai = new GoogleGenAI({ apiKey: process.env.GEMINI_API_KEY });

const cache = await ai.caches.create({
  model: "gemini-2.5-flash",
  contents: longSystemPrompt,
  ttl: "3600s",
});

const response = await ai.models.generateContent({
  model: "gemini-2.5-flash",
  contents: userMessage,
  cachedContent: cache.name,
});
```

### パターン2: 出力を短く抑える max_output_tokens 設定

Gemini API は `maxOutputTokens` をデフォルトで上限なしに動作させると、長すぎるレスポンスを返してコストを膨らませることがあります。出力長が予測できる用途であれば、必ず明示的に上限を設定します。

```typescript
const response = await ai.models.generateContent({
  model: "gemini-2.5-flash-lite",
  contents: prompt,
  config: { maxOutputTokens: 256 },
});
```

256トークンは日本語にすると約180〜200文字、英語で約180ワード程度です。要約や短い回答であれば十分なボリュームです。

### パターン3: ユーザー単位の日次トークンキャップ

サブスクユーザーであっても、無制限利用にすると、1人の重ヘビーユーザーが月コストの大半を消費する事故が起きます。私の運用では、月額プランでも1日あたり50,000トークンまでの上限を設けています。

```typescript
const DAILY_TOKEN_CAP = 50_000;

async function checkAndIncrement(userId: string, tokens: number) {
  const today = new Date().toISOString().slice(0, 10);
  const key = `quota:${userId}:${today}`;
  const current = parseInt((await kv.get(key)) ?? "0", 10);
  if (current + tokens > DAILY_TOKEN_CAP) {
    throw new Error("Daily quota exceeded");
  }
  await kv.put(key, String(current + tokens), { expirationTtl: 60 * 60 * 26 });
}
```

## 月3万円の収益にたどり着く最短ルート

月3万円を Gemini API ベースの個人開発で達成するための最短ルートは、次の3パターンのいずれかです。

| ルート | 単価 | 必要な顧客数 | 立ち上がりやすさ |
|---|---|---|---|
| サブスク（月額¥580） | ¥580 | 月50名継続 | 中 |
| 買い切り（¥1,980） | ¥1,980 | 月15本販売 | 高 |
| 既存サービスへの上乗せ | 既存ユーザーの5% | 既存300人 × 5% × ¥600 | 最高 |

私のおすすめは、すでに何らかの無料アプリ・無料サービスを運営している方なら**3つ目（既存サービスへの上乗せ）**、ゼロから始める方なら**2つ目（買い切り）**です。サブスクは継続を維持する運用負荷が高く、最初の3万円までの距離が長く感じられがちです。

## 黒字化までに「やらないこと」を決める

個人開発で Gemini API ベースのサービスを黒字化するうえで、もっとも重要なのは「**やらないこと**」を決めることです。

具体的には次のようなものは最初の3ヶ月では一切やりません。

- ユーザー認証の本格実装（Stripe Checkout の email + Cookie で十分）
- マルチテナント設計（個人向けサービスならシングルテナントで OK）
- ストリーミングレスポンス（Free Tier の段階では非ストリーミングで OK）
- 多言語対応（日英2言語に限定）
- モバイルアプリ化（Web で十分）

これらは3ヶ月運用してユーザーが定着し、月3万円が安定して入ってきた段階で、必要なものだけ着手すれば十分間に合います。

ただし、いま重要なのは、**今日選んだ1つのアイデアを Free Tier の範囲で動かしてみること**です。3,000円のコスト枠の中で動くプロトタイプを来週中に作れるかどうかが、黒字化までの距離を最短にします。
