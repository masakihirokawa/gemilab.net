Gemini 2.5 Proは、100万トークンのコンテキストウィンドウと深い推論能力を持つ、現時点でGoogleが提供する最高性能のモデルです。ただし、その強力さゆえに使い方を間違えると、コストが爆発したり、レスポンスが遅くなりすぎたりします。

Gemini API を実プロダクトで運用してきた知見から、この問題に普段から向き合ってきた立場で、要点を整理します。

2014年からの個人開発と AdMob 収益化の経験を踏まえて、現場で効くポイントだけ抽出します。

## Gemini 2.5 Pro の特性を理解する

まず、Gemini 2.5 Proが他のモデルと何が違うのかを把握しておきましょう。

**コンテキストウィンドウ**: 最大100万トークン（入力）+ 8,192トークン（出力）

**推論モード（Thinking）**: 複雑な問題に対して内部で多段階の推論を行う機能。精度は上がりますが、レスポンス時間とコストが増加します。

**マルチモーダル**: テキスト・画像・動画・音声・PDFを1つのリクエストで扱えます。

これらの特性を活かすほど価値が高まりますが、同時にコストも増えます。本番運用ではどの機能をいつ使うかの判断が重要です。

## ストリーミングAPIの本番実装

長文生成には必ずストリーミングを使ってください。一括取得だとHTTPタイムアウトが発生します。

```python
import google.generativeai as genai
import os
import time
from google.api_core import exceptions
from typing import Generator

genai.configure(api_key=os.environ["GOOGLE_API_KEY"])

class GeminiProClient:
    """Gemini 2.5 Pro の本番向けクライアント"""
    
    def __init__(self, model_name: str = "gemini-2.5-pro-preview-05-06"):
        self.model = genai.GenerativeModel(
            model_name,
            generation_config=genai.GenerationConfig(
                max_output_tokens=8192,
                temperature=0.7,
                top_p=0.95,
            )
        )
        self.model_name = model_name
    
    def generate_stream(
        self, 
        prompt: str,
        system_instruction: str | None = None
    ) -> Generator[str, None, None]:
        """
        ストリーミングでテキストを生成する。
        チャンクごとにyieldするのでWebアプリのSSEにも使える。
        """
        # system_instructionがある場合はモデルを再構成
        model = self.model
        if system_instruction:
            model = genai.GenerativeModel(
                self.model_name,
                system_instruction=system_instruction,
                generation_config=self.model.generation_config
            )
        
        for attempt in range(4):
            try:
                response = model.generate_content(prompt, stream=True)
                
                for chunk in response:
                    if chunk.text:
                        yield chunk.text
                
                # ストリーム完了後に使用量を確認
                usage = response.usage_metadata
                print(f"[完了] 入力: {usage.prompt_token_count} tokens, "
                      f"出力: {usage.candidates_token_count} tokens")
                return
            
            except exceptions.ResourceExhausted:
                if attempt == 3:
                    raise
                wait = 2 ** attempt
                print(f"レート制限: {wait}秒後にリトライ")
                time.sleep(wait)
            
            except exceptions.DeadlineExceeded:
                # タイムアウト: ストリーミング使用中はほぼ発生しないが念のため
                print("タイムアウト発生。ストリーミングを確認してください。")
                raise
    
    def generate_full(self, prompt: str, **kwargs) -> str | None:
        """
        完全なテキストを収集して返す（短い応答向け）。
        """
        full_text = ""
        try:
            for chunk in self.generate_stream(prompt, **kwargs):
                full_text += chunk
            return full_text
        except Exception as e:
            print(f"生成エラー: {e}")
            return None

# 使用例
client = GeminiProClient()

# ストリーミング（長文向け）
print("生成中... ", end="", flush=True)
for chunk in client.generate_stream(
    "量子コンピュータの仕組みを詳しく解説してください",
    system_instruction="あなたは技術解説の専門家です。初心者にも分かりやすく説明してください。"
):
    print(chunk, end="", flush=True)
print()

# 一括取得（短い応答向け）
result = client.generate_full("Pythonのリスト内包表記とは何ですか？")
print(result)
```

## Context Cachingでコストを大幅削減

Gemini 2.5 Proの最大の特徴の1つが**Context Caching**です。同じ大きなコンテキスト（ドキュメント、コードベース、プロンプト）を繰り返し使う場合、キャッシュを使うと入力トークンコストを最大75%削減できます。

```python
import google.generativeai as genai
from google.generativeai import caching
import datetime
import os

genai.configure(api_key=os.environ["GOOGLE_API_KEY"])

# 大きなドキュメントを一度キャッシュに登録
def create_document_cache(document_text: str, ttl_minutes: int = 60):
    """
    大きなドキュメントをキャッシュに登録する。
    同じドキュメントに複数の質問をする場合に有効。
    
    コスト例: 100万トークンのドキュメントに対して10回質問する場合
    - キャッシュなし: 100万 × 10 = 1000万入力トークン分の課金
    - キャッシュあり: キャッシュ登録1回 + キャッシュヒット料金（〜75%割引）
    """
    cache = caching.CachedContent.create(
        model="models/gemini-2.5-pro-preview-05-06",
        display_name="document-analysis-cache",
        system_instruction=(
            "あなたは提供されたドキュメントを深く分析する専門家です。"
            "正確な情報のみを回答し、ドキュメントに記載のない情報は推測しないでください。"
        ),
        contents=[document_text],
        ttl=datetime.timedelta(minutes=ttl_minutes)
    )
    print(f"キャッシュ作成完了: {cache.name}")
    print(f"有効期限: {ttl_minutes}分")
    return cache

def ask_with_cache(cache, question: str) -> str:
    """
    キャッシュ済みコンテキストを使って質問に回答する。
    """
    model = genai.GenerativeModel.from_cached_content(cached_content=cache)
    response = model.generate_content(question)
    
    # キャッシュヒット確認
    usage = response.usage_metadata
    print(f"入力トークン: {usage.prompt_token_count} "
          f"(キャッシュヒット: {usage.cached_content_token_count})")
    
    return response.text

# 大きなドキュメントに複数の質問をする場合の使用例
large_document = """
（100万トークン規模の大きなドキュメント、例: 法律文書・技術仕様書・コードベース）
""" * 100  # 実際には実際のドキュメントを使用

# 一度キャッシュに登録
cache = create_document_cache(large_document, ttl_minutes=120)

# 複数の質問をキャッシュを使って処理
questions = [
    "このドキュメントの主要な要点は何ですか？",
    "リスクに関する記述はありますか？",
    "実装手順をまとめてください",
    "注意事項を箇条書きにしてください",
]

for q in questions:
    answer = ask_with_cache(cache, q)
    print(f"Q: {q}")
    print(f"A: {answer[:200]}...")
    print()

# キャッシュは使い終わったら削除する（課金停止のため）
cache.delete()
print("キャッシュを削除しました")
```

**コスト比較の目安（Gemini 2.5 Pro、2026年4月現在）:**

- 通常の入力: $3.50 / 100万トークン（128k以下）
- キャッシュ済み入力: $0.875 / 100万トークン（75%割引）
- キャッシュストレージ: $4.50 / 100万トークン / 時間

1時間以内に同じドキュメントに10回以上質問するなら、キャッシュが確実に割安になります。

## 推論モード（Thinking）の制御

Gemini 2.5 Proには「思考プロセスを使って推論する」機能があります。複雑な数学・論理問題・コードの設計判断では精度が上がりますが、単純な質問に対して使うとコストと時間が無駄になります。

```python
import google.generativeai as genai
import os

genai.configure(api_key=os.environ["GOOGLE_API_KEY"])

# 思考モードを制御する
def create_model_with_thinking(
    thinking_budget: int = 8192  # 0 = 思考無効, 最大24576
):
    """
    thinking_budget:
    - 0: 思考無効（速い・安い）
    - 1024〜8192: 中程度の推論（バランス型）
    - 24576: 最大推論（遅い・高い、複雑な問題向け）
    """
    return genai.GenerativeModel(
        "gemini-2.5-pro-preview-05-06",
        generation_config=genai.GenerationConfig(
            max_output_tokens=8192,
            thinking_config=genai.ThinkingConfig(
                thinking_budget=thinking_budget
            )
        )
    )

# シンプルな質問 → 思考なし
model_fast = create_model_with_thinking(thinking_budget=0)
response = model_fast.generate_content("Pythonのリスト内包表記の書き方を教えてください")
print("[思考なし]", response.text[:100])

# 複雑な推論問題 → 最大思考
model_deep = create_model_with_thinking(thinking_budget=16000)
complex_problem = """
以下の条件を満たすアルゴリズムを設計してください：
- 10万件のユーザーデータをリアルタイムでグループ分けする
- 各グループの特徴を自動抽出する
- 新しいユーザーを即座に既存グループに分類する
- レイテンシは100ms以下
計算量・実装アプローチ・使用すべきデータ構造を論じてください。
"""
response = model_deep.generate_content(complex_problem)
print("[最大思考]", response.text[:200])
print(f"思考トークン数: {response.usage_metadata.thoughts_token_count}")
```

経験上、以下のガイドラインが役立ちます。

- **思考不要**: 翻訳・要約・単純な質問・テキスト変換
- **中程度の思考（1024〜8192）**: コードレビュー・比較分析・設計提案
- **最大思考（16000+）**: 複雑な数学問題・アーキテクチャ設計・多段階の論理推論

## マルチターン会話の実装

チャットアプリケーションでGemini 2.5 Proを使う場合、会話履歴の管理が重要です。

```python
import google.generativeai as genai
import os
from typing import Optional

genai.configure(api_key=os.environ["GOOGLE_API_KEY"])

class GeminiChatSession:
    """
    Gemini 2.5 Pro によるマルチターン会話管理クラス。
    コンテキストウィンドウの使用量を監視し、上限に近づいたら警告する。
    """
    
    MAX_TOKENS = 800_000  # 100万トークンのうち80%を上限とする（バッファ確保）
    
    def __init__(self, system_instruction: Optional[str] = None):
        self.model = genai.GenerativeModel(
            "gemini-2.5-pro-preview-05-06",
            system_instruction=system_instruction,
            generation_config=genai.GenerationConfig(max_output_tokens=4096)
        )
        self.chat = self.model.start_chat(history=[])
        self.total_tokens_used = 0
    
    def send_message(self, message: str) -> str:
        """
        メッセージを送信し、応答を返す。
        コンテキスト使用量を追跡する。
        """
        # コンテキスト残量の確認
        if self.total_tokens_used > self.MAX_TOKENS * 0.9:
            print(f"⚠️ コンテキストが上限の90%に達しました。"
                  f"新しいセッションを開始することを検討してください。")
        
        try:
            response = self.chat.send_message(message)
            
            # トークン使用量を記録
            usage = response.usage_metadata
            self.total_tokens_used = usage.prompt_token_count
            
            print(f"[コンテキスト使用量: {self.total_tokens_used:,} / 1,000,000 tokens]")
            
            return response.text
        
        except genai.types.StopCandidateException as e:
            print(f"安全フィルターによりブロック: {e}")
            return "申し訳ありませんが、その質問にはお答えできません。"
    
    def get_history_summary(self) -> str:
        """会話履歴の概要を返す"""
        turns = len(self.chat.history)
        return f"会話ターン数: {turns}, 使用トークン: {self.total_tokens_used:,}"
    
    def reset(self) -> None:
        """会話をリセットする"""
        self.chat = self.model.start_chat(history=[])
        self.total_tokens_used = 0
        print("会話をリセットしました")

# 使用例
session = GeminiChatSession(
    system_instruction="あなたはPythonの専門家です。実践的なアドバイスを提供してください。"
)

messages = [
    "Pythonで大量のファイルを効率的に処理する方法を教えてください",
    "並列処理を使う場合の注意点は？",
    "マルチプロセスとスレッドの使い分けはどうすればいいですか？",
]

for msg in messages:
    print(f"\nQ: {msg}")
    response = session.send_message(msg)
    print(f"A: {response[:200]}...")

print(f"\n{session.get_history_summary()}")
```

## よくある落とし穴と対処法

実際の本番運用で踏んだ問題をまとめます。

### ❌ 落とし穴1: 応答を毎回チェックしない

```python
# ❌ candidates が空のままテキスト取得しようとする
response = model.generate_content("質問")
text = response.text  # candidates が空なら AttributeError

# ✅ 安全な取得
def get_text_safe(response) -> str | None:
    if not response.candidates:
        return None
    candidate = response.candidates[0]
    if candidate.finish_reason.name not in ("STOP", "MAX_TOKENS"):
        return None
    try:
        return candidate.content.parts[0].text
    except (IndexError, AttributeError):
        return None
```

### ❌ 落とし穴2: Context Cachingのコストを忘れる

キャッシュは使わなくてもストレージコストが発生します。長時間TTLを設定してほぼ使わなかった場合、通常より高くつくことがあります。TTLは実際の利用パターンに合わせて設定してください。

### ❌ 落とし穴3: 本番で`preview`モデルを使い続ける

`gemini-2.5-pro-preview-05-06`などのpreviewモデルはGAバージョンと挙動が変わることがあります。本番環境では挙動変化のリスクを許容した上で使うか、GAモデルに切り替えることを検討してください。モデルバージョンはコードにハードコードせず、設定ファイルから読み込む設計にしておくと切り替えが楽です。

```python
# ✅ モデル名を設定から読み込む
import os
MODEL_NAME = os.environ.get("GEMINI_MODEL", "gemini-2.5-pro-preview-05-06")
model = genai.GenerativeModel(MODEL_NAME)
```

### ❌ 落とし穴4: エラーハンドリングを後回しにする

`google.api_core.exceptions`の各例外クラスを個別に処理することで、デバッグが格段に楽になります。

```python
from google.api_core import exceptions as google_exceptions

try:
    response = model.generate_content(prompt)
except google_exceptions.ResourceExhausted:
    # レート制限: リトライで解決
    pass
except google_exceptions.InvalidArgument:
    # 入力が不正: プロンプトを修正
    pass
except google_exceptions.PermissionDenied:
    # 認証エラー: APIキーを確認
    pass
except google_exceptions.ServiceUnavailable:
    # サービス障害: しばらく待ってリトライ
    pass
except google_exceptions.GoogleAPICallError as e:
    # その他のAPIエラー
    print(f"APIエラー {e.grpc_status_code}: {e.message}")
    raise
```

## コスト最適化のまとめ

Gemini 2.5 Proは高性能ですが適切に使わないとコストが跳ね上がります。実践的な削減方法をまとめます。

**モデルの使い分け**: 単純なタスクにはGemini 2.0 Flashを使い、Gemini 2.5 Proは本当に必要な場合だけに絞る。

**Context Caching**: 同じ大きなコンテキストを繰り返し使う場合は必ず活用します。

**Thinking Budget制御**: 複雑さに応じてthinking_budgetを設定します。単純なタスクは0に設定します。

**出力トークンの制御**: `max_output_tokens`を実際に必要な量に合わせる。デフォルトの8,192を全ケースで使うのはもったいない場合があります。

**Batch API**: 即時性が不要な大量処理には[Batch API](https://cloud.google.com/vertex-ai/generative-ai/docs/batch-prediction-gemini)を使う（50%割引）。

まず本番環境でのトークン使用量をログに記録し、どこでコストがかかっているかを可視化することから始めるといいでしょう。数週間のデータがあれば、最も効果的な最適化ポイントが見えてきます。
