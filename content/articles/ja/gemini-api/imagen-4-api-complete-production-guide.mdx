## Imagen 3からImagen 4へ——何が変わったのか

Imagen 4ファミリーがGA（一般提供）となり、Gemini APIから利用できる画像生成モデルが大きく進化しました。前世代のImagen 3と比べて、特に3つの点で差が際立っています。

1つ目はテキスト描画の精度です。Imagen 3では長い文字列をプロンプトに含めると崩れやすかったが、Imagen 4では小さなフォントサイズでも正確にスペルを維持する。ポスター、コミック、スライド用の画像を生成する場合、この改善はそのまま実用性に直結します。

2つ目は解像度。StandardとUltraでは最大2048×2048ピクセル（2K）の出力に対応しており、印刷用途やデジタルサイネージなど、高解像度が求められるシーンでもAPI一発で対応できるようになりました。

3つ目はモデルのティア分け。Fast・Standard・Ultraの3段階が用意され、速度・品質・コストのバランスを用途に応じて選べる。この選択肢の幅こそが、本番運用においてImagen 4を使いやすくしている最大の要因です。

Imagen 3の基本を振り返りたい方は[Imagen 3 API完全ガイド](/articles/gemini-advanced/gemini-imagen-3-image-generation-api-guide)を参照してほしい。

## 3モデルの性能特性とコスト構造

Imagen 4ファミリーの3モデルは、それぞれ明確に異なるユースケースを想定して設計されています。

**Imagen 4 Fast**（`imagen-4.0-fast-generate-001`）は、1枚あたり約2.7秒で生成でき、コストは$0.02/枚。最大解像度は1408×768ピクセル。サムネイル、SNS投稿画像、コンテンツプレビューなど「そこそこの品質を高速に大量生産する」用途に最適です。レート制限は150リクエスト/分と余裕があります。

**Imagen 4 Standard**（`imagen-4.0-generate-001`）は$0.04/枚で、2048×2048ピクセルまでの2K出力に対応する。ディテールの一貫性、プロンプトへの忠実度がFastより明確に高い。ECサイトの商品画像、ブログ記事のアイキャッチ、プレゼン資料など、品質とコストのバランスを取りたい場面で選ぶべきモデルです。レート制限は75リクエスト/分。

**Imagen 4 Ultra**（`imagen-4.0-ultra-generate-001`）は$0.06/枚。ファミリー最高の品質で、テクスチャの忠実度、複雑なシーン構成、テキスト描画の精度において他の2モデルを上回る。フォトリアリスティックな表現が求められるブランド素材、印刷物、広告クリエイティブに向いています。レート制限は30リクエスト/分で、大量生成には不向きだが、1枚1枚の品質を追求する用途では十分です。

ここで重要なのは、「常にUltraを使えばいい」わけではないという点です。FastとUltraの1枚あたりの価格差は3倍だが、実際のプロダクトでは用途に応じてモデルを切り替えるルーティングロジックを組むのが正解になります。この実装パターンは後述します。

## Python SDKでの基本実装

Imagen 4はGoogle Gen AI SDK（`google-genai`）を通じて利用する。以下は3モデルそれぞれの基本的な呼び出し方です。

```python
import os
from google import genai
from google.genai import types

# クライアント初期化
client = genai.Client(api_key=os.environ.get("GEMINI_API_KEY"))

def generate_image(
    prompt: str,
    model: str = "imagen-4.0-generate-001",
    aspect_ratio: str = "1:1",
    number_of_images: int = 1,
    person_generation: str = "allow_adult",
) -> list[bytes]:
    """Imagen 4で画像を生成し、バイトデータのリストを返す"""
    try:
        response = client.models.generate_images(
            model=model,
            prompt=prompt,
            config=types.GenerateImagesConfig(
                number_of_images=number_of_images,
                aspect_ratio=aspect_ratio,
                person_generation=person_generation,
            ),
        )
        images = []
        for generated_image in response.generated_images:
            images.append(generated_image.image.image_bytes)
        return images
    except genai.errors.ClientError as e:
        print(f"ClientError: {e}")
        raise
    except genai.errors.ServerError as e:
        print(f"ServerError: {e}")
        raise

# Fast: SNSサムネイル生成（高速・低コスト）
thumbnails = generate_image(
    prompt="Minimalist flat design icon of a robot reading a book, "
           "vibrant blue gradient background, no text",
    model="imagen-4.0-fast-generate-001",
    aspect_ratio="1:1",
    number_of_images=4,
)

# Standard: ブログ記事のアイキャッチ（品質・コスト両立）
hero_image = generate_image(
    prompt="Professional photograph of a developer workspace with "
           "multiple monitors showing code, warm ambient lighting, "
           "shallow depth of field",
    model="imagen-4.0-generate-001",
    aspect_ratio="16:9",
)

# Ultra: ブランド広告素材（最高品質）
brand_asset = generate_image(
    prompt='Photorealistic product shot of a sleek white wireless '
           'earbud case on a marble surface, studio lighting, '
           'text overlay reading "SoundPure Pro" in elegant sans-serif font',
    model="imagen-4.0-ultra-generate-001",
    aspect_ratio="4:3",
)

# 画像をファイルに保存
for i, img_bytes in enumerate(thumbnails):
    with open(f"thumbnail_{i}.png", "wb") as f:
        f.write(img_bytes)
    print(f"thumbnail_{i}.png を保存しました")
```

`aspect_ratio` に指定できる値は `"1:1"`、`"3:4"`、`"4:3"`、`"9:16"`、`"16:9"` の5種類。`person_generation` は `"dont_allow"`（人物生成を禁止）、`"allow_adult"`（大人のみ許可、デフォルト）、`"allow_all"`（子供も含む）から選ぶ。

なぜこのように関数でラップするかというと、後述するモデルルーティングやリトライロジックをこの層に集約するためです。APIを直接呼び出すコードをアプリケーション全体に散らすと、モデル切り替えやエラーハンドリングの変更が困難になります。

## テキスト描画の精度を最大化するプロンプト設計

Imagen 4の目玉機能であるテキスト描画を確実に活かすには、プロンプトの書き方にコツがあります。

**原則1: テキストは引用符で囲み、フォントスタイルを明示する**

```python
# テキストが崩れやすい書き方
bad_prompt = "A poster with the words Welcome to Tokyo"

# テキスト描画が安定する書き方
good_prompt = (
    'A modern travel poster featuring the text "Welcome to Tokyo" '
    "in bold sans-serif white font, centered at the top. "
    "Background: Tokyo skyline at sunset with Tokyo Tower silhouette."
)
```

テキスト部分をダブルクォートで囲むことで、モデルが「これはリテラルテキストとして描画すべき」と認識しやすくなります。さらにフォントの種類（serif/sans-serif）、太さ（bold/light）、色、配置（centered/top-left）を指定すると、出力の安定性が格段に上がる。

**原則2: テキストは短く、段階的に追加する**

1枚の画像に入れるテキストが長くなるほど、スペルミスのリスクが上がる。12語以上のテキストを1枚に入れたい場合は、メインテキストとサブテキストを分けてプロンプトに記述します。

```python
structured_prompt = (
    'Event poster design. '
    'Main headline: "AI Developer Summit 2026" in large bold white text. '
    'Subheadline: "June 15-17 | San Francisco" in smaller regular gray text below. '
    'Background: abstract geometric pattern in dark blue and purple gradients.'
)

result = generate_image(
    prompt=structured_prompt,
    model="imagen-4.0-ultra-generate-001",
    aspect_ratio="9:16",
)
```

**原則3: テキスト描画重視の画像にはUltraモデルを使う**

FastとStandardでもテキスト描画は可能ですが、長いテキストや小さなフォントサイズでの精度はUltraが明確に優れています。テキスト描画が主目的なら、1枚$0.06のUltraを選ぶのがコスト効率的にも合理的です。テキストが崩れた画像を何度もリトライするFastの方が結果的に高くつくことがあります。

## バッチ画像生成パイプラインの構築

本番サービスでは、1枚ずつ生成するのではなくバッチ処理が必要になる場面が多いです。ECサイトの商品画像一括生成、ブログ記事のアイキャッチ自動生成、多言語ポスターの量産などです。

以下は非同期処理とリトライロジックを組み込んだバッチパイプラインの実装です。

```python
import asyncio
import random
from dataclasses import dataclass

@dataclass
class ImageJob:
    job_id: str
    prompt: str
    model: str = "imagen-4.0-generate-001"
    aspect_ratio: str = "1:1"
    max_retries: int = 3
    status: str = "pending"
    result: bytes | None = None
    error: str | None = None

async def process_single_job(job: ImageJob) -> ImageJob:
    """1つの画像生成ジョブを処理する（リトライ付き）"""
    for attempt in range(job.max_retries):
        try:
            loop = asyncio.get_event_loop()
            response = await loop.run_in_executor(
                None,
                lambda: client.models.generate_images(
                    model=job.model,
                    prompt=job.prompt,
                    config=types.GenerateImagesConfig(
                        number_of_images=1,
                        aspect_ratio=job.aspect_ratio,
                    ),
                ),
            )
            job.result = response.generated_images[0].image.image_bytes
            job.status = "completed"
            return job
        except genai.errors.ClientError as e:
            if "SAFETY" in str(e) or "BLOCKED" in str(e):
                job.status = "blocked"
                job.error = f"Safety filter: {e}"
                return job
            job.error = str(e)
        except Exception as e:
            job.error = str(e)
        if attempt < job.max_retries - 1:
            wait = (2 ** attempt) + random.uniform(0, 1)
            await asyncio.sleep(wait)
    job.status = "failed"
    return job

async def run_batch(jobs: list[ImageJob], concurrency: int = 5) -> list[ImageJob]:
    """バッチジョブを並行度を制御しながら実行する

    concurrency はモデルのレート制限に合わせて調整:
    Fast: 150 RPM → concurrency=10-15
    Standard: 75 RPM → concurrency=5-8
    Ultra: 30 RPM → concurrency=2-3
    """
    semaphore = asyncio.Semaphore(concurrency)
    async def bounded_job(job):
        async with semaphore:
            return await process_single_job(job)
    results = await asyncio.gather(*[bounded_job(j) for j in jobs])
    completed = sum(1 for j in results if j.status == "completed")
    failed = sum(1 for j in results if j.status == "failed")
    blocked = sum(1 for j in results if j.status == "blocked")
    print(f"Batch complete: {completed} succeeded, {failed} failed, {blocked} blocked")
    return results
```

ここで `concurrency` パラメータが重要です。Imagen 4のレート制限はモデルごとに異なるため、Fastなら10〜15、Standardなら5〜8、Ultraなら2〜3に設定するのが安全なラインになります。レート制限を超えると429エラーが返るが、指数バックオフによって自動リトライされます。

## 用途別モデルルーティングの実装

実際のプロダクトでは、すべての画像生成に同じモデルを使うのは非効率です。用途に応じてモデルを自動選択するルーティングロジックを組み込むことで、品質を維持しながらコストを最小化できます。

```python
from enum import Enum

class ImagePurpose(Enum):
    THUMBNAIL = "thumbnail"
    HERO_IMAGE = "hero_image"
    PRODUCT_PHOTO = "product_photo"
    BRAND_ASSET = "brand_asset"
    TEXT_OVERLAY = "text_overlay"
    SOCIAL_MEDIA = "social_media"

MODEL_ROUTING = {
    ImagePurpose.THUMBNAIL: {
        "model": "imagen-4.0-fast-generate-001",
        "cost": 0.02,
        "concurrency": 12,
    },
    ImagePurpose.HERO_IMAGE: {
        "model": "imagen-4.0-generate-001",
        "cost": 0.04,
        "concurrency": 6,
    },
    ImagePurpose.PRODUCT_PHOTO: {
        "model": "imagen-4.0-generate-001",
        "cost": 0.04,
        "concurrency": 6,
    },
    ImagePurpose.BRAND_ASSET: {
        "model": "imagen-4.0-ultra-generate-001",
        "cost": 0.06,
        "concurrency": 2,
    },
    ImagePurpose.TEXT_OVERLAY: {
        "model": "imagen-4.0-ultra-generate-001",
        "cost": 0.06,
        "concurrency": 2,
    },
    ImagePurpose.SOCIAL_MEDIA: {
        "model": "imagen-4.0-fast-generate-001",
        "cost": 0.02,
        "concurrency": 12,
    },
}

def get_model_for_purpose(purpose: ImagePurpose) -> str:
    return MODEL_ROUTING[purpose]["model"]

def estimate_batch_cost(purpose: ImagePurpose, count: int) -> float:
    return round(MODEL_ROUTING[purpose]["cost"] * count, 2)

# 使用例
purpose = ImagePurpose.TEXT_OVERLAY
print(f"Model: {get_model_for_purpose(purpose)}")
print(f"50枚の推定コスト: ${estimate_batch_cost(purpose, 50)}")
# → Model: imagen-4.0-ultra-generate-001
# → 50枚の推定コスト: $3.0
```

このルーティングテーブルをアプリケーションの設定として外部化しておくと、A/Bテストでモデルを切り替えたり、コスト削減のためにルーティングルールを変更する作業が容易になります。APIコスト全般の最適化については[Gemini APIコスト最適化完全ガイド](/articles/gemini-api/gemini-api-cost-optimization-complete-guide)も参考になります。

## SynthID透かしの仕組みと本番での影響

Imagen 4で生成されたすべての画像には、SynthIDによる不可視の電子透かしが自動的に埋め込まれます。これはGoogleのResponsible AI施策の一環で、開発者側でオフにすることはできません。

SynthIDの特徴は、人間の目にはまったく見えないが、専用の検出ツールで機械的に検出できる点です。リサイズ、クロップ、軽度の圧縮を経ても透かしが残るように設計されています。

本番運用上の留意点は2つ。1つ目は、透かしの除去が困難なことです。SynthIDは画像のピクセルレベルに埋め込まれており、意図的に除去しようとすると画像品質が著しく劣化する。2つ目は法的な位置づけで、EU AI Actをはじめ、AI生成コンテンツの開示義務を設ける規制が各国で進んでいます。SynthIDの存在はこうした規制への対応を容易にするが、法的要件はAPIの透かし機能だけでは満たせない場合があります。利用規約と各国の規制を確認した上で運用すること。

## 本番運用で遭遇するエラーパターンと対処法

Imagen 4 APIを本番で運用すると、開発時には気づかなかった複数のエラーパターンに遭遇します。

**安全フィルターによるブロック（最も頻発）**

プロンプトの内容が安全ポリシーに抵触すると、画像が生成されずにブロックされます。明確に不適切でないプロンプトでもブロックされるケースがある点が厄介です。

```python
def handle_safety_block(original_prompt: str, purpose: ImagePurpose) -> list[bytes] | None:
    """安全フィルターブロック時のフォールバック戦略"""
    # 戦略1: プロンプトを簡略化して再試行
    simplified = original_prompt.replace("weapon", "tool").replace("blood", "red liquid")
    try:
        return generate_image(prompt=simplified, model=get_model_for_purpose(purpose))
    except genai.errors.ClientError:
        pass
    # 戦略2: 人物描写を除去して再試行
    try:
        return generate_image(
            prompt=original_prompt,
            model=get_model_for_purpose(purpose),
            person_generation="dont_allow",
        )
    except genai.errors.ClientError:
        pass
    # 戦略3: フォールバック画像を返す
    return None
```

画像生成のエラー全般については[Gemini 画像生成エラー完全解決ガイド](/articles/gemini-api/gemini-image-generation-errors-fix-guide)で詳しく扱っています。

## コスト最適化の実践テクニック

月間1万枚以上の画像を生成するサービスでは、モデル選択だけでなく生成戦略全体の最適化が重要になります。

**テクニック1: プレビュー→本番の2段階生成**

ユーザーに複数の候補を見せてから選ばせるUIの場合、候補生成にはFast、選択された画像の高品質版にはUltraを使います。

```python
def two_stage_generation(prompt: str, num_previews: int = 4) -> dict:
    """2段階生成: Fast でプレビュー → Ultra で本番版"""
    previews = generate_image(
        prompt=prompt,
        model="imagen-4.0-fast-generate-001",
        number_of_images=num_previews,
    )
    return {
        "previews": previews,
        "finalize": lambda: generate_image(
            prompt=prompt,
            model="imagen-4.0-ultra-generate-001",
            number_of_images=1,
        ),
    }
# コスト比較:
# 全部Ultra 4枚 → $0.06 × 4 = $0.24
# Fast 4枚 + Ultra 1枚 → $0.02 × 4 + $0.06 × 1 = $0.14（42%削減）
```

**テクニック2: 生成結果のキャッシュ**

同じプロンプトに対して毎回APIを叩く必要はありません。プロンプトのハッシュをキーにしたキャッシュ層を導入します。

```python
import hashlib
import json
from pathlib import Path

CACHE_DIR = Path("./image_cache")
CACHE_DIR.mkdir(exist_ok=True)

def get_cache_key(prompt: str, model: str, aspect_ratio: str) -> str:
    content = json.dumps({"prompt": prompt.strip().lower(), "model": model, "aspect_ratio": aspect_ratio}, sort_keys=True)
    return hashlib.sha256(content.encode()).hexdigest()[:16]

def generate_with_cache(prompt: str, model: str = "imagen-4.0-generate-001", aspect_ratio: str = "1:1") -> bytes:
    key = get_cache_key(prompt, model, aspect_ratio)
    cache_path = CACHE_DIR / f"{key}.png"
    if cache_path.exists():
        return cache_path.read_bytes()
    images = generate_image(prompt=prompt, model=model, aspect_ratio=aspect_ratio)
    cache_path.write_bytes(images[0])
    return images[0]
```

**テクニック3: 日次コスト上限の実装**

```python
import threading

class CostTracker:
    COST_MAP = {
        "imagen-4.0-fast-generate-001": 0.02,
        "imagen-4.0-generate-001": 0.04,
        "imagen-4.0-ultra-generate-001": 0.06,
    }
    def __init__(self, daily_budget: float = 10.0):
        self.daily_budget = daily_budget
        self.daily_spend = 0.0
        self._lock = threading.Lock()
    def can_generate(self, model: str, count: int = 1) -> bool:
        cost = self.COST_MAP.get(model, 0.06) * count
        with self._lock:
            return (self.daily_spend + cost) <= self.daily_budget
    def record(self, model: str, count: int = 1):
        cost = self.COST_MAP.get(model, 0.06) * count
        with self._lock:
            self.daily_spend += cost

tracker = CostTracker(daily_budget=20.0)
```

## よくある落とし穴5選と回避策

**1. 長いプロンプトがテキストとして画像内に描画される**

長いコンテキスト説明を含むプロンプトを送ると、Imagen 4がプロンプト内のテキストを「描画すべき文字」と解釈してしまうことがあります。画像内に表示したいテキストは明確に引用符で区切り、それ以外の指示はメタ指示として分離すること。

**2. Fastモデルの解像度制限を見落とす**

Fastの最大解像度は1408×768であり、それを超えるサイズを指定するとエラーになります。モデルごとの解像度上限をバリデーションに組み込んでおくべきです。

**3. 非同期処理でレート制限を即座に超過する**

`asyncio.gather()` で大量のジョブを一斉に投げると、レート制限に即座に到達する。前述の `Semaphore` による並行度制御は必須。

**4. SynthID透かしを考慮しない画像後処理**

過度なピクセル操作はSynthID透かしを損傷させる。軽度のリサイズ・クロップ・圧縮は問題ないが、全体のピクセル操作を行う場合は透かしの残存性を確認すること。

**5. person_generationのデフォルト挙動を確認していない**

デフォルトは `"allow_adult"` だが、子供向けコンテンツでは `"dont_allow"` に設定すべき場面があります。一方で、人物を含む画像を生成したいのに `"dont_allow"` を設定してしまい「なぜ人が描かれないのか」と悩むケースもあります。

## Geminiテキスト生成との統合ワークフロー

Imagen 4は単体でも強力だが、Gemini APIのテキスト生成と組み合わせることで、より高度なワークフローを構築できます。

記事テキストをGemini 2.5 Proに入力し、記事内容に適した画像プロンプトを自動生成させてから、そのプロンプトでImagen 4に画像を生成させるパイプラインです。

```python
def generate_article_image(article_text: str, style: str = "professional blog illustration") -> bytes:
    """記事テキストからAIが最適な画像プロンプトを生成し、画像を作成する"""
    prompt_response = client.models.generate_content(
        model="gemini-2.5-pro",
        contents=f"""以下のブログ記事に最適なアイキャッチ画像のプロンプトを英語で1つだけ生成してください。
要件:
- スタイル: {style}
- テキストは含めない
- 記事の核心を視覚的に表現する
- 商用利用可能な内容にする

記事:
{article_text[:3000]}

プロンプトのみを出力。説明は不要。""",
        config=types.GenerateContentConfig(temperature=0.7, max_output_tokens=200),
    )
    image_prompt = prompt_response.text.strip()
    images = generate_image(prompt=image_prompt, model="imagen-4.0-generate-001", aspect_ratio="16:9")
    return images[0]
```

このパイプラインの利点は、記事内容に合った画像を人手を介さずに生成できる点です。毎日複数の記事を公開するメディアでは、アイキャッチ画像の作成工数を大幅に削減できます。

## 本番運用で必須の3つの監視メトリクス

Imagen 4を本番で安定運用するには、単なるAPI利用ではなく、以下の3つのメトリクスを継続的に監視することが重要です。

1. **API応答時間分布**: Fastは平均2.7秒だが、時間帯や負荷によって3〜5秒に延伸することがあります。p95（95パーセンタイル）が10秒を超えないことを目安にモニタリングすること。

2. **安全フィルターブロック率**: プロンプトの何%がブロックされているか。通常は1〜3%だが、特定のプロンプトパターンで急上昇する場合があります。ブロック率の時系列グラフから、ユーザー投稿内容の傾向変化を察知できます。

3. **モデル別コスト実績**: 計画では用途別ルーティングでコストを見積もるが、実際には想定外のモデル選択が発生することがあります。日次の実績コストをモデル別に集計し、ルーティングロジックの見直しが必要か判断します。

## 次のアクション

Imagen 4は、3つのモデルティアと2K出力対応、改善されたテキスト描画によって、画像生成APIの本番利用におけるハードルを大きく下げた。最初に取り組むべきは、自分のプロダクトで生成する画像の用途を洗い出し、前述のモデルルーティングテーブルを作成することです。FastとUltraを適切に使い分けるだけで、品質を維持しながらコストを30〜40%削減できます。
