Reactアプリケーションの開発中に、Gemini APIを呼び出したとたんにコンソールへ赤いエラーが表示された経験はないでしょうか。「Access to fetch at 'https://generativelanguage.googleapis.com/...' from origin '...' has been blocked by CORS policy」というメッセージは、多くの開発者が最初にぶつかる壁のひとつです。

2014年からアプリ事業を続けている個人開発者の経験から、この問題に普段から向き合ってきた立場で、要点を整理します。

## CORSエラーとは（なぜGemini APIで起きるのか

CORS（Cross-Origin Resource Sharing）とは、ブラウザがセキュリティ上の理由から、異なるオリジン（ドメイン・ポート・プロトコル）へのHTTPリクエストを制限する仕組みです。

ブラウザは`http://localhost:3000`のようなオリジンからリクエストを送る際、サーバー側が「このオリジンからのアクセスを許可する」というレスポンスヘッダー（`Access-Control-Allow-Origin`）を返さなければ、レスポンスをブロックします。

Gemini API（`generativelanguage.googleapis.com`）は、**ブラウザからの直接呼び出し**を想定した設計になっていません。サーバーサイドのアプリケーションやCLIからのアクセスを前提としており、ブラウザ向けのCORSヘッダーを返さないため、エラーが発生します。

### エラーが発生する典型的なコード

```javascript
// ❌ これはブラウザ上で CORS エラーになる
const response = await fetch(
  'https://generativelanguage.googleapis.com/v1beta/models/gemini-2.0-flash:generateContent?key=YOUR_API_KEY',
  {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      contents: [{ parts: [{ text: 'こんにちは' }] }]
    })
  }
);
```

このコードをReactコンポーネントやブラウザのコンソールで実行すると、次のようなエラーが返ります。

```
Access to fetch at 'https://generativelanguage.googleapis.com/...' 
from origin 'http://localhost:3000' has been blocked by CORS policy: 
No 'Access-Control-Allow-Origin' header is present on the requested resource.
```

## 原因のパターン分析

CORSエラーが起きる原因は主に3つのパターンに分類できます。

**パターン1：フロントエンドから直接APIを呼び出している**

最も一般的な原因です。ReactのuseEffect内やボタンのonClickハンドラなど、クライアントサイドのコードでfetch/axiosを使ってGemini APIを呼び出しています。

**パターン2：APIキーをフロントエンドに露出させている**

CORS回避のために`localhost`プロキシを設定しようとしても、APIキーがブラウザのJavaScriptに含まれていると、ユーザーが開発者ツールで簡単に取得できてしまいます。これはセキュリティ上の重大なリスクです。

**パターン3：開発環境と本番環境で設定が異なる**

開発時はプロキシで動作していたが、本番デプロイ後に設定が適用されず、本番環境でCORSエラーが再発するケースです。

## 解決手順：サーバーサイドプロキシの実装

根本的な解決策は、**ブラウザから直接APIを呼ばず、自分のサーバーを経由させる**ことです。フロントエンドは自分のサーバーに対してリクエストし、サーバーがGemini APIを呼び出してレスポンスを返す構成にします。

### 解決策1：Next.js App Router のRoute Handlersを使う（推奨）

Next.jsを使っている場合、Route Handlersがもっともシンプルな解決策です。

```typescript
// app/api/gemini/route.ts
import { NextRequest, NextResponse } from 'next/server';

export async function POST(request: NextRequest) {
  const { prompt } = await request.json();

  // APIキーはサーバーサイドの環境変数から取得（ブラウザには露出しない）
  const apiKey = process.env.GEMINI_API_KEY;
  if (!apiKey) {
    return NextResponse.json({ error: 'API key not configured' }, { status: 500 });
  }

  const response = await fetch(
    `https://generativelanguage.googleapis.com/v1beta/models/gemini-2.0-flash:generateContent?key=${apiKey}`,
    {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        contents: [{ parts: [{ text: prompt }] }]
      })
    }
  );

  const data = await response.json();
  // 期待するレスポンス: { candidates: [{ content: { parts: [{ text: '...' }] } }] }
  return NextResponse.json(data);
}
```

フロントエンドからは自分のAPIエンドポイントを呼び出します。

```typescript
// components/GeminiChat.tsx
async function sendMessage(prompt: string) {
  // ✅ 自分のサーバー（同一オリジン）を呼び出すのでCORSエラーは発生しない
  const response = await fetch('/api/gemini', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ prompt })
  });
  const data = await response.json();
  return data.candidates?.[0]?.content?.parts?.[0]?.text ?? '';
}
```

環境変数の設定も忘れずに行ってください。

```bash
# .env.local（Gitには絶対にコミットしない）
GEMINI_API_KEY=YOUR_GEMINI_API_KEY
```

### 解決策2：Express.jsを使う（Node.js バックエンド）

React（Vite/CRA）とExpressを別々に運用している場合は、Expressのミドルウェアとしてプロキシを実装します。

```javascript
// server.js
const express = require('express');
const cors = require('cors');

const app = express();
app.use(express.json());

// 自分のフロントエンドのオリジンのみ許可する（* は避ける）
app.use(cors({ origin: process.env.FRONTEND_URL || 'http://localhost:5173' }));

app.post('/api/gemini', async (req, res) => {
  const { prompt } = req.body;

  try {
    const response = await fetch(
      `https://generativelanguage.googleapis.com/v1beta/models/gemini-2.0-flash:generateContent?key=${process.env.GEMINI_API_KEY}`,
      {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({
          contents: [{ parts: [{ text: prompt }] }]
        })
      }
    );
    const data = await response.json();
    res.json(data);
  } catch (err) {
    res.status(500).json({ error: 'Failed to call Gemini API' });
  }
});

app.listen(3001, () => console.log('Proxy server running on port 3001'));
```

### 解決策3：Google AI JavaScript SDKをNode.js環境で使う

`@google/generative-ai` パッケージはNode.js環境（サーバーサイド）での使用を想定しています。Next.jsのRoute HandlersやAPI routesの中でSDKを使いましょう。

```typescript
// app/api/gemini/route.ts
import { GoogleGenerativeAI } from '@google/generative-ai';
import { NextRequest, NextResponse } from 'next/server';

const genAI = new GoogleGenerativeAI(process.env.GEMINI_API_KEY!);

export async function POST(request: NextRequest) {
  const { prompt } = await request.json();

  const model = genAI.getGenerativeModel({ model: 'gemini-2.0-flash' });
  const result = await model.generateContent(prompt);
  const text = result.response.text();
  // 期待するレスポンス例: { text: "Geminiからの返答テキスト" }

  return NextResponse.json({ text });
}
```

## 解決できたかの確認方法

修正後、以下の手順でCORSエラーが解消されたかを確認してください。

**ステップ1：ブラウザの開発者ツールを開く**（F12またはCmd+Option+I）

**ステップ2：Networkタブを選択し、アプリケーションでGemini APIを呼び出す**

**ステップ3：リクエストの確認**

解決前は`generativelanguage.googleapis.com`へのリクエストがブロックされています。解決後は自分の`/api/gemini`エンドポイントへのリクエストが`200 OK`で返ってくることを確認してください。

**ステップ4：Consoleタブでエラーが消えていることを確認**

「CORS policy」という文字列がConsoleに表示されなければ成功です。

## 予防策：再発を防ぐためのベストプラクティス

一度正しく設定できたら、以下の習慣でCORSエラーの再発を防ぎましょう。

**APIキーは必ず環境変数で管理する**

`NEXT_PUBLIC_`プレフィックスのある変数はブラウザに露出します。Gemini APIキーには絶対に`NEXT_PUBLIC_`を付けないでください。

```bash
# ✅ 正しい（サーバーサイドのみ）
GEMINI_API_KEY=YOUR_GEMINI_API_KEY

# ❌ 危険（ブラウザに露出する）
NEXT_PUBLIC_GEMINI_API_KEY=YOUR_GEMINI_API_KEY
```

**`.gitignore`に`.env.local`を追加する**

```
.env.local
.env*.local
```

**本番環境でも環境変数を設定する**

VercelやCloudflare PagesなどのデプロイサービスのダッシュボードでAPIキーを環境変数として登録することを忘れずに。開発環境の`.env.local`は本番環境には引き継がれません。

**Gemini AIプロキシの設計についてより詳しく学びたい方**には、[GeminiのAPIゲートウェイとプロキシアーキテクチャ](/articles/gemini-api/gemini-api-ai-gateway-proxy-architecture)の記事もご参照ください。

また、Next.jsとGemini APIを組み合わせた実践的なアプリケーション構築については、[Next.jsでGemini AIチャットアプリを作る](/articles/gemini-api/gemini-api-nextjs-ai-chat-app)が参考になります。

## 全体を振り返って

Gemini APIのCORSエラーは、ブラウザのセキュリティポリシーに起因するものであり、APIの問題ではありません。解決策は一つ——**APIキーを安全に保ちながら、サーバーサイドからGemini APIを呼び出す**ことです。

Next.jsのRoute HandlersやExpress.jsのプロキシを使えば、数十行のコードで確実に解決できます。APIキーをフロントエンドに露出させず、同一オリジンのエンドポイントを経由する設計を最初から採用することで、CORSエラーとセキュリティリスクの両方を防ぐことができます。
