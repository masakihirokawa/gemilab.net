Reactアプリケーションの開発中に、Gemini APIを呼び出したとたんにコンソールへ赤いエラーが表示された経験はないでしょうか。「Access to fetch at '[generativelanguage.googleapis.com](https://generativelanguage.googleapis.com/...)' from origin '...' has been blocked by CORS policy」というメッセージは、多くの開発者が最初にぶつかる壁のひとつです。

## CORSエラーとは（なぜGemini APIで起きるのか

CORS（Cross-Origin Resource Sharing）とは、ブラウザがセキュリティ上の理由から、異なるオリジン（ドメイン・ポート・プロトコル）へのHTTPリクエストを制限する仕組みです。

ブラウザは`http://localhost:3000`のようなオリジンからリクエストを送る際、サーバー側が「このオリジンからのアクセスを許可する」というレスポンスヘッダー（`Access-Control-Allow-Origin`）を返さなければ、レスポンスをブロックします。

Gemini API（`generativelanguage.googleapis.com`）は、**ブラウザからの直接呼び出し**を想定した設計になっていません。サーバーサイドのアプリケーションやCLIからのアクセスを前提としており、ブラウザ向けのCORSヘッダーを返さないため、エラーが発生します。

### エラーが発生する典型的なコード

```javascript
// ❌ これはブラウザ上で CORS エラーになる
const response = await fetch(
  'https://generativelanguage.googleapis.com/v1beta/models/gemini-2.0-flash:generateContent?key=YOUR_API_KEY',
  {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      contents: [{ parts: [{ text: 'こんにちは' }] }]
    })
  }
);
```

このコードをReactコンポーネントやブラウザのコンソールで実行すると、次のようなエラーが返ります。

```
Access to fetch at 'https://generativelanguage.googleapis.com/...' 
from origin 'http://localhost:3000' has been blocked by CORS policy: 
No 'Access-Control-Allow-Origin' header is present on the requested resource.
```

## 原因のパターン分析

CORSエラーが起きる原因は主に3つのパターンに分類できます。

**パターン1：フロントエンドから直接APIを呼び出している**

最も一般的な原因です。ReactのuseEffect内やボタンのonClickハンドラなど、クライアントサイドのコードでfetch/axiosを使ってGemini APIを呼び出しています。

**パターン2：APIキーをフロントエンドに露出させている**

CORS回避のために`localhost`プロキシを設定しようとしても、APIキーがブラウザのJavaScriptに含まれていると、ユーザーが開発者ツールで簡単に取得できてしまいます。これはセキュリティ上の重大なリスクです。

**パターン3：開発環境と本番環境で設定が異なる**

開発時はプロキシで動作していたが、本番デプロイ後に設定が適用されず、本番環境でCORSエラーが再発するケースです。

## 解決手順：サーバーサイドプロキシの実装

根本的な解決策は、**ブラウザから直接APIを呼ばず、自分のサーバーを経由させる**ことです。フロントエンドは自分のサーバーに対してリクエストし、サーバーがGemini APIを呼び出してレスポンスを返す構成にします。

### 解決策1：Next.js App Router のRoute Handlersを使う（推奨）

Next.jsを使っている場合、Route Handlersがもっともシンプルな解決策です。

```typescript
// app/api/gemini/route.ts
import { NextRequest, NextResponse } from 'next/server';

export async function POST(request: NextRequest) {
  const { prompt } = await request.json();

  // APIキーはサーバーサイドの環境変数から取得（ブラウザには露出しない）
  const apiKey = process.env.GEMINI_API_KEY;
  if (!apiKey) {
    return NextResponse.json({ error: 'API key not configured' }, { status: 500 });
  }

  const response = await fetch(
    `https://generativelanguage.googleapis.com/v1beta/models/gemini-2.0-flash:generateContent?key=${apiKey}`,
    {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        contents: [{ parts: [{ text: prompt }] }]
      })
    }
  );

  const data = await response.json();
  // 期待するレスポンス: { candidates: [{ content: { parts: [{ text: '...' }] } }] }
  return NextResponse.json(data);
}
```

フロントエンドからは自分のAPIエンドポイントを呼び出します。

```typescript
// components/GeminiChat.tsx
async function sendMessage(prompt: string) {
  // ✅ 自分のサーバー（同一オリジン）を呼び出すのでCORSエラーは発生しない
  const response = await fetch('/api/gemini', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ prompt })
  });
  const data = await response.json();
  return data.candidates?.[0]?.content?.parts?.[0]?.text ?? '';
}
```

環境変数の設定も忘れずに行ってください。

```bash
# .env.local（Gitには絶対にコミットしない）
GEMINI_API_KEY=YOUR_GEMINI_API_KEY
```

### 解決策2：Express.jsを使う（Node.js バックエンド）

React（Vite/CRA）とExpressを別々に運用している場合は、Expressのミドルウェアとしてプロキシを実装します。

```javascript
// server.js
const express = require('express');
const cors = require('cors');

const app = express();
app.use(express.json());

// 自分のフロントエンドのオリジンのみ許可する（* は避ける）
app.use(cors({ origin: process.env.FRONTEND_URL || 'http://localhost:5173' }));

app.post('/api/gemini', async (req, res) => {
  const { prompt } = req.body;

  try {
    const response = await fetch(
      `https://generativelanguage.googleapis.com/v1beta/models/gemini-2.0-flash:generateContent?key=${process.env.GEMINI_API_KEY}`,
      {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({
          contents: [{ parts: [{ text: prompt }] }]
        })
      }
    );
    const data = await response.json();
    res.json(data);
  } catch (err) {
    res.status(500).json({ error: 'Failed to call Gemini API' });
  }
});

app.listen(3001, () => console.log('Proxy server running on port 3001'));
```

### 解決策3：Google AI JavaScript SDKをNode.js環境で使う

`@google/generative-ai` パッケージはNode.js環境（サーバーサイド）での使用を想定しています。Next.jsのRoute HandlersやAPI routesの中でSDKを使いましょう。

```typescript
// app/api/gemini/route.ts
import { GoogleGenerativeAI } from '@google/generative-ai';
import { NextRequest, NextResponse } from 'next/server';

const genAI = new GoogleGenerativeAI(process.env.GEMINI_API_KEY!);

export async function POST(request: NextRequest) {
  const { prompt } = await request.json();

  const model = genAI.getGenerativeModel({ model: 'gemini-2.0-flash' });
  const result = await model.generateContent(prompt);
  const text = result.response.text();
  // 期待するレスポンス例: { text: "Geminiからの返答テキスト" }

  return NextResponse.json({ text });
}
```

## 解決できたかの確認方法

修正後、以下の手順でCORSエラーが解消されたかを確認してください。

**ステップ1：ブラウザの開発者ツールを開く**（F12またはCmd+Option+I）

**ステップ2：Networkタブを選択し、アプリケーションでGemini APIを呼び出す**

**ステップ3：リクエストの確認**

解決前は`generativelanguage.googleapis.com`へのリクエストがブロックされています。解決後は自分の`/api/gemini`エンドポイントへのリクエストが`200 OK`で返ってくることを確認してください。

**ステップ4：Consoleタブでエラーが消えていることを確認**

「CORS policy」という文字列がConsoleに表示されなければ成功です。

## 予防策：再発を防ぐためのベストプラクティス

一度正しく設定できたら、以下の習慣でCORSエラーの再発を防ぎましょう。

**APIキーは必ず環境変数で管理する**

`NEXT_PUBLIC_`プレフィックスのある変数はブラウザに露出します。Gemini APIキーには絶対に`NEXT_PUBLIC_`を付けないでください。

```bash
# ✅ 正しい（サーバーサイドのみ）
GEMINI_API_KEY=YOUR_GEMINI_API_KEY

# ❌ 危険（ブラウザに露出する）
NEXT_PUBLIC_GEMINI_API_KEY=YOUR_GEMINI_API_KEY
```

**`.gitignore`に`.env.local`を追加する**

```
.env.local
.env*.local
```

**本番環境でも環境変数を設定する**

VercelやCloudflare PagesなどのデプロイサービスのダッシュボードでAPIキーを環境変数として登録することを忘れずに。開発環境の`.env.local`は本番環境には引き継がれません。

**Gemini AIプロキシの設計についてより詳しく学びたい方**には、[GeminiのAPIゲートウェイとプロキシアーキテクチャ](/articles/gemini-api/gemini-api-ai-gateway-proxy-architecture)の記事もご参照ください。

また、Next.jsとGemini APIを組み合わせた実践的なアプリケーション構築については、[Next.jsでGemini AIチャットアプリを作る](/articles/gemini-api/gemini-api-nextjs-ai-chat-app)が参考になります。

## 全体を振り返って

Gemini APIのCORSエラーは、ブラウザのセキュリティポリシーに起因するものであり、APIの問題ではありません。解決策は一つ——**APIキーを安全に保ちながら、サーバーサイドからGemini APIを呼び出す**ことです。

Next.jsのRoute HandlersやExpress.jsのプロキシを使えば、数十行のコードで確実に解決できます。APIキーをフロントエンドに露出させず、同一オリジンのエンドポイントを経由する設計を最初から採用することで、CORSエラーとセキュリティリスクの両方を防ぐことができます。


## エラー1: `models/gemini-pro is not found` または `404 NOT_FOUND`

### 何が起きているか

`gemini-pro` や `gemini-1.0-pro` といったモデル名は、すでに廃止またはリタイアされています。2025年以降、これらのモデル名を使用したリクエストは404エラーを返す。

```
[GoogleGenerativeAI Error]: Error fetching from https://generativelanguage.googleapis.com/...
Status: 404 Not Found
{"error":{"code":404,"message":"models/gemini-pro is not found for API version v1beta"}}
```

### 原因

古いチュートリアルやGitHubのサンプルコードは、今では使えないモデル名を使っていることが多いです。公式ドキュメントが更新されても、参照しているコードが古いままというケースです。

### 解決手順

現在利用可能なモデル名に切り替える。2026年4月時点での推奨モデルは以下のとおり：

```python
# ❌ 古い（動かない）
model = genai.GenerativeModel('gemini-pro')
model = genai.GenerativeModel('gemini-1.0-pro')

# ✅ 現在の推奨
model = genai.GenerativeModel('gemini-2.5-pro-latest')   # 最新のGemini 2.5 Pro
model = genai.GenerativeModel('gemini-2.0-flash')         # 高速・低コスト
model = genai.GenerativeModel('gemini-2.5-flash-preview-04-17')  # 2.5 Flash（プレビュー）
```

モデル一覧は `genai.list_models()` で確認できる：

```python
import google.generativeai as genai
genai.configure(api_key="YOUR_GEMINI_API_KEY")
for m in genai.list_models():
    if 'generateContent' in m.supported_generation_methods:
        print(m.name)
```

## エラー2: `400 INVALID_ARGUMENT` — リクエスト形式の問題

### 何が起きているか

リクエストの構造がAPIの仕様と合っていないときに発生します。Gemini 1.x系とGemini 2.x系ではAPIの一部仕様が変わっているため、移行タイミングで起きやすい。

よく見る原因パターン：

**パターンA: `system_instruction` の書き方が旧形式**

```python
# ❌ Gemini 1.x 形式（2.x では動かない場合がある）
response = model.generate_content(
    [{"role": "system", "parts": [{"text": "あなたは助手です"}]},
     {"role": "user",   "parts": [{"text": "こんにちは"}]}]
)

# ✅ Gemini 2.x 推奨形式
model = genai.GenerativeModel(
    model_name='gemini-2.5-pro-latest',
    system_instruction="あなたは助手です"
)
response = model.generate_content("こんにちは")
```

**パターンB: `generation_config` に存在しないパラメータ**

```python
# ❌ topK は一部モデルで非対応
config = genai.GenerationConfig(topK=40)  # エラーになる場合がある

# ✅ 基本パラメータのみ使う
config = genai.GenerationConfig(
    temperature=0.7,
    max_output_tokens=1024
)
```

### 解決手順

1. エラーメッセージの `details` フィールドを確認する（どのフィールドが問題かが書かれている）
2. [公式リファレンス](https://ai.google.dev/api/generate-content)でリクエスト形式を再確認する
3. モデルバージョンを変えたタイミングで発生した場合は、`system_instruction` の書き方が変わっていないか確認する

## エラー3: `429 RESOURCE_EXHAUSTED` — レート制限超過

### 何が起きているか

APIの無料枠（Free tier）またはProのレート上限に達しています。

```
google.api_core.exceptions.ResourceExhausted: 429 RESOURCE_EXHAUSTED
Quota exceeded for quota metric 'generate_content_requests' 
and limit 'generate_content_requests_per_day_per_project'
```

### 原因と解決手順

Gemini APIには3種類のレート制限がある：

| 制限の種類 | Free tier の上限（参考） | 対処法 |
|---|---|---|
| 1分あたりのリクエスト数（RPM） | 15 RPM | リクエスト間に `time.sleep()` を挿入 |
| 1分あたりのトークン数（TPM） | 1,000,000 TPM | プロンプトを短くする |
| 1日あたりのリクエスト数（RPD） | 1,500 RPD | 翌日まで待つ または Payプランへ移行 |

バッチ処理でAPIを叩くスクリプトを書く場合は、リトライロジックを必ず実装する：

```python
import time
import google.api_core.exceptions

def generate_with_retry(model, prompt, max_retries=3):
    for attempt in range(max_retries):
        try:
            return model.generate_content(prompt)
        except google.api_core.exceptions.ResourceExhausted:
            wait_time = 60 * (attempt + 1)  # 60秒, 120秒, 180秒
            print(f"レート制限に達しました。{wait_time}秒待機します...")
            time.sleep(wait_time)
    raise Exception("最大リトライ回数に達しました")
```

### Free tierからPayプランへの移行

Google AI StudioでプロジェクトをGoogle Cloudに紐付けると、より高いレート上限が利用できます。特に1日1,500リクエストの上限に当たっているなら、有料プランへの移行が最も根本的な解決です。

## エラー4: `SAFETY` ブロックによる空レスポンス

### 何が起きているか

Geminiの安全フィルターがコンテンツをブロックしている場合、`finish_reason` が `SAFETY` になり、テキストが返ってこありません。

```python
response = model.generate_content("...")
print(response.text)  # AttributeError: 'Response' object has no attribute 'text'
# または ValueError が発生する
```

### 解決手順

まず `finish_reason` を確認して、ブロックされているかどうかを判断する：

```python
response = model.generate_content("...")
candidate = response.candidates[0]
print(f"Finish reason: {candidate.finish_reason}")
print(f"Safety ratings: {candidate.safety_ratings}")

# SAFETY の場合のハンドリング
if candidate.finish_reason.name == 'SAFETY':
    print("コンテンツが安全フィルターによりブロックされました")
    # プロンプトを調整するか、safety_settings を変更する
```

`safety_settings` を調整することで、一部のカテゴリのフィルターを緩和できます。ただし、この調整はGoogle Cloud経由のAPIでのみ有効な場合があります。

## エラー5: `APIKeyInvalidError` または認証エラー

### 何が起きているか

APIキーが無効、期限切れ、または間違ったプロジェクトのキーを使っています。

```
google.api_core.exceptions.PermissionDenied: 403 API_KEY_INVALID
```

### 確認手順

1. [Google AI Studio](https://aistudio.google.com) → 「Get API key」でキーが有効か確認する
2. キーが正しく環境変数に設定されているか確認する：

```python
import os
api_key = os.environ.get("GEMINI_API_KEY")
if not api_key:
    raise ValueError("GEMINI_API_KEY 環境変数が設定されていません")
genai.configure(api_key=api_key)
```

3. コード内にAPIキーをハードコードしている場合は、必ず環境変数または `.env` ファイルに移動する（Gitにキーを誤ってコミットすると、Googleが自動検出して無効化することがある）

4. Google Cloud経由でAPIを使っている場合は、`GOOGLE_APPLICATION_CREDENTIALS` の設定も確認する

## gemini-2.5-pro-latest への移行チェックリスト

古いモデルから `gemini-2.5-pro-latest` に切り替えるとき、発生しやすいポイントをまとめておく：

- `system_instruction` の書き方を新形式に変更する
- `generation_config` に `thinking_config` を追加できる（思考プロセスを制御）
- コンテキストウィンドウが大幅に拡大しているため、長文入力の上限チェックを更新する
- 出力トークン数が増えた分、レート制限（TPM）への到達が早くなることに注意

Gemini APIのバージョン移行では、ほとんどのエラーは上記のどれかに当てはまる。エラーメッセージを見たらまずHTTPステータスコード（400/403/404/429）を確認し、この記事の該当セクションを参照してほしい。
