`ollama pull gemma4:4b` を実行して `Error: pull model manifest: file does not exist` が返ってきた時、Stack Overflow で見つかる回答の多くは「Ollama を最新にしてください」です。確かに半分は正解なのですが、それで解決しないケースの方が私の経験上は多いです。

このエラーは「Ollama が指定したモデル名を Ollama Library 上で見つけられなかった」状態を示しますが、その背後には5つの異なる原因が隠れています。順番に切り分けていきましょう。

## エラーの正体: manifest が無い、ではなく「探しにいったが応答がない」

`pull model manifest: file does not exist` というメッセージは、Ollama が `https://registry.ollama.ai/v2/library/<model>/manifests/<tag>` という URL に GET リクエストを投げて、404 が返ってきた時に表示されます。つまり、サーバーは応答しているが「そのモデル名・タグの組み合わせは存在しない」と言われている状態です。

ここから原因を切り分けるため、まず実際のリクエストURLを推測してみましょう。

```bash
# あなたが実行したコマンドが ollama pull gemma4:4b だった場合
# Ollama は以下を叩いている:
# https://registry.ollama.ai/v2/library/gemma4/manifests/4b

# これを curl で直接叩いて確認できる
curl -I https://registry.ollama.ai/v2/library/gemma4/manifests/4b
# 404 が返るなら、その名前のモデルが存在しない
# 200 が返るなら、Ollama 側の問題
```

この事前確認だけで、5つの原因のうち2つを除外できます。

## 原因1: モデル名の表記が間違っている（最頻出）

Ollama Library での Gemma シリーズの正式名称は、リリース時期によって変わってきました。2026年4月時点での正しい名前は以下の通りです。

| 試したモデル名 | 実際の正しい名前 | 備考 |
|---|---|---|
| gemma4 | gemma4 または gemma3:4b | Gemma 4 単独タグは存在せず、サイズ指定が必須 |
| gemma4:4b | gemma3:4b（旧）または gemma4:4b（新） | リリース時期で変わる |
| gemma-4 | （存在しない） | ハイフンは不可 |
| gemma:4 | （存在しない） | バージョン番号のみのタグは無い |

最も確実なのは、Ollama Library の検索ページ（[ollama.com](https://ollama.com/library)）で `gemma` を検索し、現時点で利用可能な正確なタグを確認することです。私はモデル名を打つ前に必ずここを確認するようにしてから、このエラーに遭遇する頻度が大幅に減りました。

実際に動くコマンドの例:

```bash
# 単独で pull
ollama pull gemma3:4b

# pull せずにいきなり実行（無ければ自動pull）
ollama run gemma3:4b
```

## 原因2: Ollama のバージョンが古い

Ollama のバージョンが古いと、新しいモデルファミリーに対応していないことがあります。Gemma 4 系列は Ollama 0.5.0 以降で正式サポートされています。

```bash
# 現在のバージョン確認
ollama --version

# macOS / Linux でアップデート
curl -fsSL https://ollama.com/install.sh | sh

# Windows は公式インストーラーから再ダウンロード
# https://ollama.com/download
```

アップデート後は、Ollama サービスの再起動を忘れずに行ってください。バックグラウンドで動いている古いプロセスが残っていると、新バージョンが認識されないことがあります。

```bash
# macOS の場合
ollama stop
# Ollama アプリを終了 → 再起動

# Linux (systemd) の場合
sudo systemctl restart ollama
```

## 原因3: レジストリへのネットワーク到達性

`registry.ollama.ai` への接続が遮断されている環境では、当然pullできません。よくあるのは以下のケースです。

**企業ファイアウォール**: `registry.ollama.ai` および `*.ollama.ai` を許可リストに追加してもらう必要があります。プロキシ経由の場合は環境変数で指定します。

```bash
export HTTPS_PROXY=http://your-proxy:port
export HTTP_PROXY=http://your-proxy:port
ollama pull gemma3:4b
```

**特定地域からのアクセス制限**: 中国本土など一部地域からは Ollama Library への直接アクセスが制限されることがあります。この場合は、後述する「ローカルファイルからの import」が現実的な解決策になります。

**DNS解決の失敗**: 稀ですが、企業内DNSが `registry.ollama.ai` を解決できないケースがあります。

```bash
# DNS解決の確認
nslookup registry.ollama.ai
dig registry.ollama.ai
```

## 原因4: タグが廃止された

Ollama Library のモデルタグは、新バージョンがリリースされると古いタグが削除されることがあります。少し前まで使えていたコマンドが急に通らなくなった場合は、これを疑います。

```bash
# 利用可能な全タグを確認するには Web で
# https://ollama.com/library/gemma3/tags
```

廃止されたタグを使い続けたい場合は、ローカルにキャッシュされた manifest をバックアップしておく必要があります。`~/.ollama/models/manifests/registry.ollama.ai/library/<model>/` 以下にあります。

## 原因5: ローカルでGGUFファイルから取り込む（オフライン解決策）

上記すべて試しても解決しない、あるいはオフライン環境で使いたい場合は、Hugging Face 等から GGUF ファイルを直接ダウンロードして Ollama に取り込む方法があります。

```bash
# 1. GGUFファイルをダウンロード（例: HuggingFace から）
mkdir -p ~/models/gemma3-4b
cd ~/models/gemma3-4b
# 適切なライセンス確認の上で
curl -L -O https://huggingface.co/google/gemma-3-4b-it-gguf/resolve/main/gemma-3-4b-it-Q4_K_M.gguf

# 2. Modelfile を作成
cat > Modelfile <<'EOF'
FROM ./gemma-3-4b-it-Q4_K_M.gguf

PARAMETER temperature 0.7
PARAMETER top_p 0.9
PARAMETER top_k 40
PARAMETER num_ctx 4096

TEMPLATE """{{ if .System }}<start_of_turn>system
{{ .System }}<end_of_turn>
{{ end }}{{ if .Prompt }}<start_of_turn>user
{{ .Prompt }}<end_of_turn>
{{ end }}<start_of_turn>model
{{ .Response }}<end_of_turn>
"""
EOF

# 3. Ollama に登録
ollama create gemma3-local -f Modelfile

# 4. 実行
ollama run gemma3-local
```

この方法なら、レジストリへの依存なくローカルで動かせます。ただし TEMPLATE のフォーマットはモデルファミリーごとに異なるため、Hugging Face のモデルカードを必ず確認してください。

## 切り分けフロー: 上から1分ずつ試す

1. `curl -I https://registry.ollama.ai/v2/library/gemma3/manifests/4b` で 200 が返るか確認
2. [Ollama Library の Gemma ページ](https://ollama.com/library/gemma3) で正しいタグ名を確認 → 別名で再 pull
3. `ollama --version` を確認 → 0.5.0 未満なら更新
4. プロキシ環境なら `HTTPS_PROXY` を設定
5. それでもダメなら GGUF ファイルから手動 import

私の経験では、原因1（モデル名の表記）と原因2（古いバージョン）で全体の8割が解決します。残りの2割が原因3〜5に該当します。
