夜、小さな文章校正ツールの原価を表計算に入れていたときのことです。公式の[料金ページ](https://ai.google.dev/gemini-api/docs/pricing)には 100 万トークンあたりの単価がきれいに並んでいるのに、「この単価で、1 人のお客さまから月にいくら残るのか」という欄はどこにもありませんでした。単価表は開発者が試すためのもので、事業の収支表ではないのです。

この記事は、Gemini API を収益化の道具として使う方に向けて、料金の見え方を整理し直したものです。技術的な使い方ではなく、**どの構成なら続けられる原価に収まるか**を考える材料にしてください。なお料金と上限は頻繁に変わります。本文の数値は 2026 年 11 月 1 日に公式ページで確認した内容で、判断の前にもう一度ご自身でご覧いただければ幸いです。

## 料金を 3 つの軸に分けて読む

モデルごとの単価表をそのまま眺めると混乱します。事業として見るときは、次の 3 つに分けると整理しやすくなります。

<table>
<thead>
<tr><th>軸</th><th>決めるもの</th><th>変わる頻度</th></tr>
</thead>
<tbody>
<tr><td>モデル</td><td>Pro 系／Flash 系／Flash-Lite 系の使い分け（原価の大半を決めます）</td><td>世代交代のたびに</td></tr>
<tr><td>アカウントの階層</td><td>Free Tier と Tier 1〜3（上限と使える機能の差）</td><td>条件の改定時</td></tr>
<tr><td>エンドユーザー向けプラン</td><td>Google AI の無料版・Pro・Ultra（API 課金ではなく、お客さまの代替手段）</td><td>プラン改定時</td></tr>
</tbody>
</table>

3 つ目は API の請求とは別物ですが、お客さまが「公式アプリで足りる」と感じるかどうかを左右します。ひとつずつ辿ります。

## 軸 1: モデルの選択が原価の大半を決める

2026 年 11 月時点の公式ページでは、標準料金（100 万トークンあたり）が次のように並んでいます。

<table>
<thead>
<tr><th>モデル</th><th>入力</th><th>出力（思考を含む）</th><th>Free Tier</th></tr>
</thead>
<tbody>
<tr><td><code>gemini-3.1-pro-preview</code></td><td>$2.00（20 万トークン以下）</td><td>$12.00（同）</td><td>なし</td></tr>
<tr><td><code>gemini-3.6-flash</code></td><td>$0.75（2026 年末まで）</td><td>$3.75（同）</td><td>あり</td></tr>
<tr><td><code>gemini-3.5-flash-lite</code></td><td>$0.30</td><td>$2.50</td><td>あり</td></tr>
<tr><td><code>gemini-3.1-flash-lite</code></td><td>$0.25（テキスト・画像・動画）</td><td>$1.50</td><td>あり</td></tr>
</tbody>
</table>

Flash 系には、2027 年 1 月 1 日から単価が引き上げられる予定が併記されています。ここで気づいたのは、**原価は「いまの単価」ではなく「来年の単価」で見積もるべきだ**ということでした。値上げ後の数字で収支が成り立たない構成は、安い期間のうちに作り直しておくほうが傷が浅く済みます。

出力単価が入力の数倍になっている点も見落としがちです。短い入力から長い文章を書かせる用途は、入力が長い要約用途より割高になります。ご自身のサービスの平均的な入出力トークン数を一度測り、1 回あたりの原価を出してみてください。

**Pro 系だけに頼らない構造を最初から作ること。** これが、私が個人開発で小さなサービスを組むときに最初に引く線です。軽い処理は Flash 系や Flash-Lite 系に回し、Pro 系は高品質モードを明示的に選んだときだけ使います。

```python
from google import genai

client = genai.Client()

# モデル ID は定数にまとめ、提供状況と単価は公式ページで確認してから差し替えます
MODEL_STANDARD = "gemini-3.6-flash"
MODEL_PREMIUM = "gemini-3.1-pro-preview"

def generate(prompt: str, premium: bool = False) -> str:
    model = MODEL_PREMIUM if premium else MODEL_STANDARD
    response = client.models.generate_content(model=model, contents=prompt)
    return response.text
```

この分岐を最初から入れておくと、後から「高品質モードは有料プランだけに限る」という設計に移りやすくなります。

大量の非同期処理には、Batch API も候補になります。公式ページでは標準料金の 50 % 引きとされています。即時の応答が要らない夜間の分類や要約には向いていて、実例は[アプリレビューの夜間分類](/articles/gemini-api/gemini-batch-api-app-reviews-overnight-classification)にまとめました。

## 軸 2: Free Tier と有料 Tier は「単価」ではなく「条件」の差

Google AI Studio で API キーを作ると、最初は Free Tier です。階層の条件は、公式の[レート制限のページ](https://ai.google.dev/gemini-api/docs/rate-limits)に次のように書かれています。

<table>
<thead>
<tr><th>階層</th><th>条件</th><th>請求上限の目安</th><th>10 分あたりの支出上限</th></tr>
</thead>
<tbody>
<tr><td>Free</td><td>有効なプロジェクトまたは無料トライアル</td><td>—</td><td>—</td></tr>
<tr><td>Tier 1</td><td>有効な請求アカウントを設定してリンク</td><td>$250</td><td>$10</td></tr>
<tr><td>Tier 2</td><td>累計 $100 の支払い＋初回の支払い成功から 3 日</td><td>$2,000</td><td>$50</td></tr>
<tr><td>Tier 3</td><td>累計 $1,000 の支払い＋初回の支払い成功から 30 日</td><td>$20,000 以上</td><td>$200</td></tr>
</tbody>
</table>

階層は自動で上がります。Free から Tier 1 は通常すぐ反映され、それ以降はおおむね 10 分以内とされています。**階層が上がっても 1 トークンあたりの単価は変わりません。** 変わるのは支出の上限、Batch のキューに積めるトークン量、そしてモデルごとのリクエスト上限です。モデルごとの RPM・TPM は階層で異なり、ページ上には載っていないため、AI Studio の画面で自分のプロジェクトの値を確かめます。

本番のサービスで Free Tier を使い続けるのは避けてください。公式ページでは、Free Tier の入出力が製品改善に使われる旨が記載されています。お客さまのデータを扱うなら、請求アカウントを紐づけて Tier 1 に上げるのが最初の一歩です。取り扱いの細則は版によって変わるので、[利用規約](https://ai.google.dev/gemini-api/terms)も合わせてご確認ください。

上限に当たったときの設計は、[レート制限とクォータ管理](/articles/gemini-api/gemini-api-rate-limiting-quota-management-production-guide)で扱っています。

## 軸 3: Google AI のプランは「お客さまの代替手段」

Google は[Google AI](https://gemini.google/subscriptions/)として、エンドユーザー向けの月額プラン（無料版・Pro・Ultra）を直接販売しています。プランの内容と価格は改定が続くため、契約前に公式ページで確認する前提で読んでください。

見ておきたいのは競合の構造です。自分のサービスが「Gemini アプリで同じことができる範囲」に収まっていると、お客さまは月額の Google AI を契約すれば足りてしまいます。汎用チャットを API につないだだけのサービスは、ここで勝ちにくくなります。私が差を作る方向として考えるのは、次の 3 つです。

1. Gemini アプリ単体ではできない連携（既存ツールや特定サービスへの埋め込み）
2. 特定領域に絞ったシステム指示と評価の流れ（翻訳、業界向けの要約、コード変換など）
3. 小さな単発作業の売り切り（月額ではなく 1 回ごとの価格）

## 立ち上げ時の組み合わせ

「もう一度ゼロから始めるなら」という前提で、規模別の考え方を書きます。数値の目標は一例で、ご自身のサービスの原価を測って置き換えてください。

**小さく始める場合。** 標準処理は Flash 系、Pro 系は高品質モードだけ。アカウントは Tier 1 で始めます。Tier 1 の支出上限は 10 分で $10 なので、急に広まったときに止まる可能性は先に頭へ入れておきます。

**利用が増えてきた場合。** Flash-Lite 系を裏側の大量処理に加え、同じ長い指示や資料を毎回送っているなら[コンテキストキャッシング](/articles/gemini-api/gemini-api-context-caching-cost-optimization)を検討します。公式ページではキャッシュ読み出しの単価が通常入力より大幅に低く設定されています（保存料は別途かかります）。Tier 2 以降は、上限に実際に当たってから上げれば十分です。

**自分のサービスを定点観測します。** 競合になりうる Google AI のプランは、私自身も一度使っておくと、お客さまが何を無料で得られるのかが体感で分かります。

## 次の一手

まず、ご自身のサービスの 1 回あたりの平均入力・出力トークン数を 50 件分だけ測ってください。それに現在の単価と、来年の値上げ後の単価を掛けて 2 通りの原価を出します。値上げ後の数字でも粗利が残る構成なら、そのまま進めて大丈夫です。残らないなら、軽い処理を Flash-Lite 系へ移すところから手を付けてみてください。

料金は「いくら使うか」ではなく、**いくら残すかで読む**ものです。続けやすい構造で始めることを、いまも大切にしています。立ち上げの全体像は[Gemini API で副業を始める 90 日ロードマップ](/articles/gemini-api/gemini-api-side-income-roadmap-2026)でも扱っています。
