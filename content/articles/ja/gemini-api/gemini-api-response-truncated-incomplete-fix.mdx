「コードを生成させたら途中で切れた」「長い記事を要約させると末尾が消える」— Gemini API を使い始めて間もないころ、こういった経験をした方は多いのではないでしょうか。私も最初のプロジェクトで同じ壁にぶつかり、原因を特定するまでに思いのほか時間がかかりました。

このガイドでは、レスポンスが途中で切れる問題のパターンを整理して、それぞれの対処法を実際に動くコードとともにご紹介します。

Dolice Labs の 4 サイト並行運用で得た実感として、この問題に普段から向き合ってきた立場で、要点を整理します。

## レスポンスが切れる原因は大きく3つある

Gemini API のレスポンスが不完全になる原因は、だいたい次の3つに分類できます。

**1. `max_output_tokens` の上限に達している**（最も多い）
**2. 安全フィルター（Safety Filter）によってブロックされた**
**3. ストリーミング実装の不備でチャンクが取りこぼされた**

それぞれで `finish_reason` の値が異なるため、まずそこを確認するのが解決の近道です。

## finish_reason を必ず確認する

`finish_reason` はレスポンスが終了した理由を示すフィールドです。トラブルシューティングの第一歩として、この値を必ず確認する習慣をつけましょう。

```python
import google.generativeai as genai

genai.configure(api_key="YOUR_GEMINI_API_KEY")
model = genai.GenerativeModel("gemini-2.5-pro")

response = model.generate_content("Pythonで簡単なWebスクレイパーを書いてください。詳しく解説も加えてください。")

# finish_reason を確認する
for candidate in response.candidates:
    print(f"finish_reason: {candidate.finish_reason}")
    print(f"token count: {response.usage_metadata.candidates_token_count}")
    print("---")
    print(candidate.text[:200] if candidate.text else "(テキストなし)")
```

`finish_reason` の主な値と意味は以下の通りです。

- `STOP` — 正常終了（モデルが自然に終了した）
- `MAX_TOKENS` — `max_output_tokens` の上限に達した → **これが原因でレスポンスが切れる**
- `SAFETY` — 安全フィルターによるブロック
- `RECITATION` — 著作権保護コンテンツの検出
- `OTHER` — その他（不明なエラー）

`MAX_TOKENS` が表示された場合は、次のセクションで説明する対処法を試してください。

## 原因1: max_output_tokens の上限 — 最も多いケース

`finish_reason` が `MAX_TOKENS` になっている場合、モデルが出力できるトークン数の上限に達しています。

### 解決策A: max_output_tokens を明示的に設定する

何も設定していない場合、モデルはデフォルトのトークン数制限で止まります。長い出力が必要なときは、`generation_config` で明示的に上限を引き上げましょう。

```python
import google.generativeai as genai

genai.configure(api_key="YOUR_GEMINI_API_KEY")
model = genai.GenerativeModel(
    "gemini-2.5-pro",
    generation_config=genai.GenerationConfig(
        max_output_tokens=8192,  # デフォルトより大きく設定
        temperature=0.7,
    )
)

response = model.generate_content(
    "Pythonで簡単なWebスクレイパーを書いてください。詳しく解説も加えてください。"
)

# finish_reason を確認
for candidate in response.candidates:
    reason = candidate.finish_reason.name if hasattr(candidate.finish_reason, 'name') else str(candidate.finish_reason)
    print(f"finish_reason: {reason}")

print(response.text)
```

モデルごとの `max_output_tokens` の最大値は異なります（Gemini 2.5 Pro は最大65,536トークン）。必要に応じて大きな値を設定してください。

### 解決策B: 出力を複数回に分割してリクエストする

一度に長い出力を求めるより、続きをリクエストするほうがうまくいくことがあります。特に長いコードや文書の生成で有効なパターンです。

```python
import google.generativeai as genai

genai.configure(api_key="YOUR_GEMINI_API_KEY")
model = genai.GenerativeModel("gemini-2.5-pro")

# チャット形式で続きを依頼する
chat = model.start_chat()

# 最初のリクエスト
response1 = chat.send_message(
    "PythonのWebスクレイパーを書いてください。まずはライブラリのインポートと基本構造から始めてください。"
)
print("=== Part 1 ===")
print(response1.text)

# finish_reason が MAX_TOKENS の場合は続きを依頼
for candidate in response1.candidates:
    reason = candidate.finish_reason.name if hasattr(candidate.finish_reason, 'name') else str(candidate.finish_reason)
    if reason == "MAX_TOKENS":
        print("\n=== Part 2（続き） ===")
        response2 = chat.send_message("続きを書いてください。")
        print(response2.text)
```

この方法はチャット履歴が保持されるため、「続きを書いてください」という指示が文脈を引き継いで機能します。長いコードの生成や、複数のセクションに分かれたドキュメント作成に向いているアプローチです。

## 原因2: 安全フィルターによるブロック

`finish_reason` が `SAFETY` の場合、コンテンツが安全フィルターに引っかかっています。

### finish_reason が SAFETY の時の情報取得

```python
import google.generativeai as genai

genai.configure(api_key="YOUR_GEMINI_API_KEY")
model = genai.GenerativeModel("gemini-2.5-pro")

try:
    response = model.generate_content("あなたのプロンプト")
    
    for candidate in response.candidates:
        reason = candidate.finish_reason.name if hasattr(candidate.finish_reason, 'name') else str(candidate.finish_reason)
        
        if reason == "SAFETY":
            print("⚠️ 安全フィルターによってブロックされました")
            # どのカテゴリで引っかかったか確認する
            for rating in candidate.safety_ratings:
                print(f"  - {rating.category.name}: {rating.probability.name}")
        else:
            print(response.text)
            
except Exception as e:
    print(f"エラー: {e}")
    # prompt_feedback も確認する（プロンプト自体がブロックされた場合）
    if hasattr(response, 'prompt_feedback'):
        print(f"プロンプトフィードバック: {response.prompt_feedback}")
```

安全フィルターによるブロックの場合、プロンプトの表現を変えることで解決できることが多いです。技術的な内容（セキュリティ関連コードなど）を扱う場合は、「学習目的で」「防御的な視点から」といった文脈を明示すると通過しやすくなります。

## 原因3: ストリーミングでチャンクが取りこぼされている

ストリーミングAPIを使っている場合、実装の不備でレスポンスが不完全に見えることがあります。ストリーミングは高速な応答を実現できる一方、正しく実装しないとチャンクが取りこぼされます。

### よくある間違いと正しい実装

```python
import google.generativeai as genai

genai.configure(api_key="YOUR_GEMINI_API_KEY")
model = genai.GenerativeModel("gemini-2.5-pro")

# ❌ よくある間違い: イテレーション中にブレークしてしまう
def bad_streaming_example(prompt):
    response = model.generate_content(prompt, stream=True)
    for chunk in response:
        if chunk.text:
            print(chunk.text, end="")
            # ここで break や continue を誤って入れてしまう場合がある
    # resolve() を呼ばないと最終的なメタデータが取れない

# ✅ 正しい実装: 全チャンクを収集して最後に resolve する
def good_streaming_example(prompt):
    response = model.generate_content(prompt, stream=True)
    full_text = ""
    
    for chunk in response:
        if chunk.text:
            print(chunk.text, end="", flush=True)
            full_text += chunk.text
    
    # ストリーミング完了後に finish_reason を確認
    response.resolve()  # 重要: これを呼ばないと usage_metadata が取れない
    
    print("\n--- ストリーミング完了 ---")
    print(f"合計トークン数: {response.usage_metadata.total_token_count}")
    
    for candidate in response.candidates:
        reason = candidate.finish_reason.name if hasattr(candidate.finish_reason, 'name') else str(candidate.finish_reason)
        print(f"finish_reason: {reason}")
        
        if reason == "MAX_TOKENS":
            print("⚠️ トークン上限に達しました。続きが必要な場合は追加リクエストを送信してください。")
    
    return full_text

# 実行例
result = good_streaming_example("Pythonの非同期処理について詳しく教えてください。")
```

`response.resolve()` を忘れると、ストリーミング完了後に `usage_metadata` や `candidates` から正確な情報が取得できません。ストリーミング実装では必ずこの呼び出しを含めることをお勧めします。

## トークン数を事前に把握してリクエストを設計する

「どのくらいのトークンが必要か」を事前に把握しておくと、`max_output_tokens` の設定判断がしやすくなります。

```python
import google.generativeai as genai

genai.configure(api_key="YOUR_GEMINI_API_KEY")
model = genai.GenerativeModel("gemini-2.5-pro")

# プロンプトのトークン数を事前にカウントする
prompt = "Pythonで簡単なWebスクレイパーを書いてください。詳しく解説も加えてください。"
token_count = model.count_tokens(prompt)
print(f"プロンプトのトークン数: {token_count.total_tokens}")

# 出力に必要なトークン数を見積もって max_output_tokens を設定
# 目安: 日本語は1文字あたり約2〜3トークン、英語は1単語あたり約1〜2トークン
estimated_output_tokens = 4096  # 想定出力サイズに合わせて調整

response = model.generate_content(
    prompt,
    generation_config=genai.GenerationConfig(
        max_output_tokens=estimated_output_tokens,
    )
)

print(f"実際の出力トークン数: {response.usage_metadata.candidates_token_count}")
print(f"finish_reason: {response.candidates[0].finish_reason}")
```

日本語テキストを扱う場合、英語と比べてトークン消費が多い点に注意してください。実際のプロジェクトで扱うテキストを使ってトークン数を計測し、余裕を持った `max_output_tokens` を設定することをお勧めします。

## まとめ: 問題診断のフローチャート

Gemini API のレスポンスが切れたと感じたら、次の順序で確認してみてください。

**ステップ1**: `finish_reason` を確認する
**ステップ2**: `MAX_TOKENS` → `max_output_tokens` を増やす or 分割リクエスト
**ステップ3**: `SAFETY` → プロンプトの表現を調整する
**ステップ4**: ストリーミング → `response.resolve()` を実装に含める

多くのケースは `max_output_tokens` の設定不足で解決します。まずここから確認してみてください。
