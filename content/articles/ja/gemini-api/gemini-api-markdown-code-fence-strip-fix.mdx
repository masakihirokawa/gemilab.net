Gemini に「実行可能な Python 関数だけを返してください」と依頼したのに、応答が ` ```python ... ``` ` で囲まれていてそのまま `exec()` に渡せなかった、という経験はないでしょうか。私自身、自動コード生成の仕組みを組み立てていたときに一番最初につまずいたのがこの問題でした。

公式ドキュメントには「出力形式はプロンプトで制御できます」と書かれていますが、Gemini は学習データの大半がコードフェンス付きの Markdown であるため、どれだけ強く指示しても一定の確率で装飾記号を付けて返してきます。私が実運用で落ち着いた「プロンプト指示 + 正規表現での後処理 + JSON スキーマ併用」という 3 段構えのパターンを順番にご紹介します。

## なぜコードフェンスが付いて返ってくるのか

LLM はプロンプトに従うように後から調整されますが、事前学習で見てきたテキストの影響を完全には消せません。Stack Overflow・GitHub・技術ブログに存在する Python コードは、ほとんどが ` ```python ... ``` ` または ` ``` ... ``` ` で囲まれた形で書かれています。Gemini 3 系はこの「コードは装飾付きで示すべきもの」という学習済みの事前分布を強く持っています。

さらに、ユーザーが `temperature=0` に設定していても、プロンプトが「生コードだけ返してください」と自然言語で書かれている限り、モデルにとっては「指示が曖昧」に見える場合があります。フェンスを付けるのが「丁寧」なのか「余計」なのかは、コンテキストでしか判断できないためです。

この現象は `gemini-2.5-pro-latest` や `gemini-3.1-pro` のような新しめのモデルでも発生します。モデルを新しくすれば解決する問題ではないと割り切ったほうが早く前に進めます。

## 対処法 1: System Instructions で抑制する（まずこれから）

最初の一手は System Instructions です。プロンプト本体ではなく、`system_instruction` に入れるほうが効きやすいのが経験則です。以下は Python SDK（`google-genai` v1 系）での書き方です。

```python
# Gemini にコードフェンスを付けないよう強く指示する例
from google import genai
from google.genai import types

client = genai.Client(api_key="YOUR_API_KEY")

SYSTEM_INSTRUCTION = """あなたは Python コード生成専用のアシスタントです。
必ず以下のルールを守ってください:
1. 応答はそのまま Python ファイルとして保存できる生コードのみとする
2. ```python や ``` といったマークダウンのコードフェンスは絶対に付けない
3. コード外の説明文、前置き、後書きは一切出力しない
4. コメントが必要な場合は Python の # コメントとして含める
"""

response = client.models.generate_content(
    model="gemini-2.5-pro-latest",
    contents="2 つの整数を受け取り、最大公約数を返す関数 gcd を作成してください",
    config=types.GenerateContentConfig(
        system_instruction=SYSTEM_INSTRUCTION,
        temperature=0.2,
    ),
)
print(response.text)
# 期待する出力: def gcd(a, b): ... （フェンスなし）
```

体感として、この指示を入れるだけでフェンス付きで返る確率は 10% 以下まで下がります。ただし「絶対に 0%」にはなりません。本番で使うなら、次の正規表現による後処理を必ず組み合わせてください。

## 対処法 2: 正規表現で安全に除去する

プロンプトで抑え込めない残りの数 % を後処理で片付けます。ポイントは「ネストしたフェンス」「言語指定なしのフェンス」「前後の空白」「末尾の改行抜け」をすべて考慮することです。

```python
import re

def strip_code_fence(text: str) -> str:
    """Gemini の応答からコードフェンスを安全に取り除く。

    対応するパターン:
    - ```python\\nコード\\n```
    - ```\\nコード\\n```
    - ```py\\nコード```
    - 前後に空白や説明文が付いているケース
    """
    if not text:
        return text

    s = text.strip()

    # 全体がフェンスで囲まれているケース（最も一般的）
    pattern = re.compile(
        r"^```[a-zA-Z0-9_+-]*\s*\n?"  # 開始フェンス（言語指定は任意）
        r"(.*?)"                       # 本体（最短マッチ）
        r"\n?```\s*$",                 # 終了フェンス
        re.DOTALL,
    )
    m = pattern.match(s)
    if m:
        return m.group(1).strip()

    # 部分的にフェンスが残っているケース（先頭または末尾のみ）
    s = re.sub(r"^```[a-zA-Z0-9_+-]*\s*\n?", "", s)
    s = re.sub(r"\n?```\s*$", "", s)
    return s.strip()

# 動作確認
samples = [
    "```python\ndef gcd(a, b):\n    return a if b == 0 else gcd(b, a % b)\n```",
    "```\nprint('hello')\n```",
    "以下がコードです:\n```python\nx = 1\n```\nご確認ください。",  # 前後に説明文
    "def plain(): pass",  # もともとフェンスなし
]
for s in samples:
    print(repr(strip_code_fence(s)))
```

`re.DOTALL` で改行もマッチ対象にし、`.*?` の最短マッチで中身だけを取り出します。前後に説明文がある場合もカバーするため、「全体マッチ → 部分マッチ」の 2 段階で処理しているのがポイントです。

## 対処法 3: JSON スキーマで構造化して受け取る

もっとも堅牢なのは、コードを文字列フィールドとして JSON で受け取ることです。`response_mime_type="application/json"` と `response_schema` を指定すると、Gemini は JSON 以外のテキストを返せなくなります。

```python
from google import genai
from google.genai import types
from pydantic import BaseModel

class CodeResult(BaseModel):
    language: str
    code: str
    explanation: str  # 説明はコード外に分離できる

client = genai.Client(api_key="YOUR_API_KEY")

response = client.models.generate_content(
    model="gemini-2.5-pro-latest",
    contents="2 つの整数の最大公約数を求める Python 関数を書いてください",
    config=types.GenerateContentConfig(
        response_mime_type="application/json",
        response_schema=CodeResult,
    ),
)

result = CodeResult.model_validate_json(response.text)
# result.code にはフェンスなしの純粋なコードが入る
print(result.code)
```

この方式のメリットは、コードと説明を別フィールドに分離できることです。ログに保存するときも「コード部分だけを Python ファイルに書き出す」処理がそのまま書けます。

デメリットは JSON エスケープのオーバーヘッドで、コード内の改行が `\\n` になるため、`response.text` をそのまま使わず必ず Pydantic（または `json.loads`）で復元することです。

## 落とし穴: 内部に三連バッククォートを含むコード

一番厄介なのは、生成したいコード自体に `"""` や ` ``` ` を含むケースです。たとえば Markdown パーサーや LLM プロンプトを生成させたいとき、コードの中にフェンス記号が混じります。

このときは対処法 2 の正規表現だけでは誤って中身の一部を削ってしまうことがあります。**コード内部にフェンスが含まれる可能性がある場合は、対処法 3 の JSON スキーマ方式が実質的に唯一の安全策**です。JSON 文字列として返るため、内部の ` ``` ` は `"\u0060\u0060\u0060"` などにエスケープされ、フェンス除去ロジックと衝突しません。

## 実運用での検証とモニタリング

後処理で剥がし切れなかったケースを放置すると、ある日「なぜか実行時エラーが増えた」という形で顕在化します。私は以下のようなログを残して、週次で確認しています。

```python
import logging

logger = logging.getLogger(__name__)

def process_code_response(raw: str) -> str:
    stripped = strip_code_fence(raw)
    if stripped != raw:
        # フェンスが剥がれた = モデルが指示を守らなかった回
        logger.info(
            "code_fence_stripped",
            extra={
                "raw_length": len(raw),
                "stripped_length": len(stripped),
                "had_language_tag": "```python" in raw or "```py" in raw,
            },
        )
    # 念のため二重チェック: まだフェンスが残っていれば warning
    if stripped.startswith("```") or stripped.rstrip().endswith("```"):
        logger.warning("code_fence_residual", extra={"snippet": stripped[:120]})
    return stripped
```

`code_fence_stripped` の発生率がプロンプト調整前後でどう変わるかを追っておくと、System Instructions の効果を定量的に評価できます。私の環境では、プロンプトを 1 行追加するだけで発生率が半減したこともあり、「雰囲気で調整」から抜け出す手がかりになりました。

## 複数コードブロックを含む応答への対応

「解説と共に段階的にコードを書いて」と頼むと、1 つのレスポンスに複数のコードブロックが含まれることがあります。最初のブロックだけ取り出したいのか、全ブロックを結合したいのかは用途によって分かれます。

```python
def extract_all_code_blocks(text: str) -> list[str]:
    # 応答内のすべての Python コードブロックを順序付きで返す
    pattern = re.compile(
        r"```(?:python|py)?\s*\n(.*?)\n```",
        re.DOTALL,
    )
    return [m.strip() for m in pattern.findall(text)]

# 使い分けの例
blocks = extract_all_code_blocks(response.text)
if len(blocks) == 1:
    code = blocks[0]
elif len(blocks) > 1:
    # パイプラインのステップとして結合
    code = "\n\n".join(blocks)
else:
    # フェンスなしの単一応答だった
    code = strip_code_fence(response.text)
```

段階的な解説を含むチュートリアル生成なら `extract_all_code_blocks` で全取得し、単一関数の生成なら先頭ブロックだけを使う、といった使い分けが現実的です。

## まとめ — 用途別の使い分け

実運用では、以下の順で判断すると手戻りが少なくて済みます。

- 軽量なスクリプト生成（CLI ツール・1 回限りの補助）なら、対処法 1 + 2 で十分です
- ユーザー入力を受けてコードを生成し保存・実行する本番機能なら、対処法 3（JSON スキーマ）を採用してください
- コード自体にフェンス記号が含まれる可能性がある場合は、迷わず対処法 3 一択です

まずは手元のスクリプトに `strip_code_fence` を 1 関数追加するところから始めてみてください。それだけでも「コピペしたコードが動かない」という日常的な詰まりが大きく減り、Gemini を自動化パイプラインに組み込むハードルが一段下がります。
