## はじめに — Vue.js 3 と Gemini API の組み合わせが最強な理由

Vue.js 3 は日本国内でも非常に多くの開発者に支持されているフロントエンドフレームワークです。シンプルな学習曲線と強力なリアクティビティシステムを持ち、AIアプリとの相性も抜群です。

Gemini API と組み合わせることで、テキストのやりとりだけでなく画像認識や音声入力にも対応した本格的なAIアプリを、比較的少ないコードで実装できます。

この記事で学べることを整理しておきます。

- Vue 3 + Vite プロジェクトへの Google AI SDK の組み込み方
- `useGemini` コンポーザブルによるロジックの再利用
- ストリーミングレスポンスのリアルタイム表示
- マルチモーダル（画像入力）の実装方法
- 本番環境向けのエラーハンドリングパターン

**対象読者**: Vue.js の基本構文を理解しており、AIアプリ開発に挑戦したい中級者の方

## 環境構築 — Vue 3 + Vite に Google AI SDK を導入する

まず、Vue 3 + Vite プロジェクトを作成し、Google AI SDK をインストールします。

```bash
# Vue 3 プロジェクトを作成（Composition API + TypeScript を選択）
npm create vue@latest my-gemini-chat
cd my-gemini-chat

# Google Generative AI SDK のインストール
npm install @google/generative-ai

# 開発サーバーを起動
npm run dev
```

次に、プロジェクトルートに `.env.local` ファイルを作成してAPIキーを設定します。

```bash
# .env.local
VITE_GEMINI_API_KEY=YOUR_GEMINI_API_KEY
```

**重要なポイント**: Vite の環境変数はフロントエンドに公開されるため、`VITE_` プレフィックスが必要です。`.env.local` は必ず `.gitignore` に追加し、APIキーをリポジトリにコミットしないようにしてください。本番環境では後述するバックエンドプロキシの利用を強く推奨します。

Vue.js アプリでのAPI連携全般についての基礎を固めたい方には、[Gemini API クイックスタートガイド](/articles/gemini-api/gemini-api-quickstart)もあわせてご覧ください。

## useGemini コンポーザブルの設計と実装

Vue 3 の Composition API の真骨頂は **コンポーザブル（Composables）** によるロジックの分離・再利用にあります。Gemini APIとの通信ロジックを `useGemini.js` として独立させることで、複数コンポーネントから同じ処理を呼び出せるようになります。

```javascript
// src/composables/useGemini.js
import { ref, reactive } from 'vue'
import { GoogleGenerativeAI } from '@google/generative-ai'

export function useGemini(systemInstruction = 'あなたは親切なAIアシスタントです。') {
  // Google AI クライアントの初期化
  const genAI = new GoogleGenerativeAI(import.meta.env.VITE_GEMINI_API_KEY)
  const model = genAI.getGenerativeModel({
    model: 'gemini-2.5-flash',
    systemInstruction,
  })

  // リアクティブな状態管理
  const isLoading = ref(false)
  const error = ref(null)
  const messages = reactive([]) // { role: 'user' | 'model', content: string }

  // チャットセッション（会話履歴を保持）
  let chat = model.startChat({
    generationConfig: {
      maxOutputTokens: 2048,
      temperature: 0.7,
    },
  })

  /**
   * メッセージをストリーミング送信する
   * @param {string} userText - ユーザーの入力テキスト
   */
  const sendMessage = async (userText) => {
    if (!userText.trim() || isLoading.value) return

    // ユーザーメッセージをリストに追加
    messages.push({ role: 'user', content: userText })

    // AIメッセージのプレースホルダーを追加（ストリーミング中に更新する）
    const aiMessage = reactive({ role: 'model', content: '' })
    messages.push(aiMessage)

    isLoading.value = true
    error.value = null

    try {
      // sendMessageStream でストリーミング送信
      const result = await chat.sendMessageStream(userText)

      // チャンクを受け取るたびにリアルタイムで表示
      for await (const chunk of result.stream) {
        aiMessage.content += chunk.text()
      }
    } catch (e) {
      error.value = e.message || 'エラーが発生しました'
      aiMessage.content = `⚠️ エラー: ${error.value}`
    } finally {
      isLoading.value = false
    }
  }

  /**
   * 会話履歴をリセットする
   */
  const resetChat = () => {
    messages.splice(0)
    chat = model.startChat({
      generationConfig: { maxOutputTokens: 2048, temperature: 0.7 },
    })
    error.value = null
  }

  return { messages, isLoading, error, sendMessage, resetChat }
}
```

**期待する動作**: `sendMessage` を呼び出すと、AIの返答が `aiMessage.content` にリアルタイムで追記されていきます。`isLoading` が `true` の間は送信ボタンを無効化してUXを改善できます。

ストリーミングAPIの詳細な仕組みを知りたい方は、[Gemini APIのストリーミングと関数呼び出しの組み合わせガイド](/articles/gemini-api/gemini-api-streaming-function-calling-guide)も参考になります。

## チャットUIコンポーネントの実装

コンポーザブルを組み込んだシンプルなチャットUIを実装します。

```vue
<!-- src/components/GeminiChat.vue -->
<template>
  <div class="chat-wrapper">
    <!-- メッセージ表示エリア -->
    <div class="message-list" ref="messageListRef">
      <div
        v-for="(msg, index) in messages"
        :key="index"
        :class="['message', msg.role === 'user' ? 'user' : 'ai']"
      >
        <span class="label">{{ msg.role === 'user' ? 'あなた' : 'Gemini' }}</span>
        <p class="content" style="white-space: pre-wrap;">{{ msg.content }}</p>
      </div>

      <!-- ローディング表示 -->
      <div v-if="isLoading" class="loading-indicator">
        Gemini が考えています...
      </div>
    </div>

    <!-- エラーバナー -->
    <div v-if="error" class="error-banner">{{ error }}</div>

    <!-- 入力フォーム -->
    <form @submit.prevent="handleSend" class="input-area">
      <textarea
        v-model="inputText"
        placeholder="メッセージを入力... (Ctrl+Enter で送信)"
        rows="3"
        @keydown.ctrl.enter.prevent="handleSend"
      />
      <div class="button-row">
        <button type="button" @click="resetChat" class="reset-btn">リセット</button>
        <button
          type="submit"
          :disabled="isLoading || !inputText.trim()"
          class="send-btn"
        >
          {{ isLoading ? '送信中...' : '送信' }}
        </button>
      </div>
    </form>
  </div>
</template>

<script setup>
import { ref, nextTick, watch } from 'vue'
import { useGemini } from '@/composables/useGemini'

// コンポーザブルを利用（システムプロンプトはカスタマイズ可能）
const { messages, isLoading, error, sendMessage, resetChat } = useGemini(
  'あなたはGemini Labの読者を支援するフレンドリーなAIアシスタントです。技術的な質問に丁寧に答えてください。'
)

const inputText = ref('')
const messageListRef = ref(null)

const handleSend = async () => {
  const text = inputText.value.trim()
  if (!text || isLoading.value) return
  inputText.value = ''
  await sendMessage(text)
}

// 新しいメッセージが追加されたら最下部へ自動スクロール
watch(
  messages,
  async () => {
    await nextTick()
    if (messageListRef.value) {
      messageListRef.value.scrollTop = messageListRef.value.scrollHeight
    }
  },
  { deep: true }
)
</script>
```

このコンポーネントは、Ctrl+Enter での素早い送信、会話リセットボタン、ローディング中の送信ボタン無効化など、実用的なUXを備えています。

## マルチモーダル対応 — 画像入力を追加する

Gemini の強みの一つはマルチモーダル対応です。コンポーザブルに画像送信機能を追加しましょう。

```javascript
// useGemini.js に追加する関数

/**
 * 画像とテキストを組み合わせて送信する（マルチモーダル）
 * @param {string} userText - テキストの説明・質問
 * @param {File} imageFile - 送信する画像ファイル
 */
const sendImageMessage = async (userText, imageFile) => {
  if (isLoading.value) return

  isLoading.value = true
  error.value = null

  // ユーザーメッセージ（プレビューURL付き）を追加
  messages.push({
    role: 'user',
    content: userText || '画像を解析してください',
    imageUrl: URL.createObjectURL(imageFile),
  })

  const aiMessage = reactive({ role: 'model', content: '' })
  messages.push(aiMessage)

  try {
    // 画像を Base64 に変換
    const base64Data = await fileToBase64(imageFile)

    const imagePart = {
      inlineData: {
        // "data:image/png;base64," の部分を除いたデータ部分のみ渡す
        data: base64Data.split(',')[1],
        mimeType: imageFile.type,
      },
    }

    // テキストと画像を配列で渡すとマルチモーダルになる
    const result = await model.generateContentStream([
      userText || '画像を解析してください',
      imagePart,
    ])

    for await (const chunk of result.stream) {
      aiMessage.content += chunk.text()
    }
  } catch (e) {
    error.value = e.message || '画像の処理に失敗しました'
    aiMessage.content = `⚠️ エラー: ${error.value}`
  } finally {
    isLoading.value = false
  }
}

// ヘルパー: File オブジェクトを Base64 文字列に変換
const fileToBase64 = (file) =>
  new Promise((resolve, reject) => {
    const reader = new FileReader()
    reader.onload = (e) => resolve(e.target.result)
    reader.onerror = (e) => reject(e)
    reader.readAsDataURL(file)
  })
```

画像解析機能の詳細実装については、[Gemini APIによる画像認識・テキスト抽出の実践ガイド](/articles/gemini-api/gemini-api-image-recognition-text-extraction-python)もあわせて参照してください。

## 本番環境向けの改善 — APIキー保護とエラーハンドリング

### バックエンドプロキシによるAPIキー保護

フロントエンドに直接APIキーを置くのはプロトタイプ段階のみにとどめるべきです。本番環境では、Vercel Functions や Node.js のバックエンドをプロキシとして挟む構成が安全です。

```javascript
// src/composables/useGeminiProxy.js（本番向け）
// フロントエンドは自前のAPIエンドポイントを経由する

const sendMessage = async (userText) => {
  // APIキーはバックエンドで管理。フロントは自前エンドポイントへリクエスト
  const response = await fetch('/api/gemini/chat', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ message: userText, history: toRaw(messages) }),
  })

  if (!response.ok) {
    throw new Error(`API Error: ${response.status}`)
  }

  // Server-Sent Events (SSE) でストリーミングを受け取る
  const reader = response.body.getReader()
  const decoder = new TextDecoder()
  const aiMessage = reactive({ role: 'model', content: '' })
  messages.push(aiMessage)

  while (true) {
    const { done, value } = await reader.read()
    if (done) break
    aiMessage.content += decoder.decode(value, { stream: true })
  }
}
```

### 429エラーの自動リトライ実装

APIレート制限に引っかかった際に自動でリトライする仕組みを追加しておくと安心です。

```javascript
// 指数バックオフによるリトライ
const sendWithRetry = async (userText, retries = 3) => {
  for (let i = 0; i < retries; i++) {
    try {
      await sendMessage(userText)
      return
    } catch (e) {
      // 429 (レート制限) の場合のみリトライ
      if (e.message?.includes('429') && i < retries - 1) {
        const waitMs = Math.pow(2, i) * 1000 // 1s → 2s → 4s
        await new Promise((res) => setTimeout(res, waitMs))
        continue
      }
      throw e
    }
  }
}
```

429エラーの詳細なトラブルシューティングについては、[Gemini API クォータ・429エラーの完全解決ガイド](/articles/gemini-api/gemini-api-quota-429-error-troubleshooting)をご覧ください。

## よくある質問（FAQ）

**Q: Vue 2 でも同じコンポーザブルは使えますか？**

A: Vue 2 では Composition API が公式サポートされていないため、`@vue/composition-api` プラグインが必要です。ただし Vue 2 は現在サポート終了（EOL）しているため、新規開発では Vue 3 への移行を強く推奨します。`useGemini.js` のJavaScriptロジック自体は変更不要で、テンプレート部分を Options API スタイルに書き換えるだけで対応できます。

**Q: TypeScript で書くにはどうすればいいですか？**

A: Google AI SDK は TypeScript の型定義を公式に提供しています。`useGemini.ts` として作成し、`Ref<boolean>` や `GenerativeModel` などの型を import して利用できます。`import type { GenerativeModel } from '@google/generative-ai'` のように型インポートを活用することで、コンパイル時のエラー検出が可能になります。

**Q: Nuxt 3 での実装と何が違いますか？**

A: 基本的なコンポーザブルのロジックは同じです。Nuxt 3 では `composables/` ディレクトリに置くことで自動インポートが有効になり、`useRuntimeConfig()` でAPIキーを安全にサーバーサイドで扱えます。また SSR との相性を考慮して `onMounted` 内でAPIクライアントを初期化するか、`<ClientOnly>` コンポーネントで囲む対応が必要な場合があります。

**Q: チャット履歴を localStorage に保存できますか？**

A: 保存自体は可能です。`watch(messages, () => localStorage.setItem('chatHistory', JSON.stringify(messages)), { deep: true })` で変更のたびに保存できます。ただし機密情報を含む会話の保存は避け、ユーザーへの明示的な説明が必要です。会話を再開する際は `startChat({ history: savedHistory })` に渡す形式への変換処理も実装してください。

**Q: 送信できる画像のファイルサイズに制限はありますか？**

A: `inlineData` 方式では、画像データをリクエストに直接含めるため、大きすぎるファイルはAPIエラーになることがあります。一般的には 4MB 以下を目安にしてください。大きなファイルの場合は File API を利用して事前アップロードし、URI参照で送信する方法が推奨されます。
