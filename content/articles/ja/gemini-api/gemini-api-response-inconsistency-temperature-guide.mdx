「同じプロンプトを投げているのに、なぜ毎回違う答えが返ってくるんだろう？」

Gemini API を使い始めて最初に感じる疑問のひとつが、これではないでしょうか。ローカルで動かすコードと本番サーバーで結果が違う、テストのたびに出力が変わってユニットテストが書けない——そんな状況に困ったことがある方は、ぜひこの記事を読んでみてください。

この「毎回変わる」挙動は仕様であり、バグではありません。ただし、用途によっては安定した出力が必要なケースも多くあります。今回は仕組みを丁寧に整理しつつ、実際のコードで安定化する方法をご紹介します。

iOS/Android アプリを 6 本並行運用してきた個人開発者として、この問題に普段から向き合ってきた立場で、要点を整理します。

## なぜ Gemini API のレスポンスは変わるのか — temperature の仕組み

Gemini API（というか、ほとんどの大規模言語モデル）は「次のトークンをどれだけランダムに選ぶか」を制御するパラメータを持っています。それが `temperature` です。

値の範囲は `0.0〜2.0`（モデルによって上限が異なります）で、デフォルトは `1.0` です。

- **temperature が高い（1.0〜2.0）**: 確率分布がなだらかになり、多様なトークンが選ばれやすい → 創造的で変化に富んだ回答になる
- **temperature が低い（0.0〜0.5）**: 確率分布が鋭くなり、最も確率が高いトークンが選ばれやすい → 一貫性が高まる

```python
import google.generativeai as genai

genai.configure(api_key="YOUR_API_KEY")

model = genai.GenerativeModel(
    model_name="gemini-2.5-pro",
    generation_config=genai.types.GenerationConfig(
        temperature=0.0,  # 最も一貫性が高い設定
        top_p=0.95,
        top_k=40,
    )
)

response = model.generate_content("日本の首都は？")
print(response.text)
# → "東京" と安定して返るようになる
```

temperature だけでなく、`top_p`（トークンの累積確率の上位何%を候補にするか）と `top_k`（上位何個のトークンを候補にするか）も変動に影響します。安定性を求めるなら `temperature=0.0`、`top_p=0.95`、`top_k=1` の組み合わせから試してみてください。

## temperature=0 にしても変わる場合の原因

「temperature を 0 にしたのに、まだ微妙に変わる」という報告を実際によく耳にします。これには主に3つの理由があります。

**① モデル側の内部確率が同率になる箇所**

temperature=0 は「最も確率の高いトークンを選ぶ」設定ですが、複数のトークンの確率が同じ場合、どちらを選ぶかは実装依存です。Gemini API の場合、インフラ側のロードバランサーや量子化レベルの違いにより、完全に決定的ではないことがあります。

**② Thinking Mode（思考モード）が有効な場合**

Gemini 2.5 Pro や 2.5 Flash では、デフォルトで思考プロセスが有効になっています。思考ステップ自体にもサンプリングが入るため、最終的な回答も変動することがあります。thinking mode を明示的に無効にするか、thinking_budget を 0 に設定すると変動が減る場合があります。

```python
# Thinking Mode を明示的に制御する例
generation_config = genai.types.GenerationConfig(
    temperature=0.0,
)

# google-generativeai SDK での thinking 設定
# (新しいSDKバージョンではgeneration_configで設定可能)
response = model.generate_content(
    "このコードのバグを特定してください: ...",
    generation_config=generation_config
)
```

**③ コンテキストに日時や動的な情報が含まれる**

プロンプトや System Instruction の中に `今日は{date}です` のような動的な文字列が入っていると、毎回コンテキストが変わるため結果も変わります。再現性を確認したいなら、まず静的なプロンプトで試してみましょう。

## 一貫性を高める設定の組み合わせ

用途別の推奨設定をまとめます。

**分類タスク・データ抽出（高い一貫性が必要）**

```python
config_for_classification = genai.types.GenerationConfig(
    temperature=0.0,
    top_p=0.95,
    top_k=1,  # 最上位トークンのみ
    candidate_count=1,
)
```

**要約・翻訳（適度な一貫性）**

```python
config_for_summarization = genai.types.GenerationConfig(
    temperature=0.2,
    top_p=0.95,
    top_k=20,
    candidate_count=1,
)
```

**創作・アイデア生成（多様性を重視）**

```python
config_for_creative = genai.types.GenerationConfig(
    temperature=1.0,
    top_p=0.95,
    top_k=40,
    candidate_count=1,
)
```

私の経験では、APIでデータ処理系のタスク（フォーム入力の分類、商品レビューのセンチメント分析など）をするときは `temperature=0.0` に固定するのが一番安心です。わずかな変動が下流のロジックに影響することがあるので、早めに設定しておくと後でデバッグが楽になります。

## Structured Output でレスポンス形式を固定する

「JSONが返ってくるときと返ってこないときがある」という問題は、temperature 以外の原因がほとんどです。Gemini API には Structured Output（構造化出力）機能があり、これを使うとレスポンスを指定した JSON スキーマに強制的に合わせられます。

```python
import google.generativeai as genai
from pydantic import BaseModel

genai.configure(api_key="YOUR_API_KEY")

class SentimentResult(BaseModel):
    sentiment: str  # "positive" | "negative" | "neutral"
    confidence: float  # 0.0 ~ 1.0
    reason: str

model = genai.GenerativeModel(
    model_name="gemini-2.5-flash",
    generation_config=genai.types.GenerationConfig(
        temperature=0.0,
        response_mime_type="application/json",
        response_schema=SentimentResult,
    )
)

review = "このカフェは雰囲気が良くて料理も美味しかったです。また来たいと思います。"
response = model.generate_content(f"以下のレビューを分析してください: {review}")

# 常に有効な JSON が返ってくる
import json
result = json.loads(response.text)
print(result)
# → {"sentiment": "positive", "confidence": 0.92, "reason": "..."}
```

Structured Output を使うと「JSONを返してください」とプロンプトに書く必要がなくなり、マークダウンのコードブロックに包まれた JSON が返ってくる問題も解決されます。詳しくは[Structured Output の本番実装ガイド](/articles/gemini-advanced/gemini-structured-output-production-guide)も参考にしてみてください。

## System Instruction でレスポンスの文体・形式を固定する

temperature を下げても「答え方がバラバラ」という場合は、System Instruction（システム指示）が有効です。出力フォーマット、使う言語、回答の長さなどを明示しておくと、変動が大幅に減ります。

```python
system_instruction = """
あなたはプロダクトレビュー分析の専門AIです。

## 必須ルール
- 必ず日本語で回答する
- センチメント（positive/negative/neutral）を必ず明記する
- 回答は100文字以内にまとめる
- 推測ではなく、テキストに明示された内容のみに基づいて判断する
"""

model = genai.GenerativeModel(
    model_name="gemini-2.5-pro",
    system_instruction=system_instruction,
    generation_config=genai.types.GenerationConfig(
        temperature=0.0,
    )
)
```

System Instruction はモデルの「性格」を設定するようなものです。これが曖昧だと、温度が低くても回答スタイルが揺れることがあります。

## Gemini API を初めて使う方へ — 設定を確認する前に

もし API を使い始めたばかりで「まず基本的なエラーから解決したい」という方は、[Gemini API で最初につまずくエラーと解決策](/articles/gemini-api/gemini-api-first-errors-beginners-guide-2026)から読み始めることをおすすめします。認証エラーやインストール周りの問題を先に整理しておくと、temperature の設定変更が正しく反映されているかどうかも確認しやすくなります。

## まとめ: 今日すぐできること

Gemini API のレスポンスが変動する主な理由は **temperature の値が高い** ことです。一貫性が必要なタスクでは、まず `temperature=0.0` を試してみてください。それでも変動が続くなら、Structured Output でスキーマを固定し、System Instruction で出力フォーマットを明示するのが効果的です。

プロンプトエンジニアリングの体系的な知識を深めたい方には、[プロンプトエンジニアリング完全ガイド（Lee Boonstra 著）](https://www.amazon.co.jp/dp/B0C9BL9BFM/?tag=pinocchio-22)が参考になります。実際のAPIとの組み合わせ方まで丁寧に書かれていておすすめです。

`temperature=0.0` + `response_mime_type="application/json"` + `response_schema` の3点セットを設定するだけで、多くのユースケースで安定した動作が実現できます。ぜひ試してみてください。
