移行の順番を決めようとして、[Gemini の廃止一覧](https://ai.google.dev/gemini-api/docs/deprecations)を開いた夏の夕方のことです。`gemini-2.5-flash` の行を探して、停止日の欄で手が止まりました。そこには日付がなく、`No shutdown date announced` とだけ書かれていたのです。

それなのに、開発者フォーラムには7月9日付で「`gemini-2.5-flash` を呼んだら404が返り、`This model models/gemini-2.5-flash is no longer available` と言われた」という[報告](https://discuss.ai.google.dev/t/gemini-2-5-flash-and-gemini-2-5-flash-lite-returning-404-no-longer-available-today-july-9-contradicts-oct-16-2026-shutdown-date/174267)が立っていました。`gemini-2.5-pro` には「[新規ユーザーには提供されない](https://discuss.ai.google.dev/t/gemini-2-5-pro-returns-no-longer-available-to-new-users-contradicts-official-deprecation-date-oct-16-2026/176380)」という別の文面の報告もあります。

この記事は8月に書いた初稿を、11月の状況に合わせて書き直したものです。11月2日の changelog で、2.5 系の扱いがはっきりしました。最初にお伝えしたいのは、**2026年12月1日から、`gemini-2.5-flash` への API リクエストは `gemini-3.5-flash-lite` へ、`gemini-2.5-pro` は `gemini-3.8-flash` へ自動で振り替えられ、料金も振り替え先の単価になる**という点です（2026年11月28日時点・公式の deprecations と changelog で確認）。

止まるのではなく、別のモデルが答えるようになります。ですから「404 が出たら直す」という待ちの姿勢では、12月1日以降の変化を取りこぼします。ここでは、404 の正体、振り替えで壊れやすい箇所、そして自分のキーで何が見えているかを確かめる手順を、順に辿ります。

2.5 Flash と 2.5 Pro の注記には、もう一つ大事な一文があります。2.5 系へのアクセスは「過去に実際に使っていたユーザー」に限られる、という趣旨です。7月から出ていた 404 の報告は、この一文でほぼ説明がつきます。

## 停止日の欄は「下限」で、404 は別の仕組みで起きていました

廃止一覧には、表の上に注記があります。原文は `The shutdown dates listed in the table indicate the earliest possible dates on which a model might be retired` です。つまり表の日付は、そのモデルが引退させられうる**いちばん早い日**であり、「その日までは使える保証」ではありません。

初稿を書いた8月、私はこの表を逆向きに読みかけていました。日付が空欄なら、当分は大丈夫だろう、と。結果は芳しくありませんでした。空欄のあいだにも、新しく切ったキーからは 2.5 系が呼べなくなっていたのです。いま思えば、空欄を猶予と読みたかったのは、移行の手間を先送りしたい私の気持ちだったのかもしれません。

404 には2種類の文面があり、意味が違います。

- `no longer available` は、その呼び出し元からモデルの入口が閉じている状態
- `no longer available to new users` は、過去の利用実績で結果が分かれる状態

後者は、長く使っている本番プロジェクトでは通るのに、後から作った CI やステージングのキーでは 404 になる、という非対称を生みます。同じコード、同じモデル ID で結果だけが違うので、原因がコード側に見えてしまうのです。

私は SDK の版を疑い、リージョンを疑い、リクエストの組み立てを疑って、半日ほど手が止まりました。用途ごとにキーを分けていると、作られた時期もばらばらになります。そこでいまは、こう線を引いています。

**期限はページで読み、いま呼べるかどうかはキーごとに確かめます。** 表の日付は計画のための材料で、動作の保証ではないのです。

## 料金はどう変わるのか（2026年11月時点・公式の料金ページで確認）

振り替えは「料金も振り替え先」です。有料枠の100万トークンあたりの単価（米ドル）を並べました。

<tr><td>→ <code>gemini-3.5-flash-lite</code></td><td>$0.30（音声を含む）</td><td>$2.50</td><td>テキスト中心なら単価は同じ。音声入力は安くなる</td></tr>

2.5 Flash から 3.5 Flash-Lite への振り替えは、テキストだけなら単価が変わりません。注意したいのは、出力トークンの量です。モデルが変われば、同じ指示でも返す長さが変わります。単価が同じでも、出力が長くなれば請求は増えます。

2.5 Pro から 3.8 Flash への振り替えは、単価だけ見れば下がります。ただし 3.8 Flash は導入価格で、2027年1月1日から入力・出力とも倍になります。12月の請求で安心して、1月の請求で驚く、という順番になりやすいのです。

## 自分のキーから何が見えているかを、5分で確かめる

推測をやめて、キーごとに `models.list` を叩くのが早いです。依存を足したくなければ `curl` だけで済みます。

```bash
curl -s "https://generativelanguage.googleapis.com/v1beta/models?pageSize=200" \
  -H "x-goog-api-key: YOUR_API_KEY" \
  | grep -o '"name": "models/[^"]*"' \
  | sed 's|.*models/||; s|"$||' \
  | sort
```

出てきた一覧に `gemini-2.5-flash` が含まれていなければ、そのキーからはもう見えていません。

**確かめるキーは1本では足りません。** 本番用と、CI・ステージング用の両方で走らせて差分を取ります。片方にしか見えないモデルがあれば、それは「過去の利用者に限定」の線引きが効いている合図です。

```python
#!/usr/bin/env python3
"""本番キーと CI キーで models.list の結果を比べ、片方にしか見えないモデルを出す。"""
import json
import os
import sys
import urllib.request

ENDPOINT = "https://generativelanguage.googleapis.com/v1beta/models?pageSize=200"
WATCH = ("gemini-2.5-flash", "gemini-2.5-pro", "gemini-2.5-flash-lite")


def list_models(api_key):
    names = set()
    url = ENDPOINT
    while url:
        req = urllib.request.Request(url, headers={"x-goog-api-key": api_key})
        with urllib.request.urlopen(req, timeout=30) as res:
            body = json.load(res)
        for model in body.get("models", []):
            if "generateContent" in model.get("supportedGenerationMethods", []):
                names.add(model["name"].replace("models/", "", 1))
        token = body.get("nextPageToken")
        url = ENDPOINT + "&pageToken=" + token if token else None
    return names


def main():
    prod_key = os.environ.get("PROD_API_KEY")
    ci_key = os.environ.get("CI_API_KEY")
    if not prod_key or not ci_key:
        print("PROD_API_KEY と CI_API_KEY を環境変数に設定してください", file=sys.stderr)
        return 2

    prod = list_models(prod_key)
    ci = list_models(ci_key)
    only_prod = sorted(prod - ci)
    only_ci = sorted(ci - prod)

    print("本番キーから見えるモデル: %d 件" % len(prod))
    print("CI キーから見えるモデル: %d 件" % len(ci))
    print("本番にだけ見える:", ", ".join(only_prod) if only_prod else "なし")
    print("CI にだけ見える:", ", ".join(only_ci) if only_ci else "なし")
    for name in WATCH:
        print("%-24s 本番=%s CI=%s" % (name, name in prod, name in ci))
    return 1 if (only_prod or only_ci) else 0


if __name__ == "__main__":
    raise SystemExit(main())
```

`generateContent` に対応したモデルだけを拾っているのは、埋め込みや音声のモデルを混ぜると差分が読みにくくなるためです。差分があれば終了コード1を返すので、定期実行に載せて「差分が出た日だけ気づく」形にできます。ページングを素直に回しているのは、提供モデルが増え続けていて、1ページに収まる保証がないためです。

出力は次のような形になります（件数とモデル名はキーによって変わるため、ここでは形だけを示します）。

```text
本番キーから見えるモデル: N 件
CI キーから見えるモデル: M 件
本番にだけ見える: gemini-2.5-flash, gemini-2.5-pro
CI にだけ見える: なし
gemini-2.5-flash         本番=True CI=False
gemini-2.5-pro           本番=True CI=False
gemini-2.5-flash-lite    本番=True CI=True
```

12月1日以降、自動振り替えされたモデルが `models.list` にどう現れるのかは、私はまだ確かめていません。ですから振り替え後は、この一覧だけでなく、次の節の `modelVersion` も併せて見ておくと安心です。

## 振り替えの前に外しておきたい設定

自動振り替えは、呼び出し側のコードを書き換えてはくれません。11月2日の changelog は、破壊的な API の変更として次のものを挙げています。function calling と `thought_signature` の検証、`thinking_budget` から `thinking_level` への置き換え、サンプリング系パラメーターとプリフィルの削除です。

手元のコードで当たりそうな箇所を、先に洗い出します。

```bash
grep -rInE 'gemini-2\.5-(flash|pro)\b|thinking_budget|top_p|top_k|candidate_count|"?temperature"?' . \
  --include='*.py' --include='*.ts' --include='*.js' --include='*.kt' --include='*.swift' \
  --include='*.json' --include='*.yaml' --include='*.yml' --include='*.toml'
```

見つかった箇所を、移行先に合わせて書き換えます。Python の `google-genai` での Before と After です。

```python
# Before: 2.5 Flash 向けの書き方（12月1日以降は 3.5 Flash-Lite が受け取る）
from google import genai
from google.genai import types

client = genai.Client()
resp = client.models.generate_content(
    model="gemini-2.5-flash",
    contents="次のレビューを「不具合」「要望」「感想」のどれかに分類してください: 壁紙が保存できません",
    config=types.GenerateContentConfig(
        temperature=0.2,                                       # 3.x では無視される
        thinking_config=types.ThinkingConfig(thinking_budget=0),  # 3.x では thinking_level へ
    ),
)
print(resp.text)
```

```python
# After: 移行先を明示し、応答したモデルも記録する
import os
from google import genai
from google.genai import types

MODEL = os.environ.get("GEMINI_MODEL", "gemini-3.5-flash-lite")

client = genai.Client()
resp = client.models.generate_content(
    model=MODEL,
    contents="次のレビューを分類してください: 壁紙が保存できません",
    config=types.GenerateContentConfig(
        system_instruction="出力は「不具合」「要望」「感想」のいずれか一語だけにしてください。",
        thinking_config=types.ThinkingConfig(thinking_level="minimal"),
    ),
)
print(resp.text)
print("requested:", MODEL, "served:", resp.model_version)
```

After で変えたのは三つです。モデル ID を環境変数で受けること、温度で出力を縛る代わりに system instruction で規則を書くこと、そして `thinking_level` に置き換えることです。`minimal` は 3.5 Flash-Lite の既定値で、公式の移行ガイドでは抽出・振り分け・分類のような大量処理にはそのまま、ツール呼び出しを伴うサブエージェントには `medium` か `high` を勧めています。

2.5 Pro から 3.8 Flash へ移る場合は、一点だけ違います。3.8 Flash は `minimal` に対応しておらず、`low`・`medium`（既定）・`high` から選びます。2.5 Flash と 2.5 Pro を同じ設定オブジェクトで呼び分けているコードは、ここで分ける必要があります。

## どの移行先を選ぶか

自動振り替えに任せず、自分で移行先を選ぶほうが、後から説明がつきます。判断の目安を表にしました。

<table>
<tr><th>いまの使い方</th><th>候補</th><th>こんなときに選びます</th></tr>
<tr><td>2.5 Flash で抽出・分類・翻訳などの大量処理</td><td><code>gemini-3.5-flash-lite</code></td><td>振り替え先と同じなので、検証の手間がいちばん少ないとき</td></tr>
<tr><td>2.5 Flash でツール呼び出しの多いエージェント</td><td><code>gemini-3.5-flash-lite</code>（<code>thinking_level</code> を medium／high）か <code>gemini-3.6-flash</code></td><td>Flash-Lite で途中終了が出るなら 3.6 Flash へ上げる</td></tr>
<tr><td>2.5 Pro で長文の推論やコード</td><td><code>gemini-3.8-flash</code></td><td>振り替え先と同じ。年明けの単価で見積もっても収まるとき</td></tr>
<tr><td>2.5 Flash-Lite</td><td>そのまま</td><td>廃止対象ではないため、急いで動かす理由がないとき</td></tr>
</table>

迷ったときは、**振り替え先と同じモデルを、自分の手で明示する**のがいちばん無難です。結果は振り替えと同じでも、コードに書いてあるモデルと実際に答えるモデルが一致するので、次に何かが変わったときの切り分けが短くなります。

## よくある誤解を三つ

一つ目は「停止日が空欄なら当分使える」という読み方です。公式の注記にあるとおり、表の日付は引退の最も早い日であり、空欄は保証ではありません。実際、空欄のあいだにも新しいキーからは呼べなくなっていました。

二つ目は「自動で振り替えられるなら、コードは何もしなくていい」という受け止め方です。changelog は12月1日までにモデル文字列を書き換え、移行ガイドの破壊的変更を確かめるよう求めています。振り替えは止まらないための猶予であって、移行の代わりではないのです。

三つ目は「2.5 Flash-Lite も同時に止まる」という早合点です。deprecations には `gemini-2.5-flash-lite` は廃止対象ではなく、追って告知があるまで API で使えると書かれています。慌てて動かすと、検証の手間だけが増えます。

## モデル ID は、コードよりも周辺に残ります

呼び出し箇所を直せば終わり、とはいきませんでした。私の手元で残っていたのは、むしろコードの外側です。

- 設定ファイルの既定値（コード側は環境変数で上書きできるのに、既定値が古いまま）
- テストの記録済みレスポンス（古いモデル ID が焼き付いたまま、緑で通り続けるテスト）
- 読者向けに書いたコード例と、手元の手順書
- App Store と Google Play の説明文や、機能紹介のページに書いた「◯◯を使っています」という一文

厄介なのは2番目です。記録済みのレスポンスを再生しているテストは、振り替えで出力が変わっても何も言いません。この構造は<a href="/articles/gemini-dev/gemini-recorded-fixture-model-retirement-freshness-gate">テストは緑のまま、本番だけが止まる</a>で、フィクスチャの鮮度を見張る側から書きました。

4番目は技術的な破損ではありませんが、読んだ人に古い前提を渡し続けます。壁紙アプリのストア説明文を多言語で直したとき、言語ごとに同じ一文が残っていて、一つずつ探すのに思った以上に時間がかかりました。移行のチェックリストに、文章の検索を1行足しておくことをお勧めします。

## 振り替えのあとに当たりやすいこと

12月1日を過ぎて最初に気づくのは、たぶんエラーではありません。返事の調子や長さが、なんとなく変わったという手触りです。要求したモデルと応答したモデルを並べて記録する方法は、<a href="/articles/gemini-updates/gemini-flash-auto-routing-requested-vs-served-model-log">Flash の返事の調子が変わった朝、最初に見るのは自分のプロンプトではありません</a>にまとめています。

温度を外したあとに出力の幅が狭まって困る場合は、<a href="/articles/gemini-api/gemini-sampling-params-deprecation-diversity-side-migration">temperature 非推奨で先に困ったのは、決定性ではなく多様性の側でした</a>が次の一歩になるはずです。

404 が返り始めたあとの扱いも、先に決めておいてください。入口が閉じたモデルの 404 は、待てば直る種類の失敗ではありません。指数バックオフで再試行を重ねても、待ち時間が積み上がるだけです。その待ち時間が成功側の統計にどう現れなかったかは、<a href="/articles/gemini-api/gemini-retired-model-permanent-error-queue-wait-measured">停止済みモデルの再試行は、成功レイテンシには出ませんでした</a>で扱いました。

今日できることを一つだけ挙げるなら、本番のキーと CI のキーで上の差分スクリプトを走らせ、2.5 系がどちらから見えているかを確かめることです。見えていないキーがあれば、そこから先に移行先を明示してください。12月1日の朝を、何も起きない朝にしておきたいと、いまも思っております。
