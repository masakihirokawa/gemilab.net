個人開発者が月10万円の副業から月50万円のBtoB案件へステップアップするとき、多くの人が壁にぶつかります。個人向けSaaSは作り方を覚えれば量産できますが、企業向け案件は営業・契約・デリバリー・継続受注といった「ビジネスの型」が求められます。ここで必要なのは技術力だけでなく、企業の意思決定プロセスを理解した設計です。

Gemini APIとGoogle Workspaceを組み合わせた企業向け案件で、月50万円規模の収益を作る設計図を共有します。私自身、個人アプリ開発から入り、企業案件も経験してきました。その過程で見えてきた「個人開発者がBtoB市場で勝てる領域」と、そこに入るための具体的な手順を実例とともに整理しました。

## なぜ「Gemini API × Workspace」がBtoBの入り口として最適か

企業向け案件で個人開発者が勝てる領域は限られています。大手のSIerやコンサルが対応できない、「小さくて、速くて、特定の業務に特化した」案件です。この条件を満たす最適な技術スタックが、Gemini APIとGoogle Workspaceの組み合わせです。

理由は3つあります。

ひとつめ、Google Workspace（旧G Suite）は中小企業〜大企業まで採用率が明確に高いです。日本の中堅企業でも6割以上がWorkspaceを使っています。つまり、「既に導入されているツール上で動くAI機能」として売り込めば、新規ツール導入の稟議という最大の壁を回避できます。

ふたつめ、Gemini APIとWorkspaceの連携はGoogle公式が推奨するルートで実装できます。Gmail、Drive、Docs、Sheets、Calendarのデータを Gemini API に渡す実装パターンが公式ドキュメントに揃っており、セキュリティ面でも企業の監査をクリアしやすいです。

みっつめ、納品形態が「Google Apps Script」「Workspace アドオン」「Gemini API 連携の独自Webアプリ」の3種類あり、案件の規模に応じて選べます。個人開発者は小さい納品形態から始めて、大きい形態へスケールできます。

## 個人開発者が勝てる5つの案件パターン

私が観測してきた、個人でも受注可能なBtoB案件の典型パターンを5つ紹介します。それぞれに価格相場も添えます。

**パターン1: 議事録自動生成ツール（15万〜40万円）**

Google Meet の録画データをGemini APIで要約し、Google Docs に自動保存するツールです。Workspaceアドオンとして提供するのが標準です。中小企業の定例会議が増える中で、「毎週の定例の議事録を手動で書いている」企業に刺さります。

実装はGoogle Apps Script + Gemini API の組み合わせで1週間程度。カスタマイズ範囲が広い（要約の長さ、タスクの抽出、担当者への自動メンションなど）ため、案件規模に応じて15万〜40万円で見積もります。

**パターン2: メール返信テンプレート生成（20万〜50万円）**

Gmailに届いたメールを Gemini API で分類し、返信ドラフトを自動生成するツールです。法律事務所、会計事務所、カスタマーサポート部門に需要があります。

ポイントは「過去のメール履歴を学習させる」機能です。単純な生成AIではなく、その企業固有の返信パターンを反映するため、価値が出ます。技術的にはVertex AIのコンテキストキャッシュまたはFine-tuningを使います。

**パターン3: Sheets上の問い合わせ自動分類・返信（15万〜35万円）**

Googleフォームで集めた問い合わせを Sheets に蓄積し、Gemini API で分類と一次返信を自動化するツールです。イベント運営、コミュニティ管理、BtoCサービスのサポート窓口に需要があります。

Apps Scriptで実装でき、納期2週間程度の案件です。問い合わせ内容のカテゴリ別集計ダッシュボードを添えると、提案の説得力が増します。

**パターン4: 営業資料の自動カスタマイズ（30万〜80万円）**

営業先企業の情報（Webサイト、プレスリリース、IR資料）をGemini APIに解析させ、その企業向けにカスタマイズした提案資料をGoogle Slidesで自動生成するツールです。BtoB SaaS企業、コンサルティング企業、広告代理店に需要があります。

案件規模が大きい理由は、営業部門全体で使う前提で設計するため、テンプレート設計、承認フロー、効果測定の仕組みまで含むことが多いためです。

**パターン5: 社内ドキュメント横断検索（50万〜150万円）**

Drive内の全ドキュメントをGemini API + Vector Searchで検索可能にするツールです。法務部門、人事部門、研究開発部門に需要があります。

案件規模が最大級の理由は、権限管理（誰がどのドキュメントを検索できるか）とデータ保持期間の設計が複雑なためです。個人で受注するならこの規模は1案件/月が上限です。

## 月50万円を構成する現実的な組み合わせ

月50万円をこれらのパターンで作るなら、現実的な組み合わせは次の通りです。

- パターン1（議事録ツール）× 2件: 30万円
- パターン3（Sheets問い合わせ）× 1件: 20万円

合計50万円、案件数3件です。パターン2は粗利率が良い（カスタマイズ範囲が広く、追加要件で見積もり追加しやすい）ため、慣れてきたら組み合わせに加えます。

## 案件の見つけ方 — 初回案件の3つのルート

ここからが個人開発者の最難関、案件の見つけ方です。私の経験則で、初回案件を獲得しやすいルートは3つあります。

**ルート1: 自分の既存クライアントへの提案**

もし既にクラウドソーシングやフリーランスとして個人向けWeb制作などをしているなら、既存クライアントに「AIで業務改善しませんか」と提案するのが最速です。信頼関係があるため、契約までのプロセスが短縮されます。

提案資料は3ページで十分です。1ページ目：現状の業務フローの時間コスト計算、2ページ目：AI導入後のフローと時間削減、3ページ目：費用と納期。Gemini APIで「あなたの業務」の改善提案を事前に試作して持っていくと成約率が上がります。

**ルート2: noteやZennでの発信からの問い合わせ**

技術ブログで「Gemini API × Workspaceで議事録自動化をしてみた」のような実例記事を書き、記事末尾に「こういう仕組みの導入を検討している企業があればご連絡ください」と入れます。月1〜2本のペースで書き続けると、半年で1〜2件の問い合わせが来るペースになります。

ルート1と比べて時間はかかりますが、問い合わせが来る頃には、あなたの技術力が事前に検証された状態なので、価格交渉が有利です。

**ルート3: クラウドソーシングの大型案件への応募**

ランサーズ、クラウドワークス、Upworkで「Google Apps Script」「Gemini API」「Workspace連携」で検索します。月10件程度、上記パターンに該当する案件が出ています。単価は相場より低めのことが多いですが、初回案件を獲得して実績を作るには有効です。

## 価格交渉の3つの基本原則

BtoB案件で個人開発者が最も失敗するのが価格交渉です。3つの原則があります。

**原則1: 時間単価ではなく、業務改善効果で見積もる**

「10時間かかるから10万円」ではなく、「この仕組みで月20時間削減できるから、年間で240時間 = 約60万円の人件費削減になる」と説明します。企業の意思決定者は、投資対効果（ROI）で判断します。

**原則2: 初期費用と保守費用を分ける**

「30万円でツール納品」ではなく、「初期費用25万円 + 月額保守5,000円」のように分けます。保守費用が継続収益になり、次の案件を獲得するまでの間も収入が発生します。

**原則3: 追加要件には必ず追加見積もりを出す**

BtoB案件では、初回見積もりの範囲を超えた要件が必ず出てきます。ここで「サービスで対応します」と言ってしまうと、時間単価が大幅に下がります。初回契約書に「追加要件は別途見積もり」と明記し、実際に追加要件が出たら別途請求します。

## 契約書の最低限の項目

個人でBtoB案件を受ける場合、契約書は必須です。大企業との契約では、企業側のテンプレートを使うことが多いですが、中小企業との契約では、あなた側からテンプレートを提示することになります。

最低限含むべき項目は7つです。成果物の範囲、納期、対価と支払い条件、著作権の帰属、秘密保持、瑕疵担保責任の範囲、契約期間と終了条件。「著作権の帰属」は特に重要で、納品した成果物の著作権を企業に譲渡するか、利用許諾するかで、将来同じコードを他の案件で再利用できるかが変わります。

個人開発者の場合、「著作権はこちら（開発者）に保持し、企業に利用許諾を与える」形にしておくと、同じ基盤技術を別の案件で横展開できます。企業側から「著作権譲渡」を強く求められた場合は、見積もりを1.5倍に調整します。

## Gemini APIでの提案書自動生成

案件獲得の効率を上げるために、Gemini APIを使った提案書自動生成の実装を共有します。これ自体もBtoB案件の一種です。

```
以下のテンプレートに沿って提案書を作成してください：

【ヒアリング情報】
- 企業名: {企業名}
- 業種: {業種}
- 現在の課題: {ヒアリングで得た課題}
- 想定される導入効果: {効果の仮説}

【出力フォーマット】
1ページ目: エグゼクティブサマリー（3行）
2ページ目: 現状の業務フローと時間コスト計算
3ページ目: 提案ソリューションの技術概要
4ページ目: 想定ROIと削減効果
5ページ目: 費用・納期・サポート体制

各ページはGoogle Docs向けのMarkdownで出力してください。
```

このテンプレートをClaude Codeで実装し、ヒアリングシートから提案書をワンクリックで生成できる仕組みにすれば、1案件あたりの提案書作成時間が2時間から20分に短縮されます。

## デリバリー自動化で月3件を並行処理する

月50万円を安定して作るには、月3件の案件を並行処理できる体制が必要です。デリバリー自動化のコア要素は3つです。

**要素1: クライアントごとのプロジェクト管理テンプレート**

GitHubまたは GitLabで、クライアント名ごとにリポジトリを作ります。README.mdに契約内容、ヒアリング議事録、進捗、質問リストをすべて記載します。Claude Codeがこの情報を参照できるため、複数案件を並行してもコンテキストが混ざりません。

**要素2: Workspace アドオンの共通基盤**

すべての案件で共通するコード（認証、Gemini API呼び出し、ログ記録、エラーハンドリング）を、自分専用のライブラリとして整備します。新規案件では、このライブラリをコピーして個別のロジックだけ追加する形にします。

**要素3: クライアントへの進捗報告自動化**

Gemini APIで毎週金曜に、GitHubコミット履歴から週次進捗レポートを生成し、Gmail APIで自動送信します。報告の手間がゼロになり、クライアントからの信頼感も高まります。

## 継続受注のための「最初の3ヶ月」の磨き込み

初回案件を納品したあとの3ヶ月が、継続受注の可否を決めます。

1ヶ月目: 納品後の利用状況ヒアリング。実際にどれくらい使われているか、どこで詰まっているかを聞きます。
2ヶ月目: 小さな改善提案。使われていない機能を削除する、よく使われる機能を更に高速化するなど、保守費用の枠内での改善を行います。
3ヶ月目: 次の案件の提案。別の業務領域での同様のツール化を提案します。「議事録自動化が成功したので、次は経費精算の自動化はどうですか」といった流れです。

この3ヶ月の磨き込みができれば、1社から年間で3〜5案件を継続受注するパターンが作れます。新規開拓コストが不要になるため、純利益率が大幅に上がります。

## 月50万円の安定化 — 1年後の姿

この設計で1年間運用すると、どんな姿になるか具体化します。

- 継続契約中の企業: 4〜6社
- 月あたり新規案件: 1〜2件
- 月あたり継続保守収入: 10〜20万円
- 月あたり新規案件収入: 30〜40万円
- 合計月間収入: 50〜60万円

ここまで来ると、次のステップは「チームを作る」か「プロダクト化する」かの選択になります。個人で維持する場合は、単価を上げて案件数を絞る方向で最適化します。
