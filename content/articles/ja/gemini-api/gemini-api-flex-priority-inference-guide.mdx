2026年4月3日、GoogleはGemini APIに新しいサービスティア「**Flex Inference**」と「**Priority Inference**」を追加しました。従来の標準ティアに加え、コスト重視か信頼性重視かを用途に応じて選べるようになりました。この記事では、両ティアの仕組み・設定方法・ユースケースを実際のコード例とともに丁寧に解説します。

## Gemini API の推論ティアとは

Gemini APIでリクエストを送信するとき、内部では「どのコンピューティングキューにルーティングするか」という優先度設定が行われています。これまでは単一の「Standard（標準）」ティアのみが存在していましたが、2026年4月からは次の3種類から選べるようになりました。

- **Flex（フレックス）**: 標準比50%割引。レイテンシに余裕があるタスク向け
- **Standard（標準）**: デフォルト。通常の用途に最適なバランス型
- **Priority（優先）**: 標準比75〜100%割増。ミッションクリティカルな用途向け

それぞれの特性を理解することで、同じ予算でより多くのAPIコールをこなしたり、ユーザー向けチャットボットの応答速度を安定させたりと、アプリケーションの品質を大きく向上させることができます。

## Flex Inference — 50%コスト削減の使い方

### Flexティアの仕組み

Flex Inferenceは、**標準料金の50%**で利用できる代わりに、レスポンスが1〜15分程度かかることを許容するティアです。Batch APIと異なり、リクエストは同期的に処理されます。標準トラフィックが増加した際にFlex処理が遅延・中断されることがあるため、クライアント側でのリトライロジック実装を推奨します。

### Flexティアが向いているユースケース

- **LLM-as-a-judge による自動評価**: モデルの品質評価・ベンチマークテスト
- **バックグラウンドエージェント**: CRM更新、コンテンツモデレーション、ユーザープロファイル構築など数分の遅延が問題ないタスク
- **研究・実験用途**: 限られた予算で大量トークンを処理したい学術実験
- **バッチ処理的ワークフロー**: SEO記事の下書き生成、データ変換、ログ解析

### Python でのFlexティア実装

```python
import google.generativeai as genai

genai.configure(api_key="YOUR_GEMINI_API_KEY")

model = genai.GenerativeModel("gemini-2.5-pro")

# service_tier を "flex" に設定するだけでOK
response = model.generate_content(
    "この四半期の売上レポートを要約して分析してください。\n\n[レポート本文]",
    generation_config={
        "service_tier": "flex"  # Flexティアを指定
    }
)

print(response.text)
# 通常より少し時間がかかるが、コストは約50%削減
```

### JavaScript でのFlexティア実装

```javascript
  generationConfig: {
    serviceTier: "flex"  // Flexティアを指定（camelCase）
  }
});

console.log(result.response.text());
```

### Flex利用時のリトライロジック（推奨）

```python
import time
import google.generativeai as genai
from google.api_core import exceptions

def generate_with_flex_retry(prompt: str, max_retries: int = 3) -> str:
    """Flexティアで生成。失敗時はリトライする"""
    model = genai.GenerativeModel("gemini-2.5-pro")

    for attempt in range(max_retries):
        try:
            response = model.generate_content(
                prompt,
                generation_config={"service_tier": "flex"}
            )
            return response.text
        except exceptions.ServiceUnavailable as e:
            if attempt < max_retries - 1:
                wait_time = 30 * (attempt + 1)  # 30秒, 60秒, 90秒
                print(f"Flex処理が中断されました。{wait_time}秒後にリトライします...")
                time.sleep(wait_time)
            else:
                raise e

    return ""

# 使用例
result = generate_with_flex_retry("製品説明文を5パターン生成してください。")
print(result)
# 期待する動作: 通常は30秒〜数分でレスポンスが返る（コストは標準の50%）
```

## Priority Inference — 最高信頼性の使い方

### Priorityティアの仕組み

Priority Inferenceは、**標準料金の75〜100%増し**となる代わりに、最も優先度の高いコンピューティングキューにルーティングされます。リクエストが削除されることなく、数秒以内のレスポンスが期待できます。動的な制限を超えたトラフィックは、503エラーなく自動的にStandardティアにダウングレードされるため、アプリケーションの安定性が保たれます。

### Priorityティアが向いているユースケース

- **カスタマーサービスチャットボット**: ユーザーがリアルタイムで待機している対話型アプリ
- **リアルタイム不正検知**: 決済処理や取引承認フロー
- **プレミアム顧客向け機能**: 高SLOが求められる有料プランのコア機能
- **緊急アラートシステム**: 遅延が許容されないセキュリティや医療関連の処理

### Python でのPriorityティア実装

```python
import google.generativeai as genai

genai.configure(api_key="YOUR_GEMINI_API_KEY")

model = genai.GenerativeModel("gemini-2.5-pro")

# service_tier を "priority" に設定
response = model.generate_content(
    "このユーザーのメッセージに即座に日本語で回答してください：" + user_message,
    generation_config={
        "service_tier": "priority"  # Priorityティアを指定
    }
)

# レスポンスヘッダーで実際のティアを確認（ダウングレード検出）
# x-gemini-service-tier ヘッダーをチェック
print(f"応答: {response.text}")
```

### ダウングレード検出の実装（REST API）

```python
import requests

headers = {
    "Authorization": f"Bearer YOUR_GEMINI_API_KEY",
    "Content-Type": "application/json"
}

payload = {
    "contents": [{"parts": [{"text": "緊急タスク: 今すぐ対応が必要な回答を生成してください。"}]}],
    "generationConfig": {
        "serviceTier": "priority"
    }
}

response = requests.post(
    "https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-pro:generateContent",
    headers=headers,
    json=payload
)

# x-gemini-service-tier ヘッダーでティアを確認
actual_tier = response.headers.get("x-gemini-service-tier", "不明")
print(f"実際に使用されたティア: {actual_tier}")
# priority → 最優先処理、standard → ダウングレードされた場合

if actual_tier != "priority":
    # 必要に応じてアラートや代替処理を実装
    print("⚠️ Priorityティアから標準に切り替わりました")

data = response.json()
print(data["candidates"][0]["content"]["parts"][0]["text"])
```

## 3つのティアを比較して選ぶ

アプリケーションのユースケースに合わせて、以下の観点から最適なティアを選択してください。

**Flex（低コスト優先）を選ぶとき**:
- バックグラウンドで非同期的に処理できる
- 1〜15分程度の遅延が許容される
- 研究・実験・バッチ処理でコストを抑えたい
- リトライロジックを自分で実装できる

**Standard（デフォルト）を選ぶとき**:
- 一般的なWebアプリや開発・テスト環境
- 数秒〜数十秒のレスポンスで十分
- コストと信頼性のバランスを取りたい

**Priority（高信頼性優先）を選ぶとき**:
- ユーザーがリアルタイムで待機している
- 遅延や中断が許容されないミッションクリティカルな処理
- 高SLOが求められるプレミアム機能
- コストより応答性・安定性を最優先したい

## コスト試算と最適な使い分け戦略

実際のプロダクトでは、ティアを適切に組み合わせることが最も効果的なコスト最適化につながります。

例えば、月間100万トークン処理するアプリケーションがあるとします。

- 全処理をStandardで行った場合のコストを「1」とすると
- バックグラウンド処理（40%）をFlexに切り替えると → コスト「0.8」（20%削減）
- さらにリアルタイム処理（20%）をPriorityに切り替えると → コスト「0.84」（品質UP、コストは若干増）
- 最終的に全体コストを抑えながら、ユーザー体験の重要部分は向上

この考え方を体系的に実践するには、各APIコールの「重要度」と「時間的余裕」を分類するアーキテクチャ設計が必要です。さらに詳しいコスト最適化の手法については、[Gemini APIコスト完全最適化ガイド](/articles/gemini-api/gemini-api-cost-optimization-complete-guide) で解説しています。

## よくある質問（FAQ）

**Q1. Flexティアでリクエストが中断された場合、自動でリトライされますか？**

いいえ、自動リトライは行われません。Flexティアは「ベストエフォート」型であり、標準トラフィックが増加した際にFlex処理が中断されることがあります。クライアント側でリトライロジックを実装することが必須です。上記のコード例を参考に、指数バックオフ（30秒、60秒、90秒など）を設定することをおすすめします。

**Q2. Priorityティアに設定しても、実際はStandardになることがありますか？**

はい、あります。PriorityティアのトラフィックがGoogleの動的な制限を超えた場合、503エラーを返す代わりに自動的にStandardティアにダウングレードされます。これはアプリの安定性を保つための設計です。レスポンスヘッダーの `x-gemini-service-tier` を確認することで、実際に適用されたティアを検知できます。

**Q3. すべてのGeminiモデルでFlex・Priorityティアが使えますか？**

2026年4月時点では、Gemini 3系（3-pro、3-flash）・Gemini 3.1系・Gemini 2.5系の主要モデルでサポートされています。最新のサポート状況は[公式ドキュメント](https://ai.google.dev/gemini-api/docs/flex-inference)でご確認ください。また、Flex/Priorityは現時点では同期APIのみの対応で、Batch APIには適用されません。

**Q4. Flexティアを使うと、生成されるテキストの品質は変わりますか？**

いいえ、品質は変わりません。Flex・Priority・Standardはいずれも同じモデルを使用しており、コンピューティングキューのルーティングが異なるだけです。処理時間（レイテンシ）のみが変化します。

Gemini APIの新しいFlex・Priorityティアを活用することで、アプリケーションのコストと信頼性を用途に応じて最適化できます。
