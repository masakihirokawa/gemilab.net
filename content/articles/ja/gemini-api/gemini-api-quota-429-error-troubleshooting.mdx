## 取り組みの背景

Gemini API を使ったアプリケーション開発で、突然 `429 Too Many Requests` エラーが発生して、サービスが停止してしまった。そのような経験はありませんか？

このエラーは、API のクォータ制限に達したときに返されるもので、一見すると単純に見えますが、実は複数の原因が隠れていることが多いです。無料枠から有料へのアップグレード、リトライロジックの実装、Google Cloud Console での監視設定など、正しく対処しないと何度も同じ問題に直面することになります。

Gemini API の 429 エラーの原因特定方法から、根本的な解決策まで、実践的なトラブルシューティング手順を順を追って整理していきます。

## 429 エラーの正体 — RESOURCE_EXHAUSTED との違い

### 429 Too Many Requests エラーが発生するパターン

Gemini API から 429 エラーが返される場合、以下の3つが主な原因です。

- **RPM（Requests Per Minute）制限**: 1分あたりのリクエスト数上限を超過
- **RPD（Requests Per Day）制限**: 1日あたりのリクエスト数上限を超過
- **TPM（Tokens Per Minute）制限**: 1分あたりの処理トークン数上限を超過

無料枠ではこれらの制限が非常に厳しく設定されており、開発中には問題がなくても、アプリがスケールすると急に出現します。

### RESOURCE_EXHAUSTED エラーとの違い

```json
// 429 エラーのレスポンス例
{
  "error": {
    "code": 429,
    "message": "Resource has been exhausted (e.g. check quota).",
    "status": "RESOURCE_EXHAUSTED"
  }
}
```

実は、Google API の内部では `RESOURCE_EXHAUSTED` が詳細なステータスコードで、HTTP の 429 はこれの上位レベルの表現です。つまり、エラーメッセージに "Resource has been exhausted" と書かれていたら、それはクォータ制限に達したことを意味しています。

一方、`INVALID_ARGUMENT` や `PERMISSION_DENIED` といったエラーコードは、リクエスト形式の誤りや認証の問題なので、クォータの問題ではありません。

## 無料枠 vs 有料プランの制限値比較

### 無料枠（Free Tier）のクォータ

無料枠は開発やテスト用に設計されており、本番環境での使用を想定していません。

| 制限項目 | 制限値 | 単位 |
| --- | --- | --- |
| RPM（Requests Per Minute） | 60 | リクエスト/分 |
| RPD（Requests Per Day） | 1,500 | リクエスト/日 |
| TPM（Tokens Per Minute） | 10,000 | トークン/分 |
| 同時接続数 | 2 | セッション |

この制限値は、**個別ユーザーごと**ではなく、**プロジェクト全体** で共有されます。つまり、複数のアプリケーションやスクリプトが同じプロジェクトで API を呼び出していると、制限に達しやすくなります。

### 有料プラン（Pay-as-you-go）のクォータ

有料プランに切り替えると、制限値が大幅に引き上げられます。

| 制限項目 | 制限値 | 単位 |
| --- | --- | --- |
| RPM | 1,000～10,000 | リクエスト/分（モデル・リージョンで異なる） |
| RPD | 制限なし | - |
| TPM | 100,000～1,000,000 | トークン/分（購入量に応じて） |
| 同時接続数 | 100 | セッション |

さらに、Google Cloud Console で **Spend Limit（使用金額の上限）** を設定することで、予期しない請求を防ぐことができます。

## Google Cloud Console での監視・設定方法

### ステップ1：Google AI Studio からプロジェクト確認

まず、使用しているプロジェクトを特定する必要があります。

1. [Google AI Studio](https://aistudio.google.com) にアクセス
2. 左上の「プロジェクト選択」をクリック
3. 現在のプロジェクト名を確認（例：`My First Project`）

### ステップ2：Google Cloud Console でクォータ状況を確認

1. [Google Cloud Console](https://console.cloud.google.com) を開く
2. 左メニューの「API と サービス」→「ダッシュボード」を選択
3. 「Generative Language API」をクリック
4. 「クォータと使用」タブを選択

ここで、現在の使用状況とセットされている上限値を確認できます。

### ステップ3：有料プランへアップグレード

1. Google Cloud Console で「請求」→「アカウント」を選択
2. 「予算と使用量」セクションで支払い情報を設定
3. 完了後、API のクォータが自動的に引き上げられます

アップグレード直後は、クォータの反映に数分～数時間かかることがあります。

## 429 エラーが発生したときの応急対処

### すぐに実装できる3つのテクニック

**1. 指数バックオフによるリトライ**

```python
import time
import anthropic
from google.api_core import gapic_v1

def call_gemini_with_backoff(prompt, max_retries=5):
    client = anthropic.Anthropic(api_key="YOUR_GEMINI_API_KEY")

    for attempt in range(max_retries):
        try:
            response = client.messages.create(
                model="gemini-2.0-flash",
                max_tokens=1024,
                messages=[
                    {"role": "user", "content": prompt}
                ]
            )
            return response.content[0].text
        except Exception as e:
            if "429" in str(e) or "RESOURCE_EXHAUSTED" in str(e):
                # 指数バックオフ: 2^attempt 秒待機
                wait_time = 2 ** attempt
                print(f"Rate limited. Waiting {wait_time} seconds...")
                time.sleep(wait_time)
            else:
                raise

    raise Exception("Max retries exceeded")

# 使用例
result = call_gemini_with_backoff("Tell me about quantum computing")
print(result)
```

**2. リクエストキューイング**

バースト的なリクエストが発生する場合は、キューイングが効果的です。

```python
import queue
import threading
import time

class GeminiQueue:
    def __init__(self, max_rpm=60):
        self.queue = queue.Queue()
        self.max_rpm = max_rpm
        self.request_times = []
        self.lock = threading.Lock()

    def add_request(self, prompt):
        self.queue.put(prompt)

    def process_requests(self):
        while True:
            prompt = self.queue.get()
            self._rate_limit_check()
            # API呼び出し処理
            self.queue.task_done()

    def _rate_limit_check(self):
        with self.lock:
            now = time.time()
            # 1分以内のリクエスト記録を保持
            self.request_times = [t for t in self.request_times if now - t < 60]

            if len(self.request_times) >= self.max_rpm:
                # 最も古いリクエストから60秒経つまで待機
                wait_time = 60 - (now - self.request_times[0])
                time.sleep(wait_time)

            self.request_times.append(now)

# 使用例
gq = GeminiQueue(max_rpm=50)
for i in range(100):
    gq.add_request(f"Question {i}")
```

**3. 無料枠での同時実行の制御**

無料枠の同時接続数制限（2セッション）を回避するため、シリアル処理を強制します。

```python
import asyncio
import aiohttp

async def process_sequentially(prompts):
    """同時接続数を1に制限してリクエスト処理"""
    semaphore = asyncio.Semaphore(1)

    async def fetch_with_semaphore(prompt):
        async with semaphore:
            # API呼び出し
            await asyncio.sleep(1)  # レート制限回避用の遅延
            return f"Response to: {prompt}"

    tasks = [fetch_with_semaphore(p) for p in prompts]
    return await asyncio.gather(*tasks)

# 使用例
prompts = ["How to learn AI?", "What is machine learning?"]
results = asyncio.run(process_sequentially(prompts))
```

## 本番環境での長期的な対策

### 有料プランの選択基準

無料枠で 429 エラーが頻発するようになった場合は、有料プランへのアップグレードを検討すべきです。

- **小規模アプリ（月 < 1万リクエスト）**: 無料枠 + Spend Limit で対応
- **中規模アプリ（月 1万～100万リクエスト）**: Pay-as-you-go（従量課金）推奨
- **大規模アプリ（月 100万+ リクエスト）**: Volume Pricing の相談を Google Cloud Sales に

### Spend Limit の設定

予期しない高額請求を防ぐため、必ず設定します。

1. Google Cloud Console → 「請求」を開く
2. 「予算」→「新しい予算を作成」をクリック
3. 「月額上限」を設定（例：¥10,000）
4. アラート通知を「予算の100%で通知」に設定

この設定により、月額の上限に達するとすべての API 呼び出しが自動的に停止されます。

### クォータ監視の自動化

Google Cloud の Monitoring（旧 Stackdriver）を使い、クォータ使用率をダッシュボード化します。

```yaml
# Google Cloud Monitoring アラート例
displayName: Gemini API 429 Rate Limit Alert
conditions:
  - displayName: RPM Usage > 80%
    conditionThreshold:
      filter: |
        resource.type="api"
        AND metric.type="serviceruntime.googleapis.com/api/consumer/quota_used_count"
        AND resource.service="generativelanguage.googleapis.com"
      threshold_value: 0.8
      comparison: COMPARISON_GT
```

## まとめ

Gemini API の 429 エラーは、適切な対策で完全に回避できます：

1. **開発初期段階**: 無料枠の制限値を理解し、リトライロジックを実装
2. **スケール時**: 有料プランへアップグレード＆Spend Limit を設定
3. **本番運用**: Google Cloud Console でクォータを継続監視
