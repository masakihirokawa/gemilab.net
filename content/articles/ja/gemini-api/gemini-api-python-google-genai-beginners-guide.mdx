Gemini API をはじめて Python から呼び出したとき、「思っていたより全然シンプルだ」と少し拍子抜けした記憶があります。

公式ドキュメントを開くと英語のコードサンプルが並んでいて、どこから手をつければいいか迷うかもしれません。でも実際には、`pip install google-genai` の一行とAPIキーさえあれば、今日中に最初の応答を受け取ることができます。

この記事では、Python の基礎はあるけれど外部APIは未経験という方を想定して、`google-genai` ライブラリの基本的な使い方をステップごとに紹介します。コードはすべてコピーしてそのまま動くことを確認済みです。

## `google-genai` ライブラリとは — なぜ今これを使うのか

以前は `google-generativeai` という名前のパッケージが主流でしたが、2025年以降は `google-genai` が公式の推奨ライブラリになっています。

大きな違いは設計思想にあります。新しい `google-genai` は型ヒントが充実していてIDEの補完が効きやすく、非同期処理との相性もよくなっています。既存の `google-generativeai` コードを移行する際の注意点については[google-genai SDK 完全移行マスターガイド](/articles/gemini-api/google-genai-python-sdk-complete-migration-masterguide)にまとめてありますが、これから始める方はシンプルに `google-genai` から入ることをおすすめします。

## 準備 — APIキーの取得とライブラリのインストール

まず [Google AI Studio](https://aistudio.google.com) にアクセスして、APIキーを発行してください。Googleアカウントがあれば数分で取得できます。無料枠でも十分な量を試せますので、最初は課金設定なしで進めて問題ありません（無料枠で何ができるかは[Gemini API 無料枠で最初のプロジェクトを作る](/articles/gemini-api/gemini-api-free-tier-beginner-first-project)で詳しく説明しています）。

ライブラリのインストールはこの一行です：

```bash
pip install google-genai
```

取得したAPIキーは、コードに直接書くのではなく環境変数として管理しましょう。うっかりGitにコミットしてしまうリスクを防げます：

```bash
# .bashrc や .zshrc、あるいは .env ファイルに追記
export GEMINI_API_KEY="YOUR_API_KEY"
```

Python側では `os.environ["GEMINI_API_KEY"]` で読み込むか、`python-dotenv` ライブラリを使う方法がよく使われます。

## 最初のテキスト生成を試してみる

準備が整ったら、さっそく動かしてみましょう。以下が最もシンプルなテキスト生成のコードです：

```python
import os
from google import genai

# クライアントの初期化（APIキーを渡すだけ）
client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])

# テキスト生成リクエスト
response = client.models.generate_content(
    model="gemini-2.5-flash",
    contents="Pythonでよく使うリスト操作を5つ、簡潔に教えてください"
)

# レスポンステキストの取得
if response.text:
    print(response.text)
else:
    # 安全フィルターやその他の理由でテキストが空の場合
    print("レスポンスが取得できませんでした")
    print("finish_reason:", response.candidates[0].finish_reason)
```

`gemini-2.5-flash` は無料枠で利用できる高速なモデルです。回答の質を優先したい場合は `gemini-2.5-pro` に変えると、より精度の高い出力が得られます（ただし1分あたりのリクエスト数制限が若干厳しくなります）。

`if response.text:` のチェックを入れているのは、安全フィルターに引っかかったときに `response.text` が `None` になるケースがあるためです。開発初期から防御的に書いておくと後で助かります。

## チャット形式で複数回のやり取りをする

次は会話の文脈を保持しながら複数回やり取りするチャットセッションです：

```python
import os
from google import genai

client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])

# チャットセッションを開始
chat = client.chats.create(model="gemini-2.5-flash")

# 1回目のメッセージ
response1 = chat.send_message("Pythonの辞書（dict）について教えてください")
print("【1回目】")
print(response1.text)

# 2回目 — 前の会話の文脈を引き継いだ質問ができる
response2 = chat.send_message("その辞書を使った実践的なコード例を見せてください")
print("\n【2回目】")
print(response2.text)
```

`client.chats.create()` で作成したチャットオブジェクトが、内部で会話履歴を自動管理してくれます。2回目の質問で「その辞書を使った」と言っても、前の会話を踏まえた回答が返ってきます。

ただし、このセッションはプロセスが終了すると消えます。ユーザーとの会話を複数のセッションにまたがって保持したい場合は、履歴を外部のデータベースやファイルに保存・復元する仕組みが別途必要になります。

## ストリーミングで応答をリアルタイムに受け取る

長い回答を生成するとき、デフォルトの通常リクエストでは全文が揃うまで待つことになります。ストリーミングを使えば、生成されたテキストをリアルタイムで受け取れるため、ユーザー体験が大きく向上します：

```python
import os
from google import genai

client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])

print("ストリーミング応答:")

# generate_content_stream でストリーミング有効化
for chunk in client.models.generate_content_stream(
    model="gemini-2.5-flash",
    contents="Pythonの非同期処理について、なるべくわかりやすく説明してください"
):
    # チャンクごとに即座に出力
    print(chunk.text, end="", flush=True)

print()  # 最後に改行を追加
```

`flush=True` を指定することで、バッファリングされずに即座に出力されます。ターミナルで試すと、文字が少しずつ流れてくる様子が確認できます。

Webアプリに組み込む場合は非同期版（`async for chunk in ...`）を使うのが一般的です。Pythonの非同期処理とGemini APIの組み合わせについては[Gemini API Python 非同期処理 asyncio 完全ガイド](/articles/gemini-api/gemini-api-python-async-asyncio-guide)で詳しく扱っています。

## 最初につまずきやすい3つのポイント

使い始めてすぐに引っかかりやすい点を先にお伝えします。詳しいトラブル対応は[はじめてのGemini API — よく起きるエラーと解決法2026](/articles/gemini-api/gemini-api-first-errors-beginners-guide-2026)にまとめてありますが、ここでは特に多いケースを紹介します。

**1. モデル名のタイプミス**：`gemini-2.5-flash` のようにハイフン区切りで正確に指定する必要があります。`gemini25flash` や `gemini_2_5_flash` では `models.generate_content()` がエラーを返します。現在使用可能なモデル名は公式ドキュメントで確認するのが確実です。

**2. レート制限エラー（HTTPエラー 429）**：無料枠では1分あたりのリクエスト数に上限があります。ループで大量のリクエストを送るとすぐに上限に達します。`time.sleep(2)` を挟む、または指数バックオフのリトライ処理を入れると安定します。

**3. インポートのパスが変わっている**：古いドキュメントやStack Overflowの回答には `from google.generativeai import ...` という書き方が残っています。新しい `google-genai` ライブラリでは `from google import genai` が正しいインポートパスです。混在しないよう注意してください。
