Gemini API を使い始めて最初に戸惑うのが、日本語出力の品質のばらつきです。英語のプロンプトでは期待通りの結果が出るのに、日本語にした途端に文体が崩れたり、敬語と常体が混在したり、カタカナ語のゆれが出てきたりします。これはバグではなく、日本語という言語の特性を API が把握しきれていないことが原因です。

私が個人アプリ開発で Gemini API を日本語タスクに使ってきた経験から、実際に効くテクニックをまとめました。

2014年からアプリ事業を続けている個人開発者の経験から、この問題に普段から向き合ってきた立場で、要点を整理します。

国際芸術賞17冠のアーティスト活動と並行して個人開発を続けてきた立場として、技術記事は読者の現場で再現できる粒度まで落とすことを心がけています。
## なぜ日本語出力はばらつくのか

日本語が英語と根本的に異なる点は、**文体の選択肢が多いこと**です。「どこに行きますか？」「どちらへいらっしゃいますか？」「どこ行くの？」は同じ意味ですが、話者・聞き手・場面によって使い分けが必要です。プロンプトに明示的な指示がなければ、Gemini は学習データから「最もありがちな」テキストを生成します。

もう一つの要因は**ハルシネーション時の特性**です。日本語の固有名詞（人名・地名・商品名）は英語より誤りが出やすく、カタカナ語のゆれ（「プログラミング」と「プログラム」の混在など）も起きやすいです。

これらを理解した上で対策を組み立てると、出力品質がかなり安定します。

## テクニック1: システムインストラクションで文体を固定する

最も効果的な方法は、システムインストラクションで文体を明示的に指定することです。

```python
import google.generativeai as genai

genai.configure(api_key="YOUR_GEMINI_API_KEY")

# システムインストラクションで文体・トーンを固定
model = genai.GenerativeModel(
    model_name="gemini-2.5-pro",
    system_instruction="""
あなたは日本語の技術記事を書くライターです。
以下のルールを必ず守ってください:

【文体】
- 常に敬体（です・ます調）を使用する
- 常体（だ・である調）は一切使わない
- 読者への呼びかけは「あなた」ではなく「読者の方」を使う

【用語統一】
- 「アプリ」と「アプリケーション」は「アプリ」で統一
- 技術用語は英語のまま（API, SDK, JSON 等）
- カタカナは長音符あり（「プログラマー」○ / 「プログラマ」×）

【禁止事項】
- 文末を「〜となります」で終わらせない（「〜です」に変える）
- 「させていただきます」は使わない
- 同じ語尾を3回以上連続させない
"""
)

response = model.generate_content(
    "Gemini API の主な特徴を3つ教えてください。"
)
print(response.text)
# 期待する出力例:
# Gemini API の主な特徴は以下の3つです。
# 1. マルチモーダル対応: テキスト・画像・音声・動画を...
```

システムインストラクションは一度設定すれば会話全体に適用されます。チャットアプリを作るなら最初に設定しておくと、全ターンで文体が統一されます。詳細は[Gemini API システムインストラクション完全ガイド](/articles/gemini-api/system-instructions-guide)も参考にしてみてください。

## テクニック2: 言語の種類を具体的に指定する

プロンプトに「日本語で答えてください」と書くのは当然ですが、**どの種類の日本語か**まで指定すると精度が大幅に上がります。

```python
# 曖昧な指定（文体がばらつきやすい）
prompt_vague = "マーケティング戦略を教えてください。"

# 具体的な指定（品質が安定する）
prompt_specific = """
以下の条件で回答してください:
- 言語: 日本語（標準語）
- 文体: 敬体（です・ます調）
- 対象読者: 中小企業の経営者（IT知識は最低限）
- 長さ: 300〜400文字程度
- 英語・カタカナ用語を使う場合は必ず括弧内で日本語の説明を付ける

質問: マーケティング戦略を教えてください。
"""
```

実際に試すと、曖昧な指定では「マーケティングには、ターゲティング（targeting）を意識する点が肝心です。セグメンテーション（segmentation）を...」のように英語カタカナ混在の出力になりがちです。具体的に指定すると「マーケティング戦略を立てる際は、まず顧客層（どんな人に売るか）を絞り込むことが重要です」のような読みやすい日本語になります。

## テクニック3: 日本語テキストの前処理で精度を上げる

日本語テキストを入力として処理する場合（レビュー分析・要約・分類など）、前処理が品質に大きく影響します。

```python
import google.generativeai as genai
import re
import json

genai.configure(api_key="YOUR_GEMINI_API_KEY")

def preprocess_japanese_text(text: str) -> str:
    """日本語テキストの前処理"""
    # 全角スペースを半角に統一
    text = text.replace('\u3000', ' ')
    # 連続する改行を最大2つに圧縮
    text = re.sub(r'\n{3,}', '\n\n', text)
    # 全角英数字を半角に変換（APIとの一貫性のため）
    text = text.translate(str.maketrans(
        '０１２３４５６７８９ＡＢＣＤＥＦＧＨＩＪＫＬＭＮＯＰＱＲＳＴＵＶＷＸＹＺａｂｃｄｅｆｇｈｉｊｋｌｍｎｏｐｑｒｓｔｕｖｗｘｙｚ',
        '0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz'
    ))
    return text.strip()

def analyze_japanese_review(review_text: str) -> dict:
    """日本語レビューを感情分析して構造化データで返す"""
    model = genai.GenerativeModel(
        model_name="gemini-2.5-flash",
        system_instruction="あなたは日本語テキストの感情分析の専門家です。"
    )

    clean_text = preprocess_japanese_text(review_text)

    prompt = f"""
以下の日本語レビューを分析してください。
必ずJSON形式で回答し、それ以外のテキストは出力しないでください。

レビュー:
{clean_text}

出力形式:
{{
  "sentiment": "positive または negative または neutral",
  "score": 1から5の整数,
  "key_points": ["要点1", "要点2"],
  "summary_ja": "20文字以内の要約（日本語）"
}}
"""

    response = model.generate_content(prompt)

    # バックティックが混入する場合の対処
    text = response.text.strip()
    if text.startswith('```'):
        text = re.sub(r'^```(?:json)?\n?', '', text)
        text = re.sub(r'\n?```$', '', text)

    return json.loads(text)

# 使用例
review = "このアプリ、最初は使い方が難しかったですが、慣れると便利です！　ただ、動作が重いのが気になります…"
result = analyze_japanese_review(review)
print(result)
# 期待する出力:
# {
#   "sentiment": "neutral",
#   "score": 3,
#   "key_points": ["慣れると便利", "動作が重い"],
#   "summary_ja": "便利だが動作が重い"
# }
```

前処理で特に効くのが全角英数字の正規化です。ユーザーが入力した「API」（全角）と「API」（半角）が混在したまま渡すと、一貫性のない出力が返ってくることがあります。

## テクニック4: Few-shot で日本語のニュアンスを教える

日本語特有のニュアンス（婉曲表現・謙遜・二重否定）を正確に処理させたい場合は、Few-shot プロンプトが効果的です。

```python
model = genai.GenerativeModel("gemini-2.5-flash")

# 日本語の婉曲表現を正確に分類する Few-shot
prompt = """
日本語の文章が「肯定」「否定」「婉曲的な否定」のどれかを判定してください。

例1:
文章: 「このサービスはとても使いやすいです」
判定: 肯定

例2:
文章: 「このサービスは使いにくいです」
判定: 否定

例3:
文章: 「このサービスは慣れれば使えないことはないと思います」
判定: 婉曲的な否定
理由: 「慣れれば」（条件付き）「使えないことはない」（二重否定で実質否定）「と思います」（確信の薄さ）

判定する文章: 「機能がないわけではないので、工夫次第では使えるかもしれません」
判定:"""

response = model.generate_content(prompt)
print(response.text)
# 期待する出力: 婉曲的な否定
# 理由: 「ないわけではない」「かもしれません」が婉曲表現
```

日本語の二重否定と婉曲表現はゼロショットでは判定精度が落ちやすいですが、Few-shot を3〜4例入れると精度が大幅に改善します。

## テクニック5: 長文日本語の分割処理

議事録・ブログ記事・レポートなど長い日本語テキストを処理する際、そのまま渡すよりも意味のある単位で分割した方が品質が上がります。

```python
def split_japanese_text(text: str, max_chars: int = 2000) -> list:
    """
    日本語テキストを意味的な区切りで分割します。
    句点・段落区切りを優先して、文章の途中で切れないようにします。
    """
    chunks = []
    current_chunk = ""

    # 段落（2連続改行）で分割を試みる
    paragraphs = text.split('\n\n')

    for para in paragraphs:
        if len(current_chunk) + len(para) <= max_chars:
            current_chunk += para + '\n\n'
        else:
            if current_chunk:
                chunks.append(current_chunk.strip())

            # 段落が max_chars を超える場合は句点で分割
            if len(para) > max_chars:
                sentences = re.split(r'(?<=[。！？])', para)
                temp = ""
                for sent in sentences:
                    if len(temp) + len(sent) <= max_chars:
                        temp += sent
                    else:
                        if temp:
                            chunks.append(temp.strip())
                        temp = sent
                if temp:
                    chunks.append(temp.strip())
                current_chunk = ""
            else:
                current_chunk = para + '\n\n'

    if current_chunk:
        chunks.append(current_chunk.strip())

    return chunks

def summarize_long_article(article_text: str) -> str:
    """長い日本語記事を要約する（分割処理対応）"""
    model = genai.GenerativeModel(
        model_name="gemini-2.5-pro",
        system_instruction="あなたは日本語記事の要約専門家です。敬体（です・ます調）で要約してください。"
    )

    chunks = split_japanese_text(article_text, max_chars=2000)

    if len(chunks) == 1:
        # 短い記事はそのまま要約
        prompt = f"以下の記事を200文字以内で要約してください:\n\n{chunks[0]}"
        return model.generate_content(prompt).text

    # 長い記事はチャンクごとに要点を抽出してから最終要約
    key_points = []
    for i, chunk in enumerate(chunks):
        prompt = f"以下のテキスト（{i+1}/{len(chunks)}部）の要点を箇条書きで3つ以内に抽出:\n\n{chunk}"
        points = model.generate_content(prompt).text
        key_points.append(points)

    final_prompt = f"""
以下の要点リストをまとめて、記事全体の要約を200文字以内で作成してください:

{''.join(key_points)}
"""
    return model.generate_content(final_prompt).text
```

分割の際に句点（。）の後ろで切るのがポイントです。英語の `split('.')` とは違い、句点は文字として扱う必要がありますが、正規表現の後読みで対処できます。

## 日本語処理でよくある失敗と対策

開発中によく遭遇するパターンを2つ挙げます。

**「丁寧すぎる出力」問題**: ビジネス文書を生成させると「〜させていただきます」「〜となっております」のような過度に丁寧な表現が並ぶことがあります。システムインストラクションに「『させていただきます』は使わない」を明示的に入れることで防げます。

**JSON 出力にバックティックが混入する問題**: 構造化データを JSON で返させると、出力が ` ```json ` で始まることがあります。上記のコード例で示したような strip 処理を必ず入れてください。`response_mime_type="application/json"` を指定する方法もありますが、一部のモデルバージョンでは挙動が変わることがあるので注意が必要です。

## まずやること

日本語対応の改善で一番効果的なのは、**システムインストラクションへの文体指定の追加**です。既存のアプリで Gemini API を使っているなら、`system_instruction` に「敬体（です・ます調）で回答する」の1行を追加するだけで、ユーザーへの返答が読みやすくなります。

プロンプト設計の基礎からさらに学びたい方は、[Gemini プロンプトエンジニアリング完全ガイド](/articles/gemini-basics/gemini-prompt-engineering-guide)もあわせて参考にしてみてください。
