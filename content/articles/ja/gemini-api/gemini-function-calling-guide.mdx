## Function Calling とは何か — AIをリアルな世界につなぐ仕組み

Gemini API の **Function Calling**（ツール呼び出し）は、AIモデルが外部の関数やAPIと連携できるようにする強力な機能です。通常、LLMはテキストを生成するだけですが、Function Calling を使うと「天気を調べる」「データベースを検索する」「カレンダーに予定を追加する」といった実際のアクションをトリガーできるようになります。

2026年現在、Gemini 2.5 Pro・Gemini 2.5 Flash・Gemini 3 シリーズすべてで Function Calling がサポートされており、個人開発者からエンタープライズまで幅広く活用されています。

Function Calling の動作フローを簡単に説明すると次の通りです。

1. 開発者が「使える関数」の定義をAPIに渡す
2. ユーザーが「東京の天気は？」と入力する
3. Gemini が「この質問には `get_weather(city="Tokyo")` を呼ぶべき」と判断し、関数呼び出し情報を返す
4. アプリ側で実際に関数を実行し、結果をモデルに渡す
5. Gemini が結果をもとに自然な回答を生成する

この「AIが判断し、アプリが実行する」という分業こそが Function Calling の本質です。

## 最初のFunction Calling実装 — 天気取得の例

Function Calling の基本を学ぶために、天気取得のサンプルを実装してみましょう。実際の天気APIの代わりに、ダミーデータを返す関数を使います。

### Step 1: 関数の定義（ツール定義）

```python
import json
from google import genai
from google.genai import types

# 実際に呼び出される Python 関数（ダミー実装）
def get_weather(city: str) -> dict:
    """指定した都市の天気情報を返す（ダミーデータ）"""
    weather_data = {
        "Tokyo": {"condition": "晴れ", "temperature": 22, "humidity": 55},
        "Osaka": {"condition": "曇り", "temperature": 19, "humidity": 68},
        "Sapporo": {"condition": "雪", "temperature": -3, "humidity": 85},
    }
    return weather_data.get(city, {"condition": "不明", "temperature": 0, "humidity": 0})

# Gemini に渡すツール定義
weather_tool = types.Tool(
    function_declarations=[
        types.FunctionDeclaration(
            name="get_weather",
            description="指定した都市の現在の天気情報（天気の状態・気温・湿度）を取得する",
            parameters=types.Schema(
                type=types.Type.OBJECT,
                properties={
                    "city": types.Schema(
                        type=types.Type.STRING,
                        description="天気を調べたい都市名（例: Tokyo, Osaka）"
                    )
                },
                required=["city"]
            )
        )
    ]
)
```

### Step 2: モデルへのリクエストと関数呼び出しの受け取り

```python
client = genai.Client(api_key=os.environ["YOUR_GEMINI_API_KEY"])

# ユーザーの質問を送信（ツール定義を同時に渡す）
response = client.models.generate_content(
    model="gemini-2.5-flash",
    contents="東京の今日の天気を教えてください",
    config=types.GenerateContentConfig(
        tools=[weather_tool]
    )
)

# Gemini がツール呼び出しを返したか確認
for part in response.candidates[0].content.parts:
    if part.function_call:
        func_call = part.function_call
        print(f"関数名: {func_call.name}")
        print(f"引数: {dict(func_call.args)}")
        # 出力例:
        # 関数名: get_weather
        # 引数: {'city': 'Tokyo'}
```

### Step 3: 関数を実行してモデルに結果を返す

```python
# 関数呼び出し情報を取得
func_call = response.candidates[0].content.parts[0].function_call

# 実際の関数を呼び出す
if func_call.name == "get_weather":
    result = get_weather(**dict(func_call.args))
    print(f"関数の実行結果: {result}")
    # 出力例: {'condition': '晴れ', 'temperature': 22, 'humidity': 55}

# 関数の結果をモデルに渡して最終回答を生成
final_response = client.models.generate_content(
    model="gemini-2.5-flash",
    contents=[
        types.Content(role="user", parts=[
            types.Part(text="東京の今日の天気を教えてください")
        ]),
        response.candidates[0].content,  # モデルの関数呼び出し
        types.Content(role="tool", parts=[
            types.Part(
                function_response=types.FunctionResponse(
                    name="get_weather",
                    response=result
                )
            )
        ])
    ],
    config=types.GenerateContentConfig(tools=[weather_tool])
)

print(final_response.text)
# 出力例: 東京の今日の天気は晴れで、気温は22°C、湿度は55%です。過ごしやすい一日になりそうですね。
```

このフローを理解することが Function Calling の第一歩です。

## 複数の関数を同時に定義する

実用的なアプリケーションでは、複数のツールを用意しておき、Gemini に使い分けてもらう設計が効果的です。

```python
# 複数の関数定義
tools = types.Tool(
    function_declarations=[
        types.FunctionDeclaration(
            name="get_weather",
            description="都市の天気情報を取得する",
            parameters=types.Schema(
                type=types.Type.OBJECT,
                properties={
                    "city": types.Schema(type=types.Type.STRING, description="都市名")
                },
                required=["city"]
            )
        ),
        types.FunctionDeclaration(
            name="search_restaurants",
            description="指定した都市とジャンルのレストランを検索する",
            parameters=types.Schema(
                type=types.Type.OBJECT,
                properties={
                    "city": types.Schema(type=types.Type.STRING, description="都市名"),
                    "cuisine": types.Schema(type=types.Type.STRING, description="料理のジャンル（例: 和食, イタリアン）"),
                    "max_results": types.Schema(type=types.Type.INTEGER, description="最大件数（デフォルト5）")
                },
                required=["city", "cuisine"]
            )
        )
    ]
)

# 質問に応じてモデルが適切な関数を選択する
response = client.models.generate_content(
    model="gemini-2.5-flash",
    contents="東京でおすすめの寿司屋を3件教えてください",
    config=types.GenerateContentConfig(tools=[tools])
)
# → Gemini は search_restaurants(city="Tokyo", cuisine="寿司", max_results=3) を選択する
```

## parallel_function_calls — 複数の関数を同時に呼ぶ

Gemini 2.5 シリーズでは、複数の関数呼び出しを**並列**に処理できます。例えば「東京と大阪の天気を同時に調べる」ような場合です。

```python
response = client.models.generate_content(
    model="gemini-2.5-flash",
    contents="東京と大阪と札幌の天気を一度に教えてください",
    config=types.GenerateContentConfig(
        tools=[weather_tool],
        # 並列呼び出しを許可（デフォルトで有効）
        automatic_function_calling=types.AutomaticFunctionCallingConfig(
            disable=False
        )
    )
)

# 複数の function_call が返される場合がある
for part in response.candidates[0].content.parts:
    if part.function_call:
        print(f"{part.function_call.name}({dict(part.function_call.args)})")
# 出力例:
# get_weather({'city': 'Tokyo'})
# get_weather({'city': 'Osaka'})
# get_weather({'city': 'Sapporo'})
```

並列呼び出しを使えば、複数のAPIリクエストを同時に処理でき、レスポンス時間を大幅に短縮できます。

## Automatic Function Calling — 自動実行モード

Google AI Python SDK では、`automatic_function_calling` を使って、関数の実行からモデルへの結果フィードバックまでを**自動化**できます。

```python
# Python 関数をそのまま渡すだけで自動的に Function Calling が動作する
def get_stock_price(ticker: str) -> float:
    """株式ティッカーシンボルの現在価格を返す（ダミーデータ）"""
    prices = {"GOOGL": 175.30, "MSFT": 420.50, "AAPL": 195.80}
    return prices.get(ticker, 0.0)

def get_company_info(ticker: str) -> dict:
    """企業情報を返す（ダミーデータ）"""
    companies = {
        "GOOGL": {"name": "Alphabet Inc.", "sector": "Technology"},
        "MSFT": {"name": "Microsoft Corp.", "sector": "Technology"},
    }
    return companies.get(ticker, {})

# 関数をリストとして渡すだけで OK
response = client.models.generate_content(
    model="gemini-2.5-flash",
    contents="Google（GOOGL）の株価と企業情報を教えてください",
    config=types.GenerateContentConfig(
        tools=[get_stock_price, get_company_info],  # 関数オブジェクトを直接渡す
    )
)

print(response.text)
# → 自動的に get_stock_price("GOOGL") と get_company_info("GOOGL") が呼び出され、
#    その結果を統合した回答が返される
```

この自動実行モードを使うと、コードが大幅にシンプルになります。プロトタイプ開発には特に便利です。

## よくあるエラーと対処法

### エラー1: 関数の戻り値が JSON シリアライズできない

```python
# ❌ 問題: datetime オブジェクトが JSON 化できない
def get_schedule(date: str) -> dict:
    from datetime import datetime
    return {"event": "会議", "time": datetime.now()}  # datetime は NG

# ✅ 解決: 文字列に変換する
def get_schedule(date: str) -> dict:
    from datetime import datetime
    return {"event": "会議", "time": datetime.now().isoformat()}  # ISO 形式の文字列
```

### エラー2: モデルが関数呼び出しをしない（テキスト回答になる）

```python
# 関数定義の description が不明確だと Gemini が呼び出しを判断できない
# ❌ 不明確な description
types.FunctionDeclaration(
    name="get_data",
    description="データを取得する",  # 何のデータか不明
    ...
)

# ✅ 具体的な description
types.FunctionDeclaration(
    name="get_weather",
    description="指定した都市の現在の気象情報（天気・気温・湿度・風速）をリアルタイムで取得する",
    ...
)
```

### エラー3: `finish_reason` が `STOP` でなく `MAX_TOKENS` になる

Function Calling のやり取りが長くなると、コンテキスト長を超えることがあります。この場合はモデルを `gemini-2.5-pro`（200万トークンコンテキスト）に変更するか、会話履歴を適切に管理してください。

## 実践的なユースケース — チャットボット + データベース検索

最後に、より実践的なユースケースとして「社内FAQチャットボット」の設計例を示します。

```python
import sqlite3

def search_faq(keyword: str, max_results: int = 3) -> list:
    """FAQデータベースからキーワードに関連する質問・回答を検索する"""
    # 実際はデータベースを検索する（ここではダミーデータ）
    faq_data = [
        {"question": "有給休暇の申請方法は？", "answer": "社内ポータルの申請フォームから申請できます。"},
        {"question": "経費精算の締め切りは？", "answer": "毎月末日が締め切りです。"},
        {"question": "リモートワークの申請は？", "answer": "上長への事前メール報告で可能です。"},
    ]
    results = [faq for faq in faq_data if keyword in faq["question"] or keyword in faq["answer"]]
    return results[:max_results]

def get_contact(department: str) -> dict:
    """部署の連絡先を取得する"""
    contacts = {
        "人事部": {"email": "hr@example.com", "tel": "03-xxxx-0001"},
        "経理部": {"email": "accounting@example.com", "tel": "03-xxxx-0002"},
    }
    return contacts.get(department, {"message": f"{department}の情報が見つかりません"})

# チャットボット関数
def company_chatbot(user_input: str) -> str:
    response = client.models.generate_content(
        model="gemini-2.5-flash",
        contents=f"以下の質問に社内FAQ情報を使って回答してください: {user_input}",
        config=types.GenerateContentConfig(
            tools=[search_faq, get_contact],
            system_instruction="あなたは親切な社内サポートチャットボットです。FAQを検索して正確な情報を提供してください。"
        )
    )
    return response.text

# 使用例
print(company_chatbot("有給休暇を申請したいのですが"))
# → 「有給休暇の申請は社内ポータルの申請フォームから行えます。詳細は人事部（hr@example.com）にお問い合わせください。」
```

## 全体を振り返って

Gemini API の Function Calling は、AIを「会話するだけの存在」から「実際にアクションできるエージェント」へと進化させる核心的な機能です。

この記事で学んだポイントをまとめます。

- Function Calling はAIと外部ツール・APIをつなぐ仕組みで、「判断はAI・実行はアプリ」という分業が基本
- ツール定義では `description` の明確さが呼び出し精度に直結する
- 複数ツールの並列呼び出しでレスポンス高速化が可能
- Automatic Function Calling を使うと実装コードを大幅に簡潔にできる
- エラーの多くは関数の戻り値のシリアライズ問題か、description の不明確さに起因する
