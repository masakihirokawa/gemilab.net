## はじめに — Gemini API × MongoDB Atlas でできること

RAG（Retrieval-Augmented Generation）は、大規模言語モデルに「外部知識を検索して回答させる」アーキテクチャです。自社ドキュメントやナレッジベースをAIに活用させたい場合、RAGは最もコスト効率の高い手法のひとつです。

この記事では、**Gemini Embedding API** と **MongoDB Atlas Vector Search** を組み合わせて、シンプルなRAGシステムを構築する手順を解説します。MongoDB Atlasは多くの開発者にとって馴染みのあるデータベースであり、ベクター検索機能を既存のドキュメントデータベースに統合できる点が大きな魅力です。

この記事で学べること：
- MongoDB Atlas Vector Searchの仕組みと設定方法
- Gemini Embedding APIでテキストをベクトル化する方法
- Pythonを使ったセマンティック検索の実装
- ドキュメントQA（質問応答）システムの構築

対象読者は、PythonとGemini APIの基本的な知識があり、RAGシステムに初めて挑戦する方です。

## MongoDB Atlas Vector Search の仕組み

MongoDB Atlas Vector Searchは、ベクトル（数値の配列）として表現されたデータに対して **コサイン類似度** や **ユークリッド距離** で最近傍検索を行う機能です。

テキストをベクトルに変換する「埋め込み（Embedding）」処理にGemini APIを使い、そのベクトルをMongoDBに保存します。検索時は、クエリテキストを同じモデルでベクトル化し、格納済みのベクトルとの類似度を計算することで、意味的に近いドキュメントを素早く取得できます。

### 埋め込みモデルの選択

Gemini Embedding APIで利用できる主なモデルを以下にまとめます。

- **`gemini-embedding-004`**: 高精度・768次元。日英どちらにも対応。多くのユースケースで推奨
- **`text-embedding-004`**: 軽量版。コスト重視の場合に有効
- **`gemini-embedding-exp-03-07`**: 実験的な最新モデル（精度重視）

このガイドでは `gemini-embedding-004`（768次元）を使用します。

## ステップバイステップ実装

### Step 1: ドキュメントを埋め込みベクトルに変換して保存

```python
import os
import google.generativeai as genai
from pymongo import MongoClient
from dotenv import load_dotenv

load_dotenv()

# Gemini API 設定
genai.configure(api_key=os.environ["GEMINI_API_KEY"])

# MongoDB 接続
client = MongoClient(os.environ["MONGODB_URI"])
db = client["rag_demo"]
collection = db["documents"]

# サンプルドキュメント（実際は自社データに差し替えてください）
documents = [
    {
        "title": "Gemini APIの基本",
        "content": "Gemini APIはGoogleが提供するAI APIで、テキスト生成、画像理解、コード生成など多様なタスクに対応しています。"
    },
    {
        "title": "MongoDB Atlasとは",
        "content": "MongoDB Atlasはフルマネージドのクラウドデータベースサービスです。Vector Searchにより、ベクトル類似度検索が可能になります。"
    },
    {
        "title": "RAGアーキテクチャの概要",
        "content": "RAG（Retrieval-Augmented Generation）は、検索システムとLLMを組み合わせて外部知識を活用した回答を生成するアーキテクチャです。"
    },
    {
        "title": "Gemini Embedding APIの活用",
        "content": "Gemini Embedding APIはテキストを高次元ベクトルに変換します。類似したテキストは近いベクトル空間に配置されるため、セマンティック検索が実現できます。"
    },
    {
        "title": "コスト最適化のポイント",
        "content": "APIコストを抑えるには、埋め込みのキャッシュ活用、バッチ処理の利用、不要なAPIコールの削減が効果的です。"
    },
]

def get_embedding(text: str) -> list[float]:
    """Gemini APIでテキストの埋め込みベクトルを取得する"""
    result = genai.embed_content(
        model="models/gemini-embedding-004",
        content=text,
        task_type="retrieval_document"  # ドキュメント検索用タスクタイプ
    )
    return result["embedding"]

# ドキュメントに埋め込みベクトルを付与してMongoDBに保存
print("ドキュメントを埋め込み中...")
for doc in documents:
    embedding = get_embedding(doc["content"])
    doc["embedding"] = embedding
    collection.insert_one(doc)
    print(f"保存完了: {doc['title']}")

print(f"\n✅ {len(documents)}件のドキュメントを保存しました")
```

### Step 2: MongoDB Atlas に Vector Search インデックスを作成

MongoDB Atlasのコンソールで以下の操作を行います。

1. 対象のクラスター → 「Atlas Search」タブを開く
2. 「Create Search Index」→「JSON Editor」を選択
3. 以下のJSONを貼り付けてインデックスを作成する

```json
{
  "fields": [
    {
      "numDimensions": 768,
      "path": "embedding",
      "similarity": "cosine",
      "type": "vector"
    }
  ]
}
```

インデックス名は `vector_index` とします。作成完了まで数分かかる場合があります。

### Step 3: セマンティック検索の実装

```python
def semantic_search(query: str, top_k: int = 3) -> list[dict]:
    """クエリに意味的に近いドキュメントをMongoDBから検索する"""

    # クエリを埋め込みベクトルに変換（検索用タスクタイプを指定）
    query_embedding = genai.embed_content(
        model="models/gemini-embedding-004",
        content=query,
        task_type="retrieval_query"  # ← 検索クエリ用
    )["embedding"]

    # Atlas Vector Search パイプライン
    pipeline = [
        {
            "$vectorSearch": {
                "index": "vector_index",
                "path": "embedding",
                "queryVector": query_embedding,
                "numCandidates": 50,  # 候補数（top_k の 10〜20倍推奨）
                "limit": top_k
            }
        },
        {
            "$project": {
                "_id": 0,
                "title": 1,
                "content": 1,
                "score": {"$meta": "vectorSearchScore"}  # 類似度スコア
            }
        }
    ]

    results = list(collection.aggregate(pipeline))
    return results

# テスト検索
query = "AIでテキストをベクトルに変換する方法"
results = semantic_search(query)

print(f"クエリ: 「{query}」\n")
for i, doc in enumerate(results, 1):
    print(f"{i}. {doc['title']} (スコア: {doc['score']:.4f})")
    print(f"   {doc['content'][:60]}...\n")
```

**期待する出力:**
```

   Gemini APIはGoogleが提供するAI APIで、テキスト生成、...

3. RAGアーキテクチャの概要 (スコア: 0.8754)
   RAG（Retrieval-Augmented Generation）は、検索システムと...
```

### Step 4: ドキュメントQAシステムの完成

```python
def answer_question(question: str) -> str:
    """質問に対してRAGで回答を生成する"""

    # 1. 関連ドキュメントを検索
    relevant_docs = semantic_search(question, top_k=3)

    if not relevant_docs:
        return "関連するドキュメントが見つかりませんでした。"

    # 2. コンテキストを構築
    context = "\n\n".join([
        f"【{doc['title']}】\n{doc['content']}"
        for doc in relevant_docs
    ])

    # 3. Gemini APIで回答を生成
    model = genai.GenerativeModel("gemini-2.5-flash")
    prompt = f"""以下のドキュメントを参考に、質問に答えてください。
ドキュメントに記載のない情報は「情報がありません」と答えてください。

=== 参考ドキュメント ===
{context}

=== 質問 ===
{question}

=== 回答 ==="""

    response = model.generate_content(prompt)
    return response.text

# 動作確認
question = "Gemini Embedding APIは何次元のベクトルを生成しますか？"
answer = answer_question(question)
print(f"Q: {question}")
print(f"A: {answer}")
```

## よくあるエラーと対処法

### エラー 1: `MongoServerError: PlanExecutor error: $vectorSearch`

Vector Searchインデックスが未作成または作成中の場合に発生します。Atlas コンソールでインデックスのステータスが「Active」になっていることを確認してください。

### エラー 2: `google.api_core.exceptions.InvalidArgument: 400`

`task_type` の指定が間違っている可能性があります。ドキュメント保存時は `retrieval_document`、検索クエリ時は `retrieval_query` を指定してください。

### エラー 3: 埋め込みの次元数が合わない

インデックス作成時の `numDimensions` とモデルの出力次元が一致していることを確認してください。`gemini-embedding-004` は768次元、`text-embedding-004` は768次元です（モデルにより異なります）。

## 応用・発展的な活用法

### メタデータフィルタリングとの組み合わせ

MongoDB Atlas Vector Searchはベクトル検索とメタデータフィルターを組み合わせられます。たとえば「特定のカテゴリのみ」「一定期間内のドキュメントのみ」を検索対象にすることが可能です。

```python
# カテゴリフィルターを追加した検索
pipeline = [
    {
        "$vectorSearch": {
            "index": "vector_index",
            "path": "embedding",
            "queryVector": query_embedding,
            "numCandidates": 50,
            "limit": 5,
            "filter": {"category": "技術ドキュメント"}  # メタデータフィルター
        }
    }
]
```

### バッチ埋め込みでコスト最適化

大量のドキュメントを処理する場合、APIコールを最小限に抑えることが重要です。Gemini Embedding APIは1回のリクエストで複数テキストをまとめて処理できます。

```python
def batch_embed(texts: list[str]) -> list[list[float]]:
    """複数テキストをまとめて埋め込み処理（コスト効率化）"""
    result = genai.embed_content(
        model="models/gemini-embedding-004",
        content=texts,  # リストで渡すとバッチ処理
        task_type="retrieval_document"
    )
    return result["embedding"]
```

さらに本格的なRAGシステムの構築を目指す方には、ハイブリッド検索（キーワード検索＋ベクター検索の組み合わせ）を解説した[Gemini APIとQdrantで構築するハイブリッドRAG本番システム](/articles/gemini-api/gemini-api-qdrant-hybrid-rag-production-system)も参考になります。

## FAQ

**Q1. MongoDB Atlasの無料プランでVector Searchは使えますか？**

はい、M0（無料）クラスターでもVector Searchを使用できます。ただし、インデックスサイズや処理件数に制限があります。本番環境ではM10以上の有料プランをご検討ください。

**Q2. Gemini Embedding APIの料金はどのくらいかかりますか？**

2026年4月時点では、`gemini-embedding-004` は無料枠内（1日あたり一定件数まで）で使用できます。超過した場合の料金は [Gemini APIの料金・課金完全ガイド2026](/articles/gemini-api/gemini-api-pricing-billing-complete-guide-2026) を参照してください。

**Q3. 日本語のドキュメントでも精度よく検索できますか？**

`gemini-embedding-004` は多言語対応しており、日本語テキストでも高い精度でベクトル化できます。ただし、同一言語内のクエリとドキュメントの方が精度が出やすいため、日本語ドキュメントには日本語クエリで検索することを推奨します。

**Q4. ChromaDBやPineconeとの違いは何ですか？**

ChromaDBやPineconeは専用のベクターデータベースです。MongoDB Atlasの強みは「既存のドキュメントデータベースとしての機能」と「ベクター検索」を1つのサービスで管理できる点です。すでにMongoDBを使っているプロジェクトでは移行コストが低く済みます。他のベクターDBとの詳細な比較は [Gemini Embedding API × ChromaDB で社内ドキュメント検索システムを構築する実践ガイド](/articles/gemini-api/gemini-embedding-chroma-document-search-system) もご参考ください。
