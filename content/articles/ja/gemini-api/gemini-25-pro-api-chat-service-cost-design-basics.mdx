個人でも有料チャットサービスを作れるようになりました。Gemini 2.5 Pro の登場で API 単価は下がり、継続的な改善も進んでいます。

ただし「安い」と「採算が取れる」は別です。利用者が増えるほど API 費用も増え、気づいたら月間赤字になる状況もあります。

このパターンは何度も見てきました。コスト設計は事業を始める前、つまり「今」決めるべきです。

2014年からアプリ事業を続けている個人開発者の経験から、この問題に普段から向き合ってきた立場で、要点を整理します。

アーティスト（国際芸術賞17冠）と個人開発者という2つの軸を行き来する中で、テクニカルな判断は「直感」と「実測値」の両方で検証する習慣がつきました。
## Gemini 2.5 Pro API の実際の単価

公式ページを見ると「Input は 1M トークンあたり $1.50」と書かれていますが、実際に何にいくらかかるのか、数字で整理しましょう。

| トークン種別 | 単価（1M トークンあたり） | 1,000トークンあたり |
|---|---|---|
| Input | $1.50 | $0.0015 |
| Output | $6.00 | $0.006 |
| Context Caching Hit | $0.375 | $0.000375 |
| Context Caching Write | $2.25 | $0.00225 |

一見すると「安い」に見えます。でも、典型的なチャット 1 リクエストを計算してみます。

**例：ユーザーが長めのシステムプロンプト + 会話履歴 + 質問を送信**

- システムプロンプト: 1,000 tokens
- 会話履歴（直近 5 やり取り）: 2,000 tokens
- ユーザーの質問: 500 tokens
- **Input 合計**: 3,500 tokens → **$0.00525**

- API からの応答: 800 tokens
- **Output 合計**: 800 tokens → **$0.0048**

**このリクエスト 1 件あたりの原価：$0.01025（約 1.5 円）**

一日 100 リクエストなら 150 円、月 3,000 リクエストなら 3,075 円。1 人のユーザーが月 30 回使うなら 50 円未満です。

ここで重要なのは「会話が続くと Input トークンが増える」という点です。

## コスト削減のキーポイント：Context Caching

個人の有料チャットサービスで最初に導入すべきは「**Context Caching**」です。

Context Caching は、頻繁に参照するシステムプロンプトや固定の参考資料をキャッシュし、2 回目以降の呼び出しでは無視されるようにします。

**実例：AI コーチング SaaS の場合**

- ユーザー共通のシステムプロンプト（フレームワーク、制約事項）: 2,000 tokens
- このプロンプトはキャッシュする（Write: 2,000 × $0.00225 = $0.0045）
- 以降のリクエストでこのプロンプトを使うたびに：Cache Hit: 2,000 × $0.000375 = $0.00075

**40 回使うと：**
- キャッシュなし：2,000 × 40 × $0.0015 = $1.20
- キャッシュあり：Write $0.0045 + Hit × 39 = $0.0045 + $0.02925 = $0.03375
- **削減額：83.9% OFF（月 100 ユーザーなら月 $108 から $3.40 に）**

ただし Context Caching には制約があります：

1. キャッシュは 5 分間有効（実装時はセッション単位で管理）
2. API 呼び出しごとに「どのコンテンツをキャッシュするか」を明示的に指定
3. 長めの固定テキスト（1,024 tokens 以上推奨）でないと効果が薄い

## Batch API で月間 40% の原価削減

コスト削減の次のステップは「**Batch API**」です。

Batch API は複数のリクエストを事前にまとめて送信し、Google のサーバーが「暇な時間帯」に処理するサービスです。通常リクエストより 50% 安いです。

ただし「リアルタイム」ではなく「最大 24 時間の遅延」があります。

**向く用途：** ユーザーが就寝中に実行する分析、毎朝の定期タスク処理、ユーザーが「バッチで後で結果をもらう」のを許容する機能

**向かない用途：** チャットの直接回答、ユーザーがリアルタイムで結果を待つケース

**実装例：AI 日記分析サービス**

ユーザーが毎日書いた日記をアップロード。夜間に Batch API で分析。朝 6 時に結果を メール配信。

```javascript
// Batch API リクエスト例
const batchRequest = {
  requests: [
    {
      custom_id: "user-123-diary-001",
      params: {
        model: "gemini-2.5-pro",
        systemInstruction: "You are an empathetic diary analyzer",
        contents: [{
          role: "user",
          parts: [{ text: diaryContent }]
        }]
      }
    },
    // ... 複数のリクエスト
  ]
};

await batchService.processBatch(batchRequest, { priority: "BATCH" });
```

**月 1,000 ユーザー × 30 日 = 30,000 リクエストを処理：**
- 通常 API：30,000 × $0.01 = $300
- Batch API：30,000 × $0.005 = $150
- **削減：50% ($150/月)**

## 複数の料金体系を使い分けるコスト モデル

実際の SaaS では「複数の機能」を組み合わせます。例えば：

**Free プラン：** Batch API のみ（日記分析のみ）→ 月額 API 費用: $20

**Pro プラン（¥580/月）：** 
- リアルタイムチャット：通常 API（Context Caching 有効化）
- 定期分析：Batch API
- 月額 API 費用: $40
- **粗利：¥580 - $40 = ¥500以上**

**Premium プラン（¥2,480/月）：**
- チャット無制限 + リアルタイム機能フル装備
- カスタム分析エンジン
- 月額 API 費用: $120
- **粗利：¥2,480 - $120 = ¥2,300以上**

100 ユーザーが均等に分布すれば：
- **月間 API 費用：($20 × 33 + $40 × 33 + $120 × 34) = $4,500**
- **月間売上（3 ヶ月無料考慮）：($0 × 33 + $580 × 33 + $2,480 × 34) ≈ $102,560**
- **月間粗利率：55% 以上**

## 隠れたコストを見落とさない

API 単価の他に、実装段階で気づくコストがあります。

**1. トークン オーバー ラン**

API が返したトークン数は実際の計算と異なることがあります（特に日本語）。余裕を見て計算してください。

**2. エラー リトライ**

ネットワークエラーやレート制限で失敗したリクエストを再実行します。これは追加の API 呼び出しになります。

リトライは「Exponential backoff」で対応し、失敗パターンを監視してください。

**3. モデル バージョン アップ**

Gemini 3 が登場すれば、単価が変わる可能性があります。今のコスト計算は「2025年の前提」です。

## ここまでのまとめ

個人で有料チャット SaaS を作る際の**コスト設計の土台は**：

1. **Context Caching を最初から設計に含める** → 80% 以上の削減余地
2. **Batch API を固定機能として用意する** → 50% のコスト削減
3. **料金体系は「API 月額費用 × 3 〜 4」を目安に** → 粗利 60% 確保
4. **監視ダッシュボードを最初から用意** → 月額費用の推移を毎日チェック

このコスト構造が確実なら、サービスの競争力は他の機能・UX で決まります。
