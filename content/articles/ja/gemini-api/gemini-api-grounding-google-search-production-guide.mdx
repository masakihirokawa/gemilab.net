## はじめに — Grounding with Google Search とは何か

Gemini API の **Grounding with Google Search** は、LLM の回答をリアルタイムのWeb検索結果と紐付ける機能です。通常のプロンプト応答では学習データのカットオフ以降の情報を知ることができませんが、この機能を有効にすることで、**Gemini が Google 検索エンジンを自動的に使用し、最新の情報を含めた回答を生成**するようになります。

たとえば「今日の株価は？」「最新の Gemini モデルのリリース情報は？」といった質問にも、Grounding を使えば Gemini が自動でWeb検索を行い、信頼性の高い情報ソースをもとに回答を生成します。さらに、回答の根拠となったWebページのURLが `grounding_metadata` として返却されるため、**情報源の透明性を担保したアプリ開発**が可能になります。

この記事では、Grounding with Google Search の基本的な仕組みから、Python・JavaScriptでの実装方法、そしてプロダクション環境での運用ノウハウまでを体系的に解説します。

---

## Grounding が必要なユースケース

Grounding with Google Search が特に有効なのは、以下のようなシーンです。

- **ニュース・時事情報の回答**: 最新ニュースや出来事についての質問に、最新情報を含めて答えたい場合
- **価格・在庫・天気などのリアルタイムデータ**: 常に変化する情報を扱うアプリ
- **事実確認（ファクトチェック）**: LLM のハルシネーションを抑制し、信頼性の高い回答を生成したい場合
- **競合調査・市場分析ツール**: 最新の企業情報・製品情報を収集したい場合
- **カスタマーサポートBot**: 最新のサービス情報・FAQ をWeb上から引き出して回答する場合

Grounding を使わない場合と比較すると、特に**時事情報・最新動向を扱うユースケース**での回答品質が格段に向上します。

一方で、クローズドなドメイン（自社の内部ドキュメントに基づく回答）が必要な場合は、[Gemini API の RAG パイプライン実装](/articles/gemini-api/gemini-flash-rag-pipeline)と組み合わせる方法が適しています。ユースケースに応じて選択肢を使い分けることが重要です。

## Python 実装 — Grounding with Google Search の基本

### シンプルな実装例

```python
import os
from google import genai
from google.genai import types

# APIキーの設定
client = genai.Client(api_key=os.environ["YOUR_GEMINI_API_KEY"])

# Grounding with Google Search を有効にして質問
response = client.models.generate_content(
    model="gemini-2.0-flash",
    contents="2026年4月の最新の Gemini AI に関するニュースを教えてください",
    config=types.GenerateContentConfig(
        tools=[types.Tool(google_search=types.GoogleSearch())]
    ),
)

# 回答テキストの表示
print("=== 回答 ===")
print(response.text)

# Grounding メタデータ（情報ソース）の表示
if response.candidates[0].grounding_metadata:
    metadata = response.candidates[0].grounding_metadata
    print("\n=== 情報ソース ===")
    for chunk in metadata.grounding_chunks:
        if chunk.web:
            print(f"- {chunk.web.title}: {chunk.web.uri}")
```

このコードを実行すると、Gemini がGoogle検索を自動で実行し、最新のWeb情報を参照した回答が生成されます。`grounding_metadata` には参照したWebページのタイトルとURLが含まれているため、情報ソースを回答と一緒にユーザーに提示できます。

### 検索クエリの制御

Grounding では、モデルが自動生成する検索クエリを確認することもできます。

```python
response = client.models.generate_content(
    model="gemini-2.0-flash",
    contents="Gemini 3.1 Pro の最新機能は何ですか？",
    config=types.GenerateContentConfig(
        tools=[types.Tool(google_search=types.GoogleSearch())]
    ),
)

metadata = response.candidates[0].grounding_metadata

# モデルが実行した検索クエリを確認
if metadata and metadata.web_search_queries:
    print("実行された検索クエリ:")
    for query in metadata.web_search_queries:
        print(f"  - {query}")
```

## JavaScript/Node.js 実装

```javascript
import { GoogleGenAI } from "@google/generative-ai";

const genai = new GoogleGenAI({ apiKey: process.env.YOUR_GEMINI_API_KEY });

async function searchWithGrounding(question) {
  const response = await genai.models.generateContent({
    model: "gemini-2.0-flash",
    contents: question,
    config: {
      tools: [{ googleSearch: {} }],
    },
  });

  const candidate = response.candidates[0];
  const answer = candidate.content.parts[0].text;

  // 情報ソースの抽出
  const sources = [];
  if (candidate.groundingMetadata?.groundingChunks) {
    for (const chunk of candidate.groundingMetadata.groundingChunks) {
      if (chunk.web) {
        sources.push({
          title: chunk.web.title,
          url: chunk.web.uri,
        });
      }
    }
  }

  return { answer, sources };
}

// 使用例
const result = await searchWithGrounding(
  "2026年に注目すべきAIトレンドを教えてください"
);
console.log("回答:", result.answer);
console.log("情報ソース:", result.sources);
```

## 本番アプリへの組み込み — FastAPI 実装例

実際のプロダクション環境で Grounding を活用する場合の実装例を紹介します。

```python
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel
from google import genai
from google.genai import types
import os

app = FastAPI()
client = genai.Client(api_key=os.environ["YOUR_GEMINI_API_KEY"])

class SearchRequest(BaseModel):
    question: str
    use_grounding: bool = True

class SearchResponse(BaseModel):
    answer: str
    sources: list[dict]
    search_queries: list[str]

@app.post("/search", response_model=SearchResponse)
async def search_with_ai(request: SearchRequest):
    try:
        config = types.GenerateContentConfig()
        if request.use_grounding:
            config = types.GenerateContentConfig(
                tools=[types.Tool(google_search=types.GoogleSearch())]
            )

        response = client.models.generate_content(
            model="gemini-2.0-flash",
            contents=request.question,
            config=config,
        )

        candidate = response.candidates[0]
        metadata = candidate.grounding_metadata

        sources = []
        search_queries = []

        if metadata:
            # 情報ソースの収集
            if metadata.grounding_chunks:
                for chunk in metadata.grounding_chunks:
                    if chunk.web:
                        sources.append({
                            "title": chunk.web.title,
                            "url": chunk.web.uri,
                        })

            # 検索クエリの収集
            if metadata.web_search_queries:
                search_queries = list(metadata.web_search_queries)

        return SearchResponse(
            answer=response.text,
            sources=sources,
            search_queries=search_queries,
        )

    except Exception as e:
        raise HTTPException(status_code=500, detail=str(e))
```

## Grounding のプロダクション運用で押さえるべきポイント

### コストと使用制限

Grounding with Google Search は通常のテキスト生成に加えて**検索実行のコストが発生**します。1リクエストに複数の検索クエリが実行される場合もあるため、使用量をモニタリングすることが重要です。

開発・テスト環境では `dynamic_retrieval_config` を使って、検索の閾値（threshold）を調整できます。

```python
response = client.models.generate_content(
    model="gemini-2.0-flash",
    contents="今日の東京の天気は？",
    config=types.GenerateContentConfig(
        tools=[types.Tool(
            google_search=types.GoogleSearch(),
        )],
    ),
)
```

### エラーハンドリング

検索サービスが一時的に利用不可になることを考慮し、フォールバック処理を実装しましょう。

```python
import time

def search_with_retry(client, question: str, max_retries: int = 3) -> dict:
    """リトライ付きのGrounding検索"""
    for attempt in range(max_retries):
        try:
            response = client.models.generate_content(
                model="gemini-2.0-flash",
                contents=question,
                config=types.GenerateContentConfig(
                    tools=[types.Tool(google_search=types.GoogleSearch())]
                ),
            )
            return {
                "success": True,
                "answer": response.text,
                "metadata": response.candidates[0].grounding_metadata,
            }
        except Exception as e:
            if attempt < max_retries - 1:
                wait_time = 2 ** attempt  # 指数バックオフ
                print(f"リトライ {attempt + 1}/{max_retries} — {wait_time}秒後に再試行")
                time.sleep(wait_time)
            else:
                # フォールバック: Groundingなしで通常応答
                print("Grounding失敗。通常モードで応答します。")
                response = client.models.generate_content(
                    model="gemini-2.0-flash",
                    contents=question,
                )
                return {
                    "success": False,
                    "answer": response.text,
                    "metadata": None,
                }
```

### レート制限への対応

大量のリクエストを処理する場合は、[Gemini API のレート制限・クォータ管理ガイド](/articles/gemini-api/gemini-api-rate-limiting-quota-management)を参照し、適切なキューイングと速度制御を実装してください。

## Grounding メタデータを活用した UI/UX の設計

Grounding のレスポンスには `grounding_supports` という情報も含まれており、**回答テキストの特定の箇所がどのソースに基づいているか**をマッピングできます。これを活用すると、Webページのような「[1][2]」形式の引用リンクを回答内に表示できます。

```python
def format_answer_with_citations(response) -> str:
    """引用付きの回答テキストを生成する"""
    candidate = response.candidates[0]
    metadata = candidate.grounding_metadata

    if not metadata or not metadata.grounding_chunks:
        return response.text

    # ソースのインデックスを作成
    sources = {}
    for i, chunk in enumerate(metadata.grounding_chunks, 1):
        if chunk.web:
            sources[i] = {"title": chunk.web.title, "url": chunk.web.uri}

    answer = response.text

    # 末尾に参考文献リストを追加
    if sources:
        answer += "\n\n**参考文献**\n"
        for idx, source in sources.items():
            answer += f"[{idx}] [{source['title']}]({source['url']})\n"

    return answer
```

## よくある質問（FAQ）

**Q1. Grounding with Google Search は Gemini のどのモデルで使えますか？**

Gemini 2.0 Flash 以降のモデルで利用可能です。`gemini-2.0-flash`、`gemini-2.5-pro`、`gemini-2.5-flash` などに対応しています。旧モデル（`gemini-1.0-pro` 等）では利用できません。

**Q2. 検索結果のソースを信頼してよいですか？**

Grounding は Google の検索インフラを利用しているため、一般的に品質の高いWebページが参照されます。ただし、すべての情報が正確であることを保証するものではありません。重要な情報は必ず情報源のURLを確認し、ユーザーにも参照元を明示することを推奨します。

**Q3. Grounding を使うと API のコストは増えますか？**

はい、Grounding を有効にすると検索実行に追加のコストが発生します。具体的な料金は [Gemini API の料金ページ](https://ai.google.dev/pricing) で確認してください。コスト最適化の観点から、常に Grounding を有効にするのではなく、最新情報が必要な質問にのみ適用する設計を推奨します。

**Q4. System Instructions と組み合わせて使えますか？**

はい、Grounding と System Instructions は組み合わせて使用できます。たとえば、検索結果を特定のフォーマットで整理するよう System Instructions で指示しながら、Grounding で最新情報を取得することが可能です。

**Q5. 検索結果の件数や対象ドメインを絞り込めますか？**

現時点では、特定ドメインへの絞り込みはサポートされていません。自社ドメインのコンテンツに限定したい場合は、Grounding ではなくFile APIやVector DBを使ったRAGアプローチが適しています。

## まとめ

Gemini API の **Grounding with Google Search** は、AIアプリに「最新情報へのアクセス」という強力な能力を付与します。特にニュース・時事情報・価格情報など、時間とともに変化するデータを扱うアプリには不可欠な機能です。

今回紹介した実装のポイントをまとめます。

- **Python SDK**: `types.Tool(google_search=types.GoogleSearch())` で即座に有効化できる

- **エラーハンドリング**: 指数バックオフのリトライとフォールバック実装を忘れずに
- **コスト管理**: 必要なリクエストにのみ Grounding を適用し、不要なコストを抑制する
