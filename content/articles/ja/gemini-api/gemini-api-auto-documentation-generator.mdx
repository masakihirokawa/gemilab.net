「コードは書いた。ドキュメントは……また今度にしよう」

こう思いながら開発を続けた結果、半年後に自分のコードを読み返して途方に暮れた経験は、多くの開発者に共通するのではないでしょうか。私自身、アプリ開発の現場でこの"また今度"の積み重ねに何度も後悔してきました。

Gemini APIは、長いコンテキストウィンドウと高いコード理解力を持ちます。この特性はドキュメント自動生成と非常に相性が良く、実際に業務で活用してみると「こんなに楽になるのか」と驚かされました。今回はPythonスクリプトを中心に、README・JSDocコメント・OpenAPI仕様書を実際に生成する方法をご紹介します。

Gemini API を実プロダクトで運用してきた知見から、この問題に普段から向き合ってきた立場で、要点を整理します。

## なぜ Gemini API がドキュメント生成に向いているのか

ドキュメント生成の難しさは、「コード全体の文脈を把握したうえで説明する」という点にあります。関数単体ではなく、プロジェクト全体のアーキテクチャを理解して、読み手にわかりやすく要約する必要があります。

Gemini 2.5 Pro のコンテキストウィンドウは最大100万トークンに達します。中規模のWebアプリのソースコード全体を一度に読み込ませて、俯瞰的なREADMEを生成することが可能です。他のモデルでは分割処理が必要だった作業も、Geminiなら一度のリクエストで完結するケースがほとんどです。

もう一点、コードの「意図」を推論する能力が高いことも大きな強みです。変数名や関数シグネチャから文脈を推測し、開発者が書いた処理の目的をかなりの精度で読み取ります。人間が書いたコメントに近いドキュメントを生成してくれます。

## セットアップ

まず必要なパッケージをインストールします。

```bash

```

APIキーは [Google AI Studio](https://aistudio.google.com/) から取得してください。環境変数として設定するのが安全です。

## README を自動生成する

最もよく使うユースケースから始めます。プロジェクトディレクトリを渡すと、README.md のドラフトを生成するスクリプトです。

```python
import google.generativeai as genai
import os
from pathlib import Path

def collect_source_files(project_dir: str, extensions: list[str]) -> str:
    """指定ディレクトリのソースコードを収集して1つの文字列にまとめる"""
    collected = []
    for ext in extensions:
        for path in Path(project_dir).rglob(f"*{ext}"):
            # node_modules や .git などのビルド成果物を除外
            if any(skip in str(path) for skip in [
                "node_modules", ".git", "__pycache__", "dist", ".next", "build"
            ]):
                continue
            try:
                content = path.read_text(encoding="utf-8")
                collected.append(f"\n\n=== {path} ===\n{content}")
            except Exception:
                continue
    return "\n".join(collected)

def generate_readme(project_dir: str) -> str:
    """プロジェクトの README.md を生成する"""
    genai.configure(api_key=os.environ["GEMINI_API_KEY"])
    model = genai.GenerativeModel("gemini-2.5-pro")

    source_code = collect_source_files(
        project_dir,
        extensions=[".py", ".ts", ".tsx", ".js", ".go", ".rs"]
    )

    prompt = f"""以下のプロジェクトのソースコードを分析し、GitHub の README.md を日本語で作成してください。

含めるべき内容:
- プロジェクトの概要（1〜2文）
- 主な機能（箇条書きで3〜5件）
- インストール手順（実際のコマンド付き）
- 使い方の例（コードスニペット付き）
- 技術スタック

ソースコード:
{source_code[:300000]}
"""

    response = model.generate_content(prompt)
    return response.text

if __name__ == "__main__":
    import sys
    project_dir = sys.argv[1] if len(sys.argv) > 1 else "."
    readme = generate_readme(project_dir)
    print(readme)
```

実行例：

```bash
python generate_readme.py /path/to/your/project
```

期待する出力（抜粋）：

```markdown
# my-api-service

FastAPIベースの軽量REST APIサービスです。PostgreSQLと連携し、JWT認証に対応しています。

## 主な機能
- ユーザー登録・ログイン（JWT）
- CRUD操作（SQLAlchemy ORM）
- 非同期処理対応（asyncpg）

## インストール手順
pip install -r requirements.txt
...
```

このスクリプトで重要なのは `node_modules` や `.git` などのビルド成果物を除外する処理です。これらを含めると不要なトークンを消費するだけでなく、生成品質が下がります。また `source_code[:300000]` で文字数を制限していますが、実際には300,000文字でも多くのプロジェクトには十分です。

## JSDoc コメントを自動追加する

既存のPythonファイルにdocstringを補完する、あるいはTypeScriptファイルにJSDocコメントを追加するスクリプトです。コードの本体を変えずにドキュメントだけを追記します。

```python
import google.generativeai as genai
import os

def add_docstrings(source_code: str, language: str = "python") -> str:
    """ソースコードにdocstring / JSDocコメントを追加する"""
    genai.configure(api_key=os.environ["GEMINI_API_KEY"])
    model = genai.GenerativeModel("gemini-2.5-pro")

    lang_instruction = {
        "python": "Python の docstring（Google スタイル）を追加",
        "typescript": "TypeScript の JSDoc コメントを追加",
        "javascript": "JavaScript の JSDoc コメントを追加",
    }.get(language, "適切なドキュメントコメントを追加")

    prompt = f"""以下のコードに{lang_instruction}してください。
コード本体は一切変更せず、コメントのみ追加した完全なコードを返してください。

コード:
```{language}
{source_code}
```"""

    response = model.generate_content(prompt)
    return response.text

# 使用例
if __name__ == "__main__":
    sample_code = """
def calculate_discount(price: float, rate: float) -> float:
    if rate < 0 or rate > 1:
        raise ValueError("rate must be between 0 and 1")
    return price * (1 - rate)
"""
    result = add_docstrings(sample_code, language="python")
    print(result)
```

実行結果（Geminiが自動補完）：

```python
def calculate_discount(price: float, rate: float) -> float:
    """割引後の価格を計算する。

    Args:
        price: 元の価格（0以上の値）。
        rate: 割引率（0〜1の範囲）。例: 0.2 は 20% 割引。

    Returns:
        割引後の価格（float）。

    Raises:
        ValueError: rate が 0〜1 の範囲外の場合。
    """
    if rate < 0 or rate > 1:
        raise ValueError("rate must be between 0 and 1")
    return price * (1 - rate)
```

このくらいの品質のdocstringを一瞬で生成してくれます。手動で書いてもこのレベルを出すには案外時間がかかるので、初期ドラフトとして非常に使いやすいです。

## OpenAPI 仕様書を自動生成する

FastAPIやExpressで書いたAPIコードから、OpenAPI（Swagger）形式の仕様書をJSON出力するスクリプトです。Structured Outputを活用して、確実にJSON形式で受け取ります。

```python
import google.generativeai as genai
import os
import json

def generate_openapi_spec(api_code: str) -> dict:
    """APIコードからOpenAPI 3.0仕様書を生成する"""
    genai.configure(api_key=os.environ["GEMINI_API_KEY"])
    model = genai.GenerativeModel(
        "gemini-2.5-pro",
        generation_config={"response_mime_type": "application/json"}
    )

    prompt = f"""以下のAPIコードを分析し、OpenAPI 3.0形式の仕様書をJSONで出力してください。
エンドポイント、パラメータ、リクエスト/レスポンスのスキーマを正確に記述してください。
存在しないエンドポイントは含めないでください。

APIコード:
{api_code}"""

    response = model.generate_content(prompt)

    try:
        return json.loads(response.text)
    except json.JSONDecodeError as e:
        raise ValueError(f"JSONパースに失敗しました: {e}\n生レスポンス: {response.text[:500]}")

# 使用例
if __name__ == "__main__":
    api_code = """
@app.get("/users/{user_id}")
async def get_user(user_id: int, include_posts: bool = False):
    user = db.get_user(user_id)
    if not user:
        raise HTTPException(status_code=404, detail="User not found")
    return user
"""
    spec = generate_openapi_spec(api_code)
    print(json.dumps(spec, ensure_ascii=False, indent=2))
```

`response_mime_type: "application/json"` を指定することで、JSONをそのまま受け取れます。これはGemini APIのStructured Output機能で、マークダウンのコードブロックで囲まれた文字列として返ってくるケースをゼロにできます。JSONパース失敗のリスクを大幅に下げられるため、本番環境での利用にも安心です。

## よくある落とし穴と対処法

実際に業務で使ってみると、いくつかのつまずきポイントがありました。

**生成されたdocstringが実装と合っていない**

Geminiは見た目の命名から推測してコメントを書くことがあります。コード本体のロジックとdocstringが微妙にズレていても平然と返してくる場合があるため、レビューは必須です。特に `Args` の型情報と `Returns` の説明が実際の動作と一致するかは必ず確認してください。

**大規模コードでコンテキストが足りない**

100,000行を超えるモノリシックなリポジトリでは、全ファイルを一度に送ることが難しくなります。ファイルごと、あるいはモジュール単位に分割して送る設計にするのがおすすめです。共通のシステムプロンプト部分のキャッシュには Context Caching 機能が役立ちます。詳しくは[Gemini API Context Caching でコストを削減する](/articles/gemini-api/gemini-api-context-caching-cost-optimization)をご覧ください。

**日本語と英語が混在した出力になる**

プロンプトに「日本語で出力してください」と明示しても、コード内のコメントや変数名が英語だと出力が混在することがあります。System Instructionsでモデル全体の言語を固定するか、出力後に言語チェックを入れると安定します。

**ファイルが多いとAPIレートリミットに引っかかる**

ディレクトリ全体を順番に処理する場合、短時間に大量のリクエストを送るとレートリミットに達することがあります。`time.sleep(1)` を挟む、あるいは非同期処理で並列数を制限するなどの対策が必要です。
