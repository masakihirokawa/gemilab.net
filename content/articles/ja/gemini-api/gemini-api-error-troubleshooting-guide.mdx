Gemini API を使った開発を進めていると、思わぬエラーに出くわすことがあります。「なぜこのエラーが出ているのかわからない」「ドキュメントを見ても英語で難しい」と感じている方も多いのではないでしょうか。

この記事では、Gemini API でよく遭遇するエラーコードを整理し、それぞれの原因と対処法をできるだけわかりやすくお伝えします。同じ問題で詰まっている方のお力になれれば嬉しいです。

## エラーコードの基本的な読み方

HTTP ステータスコードには大きく分けて以下のカテゴリがあります。

- **4xx（クライアントエラー）**: リクエスト側に問題がある
- **5xx（サーバーエラー）**: Googleのサーバー側で問題が発生している

Gemini API に限らず、4xx は「自分のコードや設定を直す必要がある」、5xx は「しばらく待てば改善することが多い」と覚えておくと整理しやすいです。

## 400 Bad Request — リクエストの形式が間違っている

**よくある原因**:
- リクエストの JSON が不正な形式になっている
- 必須パラメータが欠けている
- サポートされていないモデル名を指定した
- 入力テキストが長すぎてコンテキスト上限を超えた

**エラーメッセージの例**:
```
400 INVALID_ARGUMENT: Request contains an invalid argument
400 Bad Request: Model not found
```

**対処法**:

まずリクエストの JSON を確認します。

```python
import google.generativeai as genai

genai.configure(api_key="YOUR_GEMINI_API_KEY")

# ❌ よくある間違い：モデル名のスペルミス
model = genai.GenerativeModel('gemini-pro')  # 古い名前

# ✅ 正しいモデル名（2026年現在）
model = genai.GenerativeModel('gemini-2.5-pro')
```

入力テキストが長い場合は、テキストを分割して送るか、コンテキストウィンドウが大きいモデル（Gemini 2.5 Pro は 100 万トークン対応）を選択してください。

**モデル名の確認方法**:
```python
# 利用可能なモデル一覧を取得
for m in genai.list_models():
    print(m.name)
```

## 401 Unauthorized / 403 Forbidden — 認証・権限エラー

**よくある原因**:
- APIキーが間違っている（スペルミス・コピーミス）
- APIキーが無効化されている
- そのAPIキーでアクセスできないリソースにアクセスしようとしている
- APIの有効化を忘れている

**エラーメッセージの例**:
```
401 API_KEY_INVALID: API key not valid
403 PERMISSION_DENIED: Caller does not have permission
```

**対処法**:

1. **APIキーの確認**: [Google AI Studio](https://aistudio.google.com) でAPIキーを再確認し、コピーし直します

```python
import os

# 環境変数から読み込む（ハードコードは避ける）
api_key = os.environ.get("GEMINI_API_KEY")
if not api_key:
    raise ValueError("GEMINI_API_KEY が設定されていません")

genai.configure(api_key=api_key)
```

2. **APIの有効化確認**: Google Cloud Console で「Generative Language API」が有効になっているか確認します

3. **新しいAPIキーの発行**: 疑わしい場合は既存のキーを無効化し、新しいキーを発行します

## 429 Too Many Requests — レート制限エラー

Gemini API を使っていて最もよく遭遇するエラーのひとつです。

**よくある原因**:
- 短時間に大量のリクエストを送りすぎた（RPM制限）
- 1日あたりのリクエスト数上限を超えた（無料枠）
- 一度に送るトークン数が多すぎた（TPM制限）

**エラーメッセージの例**:
```
429 RESOURCE_EXHAUSTED: Resource has been exhausted (e.g. check quota usage)
```

**対処法**:

最も確実なのは、**指数バックオフ（Exponential Backoff）** を実装することです。

```python
import time
import google.generativeai as genai
from google.api_core.exceptions import ResourceExhausted

def generate_with_retry(model, prompt, max_retries=5):
    for attempt in range(max_retries):
        try:
            response = model.generate_content(prompt)
            return response
        except ResourceExhausted as e:
            if attempt == max_retries - 1:
                raise
            wait_time = (2 ** attempt) + 1  # 2, 3, 5, 9, 17秒
            print(f"レート制限に達しました。{wait_time}秒後に再試行します...")
            time.sleep(wait_time)
```

**無料枠の制限を超えた場合**:
- [Google AI Studio のクォータページ](https://aistudio.google.com) で使用状況を確認
- Google Cloud で課金を有効にすると上限が大幅に緩和されます
- 無料枠でも1分あたりのリクエスト数（RPM）を守ることが重要です

## 500 Internal Server Error / 503 Service Unavailable — サーバー側エラー

**原因**: Google のサーバー側で問題が発生しています。

**対処法**:
- **しばらく待つ**: 多くの場合、数分〜数十分で自然に解決します
- **Google のステータスページを確認**: [status.cloud.google.com](https://status.cloud.google.com) でサービス障害が発生していないか確認できます
- **リトライを実装する**: 自動的に再試行するコードを書いておくと安定します

```python
from google.api_core import retry

# 自動リトライ付きでリクエストを送る
@retry.Retry(predicate=retry.if_exception_type(Exception))
def stable_generate(model, prompt):
    return model.generate_content(prompt)
```

## コンテンツフィルタリングエラー

**症状**: リクエストを送っても空のレスポンスが返ってくる、または安全フィルタによってブロックされたメッセージが出る。

**原因**: 入力または出力がGoogleの安全ポリシーに抵触したと判定された。

**確認方法**:

```python
response = model.generate_content(prompt)

# 安全フィルタの判定を確認
print(response.prompt_feedback)
for candidate in response.candidates:
    print(candidate.finish_reason)  # SAFETY の場合はフィルタで停止
    print(candidate.safety_ratings)
```

**対処法**:
- プロンプトの内容を見直し、誤解を招く表現を避ける
- 医療・法律・暴力などのセンシティブなテーマは慎重に扱う
- Safety Settings でフィルタの閾値を調整できますが、業務で使用する場合はGoogleの利用規約を必ず確認してください

## まとめ：エラー別クイックリファレンス

| エラーコード | 主な原因 | 最初にすること |
|---|---|---|
| 400 | リクエスト形式ミス、モデル名誤り | リクエストJSONとモデル名を確認 |
| 401/403 | APIキー無効、権限不足 | APIキーを再発行、APIを有効化 |
| 429 | レート制限超過 | 指数バックオフで再試行 |
| 500/503 | Googleサーバー障害 | しばらく待ち、ステータス確認 |

Gemini API の開発でつまずくことは珍しくありません。エラーメッセージをよく読んで原因を特定し、一つひとつ丁寧に対処していくことが大切です。この記事が皆さんの開発の助けになれば、とても嬉しいです。
