Gemini APIを使い始めたばかりの開発者にとって、エラーメッセージは理解しづらいことがあります。このガイドでは、Gemini APIで最も一般的なエラーの原因と、それぞれの解決策を丁寧に説明します。

## Gemini APIでよくあるエラーの種類

Gemini APIを利用していると、以下のようなエラーが発生することがあります。

- 400 Bad Request — リクエストの形式が不正
- 401/403 Unauthorized/Forbidden — 認証エラー
- 429 Too Many Requests — レート制限に達した
- 500/503 Internal Server Error — Google側の一時的な障害

これらのエラーは、原因がわかれば簡単に解決できるものばかりです。それぞれの対処法を見ていきましょう。

## 400 Bad Request — リクエスト形式・モデル名の誤り

400 Bad Requestエラーは、サーバーがリクエストを理解できない場合に発生します。主な原因は3つです。

### 1. モデル名の誤り

最も多いのはモデル名を間違えるケースです。Gemini APIで利用できるモデルは限られています。

```python
import google.generativeai as genai

genai.configure(api_key="YOUR_GEMINI_API_KEY")

# ❌ 間違い：モデル名が存在しない
model = genai.GenerativeModel("gemini-invalid-model")

# ✅ 正解：実在するモデル名を使う
model = genai.GenerativeModel("gemini-2.0-flash")
response = model.generate_content("こんにちは")
print(response.text)
```

最新で利用可能なモデル一覧は、[Google AI Studioの「モデルの選択」ページ](https://aistudio.google.com/)で確認できます。よく使われるモデルは以下の通りです：

- `gemini-2.0-flash` — 高速・軽量
- `gemini-2.0-pro` — より高精度
- `gemini-2.0-flash-thinking-exp-01-21` — 思考拡張モデル

### 2. JSONフォーマットが不正

TypeScript/JavaScriptでAPIを呼び出す場合、リクエストボディのJSON形式が正しくないと400エラーが発生します。

```typescript
import { GoogleGenerativeAI } from "@google/generative-ai";

const genAI = new GoogleGenerativeAI("YOUR_GEMINI_API_KEY");
const model = genAI.getGenerativeModel({ model: "gemini-2.0-flash" });

// ✅ 正しいリクエスト形式
const response = await model.generateContent({
  contents: [
    {
      role: "user",
      parts: [{ text: "こんにちは" }],
    },
  ],
});
```

特に`contents`、`parts`、`role`などの必須フィールドが欠落していないか確認してください。

### 3. 入力長が上限を超えている

テキスト入力が非常に長い場合、リクエストが400エラーで拒否されることがあります。Gemini APIのコンテキストウィンドウ（入力可能な最大文字数）は、モデルごとに異なります。

- `gemini-2.0-flash` — 最大100万トークン

もし大量のテキストを処理する必要があれば、テキストを分割して複数回に分けてリクエストを送るようにしてください。

## 401/403 認証エラー — APIキーの設定方法

401（Unauthorized）または403（Forbidden）エラーは、APIキーが設定されていないか、権限がない場合に発生します。

### Google AI Studioを使う場合

Google AI Studioはもっとも簡単にGemini APIを試す方法です。

1. [Google AI Studio](https://aistudio.google.com/)にアクセス
2. 左側の「API キー」メニューから「新しいAPIキーを作成」をクリック
3. 表示されたAPIキーをコピー
4. コード内で以下のように設定：

```python
import google.generativeai as genai

# 方法1: 直接設定（開発用のみ推奨）
genai.configure(api_key="YOUR_GEMINI_API_KEY")

# 方法2: 環境変数から読み込み（本番環境推奨）
import os
api_key = os.getenv("GEMINI_API_KEY")
genai.configure(api_key=api_key)
```

環境変数に設定する場合は、Linux/macOSでは以下のコマンドを実行します：

```bash
export GEMINI_API_KEY="your_actual_api_key"
```

### Vertex AIを使う場合

Google Cloudプロジェクトを使用する場合は、Vertex AIを使う必要があります。Google AI Studioとは異なるセットアップが必要です。

```python
import google.generativeai as genai

# GCPの認証を自動取得
credentials, project_id = default()
genai.configure(credentials=credentials)
```

Vertex AIを初めて使う場合は、GCPプロジェクトでVertex AI APIを有効にする必要があります。詳しくは[Vertex AIのドキュメント](https://cloud.google.com/vertex-ai)をご参照ください。

## 429 Too Many Requests — レート制限の理解と回避策

429エラーは、短時間に大量のリクエストを送った場合に発生します。Gemini APIには、無料枠と有料枠でそれぞれ異なるレート制限があります。

### 無料枠のレート制限

Google AI Studioで無料でGemini APIを使う場合、以下の制限があります：

- 1分あたり最大60リクエスト
- 1日あたりの総リクエスト数に上限あり

### 有料枠のレート制限

Google Cloudで有料契約した場合：

- 1分あたり最大360リクエスト（通常）
- 利用プランやモデルによって異なる

### 指数バックオフでの対処

429エラーが発生した場合、すぐにリトライするのではなく、待機時間を段階的に増やして再試行する「指数バックオフ」を使うのが定石です。

```python
import time
import google.generativeai as genai

genai.configure(api_key="YOUR_GEMINI_API_KEY")
model = genai.GenerativeModel("gemini-2.0-flash")

def generate_with_retry(prompt, max_retries=5):
    """指数バックオフを使ったリトライロジック"""
    for attempt in range(max_retries):
        try:
            response = model.generate_content(prompt)
            return response.text
        except Exception as e:
            if "429" in str(e):
                # 待機時間: 1秒、2秒、4秒、8秒、16秒...
                wait_time = 2 ** attempt
                print(f"レート制限に達しました。{wait_time}秒待機します...")
                time.sleep(wait_time)
            else:
                raise

# 使用例
result = generate_with_retry("日本の首都は？")
print(result)
```

TypeScript/JavaScriptの場合：

```typescript
import { GoogleGenerativeAI } from "@google/generative-ai";

const genAI = new GoogleGenerativeAI("YOUR_GEMINI_API_KEY");
const model = genAI.getGenerativeModel({ model: "gemini-2.0-flash" });

async function generateWithRetry(prompt: string, maxRetries = 5): Promise<string> {
  for (let attempt = 0; attempt < maxRetries; attempt++) {
    try {
      const response = await model.generateContent(prompt);
      return response.response.text();
    } catch (error) {
      if (error instanceof Error && error.message.includes("429")) {
        const waitTime = Math.pow(2, attempt) * 1000; // ミリ秒に変換
        console.log(`レート制限に達しました。${waitTime / 1000}秒待機します...`);
        await new Promise((resolve) => setTimeout(resolve, waitTime));
      } else {
        throw error;
      }
    }
  }
  throw new Error("最大リトライ回数に達しました");
}

// 使用例
const result = await generateWithRetry("日本の首都は？");
console.log(result);
```

## 500/503 サーバーエラー — Google側の一時的な障害

500（Internal Server Error）または503（Service Unavailable）エラーは、Google側のシステムに一時的な問題が発生している場合に起こります。これはあなたのコードやAPIキーの設定に問題があるわけではありません。

### 対応方法

1. 少し待機してリトライする（指数バックオフを使用）
2. Google Cloud Status Dashboard（[status.cloud.google.com](https://status.cloud.google.com/)）でGemini APIのステータスを確認
3. 問題が継続する場合は、Google Cloud Supportに連絡する

```python
import time

def generate_with_500_retry(prompt, max_retries=3):
    """500/503エラーに対応したリトライロジック"""
    for attempt in range(max_retries):
        try:
            response = model.generate_content(prompt)
            return response.text
        except Exception as e:
            error_code = str(e)
            if "500" in error_code or "503" in error_code:
                wait_time = 5 * (attempt + 1)  # 5秒、10秒、15秒
                print(f"サーバーエラーが発生しました。{wait_time}秒後に再試行します...")
                time.sleep(wait_time)
            else:
                raise
```

## 取り組みの背景

Gemini API を使ったアプリケーション開発で、突然 `429 Too Many Requests` エラーが発生して、サービスが停止してしまった。そのような経験はありませんか？

このエラーは、API のクォータ制限に達したときに返されるもので、一見すると単純に見えますが、実は複数の原因が隠れていることが多いです。無料枠から有料へのアップグレード、リトライロジックの実装、Google Cloud Console での監視設定など、正しく対処しないと何度も同じ問題に直面することになります。

Gemini API の 429 エラーの原因特定方法から、根本的な解決策まで、実践的なトラブルシューティング手順を順を追って整理していきます。

## 429 エラーの正体 — RESOURCE_EXHAUSTED との違い

### 429 Too Many Requests エラーが発生するパターン

Gemini API から 429 エラーが返される場合、以下の3つが主な原因です。

- **RPM（Requests Per Minute）制限**: 1分あたりのリクエスト数上限を超過
- **RPD（Requests Per Day）制限**: 1日あたりのリクエスト数上限を超過
- **TPM（Tokens Per Minute）制限**: 1分あたりの処理トークン数上限を超過

無料枠ではこれらの制限が非常に厳しく設定されており、開発中には問題がなくても、アプリがスケールすると急に出現します。

### RESOURCE_EXHAUSTED エラーとの違い

```json
// 429 エラーのレスポンス例
{
  "error": {
    "code": 429,
    "message": "Resource has been exhausted (e.g. check quota).",
    "status": "RESOURCE_EXHAUSTED"
  }
}
```

実は、Google API の内部では `RESOURCE_EXHAUSTED` が詳細なステータスコードで、HTTP の 429 はこれの上位レベルの表現です。つまり、エラーメッセージに "Resource has been exhausted" と書かれていたら、それはクォータ制限に達したことを意味しています。

一方、`INVALID_ARGUMENT` や `PERMISSION_DENIED` といったエラーコードは、リクエスト形式の誤りや認証の問題なので、クォータの問題ではありません。

## 無料枠 vs 有料プランの制限値比較

### 無料枠（Free Tier）のクォータ

無料枠は開発やテスト用に設計されており、本番環境での使用を想定していません。

| 制限項目 | 制限値 | 単位 |
| --- | --- | --- |
| RPM（Requests Per Minute） | 60 | リクエスト/分 |
| RPD（Requests Per Day） | 1,500 | リクエスト/日 |
| TPM（Tokens Per Minute） | 10,000 | トークン/分 |
| 同時接続数 | 2 | セッション |

この制限値は、**個別ユーザーごと**ではなく、**プロジェクト全体** で共有されます。つまり、複数のアプリケーションやスクリプトが同じプロジェクトで API を呼び出していると、制限に達しやすくなります。

### 有料プラン（Pay-as-you-go）のクォータ

有料プランに切り替えると、制限値が大幅に引き上げられます。

| 制限項目 | 制限値 | 単位 |
| --- | --- | --- |
| RPM | 1,000～10,000 | リクエスト/分（モデル・リージョンで異なる） |
| RPD | 制限なし | - |
| TPM | 100,000～1,000,000 | トークン/分（購入量に応じて） |
| 同時接続数 | 100 | セッション |

さらに、Google Cloud Console で **Spend Limit（使用金額の上限）** を設定することで、予期しない請求を防ぐことができます。

## 429 エラーが発生したときの応急対処

### すぐに実装できる3つのテクニック

**1. 指数バックオフによるリトライ**

```python
import time
import anthropic
from google.api_core import gapic_v1

def call_gemini_with_backoff(prompt, max_retries=5):
    client = anthropic.Anthropic(api_key="YOUR_GEMINI_API_KEY")

    for attempt in range(max_retries):
        try:
            response = client.messages.create(
                model="gemini-2.0-flash",
                max_tokens=1024,
                messages=[
                    {"role": "user", "content": prompt}
                ]
            )
            return response.content[0].text
        except Exception as e:
            if "429" in str(e) or "RESOURCE_EXHAUSTED" in str(e):
                # 指数バックオフ: 2^attempt 秒待機
                wait_time = 2 ** attempt
                print(f"Rate limited. Waiting {wait_time} seconds...")
                time.sleep(wait_time)
            else:
                raise

    raise Exception("Max retries exceeded")

# 使用例
result = call_gemini_with_backoff("Tell me about quantum computing")
print(result)
```

**2. リクエストキューイング**

バースト的なリクエストが発生する場合は、キューイングが効果的です。

```python
import queue
import threading
import time

class GeminiQueue:
    def __init__(self, max_rpm=60):
        self.queue = queue.Queue()
        self.max_rpm = max_rpm
        self.request_times = []
        self.lock = threading.Lock()

    def add_request(self, prompt):
        self.queue.put(prompt)

    def process_requests(self):
        while True:
            prompt = self.queue.get()
            self._rate_limit_check()
            # API呼び出し処理
            self.queue.task_done()

    def _rate_limit_check(self):
        with self.lock:
            now = time.time()
            # 1分以内のリクエスト記録を保持
            self.request_times = [t for t in self.request_times if now - t < 60]

            if len(self.request_times) >= self.max_rpm:
                # 最も古いリクエストから60秒経つまで待機
                wait_time = 60 - (now - self.request_times[0])
                time.sleep(wait_time)

            self.request_times.append(now)

# 使用例
gq = GeminiQueue(max_rpm=50)
for i in range(100):
    gq.add_request(f"Question {i}")
```

**3. 無料枠での同時実行の制御**

無料枠の同時接続数制限（2セッション）を回避するため、シリアル処理を強制します。

```python
import asyncio
import aiohttp

async def process_sequentially(prompts):
    """同時接続数を1に制限してリクエスト処理"""
    semaphore = asyncio.Semaphore(1)

    async def fetch_with_semaphore(prompt):
        async with semaphore:
            # API呼び出し
            await asyncio.sleep(1)  # レート制限回避用の遅延
            return f"Response to: {prompt}"

    tasks = [fetch_with_semaphore(p) for p in prompts]
    return await asyncio.gather(*tasks)

# 使用例
prompts = ["How to learn AI?", "What is machine learning?"]
results = asyncio.run(process_sequentially(prompts))
```

## 本番環境での長期的な対策

### 有料プランの選択基準

無料枠で 429 エラーが頻発するようになった場合は、有料プランへのアップグレードを検討すべきです。

- **小規模アプリ（月 < 1万リクエスト）**: 無料枠 + Spend Limit で対応
- **中規模アプリ（月 1万～100万リクエスト）**: Pay-as-you-go（従量課金）推奨
- **大規模アプリ（月 100万+ リクエスト）**: Volume Pricing の相談を Google Cloud Sales に

### Spend Limit の設定

予期しない高額請求を防ぐため、必ず設定します。

1. Google Cloud Console → 「請求」を開く
2. 「予算」→「新しい予算を作成」をクリック
3. 「月額上限」を設定（例：¥10,000）
4. アラート通知を「予算の100%で通知」に設定

この設定により、月額の上限に達するとすべての API 呼び出しが自動的に停止されます。

### クォータ監視の自動化

Google Cloud の Monitoring（旧 Stackdriver）を使い、クォータ使用率をダッシュボード化します。

```yaml
# Google Cloud Monitoring アラート例
displayName: Gemini API 429 Rate Limit Alert
conditions:
  - displayName: RPM Usage > 80%
    conditionThreshold:
      filter: |
        resource.type="api"
        AND metric.type="serviceruntime.googleapis.com/api/consumer/quota_used_count"
        AND resource.service="generativelanguage.googleapis.com"
      threshold_value: 0.8
      comparison: COMPARISON_GT
```

## エラー1: INVALID_API_KEY — APIキーの設定ミス

最初の壁はここです。エラーメッセージは以下のように出ます。

```
google.api_core.exceptions.PermissionDenied: 403 API key not valid.
Please pass a valid API key.
[reason: "API_KEY_INVALID"]
```

原因として多いのは3つです。

**① 環境変数が設定されていない**

```python
import google.generativeai as genai
import os

# ❌ ハードコーディングは危険（絶対にやらない）
# genai.configure(api_key="AIzaSy...")

# ✅ 環境変数から読み込む
api_key = os.environ.get("GOOGLE_API_KEY")
if not api_key:
    raise EnvironmentError("GOOGLE_API_KEY 環境変数が設定されていません")

genai.configure(api_key=api_key)
```

ターミナルで `export GOOGLE_API_KEY="YOUR_API_KEY"` を実行してから再度試してみてください。`.env`ファイルを使う場合は `python-dotenv` を使うと便利です。

**② APIキーを有効化していない**

[Google AI Studio](https://aistudio.google.com) でAPIキーを発行しても、Google Cloud ConsoleでGenerative Language APIを有効にしていないと使えないことがあります。特にVertex AI経由で利用する場合は、プロジェクト設定の確認が必要です。

**③ APIキーに余分なスペースや改行が混入している**

コピー＆ペーストで貼り付けたAPIキーに末尾の改行やスペースが混入していることがあります。

```python
api_key = os.environ.get("GOOGLE_API_KEY", "").strip()  # strip() で確実に除去
```

## エラー2: RESOURCE_EXHAUSTED — レート制限に引っかかった

```
google.api_core.exceptions.ResourceExhausted: 429 Resource has been exhausted
(e.g. check quota usage or reduce request rate).
```

Gemini APIには無料枠と有料枠でレート制限が異なります。無料プラン（Gemini 2.0 Flash）は1分あたり15リクエストまでです。ループ処理で連続リクエストを送るとすぐに引っかかります。

```python
import google.generativeai as genai
import time
from google.api_core import exceptions

def call_gemini_with_retry(model, prompt: str, max_retries: int = 5) -> str:
    """
    レート制限エラーを指数バックオフでリトライする。
    """
    for attempt in range(max_retries):
        try:
            response = model.generate_content(prompt)
            return response.text
        
        except exceptions.ResourceExhausted as e:
            if attempt == max_retries - 1:
                raise
            wait = 2 ** attempt  # 1秒 → 2秒 → 4秒 → 8秒 → 16秒
            print(f"レート制限: {wait}秒後にリトライ (試行 {attempt + 1}/{max_retries})")
            time.sleep(wait)
        
        except exceptions.GoogleAPICallError as e:
            print(f"APIエラー: {e}")
            raise

genai.configure(api_key=os.environ["GOOGLE_API_KEY"])
model = genai.GenerativeModel("gemini-2.0-flash")

# 複数アイテムの処理
items = ["トピック1", "トピック2", "トピック3"]
for item in items:
    result = call_gemini_with_retry(model, f"{item}について説明してください")
    print(result[:100])
    time.sleep(1)  # リクエスト間に最低1秒のインターバルを入れる
```

## エラー4: INVALID_ARGUMENT — コンテキスト長の超過

```
google.api_core.exceptions.InvalidArgument: 400 Request payload size exceeds the limit
```

または、画像を含むマルチモーダルリクエストで:

```
Invalid request: the total input token count exceeds the model's limit
```

入力テキストや画像が多すぎてモデルのコンテキストウィンドウを超えた場合に発生します。

```python
import google.generativeai as genai
import os

genai.configure(api_key=os.environ["GOOGLE_API_KEY"])
model = genai.GenerativeModel("gemini-2.0-flash")

def safe_generate(prompt: str, max_chars: int = 30000) -> str:
    """
    入力テキストを安全な長さに切り詰めてから送信する。
    """
    if len(prompt) > max_chars:
        print(f"⚠️ プロンプトを {max_chars} 文字に切り詰めます（元: {len(prompt)} 文字）")
        # 末尾を切らずに中間を削除する方が文脈が保たれることが多い
        half = max_chars // 2
        prompt = prompt[:half] + "\n...[中略]...\n" + prompt[-half:]
    
    try:
        response = model.generate_content(prompt)
        return response.text
    except Exception as e:
        print(f"エラー: {e}")
        raise

# 使用量確認（トークン数を事前に確認する方法）
def count_tokens(prompt: str) -> int:
    response = model.count_tokens(prompt)
    return response.total_tokens

tokens = count_tokens("ここに長いテキスト")
print(f"このプロンプトのトークン数: {tokens}")
```

長いドキュメントを処理する場合は、Gemini 2.5 ProまたはFlashの100万トークンコンテキストを活用するか、チャンク分割処理を検討してください。

## エラー5: 応答が空またはブロックされた

```python
response = model.generate_content("...")
print(response.text)  # AttributeError: 'NoneType' object has no attribute 'text'
```

または:

```
google.generativeai.types.StopCandidateException:
finish_reason: SAFETY
safety_ratings { ... probability: HIGH }
```

Geminiには安全フィルターがあり、特定のコンテンツはブロックされます。また、`finish_reason`が`RECITATION`（著作権のある文章の再生成検出）の場合もあります。

```python
def safe_get_text(response) -> str | None:
    """
    レスポンスを安全に取得する。ブロックや空応答を適切に処理する。
    """
    # candidates が空の場合（完全ブロック）
    if not response.candidates:
        print(f"応答がブロックされました: {response.prompt_feedback}")
        return None
    
    candidate = response.candidates[0]
    
    # finish_reason を確認
    finish_reason = candidate.finish_reason
    
    if finish_reason.name == "SAFETY":
        print(f"安全フィルターでブロック: {candidate.safety_ratings}")
        return None
    
    if finish_reason.name == "RECITATION":
        print("著作権コンテンツ検出によりブロック")
        return None
    
    if finish_reason.name == "MAX_TOKENS":
        print("⚠️ max_output_tokens に達しました。値を増やしてください。")
        # 部分的なテキストは返せる
    
    # テキストを安全に取得
    try:
        return candidate.content.parts[0].text
    except (IndexError, AttributeError):
        return None

# 使用例
response = model.generate_content("質問テキスト")
text = safe_get_text(response)
if text:
    print(text)
else:
    print("テキストを取得できませんでした。プロンプトを変更して試してください。")
```

セーフティフィルターの感度は`generation_config`の`safety_settings`で調整できますが、デフォルト設定で解決できることがほとんどです。プロンプトをより中立的な表現に変えてみてください。

## まずやるべきこと

エラーが出たときの切り分け手順として、以下の順番で確認してみてください。

1. `GOOGLE_API_KEY`が正しく設定されているか（`echo $GOOGLE_API_KEY`で確認）
2. モデル名が公式ドキュメントと一致しているか
3. `response.candidates`が空でないか確認してからテキスト取得する
4. レート制限には指数バックオフを実装する
