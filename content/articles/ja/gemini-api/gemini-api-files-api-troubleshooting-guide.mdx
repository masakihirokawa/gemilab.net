画像・PDF・動画を Gemini に渡して処理させようとして、なぜかエラーになる——そんな経験はありませんか。Files API は Gemini のマルチモーダル処理の入口ですが、初めて使うとつまずきやすいポイントがいくつかあります。

ここでは、Files API の実装でよく遭遇するエラーを原因から整理し、コードと一緒に解決策を紹介します。「動いたと思ったら途中で止まる」「PROCESSING 状態がずっと続く」「API キーは正しいのにファイルが読み込めない」といった症状をお持ちの方に向けた内容です。

2014年からアプリ事業を続けている個人開発者の経験から、この問題に普段から向き合ってきた立場で、要点を整理します。

## Files API の基本構造と失敗しやすいポイント

Files API は、サイズの大きなファイルや動画・音声を Gemini に送る際に使います。直接 `inline_data` で送ることができるファイル（20MB 未満の小さな画像など）とは異なり、一度 Files API にアップロードしてから URI を Gemini に渡す二段階の仕組みです。

この「二段階」という点が、多くのエラーの原因になっています。アップロード完了 ≠ 処理可能、という状態の概念を最初に押さえておくと、その後のエラーが格段に読み解きやすくなります。

```python
import google.generativeai as genai
import time

genai.configure(api_key="YOUR_API_KEY")

# Step 1: Files API にアップロード
uploaded_file = genai.upload_file(path="document.pdf", mime_type="application/pdf")
print(f"アップロード完了: {uploaded_file.name}, 状態: {uploaded_file.state.name}")

# Step 2: ACTIVE になるまで待機（※これを省略すると失敗する）
while uploaded_file.state.name == "PROCESSING":
    time.sleep(2)
    uploaded_file = genai.get_file(uploaded_file.name)
    print(f"状態確認中: {uploaded_file.state.name}")

if uploaded_file.state.name == "FAILED":
    raise ValueError(f"ファイル処理失敗: {uploaded_file.name}")

# Step 3: Gemini に渡す
model = genai.GenerativeModel("gemini-2.5-pro")
response = model.generate_content([
    uploaded_file,
    "このPDFの内容を要約してください"
])
print(response.text)
```

待機ループを入れずにすぐ `generate_content` を呼ぶと、`PROCESSING` 状態のファイルを参照してエラーになります。これが最初の壁です。

## PROCESSING 状態が解消されない・ループが終わらない

動画や長い音声ファイルを扱うと、`PROCESSING` 状態が数分続くことがあります。ポーリング間隔が短すぎると API を叩きすぎてレートリミットに引っかかることもあるため、バックオフを組み込んだ待機を推奨します。

```python
import google.generativeai as genai
import time

def wait_for_file_active(file, max_wait_seconds=300):
    """ファイルが ACTIVE になるまで待機する（タイムアウト付き）"""
    waited = 0
    interval = 5  # 最初は5秒間隔

    while file.state.name == "PROCESSING":
        if waited >= max_wait_seconds:
            raise TimeoutError(
                f"ファイル処理がタイムアウト: {file.name}（{max_wait_seconds}秒経過）"
            )
        print(f"処理中... {waited}秒経過（{file.state.name}）")
        time.sleep(interval)
        waited += interval
        interval = min(interval * 1.5, 30)  # 最大30秒まで延長
        file = genai.get_file(file.name)

    if file.state.name \!= "ACTIVE":
        raise ValueError(f"ファイルが ACTIVE になりませんでした: {file.state.name}")

    return file

# 使い方
uploaded = genai.upload_file("large_video.mp4", mime_type="video/mp4")
active_file = wait_for_file_active(uploaded, max_wait_seconds=600)  # 10分まで待機
```

`max_wait_seconds` は動画の長さと解像度に応じて調整してください。1時間以上の動画では 10〜15 分の待機が必要になることもあります。

## MIME タイプの指定ミスによるエラー

Files API でよく起きるもう一つの問題が、MIME タイプの不一致です。`mime_type` を省略すると自動判定が働きますが、拡張子が正しくないファイルや、珍しい形式では誤判定されることがあります。

```python
# ❌ よくある間違い: MIME タイプ未指定（誤判定のリスク）
uploaded = genai.upload_file("scan.pdf")

# ✅ 正しい: MIME タイプを明示する
uploaded = genai.upload_file("scan.pdf", mime_type="application/pdf")
```

Gemini Files API がサポートする主な MIME タイプは以下のとおりです。

- **画像**: `image/jpeg`, `image/png`, `image/webp`, `image/heic`, `image/heif`
- **動画**: `video/mp4`, `video/mpeg`, `video/mov`, `video/webm`
- **音声**: `audio/mp3`, `audio/wav`, `audio/aac`, `audio/flac`
- **文書**: `application/pdf`
- **テキスト**: `text/plain`, `text/html`, `text/csv`, `text/xml`

Word（`.docx`）や Excel（`.xlsx`）は直接サポートされていない点に注意が必要です。これらを処理したい場合は PDF に変換してからアップロードするか、テキストを抽出してインラインで渡す方法を取ることが現実的です。

## ファイルサイズ超過エラー（20MB / 2GB 上限）

Files API には二つのサイズ制限があります。

- **inline_data（直接送信）の上限**: 20MB
- **Files API アップロードの上限**: 2GB

20MB 以下の小さなファイルは `inline_data` で直接送れますが、それを超えるファイルには Files API が必要です。2GB を超えるファイルは分割か圧縮が必要になります。

```python
import os
import google.generativeai as genai

def upload_file_smart(path: str, mime_type: str):
    """ファイルサイズに応じてアップロード方法を自動切り替え"""
    file_size = os.path.getsize(path)
    limit_inline = 20 * 1024 * 1024  # 20MB
    limit_files_api = 2 * 1024 * 1024 * 1024  # 2GB

    if file_size > limit_files_api:
        raise ValueError(
            f"ファイルが 2GB を超えています（{file_size / 1e9:.1f} GB）。"
            "動画は圧縮または分割してください。"
        )

    if file_size > limit_inline:
        # Files API を使う
        print(f"Files API でアップロード（{file_size / 1e6:.1f} MB）")
        uploaded = genai.upload_file(path, mime_type=mime_type)
        return ("file", uploaded)
    else:
        # インラインで送る
        print(f"インラインで送信（{file_size / 1e6:.1f} MB）")
        with open(path, "rb") as f:
            data = f.read()
        return ("inline", {"mime_type": mime_type, "data": data})
```

## ファイル期限切れによる NOT_FOUND エラー

Files API でアップロードしたファイルの有効期限は **48時間** です。この制限を意識せずに実装すると、翌々日に実行したときだけエラーが出るという、再現性の低いバグになりがちです。

```
google.api_core.exceptions.NotFound: 404 File not found: files/xxxxxxxx
```

このエラーが出たときは、ファイルが期限切れになっている可能性が高いです。長期間同じファイルを参照する設計では、再アップロードのロジックを組み込む必要があります。

```python
import google.generativeai as genai
from datetime import datetime, timezone

def get_or_reupload_file(file_name: str, local_path: str, mime_type: str):
    """ファイルが有効なら再利用、期限切れなら再アップロード"""
    try:
        file = genai.get_file(file_name)
        if file.state.name == "ACTIVE":
            print(f"既存ファイルを再利用: {file_name}")
            return file
    except Exception:
        pass  # ファイルが存在しないか期限切れ

    print(f"ファイルを再アップロード: {local_path}")
    return genai.upload_file(local_path, mime_type=mime_type)
```

バッチ処理など、同じファイルを繰り返し参照する場合は、`file_name` をデータベースに保存しておき、取得失敗時に再アップロードするパターンが堅牢です。

## 動画処理のコスト爆発を防ぐ

動画ファイルを Files API で処理すると、動画の長さに応じてトークンが消費されます。1秒あたり 258 トークンが目安で、1時間の動画では約 93 万トークンになります。意図せず長時間の動画を繰り返し処理していると、コストが急増します。

実務では以下の点を確認してください。

- **不要なファイルは都度削除する**: `genai.delete_file(file.name)` で即時削除が可能です
- **同じファイルは再アップロードしない**: `file.name`（`files/xxxxxx` 形式）を保存しておき、有効期間内は使い回します
- **動画はフレームサンプリングを検討する**: 必ずしも全フレームが必要でない場合、代表フレームを静止画として抽出して送る方法がコスト効率の良い選択です

```python
# 使い終わったファイルは明示的に削除
def safe_delete_file(file):
    try:
        genai.delete_file(file.name)
        print(f"ファイル削除完了: {file.name}")
    except Exception as e:
        print(f"削除失敗（無視）: {e}")
```

## エラーコード別の対処早見表

Files API で発生するエラーは、HTTPステータスコードと `reason` フィールドで原因を特定できます。

- **400 INVALID_ARGUMENT**: MIME タイプ不一致、またはサポートされていない形式。`mime_type` を正しく指定してください
- **403 PERMISSION_DENIED**: API キーに Files API の権限がないか、無効なキーを使用しています。Google AI Studio でキーを確認してください
- **404 NOT_FOUND**: ファイルが存在しないか 48 時間の期限切れです。再アップロードが必要です
- **413 REQUEST_TOO_LARGE**: インライン送信で 20MB を超えています。Files API を使ってください
- **429 RESOURCE_EXHAUSTED**: レートリミット超過です。指数バックオフで再試行してください
- **503 SERVICE_UNAVAILABLE**: 一時的なサービス障害です。数分後に再試行してください

Files API のトラブルシューティングで詰まったときは、[Gemini API 公式ドキュメントの File prompting recipes](https://ai.google.dev/gemini-api/docs/file-prompting-strategies) も参考になります。
