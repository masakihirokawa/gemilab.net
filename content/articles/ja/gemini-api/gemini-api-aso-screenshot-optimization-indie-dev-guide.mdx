App Store のスクリーンショットは、アプリのコンバージョン率に直結する最重要要素のひとつです。ところが、個人開発者がスクリーンショットの品質を客観的に評価しようとすると、手段が限られています。デザイナーに依頼する予算はない。A/Bテストのデータが貯まるまで時間がかかる。競合分析は目視で時間を食う。

Gemini の Vision API はこの問題を変えます。スクリーンショット画像を直接入力として受け取り、マーケティング的な観点からの評価・改善提案・競合との比較を、コードで自動化できるようになります。

この記事では、実際に動作する4つのツールを実装します。

画像ファイルのBase64変換ヘルパー:

```python
def load_image_as_part(image_path: str) -> types.Part:
    """
    ローカル画像ファイルを Gemini API の Part オブジェクトに変換する。
    JPEG・PNG・WebP に対応。
    """
    path = Path(image_path)
    suffix = path.suffix.lower()
    
    mime_map = {
        ".jpg": "image/jpeg",
        ".jpeg": "image/jpeg",
        ".png": "image/png",
        ".webp": "image/webp",
    }
    mime_type = mime_map.get(suffix, "image/jpeg")
    
    with open(path, "rb") as f:
        image_bytes = f.read()
    
    return types.Part.from_bytes(data=image_bytes, mime_type=mime_type)
```

## ツール1: スクリーンショット品質スコアリング

最初のツールは、スクリーンショットセットをASO（アプリストア最適化）の観点から評価してスコアを返します。

```python
def score_screenshots(
    screenshot_paths: list[str],
    app_name: str,
    app_category: str,
    target_market: str = "日本",
) -> dict:
    """
    スクリーンショットセットをASOの観点から評価する。

    返値のスコア（0〜100）の構成:
    - visual_hierarchy: 視覚的な優先順位付け（最重要要素が目立つか）
    - message_clarity: 1枚目で価値提案が伝わるか
    - cta_presence: 行動を促す表現があるか
    - consistency: デザインの一貫性
    - localization_fit: 対象市場への文化的適合度
    """
    parts = [
        types.Part.from_text(
            f"""あなたは App Store 最適化の専門家です。
以下のアプリのスクリーンショットセットを評価してください。

アプリ名: {app_name}
カテゴリ: {app_category}
対象市場: {target_market}

以下の観点から各スクリーンショットと全体を評価し、JSON形式で返してください。
必ず以下の形式を厳守してください:

{{
  "overall_score": <0-100の整数>,
  "scores": {{
    "visual_hierarchy": <0-100>,
    "message_clarity": <0-100>,
    "cta_presence": <0-100>,
    "consistency": <0-100>,
    "localization_fit": <0-100>
  }},
  "strengths": ["強み1", "強み2", "強み3"],
  "improvements": [
    {{"issue": "課題の説明", "priority": "high|medium|low", "suggestion": "具体的な改善案"}},
    ...
  ],
  "first_impression": "ユーザーが最初の1秒で受ける印象（1文）"
}}"""
        )
    ]
    
    # スクリーンショット画像を追加
    for i, path in enumerate(screenshot_paths):
        parts.append(types.Part.from_text(f"スクリーンショット {i+1}:"))
        parts.append(load_image_as_part(path))
    
    response = client.models.generate_content(
        model=VISION_MODEL,
        contents=parts,
        config=types.GenerateContentConfig(
            response_mime_type="application/json",
            temperature=0.2,
        ),
    )
    
    try:
        return json.loads(response.text)
    except json.JSONDecodeError:
        # JSONパース失敗時はテキストをそのまま返す
        return {"raw_response": response.text, "parse_error": True}
```

## ツール2: 競合スクリーンショット比較分析

競合アプリのスクリーンショットと自分のものを比較して、差分を可視化します。競合のスクリーンショットはApp Storeのスクリーンショット画像URLから直接取得できます。

```python
def download_image_from_url(url: str) -> bytes:
    """URLから画像をダウンロードしてバイト列で返す。"""
    response = httpx.get(url, timeout=30, follow_redirects=True)
    response.raise_for_status()
    return response.content

def compare_with_competitor(
    my_screenshots: list[str],
    competitor_name: str,
    competitor_screenshot_urls: list[str],
    focus_aspect: str = "全体的な比較",
) -> dict:
    """
    自分のスクリーンショットと競合のスクリーンショットを比較分析する。

    competitor_screenshot_urls: App StoreのスクリーンショットURLリスト
                               （App Storeページのソースから取得可能）
    focus_aspect: "価値提案", "デザイン品質", "テキスト量", "全体的な比較" など
    """
    parts = [
        types.Part.from_text(
            f"""App Storeスクリーンショットの競合比較分析を行います。

比較の焦点: {focus_aspect}

「自社アプリ」と「{competitor_name}」のスクリーンショットを比較し、
以下のJSON形式で結果を返してください:

{{
  "competitive_position": "ahead|parity|behind",
  "key_differences": [
    {{"aspect": "比較項目", "my_app": "自社の状況", "competitor": "競合の状況", "advantage": "my|competitor|neutral"}}
  ],
  "ab_test_hypotheses": [
    {{"hypothesis": "仮説", "expected_lift": "期待される改善幅の推定", "effort": "low|medium|high"}}
  ],
  "immediate_wins": ["すぐに実施できる改善案（コスト低・効果高）"]
}}"""
        )
    ]
    
    parts.append(types.Part.from_text("=== 自社アプリのスクリーンショット ==="))
    for i, path in enumerate(my_screenshots):
        parts.append(types.Part.from_text(f"自社 {i+1}:"))
        parts.append(load_image_as_part(path))
    
    parts.append(types.Part.from_text(f"=== {competitor_name} のスクリーンショット ==="))
    for i, url in enumerate(competitor_screenshot_urls[:5]):  # 最大5枚
        try:
            img_bytes = download_image_from_url(url)
            parts.append(types.Part.from_text(f"{competitor_name} {i+1}:"))
            parts.append(types.Part.from_bytes(data=img_bytes, mime_type="image/jpeg"))
        except Exception as e:
            print(f"Warning: {url} の取得失敗 ({e})")
            continue
    
    response = client.models.generate_content(
        model=VISION_MODEL,
        contents=parts,
        config=types.GenerateContentConfig(
            response_mime_type="application/json",
            temperature=0.3,
        ),
    )
    
    return json.loads(response.text)
```

## ツール3: 多言語テキスト最適化

スクリーンショット内のテキスト（キャッチコピーやラベル）を抽出し、複数市場向けに翻訳・文化適応します。

```python
TARGET_MARKETS = {
    "us": {"locale": "en-US", "culture_notes": "Simple, benefit-focused. Avoid superlatives."},
    "jp": {"locale": "ja-JP", "culture_notes": "Polite tone. Trust and quality are key values."},
    "de": {"locale": "de-DE", "culture_notes": "Technical precision valued. Features over benefits."},
    "br": {"locale": "pt-BR", "culture_notes": "Warm, emotional tone. Social proof matters."},
    "kr": {"locale": "ko-KR", "culture_notes": "Trendy language. 'Premium' and exclusivity resonate."},
}

def localize_screenshot_text(
    screenshot_path: str,
    source_market: str = "jp",
    target_markets: list[str] | None = None,
) -> dict:
    """
    スクリーンショット内のテキストを抽出し、複数市場向けに翻訳・文化適応する。
    
    返値は市場コードをキーとした翻訳結果の辞書。
    """
    if target_markets is None:
        target_markets = [m for m in TARGET_MARKETS if m \!= source_market]
    
    markets_config = {k: v for k, v in TARGET_MARKETS.items() if k in target_markets}
    markets_json = json.dumps(markets_config, ensure_ascii=False, indent=2)
    
    prompt = f"""このスクリーンショット内のすべてのテキスト要素を抽出し、
以下の各市場向けに翻訳・文化適応してください。

単純な翻訳ではなく、各市場の文化的コンテキストに合わせたローカライズをしてください。

対象市場の設定:
{markets_json}

以下のJSON形式で返してください:
{{
  "extracted_texts": ["元のテキスト要素1", "元のテキスト要素2", ...],
  "localizations": {{
    "<market_code>": {{
      "texts": ["翻訳テキスト1", "翻訳テキスト2", ...],
      "adaptation_notes": "文化適応のポイント（1〜2文）"
    }}
  }}
}}"""
    
    response = client.models.generate_content(
        model=VISION_MODEL,
        contents=[
            types.Part.from_text(prompt),
            load_image_as_part(screenshot_path),
        ],
        config=types.GenerateContentConfig(
            response_mime_type="application/json",
            temperature=0.4,
        ),
    )
    
    return json.loads(response.text)
```

## ツール4: 統合レポート生成

3つのツールを組み合わせて、一括でASO改善レポートを生成します。

```python
def generate_aso_report(
    app_name: str,
    app_category: str,
    screenshot_dir: str,
    competitor_name: str | None = None,
    competitor_screenshot_urls: list[str] | None = None,
    target_markets: list[str] | None = None,
    output_path: str = "aso_report.json",
) -> dict:
    """
    App StoreスクリーンショットのASO改善レポートを一括生成する。
    
    screenshot_dir: スクリーンショットが格納されたディレクトリ
    output_path: レポートの出力先JSONファイルパス
    """
    # スクリーンショットを取得（名前順でソート）
    screenshot_dir_path = Path(screenshot_dir)
    screenshots = sorted([
        str(p) for p in screenshot_dir_path.glob("*.{png,jpg,jpeg,webp}")
    ])
    
    if not screenshots:
        raise ValueError(f"スクリーンショットが見つかりません: {screenshot_dir}")
    
    print(f"スクリーンショット {len(screenshots)} 枚を処理します...")
    
    report = {
        "app_name": app_name,
        "category": app_category,
        "screenshot_count": len(screenshots),
        "generated_at": __import__("datetime").datetime.now().isoformat(),
    }
    
    # Step 1: スコアリング
    print("Step 1/3: スクリーンショット品質スコアリング...")
    report["quality_score"] = score_screenshots(
        screenshot_paths=screenshots[:5],  # 最大5枚
        app_name=app_name,
        app_category=app_category,
    )
    
    # Step 2: 競合比較（競合情報が提供された場合）
    if competitor_name and competitor_screenshot_urls:
        print(f"Step 2/3: {competitor_name} との競合比較...")
        report["competitor_analysis"] = compare_with_competitor(
            my_screenshots=screenshots[:3],
            competitor_name=competitor_name,
            competitor_screenshot_urls=competitor_screenshot_urls,
        )
    else:
        print("Step 2/3: 競合情報なし（スキップ）")
        report["competitor_analysis"] = None
    
    # Step 3: 1枚目のローカライズ分析
    print("Step 3/3: メインスクリーンショットのローカライズ分析...")
    report["localization"] = localize_screenshot_text(
        screenshot_path=screenshots[0],
        target_markets=target_markets or ["us", "de", "br"],
    )
    
    # JSON保存
    with open(output_path, "w", encoding="utf-8") as f:
        json.dump(report, f, ensure_ascii=False, indent=2)
    
    print(f"\n✅ レポート生成完了: {output_path}")
    print(f"   総合スコア: {report['quality_score'].get('overall_score', 'N/A')}/100")
    
    return report
```

## 実装上のポイントと注意事項

**トークンコストの管理**

スクリーンショットの画像は1枚あたり数百〜数千トークンを消費します。Gemini 2.5 Pro での処理コストは入力の画像数に比例して上がるため、本番環境では以下の工夫が効果的です。

- スコアリングには解像度を下げた画像を使用（品質評価には1080px幅で十分）
- キャッシュを活用して同じ画像の再処理を避ける
- Gemini Flash（`gemini-2.5-flash-preview-04-17`）で試してコストを削減し、最終確認だけProで行う

**App StoreのURL取得方法**

競合アプリのスクリーンショットURLは、iTunes Search APIで取得できます:

```python
import httpx

def get_competitor_screenshot_urls(app_id: str, country: str = "jp") -> list[str]:
    """iTunes Search APIでアプリのスクリーンショットURLを取得する。"""
    url = f"https://itunes.apple.com/lookup?id={app_id}&country={country}"
    resp = httpx.get(url)
    data = resp.json()
    
    if data.get("resultCount", 0) == 0:
        return []
    
    return data["results"][0].get("screenshotUrls", [])

# 使用例
zedge_screenshots = get_competitor_screenshot_urls("470786854")  # ZedgeのApp ID
```

**処理の自動化**

App Store Connect APIと組み合わせると、新バージョンのリリースごとに自動でスクリーンショット評価を実行し、品質スコアが前バージョンを下回っている場合にアラートを送る仕組みを作ることができます。
