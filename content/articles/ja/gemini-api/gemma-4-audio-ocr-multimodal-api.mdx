Gemma 4 のリリースノートを読んで「音声入力は E2B と E4B だけ対応」という一文が気になった開発者は少なくないはずです。26B や 31B ではなく、むしろ小さいモデルにこそ音声とOCRが乗っている——この非直感的な設計には明確な理由があります。

エッジデバイスで動かすからこそ、リアルタイムの音声認識と手書きテキスト認識が必要になります。クラウドAPIを呼ぶ必要がない、ネットワーク遅延ゼロのマルチモーダルAIが E2B/E4B の設計コンセプトです。

## なぜ小さいモデルに音声とOCRが乗っているのか

Gemma 4 の4モデルは用途で明確に分かれています。E2B と E4B は「スマートフォンとエッジデバイス」向けであり、音声入力・OCR・多言語手書き認識はその用途に必要だからこそ搭載されています。

一方で 26B MoE と 31B Dense は「コンシューマーGPUからクラウド」向けであり、テキストと画像・動画に集中した設計になっています。音声認識はそれぞれのモデルを組み合わせて対処するか、専用の音声処理パイプラインを使う前提です。

この設計が面白いのは、エッジデバイス向けの「小さいモデル」が、実はより多くのモダリティを処理できるという逆転です。Per-Layer Embeddings（PLE）技術により、E2B と E4B は実際の計算コストをパラメータ数より大幅に抑えているため、音声・画像・テキストを同時に扱えるコストが想定より低い。

## 音声入力の実装

Ollama 経由で E2B または E4B を使う場合、音声入力は wav または mp3 ファイルをBase64エンコードしてプロンプトに含める形式で処理できます。

```python
import anthropic
import base64
import subprocess

def transcribe_audio_gemma4(audio_file_path: str) -> str:
    # Ollamaのローカルエンドポイントを使用
    # 音声ファイルをBase64エンコード
    with open(audio_file_path, "rb") as f:
        audio_b64 = base64.b64encode(f.read()).decode("utf-8")

    # Ollama API経由でリクエスト
    import requests
    response = requests.post(
        "http://localhost:11434/api/generate",
        json={
            "model": "gemma4:4b",  # E4Bモデル
            "prompt": "この音声を文字起こししてください。話者が複数いる場合は区別してください。",
            "images": [audio_b64],  # 音声もimagesフィールドで送信
            "stream": False
        }
    )
    return response.json()["response"]

# 使用例
transcript = transcribe_audio_gemma4("meeting_recording.wav")
print(transcript)
```

リアルタイム音声入力（マイク直接）の場合は、PyAudio でストリームを取得してチャンクごとに送信するパターンが使われます。

```python
import pyaudio
import wave
import tempfile
import requests
import base64

def real_time_transcription(duration_seconds: int = 5):
    # マイクから録音
    p = pyaudio.PyAudio()
    stream = p.open(
        format=pyaudio.paInt16,
        channels=1,
        rate=16000,
        input=True,
        frames_per_buffer=1024
    )

    print(f"{duration_seconds}秒間録音中...")
    frames = []
    for _ in range(0, int(16000 / 1024 * duration_seconds)):
        data = stream.read(1024)
        frames.append(data)

    stream.stop_stream()
    stream.close()
    p.terminate()

    # 一時ファイルに保存してGemma 4に送信
    with tempfile.NamedTemporaryFile(suffix=".wav", delete=False) as tmp:
        wf = wave.open(tmp.name, "wb")
        wf.setnchannels(1)
        wf.setsampwidth(p.get_sample_size(pyaudio.paInt16))
        wf.setframerate(16000)
        wf.writeframes(b"".join(frames))
        wf.close()

        return transcribe_audio_gemma4(tmp.name)

result = real_time_transcription(10)
print("認識結果:", result)
```

## OCRと多言語手書き認識

E2B/E4B の OCR 機能は、印刷テキストだけでなく手書き文字にも対応しています。140言語以上の手書き認識をサポートしているため、日本語の手書きメモ、アラビア語の請求書、中国語の書類スキャンなど、多言語混在ドキュメントの処理が単一モデルで完結します。

```python
import requests
import base64
from PIL import Image
import io

def ocr_with_gemma4(image_path: str, language_hint: str = "日本語") -> str:
    with open(image_path, "rb") as f:
        image_b64 = base64.b64encode(f.read()).decode("utf-8")

    response = requests.post(
        "http://localhost:11434/api/generate",
        json={
            "model": "gemma4:2b",  # E2Bモデル（軽量でOCRも対応）
            "prompt": f"画像内のテキストをすべて抽出してください。言語: {language_hint}。レイアウト（段落・表・箇条書き）も維持してください。",
            "images": [image_b64],
            "stream": False
        }
    )
    return response.json()["response"]

# スキャンした書類のOCR
extracted_text = ocr_with_gemma4("handwritten_notes.jpg", "日本語")
print(extracted_text)

# 複数ページのPDFを処理する場合
def ocr_pdf_pages(pdf_path: str) -> list:
    from pdf2image import convert_from_path
    images = convert_from_path(pdf_path)
    results = []
    for i, img in enumerate(images):
        buf = io.BytesIO()
        img.save(buf, format="JPEG")
        img_b64 = base64.b64encode(buf.getvalue()).decode("utf-8")

        response = requests.post(
            "http://localhost:11434/api/generate",
            json={
                "model": "gemma4:2b",
                "prompt": f"ページ{i+1}のテキストを抽出してください。",
                "images": [img_b64],
                "stream": False
            }
        )
        results.append(response.json()["response"])
    return results
```

## 変数解像度画像処理——モバイルアプリへの実装

Gemma 4 が採用した変数解像度対応（variable aspect ratio/resolution）は、モバイルアプリ開発者にとって実用的なメリットをもたらす。スマートフォンで撮影した縦長の写真、横長のスクリーンショット、正方形のSNS画像——それぞれを事前リサイズせず、そのままモデルに送れます。

ただし、画像1枚あたりのトークン消費は最大1,120トークンに制限されています。解像度が高い画像は自動的にダウンスケールされるため、極めて細かい文字（印刷物の本文など）のOCRでは意図的に高解像度部分をクロップしてから送る設計が品質を安定させる。

```python
from PIL import Image

def crop_and_ocr(image_path: str, region: tuple) -> str:
    # region = (left, top, right, bottom) ピクセル座標
    img = Image.open(image_path)
    cropped = img.crop(region)

    # クロップ後に適切なサイズに調整
    max_size = (1024, 1024)
    cropped.thumbnail(max_size, Image.LANCZOS)

    buf = io.BytesIO()
    cropped.save(buf, format="JPEG", quality=90)
    img_b64 = base64.b64encode(buf.getvalue()).decode("utf-8")

    response = requests.post(
        "http://localhost:11434/api/generate",
        json={
            "model": "gemma4:4b",
            "prompt": "この画像のテキストをすべて正確に抽出してください。",
            "images": [img_b64],
            "stream": False
        }
    )
    return response.json()["response"]
```

## E2B/E4Bを選ぶべき実際のユースケース

音声とOCRが搭載されている E2B/E4B が特に強みを発揮するのは、次のようなアプリケーションです。

オフラインファーストのメモアプリ——ネットワーク接続なしで音声メモを自動文字起こしし、手書きスキャンも取り込める。すべてデバイス内で完結するためプライバシーリスクがありません。

現場業務支援ツール——建設現場や工場での検査レポート作成。音声で記録してその場で文章化、図面のOCRも同じモデルで処理できます。

多言語文書処理——インバウンド観光業や貿易業務で、さまざまな言語の書類をスキャンしてその場で要約・翻訳できます。

Apache 2.0 ライセンスなので商用アプリへの組み込みに制限はありません。まず Ollama で動作確認をして、プロダクションでは Raspberry Pi 5 やスマートフォンへのデプロイを検討してほしい。
