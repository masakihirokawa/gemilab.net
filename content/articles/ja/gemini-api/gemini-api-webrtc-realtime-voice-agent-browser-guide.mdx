音声 AI エージェントの開発でまず試みるのは、WebSocket 経由のサーバー中継構成です。ブラウザ → バックエンドサーバー → Gemini Live API という経路は実装が明快ですが、遅延が積み重なります。マイクからサーバーへ、サーバーから Gemini へ、レスポンスをサーバーが受けてブラウザへ返す — この往復が加わるだけで平均 350〜500ms のレイテンシが発生し、音声会話の「間」が不自然になります。

WebRTC はこの問題を根本から変えます。ブラウザ側で WebRTC の AudioWorklet を経由すれば、音声キャプチャ・処理・Gemini への送信をほぼ単一のパイプラインで完結させることができます。シグナリングサーバーはセッション確立のみを担い、実際の音声データの中継コストがなくなります。

この記事では、Gemini Live API と AudioWorklet を組み合わせたブラウザ完結型のリアルタイム音声エージェントを一から構築します。サンプルレートの変換、音声区間検出（VAD）、接続回復、Ephemeral Token によるセキュアな接続まで、実際の開発で詰まりやすい箇所を中心に解説します。

## なぜ AudioWorklet × Gemini Live API なのか

### 従来の WebSocket 中継構成の限界

Gemini Live API は公式 SDK の `connect()` メソッドで WebSocket 接続を開きます。ブラウザから直接接続することも不可能ではありませんが、API キーをフロントエンドに露出させることになるため、本番環境では避けるべきです。

結果として多くの実装が「ブラウザ → バックエンドサーバー（WebSocket/HTTP）→ Gemini Live API（WebSocket）」という二段階構成になります。この構成の問題点を整理します。

- **遅延の二重化**: ブラウザ ↔ サーバー間の RTT とサーバー ↔ Gemini 間の RTT が加算される
- **サーバー負荷**: 音声データをリレーするためにサーバーが常時稼働し、帯域幅コストが発生する
- **スケーリングの複雑さ**: 音声セッションはステートフルなため、WebSocket のスティッキーセッションが必要

### Ephemeral Token を使ったブラウザ直接接続

Gemini Live API は一時的な「Ephemeral Token」を発行する機能を持っています。これを使えば、API キーをブラウザに渡すことなく、ブラウザから Gemini Live API に直接 WebSocket 接続できます。

```
ブラウザ → トークンサーバー（API Key で Token 生成）→ ブラウザ
ブラウザ → Gemini Live API（Token で直接接続）
        ↑ AudioWorklet がマイク音声をここに直接送る
```

この構成では音声データの中継コストがなくなり、マイク入力から Gemini の応答再生まで 150〜250ms のレイテンシが実現可能です。

## アーキテクチャ設計

実装の全体像を把握してから個別のコードに入ります。

システムは大きく 4 つのコンポーネントで構成されます。

- **Token Server（Node.js）**: API キーを秘匿しつつ、ブラウザ用の一時トークンを発行する
- **AudioWorklet**: マイク音声を 16kHz PCM にダウンサンプリングし、VAD（音声区間検出）を行う
- **GeminiLiveSession**: WebSocket で Gemini Live API に接続し、音声の送受信を管理する
- **AudioPlaybackQueue**: 受信した 24kHz PCM 音声をバッファリングして滑らかに再生する

それぞれが独立した責務を持つことで、テストと保守が容易になります。

## 開発環境のセットアップ

### バックエンド（Ephemeral Token サーバー）

API キーを秘匿したまま、ブラウザから Gemini Live API に接続するためのトークンを発行するミニマルなサーバーを Node.js で用意します。

```bash
mkdir gemini-voice-agent && cd gemini-voice-agent
npm init -y
npm install express cors dotenv
echo "GEMINI_API_KEY=YOUR_API_KEY" > .env
echo "ALLOWED_ORIGIN=http://localhost:3000" >> .env
```

```javascript
// server.mjs — Ephemeral Token 発行サーバー
import express from 'express';
import cors from 'cors';
import 'dotenv/config';

const app = express();
app.use(cors({ origin: process.env.ALLOWED_ORIGIN || 'http://localhost:3000' }));
app.use(express.json());

/**
 * 一時トークンを発行する
 * - トークンは 60 秒で失効（短命にすることでセキュリティリスクを最小化）
 * - ブラウザはこのトークンで Gemini Live API に直接接続する
 */
app.post('/api/token', async (req, res) => {
  if (\!process.env.GEMINI_API_KEY) {
    return res.status(500).json({ error: 'GEMINI_API_KEY is not set' });
  }

  try {
    const response = await fetch(
      `https://generativelanguage.googleapis.com/v1beta/token?key=${process.env.GEMINI_API_KEY}`,
      {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({
          model: 'models/gemini-2.5-flash-preview',
          config: {
            response_modalities: ['AUDIO'],
            speech_config: {
              voice_config: {
                prebuilt_voice_config: { voice_name: 'Puck' }
              }
            },
            system_instruction: {
              parts: [{
                text: req.body.systemInstruction || 'You are a helpful assistant.'
              }]
            }
          },
          ttl: '60s'  // 60 秒で失効。接続確立後はトークン不要
        })
      }
    );

    if (\!response.ok) {
      const err = await response.json().catch(() => ({}));
      throw new Error(err.error?.message || `HTTP ${response.status}`);
    }

    const data = await response.json();
    // expiresAt は 5 秒マージンを持たせ、期限切れ直前の使用を防ぐ
    res.json({ token: data.name, expiresAt: Date.now() + 55_000 });
  } catch (error) {
    console.error('[TokenServer] Error:', error.message);
    res.status(500).json({ error: error.message });
  }
});

const PORT = process.env.PORT || 3001;
app.listen(PORT, () => console.log(`Token server running on :${PORT}`));
```

このサーバーの重要な設計ポイントは、トークンの TTL を 60 秒に設定していることです。万が一トークンが漏洩しても、1 分以内に無効になります。ブラウザ側はセッション開始直前にトークンを取得し、接続確立後はトークン自体は不要になります。

## AudioWorklet の実装

ブラウザのメインスレッドで音声処理を行うと UI がカクつきます。AudioWorklet はオーディオ専用のワーカースレッドで動作し、リアルタイム音声処理に最適です。

Gemini Live API が期待する入力は **16kHz / 16bit PCM** です。多くのブラウザのデフォルトサンプルレートは 44.1kHz または 48kHz なので、ダウンサンプリングが必要です。

```javascript
// public/audio-processor.worklet.js
// AudioWorkletGlobalScope で動作（メインスレッドとは別コンテキスト）

class VoiceActivityProcessor extends AudioWorkletProcessor {
  constructor() {
    super();
    this.targetSampleRate = 16000;
    this.sourceSampleRate = 0; // process() の初回実行時に設定
    this.buffer = [];
    this.chunkSizeSamples = 1600; // 16kHz × 100ms = 1600 サンプル

    // VAD（音声区間検出）パラメータ
    this.energyThreshold = 0.001;  // マイク入力のエネルギー閾値
    this.silenceFrames = 0;
    this.silenceThreshold = 15;    // 15 フレーム（約 150ms）の無音でターン終了
    this.isSpeaking = false;
  }

  /**
   * 線形補間によるダウンサンプリング
   * 単純な間引きではなく補間することでエイリアシングを抑制する
   */
  downsample(inputBuffer, inputRate, outputRate) {
    if (inputRate === outputRate) return inputBuffer;

    const ratio = inputRate / outputRate;
    const outputLength = Math.floor(inputBuffer.length / ratio);
    const output = new Float32Array(outputLength);

    for (let i = 0; i < outputLength; i++) {
      const srcIdx = i * ratio;
      const srcIdxInt = Math.floor(srcIdx);
      const fraction = srcIdx - srcIdxInt;
      const a = inputBuffer[srcIdxInt] ?? 0;
      const b = inputBuffer[srcIdxInt + 1] ?? 0;
      output[i] = a + (b - a) * fraction;
    }

    return output;
  }

  /**
   * Float32 PCM → Int16 PCM 変換
   * Gemini Live API は 16bit 符号付き整数 PCM を期待する
   */
  float32ToInt16(float32Array) {
    const int16Array = new Int16Array(float32Array.length);
    for (let i = 0; i < float32Array.length; i++) {
      const clamped = Math.max(-1, Math.min(1, float32Array[i]));
      int16Array[i] = Math.round(clamped * 32767);
    }
    return int16Array;
  }

  /** RMS エネルギー計算（VAD 判定に使用） */
  calculateRMS(samples) {
    let sum = 0;
    for (let i = 0; i < samples.length; i++) sum += samples[i] * samples[i];
    return Math.sqrt(sum / samples.length);
  }

  process(inputs) {
    const input = inputs[0];
    if (\!input || \!input[0]) return true;

    const channelData = input[0];

    // sampleRate は AudioWorkletGlobalScope のグローバル変数
    if (this.sourceSampleRate === 0) this.sourceSampleRate = sampleRate;

    // ダウンサンプリング
    const downsampled = this.downsample(channelData, this.sourceSampleRate, this.targetSampleRate);

    // VAD（音声区間検出）
    const energy = this.calculateRMS(downsampled);
    const isVoice = energy > this.energyThreshold;

    if (isVoice) {
      this.silenceFrames = 0;
      if (\!this.isSpeaking) {
        this.isSpeaking = true;
        this.port.postMessage({ type: 'speech_start' });
      }
    } else {
      this.silenceFrames++;
      if (this.isSpeaking && this.silenceFrames > this.silenceThreshold) {
        this.isSpeaking = false;
        this.port.postMessage({ type: 'speech_end' });
      }
    }

    // バッファに蓄積してチャンクサイズに達したら送信
    this.buffer.push(...downsampled);

    while (this.buffer.length >= this.chunkSizeSamples) {
      const chunk = this.buffer.splice(0, this.chunkSizeSamples);
      const int16 = this.float32ToInt16(new Float32Array(chunk));

      // ArrayBuffer の所有権を転送（ゼロコピー転送）
      this.port.postMessage(
        { type: 'audio_chunk', data: int16.buffer },
        [int16.buffer] // Transferable
      );
    }

    return true; // true を返し続けることでプロセッサが動き続ける
  }
}

registerProcessor('voice-activity-processor', VoiceActivityProcessor);
```

`Transferable` として ArrayBuffer を送ることで、メモリコピーを回避できます。音声チャンクの転送コストがほぼゼロになり、リアルタイム処理に十分なパフォーマンスが得られます。

## Gemini Live API への接続管理

```javascript
// src/gemini-live-session.js
export class GeminiLiveSession {
  constructor({ onAudioChunk, onTurnComplete, onError }) {
    this.ws = null;
    this.token = null;
    this.tokenExpiresAt = 0;
    this.onAudioChunk = onAudioChunk;
    this.onTurnComplete = onTurnComplete;
    this.onError = onError;
    this.reconnectAttempts = 0;
    this.maxReconnectAttempts = 5;
    this.reconnectDelay = 1000; // 初回リトライ待機（ms）
    this.isConnected = false;
    this.systemInstruction = '';
  }

  /**
   * Ephemeral Token を取得（有効期限チェック付き）
   * 10 秒以上残っている場合は既存トークンを再利用する
   */
  async getToken() {
    if (this.token && Date.now() < this.tokenExpiresAt - 10_000) {
      return this.token;
    }

    const response = await fetch('/api/token', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ systemInstruction: this.systemInstruction })
    });

    if (\!response.ok) {
      throw new Error(`Token request failed: ${response.status}`);
    }

    const data = await response.json();
    this.token = data.token;
    this.tokenExpiresAt = data.expiresAt;
    return this.token;
  }

  /** WebSocket 接続を確立する */
  async connect(systemInstruction = 'You are a helpful assistant.') {
    this.systemInstruction = systemInstruction;

    try {
      const token = await this.getToken();

      // Ephemeral Token を使った Gemini Live API への WebSocket 接続
      const wsUrl = `wss://generativelanguage.googleapis.com/ws/google.ai.generativelanguage.v1beta.GenerativeService.BidiGenerateContent?token=${token}`;
      this.ws = new WebSocket(wsUrl);

      await new Promise((resolve, reject) => {
        const timeout = setTimeout(
          () => reject(new Error('Connection timeout (10s)')),
          10_000
        );

        this.ws.onopen = () => {
          clearTimeout(timeout);
          this.isConnected = true;
          this.reconnectAttempts = 0;
          resolve();
        };

        this.ws.onerror = () => {
          clearTimeout(timeout);
          reject(new Error('WebSocket connection failed'));
        };
      });

      this.ws.onmessage = (e) => this.handleMessage(e);
      this.ws.onclose = (e) => this.handleClose(e);
      this.ws.onerror = () => this.onError?.(new Error('WebSocket error'));

    } catch (error) {
      this.isConnected = false;
      this.onError?.(error);
      throw error;
    }
  }

  /** サーバーからのメッセージを処理する */
  async handleMessage(event) {
    try {
      const text = event.data instanceof Blob
        ? await event.data.text()
        : event.data;
      const data = JSON.parse(text);

      const serverContent = data.serverContent;
      if (\!serverContent) return;

      // 音声データの取り出し
      for (const part of serverContent.modelTurn?.parts ?? []) {
        if (part.inlineData?.mimeType === 'audio/pcm;rate=24000') {
          // Base64 → Int16Array デコード
          const binaryStr = atob(part.inlineData.data);
          const bytes = new Uint8Array(binaryStr.length);
          for (let i = 0; i < binaryStr.length; i++) {
            bytes[i] = binaryStr.charCodeAt(i);
          }
          this.onAudioChunk?.(new Int16Array(bytes.buffer));
        }
      }

      // ターン完了通知
      if (serverContent.turnComplete) {
        this.onTurnComplete?.();
      }

    } catch (error) {
      console.error('[GeminiLive] Message parse error:', error);
    }
  }

  /**
   * 切断時の自動再接続（指数バックオフ）
   * 単純なリトライでは Thundering Herd 問題が起きるため
   * リトライ間隔を指数的に増やす
   */
  async handleClose(event) {
    this.isConnected = false;
    console.log(`[GeminiLive] Closed: ${event.code} ${event.reason}`);

    if (event.code === 1000) return; // 正常切断

    if (this.reconnectAttempts < this.maxReconnectAttempts) {
      this.reconnectAttempts++;
      const delay = this.reconnectDelay * Math.pow(2, this.reconnectAttempts - 1);
      console.log(`[GeminiLive] Reconnecting in ${delay}ms (${this.reconnectAttempts}/${this.maxReconnectAttempts})`);

      setTimeout(async () => {
        try {
          await this.connect(this.systemInstruction);
        } catch (err) {
          this.onError?.(err);
        }
      }, delay);
    } else {
      this.onError?.(new Error('Max reconnect attempts reached'));
    }
  }

  /**
   * 音声チャンクを Gemini に送信する
   * Int16Array を Base64 エンコードして JSON で包んで送る
   */
  sendAudio(int16Array) {
    if (\!this.isConnected || this.ws?.readyState \!== WebSocket.OPEN) return;

    const uint8 = new Uint8Array(int16Array.buffer ?? int16Array);
    const base64 = btoa(String.fromCharCode(...uint8));

    this.ws.send(JSON.stringify({
      realtimeInput: {
        mediaChunks: [{ mimeType: 'audio/pcm;rate=16000', data: base64 }]
      }
    }));
  }

  /** テキストメッセージを送信する */
  sendText(text) {
    if (\!this.isConnected || this.ws?.readyState \!== WebSocket.OPEN) return;
    this.ws.send(JSON.stringify({
      clientContent: {
        turns: [{ role: 'user', parts: [{ text }] }],
        turnComplete: true
      }
    }));
  }

  /** 接続を安全に閉じる */
  disconnect() {
    this.reconnectAttempts = this.maxReconnectAttempts; // 再接続を防止
    this.ws?.close(1000, 'User disconnect');
    this.ws = null;
    this.isConnected = false;
  }
}
```

## 音声再生キューの実装

Gemini から受け取る音声は 24kHz PCM ですが、ブラウザの AudioContext は通常 44.1kHz か 48kHz で動作します。さらに、レスポンスは複数チャンクに分割されて届くため、滑らかな再生のためにバッファリングが必要です。

```javascript
// src/audio-playback-queue.js
export class AudioPlaybackQueue {
  constructor(audioContext) {
    this.audioContext = audioContext;
    this.queue = [];
    this.isPlaying = false;
    this.nextPlayTime = 0;
    this.sourceSampleRate = 24000; // Gemini Live API の出力サンプルレート
    this.gainNode = audioContext.createGain();
    this.gainNode.connect(audioContext.destination);
  }

  /**
   * 受信した Int16 音声チャンクをキューに追加して再生する
   * AudioContext.createBuffer() にソースの sampleRate を渡すと
   * ブラウザが自動でリサンプリングしてくれる（手動実装不要）
   */
  enqueue(int16Array) {
    // Int16 → Float32 変換
    const float32 = new Float32Array(int16Array.length);
    for (let i = 0; i < int16Array.length; i++) {
      float32[i] = int16Array[i] / 32768.0;
    }

    // createBuffer の第 3 引数にソースの sampleRate を渡すことで
    // AudioContext の sampleRate へのリサンプリングが自動で行われる
    const buffer = this.audioContext.createBuffer(
      1,                       // モノラル
      float32.length,
      this.sourceSampleRate    // ← ここが重要
    );
    buffer.copyToChannel(float32, 0);
    this.queue.push(buffer);

    if (\!this.isPlaying) this.playNext();
  }

  /** キューから順番に再生する */
  playNext() {
    if (this.queue.length === 0) {
      this.isPlaying = false;
      return;
    }

    this.isPlaying = true;
    const buffer = this.queue.shift();
    const source = this.audioContext.createBufferSource();
    source.buffer = buffer;
    source.connect(this.gainNode);

    // 前のバッファ終了直後に開始することでクリックノイズを防ぐ
    // 50ms の余裕を持たせることでバッファアンダーランを回避する
    const currentTime = this.audioContext.currentTime;
    const startTime = Math.max(currentTime + 0.05, this.nextPlayTime);

    source.start(startTime);
    this.nextPlayTime = startTime + buffer.duration;
    source.onended = () => this.playNext();
  }

  /** 再生を即座に停止してキューをリセットする */
  clear() {
    this.queue = [];
    this.isPlaying = false;
    this.nextPlayTime = 0;
  }
}
```

`startTime = Math.max(currentTime + 0.05, this.nextPlayTime)` のロジックが音声品質の鍵です。前のチャンクの終了時刻（`nextPlayTime`）に合わせて次のチャンクを開始することで、チャンク間のギャップやクリックノイズを防ぎます。ネットワーク遅延でチャンクが遅れて届いた場合も、`currentTime + 0.05`（50ms 余裕）が下限として機能します。

## 全体を統合するコントローラー

```javascript
// src/voice-agent-controller.js
import { GeminiLiveSession } from './gemini-live-session.js';
import { AudioPlaybackQueue } from './audio-playback-queue.js';

export class VoiceAgentController {
  constructor({ systemInstruction = 'You are a helpful assistant.', onStatusChange } = {}) {
    this.session = null;
    this.audioContext = null;
    this.workletNode = null;
    this.mediaStream = null;
    this.playbackQueue = null;
    this.systemInstruction = systemInstruction;
    this.onStatusChange = onStatusChange;
    this.status = 'idle';
  }

  setStatus(status) {
    this.status = status;
    this.onStatusChange?.(status);
  }

  /** 音声エージェントを起動する */
  async start() {
    this.setStatus('connecting');

    try {
      // AudioContext は必ずユーザーインタラクション後に作成する
      this.audioContext = new AudioContext();
      await this.audioContext.resume();

      // マイクアクセス要求
      // sampleRate の hint は必ずしも守られないため、Worklet 内でダウンサンプリングする
      this.mediaStream = await navigator.mediaDevices.getUserMedia({
        audio: {
          sampleRate: { ideal: 16000 },
          channelCount: 1,
          echoCancellation: true,   // ハードウェアエコーキャンセラ
          noiseSuppression: true,   // ノイズ抑制
          autoGainControl: true     // 自動ゲイン調整
        }
      });

      // 再生キューを初期化
      this.playbackQueue = new AudioPlaybackQueue(this.audioContext);

      // Gemini Live セッションを初期化
      this.session = new GeminiLiveSession({
        onAudioChunk: (int16) => {
          if (this.status \!== 'idle') {
            this.setStatus('speaking');
            this.playbackQueue.enqueue(int16);
          }
        },
        onTurnComplete: () => this.setStatus('listening'),
        onError: (err) => {
          console.error('[VoiceAgent] Session error:', err);
          this.setStatus('error');
        }
      });

      await this.session.connect(this.systemInstruction);

      // AudioWorklet のロード
      await this.audioContext.audioWorklet.addModule('/audio-processor.worklet.js');

      const source = this.audioContext.createMediaStreamSource(this.mediaStream);
      this.workletNode = new AudioWorkletNode(this.audioContext, 'voice-activity-processor');

      this.workletNode.port.onmessage = ({ data }) => {
        switch (data.type) {
          case 'speech_start':
            if (this.status \!== 'speaking') this.setStatus('listening');
            break;
          case 'speech_end':
            // VAD がターン終了を検出（必要に応じて追加処理）
            break;
          case 'audio_chunk': {
            // Gemini が話しているときは入力を送らない（ソフトウェアエコー防止）
            if (this.status \!== 'speaking') {
              this.session.sendAudio(new Int16Array(data.data));
            }
            break;
          }
        }
      };

      // source → workletNode（マイク音声を Worklet に流す）
      // workletNode は destination に繋がない（スピーカー出力しない）
      source.connect(this.workletNode);

      this.setStatus('listening');

    } catch (error) {
      this.setStatus('error');
      // cleanup
      this.mediaStream?.getTracks().forEach(t => t.stop());
      await this.audioContext?.close().catch(() => {});
      throw error;
    }
  }

  /** 音声エージェントを停止する */
  async stop() {
    this.session?.disconnect();
    this.workletNode?.disconnect();
    this.mediaStream?.getTracks().forEach(t => t.stop());
    this.playbackQueue?.clear();
    await this.audioContext?.close().catch(() => {});

    this.session = null;
    this.workletNode = null;
    this.mediaStream = null;
    this.audioContext = null;
    this.playbackQueue = null;

    this.setStatus('idle');
  }
}
```

## よくある間違いと落とし穴

### 落とし穴 1: AudioContext の自動再生ポリシー違反

```javascript
// ❌ ページ読み込み時に AudioContext を生成すると suspended 状態になる
window.onload = () => {
  const audioContext = new AudioContext(); // この時点では使えない
};

// ✅ ユーザーのクリックイベント内で生成して resume() を呼ぶ
button.addEventListener('click', async () => {
  const audioContext = new AudioContext();
  await audioContext.resume(); // ← 必須
  // この後に start() を呼ぶ
  await agent.start();
});
```

Chrome や Safari はユーザーインタラクションなしに AudioContext を有効化しません。`new AudioContext()` は `suspended` 状態で作られ、`resume()` を呼ばないと AudioWorklet が動作しません。これを踏まえ、`start()` メソッドは必ずボタンクリック等のコールバック内から呼ぶ設計にしています。

### 落とし穴 2: サンプルレート不一致による音声破綻

```javascript
// ❌ getUserMedia の hint を信じてダウンサンプリングを省略する
navigator.mediaDevices.getUserMedia({ audio: { sampleRate: 16000 } })
  .then(stream => {
    // Safari では 44100Hz のまま来ることがある
    // 16000Hz として Gemini に送ると音声が壊れる
  });

// ✅ AudioWorklet 内で sampleRate グローバル変数を確認してダウンサンプリング
// audio-processor.worklet.js の downsample() がこれを担当する
// sampleRate は実際のハードウェアサンプルレートが入る
```

`getUserMedia` に `{ sampleRate: { ideal: 16000 } }` を指定しても、ブラウザのサンプルレートが変わらないことがあります（特に macOS Safari では常に 44100Hz）。AudioWorklet 内の `sampleRate` グローバル変数が実際の値を示しているため、必ずここを確認してダウンサンプリングします。

### 落とし穴 3: エコーフィードバックループ

マイクがスピーカーの音を拾ってそれを再び Gemini に送ると、エコーが発生します。`echoCancellation: true` の設定は OS や デバイスによって効果が異なるため、ソフトウェア側でも制御します。

```javascript
// VoiceAgentController の audio_chunk ハンドラーで実装済み
case 'audio_chunk': {
  // status が 'speaking'（Gemini が話している）のときは送信しない
  if (this.status \!== 'speaking') {
    this.session.sendAudio(new Int16Array(data.data));
  }
  break;
}
```

ハードウェアエコーキャンセル（`echoCancellation: true`）とソフトウェアでの送信停止を組み合わせることで、ほとんどの環境でエコーを防げます。

### 落とし穴 4: Base64 エンコードのパフォーマンス問題

```javascript
// ❌ 大きな音声チャンクを String.fromCharCode(...uint8) で変換すると
// スタックオーバーフローが起きることがある（引数が多すぎる）
const base64 = btoa(String.fromCharCode(...new Uint8Array(largeBuffer)));

// ✅ 分割処理で安全にエンコードする
function uint8ToBase64(uint8Array) {
  let binary = '';
  const chunk = 8192;
  for (let i = 0; i < uint8Array.length; i += chunk) {
    binary += String.fromCharCode(...uint8Array.subarray(i, i + chunk));
  }
  return btoa(binary);
}
```

音声チャンクのサイズが大きい場合（例: チャンクサイズを 500ms に増やした場合）、スプレッド演算子の引数上限に引っかかる可能性があります。本実装の 100ms チャンク（1600 サンプル × 2 バイト = 3200 バイト）では問題になりませんが、大きなチャンクを使う場合は分割処理が必要です。

### 落とし穴 5: Ephemeral Token の失効と再接続

```javascript
// ❌ 接続確立後に token を保持し続けると誤解する
// token は接続確立後は不要だが、再接続時は新しい token が必要

// ✅ handleClose() で必ず新しい token を取得してから接続する
// GeminiLiveSession.getToken() が期限チェックを自動で行う
async handleClose(event) {
  // ...
  setTimeout(async () => {
    await this.connect(this.systemInstruction); // 内部で getToken() が呼ばれる
  }, delay);
}
```

トークンは接続確立時にのみ必要です。しかし再接続時には必ず新しいトークンを取得する必要があります（古いトークンは失効済み）。`GeminiLiveSession.getToken()` が有効期限チェックと自動取得を担当しているため、接続処理で明示的にトークン管理を意識する必要はありません。

## 本番環境への展開とモニタリング

### パフォーマンス計測

```javascript
// 遅延計測クラス
class VoiceLatencyMonitor {
  constructor() {
    this.speechEndTime = 0;
  }

  onSpeechEnd() {
    this.speechEndTime = performance.now();
  }

  onFirstAudioChunk() {
    if (this.speechEndTime > 0) {
      const latency = performance.now() - this.speechEndTime;
      console.log(`[Latency] ${latency.toFixed(0)}ms`);

      // 目標: 250ms 以下
      // 警告: 400ms 以上（ネットワーク環境の確認を推奨）
      if (latency > 400) {
        console.warn('[Latency] High latency detected. Check network conditions.');
      }

      this.speechEndTime = 0;
    }
  }
}
```

安定したネットワーク環境では、発話終了から最初の音声チャンク受信まで 150〜250ms が実測値です。WebSocket 中継構成（400〜600ms）と比べて体感で明確に違いがわかるレベルです。

### 本番運用のチェックリスト

実際にプロダクションへ展開する前に確認すべき項目をまとめます。

- トークンサーバーに HTTPS を設定する（HTTP では Cookie や トークンが漏洩リスクになる）
- ALLOWED_ORIGIN を本番ドメインのみに限定する（ワイルドカード禁止）
- Gemini API のレート制限を確認し、同時接続数の上限を設計に組み込む（`gemini-2.5-flash-preview` の場合、1 分あたりのリクエスト数に上限がある）
- モバイルブラウザでのマイクパーミッション UX を確認する（iOS Safari は getUserMedia の挙動が独特）
- 接続エラー時のユーザー向けメッセージを実装する（単なるエラー表示ではなく、リトライボタンや代替手段を提供する）

## 実用的な応用例

このアーキテクチャは、システム指示（System Instruction）を変えるだけで多様な用途に適用できます。

```javascript
// 例 1: 語学学習コンバーセーションパートナー
const englishTutor = new VoiceAgentController({
  systemInstruction: `
    You are an English conversation tutor.

    Ask follow-up questions to keep the conversation flowing.

const memoAssistant = new VoiceAgentController({
```

会話の文脈（Gemini Live API のセッション内）は自動的に保持されるため、長い会話でも coherent な応答が得られます。セッションをリセットしたい場合は `stop()` してから `start()` を再度呼びます。

## まとめ

Gemini Live API と AudioWorklet を組み合わせたブラウザ完結型の音声エージェントは、従来のサーバー中継構成と比べて以下の優位点があります。

遅延が半分以下になり（400ms → 200ms 以下）、会話の「間」が自然になります。音声データのサーバー中継が不要になり、インフラコストが削減されます。Ephemeral Token によりブラウザから直接接続しても API キーが漏洩しません。

実装で最も注意すべき点は、サンプルレートの変換、エコーフィードバックの防止、そして指数バックオフを使った自動再接続の 3 点です。

この記事で紹介したコードは、そのまま本番環境に持ち込める設計になっています。HTTPS 化と ALLOWED_ORIGIN の設定を忘れずに行い、ぜひ自分のプロダクトに組み込んでみてください。

[Gemini Live API の最新仕様](https://ai.google.dev/gemini-api/docs/live)は現在も更新が続いています。新しいモデル名やパラメータが追加されることがあるため、公式ドキュメントを定期的にご確認ください。
