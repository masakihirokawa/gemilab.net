Gemini API には Structured Output という機能があって、JSON スキーマを渡すとそのスキーマに従った出力を保証してくれます。これを知ったとき、最初に思い浮かんだ使い道がアプリのレビュー分析でした。

レビューのテキストを渡すと「感情スコア」「問題カテゴリ」「対応優先度」が整然とした JSON で返ってくる——スプレッドシートへの手入力なしに自動分類できる状態になります。ここでは実際に動く Python コードを中心にその実装をお伝えします。

iOS/Android アプリを 6 本並行運用してきた個人開発者として、この問題に普段から向き合ってきた立場で、要点を整理します。

## Structured Output が解決する問題

「このレビュー、バグ報告？それとも機能要望？」という判断を普通のプロンプトで処理しようとすると、出力が揺れます。「バグ」と書いてくるときもあれば「問題」と書いてくることもある。後続処理でパースしようとすると、すぐに壊れます。

Structured Output を使うと出力の形式が保証されます。Gemini は指定した JSON スキーマ以外の形式では返答しないので、`response.parsed` をそのまま使えます。

## Pydantic でスキーマを定義する

Gemini の Python SDK は Pydantic モデルをそのまま渡せます。まずデータモデルを定義します。

```python
from pydantic import BaseModel
from typing import Literal
from enum import Enum

class ReviewCategory(str, Enum):
    BUG_REPORT = "bug_report"            # バグ・クラッシュ報告
    FEATURE_REQUEST = "feature_request"  # 機能要望
    UX_FEEDBACK = "ux_feedback"          # 使いやすさへの意見
    PERFORMANCE = "performance"          # 速度・負荷の問題
    PRAISE = "praise"                    # 称賛・ポジティブ
    OTHER = "other"                      # その他

class ReviewAnalysis(BaseModel):
    sentiment_score: float               # -1.0（強い不満）〜 1.0（強い称賛）
    category: ReviewCategory
    priority: Literal["high", "medium", "low"]
    key_issue: str                       # 1文で問題をまとめたもの
    should_respond: bool                 # 返信で評価変更を期待できるか
    reasoning: str                       # 判断根拠
```

`reasoning` フィールドがポイントです。なぜそのカテゴリ・優先度にしたかを出力させることで分類精度が上がります（Chain of Thought の一種）。後で分類結果をレビューするときにも役立ちます。

## 分析関数の実装

```python
import google.generativeai as genai
from google.generativeai import GenerativeModel

def analyze_review(review_text: str, app_name: str = "このアプリ") -> ReviewAnalysis:
    model = GenerativeModel(
        model_name="gemini-2.5-pro",
        generation_config=genai.GenerationConfig(
            response_mime_type="application/json",
            response_schema=ReviewAnalysis,
        )
    )
    
    prompt = f"""以下は「{app_name}」というアプリのユーザーレビューです。

レビュー本文:
{review_text}

このレビューを分析してください。

判断基準:
- sentiment_score: -1.0（強い不満）から1.0（強い称賛）の連続値
- priority: high=複数ユーザーに影響する問題, medium=特定ユーザーへの影響, low=提案・マイナーな意見
- should_respond: 誤解に基づく低評価、修正済みバグ報告、感謝に値するフィードバックの場合はtrue
"""
    
    response = model.generate_content(prompt)
    return response.parsed
```

## 複数レビューをバッチ処理する

1件ずつ API を叩くのはコストが高いので、複数件をまとめて処理するバッチ版も作ります。

```python
from typing import List, Dict
import time

def analyze_reviews_batch(
    reviews: List[str],
    app_name: str = "このアプリ",
    delay_seconds: float = 0.5
) -> List[Dict]:
    results = []
    
    for i, review_text in enumerate(reviews):
        try:
            analysis = analyze_review(review_text, app_name)
            results.append({
                "review": review_text,
                "analysis": analysis.model_dump(),
                "success": True
            })
        except Exception as e:
            results.append({
                "review": review_text,
                "error": str(e),
                "success": False
            })
        
        if i < len(reviews) - 1:
            time.sleep(delay_seconds)
    
    return results

# 実行例
sample_reviews = [
    "最近アップデートしてから起動するたびにクラッシュします。以前のバージョンに戻したい",
    "シンプルで使いやすい！ただウィジェットがあれば完璧でした",
    "読み込みが遅すぎる。WiFiでも10秒以上かかることがある",
    "毎日使ってます。デザインが好きで手放せません",
]

results = analyze_reviews_batch(sample_reviews, app_name="MyApp")

for r in results:
    if r["success"]:
        a = r["analysis"]
        print(f"優先度: {a['priority']} | カテゴリ: {a['category']} | 感情: {a['sentiment_score']:.2f}")
        print(f"  課題: {a['key_issue']}")
        print(f"  返信推奨: {'はい' if a['should_respond'] else 'いいえ'}")
```

出力例：

```
優先度: high | カテゴリ: bug_report | 感情: -0.85
  課題: アップデート後に起動時クラッシュが発生している
  返信推奨: はい

優先度: low | カテゴリ: feature_request | 感情: 0.72
  課題: ウィジェット機能の要望
  返信推奨: いいえ
```

## Google スプレッドシートへの書き出し

```python
import gspread
from google.oauth2.service_account import Credentials
from datetime import datetime

def export_to_sheets(results: List[Dict], spreadsheet_id: str):
    scopes = [
        "https://spreadsheets.google.com/feeds",
        "https://www.googleapis.com/auth/drive"
    ]
    creds = Credentials.from_service_account_file(
        "service_account.json", scopes=scopes
    )
    client = gspread.authorize(creds)
    sheet = client.open_by_key(spreadsheet_id).worksheet("review_analysis")
    
    rows = []
    for r in results:
        if not r["success"]:
            continue
        a = r["analysis"]
        rows.append([
            datetime.now().strftime("%Y-%m-%d"),
            r["review"][:100],
            a["sentiment_score"],
            a["category"],
            a["priority"],
            a["key_issue"],
            "はい" if a["should_respond"] else "いいえ",
            a["reasoning"]
        ])
    
    sheet.append_rows(rows)
    print(f"✅ {len(rows)}件を書き出しました")
```

## 2ヶ月使って気づいたこと

`reasoning` フィールドはデバッグに使えます。分類が明らかにおかしいとき、Gemini がレビューのどの部分に注目したかが分かります。プロンプトの「判断基準」をチューニングするときに役立ちました。

`should_respond` の精度は思ったより高いです。「誤解に基づく低評価」を拾う確率が人間の判断に近く、返信の優先順位を決める補助として使えています。最終判断は必ず人間がすることが前提ですが、候補を絞る作業は十分任せられます。

コストは Gemini 2.5 Pro で1件あたり約0.002ドル（2026年4月時点）。200件処理しても0.4ドル程度です。Structured Output を使うと「AIの出力を後処理で整形する」手間がなくなります。受け取った瞬間からデータとして使える状態——それが個人開発の小さなワークフローでも、じわじわ効いてきます。
