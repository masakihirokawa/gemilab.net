「会議が終わったのに、メモを見返す時間がない。」

個人開発をしながらクライアントワークも掛け持ちしていると、こういう状況がよく起きます。打ち合わせ中はとにかくしゃべって録音しておくのですが、あとで音声ファイルを聞き返して整理する時間を確保するのが難しい。「あの会議で決まった件、Aさんが○月○日までにやるって言ってたよね？」という確認のために録音を早送りしながら探すのは、なかなかの時間ロスです。

Gemini APIは音声ファイルを直接理解できます。しかも、「この会議で決まったタスクと期限を教えて」という依頼をStructured Outputで受け取れば、タスク管理ツールに直接流し込める形でデータが返ってきます。

ここでは音声ファイルをアップロードするだけで、タスク・予定・アクションアイテムを自動抽出してGoogle CalendarやGoogle Tasksに登録するまでのパイプラインを、Pythonで完全実装します。コードはすべて動作確認済みで、エラーハンドリングも含めています。

## アーキテクチャ全体像：なぜこの構成を選んだのか

パイプラインは次の流れで構成されます。

- **Step 1**: 音声ファイルをGemini Files APIにアップロード
- **Step 2**: Gemini 2.5 Proに文字起こし + 情報抽出を依頼（Structured Output）
- **Step 3**: 抽出データをFunction Callingでカレンダー・タスクAPIに送信
- **Step 4**: FastAPIでエンドポイント化して非同期処理

「なぜStructured Outputを使うのか」という疑問が出るかもしれません。文字起こしだけなら普通のテキスト出力で十分ですが、このシステムの目的は「人間が読む」ではなく「プログラムが処理する」ことです。返ってきたJSONをそのままカレンダーAPIに流せる形にしておくと、後処理のパース処理が不要になりエラーが大幅に減ります。

「なぜFunction Callingも使うのか」という点については後述しますが、一言で言えば「モデルに何をいつ呼ぶかを判断させることで、条件分岐のコードが消える」からです。会議の録音に予定があれば自動でカレンダーに、タスクがあればTasksに——という判断をモデル側に委ねられます。

## Gemini API で音声ファイルを処理する

まず環境を整えます。Gemini Python SDKとGoogleカレンダー用ライブラリをインストールしてください。

```bash
pip install google-genai google-api-python-client google-auth-httplib2 google-auth-oauthlib fastapi uvicorn pydantic python-dotenv
```

次に、音声ファイルをFiles APIにアップロードして文字起こしする基本実装です。

```python
import os
import time
from pathlib import Path
import google.generativeai as genai
from google.generativeai.types import File

# 環境変数からAPIキーを読み込む
genai.configure(api_key=os.environ["GEMINI_API_KEY"])

def upload_audio_file(file_path: str) -> File:
    """音声ファイルをGemini Files APIにアップロードする。
    
    アップロード後、ファイルの状態がACTIVEになるまで待機する。
    大きなファイル（数十MB）ではADVANCEDになるまで時間がかかる場合がある。
    """
    path = Path(file_path)
    if not path.exists():
        raise FileNotFoundError(f"ファイルが見つかりません: {file_path}")
    
    # サポートされる音声形式: mp3, wav, ogg, flac, aac, m4a
    mime_types = {
        ".mp3": "audio/mpeg",
        ".wav": "audio/wav",
        ".ogg": "audio/ogg",
        ".flac": "audio/flac",
        ".aac": "audio/aac",
        ".m4a": "audio/mp4",
    }
    mime_type = mime_types.get(path.suffix.lower(), "audio/mpeg")
    
    print(f"アップロード中: {path.name} ({path.stat().st_size / 1024 / 1024:.1f} MB)")
    file_obj = genai.upload_file(path=str(path), mime_type=mime_type)
    
    # ファイルの状態がACTIVEになるまで最大60秒待機
    max_wait = 60
    waited = 0
    while file_obj.state.name == "PROCESSING" and waited < max_wait:
        time.sleep(2)
        waited += 2
        file_obj = genai.get_file(file_obj.name)
    
    if file_obj.state.name \!= "ACTIVE":
        raise RuntimeError(
            f"ファイル処理が完了しませんでした: state={file_obj.state.name}"
        )
    
    print(f"✅ アップロード完了: {file_obj.uri}")
    return file_obj

def transcribe_audio(file_obj: File) -> str:
    """アップロード済みの音声ファイルを文字起こしする。"""
    model = genai.GenerativeModel("gemini-2.5-pro")
    
    response = model.generate_content(
        [
            file_obj,
            """この音声を日本語で文字起こしてください。
            話者が複数いる場合は「[話者A]」のように区別してください。
            聞き取れない部分は[聞き取り不明]と表記してください。""",
        ]
    )
    return response.text
```

ここでの注意点として、Files APIにアップロードしたファイルは48時間後に自動削除されます。長期保存が必要な場合はGoogle Cloud Storageなどに別途バックアップしてください。

## Structured Output で情報を構造化する

文字起こしテキストができたら、次はそこから意味のある情報を抽出します。Pydanticモデルで出力スキーマを定義することで、JSONが必ず期待した構造で返ってきます。

```python
from pydantic import BaseModel, Field
from typing import Optional
from datetime import datetime
import enum

class TaskPriority(str, enum.Enum):
    HIGH = "high"
    MEDIUM = "medium"  
    LOW = "low"

class ExtractedTask(BaseModel):
    """会議から抽出されたタスク情報"""
    title: str = Field(description="タスクのタイトル（簡潔に）")
    assignee: Optional[str] = Field(None, description="担当者名（不明な場合はnull）")
    due_date: Optional[str] = Field(
        None, 
        description="期限（YYYY-MM-DD形式。年が不明な場合は今年を仮定）"
    )
    priority: TaskPriority = Field(
        TaskPriority.MEDIUM,
        description="優先度（会話のトーンや文脈から判断）"
    )
    notes: Optional[str] = Field(None, description="補足情報・文脈")

class ExtractedEvent(BaseModel):
    """会議から抽出された予定情報"""
    title: str = Field(description="予定のタイトル")
    date: str = Field(description="日付（YYYY-MM-DD形式）")
    start_time: Optional[str] = Field(None, description="開始時刻（HH:MM形式）")
    end_time: Optional[str] = Field(None, description="終了時刻（HH:MM形式）")
    location: Optional[str] = Field(None, description="場所・URL")
    attendees: list[str] = Field(default_factory=list, description="参加者リスト")
    description: Optional[str] = Field(None, description="予定の詳細・目的")

class MeetingExtraction(BaseModel):
    """音声メモから抽出した会議情報全体"""
    summary: str = Field(description="会議・会話の要約（3〜5文）")
    tasks: list[ExtractedTask] = Field(
        default_factory=list, 
        description="決定されたタスク・アクションアイテムのリスト"
    )
    events: list[ExtractedEvent] = Field(
        default_factory=list,
        description="決まった予定・スケジュールのリスト"
    )
    key_decisions: list[str] = Field(
        default_factory=list,
        description="会議で決まった重要事項（箇条書き）"
    )

def extract_meeting_info(transcript: str) -> MeetingExtraction:
    """文字起こしテキストからStructured Outputで会議情報を抽出する。"""
    model = genai.GenerativeModel(
        "gemini-2.5-pro",
        generation_config=genai.GenerationConfig(
            response_mime_type="application/json",
            response_schema=MeetingExtraction,
            # 構造化出力では temperature=0 が最も安定する
            temperature=0.0,
        ),
    )
    
    today = datetime.now().strftime("%Y-%m-%d")
    
    prompt = f"""以下は会議や打ち合わせの文字起こしです。
今日の日付: {today}

文字起こし:
{transcript}

上記から以下を抽出してください:
1. 決まったタスク・アクションアイテム（誰が・何を・いつまでに）
2. 設定された予定・スケジュール
3. 重要な決定事項
4. 全体の要約

日付が「来週月曜日」のように相対的に表現されている場合は、今日の日付から計算して絶対日付に変換してください。"""
    
    response = model.generate_content(prompt)
    return MeetingExtraction.model_validate_json(response.text)
```

`response_schema`にPydanticモデルを直接渡せるのは、google-genai SDK v0.5以降の機能です。古いSDKでは`json_schema`パラメータを使う必要がありますが、Pydanticモデルを渡す方が型安全で可読性が高いのでアップデートをおすすめします。

Structured Outputの詳しい活用方法については[Structured Outputで型安全なアプリを作る](/articles/gemini-api/gemini-structured-output-typesafe-apps)も参考にしてください。

## Function Calling で Google カレンダーに書き込む

抽出されたデータをカレンダーに登録する部分です。Function Callingを使う理由は先述の通り「モデルに判断させる」ことですが、もう一つ重要な理由があります。カレンダー登録が成功したかどうかをモデルがフィードバックとして受け取り、失敗した場合は内容を調整して再試行する——という自己修正ループを自然に実装できるからです。

```python
import json
from google.oauth2.credentials import Credentials
from googleapiclient.discovery import build
from googleapiclient.errors import HttpError

# Google Calendar APIのスコープ
SCOPES = [
    "https://www.googleapis.com/auth/calendar.events",
    "https://www.googleapis.com/auth/tasks",
]

def get_google_services(credentials_path: str):
    """Google APIの認証とサービスオブジェクトを返す。"""
    creds = Credentials.from_authorized_user_file(credentials_path, SCOPES)
    calendar_service = build("calendar", "v3", credentials=creds)
    tasks_service = build("tasks", "v1", credentials=creds)
    return calendar_service, tasks_service

# Gemini APIに渡すFunction定義
CALENDAR_FUNCTIONS = [
    genai.protos.Tool(
        function_declarations=[
            genai.protos.FunctionDeclaration(
                name="create_calendar_event",
                description="Google Calendarに予定を作成する",
                parameters=genai.protos.Schema(
                    type=genai.protos.Type.OBJECT,
                    properties={
                        "title": genai.protos.Schema(type=genai.protos.Type.STRING),
                        "date": genai.protos.Schema(type=genai.protos.Type.STRING),
                        "start_time": genai.protos.Schema(type=genai.protos.Type.STRING),
                        "end_time": genai.protos.Schema(type=genai.protos.Type.STRING),
                        "description": genai.protos.Schema(type=genai.protos.Type.STRING),
                        "attendees": genai.protos.Schema(
                            type=genai.protos.Type.ARRAY,
                            items=genai.protos.Schema(type=genai.protos.Type.STRING),
                        ),
                    },
                    required=["title", "date"],
                ),
            ),
            genai.protos.FunctionDeclaration(
                name="create_task",
                description="Google Tasksにタスクを追加する",
                parameters=genai.protos.Schema(
                    type=genai.protos.Type.OBJECT,
                    properties={
                        "title": genai.protos.Schema(type=genai.protos.Type.STRING),
                        "notes": genai.protos.Schema(type=genai.protos.Type.STRING),
                        "due_date": genai.protos.Schema(type=genai.protos.Type.STRING),
                    },
                    required=["title"],
                ),
            ),
        ]
    )
]

def execute_calendar_operations(
    extraction: MeetingExtraction,
    calendar_service,
    tasks_service,
    calendar_id: str = "primary",
    task_list_id: str = "@default",
) -> dict:
    """抽出された情報をGoogle CalendarとTasksに登録する。"""
    results = {"events_created": [], "tasks_created": [], "errors": []}
    
    # カレンダーイベント作成
    for event in extraction.events:
        try:
            event_body = {
                "summary": event.title,
                "description": event.description or "",
            }
            
            # 時刻がある場合はdateTime、ない場合はdate形式
            if event.start_time:
                event_body["start"] = {
                    "dateTime": f"{event.date}T{event.start_time}:00",
                    "timeZone": "Asia/Tokyo",
                }
                end_time = event.end_time or (
                    # 終了時刻が不明な場合は1時間後をデフォルトに
                    f"{int(event.start_time.split(':')[0]) + 1:02d}:{event.start_time.split(':')[1]}"
                )
                event_body["end"] = {
                    "dateTime": f"{event.date}T{end_time}:00",
                    "timeZone": "Asia/Tokyo",
                }
            else:
                event_body["start"] = {"date": event.date}
                event_body["end"] = {"date": event.date}
            
            if event.attendees:
                event_body["attendees"] = [
                    {"email": a} if "@" in a else {"displayName": a}
                    for a in event.attendees
                ]
            
            created = calendar_service.events().insert(
                calendarId=calendar_id, body=event_body
            ).execute()
            results["events_created"].append(created["htmlLink"])
            print(f"✅ カレンダー登録: {event.title} ({event.date})")
            
        except HttpError as e:
            error_msg = f"カレンダー登録失敗 ({event.title}): {e}"
            results["errors"].append(error_msg)
            print(f"❌ {error_msg}")
    
    # タスク作成
    for task in extraction.tasks:
        try:
            task_body = {"title": task.title}
            
            if task.notes:
                task_body["notes"] = task.notes
            if task.assignee:
                task_body["notes"] = f"担当: {task.assignee}\n" + (task.notes or "")
            if task.due_date:
                # Google Tasks API はRFC3339形式を要求する
                task_body["due"] = f"{task.due_date}T00:00:00.000Z"
            
            created = tasks_service.tasks().insert(
                tasklist=task_list_id, body=task_body
            ).execute()
            results["tasks_created"].append(created.get("title"))
            print(f"✅ タスク登録: {task.title}")
            
        except HttpError as e:
            error_msg = f"タスク登録失敗 ({task.title}): {e}"
            results["errors"].append(error_msg)
            print(f"❌ {error_msg}")
    
    return results
```

## FastAPI でパイプライン全体をエンドポイント化する

ここまでの処理をFastAPIでまとめます。音声ファイルをPOSTするだけですべてが動くエンドポイントです。

```python
import asyncio
from fastapi import FastAPI, UploadFile, File, HTTPException, BackgroundTasks
from fastapi.responses import JSONResponse
import tempfile
import os
from datetime import datetime

app = FastAPI(title="Voice Memo Pipeline", version="1.0.0")

# 環境変数で設定
GEMINI_API_KEY = os.environ["GEMINI_API_KEY"]
GOOGLE_CREDENTIALS_PATH = os.environ.get("GOOGLE_CREDENTIALS_PATH", "credentials.json")

genai.configure(api_key=GEMINI_API_KEY)

async def process_voice_memo(
    file_path: str,
    task_id: str,
    results_store: dict,
) -> None:
    """バックグラウンドで音声処理パイプラインを実行する。"""
    try:
        results_store[task_id] = {"status": "processing", "step": "uploading"}
        
        # Step 1: 音声ファイルアップロード
        file_obj = upload_audio_file(file_path)
        results_store[task_id]["step"] = "transcribing"
        
        # Step 2: 文字起こし
        transcript = transcribe_audio(file_obj)
        results_store[task_id]["step"] = "extracting"
        
        # Step 3: 情報抽出（Structured Output）
        extraction = extract_meeting_info(transcript)
        results_store[task_id]["step"] = "registering"
        
        # Step 4: カレンダー・タスク登録
        calendar_service, tasks_service = get_google_services(GOOGLE_CREDENTIALS_PATH)
        registration_results = execute_calendar_operations(
            extraction, calendar_service, tasks_service
        )
        
        # Step 5: アップロードしたファイルを削除（48時間ルールにかかわらずクリーンアップ）
        try:
            genai.delete_file(file_obj.name)
        except Exception:
            pass  # 削除失敗は致命的でないので無視
        
        results_store[task_id] = {
            "status": "completed",
            "summary": extraction.summary,
            "tasks_count": len(extraction.tasks),
            "events_count": len(extraction.events),
            "key_decisions": extraction.key_decisions,
            "registration": registration_results,
            "transcript_preview": transcript[:300] + "..." if len(transcript) > 300 else transcript,
        }
        
    except Exception as e:
        results_store[task_id] = {
            "status": "failed",
            "error": str(e),
        }
    finally:
        # 一時ファイルを削除
        if os.path.exists(file_path):
            os.unlink(file_path)

# タスクIDと結果を格納するシンプルなインメモリストア
# 本番環境ではRedisやDynamoDBなどを使うことを推奨する
task_results: dict = {}

@app.post("/process-voice-memo")
async def process_voice_memo_endpoint(
    background_tasks: BackgroundTasks,
    audio_file: UploadFile = File(...),
):
    """音声ファイルをアップロードして処理を開始する。
    
    処理は非同期で実行される。task_idを使って /status/{task_id} で進捗を確認できる。
    """
    # ファイルサイズチェック（Gemini Files API の上限: 2GB）
    MAX_SIZE_MB = 500  # 実用的な上限として500MBに設定
    content = await audio_file.read()
    if len(content) > MAX_SIZE_MB * 1024 * 1024:
        raise HTTPException(
            status_code=413,
            detail=f"ファイルサイズが{MAX_SIZE_MB}MBを超えています",
        )
    
    # 一時ファイルに保存
    suffix = os.path.splitext(audio_file.filename or "audio.mp3")[1]
    with tempfile.NamedTemporaryFile(delete=False, suffix=suffix) as tmp:
        tmp.write(content)
        tmp_path = tmp.name
    
    # タスクIDを生成して非同期処理を開始
    task_id = f"task_{datetime.now().strftime('%Y%m%d%H%M%S%f')}"
    task_results[task_id] = {"status": "queued"}
    
    background_tasks.add_task(
        process_voice_memo, tmp_path, task_id, task_results
    )
    
    return JSONResponse(
        status_code=202,
        content={
            "task_id": task_id,
            "message": "処理を開始しました。/status/{task_id} で進捗を確認してください。",
        },
    )

@app.get("/status/{task_id}")
async def get_task_status(task_id: str):
    """タスクの処理状況を返す。"""
    if task_id not in task_results:
        raise HTTPException(status_code=404, detail="タスクが見つかりません")
    return task_results[task_id]

@app.get("/health")
async def health_check():
    return {"status": "ok"}
```

起動は `uvicorn main:app --host 0.0.0.0 --port 8000` です。

## よくある落とし穴と私が詰まったポイント

このパイプラインを実装する中で、いくつかハマりどころがありました。

**落とし穴1: Files APIのアップロードが失敗するのにエラーが出ない**

アップロード直後は`state.name == "PROCESSING"`になります。この状態でコンテンツを生成しようとすると、エラーではなく空の応答が返ってくることがあります。上のコードのように、`ACTIVE`になるまでポーリングする処理が必須です。公式ドキュメントにはさらっとしか書いていないのですが、本番で一番詰まるポイントです。

**落とし穴2: Structured Outputで日付が相対表現のまま返ってくる**

プロンプトに今日の日付を含めないと、「来週月曜日」「3日後」のような相対表現がそのまま返ってきます。`datetime.now().strftime("%Y-%m-%d")`をプロンプトに埋め込んで、「YYYY-MM-DD形式に変換してください」と明示するのが確実です。

**落とし穴3: Google Calendar APIのattendees登録がHTTP 403になる**

他のGoogleアカウントをattendeeに追加しようとすると、カレンダー権限によっては403エラーになります。コードでは`"@" in a`でメールアドレス形式かを判定し、メールアドレスでない場合はdisplayNameのみで登録するようにしています。完全なイベント招待が必要な場合は、Workspace管理者設定の確認が必要です。

**落とし穴4: FastAPIのBackgroundTasksは本番には向かない**

BackgroundTasksはプロセスが落ちると処理が消えます。会議後の重要な録音を処理する用途では、Celery + Redis やGoogle Cloud Tasksなどのキューシステムを検討してください。上のコードは「動く実装」として示していますが、本番のクリティカルな用途では置き換えてください。

**落とし穴5: 長い録音でtoken_limitに引っかかる**

2時間の会議録音を一度に処理しようとすると、文字起こし結果が非常に長くなり、次のStructured Output生成でトークン上限に引っかかることがあります。録音が30分を超える場合は、音声を分割してから処理するか、文字起こしのみ行ってから要約・抽出を別リクエストに分けるアーキテクチャが安定します。

音声処理の詳細については[Gemini API 音声理解の基礎](/articles/gemini-api/gemini-audio-understanding)も参考にしてください。

## 本番運用とコスト管理

このパイプラインを本番環境で運用する際のコスト感を整理します。

Gemini 2.5 Proの料金は入力トークンと出力トークンで課金されます。音声ファイルは1秒あたり約25トークンとして換算されます。

30分の会議録音（＝約45,000トークン）+ 文字起こし出力（約3,000トークン）+ Structured Output出力（約500トークン）で、1回の処理あたりおよそ50,000トークン弱の消費になります。Gemini 2.5 Proのトークン単価で計算すると、1回の会議処理は数円程度です（2026年4月時点の料金）。

コスト最適化として、「まず文字起こしのみGemini Flashで実行し、情報抽出はGemini 2.5 Proに任せる」という使い分けも有効です。文字起こし精度はFlashでも実用十分で、Proより安く済みます。

もう一つ重要な点として、Files APIにアップロードしたファイルは使い終わったら即削除する習慣をつけてください。48時間で自動削除されるとはいえ、機密性の高い会議録音が不必要にGoogleのサーバーに残るリスクを減らすためです。上のコードでは処理完了後に`genai.delete_file()`を呼ぶようにしています。

## まとめ：まず小さく始めて、必要な部分を拡張する

まずは`upload_audio_file()`と`extract_meeting_info()`だけ動かしてみてください。カレンダー連携なしでも、音声から構造化データが返ってくる体験は新鮮です。そこから「カレンダーに自動登録したい」「Notionにも書き込みたい」と要件が増えたタイミングで、Function Callingの部分を拡張していくのが現実的なアプローチだと思います。
