## Gemini API トークン上限超過エラーとは

Gemini API を使って大きなドキュメントや長い会話履歴を送信したとき、次のようなエラーに遭遇することがあります。

```
google.api_core.exceptions.InvalidArgument: 400
Request contains too many tokens. Please reduce the input size.
```

```json
{
  "error": {
    "code": 400,
    "message": "Request payload size exceeds the limit: XXXXX tokens > YYYYY token limit",
    "status": "INVALID_ARGUMENT"
  }
}
```

このエラーは「送信したリクエストのトークン数がモデルの入力上限を超えている」ことを意味しています。Gemini モデルにはそれぞれコンテキストウィンドウの上限があり、入力トークン＋出力トークンの合計がこの上限を超えるとリクエストが拒否されます。

大量のテキストを処理したい場面、複数ファイルをまとめて解析したい場面、長時間のチャット履歴を維持したい場面など、実務でよく発生する問題です。この記事では、原因の特定から具体的な解決手順、再発防止策まで体系的に解説します。

## 各モデルのトークン上限を正しく把握する

まず、使用しているモデルのトークン上限を確認しましょう。2026年4月時点の主要モデルの上限は以下の通りです。

- **Gemini 2.5 Pro**: 入力 1,048,576 トークン（約100万トークン）、出力 65,536 トークン
- **Gemini 2.5 Flash**: 入力 1,048,576 トークン、出力 65,536 トークン
- **Gemini 2.0 Flash**: 入力 1,048,576 トークン、出力 8,192 トークン
- **Gemini 1.5 Pro**: 入力 2,097,152 トークン（約200万トークン）、出力 8,192 トークン
- **Gemini 1.5 Flash**: 入力 1,048,576 トークン、出力 8,192 トークン

注意すべき点として、コンテキストウィンドウは「入力＋出力の合計」で計算されます。たとえば入力上限が100万トークンのモデルに95万トークンを送信し、出力上限の65,536トークンをリクエストすると、合計が上限を超えてエラーになる可能性があります。

また、モデルの仕様は頻繁にアップデートされるため、[公式ドキュメント](https://ai.google.dev/gemini-api/docs/models/gemini)で最新の数値を確認することをおすすめします。

## エラーの原因を特定する5つのパターン

トークン上限超過エラーが発生する原因は、大きく5つのパターンに分けられます。

### パターン1: 入力テキストが単純に大きすぎる

最も多い原因です。長い文書、複数ファイルの同時解析、大量のコードベース分析などで発生します。特に PDF や画像をマルチモーダル入力した場合、テキストに変換された後のトークン数が想定以上に膨らむことがあります。

### パターン2: チャット履歴の蓄積

マルチターン会話で `contents` 配列に過去のやり取りをすべて含めていると、会話が長くなるにつれてトークン数が累積し、いつかは上限に達します。

### パターン3: システムインストラクションの肥大化

`system_instruction` に詳細なルールやサンプル出力を大量に含めているケースです。システムインストラクションも入力トークンとしてカウントされます。

### パターン4: Function Calling の定義が多すぎる

ツール定義（`tools` パラメータ）もトークンを消費します。数十個のツールを定義していると、それだけで数千〜数万トークンを使ってしまいます。

### パターン5: 出力トークン上限の設定ミス

`max_output_tokens` を極端に大きく設定した場合、入力＋出力の合計がコンテキストウィンドウを超える計算になりエラーが発生します。

## 解決手順 Step by Step

原因が特定できたら、以下の手順で解決していきましょう。

### Step 1: 事前にトークン数をカウントする

リクエストを送信する前に、`countTokens` API で正確なトークン数を確認します。これにより、エラーを未然に防ぐことができます。

```python
# Python: トークン数の事前カウント
from google import genai

client = genai.Client(api_key="YOUR_API_KEY")

# テキストのトークン数をカウント
response = client.models.count_tokens(
    model="gemini-2.5-flash",
    contents="ここに送信したいテキストを入れる"
)
print(f"トークン数: {response.total_tokens}")
# 出力例: トークン数: 1523

# チャット履歴を含めたカウント
chat_contents = [
    {"role": "user", "parts": [{"text": "こんにちは"}]},
    {"role": "model", "parts": [{"text": "こんにちは！何かお手伝いできますか？"}]},
    {"role": "user", "parts": [{"text": "長い文書を要約してください..."}]},
]
response = client.models.count_tokens(
    model="gemini-2.5-flash",
    contents=chat_contents
)
print(f"会話全体のトークン数: {response.total_tokens}")
# 出力例: 会話全体のトークン数: 4821
```

```javascript
// JavaScript: トークン数の事前カウント
const { GoogleGenAI } = require("@google/genai");

const ai = new GoogleGenAI({ apiKey: "YOUR_API_KEY" });

async function checkTokens() {
  const response = await ai.models.countTokens({
    model: "gemini-2.5-flash",
    contents: "ここに送信したいテキストを入れる",
  });
  console.log(`トークン数: ${response.totalTokens}`);
  // 出力例: トークン数: 1523
}

checkTokens();
```

### Step 2: 入力を分割して処理する

大きなドキュメントを一度に送信できない場合は、チャンク（分割単位）に分けて処理します。

```python
# Python: 大きなテキストをチャンクに分割して処理
from google import genai

client = genai.Client(api_key="YOUR_API_KEY")

def split_text_by_tokens(text, max_tokens=500000):
    """テキストをトークン上限以下のチャンクに分割"""
    paragraphs = text.split("\n\n")
    chunks = []
    current_chunk = ""

    for para in paragraphs:
        test_chunk = current_chunk + "\n\n" + para if current_chunk else para

        # トークン数を確認
        count_response = client.models.count_tokens(
            model="gemini-2.5-flash",
            contents=test_chunk
        )

        if count_response.total_tokens > max_tokens and current_chunk:
            chunks.append(current_chunk)
            current_chunk = para
        else:
            current_chunk = test_chunk

    if current_chunk:
        chunks.append(current_chunk)

    return chunks

# 使用例
long_document = open("large_document.txt", "r").read()
chunks = split_text_by_tokens(long_document)

summaries = []
for i, chunk in enumerate(chunks):
    response = client.models.generate_content(
        model="gemini-2.5-flash",
        contents=f"以下のテキストの要点を箇条書きで要約してください:\n\n{chunk}"
    )
    summaries.append(response.text)
    print(f"チャンク {i+1}/{len(chunks)} 処理完了")

# 各チャンクの要約を統合
final_response = client.models.generate_content(
    model="gemini-2.5-flash",
    contents=f"以下の部分要約を統合し、全体の要約を作成してください:\n\n{'---'.join(summaries)}"
)
print(final_response.text)
```

### Step 3: チャット履歴を適切に管理する

長いマルチターン会話では、古い履歴をトリミングする仕組みが必要です。

```python
# Python: チャット履歴のスライディングウィンドウ管理
from google import genai

client = genai.Client(api_key="YOUR_API_KEY")
MODEL = "gemini-2.5-flash"
MAX_HISTORY_TOKENS = 800000  # 上限の約80%に設定

chat_history = []

def add_and_trim_history(role, text):
    """履歴を追加し、トークン上限を超えたら古い履歴を削除"""
    chat_history.append({"role": role, "parts": [{"text": text}]})

    # トークン数をチェック
    count = client.models.count_tokens(
        model=MODEL,
        contents=chat_history
    )

    # 上限を超えていたら先頭（最も古い）のやり取りから削除
    while count.total_tokens > MAX_HISTORY_TOKENS and len(chat_history) > 2:
        # ユーザー＋モデルのペアで削除
        chat_history.pop(0)
        chat_history.pop(0)
        count = client.models.count_tokens(
            model=MODEL,
            contents=chat_history
        )

    print(f"現在のトークン数: {count.total_tokens} / {MAX_HISTORY_TOKENS}")

def chat(user_message):
    """トークン管理付きチャット"""
    add_and_trim_history("user", user_message)

    response = client.models.generate_content(
        model=MODEL,
        contents=chat_history
    )

    assistant_message = response.text
    add_and_trim_history("model", assistant_message)
    return assistant_message

# 使用例
print(chat("Gemini APIの使い方を教えてください"))
print(chat("具体的なPythonコードを見せてください"))
# ...長い会話が続いても自動的にトリミングされる
```

### Step 4: コンテキストキャッシュを活用する

同じシステムインストラクションや参照ドキュメントを複数リクエストで使い回す場合、コンテキストキャッシュが有効です。キャッシュされたトークンは入力上限に含まれますが、コストが大幅に下がります。

```python
# Python: コンテキストキャッシュの活用
from google import genai
from google.genai import types
import datetime

client = genai.Client(api_key="YOUR_API_KEY")

# 大きなドキュメントをキャッシュ
large_doc = open("reference_manual.txt", "r").read()

cache = client.caches.create(
    model="gemini-2.5-flash",
    config=types.CreateCachedContentConfig(
        display_name="Reference Manual Cache",
        system_instruction="あなたは技術ドキュメントの専門家です。",
        contents=[{"role": "user", "parts": [{"text": large_doc}]}],
        ttl=datetime.timedelta(hours=1),  # キャッシュの有効期限
    ),
)

print(f"キャッシュ作成完了: {cache.name}")
print(f"キャッシュトークン数: {cache.usage_metadata.total_token_count}")

# キャッシュを使ってリクエスト（入力トークン消費なし）
response = client.models.generate_content(
    model="gemini-2.5-flash",
    contents="マニュアルの第3章を要約してください",
    config=types.GenerateContentConfig(
        cached_content=cache.name
    ),
)
print(response.text)
```

## 解決できたかの検証手順

修正を適用したら、以下の手順で問題が解決したことを確認しましょう。

1. **トークン数の事前チェック**: `countTokens` で入力トークン数がモデル上限の90%以内であることを確認する
2. **小さな入力でテスト**: まず短いテキストでリクエストが正常に通ることを確認する
3. **段階的にサイズを増やす**: 入力サイズを徐々に増やし、境界付近での挙動を確認する
4. **エラーハンドリングの検証**: 意図的に大きな入力を送り、`try/except` で適切にキャッチできることを確認する

```python
# 検証用コード: エラーハンドリングの動作確認
from google import genai
from google.api_core import exceptions

client = genai.Client(api_key="YOUR_API_KEY")

def safe_generate(text, model="gemini-2.5-flash"):
    """トークン上限チェック付きの安全な生成"""
    # 事前チェック
    count = client.models.count_tokens(model=model, contents=text)
    print(f"入力トークン数: {count.total_tokens}")

    if count.total_tokens > 900000:  # 上限の約90%
        print("⚠️ 警告: トークン数が上限に近いです。分割処理を検討してください。")

    try:
        response = client.models.generate_content(
            model=model,
            contents=text
        )
        print("✅ リクエスト成功")
        return response.text
    except exceptions.InvalidArgument as e:
        print(f"❌ トークン上限超過: {e}")
        return None
    except exceptions.ResourceExhausted as e:
        print(f"❌ レート制限: {e}")
        return None

# テスト実行
result = safe_generate("Gemini APIについて教えてください")
print(result)
# 出力例:
# 入力トークン数: 15
# ✅ リクエスト成功
```

## 再発防止のベストプラクティス

トークン上限超過エラーを根本から防ぐために、以下のプラクティスを開発フローに組み込みましょう。

**リクエスト前の必須チェック**: すべてのAPI呼び出しの前に `countTokens` を実行し、上限の90%を超えていたら警告を出す仕組みを入れます。本番環境ではこのチェックを自動化しておくと安心です。

**チャット履歴の自動トリミング**: マルチターン会話では、Step 3で紹介したスライディングウィンドウ方式を必ず実装してください。「直近N件」を保持するだけでなく、トークンベースで管理するのがポイントです。

**モデル選択の最適化**: すべての処理で最大モデルを使う必要はありません。短い質問には Gemini 2.5 Flash を、大量ドキュメント処理には入力上限の大きい Gemini 2.5 Pro を使い分けると効率的です。

**システムインストラクションのダイエット**: 何千文字ものシステムインストラクションを設定している場合は、本当に必要な指示だけに絞り込みましょう。具体例をたくさん含めるよりも、簡潔なルールの方がモデルは従いやすいです。

**Function Calling の定義を最小化**: 使用するツール定義は、そのリクエストで実際に必要なものだけに限定します。すべてのツールを毎回渡す設計は避け、用途に応じてツールセットを切り替える実装にしましょう。

トークン数の管理についてさらに詳しく知りたい方は「[Gemini トークンカウント API ガイド — コスト管理と最適化](/articles/gemini-api/gemini-token-counting)」が参考になります。

## よくある質問（FAQ）

### Q1: 画像や動画を送信した場合のトークン数はどう計算されますか？

画像は解像度に応じてトークンに換算されます。一般的な画像1枚は約258トークン（固定）です。ただし、高解像度の画像はタイル分割され、1タイルあたり258トークンが加算されます。動画は1秒あたり約263トークンで換算されます。正確な値は `countTokens` API で事前に確認してください。

### Q2: コンテキストウィンドウが大きいモデルに切り替えれば解決しますか？

場合によっては有効です。Gemini 2.5 Pro は100万トークンの入力に対応しており、多くのユースケースで十分です。ただし、コンテキストウィンドウが大きいほどレスポンス時間が長くなる傾向があるため、不必要に大きなモデルを使うよりも入力を最適化する方が望ましいです。

### Q3: `max_output_tokens` を指定しないとどうなりますか？

指定しない場合、モデルのデフォルト値（多くの場合8,192トークン）が適用されます。明示的に設定しない場合でもコンテキストウィンドウの計算には影響するため、必要な出力量に合わせて適切に設定することをおすすめします。

### Q4: File API でアップロードしたファイルのトークン数も上限に含まれますか？

はい、File API でアップロードしたファイルの内容もトークンとしてカウントされます。大きなファイルを複数アップロードする場合は、`countTokens` で事前にトークン数を確認し、必要に応じてファイルを分割して処理してください。

### Q5: エラーメッセージに表示されるトークン数と countTokens の結果が一致しないのですが？

これは既知の差異です。`countTokens` API はテキスト部分のみをカウントしますが、実際のリクエストではシステムインストラクション、ツール定義、セーフティ設定などの内部メタデータも含まれます。そのため、`countTokens` の結果より実際の消費トークン数がやや大きくなります。余裕を持って上限の90%以内に収めるのが安全です。
