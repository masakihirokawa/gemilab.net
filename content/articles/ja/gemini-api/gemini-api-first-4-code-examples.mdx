Gemini APIキーを取得したあとに「何を試せばいいのか分からない」と感じたこと、私にもありました。公式ドキュメントは丁寧ですが、どこから手をつければよいかの地図がなくて、最初の数日は迷子になりがちです。

ここでは私が実際に「これを最初に試しておけばよかった」と思ったコード例を4つ紹介します。テキスト生成・ストリーミング・画像解析・構造化出力という順番で進めると、Gemini APIの基本的な動作パターンが自然に身につくと思います。

---

## 準備：パッケージのインストールとAPIキーの設定

まずは `google-genai` パッケージをインストールします。

```bash
pip install google-genai
```

APIキーは [Google AI Studio](https://aistudio.google.com/app/apikey) から取得できます。環境変数に設定しておくと安全です。

```bash
export GEMINI_API_KEY="YOUR_GEMINI_API_KEY"
```

コード内では以下のようにクライアントを初期化します。

```python
import os
from google import genai

client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])
```

この `client` オブジェクトを使い回すのが基本パターンです。毎回初期化するのではなく、スクリプトや関数の先頭で1度だけ作成しておきましょう。

## 1. テキスト生成：まず動かしてみる

最もシンプルなパターンです。モデルにプロンプトを渡して応答を受け取ります。

```python
import os
from google import genai

client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])

# テキスト生成の基本パターン
response = client.models.generate_content(
    model="gemini-2.0-flash",
    contents="Pythonでファイルを読み込む最も一般的な方法を教えてください。"
)

print(response.text)
# 出力例:
# Pythonでファイルを読み込む最も一般的な方法は `with open()` 構文を使う方法です。
# ...
```

`gemini-2.0-flash` は無料枠でも十分な精度があり、応答も速いのでテスト用途に最適です。本番で精度が必要な場合は `gemini-2.5-pro` に切り替えます。

### このコードで分かること

- `generate_content()` の最小の使い方
- `response.text` でテキストを取り出す方法
- モデル名の指定の仕方

エラーが出た場合、まず `response.text` を直接 `print(response)` に変えてレスポンスオブジェクト全体を確認してみてください。安全フィルターによるブロックや認証エラーの詳細が分かります。

## 2. ストリーミング：応答をリアルタイムに受け取る

長い応答を一括で待つのではなく、生成されるたびに逐次受け取れるのがストリーミングです。チャットアプリやCLIツールを作るときに特に便利です。

```python
import os
from google import genai

client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])

# ストリーミングで逐次受信
for chunk in client.models.generate_content_stream(
    model="gemini-2.0-flash",
    contents="Pythonの非同期処理（asyncio）について300文字で説明してください。"
):
    # chunk.text が None でないことを確認してから出力
    if chunk.text:
        print(chunk.text, end="", flush=True)

print()  # 最後に改行
# 出力例（少しずつ表示される）:
# Pythonの非同期処理はasyncioモジュールを使って実装します...
```

ストリーミングで意外と詰まるのが `chunk.text` が `None` になるケースです。最後のチャンクや安全フィルターの情報チャンクでは `None` が返ることがあるため、必ず `if chunk.text:` でガードしてください。

### ストリーミングを使うべき場面

- ユーザーに待ち時間を感じさせたくない場合
- 応答が長い（500文字超）場合
- WebSocketやSSEで逐次配信する場合

逆に、後続の処理でテキスト全体が必要な場合（ファイルへの書き出しなど）は通常の `generate_content()` のほうがシンプルです。

## 3. 画像解析：マルチモーダルの入り口

Geminiのマルチモーダル能力を試すなら、画像解析が一番手軽です。ローカルの画像ファイルを渡してその内容を解説させてみましょう。

```python
import os
from pathlib import Path
from google import genai
from google.genai import types

client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])

# ローカル画像を読み込む（PNG/JPEG/WebP/HEIC に対応）
image_path = Path("sample.jpg")  # 試したい画像に変更してください
image_data = image_path.read_bytes()

response = client.models.generate_content(
    model="gemini-2.0-flash",
    contents=[
        types.Part.from_bytes(data=image_data, mime_type="image/jpeg"),
        "この画像に写っているものを日本語で説明してください。"
    ]
)

print(response.text)
# 出力例（写真の内容による）:
# 画像には机の上に置かれたコーヒーカップが写っています。カップは白...
```

`contents` をリスト形式にして、画像パートとテキストパートを混在させるのがポイントです。画像は `from_bytes` に `mime_type` を指定して渡します。

### 試してみると面白い活用例

- スクリーンショットのUI要素を言語化する
- 手書きメモを文字起こしする
- 商品写真から説明文を自動生成する

私が最初に試したとき、アプリのスクリーンショットから「このUIにあるボタンのAccessibilityを改善するには？」と聞いたら、思いのほか具体的なフィードバックが返ってきて驚いた経験があります。

## 4. 構造化出力：JSONを確実に受け取る

「回答をJSON形式で返して」とプロンプトで依頼しても、Geminiが気を利かせてMarkdownのコードブロックで包んでしまうことがあります。構造化出力機能を使えば、後処理不要でパース可能なJSONが手に入ります。

```python
import os
from google import genai
from google.genai import types
import json

client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])

# JSON Schemaを指定して構造化出力を要求する
response = client.models.generate_content(
    model="gemini-2.0-flash",
    contents="Pythonのデータ型を3つ挙げて、名前と簡単な説明をJSON形式で返してください。",
    config=types.GenerateContentConfig(
        response_mime_type="application/json",
        response_schema={
            "type": "array",
            "items": {
                "type": "object",
                "properties": {
                    "name": {"type": "string"},
                    "description": {"type": "string"}
                },
                "required": ["name", "description"]
            }
        }
    )
)

# 文字列ではなく、すでにパース可能なJSONが返る
data = json.loads(response.text)
for item in data:
    print(f"{item['name']}: {item['description']}")

# 出力例:
# int: 整数を表すデータ型です
# str: 文字列を表すデータ型です
# list: 複数の要素を順番に格納するデータ型です
```

`response_mime_type="application/json"` と `response_schema` を組み合わせることで、スキーマ通りのJSONが返ってきます。Markdownのコードフェンスを `strip()` で除去するコードが不要になるため、プロダクションコードがずっとシンプルになります。

### 構造化出力が特に役立つ場面

- APIレスポンスをそのままDBに保存したい場合
- フロントエンドに渡す前にデータを整形したい場合
- 複数フィールドを持つオブジェクトを確実に取り出したい場合

## 4つを試して分かったこと

この4つを順番に実行すると、Gemini APIの「使い方の幅」が体感的に掴めます。私が感じたポイントをまとめておきます。

- **ストリーミングは思ったより簡単**: 別のAPIを覚える必要がなく、メソッド名が変わるだけで感覚が変わる
- **マルチモーダルの敷居が低い**: 画像をバイト列で渡すだけで、特別な前処理が要らない
- **構造化出力はプロダクション必須**: プロンプトで「JSON形式で」と頼む時代はもう終わり
- **モデルの切り替えは1行**: `model="gemini-2.5-pro"` に変えるだけで試せるので、コスト感覚が掴みやすい
