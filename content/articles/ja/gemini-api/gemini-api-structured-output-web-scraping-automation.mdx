Web から情報を収集するとき、スクレイピングで取得した HTML の山をどう整形するかで毎回悩む方は多いのではないでしょうか。正規表現を書いて、BeautifulSoup で要素を選んで、辞書に詰め込んで……このパターンを繰り返すうちに、サイトの構造が変わって全部書き直し、という経験をしたことがある方もいらっしゃると思います。

Gemini API の **Structured Output（構造化出力）** を使うと、このプロセスが大きく変わります。「この HTML から商品名・価格・レビュー数を JSON 形式で取り出して」と指示するだけで、サイト構造に依存しない柔軟なデータ抽出が実現できます。本記事では、この組み合わせの実装方法を、実際に動くコードとともに解説します。

## Structured Output とは：型安全なデータ抽出の仕組み

Gemini API の Structured Output は、モデルの出力を **JSON Schema に厳密に合わせる** 機能です。`response_mime_type="application/json"` と `response_schema` を指定するだけで、自由形式のテキストではなく、定義した型に沿った JSON が必ず返ってきます。

従来の Web スクレイピングとの本質的な違いは次の点です。

- **従来**: HTML 構造を解析 → XPath/CSS セレクタで要素を特定 → データを手動整形
- **Gemini + Structured Output**: HTML を丸ごと渡す → 必要なデータの「意味」で抽出 → 型安全な JSON が返る

サイトの構造が変わっても、「商品名」「価格」という意味さえ変わらなければ、抽出ロジックの修正は不要です。これが実務での大きなメリットになります。

## 基本実装：商品データの構造化抽出

まず、Pydantic モデルで抽出したいデータの構造を定義します。

```python
import os
import requests
from bs4 import BeautifulSoup
from pydantic import BaseModel
from typing import Optional
import google.genai as genai
import google.genai.types as types
import json

# --- データモデル定義 ---
class ProductInfo(BaseModel):
    name: str               # 商品名
    price: Optional[str]    # 価格（通貨記号含む）
    rating: Optional[float] # 評価スコア（0〜5）
    review_count: Optional[int]  # レビュー数
    availability: Optional[str]  # 在庫状況
    description: Optional[str]   # 商品説明（100文字以内）

class ProductList(BaseModel):
    products: list[ProductInfo]
    total_found: int
    page_title: str

# --- Gemini クライアント初期化 ---
client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])

def scrape_and_structure(url: str) -> ProductList:
    """URLからHTMLを取得してGeminiで構造化データに変換する"""

    # Step 1: HTML取得
    headers = {"User-Agent": "Mozilla/5.0 (compatible; DataBot/1.0)"}
    response = requests.get(url, headers=headers, timeout=15)
    response.raise_for_status()

    # Step 2: テキスト抽出（不要なタグを除去してトークン節約）
    soup = BeautifulSoup(response.content, "html.parser")
    for tag in soup(["script", "style", "nav", "footer", "header"]):
        tag.decompose()
    # メインコンテンツエリアを優先取得
    main = soup.find("main") or soup.find("article") or soup.find("body")
    clean_text = main.get_text(separator="\n", strip=True)[:8000] if main else ""

    # Step 3: Gemini で構造化抽出
    prompt = f"""
以下のWebページのテキストから、商品情報を抽出してください。
価格は通貨記号を含む表示のまま保持し、評価スコアは数値に変換してください。
見つからない項目はnullとしてください。

ページテキスト:
{clean_text}
"""

    gemini_response = client.models.generate_content(
        model="gemini-2.5-pro",
        contents=prompt,
        config=types.GenerateContentConfig(
            response_mime_type="application/json",
            response_schema=ProductList,
        ),
    )

    # Step 4: Pydanticモデルとして返す
    return ProductList.model_validate_json(gemini_response.text)

# 実行例
if __name__ == "__main__":
    result = scrape_and_structure("https://books.toscrape.com/")
    print(f"ページタイトル: {result.page_title}")
    print(f"取得件数: {result.total_found}")
    for product in result.products[:3]:
        print(f"  - {product.name}: {product.price} (評価: {product.rating})")
```

実行すると、たとえば次のような出力が得られます。

```
ページタイトル: All products | Books to Scrape
取得件数: 20
  - A Light in the Attic: £51.77 (評価: 3.0)
  - Tipping the Velvet: £53.74 (評価: 1.0)
  - Soumission: £50.10 (評価: 1.0)
```

## 競合サイト価格監視への応用

単発の抽出だけでなく、定期実行による価格モニタリングにも活用できます。

```python
import time
from datetime import datetime
from pathlib import Path

class PriceMonitor:
    """複数URLの価格を定期監視するクラス"""

    def __init__(self, urls: list[str], output_dir: str = "price_data"):
        self.urls = urls
        self.output_dir = Path(output_dir)
        self.output_dir.mkdir(exist_ok=True)
        self.client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])

    def fetch_prices(self, url: str) -> dict:
        """単一URLの価格情報を取得"""
        class PricePoint(BaseModel):
            product_name: str
            current_price: Optional[str]
            original_price: Optional[str]  # セール前価格
            discount_rate: Optional[str]   # 割引率

        class PricePage(BaseModel):
            prices: list[PricePoint]
            timestamp: str

        headers = {"User-Agent": "Mozilla/5.0 (compatible; PriceBot/1.0)"}
        try:
            resp = requests.get(url, headers=headers, timeout=15)
            soup = BeautifulSoup(resp.content, "html.parser")
            for tag in soup(["script", "style", "nav"]):
                tag.decompose()
            text = soup.get_text(separator="\n", strip=True)[:6000]
        except Exception as e:
            return {"error": str(e), "url": url}

        prompt = f"""
以下のページから、全商品の価格情報を抽出してください。
セール価格がある場合は original_price と discount_rate も取得し、
timestampは現在時刻 {datetime.now().isoformat()} を設定してください。

{text}
"""
        # 定期監視にはFlashでコスト削減（Proの約1/20）
        response = self.client.models.generate_content(
            model="gemini-2.5-flash",
            contents=prompt,
            config=types.GenerateContentConfig(
                response_mime_type="application/json",
                response_schema=PricePage,
            ),
        )
        return json.loads(response.text)

    def run_monitoring(self, interval_minutes: int = 60):
        """指定間隔で全URLを監視"""
        while True:
            for url in self.urls:
                print(f"[{datetime.now().strftime('%H:%M')}] 監視中: {url}")
                data = self.fetch_prices(url)

                filename = url.replace("https://", "").replace("/", "_")[:50]
                filepath = self.output_dir / f"{filename}_{datetime.now().strftime('%Y%m%d_%H%M')}.json"

                with open(filepath, "w", encoding="utf-8") as f:
                    json.dump(data, f, ensure_ascii=False, indent=2)

                time.sleep(2)  # レート制限対策

            print(f"次の監視まで {interval_minutes} 分待機...")
            time.sleep(interval_minutes * 60)
```

ここで重要なのは、**定期監視には Gemini Flash を使うこと**です。Pro に比べてコストが約 20 分の 1 に抑えられます。複雑な解釈が必要な場合だけ Pro を呼び出す設計が実務では最も合理的です。

## ニュース・ブログの自動要約収集

製品データだけでなく、ニュースサイトやブログの記事を Structured Output で整形する使い方も実用的です。

```python
class NewsArticle(BaseModel):
    title: str
    published_date: Optional[str]
    author: Optional[str]
    summary: str          # 3文以内の要約
    keywords: list[str]   # 主要キーワード（最大5個）
    sentiment: str        # "positive" / "neutral" / "negative"
    url: str

class NewsFeed(BaseModel):
    articles: list[NewsArticle]
    source_name: str

def collect_news(url: str) -> NewsFeed:
    """ニュースページから記事一覧を構造化して収集"""

    headers = {"User-Agent": "Mozilla/5.0"}
    resp = requests.get(url, headers=headers, timeout=15)
    soup = BeautifulSoup(resp.content, "html.parser")

    for tag in soup(["script", "style", "nav", "footer", "aside"]):
        tag.decompose()

    text = soup.get_text(separator="\n", strip=True)[:10000]

    prompt = f"""
以下のニュースサイトのテキストから、記事一覧を抽出してください。
各記事の要約は3文以内にまとめ、sentimentは記事全体のトーンを評価してください。
URLは元のページのURLを使用: {url}

{text}
"""

    client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])
    response = client.models.generate_content(
        model="gemini-2.5-pro",
        contents=prompt,
        config=types.GenerateContentConfig(
            response_mime_type="application/json",
            response_schema=NewsFeed,
        ),
    )

    return NewsFeed.model_validate_json(response.text)
```

## よくあるエラーと対処法

Structured Output + スクレイピングの組み合わせで遭遇しやすい問題を整理します。

**HTML が長すぎてトークン上限を超える**

Gemini 2.5 Pro は 200 万トークンの長文脈を持ちますが、コスト面から実用的な上限は 8,000〜15,000 文字程度のテキストです。`soup.get_text()` の後に文字数制限をかけ、メインコンテンツエリアだけを抽出する工夫が効果的です。

```python
main = soup.find("main") or soup.find("article") or soup.find("body")
text = main.get_text(separator="\n", strip=True)[:8000] if main else ""
```

**`response_schema` の型エラー**

Pydantic v2 を使う場合、`Optional[str]` は `None` を許容しますが、モデルが空文字を返すケースに注意が必要です。`model_validator` でバリデーションをカスタマイズすることをお勧めします。

```python
from pydantic import model_validator

class ProductInfo(BaseModel):
    price: Optional[str] = None

    @model_validator(mode="after")
    def clean_price(self):
        if self.price == "":
            self.price = None
        return self
```

**robots.txt を無視したスクレイピングへの注意**

スクレイピングを実装する前に、対象サイトの `robots.txt` を必ず確認してください。`Disallow: /` となっているサイトへのアクセスは、技術的には可能でも法的・倫理的な問題となる場合があります。商用利用の場合は公式 API の提供有無を先に確認することを強くお勧めします。

## コスト管理の実践

Structured Output を使ったスクレイピングはトークンを消費するため、コスト計算をしながら設計することが重要です。

1 リクエストあたり入力 5,000 トークン・出力 500 トークンとした場合の試算です。

- Gemini 2.5 Flash: 約 0.00008 ドル（約 0.01 円）
- Gemini 2.5 Pro: 約 0.00063 ドル（約 0.09 円）

Flash で毎日 1,000 URL を監視した場合、月額 3 ドル以下に収まります。Pro は複雑なページ、Flash はルーティン監視、という使い分けが実務的には最も効率的です。

## まとめ

Gemini API の Structured Output は、従来のスクレイピング実装の「脆さ」を大きく改善してくれます。HTML 構造に依存せず意味でデータを抽出できるため、サイトのリニューアルに強く、新しい項目の追加も Pydantic モデルの変更だけで対応できます。
