## はじめに：なぜ REST API を直接使うのか

Gemini APIを利用する方法として、PythonやJavaScriptのSDKを使うアプローチが広く知られています。しかし、以下のようなケースでは **REST APIを直接呼び出す** 方法が有効です。

- SDKがサポートしていない言語（Go・Rust・PHP・Ruby・Swift など）を使っている
- バックエンドサーバーに余分なライブラリを入れたくない
- Postman や cURL で手軽に動作確認したい
- マイクロサービスから軽量なHTTPリクエストだけで呼び出したい
- 低レイヤーの制御が必要な本番環境構築

## 前提知識と環境準備

### 必要なもの

- **Google AI Studio の APIキー**（無料で取得可能）
- cURL または任意の HTTP クライアント（fetch・axios など）
- インターネット接続

### APIキーの取得

[Google AI Studio](https://aistudio.google.com/) にアクセスし、「Get API key」からキーを発行します。取得したキーはリクエストのクエリパラメータ `?key=YOUR_API_KEY` として渡すか、`x-goog-api-key` ヘッダーとして付与します。

> ⚠️ APIキーはコードに直接書かず、環境変数（`GEMINI_API_KEY`）で管理してください。

## エンドポイント構造を理解する

`generativelanguage.googleapis.com` の基本エンドポイント構造は以下の通りです。

```
https://generativelanguage.googleapis.com/v1beta/models/{MODEL_ID}:{METHOD}?key={API_KEY}
```

- **MODEL_ID**: 使用するモデル名（例: `gemini-2.5-pro-latest`）
- **METHOD**: 実行するアクション（`generateContent` / `streamGenerateContent` / `countTokens` など）

### Gemini 2.5 Pro のエンドポイント例

```
# テキスト生成（非ストリーミング）
POST https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-pro-latest:generateContent?key=YOUR_API_KEY

# ストリーミング生成
POST https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-pro-latest:streamGenerateContent?key=YOUR_API_KEY

# トークン数カウント
POST https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-pro-latest:countTokens?key=YOUR_API_KEY
```

## cURL で最初のリクエストを送る

最もシンプルな cURL コマンドでの呼び出し例です。

```bash
# 基本的なテキスト生成リクエスト
curl -X POST \
  "https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-pro-latest:generateContent?key=YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "Gemini 2.5 Pro の主な特徴を3つ教えてください。"
          }
        ]
      }
    ]
  }'
```

### 期待されるレスポンス（抜粋）

```json
{
  "candidates": [
    {
      "content": {
        "parts": [
          {
            "text": "Gemini 2.5 Pro の主な特徴：\n\n1. **高度な推論能力**：..."
          }
        ],
        "role": "model"
      },
      "finishReason": "STOP",
      "index": 0
    }
  ],
  "usageMetadata": {
    "promptTokenCount": 22,
    "candidatesTokenCount": 180,
    "totalTokenCount": 202
  },
  "modelVersion": "gemini-2.5-pro-001"
}
```

テキストを取得するには `candidates[0].content.parts[0].text` を参照します。

## JavaScript（fetch）での実装

Node.js やブラウザから fetch を使って呼び出す実装例です。

```javascript
// gemini-rest-api.js
const API_KEY = process.env.GEMINI_API_KEY; // 環境変数からAPIキーを取得
const MODEL = "gemini-2.5-pro-latest";
const BASE_URL = "https://generativelanguage.googleapis.com/v1beta/models";

/**
 * Gemini 2.5 Pro REST API でテキスト生成
 * @param {string} prompt - ユーザーのプロンプト
 * @param {object} options - 生成オプション
 * @returns {Promise<string>} - 生成されたテキスト
 */
async function generateText(prompt, options = {}) {
  const url = `${BASE_URL}/${MODEL}:generateContent?key=${API_KEY}`;

  const requestBody = {
    contents: [
      {
        role: "user",
        parts: [{ text: prompt }],
      },
    ],
    generationConfig: {
      temperature: options.temperature ?? 1.0,     // 創造性（0.0〜2.0）
      maxOutputTokens: options.maxTokens ?? 8192,  // 最大出力トークン数
      topP: options.topP ?? 0.95,                  // サンプリング確率
    },
  };

  const response = await fetch(url, {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
    },
    body: JSON.stringify(requestBody),
  });

  if (!response.ok) {
    const error = await response.json();
    throw new Error(`Gemini API Error: ${error.error?.message ?? "Unknown error"}`);
  }

  const data = await response.json();

  // テキストを抽出して返す
  return data.candidates?.[0]?.content?.parts?.[0]?.text ?? "";
}

// 実行例
(async () => {
  const result = await generateText(
    "TypeScript で簡単な REST APIサーバーを書くコード例を教えてください。"
  );
  console.log(result);
})();
```

            "text": "Go 言語でHTTPサーバーを立てる最小構成を教えてください。"

// システムインストラクション付きリクエスト

## マルチターン会話（会話履歴の管理）

REST APIでは会話履歴をクライアント側で管理し、毎回全履歴を送信します。

```javascript
// マルチターン会話の実装
class GeminiChatSession {
  constructor(apiKey, model = "gemini-2.5-pro-latest") {
    this.apiKey = apiKey;
    this.model = model;
    this.history = []; // 会話履歴
    this.baseUrl = "https://generativelanguage.googleapis.com/v1beta/models";
  }

  async sendMessage(userMessage) {
    // ユーザーメッセージを履歴に追加
    this.history.push({
      role: "user",
      parts: [{ text: userMessage }],
    });

    const url = `${this.baseUrl}/${this.model}:generateContent?key=${this.apiKey}`;

    const response = await fetch(url, {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({
        contents: this.history, // 全履歴を毎回送信
      }),
    });

    const data = await response.json();
    const assistantMessage = data.candidates?.[0]?.content?.parts?.[0]?.text ?? "";

    // モデルの返答も履歴に追加
    this.history.push({
      role: "model",
      parts: [{ text: assistantMessage }],
    });

    return assistantMessage;
  }

  clearHistory() {
    this.history = [];
  }
}

// 使用例
const chat = new GeminiChatSession(process.env.GEMINI_API_KEY);

(async () => {
  const reply1 = await chat.sendMessage("JavaScriptとTypeScriptの違いを教えてください。");
  console.log("モデル:", reply1);

  const reply2 = await chat.sendMessage("TypeScriptの導入で一番つまずくポイントは？");
  console.log("モデル:", reply2); // 前の会話文脈を踏まえた回答が返る
})();
```

> 💡 会話履歴が長くなるほどトークン消費が増えるため、古いメッセージを削除する「ウィンドウ管理」を実装することが実運用では重要です。詳しい実装パターンは [Gemini API でマルチターン会話を長期保持するセッション管理](/articles/gemini-api/gemini-25-pro-latest-api-quick-start) で解説しています。

## ストリーミングレスポンスの実装

長いテキストを生成する場合、レスポンス全体を待つより **ストリーミング**で逐次受信する方が UX が向上します。

```javascript
// ストリーミングレスポンスの実装
async function streamGenerateText(prompt) {
  const url = `${BASE_URL}/${MODEL}:streamGenerateContent?key=${API_KEY}&alt=sse`;

  const response = await fetch(url, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({
      contents: [{ role: "user", parts: [{ text: prompt }] }],
    }),
  });

  if (!response.ok) {
    throw new Error(`HTTP Error: ${response.status}`);
  }

  // Server-Sent Events (SSE) を読み取る
  const reader = response.body.getReader();
  const decoder = new TextDecoder();
  let buffer = "";

  while (true) {
    const { done, value } = await reader.read();
    if (done) break;

    buffer += decoder.decode(value, { stream: true });
    const lines = buffer.split("\n");
    buffer = lines.pop() ?? ""; // 最後の不完全な行をバッファに残す

    for (const line of lines) {
      if (line.startsWith("data: ")) {
        const jsonStr = line.slice(6).trim();
        if (jsonStr === "[DONE]") return; // ストリーム終了
        try {
          const chunk = JSON.parse(jsonStr);
          const text = chunk.candidates?.[0]?.content?.parts?.[0]?.text ?? "";
          if (text) process.stdout.write(text); // テキストを逐次出力
        } catch {
          // JSONパースエラーは無視（不完全なチャンクの場合あり）
        }
      }
    }
  }
}

// 実行例
(async () => {
  await streamGenerateText("量子コンピュータの仕組みをわかりやすく説明してください。");
  console.log("\n--- 完了 ---");
})();
```

## よくあるエラーと対処法

### 400 Bad Request：リクエスト形式エラー

```json
{
  "error": {
    "code": 400,
    "message": "Request payload size exceeds the limit: 20971520 bytes.",
    "status": "INVALID_ARGUMENT"
  }
}
```

**原因**: リクエストサイズが20MB制限を超えている（画像・動画の添付など）

**対処法**:
- 画像は Base64 ではなく Google Cloud Storage URL で渡す
- 長いプロンプトを分割して送信する

---

### 403 Forbidden：APIキーの権限エラー

```json
{
  "error": {
    "code": 403,
    "message": "API key not valid. Please pass a valid API key.",
    "status": "PERMISSION_DENIED"
  }
}
```

**対処法**:
- Google AI Studio でAPIキーを再発行する
- リクエストURLの `?key=` パラメータが正しく設定されているか確認する
- APIキーの利用制限（IPアドレス制限など）を確認する

---

### 429 Too Many Requests：レートリミット超過

```json
{
  "error": {
    "code": 429,
    "message": "Resource has been exhausted (e.g. check quota).",
    "status": "RESOURCE_EXHAUSTED"
  }
}
```

**対処法**:
- 無料枠では1分あたりのリクエスト数（RPM）に制限がある
- Exponential Backoff（指数バックオフ）でリトライを実装する
- Pay-as-you-go プランへの移行を検討する

```javascript
// Exponential Backoff によるリトライ実装
async function fetchWithRetry(url, options, maxRetries = 3) {
  for (let attempt = 0; attempt < maxRetries; attempt++) {
    const response = await fetch(url, options);
    
    if (response.status === 429) {
      // レートリミット時は指数バックオフで待機
      const waitMs = Math.pow(2, attempt) * 1000 + Math.random() * 500;
      console.log(`Rate limited. Retrying in ${waitMs}ms... (attempt ${attempt + 1})`);
      await new Promise(resolve => setTimeout(resolve, waitMs));
      continue;
    }
    
    return response;
  }
  throw new Error("Max retries exceeded");
}
```

---

### 500 Internal Server Error：モデルエラー

一時的なサーバー側のエラーです。同じく Exponential Backoff で数秒後にリトライしてください。

## generationConfig でレスポンスを制御する

`generationConfig` フィールドを使うと、モデルの出力を細かく制御できます。

```javascript
const requestBody = {
  contents: [/* ... */],
  generationConfig: {
    // 出力の多様性（0.0=決定論的、2.0=最大多様性）
    temperature: 0.7,

    // 次トークンの候補を上位何%に絞るか（0.0〜1.0）
    topP: 0.9,

    // 次トークンの候補を上位何件に絞るか
    topK: 40,

    // 最大出力トークン数
    maxOutputTokens: 4096,

    // 特定の文字列が出力されたら生成を停止
    stopSequences: ["---END---"],

    // JSON形式で出力する（構造化出力）
    responseMimeType: "application/json",
  },
};
```

### 構造化出力（JSON モード）

`responseMimeType: "application/json"` と `responseSchema` を組み合わせると、型付きのJSONを安定して出力できます。

```javascript
const requestBody = {
  contents: [
    {
      role: "user",
      parts: [
        {
          text: "東京・大阪・名古屋の3都市について、人口と有名な観光地を教えてください。",
        },
      ],
    },
  ],
  generationConfig: {
    responseMimeType: "application/json",
    responseSchema: {
      type: "array",
      items: {
        type: "object",
        properties: {
          city: { type: "string" },
          population: { type: "number" },
          attractions: {
            type: "array",
            items: { type: "string" },
          },
        },
        required: ["city", "population", "attractions"],
      },
    },
  },
};
```

## x-goog-api-key ヘッダーでの認証

クエリパラメータ方式の代わりに、リクエストヘッダーにAPIキーを含める方法も利用できます。

```bash
# ヘッダーでAPIキーを渡す方法
curl -X POST \
  "https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-pro-latest:generateContent" \
  -H "Content-Type: application/json" \
  -H "x-goog-api-key: YOUR_API_KEY" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [{ "text": "Hello, Gemini!" }]
      }
    ]
  }'
```

> 💡 ヘッダー方式は URLにAPIキーが露出しないため、アクセスログへのキー漏洩リスクを軽減できます。プロダクション環境では積極的に採用してください。

## FAQ

**Q. SDK（google-generativeai）と REST API を直接使う場合、何が違いますか？**

A. SDKはREST APIのラッパーであり、内部的には同じエンドポイントを呼び出しています。SDKはセッション管理・エラーハンドリング・型安全性などを自動で処理してくれますが、SDKが対応していない言語や環境ではREST APIを直接呼び出す必要があります。どちらの方法でも同じモデルの能力を最大限に活用できます。

**Q. APIキーをクエリパラメータで渡すのは安全ですか？**

A. HTTPS通信であれば暗号化されるため、基本的には問題ありません。ただし、Webサーバーのアクセスログや、Postman などのデバッグツールのログにキーが記録される可能性があります。プロダクション環境では `x-goog-api-key` ヘッダーを使う方が望ましいです。また、APIキーには必ず**Google Cloud Console でIPアドレス制限やリファラー制限**を設定することをおすすめします。

**Q. `gemini-2.5-pro-latest` と `gemini-2.5-pro-001` はどう違いますか？**

A. `gemini-2.5-pro-latest` は Gemini 2.5 Pro シリーズの最新バージョンに自動で向き直すエイリアスです。`gemini-2.5-pro-001` のように特定バージョンを固定することもできます。本番環境では挙動の変化を避けるために特定バージョンを固定し、開発・テスト段階では `-latest` を使うのがおすすめです。レスポンスの `modelVersion` フィールドで実際に使用されたバージョンを確認できます。

**Q. 無料枠で使える場合、利用制限はありますか？**

A. 無料枠（Free tier）では、Gemini 2.5 Pro は **1分あたり5リクエスト（RPM）・1日あたり25リクエスト（RPD）** に制限されています。個人の学習・プロトタイプ開発には十分ですが、本番運用には Pay-as-you-go プランへの移行が必要です。最新の制限値は [Google AI Studio の公式ドキュメント](https://ai.google.dev/gemini-api/docs/rate-limits) で確認してください。

**Q. Python SDK からこの記事の実装に移行する際の注意点は？**

A. 最も注意が必要なのは **エラーハンドリング** です。Python SDK は 429 や 500 エラーを自動でリトライしてくれますが、REST APIを直接使う場合は自前で実装が必要です。また、マルチターン会話の履歴管理もSDKが自動化してくれた部分なので、本記事のサンプルを参考に実装してください。
