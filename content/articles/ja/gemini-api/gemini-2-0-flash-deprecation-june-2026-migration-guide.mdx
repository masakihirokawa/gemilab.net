「最近 API を呼ぶと `model is deprecated` みたいなエラーが出てきた」という経験がある方は、既に移行を促すメッセージを受け取り始めているかもしれません。Gemini 2.0 Flash（`gemini-2.0-flash`）は **2026年6月1日** をもって廃止予定です。

とはいえ、「廃止」と言われても何をどう変えればいいのか、変えると何が変わるのか、すぐにイメージするのは難しいですよね。ここでは実際のコードを使いながら移行の全手順と注意点をまとめています。6月1日まで余裕はあっても、早めに動いておくほうが安心できます。

---

Gemini API を実プロダクトで運用してきた知見から、この問題に普段から向き合ってきた立場で、要点を整理します。

2014年から個人開発でモバイルアプリを続けてきた立場で見ると、API の選び方は AdMob を含む既存スタックとの相性が鍵です。

## なぜ今すぐ移行すべきなのか

「6月1日まで時間があるから後でいいや」という気持ちはよくわかります。ただ、経験上それが痛い目に合うパターンです。

廃止日以降、`gemini-2.0-flash` を指定した API 呼び出しはエラーになります。本番サービスが止まるのは最悪のシナリオですが、それ以前に以下の理由から **今動いておく** ことをおすすめします。

- **レート制限の新ルール適用**: 2025年4月から Gemini API はプリペイド課金が必要なリクエストについてTier制の月額上限（Tier 1: $250、Tier 2: $2,000）が適用されています。モデル移行のタイミングで自分の利用状況を確認できます
- **2.5 Flash の品質が想像以上に良い**: Thinking モードや推論精度が上がっており、同じプロンプトでも出力が改善されます
- **移行作業は思ったより短時間**: モデル名の置き換えだけで動くケースが大半です

---

## Gemini 2.0 Flash と 2.5 Flash の違い

移行前に両者の違いを簡単に整理しておきます。

**主要な変更点：**

- **モデル名**: `gemini-2.0-flash` → `gemini-2.5-flash`（または `gemini-2.5-flash-preview-04-17` のような具体的バージョン）
- **コンテキストウィンドウ**: 2.0 Flash は 1M トークン、2.5 Flash も 1M トークン（同等）
- **Thinking モード**: 2.5 Flash には思考モードが内蔵されており、推論系タスクの精度が大きく向上
- **マルチモーダル**: 音声・動画入力の対応が拡張されています
- **料金**: Flash クラスなので大幅な変動はありませんが、Thinking を有効にするとトークン消費が増えます

大半のユースケースでは **モデル名を変更するだけ** で移行が完了します。ただし Thinking に関しては少し注意が必要なので後述します。

## 最速移行：モデル名を置き換えるだけ

最もシンプルな移行方法から始めましょう。以下が典型的な Python コードの変更例です。

```python
# === 移行前（Gemini 2.0 Flash）===
import google.generativeai as genai

genai.configure(api_key="YOUR_GEMINI_API_KEY")

model = genai.GenerativeModel("gemini-2.0-flash")  # ← ここを変更する

response = model.generate_content("Pythonで素数を判定する関数を書いてください")
print(response.text)
```

```python
# === 移行後（Gemini 2.5 Flash）===
import google.generativeai as genai

genai.configure(api_key="YOUR_GEMINI_API_KEY")

model = genai.GenerativeModel("gemini-2.5-flash")  # ← 変更後

response = model.generate_content("Pythonで素数を判定する関数を書いてください")
print(response.text)
```

これだけで大半のケースは動きます。実際に私が管理しているいくつかのスクリプトで試した限り、**テキスト生成・画像認識・JSON出力のいずれも最初の書き換えだけで問題なく動きました**。

### REST API を使っている場合

Python SDK ではなく REST API を直接叩いている場合も同様です。

```bash
# === 移行前 ===
curl -X POST \
  "https://generativelanguage.googleapis.com/v1beta/models/gemini-2.0-flash:generateContent?key=YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"contents": [{"parts": [{"text": "Hello"}]}]}'

# === 移行後 ===
curl -X POST \
  "https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-flash:generateContent?key=YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"contents": [{"parts": [{"text": "Hello"}]}]}'
```

URL 内のモデル名だけ変わります。

## Thinking（思考モード）の扱い

Gemini 2.5 Flash で変わった点の中で最も注意が必要なのが **Thinking モード**です。2.5 Flash はデフォルトで Thinking が有効になっていることがあり、これがトークン消費と応答時間に影響します。

### Thinking を明示的にオフにする方法

レイテンシーを重視するアプリや、シンプルなテキスト生成タスクでは Thinking を無効にするほうがコスト効率が良いです。

```python
import google.generativeai as genai

genai.configure(api_key="YOUR_GEMINI_API_KEY")

# Thinking を明示的に無効化した設定
generation_config = genai.GenerationConfig(
    # thinking_config は現時点では SDK によって記法が異なる場合があります
    # 以下は概念的な例として参照してください
)

model = genai.GenerativeModel(
    model_name="gemini-2.5-flash",
    generation_config=generation_config,
)

response = model.generate_content(
    "次の文章を3行に要約してください：\n" + long_text
)
print(response.text)
```

一方、**複雑な推論が必要なコーディング支援や問題解決では Thinking をオンにした 2.5 Flash の方が明らかに精度が上がります**。用途に応じて切り替えることをおすすめします。

## よくある移行時のつまずきポイント

実際に移行作業をしていて気づいた、陥りやすい問題をまとめます。

**1. `model` パラメータに旧バージョンが残っている**

設定ファイルや環境変数でモデル名を外出しにしている場合、コード本体を変えても設定ファイルに古いモデル名が残っているケースがあります。以下のように検索して一括確認することを推奨します。

```bash
# プロジェクト全体でモデル名の指定を確認する
grep -r "gemini-2.0-flash" . --include="*.py" --include="*.json" --include="*.env" --include="*.yaml"
```

これで `.py` だけでなく設定ファイルにも漏れなく確認できます。

**2. ストリーミングの挙動が微妙に変わる**

ストリーミングレスポンスを使っている場合、Thinking モードが有効だとストリームの開始が少し遅くなることがあります。UX に敏感なリアルタイムチャット系アプリでは体感できる差が出ることも。この場合は Thinking を明示的にオフにするか、プログレスインジケーターを調整するといいでしょう。

**3. 旧 SDK バージョンとの互換性**

`google-generativeai` の古いバージョンを使っていると `gemini-2.5-flash` が認識されないことがあります。

```bash
# SDK を最新バージョンに更新
pip install --upgrade google-generativeai
```

移行と同時に SDK を最新にしておくのが安全です。

## チャット（マルチターン）も問題なし

チャット形式でやり取りするアプリでもモデル名の変更だけで移行できます。念のため実際に動作するコードを載せておきます。

```python
import google.generativeai as genai

genai.configure(api_key="YOUR_GEMINI_API_KEY")

model = genai.GenerativeModel("gemini-2.5-flash")

# チャット履歴を維持するセッション
chat = model.start_chat(history=[])

# 1回目のメッセージ
response = chat.send_message("Pythonでリストを降順に並べ替える方法を教えてください")
print("AI:", response.text)

# 2回目のメッセージ（前の文脈を引き継ぐ）
response = chat.send_message("それをラムダ式で書く方法は？")
print("AI:", response.text)

# 期待する動作：
# 「それ」が前の質問（リスト並べ替え）を指すことを文脈から理解して回答する
```

2.5 Flash への移行後も、チャット履歴の維持・文脈理解は問題なく動きます。

移行前に確認しておきたい項目をまとめました。

- `gemini-2.0-flash` を検索してすべての参照箇所を特定した

- SDK を最新バージョンに更新した
- テスト環境で動作確認した
- Thinking モードの扱いを用途に応じて決めた
- ストリーミングを使っている場合は体感レイテンシーに問題がないか確認した
