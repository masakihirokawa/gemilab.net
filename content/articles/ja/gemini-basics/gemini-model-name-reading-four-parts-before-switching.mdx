古い解説記事に書かれていたモデル名を貼り付けたら、エラーになりました。公式の一覧を開くと、似た名前が二十以上も並んでいて、どれに替えればよいのか見当がつかないのです。そんな場面は、これからも何度か訪れるのだと思います。

お伝えしたいのは、**モデル名は暗記するものではなく、4つの部品に分けて読むもの**だということです。読み方の手順と、読めない語に出会ったときの確かめ先を書き残します。

## 名前は「世代・系統・派生・公開段階」の4つでできています

公式のモデル一覧ページ（2026 年 10 月 24 日に私が確認しました）には、一覧の前に「名前とバージョン」の説明があります。そこでは、モデルの名前が次の4種類の「バージョンの型」に分かれると書かれています。

この表を頭に置いたうえで、名前を左から順に分けていきます。

1. **世代**: 3.8、3.6、4 のような数字です。大きいほど新しい世代、と受け取って大きな間違いはありません。
2. **系統**: flash や pro です。同じ世代の中での役割が違います。
3. **派生**: lite、tts、live、image などです。小型版、音声合成、リアルタイム対話、画像といった用途の違いを表します。
4. **公開段階**: 末尾の preview や、preview の後ろに付く月と年（たとえば 04-2026）です。

公式ページは lite や tts といった接尾辞そのものを定義しているわけではありません。モデルごとの説明文から読み取れる意味を、私が整理したものです。ここは断定しすぎないようにしています。

最後の2行は、型にきれいには収まりません。deep-research は Gemini の「世代と系統」を持たない別の仕組みですし、argon は flash や pro のような系統の語ではなさそうです。argon が何を意味するのか、公式ページには説明がありませんでした。ですから私は、argon を「系統を表す新しい名前」と仮置きし、意味を断定しないことにしています。

## 名前を分けるスクリプトで、読めない語を見つける

手で分けていると、読めない語を見落とします。そこで、名前を部品に分け、知らない語を「未登録」と正直に返すだけの短いスクリプトを作りました。外部のライブラリは使いません。Python が入っていれば動きます。

```python
import re
import sys

STAGE = {
    "preview": "プレビュー版（仕様や提供が変わりやすい）",
    "exp": "実験版（本番利用は想定されていない）",
    "latest": "最新版を指す別名（中身が入れ替わる）",
}
ROLE = {
    "lite": "小型・低コスト寄りの派生",
    "tts": "文章を音声にするモデル",
    "live": "リアルタイムの音声・映像のやりとり向け",
    "image": "画像を扱うモデル",
    "pro": "上位（高性能）の系統",
    "flash": "高速・軽量の系統",
}
VERSION = re.compile(r"^\d+(\.\d+)*$")
MONTH_YEAR = re.compile(r"^(0[1-9]|1[0-2])$")


def decode(name):
    parts = name.split("-")
    out = []
    for i, p in enumerate(parts):
        nxt = parts[i + 1] if i + 1 < len(parts) else ""
        if i == 0:
            out.append((p, "ブランドまたは製品名"))
        elif VERSION.match(p) and len(p) == 4 and p.isdigit() and MONTH_YEAR.match(parts[i - 1]):
            out.append((p, "年（直前の月と対で日付になる）"))
        elif MONTH_YEAR.match(p) and len(nxt) == 4 and nxt.isdigit():
            out.append((p, "月（このあと年が続く）"))
        elif VERSION.match(p):
            out.append((p, "世代・バージョン"))
        elif p in STAGE:
            out.append((p, "公開段階: " + STAGE[p]))
        elif p in ROLE:
            out.append((p, "役割・系統: " + ROLE[p]))
        else:
            out.append((p, "未登録の語（公式のモデル一覧で確認する）"))
    return out


if __name__ == "__main__":
    for name in sys.argv[1:]:
        print(name)
        for token, meaning in decode(name):
            print(f"  {token:<10} {meaning}")
```

実行は、調べたい名前を並べるだけです。

```bash
python3 decode_model_name.py gemini-3.8-flash-lite-tts deep-research-preview-04-2026 gemini-4-argon
```

deep-research の行は、正しくありません。deep を「ブランド」、research を「未登録」と判断してしまいました。名前の先頭が必ずブランドとは限らず、ハイフンで区切った単語がひとつの名前になっている場合があるためです。

私はこの誤りを直さずに残しています。**分け方の規則が通用しない名前を、機械が静かに誤読する**ことこそ、この手順の限界を示しているからです。「未登録」と出た語、つまり argon や research が出たときは、次の節の確かめ先に戻ります。

## 読めない語が出たときの確かめ先

読めない語を、推測で意味づけしないでください。確かめ先は次の順に見ると、迷いません。

1. **公式のモデル一覧ページ**: 現在使えるモデルが、名前と用途の説明つきで並んでいます。その名前が載っているか、まず探します。
2. **公式の廃止予定ページ**: 載っていなければ、ここに「停止」「非推奨」として移っていないかを見ます。停止日の欄が「発表なし」のこともあります。
3. **モデルの説明文**: 名前だけでは分からない用途は、一覧の説明文に書かれています。

載っているのに自分の環境だけ使えないのなら、名前の問題ではなく、提供の絞り込みの可能性があります。その切り分けは、次の記事に詳しく書きました。

## 名前を替えるときに、私が守っていること

名前が読めるようになると、「新しい世代に替えればよい」と急ぎたくなります。ただ、世代が上がっても、系統や派生が合っていなければ、期待した動きにはなりません。tts のモデルを、文章を作る用途で呼ぶことはできないからです。

そこで私は、替える前に次の3点を紙に書きます。

- 今の名前の「世代・系統・派生・公開段階」
- 替え先の名前の同じ4項目
- 4項目のうち、違うものはどれか

違いが「世代」だけなら、置き換えで済むことが多いです。「派生」や「系統」が違うなら、別の用途のモデルに替えようとしています。立ち止まって、公式の説明文を読み直します。

**名前は、読めない語を無理に読まず、確かめに行くための手がかり**だと思っています。

今日できるのは、使っているモデル名をひとつ選び、4項目に分けてみることです。分けられなかった語が、次に公式ページで確かめる語になります。
