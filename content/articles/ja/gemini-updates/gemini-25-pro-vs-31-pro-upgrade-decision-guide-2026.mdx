Gemini 3.1 Pro がリリースされてから数ヶ月が経ちました。「2.5 Pro を使い続けていいのか」「コストは上がるのか」と気になりながらも、移行に踏み切れていない方は多いのではないでしょうか。

私も同じ状況でした。個人開発で Gemini API を使ってアプリを作っているのですが、「3.1 Pro に変えたら何かが変わるのか」がずっと気になっていました。そこで実際に3ヶ月間、同じタスクを両モデルで動かし続けてみました。

結論から言うと、**移行すべきケースとそうでないケースは明確に分かれます**。以下にその詳細をまとめました。

## スペックで見る2つのモデルの差

まず数字を整理しておきます。

**Gemini 2.5 Pro の仕様**

- コンテキストウィンドウ: 200,000トークン（入力）
- 推論モード: Thinking Mode（思考予算で制御可能）
- マルチモーダル: テキスト・画像・音声・動画
- 主な強み: 高精度なコード生成、論理推論、コスト効率

**Gemini 3.1 Pro の仕様**

- コンテキストウィンドウ: 2,000,000トークン（入力）—— 2.5 Pro の10倍
- 推論モード: Adaptive Thinking（3段階の自動調整）
- マルチモーダル: 同上
- 主な強み: ARC-AGI-2で77.1%を達成した高度推論、エージェンティックタスク、超長文脈処理

コンテキストウィンドウが10倍というのは数字で見ると地味ですが、実際に使うと体感が大きく変わります（後述します）。

## 実際の性能差を体感するコード例

同じプロンプトを両モデルで処理し、応答品質の差を確認するスクリプトです。

```python
import google.generativeai as genai
import time

genai.configure(api_key="YOUR_GEMINI_API_KEY")

# 2.5 Pro と 3.1 Pro を並べて比較実行
models = {
    "gemini-2.5-pro": "Gemini 2.5 Pro",
    "gemini-3.1-pro": "Gemini 3.1 Pro",
}

# 複雑な推論タスクで性能差が出やすいプロンプト
prompt = """
以下のPythonコードにはバグが含まれています。
すべて特定し、修正済みのコードと説明を返してください。

def calculate_stats(data):
    total = sum(data)
    average = total / len(data)
    sorted_data = sorted(data)
    n = len(sorted_data)
    if n % 2 == 0:
        median = sorted_data[n/2]   # バグ1: 整数除算が必要
    else:
        median = sorted_data[n//2]
    variance = sum((x - average) ** 2 for x in data) / n  # バグ2: 標本分散なら n-1
    return {"mean": average, "median": median, "std": variance}  # バグ3: stdにvarianceを返している
"""

for model_id, model_name in models.items():
    model = genai.GenerativeModel(model_id)
    start = time.time()
    response = model.generate_content(prompt)
    elapsed = time.time() - start
    print(f"\n{'='*50}")
    print(f"【{model_name}】応答時間: {elapsed:.1f}秒")
    print(response.text[:600])
```

私の環境では、3.1 Pro は 2.5 Pro と比べて**バグの説明がより体系的で、同様のミスを防ぐための一般的な注意点まで補足してくれる**ことが多かったです。応答時間は 3.1 Pro の方が若干長くなることもありますが、タスクの性質によって変動します。

ただし、この程度のコードレビューなら 2.5 Pro でも十分な回答が返ってきます。差が顕著になるのは「長大なコードベースを渡す」「複数ファイルにわたる設計の問題を見つける」ような場面でした。

## コストへの影響を正直に計算する

料金の詳細は [Google AI for Developers の料金ページ](https://ai.google.dev/pricing) で確認いただく必要がありますが、傾向として**3.1 Pro は 2.5 Pro より高い料金帯**に設定されています。

個人開発レベルの利用（1日数百リクエスト程度）であれば、月額の差は数ドル〜数十ドルの範囲に収まることが多いです。ただし、大量のトークンを消費するユースケース（長文処理、大量バッチ処理など）では、コスト差が無視できなくなります。

コストの詳しい最適化手法については [Gemini API コスト最適化完全ガイド](/articles/gemini-api/gemini-api-cost-optimization-complete-guide) も参考になります。

## 「移行すべき」4つのシナリオ

3ヶ月の使用を通じて、3.1 Pro への移行が明確に効果を発揮したのは次のようなケースでした。

**1. コードベース全体を文脈として渡すとき**

2.5 Pro の 200K トークン制限では、ある程度の規模のプロジェクトでファイルを切り分けなければならない場面があります。3.1 Pro の 2M トークンなら、大抵のリポジトリをそのまま渡せます。詳細は [Gemini 3.1 Pro の 2M コンテキスト活用ガイド](/articles/gemini-advanced/gemini-31-pro-2m-context-batch-analysis-guide) が参考になります。

**2. エージェントが複数ステップのタスクを自律実行するとき**

エージェンティックなワークフロー（ツール呼び出し → 結果の解釈 → 次の行動の決定）では、3.1 Pro の Adaptive Thinking が精度の底上げに貢献します。[Gemini 3.1 Pro のエージェンティック・コーディング解剖記事](/articles/gemini-advanced/gemini-31-pro-agentic-coding-deep-dive) に仕組みの詳細があります。

**3. 数学・論理の高精度が必要なとき**

ARC-AGI-2 のスコア差が示すように、高度な推論タスクでは 3.1 Pro の優位が顕著です。ビジネスロジックの複雑な検証や、数式を含む文書の解析などで差が出ます。

**4. 長い会話履歴を保持するチャットボット**

長期にわたる会話文脈を蓄積する用途では、コンテキストウィンドウの広さが直接的なユーザー体験に影響します。会話が長くなるほど、3.1 Pro の広いコンテキストが活きてきます。

## 「2.5 Pro で十分」なケース

一方で、以下のケースでは 2.5 Pro を使い続けることが合理的だと感じました。

- テキスト要約・分類・抽出など、比較的シンプルな NLP タスク
- 1万トークン以内の短い会話や単発の質問応答
- コスト最優先の大量バッチ処理（この場合はさらに Flash も検討する価値があります）
- 既存のプロダクションコードが安定稼働しているとき（変更リスクを取る必要がない）

「良いモデルを使えば使うほどいい」は必ずしも正しくありません。タスクの性質に対して適切なモデルを選ぶことが、コスト効率と品質のバランスを取る鍵です。

## API 移行は 5 分で完了します

実際の移行作業は拍子抜けするほど簡単です。コードの変更は1行だけです。

```python
# 変更前
model = genai.GenerativeModel("gemini-2.5-pro")

# 変更後
model = genai.GenerativeModel("gemini-3.1-pro")
```

REST API を使っている場合も同様で、モデル名の部分だけを置き換えます。

```bash
# 変更前
curl -X POST \
  "https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-pro:generateContent" \
  -H "x-goog-api-key: YOUR_GEMINI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"contents": [{"parts": [{"text": "テスト入力"}]}]}'

# 変更後（モデル名だけ変更）
curl -X POST \
  "https://generativelanguage.googleapis.com/v1beta/models/gemini-3.1-pro:generateContent" \
  -H "x-goog-api-key: YOUR_GEMINI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"contents": [{"parts": [{"text": "テスト入力"}]}]}'
```

レスポンスの形式は同じなので、既存のパースロジックはそのまま使えます。移行後の安定化として、1〜2週間は両モデルを並行稼働させて出力の差を観察することをおすすめします。本番環境では、まず一部のトラフィックだけを 3.1 Pro に向けて挙動を確認するのが安全なアプローチです。

## まず「一番長いリクエスト」だけ試してみてください

おすすめの移行方法は、今すぐすべてを切り替えるのではなく、**「一番コンテキストが長くなるリクエスト」だけを 3.1 Pro に向けてみること**です。コスト変化を最小に抑えながら、実際の差を体感できます。

Gemini API の料金体系は進化し続けているので、最新の価格は必ず [公式の料金ページ](https://ai.google.dev/pricing) で確認してください。自分のユースケースでどちらが合理的か、小規模なテストで確かめてから判断するのが一番確実です。
