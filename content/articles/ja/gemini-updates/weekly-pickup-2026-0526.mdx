## 第1位：Streamlit と Gemini API でブログ運営ダッシュボードを作る

[Streamlit と Gemini API でブログ運営ダッシュボードを作る — GSC と GA4 を一つの画面に統合する実装メモ](/articles/gemini-api/gemini-api-streamlit-personal-blog-ops-dashboard-gsc-ga4)

今週もっとも読まれたのが、自分のブログ運営に必要な数字を Streamlit で 1 枚にまとめる、というシンプルな話題でした。GSC のクエリ・GA4 のエンゲージメント・公開済み記事のメタデータを Python で取り込み、Gemini API に「上位順位を取りそうなテーマ」「逆に落ちつつあるテーマ」を読ませる構成です。

私自身、Claude Lab を含む 4 サイトを並行運用していますが、サイトごとに別タブを開いて読む運用にはとっくに無理が来ています。記事内には、GSC API のクエリ範囲指定や、Gemini API のレスポンスを表に展開するための小さなプロンプトを共有しています。Streamlit のシンプルさが Gemini のレスポンスを「触れる対象」に変えてくれた点で、個人運営にちょうど良い設計でした。

```python
# Gemini に GSC データを渡して読ませる小さなプロンプト
prompt = f"""次の表は過去 30 日の GSC クエリです。
順位が改善傾向で、まだ CTR が低いクエリを 5 件、改善提案つきで挙げてください。
表（CSV）:
{gsc_csv_text}
"""
```

## 第2位：Apple Vision Framework × Gemini API のハイブリッド画像認識 — 壁紙アプリで 7 割コスト削減

[Apple Vision Framework × Gemini API のハイブリッド画像認識 ─ 壁紙アプリでクラウド推論コストを 7 割削減した設計メモ](/articles/gemini-api/gemini-vision-apple-vision-hybrid-cost-reduction-wallpaper)

私が運営している壁紙アプリでは、ユーザー画像をプレビューする際に「肌が大きく写るものは除外する」「文字情報が多いものはタグ付けする」といった軽い画像解析を回しています。これを全部 Gemini Vision に投げると確かに精度は良いのですが、利用が増えるにつれてクラウド推論コストが想定を上回り始めました。

そこで Apple Vision Framework で「端末側で判定できる軽い特徴」を先に確定し、不確定なケースだけを Gemini Vision に回すという二段構えに切り替えたところ、月額のクラウド推論コストが約 7 割減になりました。記事では、Apple Vision で何を確定的に拾い、何を Gemini に委ねるかという境界線の引き方を、実装サンプルとともに整理しています。

## 第3位：Gemini 3 Pro と Flash を AdMob 月次レポートの並列分析に使って見えた使い分け

[Gemini 3 Pro と Flash を AdMob 月次レポートの並列分析に使って見えた使い分け](/articles/gemini-api/gemini-3-pro-flash-admob-monthly-report-parallel-memo)

毎月の AdMob レポート分析を「Gemini 3 Pro と Flash 両方に同じ質問を投げて結果を比較する」運用に切り替えてから 10 日間の所感です。Pro は「文脈を踏まえた次の打ち手」の提案が明らかに鋭く、Flash は「数値の俯瞰と異常値検出」で十分速い、という棲み分けが見えてきました。

個人開発で AdMob 収益を見ている方は、おそらく似た悩みを抱えているはずです。レポートを並べたまま放置しがちなところ、Pro と Flash を並列にすることで意思決定が早まり、結果として広告ユニットの差し替え判断も早まりました。記事には、両モデルへ同時に投げるための薄いオーケストレーション層のサンプルが入っています。

## 第4位：Streamlit と Gemini で社内 BI を本番運用する

[Streamlit と Gemini で社内 BI を本番運用する — 認証・コスト最適化・キャッシュ・可観測性の設計メモ](/articles/gemini-dev/streamlit-gemini-data-analysis-multiuser-auth-bi-2026)

第 1 位の Streamlit ダッシュボードを、より本格的なチーム運用に拡張する話題です。複数ユーザーが触る前提になると、Cloud Run と OAuth の組み合わせ、SDK 呼び出しのキャッシュ層、Gemini API のレート制限を吸収するスロットリング、ログの可観測性、と一気にやることが増えます。

私は個人開発ですが、4 サイトの運営は単独でやるにはやはり負荷があり、外部の方に一部触っていただく場面もあります。そうした「半チーム運用」のために整理した設計メモがこの記事です。Auth の境界を明確にし、Gemini への問い合わせを user_id ごとにキャッシュするだけで、推論コストはぐっと落ち着きました。

## 第5位：Gemini 2.5 Flash で個人開発アプリのヘルプ翻訳を3ヶ月運用した所感

[Gemini 2.5 Flash で個人開発アプリのヘルプ翻訳を3ヶ月運用した所感](/articles/gemini-api/gemini-flash-iap-help-translation-3month-indie-review)

私の壁紙アプリは英語・日本語に加えて、最近は中国語・韓国語・スペイン語にも対応しています。これらのヘルプ文書の翻訳を Gemini 2.5 Flash に切り替えてから 3 ヶ月、レビューでの「翻訳が変」というフィードバックがほとんど来なくなりました。

記事では、翻訳を「機械的に流す」のではなく、Flash に対して「アプリの世界観」「ターゲット読者層」「禁止表現」を毎回プロンプトで申し送る運用に切り替えたことが、ブレを抑えた一番のポイントだったと書いています。月のコストは Gemini Pro と比較して圧倒的に低く、個人開発の多言語対応の現実解として扱いやすい構成になりました。
