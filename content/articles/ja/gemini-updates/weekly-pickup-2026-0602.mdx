## 第1位：Firebase AI Logic で iOS から Gemini を呼ぶと403になる

今週いちばん読まれたのは[Firebase AI Logic で iOS から Gemini を呼ぶと 403 になる原因と対処](/articles/gemini-api/firebase-ai-logic-ios-gemini-403-permission-denied-fix)でした。iOS アプリから Gemini を呼んだ瞬間に PERMISSION_DENIED が返ると、コードを疑いたくなりますが、原因の多くは Firebase 側の API 有効化漏れや App Check の設定にあります。

私自身、新しいアプリに組み込んだ初日にこの403で半日溶かしました。クライアントコードよりも先に、コンソール側の有効化状態を確認するのが結局いちばん速い切り分けです。

## 第2位：Gemini 2.5 Flash と Flash-Lite の使い分け

2位は[アプリ説明文のローカライズで Gemini 2.5 Flash と Flash-Lite を使い分けた所感](/articles/gemini-api/gemini-flash-vs-flash-lite-app-localization-cost-quality-review)です。短い定型文は Flash-Lite、ニュアンスが効く説明文は Flash、という分け方でコストと品質のバランスを取った実体験をまとめています。

全部を高いモデルに寄せる必要はありません。文章の役割ごとにモデルを変えるだけで、月々のAPI費用は目に見えて下がります。

## 第3位：本文が空なのに MAX_TOKENS になるときの対処

トラブルシューティングから[Gemini 2.5/3 で本文が空なのに finish_reason が MAX_TOKENS になるときの原因と対処](/articles/gemini-api/gemini-thinking-model-empty-output-max-tokens-budget-fix)が上位に入りました。思考モデルでは内部の思考トークンが上限を食い切り、本文が出る前に打ち切られることがあります。

```python
# thinking_budget を明示し、本文用のトークンを確保する
from google import genai
client = genai.Client()
resp = client.models.generate_content(
    model="gemini-2.5-pro",
    contents="要約してください",
    config={
        "thinking_config": {"thinking_budget": 1024},
        "max_output_tokens": 4096,  # 思考分とは別に本文用を確保
    },
)
print(resp.text)
```

`max_output_tokens` を上げるだけでなく、`thinking_budget` を明示して思考と出力のトークンを分けて考えるのが要点です。
