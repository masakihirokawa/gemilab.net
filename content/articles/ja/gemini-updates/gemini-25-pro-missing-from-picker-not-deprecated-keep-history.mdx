昨日まで選べていたモデルが、今日の一覧に見当たらないのです。AI Studio のコミュニティには、9 月 18 日にそうした報告が立ちました。夕方までは使えていたのに、気づくと一覧から 2.5 Pro が消えていた、という内容です。同じスレッドには、過去の会話が途中で固まってしまったという声も並んでいました。読みながら、胃のあたりが少し重くなったのを覚えています。

最初にお伝えしたいのは、**「一覧にない」ことと「廃止された」ことは別の話**だということです。見分け方と、会話の履歴を手元に残しておく順番を書き残します。

## 一覧から消えたときに最初に見るもの

感覚で「廃止だ」と決めず、公式の廃止予定ページを開きます。2026 年 10 月 21 日に私が確認した時点で、次のように書かれていました。

同じページには、2.5 系へのアクセスを「過去に実際に使ったことのある利用者」に限っていること、そしてモデルは非推奨ではなく、追って知らせるまで API で提供され続けることが記されています。新しいプロジェクトには 3.5 Flash-Lite か 3.8 Flash が案内されています。

つまり、停止日は決まっていません。一方で、新しく使い始める人や、最近使っていないと判定された人には見えにくくなる、という絞り込みが入っています。

## 自分に起きているのはどちらか

画面と API の両方で確かめると、切り分けが速くなります。

1. AI Studio のモデル選択を開き、空白部分をクリックして一覧を広げます。コミュニティでは、これで選べたという報告がありました。ただし私の環境で再現した結果ではありません。
2. 別のプロジェクトのキーで同じモデル名を呼び、結果を比べます。
3. 404 が返る場合は、モデル名の綴りより先に、利用者の絞り込みを疑います。この切り分けは、[2.5 Flash が 404 になったのに停止日が出ていなかった件](/articles/gemini-api/gemini-25-flash-404-no-longer-available-shutdown-date-unannounced)で細かく書きました。

コミュニティには、プラン階層や費用の都合ではないかという推測も出ていました。ただ、動画を根拠にした憶測で、公式には確認できていません。ここでは「公式が書いていること」だけを前提にしています。

## 画面と API で見え方が違うことがある

AI Studio のモデル一覧から消えたことと、API が実際に応答しなくなったことは、同時に起きるとは限りません。公式ページは API での提供が続くと書いていますので、一覧に見えなくても、すでにモデル名を指定して呼んでいたコードは動き続ける可能性があります。逆に、新しく作ったキーやプロジェクトでは 404 になることもあり得ます。

ここで焦って別のモデルに書き換えると、出力の癖が変わって、元の問題が見えなくなってしまいます。まずは「画面で選べない」「API が失敗する」「過去の会話が続けられない」の三つを別々の症状として書き出してください。どれが起きているかが分かれば、次に確かめる場所も決まります。

## 履歴をモデルに縛られない形で残す

私自身、個人開発で試作の会話を AI Studio に置きっぱなしにしがちでした。一覧から消えたとき、その会話が続けられなくなる可能性は、頭では分かっていても備えていませんでした。結果は芳しくありませんでした。いまは次の三つを、モデルの動向とは無関係に済ませるようにしています。

- 大事な会話は、節目ごとに Google ドキュメントなどへ書き出します。共有範囲の確認は[書き出す前の共有設定の点検](/articles/gemini-advanced/gemini-export-to-docs-check-sharing-before-sending)にまとめています。
- 会話の冒頭に、使ったモデル名と日付を 1 行書いておきます。あとで別のモデルに貼り直すときの手がかりになります。
- API を使う場合は、モデル名を固定して呼び、返ってきたモデル名を記録します。考え方は[既定モデルの固定と、静かな差し替えの検知](/articles/gemini-api/gemini-api-default-model-pinning-silent-upgrade-detection-production)に書きました。

**モデルは動いても、記録は自分の側に置いておく。** この線引きだけは、忙しい週でも守るようにしています。

## 次のアクション

まずは、いま続けている会話のうち、手放したくないものを一つだけ選んでください。それをドキュメントに書き出し、冒頭にモデル名と日付を添えるところから始めていただければ幸いです。
